# 两级 Tab 与右键菜单精简方案

日期：2026-11-09。状态：用户授权后已实施；验收与发行见[实施记录](implementation-tab-interactions.md)。适用于主窗口与独立窗口的服务器标签、组件标签和分屏标签栏；在既有[工作台设计](plan-workbench-layout.md)与[Tab 新建规则](plan-default-behavior-terminal.md)上收敛交互。

## 1. 对需求的理解

用户明确要求：删除一级、二级标签栏的三个点，以右键提供操作；重新设计菜单，减少选项，做到简单明了。

据此推测，用户希望平时看到的是正在使用的服务器和页面，需要整理窗口或分屏时才出现少量动作。菜单应让人立即知道会发生什么，不要求先理解工作区、Host、标签组、来源位置等内部概念。低频布局能力可以主动缩减，不需要把全部旧选项换个位置继续堆起来。

本方案采用以下取舍。用户已授权按本方案实施：

- 标签栏保留标题、状态、关闭按钮和新建加号；三个点入口删除，不改为另一种“更多”按钮。
- 一级标签负责当前窗口中的服务器工作台，二级标签负责一个页面；分屏布局操作放在所属标签栏空白处的右键菜单。
- 常用分屏只提供右侧和下方两个方向，其他位置靠现有拖拽调整。
- 缩减整组移窗、任意窗口目标列表、手动窗口布局恢复等高级入口。
- 取消分屏只整理布局，页面和会话继续运行；关闭标签才进入既有关闭检查。

## 2. 当前问题与范围

源码中一级右键菜单与三个点打开同一份菜单，内容包含移至新窗口、多个独立窗口、返回主窗口、全部返回、恢复布局和两种关闭范围。二级三个点实际属于整个标签组，菜单同时包含分屏、放大、整组移窗、返回、逐组合并、逐组切换和整组关闭；页面右键另有四个方向、逐组移动、多个窗口、两种返回与恢复显示。选项会随窗口和分屏数量增长。

本次规划只处理核心两级标签与分屏交互。侧栏面板标题上的菜单、左右工具条的更多组件入口、文件和终端内部业务右键菜单保持各自职责。本轮不调整配色、字体、主题或插件业务规则。

## 3. 标签栏与基本操作

| 对象 | 常驻内容 | 左键与加号 | 右键对象 |
| --- | --- | --- | --- |
| 一级服务器标签 | 连接状态、名称、× | 点击切换；＋沿用已有服务器选择与连接流程 | 当前被右键的服务器标签 |
| 二级组件标签 | 图标、标题、未保存标记、× | 点击切换；＋调用插件声明的默认新建行为，归属点击所在分屏 | 当前被右键的页面 |
| 二级标签栏空白 | 留出可右键的空白区域 | 不新建、不关闭、不触发窗口拖动 | 当前分屏的布局 |

关闭按钮继续保留，不因悬停或选择而改变占位。右键未选中的标签不自动切换当前内容；菜单操作绑定被点击对象，不绑定最近活动标签。固定“服务器管理”标签不提供工作台关闭或移窗菜单。一级标签条空白继续用于窗口拖动，不新增窗口管理菜单。

排序、拖入其他分屏和已有跨窗拖拽沿用适用平台的既有行为。菜单出现时结束拖拽意图；点击 × 或＋不得同时开始标签或原生窗口拖动。本轮不增加中键关闭或新的全局快捷键。

## 4. 一级标签右键菜单

普通主窗口菜单只有两项：

```text
移到新窗口
──────────
关闭标签
```

独立窗口通常为：

```text
返回主窗口
──────────
关闭标签
```

当独立窗口包含多个服务器标签时，再显示“移到新窗口”，便于单独拆出其中一个。独立窗口仅有一个服务器标签时，不提供把整份内容重新搬到另一个新窗口的重复操作。一级菜单最多三项。

“关闭标签”与 × 完全相同：处理当前窗口中该服务器标签下的页面；同一服务器在其他窗口中的工作台继续存在。最后一份工作台关闭时，才按既有生命周期结束整个服务器工作区。关闭摘要应列出实际受影响页面，标题使用“关闭服务器标签”；不把局部关闭文案写成“断开服务器”。

删除菜单中的“关闭服务器工作区（所有窗口）”“此窗口全部返回主窗口”“恢复上次窗口布局”及逐个独立窗口的移动项。不新增“关闭其他”“关闭右侧”等批量动作。用户通过已有拖拽整理多个标签，或逐个关闭当前标签。

## 5. 二级标签右键菜单

普通页面菜单固定四项，已经移出的页面最多增加一项返回：

```text
移到右侧分屏
移到下方分屏
移到新窗口
返回原窗口        仅在存在有效返回目标时出现
──────────
关闭标签
```

- **分屏：** 把被右键的页面移动到所属分屏的右侧或下方新区域，保留同一个页面实例、终端会话与文件草稿，不复制页面、不自动新建终端。原区域还有页面时显示其余页面；只有这一页时保留一个可新建的空区域。右键标签栏空白的分屏命令则创建空区域，当前页面留在原区域。
- **移到新窗口：** 只移当前页面。页面已经独占一个独立窗口的全部工作台内容、没有其他工具或待处理内容时，隐藏该项；整个窗口重新拆出没有实际收益。
- **返回原窗口：** 将既有“返回来源”与“返回主窗口”合成一个入口。优先回原窗口和原位置；来源已关闭时回当前服务器在主窗口的有效工作台。使用回退目标时文案改为“返回主窗口”；两种文案互斥，不同时出现。没有有效返回目标时隐藏，不默认重建旧窗口。
- **关闭标签：** 与 × 共用关闭流程。文件未保存、任务运行中、取消、保存失败等行为沿用既有规则。关闭单个页面不结束共享服务器连接。

移到指定已有标签组或已有窗口的菜单列表删除；适用平台仍可拖拽到目标区域。菜单不使用编号标签组或编号窗口，也不新增目标选择弹窗。

中央区域中的侧栏工具使用更短的菜单：“停靠到侧栏”“移到新窗口”“隐藏工具”，有有效跨窗来源时增加互斥的返回项。停靠优先采用当前工作台记住的侧栏位置，无记忆时采用插件默认位置；隐藏与现有工具 × 一致，保持后台任务与实例。侧栏左右位置的调整继续由侧栏自身入口负责，不在工具标签菜单展开两个方向。

健康页面不显示“恢复显示”。确实发生界面挂载错误时，在原有错误提示区域提供“重试显示”，只恢复显示表面，不重建业务会话，不因普通业务错误或连接断开而重载页面。

## 6. 分屏布局与空区域

二级标签栏空白处的右键菜单：

```text
左右分屏
上下分屏
──────────
取消此分屏       当前工作台有多个分屏时出现
```

“取消此分屏”将当前区域的标签按原顺序并入相邻区域，再移除当前区域。目标按布局阅读顺序选择前一个区域；没有前一个时选择后一个，不弹目标列表。当前区域有活动页面时，合并后继续显示该页面；当前区域为空时，保留目标区域的活动页面。所有页面、工具和业务任务继续存在，不发关闭或 dispose 请求。

整组移窗、整组返回、逐组合并、逐组切换、手动放大和“关闭标签组”退出常规菜单。单页迁移与整份工作台迁移已覆盖主要场景；取消分屏可以完成常见的布局收拢。

显式分屏形成的空区域保留，空白正文只提示“点击＋新建，或拖入标签”，删除正文中的重复分屏按钮。关闭或迁出最后一页产生的空区域自动回收；分屏命令本身留下的空区域属于用户请求的布局，不能立即回收。工作台最后一个区域始终保留，以便继续新建。收回区域不得顺带关闭服务器标签或其他工作台内容。

小窗口继续自动显示当前分屏，并汇总其他分屏的未保存与错误数量。仅在有隐藏区域时显示一个“其他分屏（数量）”入口，列表按实际页面标题识别目标，不混入移窗、关闭等动作；点击切换显示，扩大窗口恢复原布局。这是窄窗口的导航入口，不作为新的常驻更多菜单。

## 7. 菜单状态、失败与平台规则

| 情况 | 明确行为 |
| --- | --- |
| 鼠标右键 | 菜单出现在点击位置附近；窗口边缘自动避让，短菜单不出现滚动条 |
| 键盘操作 | 标签获得焦点后，Shift+F10 或菜单键打开同一菜单；方向键选择、Enter 执行、Esc/Tab 关闭，Esc 返回原标签焦点；插件 iframe 中的按键继续交给插件 |
| 空间不足 | 两个分屏动作仍保留并禁用，给出统一提示“窗口空间不足”；不把原因拼进每条菜单标题 |
| 对象变化 | 右键另一对象时替换菜单；切换工作台、关闭/移动目标、失焦或开始拖拽时关闭；执行前核对对象身份与布局状态 |
| 异步操作中 | 菜单选择后立即收起；受影响的标签防重复操作，并显示既有移动或关闭进度；其他区域仍可使用 |
| 移动失败或结果未知 | 保留原页面和输入，复用原请求回执确认结果；不再次创建窗口或业务页面，不自动重发副作用 |
| 关闭取消或保存失败 | 原页面、布局与草稿保留；继续复用本次已提交的关闭修复与既有生命周期规则 |
| 合并与布局保存失败 | 核心先验证并原子提交；拒绝时保留原布局，已提交但持久化失败时明确报告保存失败，不假装落盘成功 |

主窗口与独立窗口、浅色/深色/多巴胺三主题采用相同动作和文案。五个正式平台均保留菜单的新窗口与返回操作；任意已有窗口目标退出菜单后，Wayland 等不能使用既有跨窗拖拽的平台不提供该高级操作。这是本次主动缩减的能力边界，不能宣称所有旧操作均有键盘等价入口。

已有布局文件、页面实例、服务器 Context、插件 API 与默认新建约定继续沿用。删除的是用户入口，内部整组移动、全工作区关闭等仍按系统流程需要保留；不借菜单精简修改连接、资源或插件权限设计。手动恢复额外窗口的入口退出本轮界面，不另藏到设置，也不删除旧布局记录或自动重开全部历史窗口。

## 8. 实施边界与验收

后续实施以两级标签和分屏交互为一个主题：先迁移右键与键盘入口，再删除三个点和旧菜单；统一关闭/隐藏/返回文案，最后实现取消分屏与空区域回收。核心前端落点为 `src/workspaces.ts`、`src/components.ts` 及相关样式；布局合并、原子提交与空组回收按需要接入现有核心布局服务，不新增生产依赖。

现有 UI、布局、桌面和原生交互测试中通过 `.tab-menu-button`、`group-menu` 打开菜单的调用要同步改用真实右键或键盘；保留实际核心、插件夹具与关闭结果断言，不把删除测试当作通过。操作文档在实施后更新；本提案与当前已实现能力分开记录。

| 验收场景 | 预期结果 |
| --- | --- |
| 主窗口、独立窗口的两级标签栏 | 无三个点；标题、状态、× 和＋仍可用，按下期间刷新不重复触发动作 |
| 一级普通/独立/多标签窗口 | 分别符合两项/两项/最多三项规则，× 与菜单关闭范围一致 |
| 二级普通页、移出页、中央工具 | 分别使用对应短菜单，返回项互斥，不展开窗口/标签组列表 |
| 右键非活动标签、右键空白栏、键盘菜单 | 操作正确对象；不抢当前页面、不打开插件正文或浏览器菜单，Esc 恢复焦点 |
| 1 页/多页的两种分屏、空区域取消 | 位置明确，不复制会话；显式空区域保留，取消分屏合并内容并结束操作 |
| 关闭或移出区域最后一页 | 回收无内容区域，保留最后工作台区域；取消关闭保持原布局 |
| 合并未保存文件、终端和后台工具 | viewId/会话/正文连续，工具仍运行；取消分屏不出现保存或任务停止对话框 |
| 关闭、迁移、刷新、失败及迟到结果 | 复用原身份与回执，取消和失败不会遗失草稿，不发生重复创建或永久等待 |
| 720×480、长标题、三主题与窄布局 | 菜单完整可见；隐藏分屏可访问，恢复宽窗口不丢原树与比例 |
| 五平台与原生交互 | 验证系统右键/菜单键、标题栏拖动、移窗与返回；浏览器模拟不能替代原生包验收 |

本方案的实现、验证与已知限制统一记录在[实施记录](implementation-tab-interactions.md)，正式发行以[版本说明](releases/v0.19.0.md)为准。
