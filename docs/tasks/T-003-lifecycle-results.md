流程及断言：

1. 创建服务器，处理主机信任并设置内存密码；新建两个真实 PTY，核对两个租约共享同一 SSH 连接。
2. 关闭会话列表，核对两个终端及全部资源 ID 不变；重开列表后仍为原会话。
3. 用目录占用隔离数据的 `workbench.pending` 注入真实保存失败：配置/同窗口移动应返回 `STORAGE_ERROR` 且内存、修订和磁盘不变；跨窗口弹出已交接成功，应返回 `committed: true`、`persisted: false` 与警告，目标可用且既有提示区明确显示已移动但未保存。移除故障后，通过实际 worker 的 `sessions.rename` 修改标题，核对同一 sessionId、工作台视图、原生 Tab 文本及 Windows 窗口标题；窗口标题同时保留服务器名与新终端名。核对全部 PTY/租约/连接 ID 不变，并确认正常保存已包含实际目标位置。
4. 关闭更新标题后的独立窗口，等待其原生 shell 页面、视图、PTY 与租约结束；第二个终端及共享连接身份保持。通过该终端当前挂载桥发送唯一测试标记，验证真实 SSH 回送继续显示；这一步不验收物理键盘输入路线。
5. 删除服务器时不选择结束会话应明确拒绝，保持服务器、工作台与所有资源身份；选择结束会话后，剩余 PTY/租约/连接、服务器、工作区及视图均清理，同时远端 fixture 的 shell/connection 计数归零。
6. 另建服务器与两个活动 PTY，一个弹出独立窗口；此时明确 `app.exit`，检查正常退出码 0，并在仍运行的 fixture 中等待全部 shell/connection 实际关闭。
7. 用同一隔离数据目录重启，核对原视图 ID 只恢复为 ended 占位，没有 sessionId/ptyId/generation，资源和 worker 会话为空且未重新连接 SSH。再次正常退出。保留各阶段脱敏快照及结果，停止测试服务并清理其 6 个临时私钥文件。

默认独立 CLI 模式用现有 `windows.ps1` 仅检查/关闭指定测试 PID 的窗口。本次 Computer Use 会话使用外部关闭模式，避免混用 PowerShell UI 自动化：

```powershell
$env:SODECK_LIFECYCLE_EXTERNAL_CLOSE='1'
node tests/desktop/lifecycle.mjs
```

脚本打印本轮 `.qa/lifecycle/<时间戳>` 目录，写入 `close-request.json` 后等待最多 180 秒。操作者用 Computer Use 识别该测试 PID 的窗口、核实实际完整标题并关闭，随后在同目录写入 `close-confirmation.json`，内容为 `{"observedTitle":"实际完整标题","closed":true}`。该文件只记录实际操作结果；脚本仍独立核对 shell 页面关闭、工作台和资源释放。未观察到标题或未操作时不能预填确认。本模式不调用 `nativeWindow`/PowerShell。

本流程验证实际 worker、原生工作台与资源生命周期，不验收重命名输入交互、中文 IME、Linux shell 或跨屏拖动。执行结果在下方回填，不以计划替代通过。
