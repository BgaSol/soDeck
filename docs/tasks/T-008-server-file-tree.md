## 1. 用户原意与推荐方案

用户要求：“新增一个磁盘目录树，在每个服务器 tab 中都有。文件节点能看到文件大小。目录节点，如果是目录挂载，能看到挂载的详细信息。……推测一下我的意图……先出一份功能设计。”明确要求已写入 [P-32](../product.md)。

推测目标：操作服务器时直接了解文件层级和大小，识别某个目录实际对应的磁盘、网络共享或另一处目录，以及当前可用空间，减少反复查询命令。用户未明确要求完整文件管理器、磁盘分析器或挂载管理。

推荐可观察结果：

1. 每个服务器工作区有“文件”侧栏，默认在左侧；新工作区默认展开，可收起/改到右侧。目录树与中央终端并存，每服务器一份，不按终端 Tab 重复。
2. 从远端 Linux `/` 开始，逐层展开和路径定位；普通文件直接显示大小，选中可看精确字节数。目录不自动扫描计算内容总大小。
3. 挂载点有明确标记，选中后在侧栏下方显示来源、类型、容量/已用/空闲/账号可用、读写状态；高级区展开参数、源内路径及标识等实际可得信息。
4. 区分挂载点、普通后代、bind 和符号链接；覆盖本地、网络及虚拟文件系统。容量属于文件系统，未知字段如实显示，不把所有挂载强行对应为物理硬盘。
5. 切换服务器保留各自展开/选择/滚动，完整工作区拆合一起迁移；关闭工作区重开和完整重启不恢复旧文件现场。新建服务器按 P-34 自动创建首终端，文件侧栏等待核心连接就绪后取得自己的租约读取；没有连接时保留手动“连接并读取”，文件能力不依赖终端存在。
6. 只读首轮：浏览、属性、挂载查询、刷新和复制路径；编辑/传输、递归总量、挂载/卸载和自动改变终端目录留待后续。

本方案应用已读取的 `apple-design`：熟悉树形导航、就近详情、即时反馈、稳定布局、克制动效、清晰排版和完整键盘操作。对应落点与测试以 F-FILES-001 第 5/7 节为准。本轮只有文档内结构示意，未创建交互原型。
