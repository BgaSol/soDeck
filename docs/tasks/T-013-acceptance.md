# SoDeck v2 · T-013 核心跳板开发包

Windows 本地开发包，核心 2.0.0-dev.7、API/SDK 4.4.0、终端 0.6.0、文件 0.3.3。尚未正式发布，不是安装器。双击本目录的 `Start-SoDeck.cmd` 启动，配置保存在本目录 `data/`，不覆盖其他开发包或 v1 数据。

1. 添加目标服务器，在“连接方式”选择“通过 SSH 跳板”，选择已有直连档案；没有候选时点“添加跳板服务器”，保存后应返回原目标草稿，且不会打开跳板工作区。
2. 保存并打开目标。按“跳板 1/2”“目标 2/2”分别核对指纹及认证，确认终端输入输出、文件树和挂载详情均可用。跳板只需允许 TCP 转发，不需要交互 shell。
3. 打开目标的第二个终端，关闭其中一个，另一终端和文件仍应正常。点底部连接状态可查看完整路径；“运行资源”可查看路径和持有实例。
4. 修改跳板配置后，已有连接应保留；新建终端使用新路径。新旧连接不一致时，文件显示“连接不同，暂不跟随”。删除被引用的跳板会先列出依赖并阻止删除。
5. 切换深浅色、拆合工作区，再从应用菜单明确退出。重新启动应保留档案，但没有上次的连接或工作现场。

本轮支持一层 SSH 跳板；不包含多层链、代理、Agent/MFA、v1 数据导入或安装发布。断线后需手动重试，不自动直连或重放终端输入。

数据升级会在 `data/core/backups/before-routes-*` 保存数据库和凭据备份。回退时只向独立的旧版数据目录恢复匹配的升级前备份，不把新增跳板数据交给旧核心。不要复制本次测试环境的私钥或临时数据。

实测及边界见 `RESULTS.md`、`evidence/`、`screenshots/`、`build.json`。方案已确认；用户功能验收及正式发布另行记录。

工作区中的测试临时文件因自动审批策略未能删除，服务已全部停止；此开发包不包含这些文件。该清理项仍由 T-013 跟踪。
