## 1. 原实施方案

用户反映无法在界面完成“本机 → SSH 192.168.1.16 → SSH 192.168.1.104 → SOCKS 127.0.0.1:12021 → SSH 65.11.10.24”，要求理解、推断并出设计。随后明确代理运行在 `192.168.1.104` 上。此答复只确认网络含义，不视为方案或编码确认。

推荐将三种互斥连接方式改为“直接连接 / 经由中转”，使用可插入、排序、移除的 SSH/SOCKS5 有序列表，明确每站由谁访问与回环归属。核心依次组合传输，只打开最终目标工作区；已有 SSH/单 SOCKS 仍可表达，不增加固定跳数。沿用 T-025 已存 SSH 选择与代理内联持久创建。

范围、顺序语义、界面和功能测试集中在F-CORE-031。用户继续要求代码方案，随后明确“不需要做兼容，数据库要简单明了”“插件如果有需要改的地方，在插件中也要做出修改计划”。本r2提交统一类型化执行器、单一步骤表、凭据绑定与条件写、API/SDK6/core v7、超时/预算、四插件独立接入和MR-CODE-01～10。

不做旧三模式/API适配或v6数据迁移。确认实施后按P-52备份旧核心库及秘密，再建空v7，服务器/代理/分组/核心设置/信任需要重新配置；独立插件文件保持，不按同名恢复旧serverId。交付建议包含四个API6官方包与独立Windows开发目录包，不包含安装器、提交/推送或发布。
