# SoDeck v2 · 多级 SSH 跳板开发包

Windows 本地开发包：核心 2.0.0-dev.10、API/SDK 4.6.0、终端 0.7.1、文件 0.4.1。双击 `Start-SoDeck.cmd` 启动，配置保存在本目录 `data/`。这是独立目录包，不覆盖原 T-013 单跳包，也不是正式安装器。

1. 添加 A，然后让 B 经由 A、C 经由 B、目标 D 经由 C。已有跳板的服务器也能被选为跳板；也可从 D 的表单连续“添加跳板服务器”，逐级保存返回。确认各层草稿保留、只打开最终目标。
2. 打开 D，依次核对每台服务器身份并认证。对话框显示当前第几台/总数以及最终目标。确认终端、文件目录和挂载信息均来自 D，中间服务器只需允许 TCP 转发。
3. 点底部连接状态查看完整路径；在“运行资源”展开每段中转状态。多开一个终端、关闭其中一个，其他使用者继续工作。
4. 修改 B 后，已有会话保留原路径，新连接采用新配置；删除 A/B 时应列出直接和间接依赖并阻止误删。选自身或后代形成循环的路径不能保存。
5. 切换三主题、拆合窗口、收起托盘，再明确退出并重启。应保留档案、清空上次工作现场，退出时释放所有连接。

路径配置没有固定业务跳数上限，必须有限且无环。运行时有全局资源预算：最多 256 个 SSH 会话、256 个内部桥和 64 个目标连接；容量不足会明确拒绝，不截短路径。真实 OpenSSH 验证到 3 层跳板，更深验证使用协议夹具；1000 层测试验证配置、保存与分页，不代表建立了 1000 层网络连接。

数据从 schema 2 升为 3 前自动备份数据库和凭据。旧单跳核心会拒绝新数据；回退应把升级前 `data/core/backups/before-routes-*` 的内容恢复到独立旧版数据目录，再用匹配的旧包打开。

实测见 `RESULTS.md`，证据和截图在 `evidence/`、`screenshots/`，文件散列见 `build.json`。没有捆绑服务器档案、测试数据或私钥。方案已确认，用户验收和正式发布尚未进行。

工作区的本轮测试临时文件因自动审批策略未能删除，测试App/VM已停止；交付目录不含这些文件。
