## 1. 本次理解与具体方案

用户最初提供六项反馈并要求“根据我上面说的，推测一下我的意图，根据我的意图，做下一步的功能设计”。当时授权为只读核实和文档设计；随后用户明确要求实施完整方案，当前授权见第 3 节。用户的明确要求已写入产品 P-23 至 P-29；新反馈覆盖旧终端分屏要求，不能以 T-004 已确认来恢复用户已不要的交互。

推测目标：界面围绕“选服务器 → 切终端 → 操作”组织，内容占据主要空间；同类控件有同样样式，常用输入无需学习特殊操作，低频操作可通过右键找到并随时退出。独立窗口承担并排工作。

提交的推荐方案：

1. 统一现有深色界面为中性石墨色、单一低饱和蓝强调；按用户补充的 P-29，全部颜色独立为主题数据，核心和终端只消费语义令牌，状态色/阴影/遮罩/终端调色板也不硬编码。系统字体、间距、图标和控件状态统一，覆盖已有管理页与对话框。
2. 两层 Tab：上层服务器、下层终端；移除左侧终端列表及重复工具栏，新建放在 Tab 行。保留窄工具轨，不删除整个插件停靠能力。
3. Tab 不再生成省略号截断或更多图标；常见名称完整显示，超长裁切并可悬停/键盘查看完整名，多页用滚动与已打开页列表；原始用户名称不改写。
4. 取消终端左右/上下分屏；推荐同时取消底部终端停靠，中央单组 + 独立窗口。旧布局合并为 Tab，保留会话占位、名称与窗口归属，不用重建连接替代迁移。
5. 复制粘贴采用有选区 Ctrl+C 复制、无选区 Ctrl+C 中断，支持 Ctrl+V / Ctrl+Shift+V / Shift+Insert；右键打开菜单，显式保留远端鼠标模式和 IME。
6. 服务器/终端低频操作进入右键，键盘有等价入口；所有菜单覆盖外部点击、Esc、同触发器、窗口失焦、切页、拖动和对象销毁。跨原生 WebView 正确关闭、交还焦点，菜单期间终端画面保持可见。

以上中性深色方向、移除终端底部停靠、Ctrl+C 分工、右键菜单、长标题裁切与完整名称入口已随 r2 获得确认。后续如改为右键直接粘贴或不同视觉方向，先修订对应规则。

本次包含颜色独立定义与统一消费，为以后更换主题准备；不包含 T-005 的启动/设置、主题选择/导入/编辑或热切换入口、新插件和会话托管。总体架构遵循 P-22，不把终端业务转入核心。完整工作区/单视图拆合、默认关闭和托盘规则继续保留。

## 2. 工作区及源码核实

2026-10-25 设计时只读核实分支 `codex/t-004-server-tabs`、HEAD `557728f`。工作区已有大量 T-004 未提交代码、验证文件和 T-005 文档。实施时创建 `codex/t-006-workbench-interaction` 并备份初始文件至 `.local/t006-baseline/`，保留全部既有改动。下表是设计时源码事实；当前实现与证据见第 5 节。未读取用户业务服务器。

| 事实/风险 | 源码证据 | 对设计的影响 |
| --- | --- | --- |
| 服务器/终端 Tab 均有 Ellipsis，终端内部另有 MoreHorizontal；应用入口也是省略号 | `apps/desktop/src/server-tabs.tsx`、`app.tsx`、`plugins/terminal/src/terminal-view.tsx` | 去除多层更多入口，明确右键作用域与应用入口 |
| Tab 样式都使用 `text-overflow:ellipsis`；两份样式及 xterm 各有硬编码颜色 | 外壳 `styles.css`、插件 `terminal.css`、`terminal-view.tsx` | 同时处理标题与按钮，统一跨表面主题来源 |
| `terminal.sessions` 默认在工作区打开；终端声明 tab/dock/window 和 bottom | `plugins/terminal/manifest.json`，当前 0.2.1 / API 2 | 不只隐藏左侧 DOM；需要清单退役、旧布局和相应业务入口迁移 |
| 外壳仍有独立分屏工具栏、两个中央组、底部落点与“移到另一区域” | `apps/desktop/src/app.tsx` | 取消整套用户入口和旧请求支持，保留读取旧布局用于迁移 |
| 终端显式自定义键位只有 Ctrl+Shift+C/V；粘贴异步返回后直接调用当前 xterm | `terminal-view.tsx` 的 copy/paste 与 attachCustomKeyEventHandler | 不能从源码断言 Ctrl+V 实际一定失败；需定义标准键位、默认事件去重和异步目标代次检查，再做原生复现 |
| 外壳有全局 Esc；未见外部点击/失焦关闭菜单。终端菜单 Esc 只在菜单节点处理，打开时未见主动焦点进入 | `app.tsx`、`terminal-view.tsx` | 存在关闭路径缺口，不声称已经确认唯一根因；先记录复现矩阵再修复 |
| 菜单与模态共用 blocked，导致 NativeSurface visible=false 并调用 workbench.modal | `app.tsx`、`surface.tsx`、原生 `native.rs` | 临时菜单与真正模态需要区分，跨表面关闭不能只加 DOM 监听；保留真实原生画面与输入隔离 |

本轮已读取 apple-design、UI/测试规范、架构、工作台、服务器 Tab、终端规格及旧任务。技能落点在 F-CORE-008 第 5 节、F-TERM-002 第 4 节与 UI r8；不因技能建议交互原型而绕过仓库的先确认后编码规则。

## 4. 确认后的实施落点与验证

以下是已确认的修改边界；实际覆盖和未完成验证由第 5 节记录：

| 层次 | 修改范围 | 约束 |
| --- | --- | --- |
| 核心外壳 | 两层 Tab、长名/溢出、菜单、工具栏/分屏入口、现有对话框及管理页公共样式 | 不添加终端业务分支；核心负责通用展示 |
| 独立主题数据/解析层 | 完整颜色表、语义/状态令牌、终端调色、派生/回退；生成 CSS/JS/原生消费快照 | 具体色值仅在主题定义维护；同一构建可用不同主题数据，组件和业务代码不变 |
| 工作台/原生适配 | 单组布局、旧布局合并、跨 WebView 弹层/焦点生命周期、独立窗口标题与拖回 | 保持稳定视图/会话身份及现有迁移事务，真实原生验证 |
| SDK/公开契约 | 最小主题/菜单呈现与视图退役声明，版本兼容、过期请求/取消结果 | 编码前补齐具体 schema/错误码/版本矩阵到实施方案；在本次已确认语义内自主细化，超出范围再确认 |
| 终端插件 | 删除列表贡献及底部位置，迁移新建/重命名入口，键位与剪贴板去重/焦点保护，主题与本地菜单接入 | 业务及输入语义留在插件，核心只提供剪贴板/PTY/公共 UI |
| 验证与交付 | 旧用例适用调整，菜单/粘贴/布局迁移回归，独立 Windows 开发包及实际截图 | 只更新本次受影响预期，不覆盖 T-004 旧证据，不把浏览器结果当原生通过 |

优先验证菜单能退出与复制粘贴目标正确，再完成导航/视觉的整体验证及多窗口回归；这些是同一交付范围，不拆成多次审批。UX 与 IN 的准备、步骤、预期和清理由所属规格维护。类型/契约/布局测试验证逻辑，浏览器验证状态，Windows 原生验证剪贴板/菜单/IME/焦点，Linux/OpenSSH 验证真实输入与进程；缺失环境须保留未运行并注明解除条件。

建议最终试用顺序：打开两台服务器并新建/切换终端；检视两层 Tab 与长名；右键后点击外部/按 Esc；复制与粘贴并测试无选区中断；拆出/返回窗口，再验证关闭和托盘。实现后交付实际入口、版本/哈希、截图与测试证据，不以文字方案代替用户验收。
