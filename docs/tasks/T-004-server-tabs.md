## 1. 本次方案

用户要求：“不要显示顶部标题栏……服务器列表，作为顶部 tab 页。并且可以在新窗口打开，也可以合并回主窗口。你先理解一下我的意思，推断一下我想要的是什么。出一份功能设计。”

本轮直接授权理解、只读核实与文档设计，不包含应用、原型、测试和构建代码。推荐方案：窗口顶部用一行服务器工作区 Tab 和 Windows 控制；一级服务器、二级插件页面；整工作区可拖出/菜单移窗、跨窗移动及合并回主窗口；同一工作区唯一归属、会话继续。子窗口也可容纳多个服务器，完整服务器档案经“＋”搜索打开。详细操作、关闭与异常规则以 F-CORE-006 为唯一来源。

本次最需用户评审的推断：

1. 顶部每个 Tab 代表整份服务器工作区，拆合时带走其内部面板与分屏。
2. 顶部显示已打开工作区；全部档案保留在选择器，重复打开定位已有窗口。
3. 工作区子窗口也可放多个服务器 Tab；主窗口身份固定。
4. 关闭服务器 Tab / 工作区子窗口结束相应工作区；合并保留会话，主窗口关闭仍收起到托盘。
5. 根据用户继续追问插件实例和核心能力，建议保持每插件一个业务实例，并将当前终端专用外壳编排收敛到通用视图、命令、元数据和生命周期契约；本次核心与终端可能需要配套适配，不承诺旧插件零改动。具体增量见 F-CORE-006 第 6 节，尚待确认。

本次范围不包含新业务插件、工作区镜像、退出后服务或新增会话托管。功能设计及[代码修改方案 r1](../technical/server-tabs-implementation.md)已可评审：明确修改文件/模块、公共接口与来源、原生命中/跨窗拖动、布局 schema 2、插件 API 2 配套升级、迁移预算和测试入口。后续确认覆盖本次语义后内部实现细节自主完成；增加用户可见限制或改变已确认交互时先说明并确认受影响部分。

本轮交付供确认的代码方案包含：核心窗口/工作区/通用视图服务、终端一次公共接口适配、旧布局与旧包升级、已有终端流程回归和新多窗口验证，产物为独立 Windows 开发包。完整方案以所链接技术文档为准，不以本摘要替代接口与验收。
