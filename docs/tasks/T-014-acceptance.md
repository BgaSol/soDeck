# 网络隧道开发包使用说明

Windows 开发版 `2.0.0-dev.11`，网络插件 `0.1.0`，API/SDK `4.7.0`。包含终端 `0.7.1`、文件 `0.4.1`，支持多巴胺、浅色和深色主题。用户验收：待进行；本文件不是验收通过记录。

## 打开

在完整目录 `.local/dev/SoDeck-v2-T014-NetworkTunnel/` 中双击 `Start-SoDeck.cmd`。首次运行会在包旁建立独立 `data`，不要只复制 exe。需 Windows WebView2 Runtime；这是 debug 目录包，尚未提供正式安装器。

在服务器配置中设置 SSH 连接；需中转时选择上一台服务器，核心自动展开完整路径。打开最终访问节点的服务器工作区，再从插件工具入口打开“网络隧道”。

## 五步验收

1. **端口转发**：新建端口转发，指定本机端口和“从最终 SSH 节点看见的”目标地址、端口；保存并启动。普通客户端直接连接页面显示的本机地址。目标填 `127.0.0.1` 代表最终 SSH 节点自身。
2. **内网代理**：新建内网代理，入口可设为 `127.0.0.1:10808`。启动后在浏览器设置 HTTP 或 SOCKS5 代理，地址栏输入远端服务原地址，例如 `http://192.168.1.18`。确保该地址未被浏览器的内网代理例外绕过。无需在 SSH 主机上部署额外代理程序。
3. **切换目标与检查**：保持同一代理地址，访问另一远端服务；在详情输入测试主机/端口，分别检查 HTTP CONNECT 或 SOCKS。检查成功只表示目标 TCP 可连接，不保证网页、TLS 或登录成功。需远端解析域名的命令行示例使用 `socks5h`。
4. **运行与配置**：编辑保存中的规则，确认当前运行仍使用旧快照；明确重启后应用新配置。切换视图、移出/合并窗口或收起到托盘，应保持运行。关闭该视图或停止规则应释放入口，其他规则继续工作。
5. **退出重开**：使用 App 的退出入口，确认连接结束；重新启动后配置仍在，规则不会自动运行。自动恢复默认关闭，可在规则中明确启用；链路故障后最多重试三次，不重放原业务请求。

入口只监听本机回环，同一内网代理端口支持 HTTP、HTTPS CONNECT 与 SOCKS5 CONNECT。SoDeck 不修改系统/浏览器代理设置。端口冲突请修改规则或释放端口，不会静默换端口。停止代理后，需要自行恢复客户端代理设置。

## 验证与边界

工程实测及证据见 `RESULTS.md`，目录包版本和 SHA-256 见 `build.json`，实际界面见 `screenshots/`。在源码文档中对应 `T-014-results.md`。

本轮验证了真实 Windows App、Debian 多节点及独立内网、Windows 临时 loopback OpenSSH、真实 Chromium、负载、协议故障、独立插件更新和旧插件兼容。Windows SSH 结果不代表独立 Windows VM/LAN 已验证。TCP 之外的 UDP、VPN、全系统路由及退出后运行不在本版范围；远端服务的可达性由最终 SSH 主机网络决定。
