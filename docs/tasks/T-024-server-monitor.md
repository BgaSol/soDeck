## 1. 本次方案

用户希望新增插件，查看“当前tab页连接远端服务器的资源占用情况”，要求先理解、推断并设计需求。已明确的是插件形态、远端对象和本轮设计授权；不把推荐细节或其他任务授权当成本任务编码确认。

推荐解释：顶部服务器Tab决定当前观察对象，用户在终端操作时可并排看到该机器CPU、内存、磁盘和网络变化；不是单个终端进程或SoDeck自身的资源。

本次建议：

1. 独立资源监控插件，右侧面板默认展示概览，可收起/移入中央/弹窗；每工作区单实例，独立窗口固定原服务器。
2. CPU/负载、内存/Swap、文件系统容量、块设备I/O、网卡收发与在线时长；默认2秒刷新，容量30秒，最近10分钟内存趋势。
3. 通过核心连接与独立只读通道采集，遵守直连/跳板/SOCKS路径及P-14；不干扰终端、不要求安装Agent。客户端先Windows，远端先Linux，BusyBox按能力降级。
4. 停止/隐藏暂停采集，缺失与0、过期与实时区分；不做长期后台监控或跨启动历史。进程排行、GPU/容器、告警、导出和其他远端OS后置。

与现有功能的关系：T-019负责SoDeck通信，不能用其连接带宽代替远端网卡负载；文件插件仍拥有目录/挂载界面，本插件独立解释其指标，不跨插件调用；T-023设置provider不作为本轮依赖。

本次代码方案：新增monitor独立包与controller/collector/metrics/UI模块；公共层提供有界exec客户端、公开单调clock、通用系列图表与默认视图不抢占。T-023已获实施授权并占用API5.1，本任务顺接API/SDK5.2、公共UI1.6、monitor0.1.0；数据库schema6/观测schema2不变，保留T-023设置/外观变化。已有插件无需为监控业务重写或统一升级。

采样固定fast与slow两lane、总exec≤4（fast3/slow1）、最多8个可见目标同时采样；每目标64网卡/64设备/128挂载、最多64个完整controller，超额排队/partial/容量提示；每controller缓存4MiB、全插件32MiB。容量仅根/选中及明细可见最多8行，至少30秒；时间/取消/迟到回执处理与实际测量场景见代码方案§4/8。上述限制及公共行为增量随本稿整体提交确认。
