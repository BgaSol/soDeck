## 2. r1 提交方案

推荐先完整交付 **本机 → SSH 跳板 A → 目标 B**，多个目标可引用同一 A 档案。目标表单选择直接/经跳板，展示路径、两端独立认证。无候选时可保存并选用 A，不打开 A 工作区。打开 B 自动首终端仍按 T-009；文件插件独立使用核心连接，无终端依赖。

核心持有有序路径快照、传输、主机信任、凭据、租约、阶段/错误和释放；插件持有自己的终端/文件业务。不同目标首轮不共享底层 A socket；同目标工作区多消费者按完整路径复用。该取舍保留资源复用且限制互相影响，跨目标连接池后续按实测需求设计。

改路径只影响新连接，已有会话维持快照；路径身份改变时重新确认目标身份/凭据；引用中的跳板不能直接删除。断线无静默直连或输入重放。界面采用已读取的 apple-design：渐进展开、路径邻近选择、逐段反馈、焦点/键盘、缩放和主题一致，具体规则及草图在功能规格。

本轮包含 Windows/隔离 Linux/OpenSSH、密码及私钥混用、终端/文件接入、错误/取消/资源、旧直连与 API 4 插件兼容、独立开发目录包验证。多层跳板、代理、用户端口转发、Agent/MFA、v1 导入、其他客户端平台和正式发布后置；不扩大 T-012 视觉任务授权。

需要确认的主要选择是单层完整交付及上述用户行为；不要求用户先回答 Rust 模块或命名细节。若实际需求包含“跳板本身还需跳板”，应在实施前把范围改为多层并补相应设计与测试。

## 4. 确认后的实施规划

1. **契约/存储与路径解析**：新增非秘密路径模型、原子引用校验、完整依赖快照、信任上下文和数据迁移；版本化路由查询/阶段和认证载荷，旧接口保留形状。固定采用的增量能力版本，检查与当时工作区公共通信的兼容。
2. **传输关口**：在 `crates/core` 内提取连接路径、transport/转发驱动及生命周期，保留当前 SSH/PTY/Remote I/O 原语；验证真正的嵌套 SSH、远端 DNS、转发拒绝、背压及可取消清理。失败则记录证据，不能以 shell 内 ssh 充数。
3. **核心接入**：`lib.rs`/连接协调与 `remote_read.rs` 按完整路径复用、观察和释放；变更/删除看保存和运行两类依赖；`store.rs`/`secrets.rs` 处理上下文与迁移；资源和调用记录能追溯节点阶段。
4. **外壳与插件**：服务器表单/选择器、认证协调与弹窗分离 workspace/target/hop；新能力经公开 SDK/契约提供。终端仅呈现连接失败与重试，文件保持独立租约及严格代次跟随；不得导入核心内部模块。
5. **按功能流程验证并交付**：增量用例→既有直连/首终端/目录跟随/移窗回归→Windows 原生→独立目录包；提供经跳板的真实终端+文件截图、资源释放证据、限制与 3–5 步用户验收入口。

预计涉及核心模型/存储/凭据/SSH/Remote I/O，外壳服务器与认证服务，公开契约/SDK，终端和文件的呈现/回归，测试夹具与包说明。详细内部模块划分在确认范围内自主处理，不重做总体架构；任何主版本破坏、跨平台承诺或替代外部 SSH 方案须先更新并确认。

测试环境和清理以 F-CORE-014 §6 为准。既有单 SSH 协议夹具或 T-008 的 Linux VM不能直接当作“已具备隔离跳板网络”；确认后先验证其拓扑，必要时在专用 VM 内创建受控多个 sshd/网络。必须证明 B 仅从 A 可达、域名仅 A 可解析。业务地址和日常环境不参与故障测试。

## 6. r2：取消单层限制，支持任意有限级跳板

### 6.1 最新要求与修订责任

2026-10-26 用户指出：“你只兼容了一层跳板，逻辑都是一样的，你为什么不做成无限跳板？”这是明确的多级能力要求。单层是 AI 原方案主动收缩的范围，不是 SSH 限制，也不应把这一设计取舍归责于用户此前确认。

目标确定为任意有限级、无循环的 SSH 路径；每台服务器仍选一台直接前驱，前驱可继续引用跳板。无需新增插件逻辑或让用户逐层打开终端。`本机 → A → B → C → D` 与直连使用同一核心模型。

只读核实后已更新具体方案与测试，当前未修改应用、测试或构建代码；r1 包仍为单层。多级需求与 T-014 的多机中转一致，SSH 基础路径由本任务维护，T-014 的固定转发/HTTP/SOCKS 插件功能仍按其自身方案推进。

### 6.2 本次可评审结果与影响

完整行为、预算、兼容与测试的唯一来源为 [F-CORE-014 r3 §7](../core/ssh-jump.md#7-多级路径修订方案r3替代-r1-的单层限制)：

- 界面继续选一台跳板，可选已使用跳板的档案；完整路径可展开，新增子步骤同样支持多级，当前认证/失败节点明确到 k/N。
- 复用、凭据与信任按完整路径及有效前缀处理；中间变化影响下游新连接，现有会话保持原快照。
