## 1. 用户原意与推荐方案

用户要求：“终端切换时候，目录跟着切换，终端 cd 时候，目录也跟着切换”，并要求先理解意图、给出功能设计。本轮只设计和维护文档，不包含应用、原型、测试或构建编码；此前 T-008 的实施授权不自动覆盖本次新增联动。

推测目标：以正在操作的终端为工作中心，让文件侧栏始终能展示这个终端所在位置，减少切换终端后重新找目录的操作。同一服务器的多个终端可以处于不同目录，文件树跟随当前终端，而不是为整台服务器保存一个“终端目录”。

推荐行为：

1. 每服务器仍只有一个文件树；新工作区默认开启“跟随终端”。终端 A 位于 `/srv/app`、B 位于 `/var/log`，切换 A/B 时文件树定位各自最近确认的工作目录。
2. shell 完成目录改变、重新显示提示符并报告实际目录后，文件树展开必要祖先、选中该目录、展开一层并滚动到可见位置；树根保持 `/`，既有其他分支保留。不把某个终端当前路径变成全局服务器路径。
3. `cd` 失败不跳；`cd ..`、`cd -`、`pushd/popd`、别名及函数以实际结果为准；复合命令执行完后跟随最终报告的目录。后台终端只更新自己的最近目录，不拉动当前文件树。
4. 文件工具栏增加“跟随终端”开关及“定位到终端目录”一次性动作，并显示来源终端和状态。手动浏览允许暂时离开；相同目录的重复提示符不把树拉回，下一次真实目录改变或主动切换终端才重新跟随。需要持续停留时关闭跟随；一次性定位不改变开关。
5. 联动只从终端指向文件树。点击树不会给终端发送 `cd`；同步不抢终端焦点、不打开隐藏文件面板、不发起新的认证，保持原来的输入及连接规则。
6. 首期客户端/远端范围延续 Windows + Linux/OpenSSH。代码方案推荐先验证 Bash 5.1/5.2 常规配置的会话内环境集成；Zsh 5.9 本批验证普通终端降级，自动跟随为后续候选。登录配置/钩子兼容有明确采用关口，未通过不得默认启用或宣称完成。tmux/screen、嵌套 SSH、容器 shell、`sudo -i`/`su` 及 chroot 不自动穿透，不把内部路径套到外层文件树。

以上默认值、手动浏览规则和兼容范围是推荐设计，尚未获得用户确认。一次性“当前目录定位”也只使用已确认的报告，不在用户正在输入的终端偷偷执行 `pwd`。

## 4. 本次代码决策与实施关口

- 用类型化 RPC、最新状态订阅、有界流三条路径；新增纯通信 crate 和无 DOM SDK，共用身份/作用域/修订/容量，不建任意事件转发或共享业务 store。首批迁入目录与呈现两种状态，证明复用。
- 核心 DirectoryContextService 持有公开上下文，工作台持有来源选择；终端只报告事实，文件 FollowController 负责定位。目录选择与键盘焦点分离，快速切换/手动提交的迟到结果不回写。
- PTY 增加同所有者非破坏观察，worker 解析；原 UI 显示 read/ack 与迁移不变。独立缓冲超限显式 gap，不堵主终端。
- Bash 通过通用 PTY exec 启动候选，保持真实 login shell、不写 dotfiles；DR-02/07 先验证原配置和提示符/退出码等。候选失败不得降低预期交付，需要改变启动语义时先更新方案确认；可继续无依赖通信工作。本轮不启动实验。
- 路径映射核对实际 PTY 进程身份、根、挂载命名空间及各自 SFTP 视图；受限/未知明确降级，不能只比较 hostname 或独立 exec 的 pwd。
- 计划 dev.6 / API、SDK 4.2 / terminal 0.5.0 / files 0.2.0；旧响应投影和旧包保持，跨版本组合分别验证。容量、时限和先通信后联动的实施顺序详见代码方案。
