# T-009：全新启动与打开服务器自动连接

任务状态：待验收 · 任务类型：功能
更新日期：2026-10-26 · 方案：r2
本轮授权：2026-10-26 用户在 r2 方案后明确答复“可以开始改了”，授权按本方案实施应用、测试和本地构建；不包含 Git 提交、推送或发布。

## 1. 用户原意与方案

用户反馈：“现在每次打开，都会有上次的空会话，这不是我期望的，每次启动，我希望启动一个全新的程序，不要保留上次的历史。你理解一下我的意思，推测一下我的意图，做一下后面的功能设计。”明确目标登记为[产品 P-33](../product.md)。

同日用户补充：“每次创建服务器 tab 页的时候，至少要开一个终端，连接到服务器”，并要求继续理解意图、完善设计。登记 P-34，替代 r1 中打开工作区后另点新建的建议；不把补充需求记为对其他边界的确认或编码授权。

推断：用户希望每次开始工作时有一个干净、可自主选择的入口，避免手动关闭没有真实连接的旧终端。推荐将“配置长期保留、工作现场仅限本次运行”作为全应用统一规则，不只过滤空终端。

推荐结果：

1. 完整启动只有一个可见主窗口，服务器 Tab、终端页、独立窗口与待连接操作均为空；正常退出、崩溃和插件更新后启动一致。
2. 保存服务器档案、记住的凭据、主机信任、已安装插件与已有偏好；主窗口尺寸/位置可保留，不保留隐藏状态。诊断/调用记录按原规则保存，远端 shell 历史不处理。
3. 空态提供“打开服务器”；无档案时提供“添加服务器”。用户新建服务器工作区即自动创建一个首终端并连接，认证就绪后直接使用；App 启动本身仍不连接，不弹恢复提示。
4. 同次运行切换、拆合、表面恢复与托盘继续保留工作；P-18 的主窗×收起到托盘不变，明确退出才结束 App 持有资源。
5. 停止跨启动保存工作现场，旧工作台快照退役；清理失败也不恢复旧会话，不清空配置或整个数据目录。
6. 首终端只随工作区创建触发一次，已有工作区定位/切换/拆合不增开；关闭服务器再打开是新创建。建议允许用户关闭最后一个终端，不自动补回。
7. 失败/取消保留本次首终端页并支持原位重试；不绕过认证/主机信任，不因自动打开突破容量预算。新增表单建议“保存并打开”，编辑仅保存，部分保存失败不触发连接。

功能和逐项测试由 [F-CORE-010](../core/clean-start.md) 维护。已读取并使用 `apple-design`，采用单一主操作、稳定空态、明确焦点和即时反馈；具体落点见该规格 §2.3。本轮无编码原型。

## 2. 实际行为与影响

核实基线：2026-10-26，`v2` 分支，HEAD `d550c76`；开始时已有 T-008 文档修改及未跟踪文件，本次在其基础上追加相关索引，保留原内容。以下为只读源码结论，未对用户正在运行的 App 进行复现或改动：

| 核实内容 | 证据与含义 |
| --- | --- |
| 启动读取旧工作台，再恢复插件视图及窗口 | `apps/desktop/src-tauri/src/app.rs` 的 `Workbench::load`、`lifecycle.restore` 与子窗口/独立视图重建流程 |
| 布局文件含视图、工作区、窗口和活动项，运行资源不持久化 | `apps/desktop/src-tauri/src/workbench.rs` 的 `Workbench`、`load`、`save`；运行/加载中的旧视图转为 ended |
| 终端恢复得到一个空的已结束会话模型 | `plugins/terminal/src/worker.ts` 的 `lifecycle.restore` 新建 ended session，PTY/stream/lease/connection 为空；与用户所述空会话一致 |
| 退出确实关闭资源，但仍保存工作台 | `app.rs` 的 `shutdown` 调用 core.shutdown 后 save；因此只改退出清理不足以覆盖崩溃或旧快照 |
| 已有空态与服务器选择器 | `apps/desktop/src/app.tsx` 的 welcome 及 workspace-empty；新设计可复用容器和表单 |
| 同数据目录第二个进程由锁拒绝 | `app.rs` 的 `try_lock_exclusive`；本轮不把第二次双击描述为已实现“显示现有窗口” |
| 打开工作区当前没有首终端初始化命令 | `workbench_services.rs` 的 `workspaces.open` 创建默认 `workspaceEntries` 视图；终端 manifest 的 workspaceEntries 为空，primary 新建命令不自动执行 |
| 当前终端先连接/创建 PTY，之后创建视图 | `plugins/terminal/src/worker.ts` 的 `open`；r2 的立即显示首终端加载/错误页需调整插件流程，不能仅由外壳加一次直接 PTY 调用 |
| 新增和编辑成功目前都调用 openServer | `apps/desktop/src/app.tsx` 的 ServerDialog.onSaved；r2 建议区分新增“保存并打开”与编辑“保存”，避免编辑关闭中的档案隐式创建 Tab 并连接 |
| 现有终端预算为全 App 最多 8 个，包含正在创建的操作 | `worker.ts` 的 sessions.size + opening 校验；自动首终端不扩大额度，达到上限应显示目标未完成并允许释放后重试 |

架构沿用 P-22：核心控制启动、窗口和通用状态寿命，插件管理业务模型与偏好；不将终端逻辑搬入核心，不删除同进程的表面恢复。T-005/T-008 可独立评审，本功能不把它们的设计自动纳入实现授权。
