# 服务器管理设计方案

状态：目录服务与页面已实现，连接未实现。日期：2026-11-05。

## 1. 这一版交付什么

核心维护一份可长期保存的服务器与 SOCKS5 代理目录，支持新增、编辑、复制、删除、搜索和服务器分组；录入独立认证资料，保存有序的 SSH / SOCKS5 混合多层路径。关闭并重开应用后，资料、顺序和引用关系保持。修订 r2：按用户补充纳入 SOCKS 代理跳板，替代初稿的纯 SSH 路径。

本轮的“支持多层跳板”指能够完整编辑、校验和保存路径。不会发起 TCP、SSH、DNS 查询或登录，不测试连通性，不创建终端，不显示在线/离线状态。保存只表示资料保存成功。连接与实际多跳传输在下一轮实现。

服务器、代理目录和凭据存储属于核心。核心无业务插件时仍可使用；本轮不添加插件接口、终端视图或网络代理实现，不修改核心与插件的独立分发方式。这里管理的是已经存在的 SOCKS5 服务地址，不启动或部署 SOCKS 服务；未来由核心建立本地 SOCKS 监听属于另一项网络能力。

## 2. 旧版表单的保留与收敛

参考旧仓库 `apps/desktop/src/connection-home/` 下实际使用的 `ssh-form.tsx`、`credential-fields.tsx`、`proxy-fields.tsx`、`access-path-fields.tsx`、`route-step-fields.tsx`、`group-fields.tsx`，以及 `docs/design/connection-editor-refinement.md` 和 `docs/core/mixed-route.md`。旧稿仅提取纯 SSH 部分有遗漏，本修订补齐混合路径。

字段和顺序沿用旧版，重写为当前 DOM/TypeScript 界面的实现；不移植旧版 React、复杂草稿恢复和连接状态机。

| 顺序 | 分区 | 字段与行为 |
| --- | --- | --- |
| 1 | 服务器 | 主机地址与 SSH 端口同行，下一行用户名。端口默认 22。地址支持域名、IPv4、IPv6。 |
| 2 | 身份认证 | 密码/私钥二选一。密码显示登录密码；私钥显示本地文件路径、选择文件、私钥口令。均可留空，未来连接时再提供。 |
| 3 | 连接路径 | 直接连接/经由中转。按顺序添加 SSH 跳板或 SOCKS5 代理；支持选择、上移、下移、移除。最终 SSH 目标固定在末尾。 |
| 4 | 名称与分组 | 显示名称可留空，按主机地址自动生成，非 22 端口带端口，IPv6 加方括号。分组可选未分组，允许创建分组。 |

认证区域保留“在此设备上记住密码/私钥口令”。新建资料和切换认证方式时默认勾选，编辑已有资料时沿用实际保存状态；未勾选的输入只在当前核心进程内存中有效，退出即清除。连接时补填凭据也默认勾选记住，整条连接成功后将新密码、私钥路径或口令写回对应服务器/代理资料，覆盖旧凭据；补填时取消勾选则仅本次尝试有效，不修改原保存值。认证失败、取消、拒绝指纹或后续节点失败均不保存。用户已明确选择：**记住的密码和口令直接写入本机文件，不加密，不接系统凭据库，不增加主密码或解锁流程。** 私钥文件仍保存在用户选择的位置，本轮不复制或托管私钥内容；目录保存其路径，口令按勾选结果保存。

密码和私钥路径允许缺省，不妨碍保存服务器目录。编辑已有凭据时不回填秘密：显示“已保存，留空保持”，另有明确的“清除已保存凭据”；更改认证方式后旧凭据不用于新方式。

SOCKS5 表单同样沿用旧版：代理地址与端口（默认 1080）、无认证/用户名和密码、代理用户名、代理密码及记住选项、代理名称。代理密码与 SSH 密码分别保存。代理可先在“SOCKS5 代理”目录管理，也可在路径节点中原位“新建代理 → 保存并选用”；取消父服务器草稿不删除已保存代理。页脚只有“取消”和“保存服务器/保存修改”，不出现“保存并连接”。

## 3. 页面与交互

- 无独立标题栏；“服务器”作为核心工作台的常驻页。状态、消息与设置保留在右上角，插件管理留在设置内。
- 页面主体为服务器列表：名称、账号与地址、分组、直连/跳板数量；用认证资料状态表达“已保存/连接时提供”，不以颜色冒充连接成功。
- 页面内提供“服务器 / SOCKS5 代理”两个目录入口；代理列表展示名称、地址、认证方式与引用数量，支持新增、编辑、复制和删除。代理没有 SSH 用户名、私钥、分组或自己的隐式路径。
- 点击一行选中并展示详情，不发起连接。右侧详情展示账号、地址、认证方式和完整路径；路径中的节点可以定位到对应服务器。
- 搜索名称、地址、用户名和分组；分组筛选与名称排序保持简单。默认按名称排序，不提供拖拽排序、标签体系或批量编排。
- 新增/编辑使用居中的表单浮层，保留原列表上下文。正文可滚动，标题与底部操作固定；最大宽度约 720px，适配当前应用的 720×480 最小窗口。
- 复制生成新的服务器与步骤 ID，保留普通资料、分组及节点引用，名称加“副本”；不复制记住的密码、口令或临时秘密。复制代理同样生成新 ID 且不携带密码。
- 未保存时关闭、切换或取消，先选择“继续编辑/放弃修改”。保存失败保留输入；重复点击保存不产生多条记录。
- 被其他路径引用的服务器不能直接删除，提示依赖它的服务器列表，先编辑那些路径。普通删除确认只删除 SoDeck 档案及相应保存凭据，不操作远端服务器或用户的私钥文件。
- 分组先采用单层结构；名称可编辑，删除分组时服务器移到“未分组”，不会删除服务器。新建分组为单独保存，取消服务器表单时保留已创建的分组，并在创建处说明。

采用现有多巴胺主题演示：奶油底、黄色选中、薄荷绿点缀、深色轮廓、无投影。正式实现使用现有主题变量，同时支持系统、浅色和深色。

## 4. 数据结构：服务器资料与有序路径

采用四种概念：服务器记录、代理记录、单层服务器分组、服务器的有序中转步骤。服务器与代理通过稳定 ID 引用；步骤另有固定 ID，排序后仍能识别同一节点，不通过名称、IP 或数组位置关联。

```ts
type ServerCatalog = {
  schemaVersion: 1;
  revision: number;
  groups: { id: string; name: string }[];
  servers: ServerRecord[];
  proxies: Socks5ProxyRecord[];
};

type RouteStep =
  | { id: string; kind: "ssh"; serverId: string }
  | {
      id: string;
      kind: "socks5";
      proxyId: string;
    };

type Socks5ProxyRecord = {
  id: string;
  name: string;
  protocol: "socks5";
  host: string;
  port: number;
  authentication:
    | { type: "none" }
    | { type: "usernamePassword"; username: string; savedPassword: string | null };
  createdAt: string;
  updatedAt: string;
};

type ServerRecord = {
  id: string;
  name: string;
  groupId: string | null;
  protocol: "ssh";
  host: string;
  port: number;
  username: string;
  authentication:
    | { type: "password"; savedPassword: string | null }
    | {
        type: "privateKey";
        privateKeyPath: string | null;
        savedPassphrase: string | null;
      };
  route: RouteStep[];
  createdAt: string;
  updatedAt: string;
};
```

ID 由核心生成，创建后不因改名、换 IP 或改分组而改变。时间为 UTC RFC 3339。`revision` 是目录的单调递增修订，用于拒绝旧表单覆盖更新后的目录；不是另外一套发布版本。前端草稿单独维护，未保存不改目录。

`protocol: "ssh"` 明确本轮记录类型，不设计其他协议的空接口。`authentication` 使用可区分类型，避免私钥模式同时残留密码字段。没有记住的密码或口令为 null；勾选记住时对应字段直接保存原文。不另建凭据引用表或第二个凭据文件。

以上是核心内部的磁盘数据类型。发给界面的 `ServerView` 只投影普通资料、认证方式、私钥路径及 `hasSavedSecret` / `hasSessionSecret`；不包含 `savedPassword` 或 `savedPassphrase`。插件也不能通过普通目录查询取得密码。界面提交新输入与磁盘读取模型分开，不直接序列化内部记录给前端。

### 路径的唯一语义

每条服务器记录的 `route` 是从本机到目标之前、按访问顺序排列的完整中转列表。空数组表示直连。目标隐含为记录自己，不再在数组尾部重复保存。`kind` 明确区分 SSH 服务器引用与 SOCKS5 代理引用，不通过 ID 文本猜协议；不再使用初稿的 `jumpServerIds`。

```json
{
  "schemaVersion": 1,
  "revision": 7,
  "groups": [{ "id": "group-prod", "name": "生产环境" }],
  "servers": [
    {
      "id": "server-a", "name": "入口跳板", "groupId": "group-prod",
      "protocol": "ssh", "host": "203.0.113.10", "port": 22,
      "username": "ops", "authentication": { "type": "password", "savedPassword": null },
      "route": [],
      "createdAt": "2026-11-05T00:00:00Z", "updatedAt": "2026-11-05T00:00:00Z"
    },
    {
      "id": "server-b", "name": "内网跳板", "groupId": "group-prod",
      "protocol": "ssh", "host": "10.20.0.8", "port": 22,
      "username": "ops", "authentication": { "type": "password", "savedPassword": null },
      "route": [{ "id": "step-b-a", "kind": "ssh", "serverId": "server-a" }],
      "createdAt": "2026-11-05T00:00:00Z", "updatedAt": "2026-11-05T00:00:00Z"
    },
    {
      "id": "server-c", "name": "生产应用", "groupId": "group-prod",
      "protocol": "ssh", "host": "10.30.0.21", "port": 22,
      "username": "deploy", "authentication": { "type": "password", "savedPassword": null },
      "route": [
        { "id": "step-c-a", "kind": "ssh", "serverId": "server-a" },
        { "id": "step-c-p", "kind": "socks5", "proxyId": "proxy-p" },
        { "id": "step-c-b", "kind": "ssh", "serverId": "server-b" }
      ],
      "createdAt": "2026-11-05T00:00:00Z", "updatedAt": "2026-11-05T00:00:00Z"
    }
  ],
  "proxies": [{
    "id": "proxy-p", "name": "入口主机本地代理", "protocol": "socks5",
    "host": "127.0.0.1", "port": 1080, "authentication": { "type": "none" },
    "createdAt": "2026-11-05T00:00:00Z", "updatedAt": "2026-11-05T00:00:00Z"
  }]
}
```

上例中，A 的路径为本机 → A，B 为本机 → A → B，C 为本机 → A → SOCKS5 P → B → C。这里只演示配置，不声称示例网络一定可达。

**引用 SSH 节点只提供它自己的地址、用户名、认证方式与凭据，不会递归展开它自己的 `route`。** 因而编辑 C 时，界面明确列出 A、P、B 三站。只选择 B 就是本机 → B → C，不会暗中补上 A。SOCKS5 记录只提供端点及代理认证，实际访问来源由它在路径中的位置决定。选择器展示名称与地址，完整路径预览保持可见。

这个选择让同一台 SSH 跳板或代理可以出现在不同路径、不同位置，不需要复制它的密码和地址，也不会因节点自己的连接路径改变而悄悄增加其他节点。每条实际路径就是一个有限数组，没有单级、两级或三级的业务上限。允许纯 SSH、纯 SOCKS5 中转、SSH→SOCKS5、SOCKS5→SSH、连续 SOCKS5 和更多混合；最终目标仍是 SSH 服务器。

### 地址与域名解析的含义

- 第一站从运行 SoDeck 的本机访问。
- 紧跟 SSH 的节点从该 SSH 主机所在网络访问；未来通过 SSH TCP 转发建立下一段，不要求跳板打开 shell。
- 紧跟 SOCKS5 的节点从该代理的出口网络访问；连续代理逐站 CONNECT，不能绕过前一站。
- 节点地址为 `127.0.0.1` / `::1` 时，归属是它的**紧邻前一站**的访问环境。SSH A → SOCKS5 `127.0.0.1:1080` 指 A 上的代理；放到第一站则指 SoDeck 本机。SOCKS5 后的回环指前一代理出口环境，不能一律解释为最近一台 SSH。
- 按用户补充固定为逐站远端解析：本机只解析直接访问的首站；SSH 转发保留下一站域名，由该 SSH 主机解析；SOCKS5 CONNECT 发送下一站域名，由该代理解析。连续代理时，前一代理解析后一代理地址，后一代理再解析其下一站。IP 字面量无需 DNS。不提供本机解析选项，步骤中也不保存 DNS 策略字段。
- 排序、替换、移除后立即重算每站访问来源和回环说明。错误来源不能自动降级成直连或切换 DNS。这些是未来连接层遵循的语义，本轮只展示与保存，不执行网络操作。

不采用 `jump1/jump2/jump3` 固定字段，也不同时存一份嵌套链、一份父节点和一份展开链。名称、地址及跳板数量全部从 ID 引用派生；不把列表展示文案当成第二份事实。

### 保存时的基本检查

1. 地址和用户名非空，端口为 1–65535 的整数。允许域名及 IPv6，不要求本机能解析或到达。
2. 引用的分组、SSH 服务器和 SOCKS5 代理必须存在；路径不包含 SSH 目标自己，不重复同一 SSH 服务器 ID，步骤 ID 也不能重复。
3. “经由中转”至少选择一站；未选完时可继续编辑，不能保存成残缺路径。SOCKS5 的无认证不要求账号；账号认证要求用户名，密码可留待未来连接时提供。
4. 不按名称或 IP 去重：不同网络里可以存在相同私网地址；重名在选择器里用账号、地址和分组区分。
5. SOCKS5 允许重复引用同一代理记录：同一 `127.0.0.1:1080` 在不同来源可能指不同服务。每次出现用步骤 ID 和有序前缀区分，不能只按 IP/端口或 proxyId 判定循环。实际可达性只能在下一步连接时验证。
6. 单次请求和文件读取采用常规字节/资源限制，不把资源预算写成固定跳数上限；超限如实报告，不能静默截断路径。

已引用节点的名称变化即时反映到所有路径。地址、账号或认证方式变化时，在保存前列出受影响的目标；其后续连接将使用新资料。凭据不会因改名、改分组而清除；更换目标地址、账号或认证方式时不沿用旧秘密，界面要求重新提供或留待连接时输入。

下一轮连接必须逐节点验证主机身份、绑定所选路径的凭据上下文，再使用秘密；不能因本轮资料有效就假定身份已受信任。连接快照、指纹库和断线状态均在连接阶段设计实现，不塞进服务器目录。

## 5. 存在哪里

沿用当前核心使用 JSON 文件的方式，新增 `<应用数据目录>/servers.json`，包含整个 `ServerCatalog`。服务器、分组与共享代理在同一个文件内提交，引用检查与删除可一次提交。当前阶段不引入 SQLite、ORM、配置服务或跨文件事务框架。当前仍为设计，`schemaVersion: 1` 直接采用混合路径，无需为未发布初稿增加迁移代码。

| 数据 | 保存位置 |
| --- | --- |
| 服务器/代理普通资料、分组、混合路径、各自记住的密码/口令 | `servers.json`，按用户选择明文保存 |
| 上一份有效目录 | `servers.json.bak`，只保留一份，同样可能含有明文密码/口令 |
| 私钥内容 | 用户选择的本地文件，不复制进 JSON、不自动搬动或删除 |
| 未勾选记住的秘密、未保存草稿 | 核心/界面对应的进程内存，按生命周期清除 |
| 搜索词、当前选中项、浮层状态 | 界面状态；不属于目录，不记为服务器修订 |
| 未来连接、PTY、通道、错误与耗时 | 连接模块的运行状态，本轮不保存这些状态 |

应用数据目录通过现有平台适配获取，不使用开发机绝对路径，不写入安装目录。私钥路径是本机路径，服务器 host 是远端地址，两者分开处理。复制目录文件会连同记住的密码/口令一起复制，但不会复制私钥文件；跨设备导入导出本轮不做。

### 目录写入与恢复

- 复用现有应用数据单实例锁；核心串行完成目录变更。保存传入基础修订，不匹配时保留草稿并提示重新载入，不静默覆盖。
- 在内存副本上校验完整变更，写同目录临时文件并同步，再以跨平台原子替换提交；成功后才更新内存和界面。保留上一份经过校验的备份。
- 文件不存在按空目录首次创建。JSON 损坏、引用无效或 `schemaVersion` 不支持时，显示错误并保留原文件，禁止用空列表覆盖；备份恢复由用户明确触发。
- 这是新的独立文件，不更改现有插件、消息、主题格式。版本字段用于今后必要的迁移，不提前做迁移框架，也不自动导入旧 soDeck-v2 数据。

### 密码保存与编辑

密码和私钥口令属于服务器表单的本地资料管理，不建立 SSH 连接。秘密只经明确的保存命令送往核心，不出现在公开目录快照、事件、日志、消息或错误正文中。界面只接收“已保存/本次运行可用/连接时提供”等派生状态。

保存命令明确表达保留、替换或清除秘密；不能拿密码框的空字符串同时表示三种动作。编辑已保存记录时，保持记住且留空表示保留原值；有新输入表示替换；“清除已保存凭据”同时清除磁盘与本次内存值。取消记住后，提交成功才从磁盘移除对应字段，可将仍适用的当前秘密保留到本次进程内存。更换身份时旧秘密不迁移到新身份。

普通资料和持久密码在同一次 JSON 原子写入中提交，不需要跨系统事务。写入失败时保留旧记录及表单输入，不显示成功。删除和复制沿用同一份目录变更规则；复制默认清除秘密。

备份是一份完整旧目录，因此清除当前密码后，上一份备份可能仍含旧值。“清除”不承诺清除历史备份或安全擦除磁盘；需要连备份一起移除秘密时作为明确的后续操作处理。本轮无凭据服务、加密依赖、解锁界面或密钥迁移。

## 6. 最小代码职责与接口

- `servers.rs`：服务器/代理目录类型、资料变更、混合路径校验、依赖查询；不调用 SSH 或 SOCKS。
- `servers.rs` 持有目录存储；复用 `storage.rs` 的同目录临时文件、同步与替换写入。核心快照汇总目录错误。
- `servers.rs` 内区分磁盘模型、只读界面模型和表单变更；进程内临时秘密按服务器 ID 管理，退出释放。普通目录查询不能返回秘密。
- `main.rs`：只注册桌面命令。`core.rs`：持有目录服务并发布更新；不把表单状态放进核心。
- `servers.ts` 与对应样式：列表、详情和表单；沿用现有 TypeScript/DOM，不引入新前端框架。

桌面桥只需要：读取目录、保存/复制/删除服务器及代理、保存/删除分组，以及表单所需的清除凭据动作。被路径引用的代理同样阻止直接删除；编辑共享代理展示受影响服务器。路径预览和引用检查与保存使用同一套核心规则；UI 可即时预览，保存以核心结果为准。本轮不扩展插件 RPC、不建立通用工作流 API。

## 7. 实施顺序与验收

1. **目录服务**：先完成类型、引用规则和原子存储，使用隔离数据目录验证保存、重开、失败与备份恢复。
2. **资料管理页面**：完成列表、详情、搜索分组和沿用旧版字段的表单；用脚本验证普通资料和跳板顺序变化。
3. **本机密码保存**：完成明文记住、留空保持、显式清除和不记住时仅进程内有效；不接系统凭据库或网络。
4. **实际包检查**：执行相关格式、类型、构建与测试，五目标原生打包和启动退出，验证目录与记住的资料在实际包重开后保持；不能用编译成功代替验证。

可验收行为：

- 新增、编辑、复制、删除和分组操作后重开核心，列表与路径准确恢复；复制不携带秘密。
- 直连、纯 SSH、纯 SOCKS5 中转和 SSH/SOCKS5 混合路径都可保存；至少覆盖三层中转与连续代理，另用深链样例确认没有写死业务层数；不会对被引用节点递归展开。
- 调整顺序后，访问来源、回环含义与下一站解析来源准确更新；固定逐站远端解析，没有本机解析选项。代理认证和 SSH 认证分开。代理新增、编辑、复制和引用删除限制有效；内联保存代理后取消服务器草稿，代理依然存在。
- 自身、重复、缺失引用、端口错误和旧修订被拒绝，草稿仍保留；相同私网 IP 的不同记录可共存。
- 修改跳板名称不破坏引用；修改地址有依赖提示；删除仍被引用的跳板被阻止。删除分组仅解除归属。
- 勾选记住后，密码/口令按选择写入本机 JSON；不出现在公开快照和日志。记住后重开可用，未记住的退出清空。
- 注入目录写入失败、损坏 JSON 和未知版本，不出现假保存或空目录覆盖；本轮没有系统凭据后端。
- 720×480 和四主题下，表单完整可访问，路径长名称/IPv6 不撑破窗口；关闭脏表单有明确选择。
- 整个管理流程无网络请求、无 SSH 进程或会话、无后台连通性测试。开发验收优先使用脚本，不操作用户鼠标或真实服务器。

## 8. 原型与实现验证

本文件的目录管理范围现已实现。早期交互原型只修改示例数据；产品验证使用真实 Rust 目录服务与隔离数据文件，绝不访问真实服务器。生产依赖不变，新增固定版本 Playwright 1.64.0 仅用于开发验收；可用原生脚本手工验证替代，但自动化保证写入失败、重开与模态表单路径可重复。
