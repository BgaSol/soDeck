## 2. 实施方式

按六个阶段推进。第三阶段作为一次完整修改交付，覆盖核心、文件和文本菜单及插件资源打包；第四阶段完成三系统本地文件适配及对应原生验证；第五阶段仍分别验证表单与工作台更新；第六阶段按已确定的报文库方案一次处理核心、网络插件和检查器，并完成网络与实际包验收。

每批开始时先查看工作区状态和相关差异，将本批范围与已有未提交改动区分清楚。当前工作区包含工作台交互、文件剪贴板、更新说明及工作流等改动，不能将整个工作区当作本次整改提交。

每批先建立缺陷复现和验收行为，再修改代码。新增生产依赖时说明用途、当时的维护状态、替代方案和选择理由，固定版本并提交锁文件；出现在现有锁文件中的传递依赖，仍需在实际使用的目标中声明直接依赖。

优先使用已有标准工具或直接依赖。库负责通用解析、定位或系统绑定，SoDeck 继续负责目标选择、会话归属、生命周期、异步结果有效性和错误展示。

## 3. 第一阶段：统一插件版本读取

目标：插件标签、包名、`plugin.json` 和更新清单始终读取当前插件自己的 Cargo 包版本，合法 TOML 写法不影响结果。

范围：`scripts/release-metadata.mjs`、`scripts/package-plugin.mjs` 及相关脚本测试。采用 `cargo metadata --format-version 1 --no-deps --locked --manifest-path <插件 Cargo.toml>`，按清单路径选择对应包，检查命令退出状态和 JSON 结构。不能直接取 `packages[0]`，也不能用 `metadata.binary` 代替包身份。

两个真实调用处复用一个小型元数据读取函数；保留现有版本与标签约定，不顺带增加预发行版本、发布状态机或新的打包框架。核心版本继续只取 `src-tauri/tauri.conf.json`。

验收：

- 空格差异、单引号、依赖声明在前等合法 TOML 均读取正确包版本。
- workspace 或多包场景不会误取其他包版本；Cargo 失败、包缺失、无效清单明确报错。
- 包名、插件清单、更新清单与标签一致，三个业务插件仍能通过各自独立打包入口构建。
- 干净构建环境显式安装所需 Cargo 工具链；不靠本机路径，也不依靠正则回退掩盖失败。

风险：元数据命令可能受锁文件和依赖解析影响，需要核验现有 Actions 调用顺序及脚本测试环境。此批不改发布工作流优化策略；仅在本批工具输入变化确有需要时调整受影响步骤。

## 4. 第二阶段：文件 URI 使用标准 URL 转换

目标：接受合法本地文件 URI，正确转换为本地路径，并保持当前文件剪贴板的来源与条目检查。

范围：`src-tauri/src/desktop_files.rs` 的 URI 条目解析及测试。优先复用已有 `reqwest::Url` 的解析与 `to_file_path`；URI-list 的逐行读取、注释、GNOME copy/cut 标记仍是剪贴板格式适配。

不能直接将所有字节转换成有损 UTF-8 后传给 URL 库。实施时核验 Unix 非 UTF-8 文件名的百分号表示、百分号错误处理和 URL 规范化行为；库允许但现有业务拒绝的输入，仍需保留明确检查。

验收：

- scheme 与 localhost 的合法大小写、中文、空格、百分号和非 UTF-8 Unix 文件名正确处理。
- 非 file scheme、非本地主机、NUL、非法百分号及超出 4096 项的输入按明确规则拒绝。
- 实际 Linux 文件管理器复制文件后，文件插件能读到相同本地路径；普通文本路径不被误当作文件剪贴板。

风险：标准 URL 规范化与当前路径字节语义可能不同；以实际文件路径和现有行为测试为准，不能只验证字符串解析成功。

## 5. 第三阶段：菜单定位复用 Floating UI

一次完成所有现有菜单的定位、尺寸约束、更新与清理，同时完成独立插件资源构建。不再分 3A/3B。菜单动作、目标选择、剪贴板状态和键盘操作由各自现有代码维护，公共部分只负责定位与对应观察器生命周期。

### 采用的库与共用入口

采用 `@floating-ui/dom 1.8.0`，在根 `package.json` 固定直接依赖并提交锁文件。2026-11-06 查询 [npm 元数据](https://registry.npmjs.org/@floating-ui/dom)，该版本发布于 2026-07-11，MIT 许可，来自持续维护的 [Floating UI 项目](https://github.com/floating-ui/floating-ui)。替代方案为 Popper；Floating UI 的原生 DOM 接口、虚拟锚点和自动更新适合当前 TypeScript/原生 DOM 与插件 iframe，使用现有 Vite 构建即可。

新增小型 `src/menu-position.js` 及类型声明，导出一个 `attachMenuPosition` 入口。它接受菜单 DOM、真实元素或带 `contextElement` 的指针位置、主菜单/子菜单类型以及有效性/失效回调，返回 `ready`、`update`、`dispose`。内部列表的滚动由共同 CSS 规则处理。

内部直接使用 `computePosition`、`offset`、`flip`、`shift`、`size`、`hide` 和 `autoUpdate`；不再手算菜单坐标、方向或边缘余量。核心直接导入；为现有普通脚本式插件暴露同一入口到 `window.SoDeckMenuPosition`。公共入口不持有服务器、插件 RPC 或剪贴板数据，不创建菜单配置系统或业务菜单框架。

### 各菜单的确定行为

| 菜单 | 参考位置与方向 | 修改落点 |
| --- | --- | --- |
| 工作区菜单 | 对齐触发按钮，默认向下；下方不足时向上，水平方向保持在窗口内 | `src/workspaces.ts`，删除固定 190px 避让计算 |
| 组件、页面列表菜单 | 对齐按钮，默认向下；搜索或列表更新后重新测量 | `src/components.ts`，替换手写定位与专用定位 ResizeObserver |
| 文件主菜单 | 鼠标打开使用右键点；键盘打开使用当前文件行 | `plugins/files/ui/tree.js`，替换主菜单定位 |
| 文件子菜单 | 对齐父菜单项，依次尝试右、左、下、上；空间仍不足时限制内容尺寸 | 同一文件，删除 `placeSub` 的手算分支 |
| 文本菜单 | 鼠标打开使用右键点；键盘打开使用输入框或选中文本的来源元素 | `src/text-menu.js`，替换坐标计算，保留选区快照 |
| 终端专用菜单 | 鼠标使用右键点，键盘使用终端元素；复用同一定位入口 | `plugins/terminal/ui-src/input.js`，保留 xterm 的复制粘贴与鼠标报告规则 |

统一按当前菜单所属窗口的视口避让，边缘留 8px；iframe 菜单使用自身视口，坐标使用 CSS 像素，不乘设备像素比、不转换到宿主或桌面坐标。普通菜单间距 4px，子菜单间距 7px。

真实元素与键盘菜单跟随参考元素的滚动和位置变化；元素被删除、隐藏、移出可见区域或所属工作区失效时关闭。指针菜单在缩窗时重新避让，来源内容滚动时关闭，避免停在旧内容位置；菜单自己的滚动不关闭菜单。子菜单跟随父菜单项，父项滚出父菜单可见内容区时关闭子菜单。

子菜单翻转后，鼠标从父项跨越间距进入子菜单也必须可用。保留悬停打开，但切换/离开时使用短暂的悬停意图延迟，进入当前子菜单取消关闭；点击、键盘和触控不等待延迟。不再通过手算指针三角区域解决，关闭菜单时同时清理延迟任务。真实鼠标回归覆盖左右与上下展开，不能只检查两个菜单的坐标。

菜单操作在打开时保存目标：文件路径/选择集合、工作区 ID、组件定义与文本选区不因重新定位而变化。文件剪贴板状态更新现有按钮，不重建菜单 DOM；原有异步结果有效性校验继续使用。

### 尺寸、层级与生命周期

- 使用固定定位，`flip` 和 `shift` 完成方向选择和边缘避让，`size` 按实际可用空间限制宽高。保留现有正常宽度与组件列表高度上限；移除与库冲突的硬编码定位和最小宽度，极小窗口也不强行撑出视口。
- 外框保留边框、阴影且不裁切；工作区/文本菜单增加内部滚动列表，组件和文件菜单复用现有列表。搜索框保持在列表外，只有内容区纵向滚动；焦点移动到不可见项时滚动到该项。
- 文件子菜单继续放在主菜单的 DOM 树内，保持现有事件归属和外部点击判断；定位由库处理其实际包含块，不把父菜单坐标再次当成视口坐标。
- 对话框内的文本菜单继续属于对话框 DOM。支持 Popover 的 WebView 使用现有手动 popover 顶层；不支持时保持对话框内固定定位。先建立正确层级再测量，核验 Tauri WebView，不能只依靠提升 z-index。
- 首次定位完成前不显示菜单，`ready` 确认菜单仍有效后再显示和设置焦点，避免在原点闪现或焦点落入已关闭菜单。
- 仅菜单打开期间启用 `autoUpdate`，默认不启用逐帧轮询；内容变化调用同一 `update`。对来源元素移除、隐藏和作用域变化补充失效检查，该检查不因菜单自身样式更新反复触发定位。
- 每次异步测量带当前实例/更新序号；坐标和 `size.apply` 的样式写入都检查有效性。关闭、隐藏子菜单、切换工作区、unmount/dispose 时先结束定位，迟到结果不能重新显示、移动或抢焦点。
- Escape、Tab、点击外部、失焦及子菜单左右键沿用现有交互规则；恢复到有效触发元素或原文本选区。不要用全局拦截键盘或重绘整个页面来解决定位问题。

### 插件资源与构建方式

当前文件、网络插件通过普通 `<script src="text-menu.js">` 加载共享文本菜单，`package-plugin.mjs` 直接复制源码。引入 npm 库后改为以下确定流程：

1. `src/text-menu.js` 导入上述定位模块，继续提供 `window.installTextMenu`；定位模块同时提供 `window.SoDeckMenuPosition`。核心由现有 Vite 正常构建模块依赖。
2. 新增小型 `scripts/plugin-menu-assets.mjs`，使用根目录已有固定版本 Vite 的库构建模式，将 `src/text-menu.js` 及 Floating UI 打成一个普通浏览器脚本，文件仍叫 `ui/text-menu.js`。禁用项目配置读取与独立输出目录清空，保证不覆盖其他插件 UI 资源。
3. `scripts/package-plugin.mjs` 在组装 UI 资源时调用该函数，替换直接复制文本菜单源码。包内脚本包含所需库，不含运行时 npm 导入，不连接 CDN；附带依赖许可证。
4. 文件和网络插件沿用原有脚本加载顺序：文本菜单在剪贴板桥之前，文件树在定位入口可用之后。终端 UI 在剪贴板桥前补载同一脚本，通用文本菜单继续排除 `.xterm`；终端专有复制粘贴由既有终端实现处理。
5. 终端本地 UI 构建调用同一资源函数，保证直接构建后的页面与发行包都具备该脚本，不能只让最终打包阶段补齐。
6. 插件工作流的打包任务先执行根目录 `npm ci`，终端仍安装其自己的锁定依赖。根依赖安装用于构建共享 UI 脚本，不构建核心、不要求核心 dist 或其他插件产物。更新开发和分发文档中的实际构建前提。

不提交生成的菜单脚本作为第二份源码，不创建共享资源版本/发布系统，也不将库能力放进核心 RPC。三个插件各自携带自己的静态脚本，继续独立打包和分发。

### 一次交付的验收标准

先保留工作区缩窗缺陷的失败复现，再使用真实浏览器输入覆盖下列行为。补测试时验证操作结果与实际几何，不只检查是否调用了库。

| 场景 | 验收 |
| --- | --- |
| 打开后缩窗、最大化/还原、滚动参考区域 | 菜单完整留在当前视口，跟随有效参考元素或按指针菜单规则关闭 |
| 四边位置、长列表、长标签、搜索过滤、粘贴状态变化 | 按可用空间翻转/避让，内容可操作、边框不裁切，页面没有横向溢出 |
| 小文件 iframe，子菜单左右都无足够空间 | 子菜单改为上下展开或限制内容尺寸，父子鼠标穿越间距、键盘导航和点击都可用 |
| 对话框中的输入框和插件文本输入 | 文本菜单可见可点击，焦点和选区正确，复制/剪切/粘贴/全选结果与只读状态一致 |
| 连续开关、锚点移除、工作区切换、迟到定位/剪贴板结果 | 旧菜单不复活、不抢焦点、不操作新的目标，无残留菜单节点或页面异常 |
| 源码开发与正式前端产物 | 相同测试行为通过，覆盖浅色、深色、多巴胺及 1100×720、720×480、320×240；文件 iframe 另覆盖 320×200、180×160 |
| 核心及三个实际独立插件包 | 静态资源完整；普通脚本可直接加载，无裸 npm 导入或 CDN 请求；菜单交互与程序启动退出通过 |

扩展现有工作区、交互、桌面文本菜单、文件和终端输入回归；文件定位测试显式载入正式共享菜单脚本。新增资源构建回归核验普通脚本产物、必要入口与许可证。执行相关格式/类型、脚本、前端、UI、核心和插件打包检查，并按项目约定记录实际完成的平台。

完成条件是所有上述菜单迁移、旧定位代码清理、开发/发行资源一致和相关行为回归共同通过。这些属于一个菜单定位主题，在同一次实施中完成；不把插件打包或小窗口子菜单作为后续补丁遗留。

## 6. 第四阶段：三系统本地文件适配整改

本阶段完整处理 macOS、Windows、Linux 的系统文件剪贴板读取和本地目标目录打开。三个系统共用既有核心接口，分别使用适合本系统的绑定和资源管理方式。实施按依赖顺序推进，作为一个完整阶段交付，不拆成需要用户逐次确认的多个方案。

### 6.1 目标、范围与已有证据

用户应能从本机文件管理器复制文件或文件夹，在文件插件粘贴上传，并从下载任务打开本地目标目录；剪贴板忙、来源改变或页面失效时，应得到明确结果，不能把旧文件列表用于新操作。这与远程服务器运行 Windows、Linux 或 macOS 无关。

| 当前落点 | 已核对的实现 | 本阶段工作 |
| --- | --- | --- |
| `desktop_files/macos.rs` | 手写 `objc_msgSend` 与多处 `transmute`；`isFileURL` 走 `usize` 返回签名，手工创建/释放 autorelease pool | 使用 objc2 类型化绑定；核对布尔、整数、可空对象、对象所有权和原生路径转换 |
| `desktop_files/windows.rs` | 已直接依赖 `windows-sys`；有剪贴板关闭 Guard、版本前后检查、5 次打开重试与路径长度检查 | 保留标准绑定和已有保护；核查错误边界、格式常量、忙/变化场景与句柄释放，不预设必须重写 |
| `desktop_files/linux.rs` | 手写 GTK/GDK/GLib 声明与裸指针回调；自行登记请求、处理格式回退和 owner-change | 改用现有 GTK3 体系的绑定，明确请求取消、超时、迟到回调、订阅清理与路径 URI 生成 |
| `desktop_files.rs`、`main.rs` | macOS/Linux 已由 Tauri 调度到主线程，读取有 5 秒等待上限；`input.revision` 查询格式，`input.clipboard` 读取并登记来源 | 保留线程调度和协议，补请求生命周期与失效验证；确认同步系统调用阻塞不被误认为已由外围超时中断 |
| `main.rs::clipboard_roundtrip`、`scripts/smoke.mjs` | `SODECK_TEST_CLIPBOARD=1` 当前只测文本往返与大小限制 | 另补实际文件格式的原生验收；文本烟测成功不作为文件剪贴板证据 |
| `remote_files/operations.rs`、文件插件 | 来源登记已再次检查页面及资源归属；粘贴前后已有 revision、连接、目标与焦点核对 | 用集成回归验证这些保护，只有发现实际缺口时才修改对应落点 |

macOS 的签名差异是可确认的源码问题，Linux 的手写绑定与生命周期是维护风险；本规划没有复现 macOS/Linux 崩溃或认定 Windows 已有同一故障。实施时把可复现缺陷、绑定替换和平台验收分别记录。

范围以核心 `src-tauri/src/desktop_files/`、共同入口、目标依赖和相关测试为主。必要时触及 `main.rs` 的文件 RPC/烟测和既有来源登记验证。文件插件只承担既有业务流程回归；当前普通文本剪贴板、菜单、远程路径处理和网页外链打开继续使用各自现有入口。系统格式中的 `cut` 标记不在本阶段新增本地删除语义，上传仍按现有复制行为执行。

### 6.2 先固定接口与可验收行为

保留 `Clipboard { paths, revision, has_files }`、`clipboard(handle, files)`、`reveal_directory(handle, path)` 和插件 API v1。`revision` 是不透明变化令牌，调用方只判断相等/不相等，不解析为数值，不跨系统比较。

| 场景 | 确定行为 |
| --- | --- |
| 仅查询可用性 | `files=false` 查询是否提供文件格式，不读取完整文件内容、不登记 input、不建立任务；返回原有 revision/hasFiles 字段 |
| 系统为空或只有文本/图片 | 返回无文件，文件菜单粘贴置灰；普通文本即使写成 `/tmp/a`、`C:\\a` 或 `file:///…` 也不转为文件来源 |
| 实际文件列表 | 保留文件与目录的原生路径；最多 4096 项；超过上限明确失败，不静默截断 |
| 非法列表 | 保留既有 URL/NUL/非法编码检查，列表发生错误不把部分已读路径登记为有效 input；支持格式中夹杂普通非文件项目的处理沿用明确的系统规则 |
| 路径字符 | 中文、空格、emoji、`%/#/?` 按实际文件名处理；Unix 百分号表示的非 UTF-8 名称保留字节，Windows 路径保持 UTF-16 语义；不经过有损字符串转换 |
| 剪贴板变化 | 读取前后核对系统变化信息；改变时明确重试或失败，不混合两个来源。再次粘贴重新核对，不沿用菜单打开时的旧内容 |
| 页面、连接或目标失效 | 迟到结果不能登记到失效页面、创建任务或作用于新目标；已产生但未使用的来源按原有释放路径清理 |
| 超时/取消 | macOS/Linux 保留 5 秒等待上限；超时结束本次业务请求，迟到回调不能再次完成。同步系统调用和底层 OS 请求能否真正取消须分别说明 |
| 打开本地目录 | 使用原生目录 API 或标准本地文件 URL；中文/空格路径正确，无 shell 拼接，失败明确返回；只打开已登记下载目标对应目录 |
| 长期运行与退出 | 反复读取、变化、取消后请求数量有界；清理系统订阅与业务引用，核心及文件插件正常退出 |

保留各平台已有容量限制：Linux 文件格式正文最多 4MiB；Windows 单路径保留原有长度检查。共同层对相同规则才提取小函数，不新增统一后端 trait、插件权限系统或文件剪贴板缓存框架。

任务在主线程队列中等待期间已经超时/取消时，真正执行前检查接收端有效性，跳过系统读取；运行中的系统调用则按其实际取消能力处理。共同入口继续统一返回数据，平台注册状态和 GTK 对象留在主线程后端中，不能把非 Send 的 GTK 对象放入跨线程共享的 AppCore。

### 6.4 macOS 的具体修改

1. 在 macOS 条件依赖中声明上述 objc2 包；启用本次用到的 `NSPasteboard`、`NSWorkspace`、`NSArray`、`NSString`、`NSURL` 等最小 feature，检查其平台和线程标记。
2. 删除自定义 `Obj`、`objc_getClass/sel_registerName/objc_msgSend` 声明、`msg/arg/number` 及各处 `transmute`。使用 `NSPasteboardTypeFileURL`、类型化数组和可空返回值，不再将 C 字符串指针伪装成 Objective-C 对象参数。
3. 保留 `generalPasteboard` 与逐项 `pasteboardItems` 的读取方式，避免借迁移改变支持格式。轻量查询只检查提供的格式；实际读取按条目数限制后读取文件 URL。空数组、没有文件类型、NSURL 构造失败和非 file URL 分别处理，避免 `nil` 掩盖为成功。
4. `changeCount` 按 `NSInteger` 使用，`isFileURL`、`openURL` 按绑定的 `bool` 使用；读取结束再核对 changeCount。不得用一个通用整数返回函数代替不同签名。
5. 使用 `Retained` 和 `autoreleasepool` 管理对象；保持 URL/NSString 存活到读取完成，`fileSystemRepresentation` 返回的字节立即复制到原生 `OsString/PathBuf`，不把借用指针带出 pool。
6. 打开目录使用类型化 NSURL 文件系统路径构造和 `NSWorkspace::openURL`。输入 C 字符串仍校验 NUL，必要的裸指针转换限制在小型、有安全说明的边界内；保留 Tauri 主线程调度。
7. 核验文件 URL 主机与现有本地来源规则、Unix 字节语义。涉及与 Linux 共用 URL 检查时复用第二阶段函数并补测试；只在确认第二个真实用例和语义一致后扩展编译条件。

macOS 原生回归覆盖 Finder 多文件/文件夹复制、中文/空格/emoji、空剪贴板、文本 URL、读途中 changeCount 变化、打开目录、连续 100 次读取及退出。测试实际路径与文件内容，不只测试返回值非空。

### 6.5 Linux 的具体修改

1. 使用 Tauri 已采用的 GTK3/GDK/GLib 版本，继续在已有主线程和主循环中运行；使用默认 display 的 CLIPBOARD，不自行初始化第二个 GTK 运行时或另建 GUI 线程。
2. 删除本模块手写的系统函数声明与通用 `Ptr`；优先用 `gtk::Clipboard`、`gdk::Atom`、`gtk::SelectionData` 和 GLib 对象/错误管理。对高层无法覆盖的调用使用同版本生成接口，保留有限、明确类型的 FFI 边界和安全说明。
3. 当前 gtk 0.18.2 已核对：有 `request_contents`，但没有可直接调用的高层 `request_targets`，生成的 `connect_owner_change` 也被注释掉。格式查询优先用 `request_contents(TARGETS)` 与 `SelectionData::targets()`；owner-change 使用 GLib 动态信号连接，并保存连接 ID。先在 X11/Wayland 核验这条路径；需要专用 targets 调用时使用生成的 GTK 接口，不重新手写声明。
4. 内容读取继续先请求 `text/uri-list`，未提供时回退 `x-special/gnome-copied-files`；空内容、未支持格式、非法数据与剪贴板变化有各自结果。保持第二阶段 URL 解析与 4096 项检查，`copy/cut` 行仅作为格式标记。
5. 在复制数据前检查 `SelectionData::length()`：负数为失败/回退，0 为无数据，超过 4MiB 拒绝。gtk 0.18.2 的 `data()` 会直接复制正文，不能先调用它再检查长度。需要处理非零长度与空指针等异常时，使用生成接口完成小范围受检读取；不把 native SelectionData 的借用带出回调。
6. 保留每请求独立身份及 4 个并发槽位，并把上界覆盖到尚未返回的系统请求，包含业务已经超时/取消的请求。完成时移除；超时/取消立即释放发送端和业务引用，仅保留轻量过期标记，直到系统回调返回或后端退出才归还系统槽位。全部槽位被无响应来源占用时明确返回忙，不能靠删除登记后无限发起新的底层请求。回调只有仍有效时提交一次结果，失效请求不再发送格式回退读取。
7. GTK 请求没有通用硬取消接口，高层 FnOnce 闭包也不能保证在业务超时后立刻被 GTK 释放。系统持有的回调只保存轻量 ID/弱引用，不能长期保留文件数组或业务资源；如果闭包实现不满足上述资源上界，使用生成接口配合既有 ID 回调方式。测试实际 GTK 的失败/超时回调和槽位恢复，不假定某个版本会在固定时长内回调。回调内的错误和锁状态明确处理，不能让 Rust panic 穿过 FFI 边界。
8. 在主线程后端状态中保存 owner-change 连接 ID；退出路径在 GUI 事件循环结束前断开订阅、结束业务请求，迟到回调只作失效处理。revision 继续为当前进程观察到的变化令牌；同一来源进程反复改写和文件→文本切换必须实测。若桌面通知不足以维持现有粘贴有效性规则，记录具体复现并修正该路径，不能用时间戳伪造系统变化或在每次轮询无条件递增。
9. 目录打开使用现有 `reqwest::Url::from_file_path` 生成本地 URL，替换本模块手写逐字节百分号拼接，再调用 GTK 的目录打开封装。错误由 GLib 类型管理；不改网页外链打开，也不依赖 `xdg-open` shell 拼接。

Linux 除共同用例外覆盖 GNOME copy/cut 格式、同一 owner 改写、非 UTF-8 文件名、无响应来源、来源退出、超时后到达回调、格式回退途中取消、100 次交错读取/取消以及退出。X11 与原生 Wayland 分别记录，XWayland 不算原生 Wayland。

### 6.6 Windows 的具体核查与修改

1. 保留 `windows-sys`、`spawn_blocking`、CloseClipboard Guard、5×20ms 打开重试及已有前后序列号检查；先复现再修正缺口。
2. 使用有名称的 CF_HDROP 格式常量；确认 `GetClipboardData` 句柄是借用的剪贴板数据，读取端只关闭剪贴板，不错误调用 `GlobalFree` 或 `DragFinish`。
3. 分开检查无文件格式、打开剪贴板失败、数据句柄无效、路径长度/实际长度不一致与序列号变化。每条错误路径都释放已打开的剪贴板；轻量查询不执行打开重试或读取路径列表。
4. 保留 UTF-16→OsString→PathBuf 转换，校验 NUL 和路径边界；覆盖长路径。Explorer 提供且当前 OS 可访问的 UNC 路径沿用本机文件系统来源语义，不能误套 Unix URL 主机规则拒绝。
5. 核验 `ShellExecuteW` 的返回值规则，失败明确返回；打开目录传入原生路径，不走 cmd/PowerShell。保留函数所需 unsafe，改动以实际缺陷和可验证行为为依据。

Windows 原生回归除共同用例外覆盖另一个进程短暂/持续占用剪贴板、5 次重试后的忙结果、读取中格式变化、读取错误后的再次打开、UTF-16/长路径、目录打开和 100 次重复读取。x86_64 与 ARM64 都使用本架构实际核心包。

### 6.7 测试设计与执行顺序

先给可复现问题建立失败用例；没有原生环境时可以核对类型/编译和添加回归，但不能记录“原生缺陷已复现”。测试验证路径、内容、结果与资源生命周期，避免只断言调用了某个库函数。

| 层次 | 用例与断言 | 落点 |
| --- | --- | --- |
| 核心纯逻辑 | URI 字节/大小写/百分号、4096/4097 项、非法部分列表；必要的请求一次完成/失效规则 | 既有 `desktop_files.rs` 测试及平台模块测试；只为真实共享逻辑增加小范围单测 |
| 原生绑定 | 独立提供者写入本系统实际文件格式；实际核心读轻量信息与完整路径，检测变化、忙和失败 | 测试夹具作为 test-fixtures 工具单独构建，不发行；core 验证通过实际平台入口读取，不用 JS 或核心 RPC stub 替代 |
| 异步故障 | 暂停/改变/关闭提供者，触发 5 秒超时、迟到结果与回退取消；核对无重复完成、业务请求有界 | 可控外部提供者与平台模块生命周期回归；无法稳定驱动的时序仅对相应边界加测试注入，不改生产 API |
| 插件集成 | 文件→文本切换、旧菜单粘贴、读取中换连接/页面、有效文件上传、失败后重试；核对文件内容和无多余任务/input | 扩展现有 `test-files-ui.mjs`、文件连接集成用例；使用真实文件插件与隔离回环 OpenSSH |
| 实际核心包 | EXE/DEB/AppImage/DMG 中的程序使用同一适配入口，文件列表正确、目录打开、退出成功 | 扩展既有 smoke 协议，新增单独文件测试开关与逐用例报告；当前 clipboardNative 字段仍只代表原文本用例 |
| 实际桌面 | Explorer、Finder、Linux 文件管理器真实复制/再次复制，下载目标打开 | 在对应架构实际桌面会话记录操作、路径/内容、失败重试与退出；合成格式测试不替代此层 |

现有 `test-files-ui.mjs` 将 `input.revision` 替换为固定测试结果，因此它目前只证明业务/UI 行为。受控时序回归可以继续使用夹具，但新增实际包组合用例必须经过真正的 Tauri `component_data` 与系统适配入口；不能覆盖掉文件剪贴板查询后仍报告原生验收通过。

实施时新增文件烟测开关与报告，例如 `SODECK_TEST_DESKTOP_FILES=1` 和 `desktop-files-result.json`。这些是本阶段待实现项，当前不能按已存在命令执行或在文档阶段添加调用它们的工作流。`scripts/smoke.mjs` 只有明确请求此层时才要求该层报告，逐次启动清除旧报告；“普通 smoke 成功”和上一轮报告都不能代替当前文件用例成功。

自动写入剪贴板只在隔离测试桌面和显式测试模式进行；使用测试目录与测试来源，不操作用户真实文件。现有文本烟测只能恢复文本，不能承诺保存/恢复所有原生剪贴板格式；人工用真实文件管理器执行复制并由应用读取。目录打开只针对测试下载目录，结束时清理测试启动的窗口/提供者和临时资料。

执行顺序如下，每项都有明确产出，后项复用前项结果：

1. **行为与失败基线**：核对现有差异，保存本阶段基线；整理上述用例，跑当前相关测试；记录实际失败和尚无环境的用例。
2. **核心适配实现**：先 macOS 类型替换，再 Linux 绑定/请求生命周期，再 Windows 边界核查；每个系统完成后运行其相关格式、测试和原生检查。共同层只接纳证据支持的共享修正。
3. **文件来源集成与测试入口**：补原生提供者、文件 smoke 层和旧结果拒绝回归，复验插件原有目标/来源检查。该项与系统实现交错验证，不等三个系统全部写完才测试。
4. **五目标实际包验证**：通过既有原生 runner 构建、打包、启动/退出，另跑文件原生用例；文件插件组合流程在独立验证工作流执行。
5. **文档与交付**：更新本阶段实施记录、实际变化的开发/分发说明和必要版本说明，列清完成目标、未完成用例与已知风险；不把测试结果追加到根 README。

### 6.8 平台、构建和工作流安排

| 正式目标 | 实际产物 | 系统互操作验收 |
| --- | --- | --- |
| Windows x86_64 | 原生 x64 NSIS 包内 EXE | 原生绑定/忙与变化用例、Explorer 复制、目录打开 |
| Windows ARM64 | 原生 ARM64 NSIS 包内 EXE | 同上，不以 x64 模拟运行替代 |
| Linux x86_64 | 原生 DEB、AppImage | X11 原生格式回归；GNOME/KDE 中原生 Wayland 文件复制及目录打开 |
| Linux ARM64 | 原生 ARM64 DEB、AppImage | 同上，不以交叉编译或 x86 容器替代 |
| macOS ARM64 | Apple Silicon DMG 内 app | AppKit 原生格式回归、Finder 复制、目录打开和对象生命周期 |

Linux 两种会话覆盖读/变化/取消和目录打开。现有 `build.yml` 的 `dbus-run-session + xvfb-run` 只提供 X11 证据；Wayland 要在真正支持剪贴板 offer 与焦点的桌面会话核验，并确认应用使用 Wayland 后端。无会话/无显示服务的测试只能证明明确返回不可用错误，不能标为剪贴板成功。

开发检查复用已有 `npm run check`、`npm run scripts:test`、`npm run test`、`npm run web:build`；类型绑定改动在目标系统编译并运行相应测试。核心继续按分发文档的 NSIS、DEB/AppImage、DMG/app 命令独立构建；文件集成复用 `npm run files:test` 和独立 `plugin:build -- --plugin files`。没有修改终端/网络 Rust 业务时，不把它们的全套远程验收加入本阶段。

扩展现有 `.github/workflows/build.yml` 的核心原生文件验证与报告上传；仅在实现了测试入口后添加调用。核心包构建和核心文件烟测不依赖业务插件。文件来源→远端上传→下载目标目录的组合验证扩展 `.github/workflows/remote-integration.yml`，继续读取各自独立构建的实际核心/文件插件产物。保留普通 Artifact/Release 流程，不建立五平台联动发布门禁或新发布框架。

本机可先完成 Windows x86_64 实施与验证，以及其他平台源码准备。其他目标的编译检查依赖对应工具链和系统 SDK，实际完成范围以获得的原生 runner/桌面环境为准。缺少 macOS、ARM64 或 Wayland 环境时标记待验收，并继续可独立完成的工作；不能因预算/时间或 Windows 通过将整个阶段判定完成。

### 6.9 完成条件

- macOS 对应手写消息签名和 `transmute` 已移除，类型/可空性/对象生命周期与实际 API 一致。
- Linux 对应手写系统声明已移除，高层未覆盖的边界使用生成接口；格式回退、超时、订阅与迟到结果有明确实现及回归。
- Windows 标准绑定和已有保护保留，复现的问题修复并回归；没有为了引库而扩大改写。
- 文件轻量查询、实际读取与旧结果拒绝通过核心、真实文件插件及实际包三层验证；普通文本不误判为文件。
- 五个正式目标使用原生产物完成构建、打包、启动/退出及适用的文件用例；Linux 原生 X11/Wayland 证据分别记录，实际文件管理器复制与目录打开有证据。
- 依赖用途/维护状态/替代方案、API兼容与测试命令文档同步；实施记录如实列出未完成项，既有未提交改动保留。没有必要的阶段工作遗留为“后续小补丁”。

## 7. 第五阶段：渐进替换 DOM 更新基础逻辑

目标：无关状态刷新不打断输入、选区或按钮点击，工作台重绘不重建运行中的插件 iframe。

先验证 `morphdom` 是否适合现有 HTML 字符串与事件委托。不能承诺引库后自动保留全部浏览器状态；仍需明确 DOM 身份、表单受控状态、输入组合过程、滚动和插件 surface 生命周期。若不适合当前结构，记录具体原因再选其他方案；Lit 不作为本轮预定的整体迁移目标。

### 5A：先修服务器表单重绘

只处理 `replace` 的服务器编辑表单调用处。验收密码框 `[1,4]` 选区、输入焦点、中文 IME、textarea/select/checkbox、异步刷新期间的新输入，以及切换服务器后正确显示新数据。相同逻辑实体的 DOM 才能复用，不能把旧服务器未提交的输入错误保留到新服务器。

采用成熟库更新表单后，删除该调用路径不再需要的整块替换与状态恢复逻辑；其他 `replace` 使用处逐个核验后迁移，不直接全局替换。

### 5B：再替换工作台外壳 diff

处理 `patchChildren`/`patchChrome`，保留明确的工作区、视图和按钮身份。验收按下到抬起之间发生刷新时点击恰好执行一次、Tab 排序/增删、焦点保留、移窗与回移，以及 iframe、PTY 和草稿继续使用原有资源。

现有按压期间延迟更新的规则先作为行为约束保留；只有稳定复现证明可安全去除时才删除。DOM 更新库不能接管插件 iframe 内的渲染或核心资源生命周期。

风险：此阶段影响面最大，必须在表单批次验证后再进入工作台批次。测试失败时依据实际用户行为定位，不能放宽已有点击、焦点或资源身份断言。

## 8. 第六阶段：核心与插件接入 SOCKS5 报文库

完整设计见[SOCKS5 协议库接入计划](plan-socks5-library-adoption.md)，该文档统一维护选型、各文件修改、协议行为、弱网络与五目标实际包验收要求。

已确定采用 `socker = "=1.0.0"` 的纯报文编解码接口，一次覆盖核心客户端、网络插件服务端和同步检查器。库不依赖 Tokio、socket 或 DNS；核心继续管理传输、认证资料、取消、超时和资源，插件继续通过核心 RPC 连接目标及移交通道。配置密码时只提供密码认证，具体连接失败 REP 保留。

该库属于较新的小项目，不能把接口适配和隔离测试等同于整体稳定性提升。2026-11-07 已核对发行源码、许可与依赖，并在临时项目运行上游及兼容性测试；维护风险、替代候选、已验证范围与未完成事项均见完整计划。原 `socks-http-kit` 高层原型丢失具体 REP，不作为生产替换方案。

核心、网络插件及检查器的生产代码和锁文件已接入固定报文库，相关回归和独立互操作已实施。弱网络对照、实际包结果及五目标原生验收的完成范围写入[基础逻辑复用实施记录](implementation-standard-library-adoption.md)，未运行目标继续标记待验收。

## 9. 每批验证与交付

实施阶段执行与改动相关的格式化、类型检查、测试和构建，复用现有 `npm run check`、`npm run scripts:test`、`npm run test`、`npm run build` 及独立插件构建入口。涉及插件 Rust 时同时运行相应格式检查和测试；UI 改动使用真实浏览器输入回归。

构建与打包入口必须在干净环境和 GitHub Actions 可运行。受影响的发行组件需要五目标构建、打包，并验证实际包内程序启动与退出；对应用户场景在适用平台原生验证，ARM64 使用原生产物。核心包继续独立于业务插件构建和组合验收。

每批完成时明确列出改动、已运行验证、未运行目标、未完成事项和风险。实施证据写入对应 `docs/implementation-*.md` 或现有相关实施记录；此计划不复制每批日志。使用方式、开发命令或分发输入发生实际变化时再更新对应职责文档。

Tauri 官方 opener 作为独立的后续候选：先确认当前网页打开适配是否存在实际缺陷或明显维护收益，再决定新增直接依赖。它不属于上述缺陷修复的必需完成条件。
