# 工作台按钮与文件菜单整改设计

日期：2026-11-06。状态：方案已实施到源码；实际验证与平台边界见 [实施记录](implementation-workbench-interactions.md)。以下保留设计目标和可验收行为。

## 1. 需求理解与整改范围

用户希望工作台具有稳定的桌面交互：一次点击就有响应，打开菜单后可以迅速找到常用操作，菜单准确表达当前能否执行，浮层的边框和位置完整可靠。

截图中的三个问题对应三项整改：

| 问题 | 用户预期 | 整改目标 |
| --- | --- | --- |
| 两侧组件按钮、面板更多按钮有时按下后失焦，抬起无响应 | 按下立即反馈，正常抬起只执行一次 | 保持按钮节点和焦点连续，消除刷新打断点击 |
| 粘贴一直可用，菜单文案过长，展开/折叠混在操作中 | 熟悉的短名称、合理分组、真实的可用状态 | 重组文件菜单，按剪贴板、选择和目标目录决定可用性 |
| 文件菜单边框缺失并出现双向滚动条 | 菜单是完整浮层，常规尺寸下无需滚动 | 外框与内部滚动区分离，按插件视口定位 |

保留现有工作台结构和浅色、深色、多巴胺三种主题。按钮与容器的可靠性属于核心；文件菜单动作与远程文件剪贴板规则属于文件插件；本地剪贴板格式检测属于核心系统适配层。

## 2. 已确认的原因与待验证边界

### 2.1 点击中途被刷新打断

`src/components.ts` 的 `paint()` 使用 `src/ui.ts` 的 `replace()` 更新侧栏按钮、面板标题栏和内部 Tab。`replace()` 用 `element.innerHTML === html` 判断内容是否变化，不相等就整体设置 `innerHTML`。

按钮图标包含 `<path .../>` 等 SVG 字符串。浏览器读取 `innerHTML` 时会规范化为 `<path ...></path>`；布尔属性等 HTML 序列化差异也可能触发同类问题。因此，相同的渲染输入仍会被判定为不同，按钮被重新创建。

已用真实 `replace()`、`icon()` 和浏览器鼠标输入复现：

1. 正常按下、抬起，点击触发 1 次。
2. 同一按钮按下并获得焦点后，用相同输入调用 `replace()`。
3. 原按钮断开 DOM，焦点丢失；鼠标抬起，点击触发 0 次。

这条链路能够解释“按下时焦点丢了一下，抬起没反应”。`workspaces-changed`、组件挂载完成和布局容量变化等路径会刷新工作台，增加遇到该时序的机会。尚未在用户安装版记录一次真实失效的完整事件序列，因此不能将所有偶发失效都归于同一原因；原生焦点切换、拖动区域和异步焦点恢复仍需专项回归。

### 2.2 文件菜单没有状态与层级

`plugins/files/ui/tree.js` 的 `showMenu()` 把 13 项动作平铺，其中“粘贴文件条目”直接绑定 `paste()`，没有 `disabled` 条件。是否有可粘贴内容在点击后才检查。展开与折叠合成一个名称，也没有按目录当前状态说明行为。

`plugins/files/ui/transfer.js` 已区分本服务器远程条目与系统剪贴板本地文件。新的可用状态必须覆盖两种来源，不能只检查本页面是否按过“复制”，也不能将路径文字当作文件。

### 2.3 外框被滚动容器裁切

共享 `src/ui.css` 用透明边框预留几何空间，再以 `::before { inset: -2px }` 绘制实际描边。文件插件的 `.tree-menu` 又直接设置 `overflow-y: auto`；未明确设置的横向 overflow 也计算为 `auto`。

局部复现中，菜单内部宽高为 196×426 CSS px，滚动宽高为 198×428 CSS px。内容原本可以容纳，外扩描边仍增加横、纵各 2px 的滚动范围；滚动区裁切外侧描边，形成截图中的缺框和双向滚动条。

核心组件菜单已有外框与列表分离的修复。文件插件仍使用旧结构，不能把核心已修复等同于插件菜单已修复。文件菜单还受自身 iframe 高度限制，截图中菜单过长会进一步造成真实的纵向溢出。

## 3. 按钮交互设计

### 3.1 正常点击契约

- 鼠标按下时立即显示按压背景；按钮尺寸、位置和节点保持稳定。
- 在按钮内抬起时执行一次动作。按下后移出按钮并在外部抬起，取消动作；`pointercancel` 取消并清理按压状态。
- 在按下与抬起之间收到无关状态、主题或网络数据更新，仍然完成正常点击。
- 菜单打开时再次点击同一入口，关闭菜单；点击另一入口，关闭旧菜单并打开新菜单，同一次点击完成切换。
- 点击图标和按钮留白区域均命中同一操作。保持现有约 28–32 CSS px 命中区及按钮间距，不通过扩大到相邻控件来补偿失效。
- 保留 Enter/Space 的原生按钮行为。进行异步操作时只禁用确实不能重复执行的入口，例如新建终端正在提交，其他按钮继续工作。

按下用于反馈，正常点击用于执行。不能把全部动作改绑到 `pointerdown` 来绕过点击丢失，否则拖出取消、键盘激活和误触行为会变差。

### 3.2 渲染与事件处理

1. 修正 `replace()` 的变化判断：比较同一套渲染输入或语义状态，不用浏览器序列化后的 HTML 与原始模板直接比较。缓存必须随容器销毁和外部写入失效，不能因为缓存相等而忽略真实 DOM 变化。
2. 工作台侧栏、面板标题按钮和两级 Tab 使用稳定节点。按工作区、动作和组件/视图标识复用节点；状态变化直接更新文本、类、可用状态和 ARIA 属性。只增删真正变化的项目，不重建整排按钮。
3. 布局变化只重算几何。侧栏容量变化仅调整受影响的入口，不因一个容量数字改变而重新绘制整套工作台。
4. 按压期间，如目标确实因组件退出而失效，取消交互并说明组件不可用；不把旧操作转到新组件。其他会移动当前按钮的布局更新在交互结束后应用。
5. 继续采用稳定容器上的事件委托；执行时复核组件/视图仍存在及连接状态。避免重复注册同一委托监听。

先针对真实工作台容器做小范围节点复用，再判断是否有第二个用例需要共享辅助函数，不引入新的 UI 框架或生产依赖。

### 3.3 焦点规则

| 场景 | 焦点去向 |
| --- | --- |
| 鼠标打开菜单 | 菜单可操作，保留入口关联；打开瞬间不把鼠标下面的普通项渲染成已悬停 |
| 键盘打开菜单 | 第一项可用操作；可搜索列表先进入搜索框 |
| Esc 关闭 | 返回原入口；入口已移除则返回同一侧的有效入口 |
| 外部点击关闭 | 保留用户刚点击的新目标，不强制恢复旧入口或终端焦点 |
| 点击文件动作 | 返回对应文件树；需要对话框时进入对话框 |
| 异步打开组件完成 | 仅在工作区、目标和交互代次仍相同的情况下进入该组件；用户已点击别处则不抢焦点 |

菜单记录入口的逻辑标识，不能只保存可能已断开的 DOM 引用。父页面收不到 iframe 内的普通指针事件，关闭菜单和焦点判断需覆盖子视图交互；若需补充事件，只通过核心 UI 桥转发通用交互信息。

## 4. 文件菜单设计

### 4.1 文案与操作位置

| 当前名称 | 推荐名称/位置 |
| --- | --- |
| 展开 / 折叠 | 移出右键菜单；由目录行箭头、双击、←/→负责 |
| 下载文件夹 / 下载文件 | 下载 |
| 复制完整路径 | 复制路径 |
| 刷新所在目录 | 刷新 |
| 复制文件条目 / 剪切文件条目 / 粘贴文件条目 | 复制 / 剪切 / 粘贴 |
| 新建文件 / 新建文件夹 | 新建 → 文件 / 文件夹 |
| 上传文件 / 上传文件夹 | 上传 → 文件 / 文件夹 |
| 删除选中条目 | 删除 |

菜单名称只写动作，作用对象由右键目标和选择范围决定；必要解释放在简短提示或对话框中。新建、上传、重命名等打开下一步输入的动作可以使用省略号，但全项目保持一致。

### 4.2 单目录菜单（推荐）

```text
下载
────────────
剪切
复制
粘贴                 不可用时置灰
复制路径
────────────
新建             ›   文件… / 文件夹…
上传             ›   文件… / 文件夹…
刷新
────────────
重命名…
删除
```

第一层由 13 项缩为 10 项，用分隔线区分传输、剪贴板、目录操作和条目修改。保留常用复制/剪切/粘贴为独立行，减少寻找成本。重命名、删除放在末尾；删除使用危险文字色，沿用已有确认机制。

新建和上传各只有一级子菜单。鼠标悬停或点击均可打开；移向子菜单时保持打开，不跨越间隙后立即关闭。子菜单默认向右，空间不足向左；键盘 →/← 打开/返回，Esc 先关闭子菜单，再关闭主菜单。

如果插件视口左右均放不下子菜单，改为从触发项上方或下方展开，并限制内部列表高度，保持触发项可点击。

### 4.3 按右键上下文裁剪

| 上下文 | 显示的主要操作 | 对象与目标 |
| --- | --- | --- |
| 单个目录 | 上述 10 项 | 粘贴、新建、上传进入右键目录；条目操作作用于该目录 |
| 单个普通文件 | 打开、下载、剪切、复制、复制路径、重命名、删除、刷新 | 刷新所属目录；目录写入操作放到目录或空白菜单 |
| 多选 | 下载、剪切、复制、复制路径、删除 | 保留完整选择，不展示单对象打开/重命名或有歧义的目标操作 |
| 文件树空白 | 粘贴、新建、上传、刷新 | 使用文件浏览器当前根目录，不能偷偷沿用上次选择的子目录 |
| 根目录等不可修改的结构项 | 保留仍适用的读取/目录操作 | 不展示不支持的剪切、重命名、删除 |

右键选中项时保持已有多选，右键未选中项时选中该项。菜单打开后固定目标路径与选择快照；后台刷新不得使动作悄悄转到其他条目。

行前箭头、目录双击和方向键已具备展开/折叠能力，本次直接复用；不增加“查看”子菜单继续重复放置。对不支持的文件类型，打开动作沿用现有编辑器检查和错误说明。

## 5. 粘贴可用状态

“亮着”按两种含义处理：可用性必须真实；普通可用项也不持续涂选中色。只有鼠标真实悬停、键盘当前焦点或按压时显示对应背景，禁用项不因悬停变亮。

### 5.1 状态表

| 剪贴板与目标状态 | 粘贴状态 | 原因 |
| --- | --- | --- |
| 尚未读取状态 | 禁用，结果回来后原位更新 | 正在读取剪贴板 |
| 空、只有文本/路径文字/图片或不支持的格式 | 禁用 | 没有可粘贴的文件 |
| 系统剪贴板包含支持的本地文件或目录，目标目录有效且已连接 | 可用 | 执行上传 |
| 文件插件保存了有效远程复制/剪切来源，当前连接上下文与剪贴板 revision 匹配，目标有效 | 可用 | 执行远程复制/移动 |
| 远程来源连接不匹配、连接已更换、revision 已变化或剪切已完成 | 禁用该远程来源；有独立有效本地来源时按本地来源判断 | 需要重新复制 |
| 目标连接断开、目标不存在或不是目录 | 禁用 | 当前目标不可用 |
| 复制/移动目录到其自身或后代等已知无效目标 | 禁用 | 不能粘贴到来源目录内部 |
| 状态读取失败 | 禁用，保留其他操作 | 无法读取剪贴板，可重新打开菜单重试 |

系统剪贴板有效本地文件与远程来源按现有优先顺序处理；本地文件上传不继承系统“剪切”语义，不删除本地源文件。复制路径只产生文字，不启用文件粘贴。

### 5.2 获取与更新方式

- 菜单立即打开，粘贴先禁用；异步结果仅更新该按钮，不重建菜单、不改变焦点、不弹提示。
- 打开菜单、窗口重新激活，以及本插件复制/剪切完成后刷新状态。菜单可见期间按轻量、单请求在途的方式检查 revision/格式变化，使外部复制文件后状态也能更新；关闭即停止。不得长期读取剪贴板或扫描文件树。
- 所有响应带菜单代次和连接上下文核对；旧菜单、旧目标或旧 revision 的结果不得更新新菜单。
- 点击粘贴时再次核对 revision、来源和目标，避免菜单打开后剪贴板已变化却执行旧来源。失败时给出简短具体原因，仍由实际文件操作检查远端操作系统权限。

职责划分：

1. 核心提供通用本地剪贴板状态：revision 与是否有受支持的文件格式。查询不注册上传 input、不预创建任务、不读取文件内容。
2. 文件插件提供只读远程剪贴板状态，核对连接上下文、revision 和剪切消费状态，不创建 selection 或消耗剪贴板。
3. 文件 UI 合并这两份状态与固定目标，计算粘贴是否可用。远程文件规则留在插件中。

当前 `input.revision` 虽然返回 `count`，但原生实现的 revision-only 路径不枚举文件，不能把 `count === 0` 当作“无文件”。实施时需补充真实格式状态，使用 UI v1 的兼容增量字段或通用查询；旧核心无法判断时按未知状态处理，不能虚构“可用”。相关 API 文档在接口实施时同步更新。

## 6. 菜单外观、尺寸与定位

### 6.1 完整外框

菜单采用“外层浮框 + 内层列表”，子菜单采用相同结构。外框负责背景、完整描边、圆角、阴影和定位；外框不承担滚动，内部列表在确实超高时才纵向滚动。

优先复用核心组件菜单已验证的结构，保持现有透明边框占位和主题描边厚度。避免在滚动元素上绘制负 inset 描边；不要用把所有滚动条隐藏的方式掩盖内容溢出。

- 常规菜单建议宽 208–224 CSS px，行高 30–32 CSS px，左右留白 10–12 CSS px，图标 16 CSS px。
- 这些尺寸按 CSS 逻辑像素验收，不用截图物理像素倒推。高 DPI 下仍保持适当密度。
- 图标靠左、短名称居中对齐到同一文字列，子菜单箭头和实际已支持的快捷键靠右。未实现的快捷键不显示。
- 背景为不透明主题面板色；描边沿用主题变量，圆角约 8–10 CSS px。多巴胺主题维持较清楚的深色边缘。
- 常规项目不省略短名称；组件长标题可以省略并提供完整提示。

### 6.2 定位与溢出

1. 在不改变焦点的情况下挂载并测量实际尺寸，首帧完成定位，不能先闪到左上角再移动。
2. 面板菜单锚定入口，默认向下；侧栏底部“更多”向上。右键菜单靠近指针，必要时整体向上/左移。
3. 核心菜单使用核心视口；文件菜单留在自己的 iframe 中，使用 iframe 的可用宽高，不越过插件边界覆盖终端。
4. 外框与视口边缘至少保持 6–8 CSS px；子菜单与主菜单保留可连续移入的区域。
5. 常规 10 项菜单通过分组和紧凑布局完整展示，无横、纵滚动条。空间确实不足时，只让内层列表纵向滚动，外框四边始终可见；任何尺寸下均不出现横向滚动条。
6. 字体放大时允许菜单自然增宽到视口上限，不压缩字体；高度不足沿用内部纵向滚动。窗口缩放、插件面板尺寸变化后重新定位，目标已消失则关闭并采用焦点回退规则。

短操作菜单与长组件/页面列表是不同内容形态。长列表继续保留内部纵向滚动和固定搜索框，不能为追求“所有菜单无滚动条”而使最后一项不可达。

## 7. 面板更多菜单的文案整理

图 1 的面板设置菜单同步缩短文案，明确区分当前操作和新工作区默认设置：

```text
移到左侧 / 移到右侧
隐藏入口 / 固定入口
入口置顶
────────────
✓ 新工作区自动展开
恢复推荐布局
```

“新工作区自动展开”使用带勾选状态的菜单项，表达默认偏好；取消勾选等价于新工作区默认隐藏，不影响当前已打开面板。“隐藏入口”只改变工具栏固定状态，面板收起仍由标题栏减号完成。“恢复推荐布局”保持现有动作范围，不能扩展为清空所有工作区布局。

## 8. 实施拆分与验收

按三个完整问题分别实现、测试和提交，核心与文件插件独立构建和分发：

| 顺序 | 完整改动 | 验收重点 |
| --- | --- | --- |
| P0 | 工作台按钮节点、点击和异步焦点稳定性 | 按压中刷新仍执行一次；不误触、不抢焦点 |
| P1 | 文件菜单分组、短文案与粘贴状态 | 各上下文操作正确；空剪贴板禁用；有效来源启用 |
| P1 | 文件菜单外框、子菜单定位与内部溢出；面板菜单文案整理 | 四边可见、常规无滚动、小窗口仅内部纵向滚动 |

### 8.1 必须加入的回归

- 真实事件序列：`mouse.down → 工作台刷新 → mouse.up`。覆盖两侧组件入口、面板更多、收起和内部 Tab，分别检查节点身份、焦点和动作次数；不得只调用 `element.click()`。
- 无关状态更新与真正的单项变化都不能重建其他按钮。组件在按压中退出则取消，不操作其他实例。
- 菜单入口再点击关闭、入口之间一次切换、外部点击和 Esc 的焦点去向；异步打开组件期间用户转向别处，完成后不夺回焦点。
- 空剪贴板、纯文字路径、有效本地文件、同连接远程复制/剪切、不同连接来源、剪切消费、revision 改变、菜单关闭后的迟到响应。
- 单目录、单文件、多选、空白菜单，验证作用对象、目标目录和选择快照；禁用项不可通过鼠标或键盘执行。
- 新建/上传子菜单的右侧/左侧展开、跨菜单移入、方向键和 Esc；主菜单四边可见、无横向溢出。
- 检查 `scrollWidth/clientWidth` 与 `scrollHeight/clientHeight`，配合截图检验描边，允许布局舍入误差，不以“能点到项”代替几何验收。

### 8.2 平台、主题与命令

浏览器回归覆盖三主题、1100×720 和 720×480 主窗口、约 240–400 CSS px 插件宽度及不足 360 CSS px 的插件可用高度。正常尺寸无滚动，极小尺寸内部纵向滚动可到最后一项。

实施后按受改动范围运行 `npm run check`、`npm run scripts:test`、`npm run test`、`npm run web:build`；工作台使用现有工作区及正式前端 UI 回归，文件菜单使用现有文件 UI/流程回归。涉及 Rust 状态服务时补充对应格式检查、单元测试及真实文件流程。核心用 `npm run build`，文件插件用 `npm run plugin:build -- --plugin files` 独立打包。

Windows x86_64/ARM64、Linux x86_64/ARM64、macOS ARM64 均需验证实际产物的启动与退出；交互还需各平台原生 WebView 验证，包括失焦后第一次点击、按住时异步刷新、100%/150%/200% 显示比例及混合 DPI 切换。交叉编译或 Chromium 成功不能替代这些实际设备验证。
