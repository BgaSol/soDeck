# SSH 端口转发与跳板共用能力：功能需求

状态：功能已在独立分支实现；验证结果和待完成的原生验收见 [实施与验证记录](port-forwarding-implementation.md)。整理日期：2026-10-16。

本文定义本次要交付的功能、默认行为和验收标准。实现方案见 [端口转发设计](port-forwarding-design.md)；功能范围与行为以本文为准，技术参数以实现验证结果为依据。

## 1. 本次目标

本次交付两项相互配合的能力：

1. 新增本地 TCP 端口转发，让本机应用通过已有 SSH 服务器访问服务器自身或其内网中的服务。
2. 从现有跳板连接中抽出共用的 SSH 转发内核，跳板与新功能共同使用；现有跳板的用户配置、逐跳认证和使用体验保持兼容。

典型场景：本机 DBeaver 连接 `127.0.0.1:13306`，SoDeck 经由服务器 B，将连接转发至 B 能访问的 `db.internal:3306`。数据库账号和密码仍在数据库客户端中填写。

本次支持路径：

```text
直连：本机应用 → 本地监听端口 → SSH 服务器 B → 目标 TCP 服务
跳板：本机应用 → 本地监听端口 → SSH 跳板 A → SSH 服务器 B → 目标 TCP 服务
```

目标服务无需作为 SSH 服务器保存，也无需安装 SoDeck 代理。SSH 服务和账号需要允许向目标转发；不要求开启交互终端、SFTP 或安装远端命令工具。

## 3. 共用跳板能力（F01、F05）

- 跳板与本地端口转发共同使用 SSH 通道建立、双向字节传输、背压、半关闭、超时、取消和资源释放能力。
- 既有连接层负责服务器路径、逐跳认证、指纹检查和连接身份。
- 跳板内部通道由使用它的 SSH 连接持有。用户无需创建额外端口规则，内部通道也不作为用户规则显示或单独停止。
- 本地端口规则由应用后台管理器持有，不依赖终端标签是否存在。
- 共享实现，但终端、文件任务和不同转发规则仍分别持有自己的物理 SSH 路径。停止规则不得影响其他业务。
- 一条规则内的多个业务连接共用该规则的 SSH 连接，各有独立通道。多连接的数据不可串流。
- 支持当前单层跳板 A → B；目标业务服务不计作新的 SSH 跳板。
- 跳板 A 中断会使其承载的 SSH B 失效，由业务层决定是否重新建立完整路径。不得把旧 SSH 字节流直接续接到新连接。
- 共用内核上线前，现有终端、SFTP、文件任务、Docker 和日志的跳板路径必须通过回归。

## 4. 管理界面（F02、F03）

### 4.1 入口

- 主工作区提供“端口转发”全局入口，显示当前已就绪规则数量，并在存在失败或需处理状态时显示标记。
- 点击打开独立的单实例管理窗口；重复打开恢复并聚焦原窗口。
- 服务器选择界面提供“配置端口转发”入口，打开管理窗口并预选服务器。
- 从已连接会话进入也可预选服务器，并展示本次将采用的完整连接路径。
- 没有任何终端标签时，仍可创建和启动规则。

### 4.2 列表、详情与操作

列表支持按名称、经由服务器和目标地址搜索，显示名称、本地地址、目标地址、经由服务器、状态和活动连接数。空列表、无搜索结果、失效服务器引用和失败状态均有明确说明。

详情显示完整 SSH 路径、实际监听地址、运行开始时间、双向速率和累计量、最近目标连接结果以及近期运行事件。

操作包括新增、编辑、删除、启动、取消启动、停止、重试、处理认证、复制本地地址、测试目标连接，以及可选的打开网页。只显示或启用当前状态适用的操作。

窗口外观沿用应用现有标题栏和主题；键盘可完成表单和列表操作，状态不只用颜色表达，长地址和错误可完整查看。

### 4.3 新建规则字段

| 字段 | 要求与默认值 |
| --- | --- |
| 名称 | 必填；可重名，使用内部 ID 区分 |
| 经由服务器 | 从已有服务器中选择；展示直连或单层跳板路径 |
| 目标地址 | 必填；域名、IPv4 或 IPv6，交由最终 SSH 服务器解析/连接 |
| 目标端口 | 必填；1–65535 |
| 本地地址 | 默认 `127.0.0.1`；高级选项可选 `::1`，一次只监听一个地址 |
| 本地端口 | 固定端口或自动分配；固定模式要求 1–65535 |
| 断线自动重连 | 默认开启 |
| 网页打开方式 | 默认“无”；可选 HTTP 或 HTTPS，只影响打开链接 |

表单展示本机地址、完整 SSH 路径和目标地址。提供“保存”和“保存并启动”。地址与端口分开填写，目标字段不接受 URL 或路径。

目标地址旁明确说明：“由经由服务器访问；127.0.0.1/::1 表示该服务器自身。”本地访问地址明确使用 IP，避免 localhost 的地址族差异。

### 4.4 编辑与删除

- 名称和网页打开方式属于展示设置，保存后立即更新。
- 经由服务器、目标、本地监听参数和自动重连策略属于运行设置。已停止时保存即可；运行时提供“保存，下次启动生效”和“停止并应用”。
- 保存运行设置后，当前运行快照保持不变，界面显示“有修改待应用”，详情可区分当前运行值和已保存值。普通网络自动重连不会应用待生效修改。
- “停止并应用”先终止旧运行，再按已保存设置启动。如果新启动失败，保持失败状态，不暗中恢复旧目标。
- 底层服务器配置变化也不热切换现有隧道；需要用户显式重新启动才能应用新路径或配置。
- 删除持有运行资源的规则，先说明会停止该规则并关闭其连接，确认后停止并删除；纯配置删除不影响其他规则。
- 被规则引用的服务器需先修改或删除对应规则，才能删除服务器配置。

## 5. 监听、认证和连接（F04、F05）

- 默认只允许本机访问；本次不提供 `0.0.0.0`、`::` 或指定局域网网卡监听。
- 固定端口被占用时显示冲突，不自动换端口、不终止占用进程。重复规则可以保存，但同一地址端口不能同时启动。
- 自动端口由系统分配并保持占用，显示最终可用端口。自动重连保留端口；停止后再次启动可能改变。
- 目标域名由最终 SSH 服务器解析；本机无法解析该域名不能阻止转发。
- 复用服务器的密码、私钥、SSH Agent 和指纹机制，规则不单独保存 SSH 凭据。
- 所有 SSH 跳分别认证和检查指纹；首次或变更时通过管理窗口处理。
- 数据库或 Web 的账号认证仍由对应业务客户端完成。
- 支持浏览器和数据库连接池的多条并发连接，并限制等待队列、连接数和缓冲用量。超限快速失败并显示原因，不无限排队。
- 一次业务连接失败通常只结束对应连接；底层 SSH 失效时结束该规则中的旧业务连接。
- 业务数据在本机 socket 和 SSH 通道之间转发，不经由界面、不执行内容、不写入日志。

## 6. 生命周期与重连（F06、F07、F11）

### 6.1 用户操作与结果

| 操作或事件 | 规定行为 |
| --- | --- |
| 双击启动、重复请求 | 同一规则只有一代活动运行，不重复监听 |
| 首次启动 | 保留本地端口，建立 SSH 路径并完成认证 |
| 首次启动失败/取消/认证超时 | 释放端口和本次连接，显示原因；由用户重试 |
| 关闭尚未完成首次启动的管理窗口 | 取消本次启动尝试，释放端口和连接 |
| 关闭已经运行的规则所在管理窗口 | 转发继续，重新打开可查看状态 |
| 关闭、切换、拖出或移回终端标签 | 不影响端口转发 |
| 网络断线且开启自动重连 | 关闭旧业务连接，保留本地端口，重建完整路径 |
| 网络断线且关闭自动重连 | 释放运行资源，显示“已停止 · 连接中断”，由用户重新启动 |
| 自动重连遇到认证/指纹问题 | 保留本地端口，进入“需处理”，暂停自动尝试 |
| 在重新认证过程中关闭窗口/取消/超时 | 结束本次认证尝试，仍为“需处理”，保留端口直至处理或停止 |
| 点击停止 | 取消启动/重连计时，关闭监听、业务连接及该规则的 SSH 路径 |
| 退出应用 | 在现有退出流程中统计并停止全部规则，等待资源收尾 |
| 再次启动应用 | 读取已保存规则，全部为已停止；不自动启动 |

首次启动未完成时关闭窗口取消启动，与已运行规则在后台重连的行为分开处理。后台重连如需用户交互，只显示需处理标记，用户打开管理窗口后再发起交互。

有活动业务连接时，停止前展示会中断的连接数量；没有活动连接时可直接停止。确认停止后到达的新连接同样归该次停止处理，不允许迟到的认证、重连或启动结果重新开启规则。

### 6.2 自动重连规则

- 自动重连适用于该次运行已经成功启动之后的可重试网络故障。首次启动失败不无限自动尝试。
- 使用带轻微抖动的退避，约 1、2、4、8、16、30 秒，最大间隔约 30 秒；显示原因、次数和下次尝试时间。
- 用户停止、应用退出优先取消重连，不等待下一次重试时间。
- 在启动未就绪、重连和需处理期间，若本地端口仍保留，接入的新连接快速关闭；不积压业务数据等待恢复。
- 成功重连仅恢复新连接能力，已中断的 TCP 会话不能透明续接。数据库客户端和浏览器自行重连；SoDeck 不重放 SQL、HTTP 请求或旧字节。
- 每次重建都校验各跳身份。认证失败或主机密钥变化不能作为普通网络错误无限重试或自动接受。
- 私钥口令和本次认证上下文仅按运行需要保留在内存中；停止后释放该规则持有的引用。
- 业务连接长期空闲是合法状态；不能仅凭无业务流量判定断线。断网、黑洞网络和休眠恢复需验证实际探测及恢复行为。

## 7. 状态、诊断和访问操作（F08、F09）

### 7.1 规则状态

| 状态 | 用户可理解的含义 |
| --- | --- |
| 已停止 | 当前没有监听和转发连接；可附上次停止原因 |
| 启动中 | 正在保留端口、连接或认证 SSH 路径 |
| 等待认证/核对指纹 | 展示具体服务器和步骤，等待用户回答 |
| 已启动 | 本地监听与 SSH 路径已就绪，可以接收业务连接 |
| 正在重连 | 原路径中断，正在按退避恢复 |
| 需处理 | 需要修正认证或核对身份，自动重试暂停 |
| 启动失败 | 本次启动未成功，显示阶段与原因 |
| 停止中 | 正在取消操作和释放资源 |

规则状态、目标最近连接结果和“有修改待应用”分别展示。例如可同时显示“已启动”和“最近连接目标失败”，不能把一次目标失败显示成整个 SSH 路径已断开。

### 7.2 测试目标连接

- 已启动的规则提供“测试目标连接”，每规则同时最多一项测试，支持取消和超时。
- 测试从最终 SSH 服务器向目标打开 TCP 通道后关闭，不发送数据库、HTTP 等业务请求。
- 结果说明来源服务器、目标、成功/失败和时间；服务端可能记录这次短连接。
- 测试证明目标 TCP 可连接，不证明数据库登录、HTTP 内容或应用功能正确，也不代替本机应用的端到端使用验证。
- 第一版不后台轮询目标健康，不自动识别服务类型。未启动规则提示先启动再测试。

### 7.3 错误要求

至少能区分：配置/引用失效、本地端口冲突、入口 SSH 不可达、跳板到目标 SSH 失败、认证失败、主机密钥问题、转发被拒绝、目标通道建立失败/超时、连接数超限。

显示发生阶段、涉及的服务器、目标和底层实际给出的原因。底层只提供通用错误时保留通用描述，不自行判断一定是 DNS、防火墙或权限问题。目标错误可再次测试或由新业务连接重试，SSH 认证错误引导至需处理操作。

### 7.4 地址复制和网页打开

- 已启动时可复制实际本地 `host:port`，详情中可分别复制主机、端口。
- IPv6 组合地址使用 `[::1]:端口` 格式；自动端口确定前不提供虚构地址。
- HTTP/HTTPS 打开方式显式设置后，可使用系统默认浏览器打开本地链接；地址从该次实际监听值生成。
- 未就绪时禁用访问操作；详情仍可查看、复制配置字段，并明确其不是当前可用地址。
- 不改写 HTTP Host、HTTPS SNI、证书或重定向，不绕过浏览器证书检查。依赖原始内网域名的站点需保留使用边界说明。

## 8. 存储、流量与事件（F10、F11）

- 规则持久化在本机，包含服务器引用、转发地址、端口和行为设置；不额外复制密码、私钥或业务凭据。
- 活动连接、监听 socket、运行认证上下文和实际运行状态不作为下次自动恢复依据。
- 外部修改或重建服务器数据库后，失效引用显示“请选择服务器”，不得自动绑定同名配置。
- 配置并发修改需要冲突检查，不能由过期窗口静默覆盖新配置。重建服务器数据库前也检查活动隧道。
- 每条规则显示当前运行的业务发送/接收速率和累计量；自动重连延续该次累计，停止保留本次摘要至下一次启动或退出应用，新的显式启动重新计数。
- 现有应用通信统计增加端口转发分类，延续 SSH 传输层计量。规则的业务字节与含 SSH 开销的统计分开命名，不相加，跳板外层不重复计数。
- 展示近期启动、停止、断线、重连、认证及目标失败事件，重复错误合并计数。事件记录有界，第一版只保留在应用运行内存中。
- 日志和事件不保存转发载荷、SQL、HTTP 内容或认证秘密。
- 即使没有终端会话，只要存在启动中、运行、重连或需处理的规则，退出流程也必须识别并关闭其资源。

## 9. 本次不包含

| 不纳入项 | 边界 |
| --- | --- |
| 远程转发 `ssh -R` | 本次仅本地端口到远端服务 |
| SOCKS5 动态代理 `ssh -D` | 本次每条规则固定一个目标 |
| UDP、Unix socket 转发 | 本次仅 TCP 端口 |
| 多层跳板 | 沿用当前一层 A → B |
| 局域网共享监听 | 本次只提供回环地址 |
| VPN、系统代理、自动修改 hosts | 本次不改变系统网络配置 |
| 自动改写网页或集群节点地址 | 域名、证书及服务发现遵循客户端原行为 |
| 跨功能共享 SSH 连接池 | 共享内核，各业务分别持有连接 |
| 规则分组、批量操作、导入导出 | 后续按需求设计 |
| 应用启动自动启用、退出后驻留 | 本次手动启动，随应用退出停止 |
| 长期流量历史和业务内容审计 | 本次只做当前运行统计与近期事件 |

Redis Cluster、MongoDB 副本集等服务可能返回其他节点的内网地址，单个端口映射不保证完整集群可访问。数据库 TLS/HTTPS 仍由业务客户端和目标服务处理，SSH 认证不替代业务认证。

## 10. 验收标准（F12）

| 编号 | 验收场景 | 必须满足 |
| --- | --- | --- |
| A01 | 普通直连 | 本机通过配置端口访问真实测试 TCP 服务，双向字节一致 |
| A02 | 单层跳板和远端域名 | A → B 正确工作，目标域名仅 B 可解析也能连接 |
| A03 | 服务器自身服务 | 目标回环地址指向最终 SSH 服务器 |
| A04 | 原有业务回归 | 终端、SFTP、文件任务、Docker、日志经跳板正常工作 |
| A05 | 生命周期隔离 | 关闭终端、停止其他规则、移动窗口都不误断本规则 |
| A06 | 端口与 IPv6 | 固定冲突、自动分配、重复启动、IPv4/IPv6 和地址复制正确 |
| A07 | 并发与完整性 | 浏览器/连接池式并发，无串流、丢字节、无限缓冲，半关闭响应完整 |
| A08 | 权限与认证 | 真实 OpenSSH 限制生效，各跳密码/私钥/可用 Agent 和指纹流程正确 |
| A09 | 故障恢复 | 断网、黑洞、休眠后按约定处理；新连接恢复，旧请求不被重放 |
| A10 | 窗口与认证取消 | 首次启动和重新认证关闭窗口的不同资源行为正确 |
| A11 | 配置变更 | 运行快照不热切换，待应用状态清楚，新启动失败不自动回旧目标 |
| A12 | 目标测试和诊断 | 可达性与业务认证区分；目标失败不误停其他正常连接 |
| A13 | 保存与退出 | 重开恢复配置且不自启，任何活动规则都纳入退出收尾 |
| A14 | 无终端运行 | 仅使用转发权限即可连接，不要求 PTY、SFTP 或远端命令 |
| A15 | 资源与统计 | 停止释放资源，反复启动/重连无累积泄漏，流量不重复计量 |
| A16 | 三平台原生验证 | Windows、macOS、Linux 的监听、认证、窗口、停止和退出行为一致 |

验证包括 Rust 协议/状态测试、隔离 OpenSSH 与目标服务的真实联调、界面交互测试及原生桌面验收。吞吐、空闲 CPU、并发上限和内存需要实际测量；设计中的初始预算不是已验证的性能承诺。

## 11. 实施顺序

1. 抽取共用转发内核，保持现有跳板行为并完成回归。
2. 实现无界面的本地转发，验证真实协议、并发和生命周期。
3. 完成规则存储、独立认证、状态机、重连与退出处理。
4. 完成管理窗口、访问操作、诊断、统计和三平台验收。
