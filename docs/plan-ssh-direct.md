# 核心 SSH 直连实施计划

状态：历史设计提案，未实现。2026-11-05 用户将本轮范围改为混合多层跳板、真实终端、文件查看/下载/小文件修改及带宽统计，执行范围以 [远程工作台设计](plan-remote-workbench.md) 为准。下文保留为直连基础的历史说明，其中“本轮拒绝跳板”等限制不再适用于当前计划。

## 1. 本轮目标与边界

用户从现有服务器目录发起真实 SSH 直连；完成服务器身份检查及密码或私钥认证后，核心建立连接会话，并交给现有工作台。用户能取消、断开、手动重连；关闭工作台、退出及升级重启能正确结束连接。

本轮交付核心连接能力，不交付终端、文件、网络转发、Docker 或 NetBird 的业务实现。自动验收通过非交互测试命令验证会话可用，不在产品中增加临时命令输入框。没有业务插件时，连接成功仍能打开工作台、查看状态和断开。

只接受 `route: []`。已有非空路径仍可维护，但发起连接时返回“本版尚未支持跳板连接”，不得忽略路径或回退直连。直连的域名由本机解析；后续多跳仍遵守首站本机访问、后续地址交给紧邻前站 SSH/SOCKS 服务解析的约定。

不增加插件权限、系统凭据库、凭据加密、SSH agent、读取用户 SSH config、交互式多因素认证、自动后台重连或启动自动连接。

## 2. 用户流程

1. 服务器详情增加“连接”；列表仍按现有方式选择记录，不把单击行改成登录。保存资料仍是独立动作。
2. 核心读取所选资料及可用凭据，生成连接尝试，立即反馈阶段；网络工作不阻塞界面。
3. 缺少密码、私钥路径或加密私钥口令时，在核心弹窗补填。已有记住选项继续有效，默认不勾选；补填值只在核心需要的连接流程中使用，普通快照、事件、插件及日志不包含秘密。
4. 完成 TCP 和 SSH 握手后检查服务器主机密钥；确认后才提交认证秘密。首次连接展示目标地址、密钥算法及 SHA-256 指纹，用户选择信任或取消。
5. 已记录的密钥一致则继续；密钥变化时暂停，展示旧值与新值，通过明确的“更新指纹并继续”操作更换信任记录，不静默覆盖。
6. 认证成功且该尝试仍有效，核心登记真实会话，再调用已有 `accept_connected`。仅此时创建并激活服务器工作台。
7. 失败在原入口显示阶段、原因及重试操作，不创建假工作台。取消后不再弹出该尝试的补填或指纹对话框。

用户等待补填或指纹确认时可取消。错误口令不自动反复尝试，用户修正后重新发起，避免无意触发服务器锁定策略。用户未勾选记住的值不写入文件；失败后不把输入自动改成记住。

同一 `serverId` 同时只允许一个有效连接尝试：重复点击定位当前进度，已连接则定位既有工作台及其窗口；已断线则定位工作台并提供重连。相同地址的不同档案仍按不同 `serverId` 管理。

## 3. 会话和状态

沿用现有 `Context { workspaceId, serverId, connectionId, generation }`，不创建另一套工作台身份。

| 对象 | 保存什么 | 生命周期 |
| --- | --- | --- |
| 服务器档案 | 地址、账号、认证方式、私钥路径、已有保存凭据、路径 | 现有 `servers.json` |
| 连接尝试 | attemptId、serverId、配置身份快照、当前阶段、取消信号、待回复问题 | 仅内存，结束后撤销所有回复入口 |
| 连接会话 | connectionId、连接时的目标信息、真实 SSH 句柄、关联工作台、状态 | 仅内存，连接结束后释放 |
| 服务器信任记录 | 规范化主机地址、端口、密钥算法、公开密钥及指纹 | 新增应用数据目录下 `ssh-hosts.json` |

主机信任按用户填写的规范化地址与端口识别，不按某次 DNS 返回的 IP 或档案名称识别。不同档案使用同一端点时复用信任记录；不导入或修改操作系统的 `known_hosts`。公开密钥不是认证私钥。

连接尝试阶段保持简单：准备资料 → 等待必要输入 → 连接网络 → SSH 握手 → 检查主机身份 → 认证 → 成功；失败和取消为终态。已连接会话另有“已连接 / 正在断开 / 已断开”，不把所有过程塞进工作台的 `connected` 布尔值。

每个异步完成和对话框回复都校验 attemptId、问题标识和当前状态。取消、关闭来源窗口、退出或新尝试取代旧尝试后，迟到的认证成功不得创建工作台；多余 SSH 句柄立即关闭。

连接身份包含地址、端口、账号、认证方式、私钥路径和路径。连接中修改这些资料或删除档案，会取消对应尝试，要求按新资料重新发起；只改名称或分组不取消。临时补填的秘密只能写回仍匹配该身份的档案，不能覆盖后来编辑的新身份。

## 4. 认证与连接行为

- 密码认证使用既有核心保存值或本次输入，不回填已保存密码到界面。
- 私钥在核心按本地路径读取；最低验证 OpenSSH 格式的 Ed25519 与 RSA 私钥，加密及未加密各有用例。具体格式或算法不支持时明确返回原因。
- 保持密码和私钥两种显式认证方式，不自动轮询用户电脑上的其他密钥或改用其他认证方式。
- SSH 算法采用所选库的现代默认策略，协商失败明确提示，不静默放开旧算法。
- 网络连接、握手和认证的非交互等待建议各以 30 秒为初始上限；等待用户输入另算，可随时取消。先固定合理默认值，不增加一页高级设置。
- 连接完成后启用 SSH 保活并监听传输关闭；初始建议每 30 秒探测，连续 3 次失败判定断线。对显式 EOF、重置或协议错误立即更新状态，不等待保活窗口。
- 网络读写在异步任务中进行；不持有目录、工作台或组件注册表的锁等待网络、用户输入或关闭。核心 UI 仍能响应其他服务器的操作。

初始命令执行能力仅用于核心集成验收：有超时、输出上限和退出码，超限即终止，不把无限输出塞进现有 JSON 行 RPC。生产插件的命令、PTY 和大数据流接口留到真实使用阶段确定。

## 5. 断开、重连和窗口

| 操作或事件 | 行为 |
| --- | --- |
| 切换工作台、隐藏面板 | 连接继续运行 |
| 拖出、合回或移动工作台 | 只变窗口归属，连接 ID 与 generation 不变，不重新认证 |
| 主动断开 | 关闭实际连接，保留原工作台及断线状态 |
| 网络意外断开 | 保留原工作台，显示原因，提供手动重连；不自动循环登录 |
| 手动重连 | 更新同一工作台，成功后换 connectionId 并递增 generation，拒绝旧 Context |
| 关闭工作台或含工作台的独立窗口 | 先走已有关闭协调，确认通过后取消相关尝试并关闭连接，再移除工作台 |
| 移走最后一个工作台后回收空窗口 | 不断开已经移走的连接 |
| 退出、插件重启生效或核心更新重启 | 先完成现有表单和组件关闭协调；进入退出后拒绝新连接，允许插件在原有期限内收尾，随后关闭剩余连接再结束进程 |

已建立的连接不因修改档案而改变目标。手动重连重新读取当前资料；若连接身份与原工作台不同，先展示旧目标与新目标及账号变化，由用户明确选择按新配置重连。新资料包含跳板则按本轮边界拒绝。只改密码或口令时按匹配身份取当前凭据，缺少则补填，不恢复已被用户清除的旧保存值。

重连失败不递增 generation、不创建另一个工作台。取消或关闭与重连成功并发时，以仍存活的有效尝试及工作台为准；未被接纳的新连接必须释放。重连不自动恢复远程命令或未来插件任务。

## 6. 界面和错误反馈

复用现有无独立标题栏、多巴胺外观和浮层，不重新设计服务器管理页。

- 服务器详情：连接、进度、取消、失败重试；有工作台时显示“前往工作台”。
- 核心弹窗：补填认证、首次指纹确认、指纹变化确认；回复绑定明确的服务器和连接尝试。
- 工作台：连接状态、断开和重连入口；断线不冒充服务器宕机。
- 右上角系统状态：当前已连接数、正在连接数和连接摘要；不增加默认周期性服务器探活。
- 日志：记录尝试、阶段耗时、连接/断开原因、会话 ID，过滤密码、私钥内容和口令。连接失败在当前操作处反馈，不把每一条普通日志都升级成通知。

内部错误用稳定的 code 和 stage，界面展示可操作的中文说明。至少区分：路径暂不支持、DNS 失败、连接拒绝、连接超时、主机密钥未确认或变化、私钥读取/解析失败、口令错误、认证失败、算法不兼容、连接已取消和连接已失效。

## 7. 代码边界及依赖选型

建议新增 `src-tauri/src/connections/`，按实际职责放置管理器、SSH 适配及主机信任存储。服务器目录通过核心内部接口提供连接资料，继续保持前端只读投影不含秘密。`workspaces.rs` 仍管理工作台归属，不操作 SSH 句柄；关闭协调统一调用连接管理器。

桌面桥只覆盖本轮需要的发起、查询状态、取消、回复认证/指纹问题、断开和手动重连，使用具体类型。状态推送以核心为准，前端重新查询可恢复进度。插件继续取得现有 Context；不提前生成整套文件、PTY 或网络 SDK。

SSH 库优先验证 [russh](https://github.com/warp-tech/russh)。2026-11-05 查询 crates.io 的稳定版为 0.65.1、Apache-2.0、最低 Rust 1.89，仓库当前 Rust 1.99.1 满足版本下限；该项目近期仍有更新。这些信息只能证明候选适配，不能替代五目标构建和认证验证。

其默认 feature 包含 `aws-lc-rs`，不能因 Rust 实现就假定没有原生构建依赖。先验证关闭默认 feature、显式选择 `ring` 与 `rsa` 所需能力的方案，检查支持的密钥格式、包内依赖及原生 ARM64 产物。最终版本和 feature 通过验证后精确固定并提交锁文件，新增异步或密钥直接依赖一并说明用途。

替代方案为 `ssh2/libssh2`，代价是额外 C 库和平台链接维护；调用系统 `ssh` 会引入用户环境、交互认证及进程控制差异，不作为首选。本轮只落设计，不添加生产依赖。

## 8. 四个实施批次

1. **连接管理与选型验证**：验证候选库五目标可构建及最低认证能力；完成核心内部连接资料接口、attempt/session 数据和取消规则。提交主题是核心具备可验证的直连管理基础。
2. **真实认证闭环**：接入 TCP/SSH、指纹存储、密码/私钥、超时及有界测试命令，用隔离测试端验证成功与错误。提交主题是真实认证成功后才能产生可用会话。
3. **界面和生命周期接入**：连接按钮、核心补填弹窗、成功交接工作台、重复点击、断开与重连、窗口移动和退出清理。提交主题是用户能从目录管理真实连接。
4. **回归与发行验收**：补齐真实包流程、五目标验证记录和相关文档，复用现有核心发布与在线更新入口。提交主题是可安装版本能完成连接和清理。

每批在对应层完成集成验证后继续，不先建立通用多协议框架。已有组件 UI 改动保持独立主题，不与本轮连接代码混成一个提交。

## 9. 验收清单

| 场景 | 通过标准 |
| --- | --- |
| 密码认证 | 已保存、仅当前运行、连接时补填分别可用；错误密码不创建工作台 |
| 私钥认证 | 最低支持范围内的加密/未加密 Ed25519、RSA 可用；缺文件、坏格式、错口令可区分 |
| 主机身份 | 首次确认、再次复用、变化暂停、取消不认证；未确认前不提交认证秘密 |
| 路径 | 空路径直连；非空路径在开网络前拒绝，无绕过或直接回退 |
| 超时和取消 | DNS/TCP/握手/认证各阶段可取消，取消后迟到结果不建工作台；等待用户回复可取消 |
| 并发与资料变更 | 重复点击只保留一个尝试；不同档案可并行；身份变更取消尝试；旧回复不影响新尝试 |
| 会话绑定 | 只有真实认证成功创建工作台；拖出合回不重连、不变 Context |
| 断线和重连 | 远端主动关闭和网络失联可识别；重连成功才换代次；旧 Context 无法操作新会话 |
| 清理 | 主动断开、关闭工作台、子窗口关闭、应用退出和更新重启后无残留连接或挂起任务 |
| 敏感数据 | 日志、错误、事件、普通快照和插件无密码或私钥；未记住值不落盘；取消不误写其他身份 |
| 持久化 | 重开保留目录及明确记住的主机信任；不恢复运行会话或自动登录；写失败不显示假成功 |

优先脚本和无头测试，不操作用户鼠标、不使用用户的生产服务器。自动测试端使用隔离地址、临时用户资料和明确生成的密钥；至少增加独立 OpenSSH 服务的互操作检查，不能只用客户端同一库实现的测试服务证明兼容性。

执行现有 `npm run check`、`npm run test`、`npm run scripts:test`、`npm run ui:test` 和前端构建；实现新增用例纳入这些入口，不在文档中列出尚不存在的命令。包内验收在五个原生系统架构组合分别执行启动、连接隔离 SSH 测试端、断开、退出和重开，ARM64 使用原生 ARM64 程序。

复用现有 GitHub Actions/Releases 和更新清单，核心仍独立打包，不因本轮而绑定任何业务插件。发布记录列出每个目标实际完成结果；未运行项不能记作通过。GitHub 构建/运行验证不替代真实设备的所有网络和安装升级场景。

## 10. 完成定义

五目标可交付的核心能按上述流程建立并结束真实 SSH 直连，失败和取消不产生假会话，工作台移动保持连接，原位重连淘汰旧 Context，关闭及更新重启能清理资源。README、产品需求、架构和发布说明同步实际状态。终端等后续业务按各自阶段独立实现和发行。
