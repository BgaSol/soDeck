# Docker 管理 UI 设计

日期：2026-10-17。基于 `docker-management-plan.md` 的四批功能范围，使用 `apple-design` 技能设计。本文件描述拟实现的界面与交互；原型使用示例数据，尚未接入 SSH、Docker 或 Tauri 管理接口。

2026-10-18 实施补充：正式 React／Tauri 界面已接入，实际功能、截图检查与验证范围见 `docker-management-implementation.md`。原型继续用于设计参考，不代表运行中的管理数据。

## 1. 设计结论

Docker 继续作为工作区右侧的一部分，与文件面板、终端保持同一套视觉语言。界面以清晰的对象列表、紧凑的操作区和可展开的信息分组组织内容，主要依靠留白、字重与对齐建立层次。

设计重点是三个连续步骤：定位对象、理解状态、完成操作。用户进入详情后，应立即知道容器是否运行、是否健康，以及下一步可以做什么。

交付内容：

- 交互原型：`docs/prototypes/docker-management.html`。
- 原型样式／交互：同目录 `docker-management.css`、`docker-management.js`。
- 预览图：`docs/prototypes/screens/`。
- 本设计规范：覆盖容器、镜像、项目、创建表单、资源清理、任务反馈、响应式与辅助功能。

原型顶部的“侧栏宽度／演示场景／深浅色／重置”属于设计评审工具，不进入正式产品。原型提供四批功能的整体预览；正式交付按功能批次逐步显示入口。

## 2. 与现有 App 的一致性

本次重新运行当前 Docker 详情的浏览器用例并检查截图，以当前源码为准；历史 `.qa/monitor-ui-docker-*.png` 中的整栏展开布局不作为本次设计基线。

| 项目       | 沿用的规范                                                    | Docker 新界面的使用方式                                  |
| ---------- | ------------------------------------------------------------- | -------------------------------------------------------- |
| 总体布局   | 文件／终端／右侧服务三栏；窄窗口降为两栏或单区域              | Docker 列表与详情只在右栏切换                            |
| 背景       | `--sidebar`、`--surface`、`--canvas`                          | 侧栏保持浅灰／深灰，按钮与弹层使用现有表面色             |
| 强调色     | `--blue`、`--accent-text`                                     | 启动、拉取、创建等推进动作；链接使用文字强调色           |
| 状态色     | `--green`、`--warning`、`--error`                             | 颜色总配文字，健康状态与运行状态分别表达                 |
| 文字       | 系统字体、`--font-body`、`--font-secondary`、`--font-caption` | 对象名称使用 13–16px 的现有层级；辅助信息 11–12px        |
| 标识与路径 | `--mono`                                                      | ID、路径、镜像引用、端口；长内容换行或省略并支持完整复制 |
| 圆角       | `--radius-control`／`--radius-popover`／`--radius-dialog`     | 约 6px 控件、10px 菜单、16px 对话框                      |
| 图标       | 现有 Lucide 线性图标，约 16px、1.7px 描边                     | 使用项目既有图标体系，不增加图标品牌色                   |
| 控件       | 28px 紧凑控件、32px 普通按钮、34px 输入框                     | 详情操作与现有日志／终端按钮尺寸一致                     |
| 菜单与确认 | 现有 `menus.css` 的密度、分组和危险操作                       | 删除放菜单底部，明确对象与影响范围                       |

原型直接引用 `src/theme.css`，不复制另一套 Docker 配色。终端继续使用 App 的终端底色；浅色和深色模式分别由现有主题变量控制。

材质集中用于顶部栏、浮层与任务提示，保留现有的分栏边界。主体内容采用稳定底色，保证高密度文字可读。

## 3. 信息架构与入口

```text
工作区右栏
└─ 监控 / Docker
   └─ Docker
      ├─ 引擎状态、Endpoint、刷新、更多
      ├─ 容器 / 镜像 / 项目
      │  ├─ 搜索、筛选、当前类型的创建入口
      │  └─ 对象列表 → 对象详情 → 返回原列表
      ├─ 更多 → 空间与资源 / 操作记录
      └─ 后台任务摘要（存在任务时显示）
```

- 第一批保留“容器 / 镜像”；Compose 交付后增加“项目”。
- 卷、网络与清理集中在“空间与资源”，不继续横向增加分段。
- 镜像页显示“拉取镜像”，容器页在第三批显示“创建容器”，项目页显示“关联项目”。每页只保留一个创建类入口。
- 引擎区保留 Endpoint。它说明操作目标，不能被服务器名称替代。
- 页面级更多菜单提供低频入口，行级更多菜单只影响该对象。

## 4. 容器列表

从上到下为：引擎摘要、对象类型分段、搜索、状态筛选与创建入口、对象列表、简短异常摘要。

容器行高度约 60–64px。第一行名称，第二行镜像引用；左侧小状态点，右侧状态文字和更多菜单。默认不把 CPU、端口、运行时长等全部塞入列表。

| 信息           | 展示规则                                             |
| -------------- | ---------------------------------------------------- |
| 正常运行       | 绿色状态点 + “运行中”                                |
| 运行但不健康   | 行尾突出“不健康”，详情继续分别显示“运行中”和“不健康” |
| 已停止         | 中性状态点 + “已停止”                                |
| 重启中／已暂停 | 对应文字；重启异常使用警告色                         |
| 操作中         | 当前对象显示“操作中”或具体动作，不替换成最终运行状态 |
| 结果待确认     | 显示“待确认”，详情给出核对入口                       |

状态筛选包含“全部状态／运行中／需要关注／已停止”。需要关注包括明确的不健康、重启异常等，不把未配置健康检查计为异常。

点击主体进入详情；更多按钮独立可达。结构采用带按钮的列表，避免在已有按钮式 `listbox option` 内嵌另一个按钮。方向键可移动对象焦点，Enter 进入详情，Shift+F10 打开对象菜单。自动刷新保持原有稳定排序。

## 5. 容器详情

### 5.1 首屏层次

```text
← 返回容器

api-gateway
nginx:1.27-alpine
● 运行中 · 健康

[停止] [重启] [日志] [···]

概览                         storefront
容器 ID       a18c2d4e6f90  复制
已运行        3 天
重启策略      unless-stopped
最近退出      —

CPU  0.8%           内存  42 / 512 MiB

⌄ 端口与网络       2 个端口 · 1 个网络
  0.0.0.0:8080 → 80/tcp             转发
  storefront_default · 172.20.0.2
› 存储             2 个挂载
› 配置             命令、环境变量与标签
› 进程与资源       按需查看
```

详情左右留白 14–22px，名称最多两行。默认展示概览与端口分组，存储、配置和进程折叠。展开状态按对象保留；环境变量值在离开详情后重新隐藏。

第一批不显示资源采样区域；第二批加入轻量 CPU／内存读数。CPU 默认使用数值，只有确定统计尺度时才使用进度表达，不把多核 CPU 当作固定 100% 容量；内存以用量／限制表达。原型的细条用于预览视觉密度，正式实现须按上述口径接入。

### 5.2 主操作随状态变化

| 容器状态       | 可见操作                       | 更多菜单                                     |
| -------------- | ------------------------------ | -------------------------------------------- |
| 运行中         | 停止、重启、日志               | 终端、暂停、重命名、重启策略、强制停止、删除 |
| 已停止／已创建 | 启动、日志                     | 重命名、重启策略、删除                       |
| 已暂停         | 恢复、日志                     | 停止、重命名；具体可用动作由后端能力判断     |
| 重启中         | 停止、日志                     | 强制停止                                     |
| 执行中         | 原动作显示进度；互斥动作不可用 | 查看任务；日志等独立读取仍可用               |
| 结果待确认     | 核对当前状态、日志             | 查看操作记录                                 |
| 对象已移除     | 保留名称和身份说明             | 返回列表、本地日志档案入口                   |

320–439px 侧栏最多显示三个文字动作和一个更多按钮；440px 起可增加终端快捷入口。按钮尺寸随文字适配，不能靠缩小字体挤进更多操作。

“启动／恢复”可使用蓝色主按钮；停止、重启使用普通按钮。详情不会默认出现大面积红色操作区。普通启停直接执行；强制停止、删除和范围性操作进入确认流程。AutoRemove 等会改变后果的特殊情况单独解释。

### 5.3 详情分组

| 分组       | 内容与交互                                                                                                  |
| ---------- | ----------------------------------------------------------------------------------------------------------- |
| 概览       | 运行与健康、ID、创建／启动／退出时间、退出码、OOM、重启次数与策略；正常状态突出常用字段，异常时优先展示原因 |
| 端口与网络 | 宿主地址、发布端口、容器端口／协议、网络与 IP；确认引擎属当前服务器后可预填转发草稿                         |
| 存储       | Bind Mount／Volume、两端路径、只读／读写；可复制、查看卷详情或定位宿主机路径                                |
| 配置       | Entrypoint、Command、工作目录、用户、环境变量、Labels；值按需展开，原始 inspect 为次级入口                  |
| 进程与资源 | 进程、CPU／内存、累计网络与磁盘 I/O；缺失或过期明确标注                                                     |

外部引擎的宿主路径不能直接定位到当前 SFTP，端口也不能未经确认就预填为当前服务器。对应入口给出原因或进入目标核对。

## 6. 镜像与创建容器

### 6.1 镜像页

列表沿用容器行结构，名称为 `repository:tag`，第二行显示容器引用数量，右侧大小。镜像详情展示 ID、平台、创建时间、大小、所有 Tag 和引用容器。

主要操作为“创建容器”；“拉取更新”为普通按钮；更多菜单提供添加 Tag 与移除引用。无 Tag 镜像用短 ID 展示，完整 ID 可复制。

移除单个 Tag 与删除镜像实体使用不同标题和说明。引用冲突显示具体容器，优先提供查看容器的入口。镜像拉取成功后，已有容器不会在 UI 中被标记成已升级。

### 6.2 拉取镜像

使用约 460px 的现有风格对话框。默认只有镜像名称输入；平台放高级选项。提交后同一弹层切换为进度，不再打开第二个弹层。

进度按“连接仓库 → 下载层 → 校验与解压 → 完成”显示。能得到可信字节数才显示百分比；其余使用阶段与不定进度。“后台运行”关闭弹层，任务进入侧栏底部摘要。完成定位新镜像，失败保留原因。

### 6.3 创建容器

使用约 580px 的任务对话框，长表单内部滚动，操作区保留明确的取消与“创建并启动”。

- 顶部：镜像、容器名称、重启策略。
- 默认展开“端口发布”：宿主端口、容器端口、协议、绑定地址。
- 可展开“存储”：类型、源路径／卷、目标路径、只读选项。
- 可展开“环境变量与网络”：键值行、网络选择；进一步高级项包含命令与工作目录。
- 名称与端口格式在输入时校验；服务端冲突显示在对应字段或表单顶部。
- 创建成功但启动失败时保留对象，结果写成“已创建，启动失败”，提供详情与日志入口。

此流程沿用现有表单、对话框和文件选择习惯。首版支持基础独立容器，复杂部署通过项目配置处理。

## 7. Compose 项目

项目列表行展示项目名、配置路径、运行服务数与关注数量。没有可用配置的项目显示“待关联配置”，主操作引导关联文件，不直接猜测工作目录。

项目详情与容器详情保持同样层次：返回、名称与配置路径、运行摘要、操作、服务列表、项目配置。

| 入口       | 用户理解                     | UI 行为                              |
| ---------- | ---------------------------- | ------------------------------------ |
| 启动       | 启动已存在的服务容器         | 项目与服务显示进度                   |
| 停止       | 停止服务，保留对象           | 多对象操作显示影响服务摘要           |
| 重启       | 使用当前配置重启服务         | 不显示成应用配置或更新版本           |
| 更新部署   | 拉取镜像并应用配置，可能重建 | 预览服务、文件和保留的卷，再提交     |
| 日志       | 查看项目各服务日志           | 首版按服务打开已有日志窗口           |
| 编辑配置   | 修改已关联 Compose 文件      | 打开既有文件编辑器，保存后不自动部署 |
| 停止并移除 | Down 的实际效果              | 更多菜单中的危险动作，预览容器与网络 |

Down 确认明确保留卷。将来若支持删除卷，单独列出卷并再次确认，不默认勾选。项目移除后保留配置关联，详情显示“尚未部署”，主操作变为“部署项目”。

## 8. 空间、卷、网络与维护

“空间与资源”从引擎更多菜单进入，仍在右栏显示。顶部为总占用与可回收估计，下面按镜像、容器、卷、构建缓存逐行列出。卷与网络列表通过分组展开。

清理采用两步：先选择类型，再预览对象。确认按钮写“清理所选内容”，同时显示所选数量。卷删除独立处理，不包含在默认清理范围。完成显示实际结果，部分失败保持逐项状态。

| 后续维护能力     | UI 入口与规则                                                                   |
| ---------------- | ------------------------------------------------------------------------------- |
| 批量操作         | 列表更多 → 选择多个；进入选择模式后显示复选框与底部操作条，离开模式恢复普通列表 |
| 容器文件上传下载 | 容器更多 → 文件传输；明确本机／服务器／容器路径，结果进入任务记录               |
| 镜像导入导出     | 镜像页更多；使用现有路径选择和传输进度语言                                      |
| 卷创建／删除     | 空间与资源 → 卷；详情展示引用容器，删除数据使用明确确认                         |
| 网络连接／断开   | 网络详情 → 已连接容器；操作前列出目标与影响范围                                 |

批量条只显示当前集合共同可执行的动作；结果按对象列出成功、失败、结果待确认。列表宽度保持稳定。

## 9. 操作反馈与确认

### 9.1 日常操作

点击后立即产生按下反馈，随后当前动作显示忙碌；列表和详情同步。等待远端时仍可搜索、切换对象和查看日志。已提交操作不会随详情关闭而重新发起或隐式取消。

侧栏底部出现一条任务摘要：图标／进度、动作与对象、状态、任务数量。点击打开操作记录。一次任务完成可短暂显示成功提示；失败与结果待确认保留到用户处理。状态通过 live region 同步给读屏软件。

### 9.2 结果待确认

使用警告色的局部说明：

> 操作结果待确认
> 连接在执行中断开，容器可能已发生变化。
> 核对当前状态

不直接显示“失败，重试”。用户先核对对象，确认后才恢复管理操作。当前目标名称、ID 与引擎始终可查看。

### 9.3 确认框

确认框包括具体动作标题、后果说明、对象摘要、取消与具体动作按钮。对象摘要显示名称、短 ID、服务器与 Endpoint；完整身份可复制。

- 删除：说明容器可写层会丢失、卷与镜像是否保留。第一批要求先停止再删除；后续强制删除单独设计明确选项。
- 强制停止：说明进程立即终止，可能无法完成清理。
- AutoRemove：普通停止前提示退出后的删除行为。
- 初始焦点在取消；不能把 Enter 默认映射到危险动作。
- 不提供无法兑现的“撤销”。

## 10. 空态、异常与页面连续性

| 场景                 | 处理                                             |
| -------------------- | ------------------------------------------------ |
| 首次加载             | 保留页面结构与简短加载状态，列表区域显示加载反馈 |
| 无容器／镜像／项目   | 小图标、标题、一句说明、一个下一步入口           |
| 筛选无结果           | 显示“清除筛选”，不误报为服务器上没有对象         |
| 无 Docker 命令       | 明确“当前账号未找到 Docker 命令”，提供重新检测   |
| 无权限／引擎不可达   | 显示原因；保留已有数据并标记最后更新时间         |
| 连接中断             | 保留列表和详情，停用管理动作；本地档案仍可阅读   |
| 对象被删除／同名重建 | 保留原 ID 与说明，不自动切换到新对象             |
| 健康状态未知         | 明确“未知／未配置”，不显示为健康                 |
| 操作失败             | 原位显示具体原因，保留筛选、选择与滚动位置       |
| 详情返回             | 回到原列表对象，恢复滚动和键盘焦点               |

任务状态由后端共享，视图不独自推断任务成功。多窗口必须展示一致的对象进度，切换主题、窗口迁移和刷新不应打断任务。

## 11. 响应式、动效与辅助功能

### 11.1 尺寸

- 工作区继续使用现有 1200px／760px 布局阈值；侧栏默认 360px，范围 320–480px。
- 320–439px：单列详情，三个文字操作加更多，路径允许换行；不出现水平滚动。
- 440–480px：可加入终端快捷操作，仍保持单列信息分组。
- 小窗口：延续现有单区域切换；弹层宽度为视口减左右留白，表单列自动堆叠。
- 若未来引入更宽独立管理窗口，可使用列表／详情并列；不作为当前侧栏的前提。

### 11.2 Apple Design 的具体应用

| 原则         | 本设计中的表现                                          |
| ------------ | ------------------------------------------------------- |
| 即时响应     | pointer-down 即给反馈，提交动作在 click／键盘激活时发生 |
| 熟悉性       | 沿用工作区分栏、分段、菜单、输入框和独立日志窗口        |
| 空间连续性   | 列表与详情按同一路径往返，返回恢复原对象位置            |
| 可打断       | 导航过渡期间不锁输入，反向操作从当前视觉位置继续        |
| 克制的物理感 | 详情切换约 8px 位移、临界阻尼弹簧；菜单从触发点附近出现 |
| 渐进展示     | 首屏展示状态和常用动作，高级配置按组展开                |
| 清晰的层次   | 菜单／对话框用材质与深度区分，普通信息使用字重和留白    |

导航弹簧使用阻尼比 1、响应约 0.3 秒；普通颜色反馈约 120ms。无拖拽动量的界面不需要弹跳。减少动态效果时采用静态切换或短淡化；减少透明度时使用实色表面；提高对比度时增加边界清晰度。

### 11.3 辅助功能

- 操作按钮具有完整名称；图标按钮提供 aria-label。
- 菜单支持上下键、Home／End、Esc，关闭后焦点返回触发点。
- 对话框锁定焦点，Esc 取消，关闭后恢复入口焦点；危险操作取消优先。
- 分组使用原生 details／summary 或等价语义，展开状态可被读屏软件识别。
- 不把整个 Docker 页标成 busy；只标记对应对象或任务。
- 状态颜色配可见文字；支持键盘、文字放大和触摸输入。
- 生产实现对细小图标提供足够的实际点击区域；粗指针时增大到约 44px。

## 13. 原型范围与验证
