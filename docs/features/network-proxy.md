# 网络隧道

网络隧道插件在当前服务器工作区管理 TCP 转发和 SOCKS5 代理，默认右侧收起。它复用核心现有认证会话和完整跳板链，与服务器管理中用于建链的 SOCKS5 资料是不同用途。

规则列表、详情和编辑表单复用宿主的 DOM 协调资源，但由插件独立打包并管理草稿、轮询和实体切换。卸载结束计时器、按压队列与监听；卸载或重新挂载前的迟到快照不会重新绘制旧页面。普通轮询不重新创建网络监听。

规则配置先写同目录独占临时文件、同步后原子替换；提交失败保留旧规则，读取损坏时禁止覆盖原文件。临时文件不使用固定名称，保存不改变正在运行的监听。

## 规则与运行

- TCP 转发：本机监听 → 当前服务器 → 固定目标。
- SOCKS5：本机提供无认证的 TCP CONNECT，支持 IPv4、IPv6 和域名；目标域名由最终远端服务器解析，客户端需选择代理解析，例如 `socks5h://`。
- 默认监听 `127.0.0.1`，端口自动分配，也可指定本机 IP 和固定端口。`0.0.0.0` 或 `::` 监听对应地址族全部接口；端口冲突明确报错。
- 规则按服务器保存，支持新建、编辑、删除、启动、停止、复制实际入口和检查连通性。保存只写配置，不修改已经运行的监听。应用新配置需分别停止、确认清理完成、再启动；没有保存并重启的组合动作。
- 启动中、运行中、停止中和状态待确认的规则不能删除；确认清理完成后才可删除，先落盘成功再移除运行记录，写入失败保留规则。收起、切换和移窗保留原端口，断线、工作区关闭、插件或应用退出释放端口；重连和重开后手动启动。

规则文件 `network-rules.json` 只保存配置与服务器 ID，不保存 SSH 凭据或运行状态。当前最多 256 条、512 KiB，原子保存并检查修订；损坏或不支持的 schema 保留原文件。

## 其他插件的快捷入口

网络隧道 0.5.0 在同一核心组件通讯机制上提供普通 TCP 目标的创建／复用和规则定位。后台 manager 按工作区初始化，隐藏或从未显示侧栏也能运行；初始化不启动保存规则。需要核心 commands.v1、sharedState.v1、ui.background.v1 及原有网络／视图能力，缺少时明确提示升级核心。

[Docker 端口](docker.md#容器端口隧道)是首个调用方。新规则保存后启动，默认本机回环自动端口；固定目标的已有回环规则可复用，存在歧义时选择。监听类型、bind、target 必须与固定运行配置一致，配置仅改名不要求重启。状态未知、停止或尚未确认清理、其他 Context 持有时不补建替代规则。手动与快捷路径使用同一保存／启动／停止／检查服务；保存仍不会更改运行监听。

命令回执只表示业务接纳，真实运行和检查结果通过核心共享状态发布。新启动自动检查一次 TCP；复用／加入已有启动不重复检查。检查不证明应用健康，失败不关闭正常监听。跨插件命令和普通 UI 不直接互调，凭据仍在核心。协议字段见[插件 API](../plugin-api.md#网络隧道协作契约)。

创建来源关闭或 Docker 插件退出不结束已交接的监听；资源归网络隧道自己的 manager。核心负责关闭冻结与取消关闭，后台逻辑视图不保留另一套可能无法解除的关闭状态。网络隧道逻辑管理视图／工作区结束、连接断开或本插件退出清理资源；重连不恢复旧运行。规则保持普通固定端点语义，不绑定或追踪容器。

## 状态、检查与边界

显示实际绑定入口、连接数、约三秒速率和本次运行累计有效载荷。查询失败显示“状态待确认”，保留原监听、最后观测时间和累计量，速率标为过期；禁用启动、删除和检查，允许停止原启动或继续查询。停止回执只说明接受取消，必须等核心确认监听、流、转发和探测任务全部退出后才能重新启动或删除。客户端连接错误与整条规则监听失败分开；普通连接错误写日志，重要中断按服务器去重，不因日志级别自动弹消息。

连通性检查经过实际本地入口及 SOCKS5 协商，只证明 TCP 可达，不保证上层服务、认证或业务健康。刷新保留规则节点、输入、焦点和展开状态，不打断按压中的操作。

不提供 HTTP 代理、UDP、反向转发、自动重连或系统代理接管。插件配置规则，核心提供通用监听、TCP 通道、有界协商、字节传输及归属清理；不把 SOCKS5 业务规则放进核心权限系统。

## 操作反馈

规则列表进入详情与返回采用对应方向。启停、待确认、停止中、失败、连通性检查与复制结果即时显示真实文字，不反复淡化或提前显示成功；隐藏页面的迟到反馈不启动动效。节奏和减少动态效果规则见[界面规范](../../DESIGN.md#动效)。
