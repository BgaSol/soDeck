# 日志与重要消息

日志用于排查问题，重要消息用于向用户报告需要知道的结果和中断。它们是两个独立接口，日志级别不决定是否弹通知。

日志和消息各自在管理台中使用完整页面。顶部消息入口打开同一个消息页；切回工作台保留会话和插件页面。

## 日志

核心和插件日志统一存储，附加核心接收时间、插件来源和本次进程实例。插件可写 debug/info/warn/error，并附结构化字段；stdout 保持 RPC 协议，stderr 作为诊断。

日志页可按来源、级别和时间筛选。插件启动、停止、异常退出及受管操作失败保留来源；插件不能通过提供字段冒充另一个实例。当前 JSONL 日志每份约 10 MiB 轮转，最多五份；界面查询为有界结果，不能当成永久审计仓库。

日志与消息接收时间保存为 Unix 毫秒时间戳，界面按本机时区显示。日志起止筛选使用本地日期与时间，输入精度为分钟，提交时转换为毫秒时间戳；清空输入移除对应边界，零时间戳也是有效边界。夏令时重复或不存在的本地时间按系统日期规则解释。

查询磁盘 JSONL 日志时，每行最多 16 KiB（含换行）。遇超长行或不可恢复的读取错误，保留此前读到的记录并停止读取当前文件，继续其余轮转文件，再合并内存回退；未超长但 JSON 格式错误的行仅跳过该行。读取中断的重试规则见[插件 API](../plugin-api.md#通信)。

## 重要消息

消息包含标题、正文和 info/success/warning/error 类型，由核心附加身份、时间和未读状态。消息中心展示历史及未读数，支持已读操作。最多保存 1000 条，超过后淘汰最旧条目。

发布参数独立选择 `notify`，并可通过去重键更新同一事件；普通错误可以留在消息中心而不打断用户。数据写入失败明确提示并保留原文件。需要排障的失败不得只留短暂提示而失去来源。

当前消息没有通用的“跳到对应业务任务”路由；不能解析标题或正文猜测导航目标。消息到任务的后续设计仍待确定。

## 维护约束与入口

不写入密码、私钥口令、完整远端正文或容器环境变量等秘密。生命周期日志由核心产生，业务含义由插件报告；消息接收成功不证明远端操作已经成功。
