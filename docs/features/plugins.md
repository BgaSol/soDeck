# 插件管理

核心安装包只包含桌面壳和通用运行能力。终端、文件、网络隧道、系统状态和 Docker 都是独立插件，分别安装、版本化和更新。

## 安装与配置

设置的插件页提供“已安装”和“官方插件”。官方目录读取仓库各插件发行配置，不在核心维护业务插件名单；缓存可刷新，网络错误保留原因。选择官方插件后下载对应系统与原生架构的包，也可添加本地插件目录。

本地目录必须有有效清单、程序入口、版本、核心 API 主版本和平台声明。界面可以查看来源和运行状态，配置启用/关闭，移除登记，或进入[软件更新](updates.md)。本地插件缺少更新来源时可以显式配置。

| 操作 | 生效时机 |
| --- | --- |
| 安装并启用 | 保存配置，重启后加载 |
| 关闭已加载插件 | 保存关闭意图，本次运行保持至重启 |
| 升级已启用或本次加载过的插件 | 准备新程序，重启时切换 |
| 更新完全关闭且未加载的插件 | 更新登记并保持关闭，不要求额外重启 |
| 移除插件 | 按运行状态先关闭并重启，再移除登记；不擅自删除用户的外部程序目录或插件数据 |

新程序初始化失败时使用保存的旧程序回退，数据继续保留。升级不把未启动的新清单提前应用到正在运行的插件。

## 运行与故障

核心按保存配置启动独立插件进程，以版本化 RPC 提供连接、视图、文件、网络、设置、日志及重要消息能力。分进程用于生命周期管理和故障恢复，插件是可信扩展，没有权限清单、逐项授权或沙箱承诺。

核心检查初始化结果、帧大小、参数、进程实例和资源状态。stdout 只用于协议，stderr 进入诊断；进程启动、停止和异常退出均记录来源。失败通过运行状态和重要消息显示，用户可以排查后重启；不以无限重启掩盖错误。

插件之间不直接调用。跨插件共享状态经核心完成，业务含义由插件实现。核心中的测试夹具不出现在官方目录，也不随安装包发行。
