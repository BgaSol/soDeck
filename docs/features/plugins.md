# 插件管理

核心安装包只包含桌面壳和通用运行能力。终端、文件、网络隧道、系统状态和 Docker 都是独立插件，分别安装、版本化和更新。

更新来源以当前宿主草稿编辑，切页或关闭设置保留；成功保存推进基线，保存中禁用编辑。保存比较实际基线，其他窗口已修改时拒绝覆盖并保留输入，可选择“放弃并读取当前来源”。来源草稿也参与[关闭生命周期](lifecycle.md)。

## 安装与配置

管理台的插件页提供“已安装”和“官方插件”。官方目录读取仓库各插件发行配置，不在核心维护业务插件名单；缓存可刷新，网络错误保留原因。选择官方插件后下载对应系统与原生架构的包，也可添加本地插件目录。

应用每次启动时，插件登记配置可正常读取且登记数为 0，主窗口默认进入“插件管理 → 官方插件”，自动按目录顺序安装本轮全部适用官方插件。安装保存为启用状态，完成后点击“重启并开始使用”，重启加载后默认进入服务器连接页。核心安装包仍不含业务插件，下载沿用已保存的网络设置；每日自动检查开关不控制这次默认安装。

启动条件按登记数判断：关闭、运行失败、目录丢失或旧 API 的登记均算已安装，不触发自动补装；配置损坏或不可读保留错误和原文件，不把回退空列表当作无插件。运行中移除最后一个插件，下次启动才重新判断。启动事实只在当前进程保留，切页、前端重载或独立服务器窗口不重复启动；迟到的读取不会抢走用户已经改变的导航。

本轮目录取得后固定名单，不因第一个插件安装成功而停止，也不追装刷新后新出现的插件。逐项显示实际下载、校验和安装结果；无正式发行、不兼容和下载/登记失败明确显示原因，继续处理其他项，已成功项不回滚。目录失败可“重新获取并安装”，列表中的失败项可逐项重试；普通“刷新列表”只刷新目录。没有可用缓存时离线无法安装；成功取得空目录明确显示暂无可安装插件。

目录获取至整轮结束期间，暂停其他安装/更新、插件登记修改及重启，页面浏览和网络设置仍可使用。切页或重载后继续展示本轮结果，任务结束后释放占用；安装完成不自动重启，有成功安装即可先重启使用。准备任务不持久化：部分成功后重启不自动补齐剩余插件，用户可在插件页继续安装；全部失败仍为 0，下次启动再尝试。后续新上架插件不自动补装。

插件可携带自己的图标，已安装列表、更新、侧栏、标签和组件设置使用当前插件包资源。插件关闭或启动失败时仍可显示图标；图片损坏时显示通用插件图标，业务继续可用。官方预览按同源配置读取并缓存，不覆盖本地包；声明和兼容见[插件图标](../plugin-api.md#插件图标)。

切换到其他页面再返回时，保留插件列表类型和已选详情；“返回插件管理”明确回到原列表。消息、状态和工作台错误中的“查看插件”直接打开来源插件详情，“打开插件管理”打开插件列表，均使用插件一级导航，不跳到设置页。

本地目录必须有有效清单、程序入口、版本、核心 API 版本和平台声明。界面可以查看来源和运行状态，配置启用/关闭，移除登记，或进入[软件更新](updates.md)。本地插件缺少更新来源时可以显式配置。

| 操作 | 生效时机 |
| --- | --- |
| 安装并启用 | 保存配置，重启后加载 |
| 关闭已加载插件 | 保存关闭意图，本次运行保持至重启 |
| 升级已启用或本次加载过的插件 | 准备新程序，重启时切换 |
| 更新完全关闭且未加载的插件 | 更新登记并保持关闭，不要求额外重启 |
| 移除插件 | 按运行状态先关闭并重启，再移除登记；不擅自删除用户的外部程序目录或插件数据 |

新程序初始化失败时仅回退到同一 API 基线内、实际启动成功的旧程序。无兼容包时明确保留失败，插件数据与更新入口继续保留。API 1 插件在新核心中不执行，可在管理页升级；升级前的登记、启用意图和用户资料保留。升级不把未启动的新清单提前应用到正在运行的插件。

## 运行与故障

核心按保存配置启动独立插件进程，以版本化 RPC 提供连接、视图、文件、网络、设置、日志及重要消息能力。分进程用于生命周期管理和故障恢复，插件是可信扩展，没有权限清单、逐项授权或沙箱承诺。

核心检查初始化结果、帧大小、参数、进程实例和资源状态。stdout 只用于协议，stderr 进入诊断；进程启动、停止和异常退出均记录来源。失败通过运行状态和重要消息显示，用户可以排查后重启；不以无限重启掩盖错误。

插件之间不直接调用。跨插件共享状态经核心完成，业务含义由插件实现。核心中的测试夹具不出现在官方目录，也不随安装包发行。

## 操作反馈

安装、运行及待重启状态即时显示，列表按插件身份更新；状态文字变化不反复淡化。启用和关闭仍在重启后生效，插件详情与返回采用对应方向。节奏和减少动态效果规则见[界面规范](../../DESIGN.md#动效)。
