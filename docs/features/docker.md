# Docker

Docker 是独立插件，默认固定在右侧工具栏、按需打开。通过核心短命令和非交互命令流复用当前连接；Docker 命令和业务规则全部留在插件，不直接依赖 SSH 实现或其他插件。

## 当前功能

- 读取当前服务器的 Engine、Docker Root、容器、镜像、网络和卷。Compose 项目是真正可折叠的组，无项目标签的容器归入“独立容器”，可关闭分组平铺浏览。
- 资源树单层展开容器、镜像、网络与卷；容器通过概览、端口、挂载和网络四个页签就地查看信息，镜像、网络和卷保留摘要及引用。同一时间只展开一个实际对象。主区域仅用于日志和终端。环境变量整表、全部标签及通用 inspect 字段浏览器不再提供。
- 在中央日志工作区连续阅读，跟随最新、固定当前位置、按时间补读、搜索/筛选、查看上下文和详情、复制原文及导出当前结果；右侧缩略支持定位和拖动。
- 对象菜单提供容器启动、停止、重启、暂停、恢复和删除。启动、恢复直接执行，其余在侧栏确认；只允许删除已停止容器，不使用 force 或删除挂载卷参数。行内按钮与对象菜单使用相同可用动作。
- 单击名称选择并展开对象，箭头或 Enter 展开／收起；引用定位并展开真实资源。右键、选中行“更多”和 Shift+F10 打开相同对象菜单，日志／终端和维护入口位于对象下面。已有手动停靠位置继续恢复，首次默认位于右侧。
- 运行中的容器可从资源树打开终端。Linux Engine 默认 /bin/sh，Windows Engine 默认 cmd.exe，未知系统要求明确填写程序；侧栏“更多 → 终端选项”可修改容器内的可执行程序。通过核心 terminal.open.v1 命令请求终端插件。
- 按需读取 CPU、内存、网络、块 IO 和进程数；累计字节不当作速率。已读取分类按设置刷新，对象信息和指标按需读取；只刷新当前展开对象的信息。
- 拉取公开镜像，删除无引用镜像、自定义网络和未使用卷；侧栏任务查看执行结果与拉取原始输出。

Compose 分组依赖项目标签，不猜测名称，也不执行部署。创建/编辑容器、Compose up/down、build/push、Registry 凭据、批量操作、prune 和 Kubernetes 不在当前范围。

日志通过核心 session.process 与正文订阅、通用本地导出实现，使用当前统一插件 API；启用中的插件升级在重启后生效。验证与未完成范围见[日志后续验收](../plans/docker-log-viewer.md)，对应插件记录见[CHANGELOG](../../plugins/docker/CHANGELOG.md)。

资源树从 Docker 0.5.0 提供，来源与验收范围见插件 [CHANGELOG](../../plugins/docker/CHANGELOG.md)。搜索常驻，状态、健康和 Compose 分组收在“筛选”，socket 编辑位于底部“连接设置”。操作结果带对象身份，离开当前页后仍可从任务查看。断线或数据待刷新时禁用维护，保留快照；不适用操作按容器状态隐藏，未运行容器的终端入口明确不可用。

Docker 0.5.1 的侧栏名称由宿主面板显示一次；插件顶部显示连接状态、刷新和“更多”，Engine 版本与架构作为次要信息。全部折叠、自动刷新开关、连接信息和拉取入口集中在“更多”，Esc 返回触发入口。加载状态显示在分类或对象行右侧，不生成名为“正在读取”的资源行；首次加载显示“加载中”，后台更新保留原资源与数量并显示“更新中”，已读进度只在有实际数据时出现。空分类、无匹配结果和失败可重试各自显示明确提示，加载不阻止浏览已经读取的资源；发行与验收范围见[0.5.1 记录](../../plugins/docker/CHANGELOG.md#051)。

后台刷新保留展开、选择、实际行锚点、菜单、键盘焦点及 Shell 输入选区。Esc 关闭菜单或取消未提交确认，并返回可见触发入口。方向键、Home/End 支持整棵树分页导航。搜索保留匹配祖先，清空恢复搜索前位置；容器状态/健康过滤只影响容器分类。

## Compose 工作目录

Compose 分组的右键、更多及键盘菜单提供“跟随”，只发布一次该项目的工作目录，供已开启目录跟随的组件自行接收。不会打开文件面板、启动或检查其他插件；“已发布目录位置”不表示文件已完成导航。重复点击同一路径是一次新的发布，选择和刷新项目不发布。

目录取自全部项目成员的 `com.docker.compose.project.working_dir` 标签，聚合不受搜索、筛选或分页影响。需要完整、当前的容器索引及一致的合法绝对目录；缺失、冲突或观察已变时禁用／拒绝并说明原因，不取第一个成员或猜测配置文件父目录。项目与 Engine／连接身份固定，旧菜单不能切换目标。

菜单展示完整目标，含义是“在当前服务器定位；目录来自 Compose 标签”。该标签可能来自另一台 Compose 客户端；文件服务只能核对当前服务器是否能访问此路径，不能证明它与另一机器的原项目相同。容器、Desktop VM、UNC 和相对路径不自动映射。不新增部署、Compose up/down 或目录映射设置。接口见[通用目录位置](../plugin-api.md#通用目录位置)，文件端操作见[文件](files.md#目录与联动)。

## Docker Root 与资源关系

Docker Root 位于 Engine 下、四类资源之前，不被搜索和容器筛选隐藏。读取实际 `DockerRootDir`，支持自定义及 rootless 绝对路径；未读取、字段缺失和访问失败明确显示未读取，不以 `/var/lib/docker` 补值。断线保留已读路径并标为待刷新，切换 Engine 清除旧目录。Enter 打开树内连接信息查看完整路径，菜单可复制；只读，不编辑 data-root 或浏览其内部文件。

分类与对象关系分批按需读取，独立显示加载、失败和不完整。容器的镜像、端口、网络和挂载通过下述页签组织；命名卷引用与 bind 的主机/容器路径分别展示。镜像以完整 ID 去重计数，仓库/标签为别名，同一对象可以在多个仓库出现；无标签对象单列。网络显示连接容器，镜像和卷显示全部引用容器，包括停止容器。引用始终定位所属分类的实际对象，不在原对象下面递归展开。

镜像展示大小、平台、别名及引用容器；网络展示驱动、范围、子网／网关和连接容器；卷展示驱动、范围、远端位置和引用容器。集合就地分页，显示不完整与后台引用完整性分开判断。

连接设置、拉取镜像、任务与操作确认都挂在树内。分类／Compose／仓库分组仍可同时展开，整个树只有一处活跃行内区域。基础资源行保持固定高度，行内区域按实际内容测量，滚动、键盘和后台刷新共用位置换算；保持输入和滚动锚点，不维护第二个详情面板。

## 容器页签详情

Docker 0.11.0 的容器展开区使用固定操作栏、四个页签及共享结果/确认区域，沿用三主题的紧凑工作台风格。日志、终端与维护操作留在上方；切页保留按钮、确认表单和固定目标，结果在任意页签可见。发行与验收范围见插件 [CHANGELOG](../../plugins/docker/CHANGELOG.md)。

Docker 0.11.1 的页签栏复用公共工具底色和当前项底色，多巴胺为绿底、黄色当前项；数量采用次级字号。操作栏和内容区统一对齐，极窄侧栏的页签分成两行，保持完整名称和数量可读。

| 页签 | 内容 |
| --- | --- |
| 概览 | 镜像引用、状态及退出码、健康、启动/退出时间和重启策略；“更多信息”提供完整 ID、复制和手动资源快照，不新增指标轮询 |
| 端口 | 每条实际发布绑定及原有创建/启动、候选选择、复制入口和查看隧道；IPv4/IPv6 分别显示 |
| 挂载 | 主机源与容器目标分行，标出只读，命名卷可定位；远端 Windows 路径保留原值 |
| 网络 | 网络引用及实际 IPv4/IPv6 地址，缺失地址不补值 |

普通打开新容器默认概览，同一容器重复打开保留页签；对象菜单“端口隧道…”直达端口。左右方向键、Home/End 切换页签，Esc 返回所属资源行；确认表单中的 Esc 仍取消确认。数量为 0 的页签仍可进入；未读取显示“—”，截断时说明数量仅代表已保留条目。

对象观察仍由既有后台加载；页签只投影当前需要的集合，不因切页重新执行 inspect、指标或维护命令。每个集合仅缓存当前一页，观察版本变化后失效；前进使用实际返回游标，返回使用实际前页起点，适用于字节预算导致不足一页的结果。数据减少后收敛到有效位置，不把旧对象/范围的迟到响应写入当前页面。

页签与分页位置随同一逻辑 View 的导航保存，支持冻结、重挂载和移窗，不是跨应用重启的全局偏好。换实际对象或连接范围重新初始化；隐藏、详情滚出视口或冻结时停止新读取及端口展示订阅，只读候选不发业务请求或订阅。离开端口页不会撤销已经提交的隧道，待确认结果仍可从共享结果区“查询原请求”，沿用原票据。

## 资源维护与拉取

删除入口要求当前分类索引和引用完整。确认固定 Context、socket、Engine、实际 ID 与观察版本；执行前重新读取对象及全部引用，超限、部分失败或身份改变拒绝删除。系统网络不能删除，自定义网络须没有连接端点；镜像/卷须没有任何容器引用。

镜像按完整 ID 执行 `image rm --no-prune`，确认展示受影响别名。Docker 可能因多标签或保护拒绝删除，插件不会强制删除或逐标签解除引用。卷只用名称删除，并比较 Name、Driver、Scope、CreatedAt、Options 和 Labels；Docker 卷没有不可变唯一 ID，也没有原子 compare-delete，无法完全消除外部同名重建的竞态。删除卷永久删除其中数据。

拉取入口先输入，再显示规范化完整引用并确认；未填写标签时明确补 `:latest`。当前仅管理无需登录的公开源，不保存 Registry 凭据。使用独立核心命令流，隐藏侧栏继续运行，关闭 View 释放资源；每 View 一个、插件同时两个任务，输出捕获上限 4 MiB，等待期限 15 分钟。只有远端退出已确认且退出码 0 才成功；取消、超时或断线显示未确认，不生成新意图重发，需刷新核对镜像。

任务历史最多 64 条/View；保留最多 8 个拉取捕获，当前拉取可查看原始 stdout/stderr，淘汰捕获后不能再次读取。任务结果明确成功、失败、未确认，成功后刷新已读分类。

## 容器日志

Docker 0.10.0 的日志会话由插件进程持有，页面只读取有界投影。需要核心 2.3.0 的只读页面查询与视图独立入口；缺少能力时明确提示升级，不运行旧 Worker 数据通路。启用中的核心与插件更新按各自机制重启生效。

打开默认读取当前可读历史的最后 1000 条，不设置最近 15 分钟下界。运行数月或几天没有输出的容器也显示真正最后的输出与时间；运行中随后跟随，停止容器显示退出前尾部。首段阅读数据最多约 2 MiB（含解码与记录开销），正文实际条数以保留范围为准。Docker 的 tail/since 减少返回量，不保证 daemon 不扫描旧历史。

滚动向上、拖选、查找和查看详情自动固定阅读；后台继续有界接收，新增数量独立累计，不因近期内容淘汰而减少。“回到最新”恢复跟随；查看有限历史后会重新建立缺少的最新采集任务。保留当前查找条件，条件入口可以直接清除。“返回刚才的位置”只保留一个历史阅读窗口。隐藏页面停止绘制，插件继续接收；重挂载、移窗与候选页读取同一会话，不重新执行 Docker 命令。关闭 View 取消任务并释放所属资源。

顶部“查看更早日志”按当前实际最早记录的源时间补读，跨越没有输出的安静期，不按固定 15 分钟倒退。先完整核对同一纳秒边界，保留真实重复行和原有记录身份，再读取更早尾部；边界改变、单个时间戳记录过密、容量或超时无法保证连续时明确提示缩小时段，不静默跨过。更晚内容可按相邻时段补读。已解析历史及时释放核心进程资源，不限制为保留 12 个历史命令。

时间菜单提供最新、过去 15 分钟/1 小时/24 小时、本次启动以来、定位时间和自定义时段。相对范围固定请求时的新鲜 Engine 时间；本次启动依赖 Engine 的可靠启动/退出时间，缺失时提示不可用。定位时间读取前后各 5 分钟并落位，可继续扩展。所选时段与当前已加载范围分别展示，时段浏览首先仍是有限预览。源时间以纳秒保存，日历与时区由 chrono 解析；拒绝闰秒、超过 9 位的小数和 UTC 纪元之前的结果，输入年份为 1970–9999，不用 i64 纳秒截短可表示年份。所有时间注明本机时区，详情保留源时间，缺少源时间使用接收时间但不据此证明历史覆盖。

查找默认在已加载窗口内按不区分大小写的字面匹配，高亮并保留原上下文；计数按匹配记录，上一条/下一条及 F3/Shift+F3 导航。“只看匹配”收窄结果，可展开前后各 10 条。级别只读取明确前缀或 JSON level/severity；stdout/stderr 是来源，stderr 不等于 ERROR，TTY 合并时说明来源限制。

有关键词时可“搜索历史”，最新模式默认切换为过去 24 小时，已有有限时段则搜索整个所选时段。搜索从最近的区段向更早区段推进，使用同一解析/查找规则，只保留命中与前后各 10 条上下文；显示已检查与正在读取的区段，不猜测总量百分比。一次上限为 120 秒、256 MiB 原文扫描、500 条命中或阅读容量，先到为准。取消、断线和达到上限保留部分命中并明确未完成；仅有可靠完整区段边界时提供继续搜索，改变关键词或筛选必须重新搜索。零命中只代表明确显示的已检查范围。

布局 ID 按序列化字节预算分页，页面仍以同一 revision 重组完整投影，不改变记录身份或阅读窗口。正文使用虚拟渲染，保留记录和行内像素锚点，选区活动时不替换正文 DOM。默认换行，可显示来源；长内容正文预览，详情分块查看原文与可解析 JSON。单条原文上限 1 MiB，超出标为未完整保留，复制明确为已保留部分。ANSI 控制序列不执行；stdout/stderr 分别用有界状态机清理 CSI、OSC、DCS 和字符集切换，跨块、跨记录保留状态。Tab 保留，载荷不混入搜索或级别识别；原文截断后仍处理丢弃部分的控制状态，输出缺口则重置状态。显示去除控制效果的安全文本；原字节继续保留用于复制和导出，不猜测任意异常堆栈分组。移除右侧缩略及其设置，以补读、时间定位和匹配导航定位。

原生选区可复制，详情提供原文复制。“更多”导出当前已保留的筛选结果，或勾选导出当前记录及前后各 10 条。导出在插件会话冻结不可变记录，后续输出不混入，附实际身份、所选时段、覆盖与条件；含未完整保留长记录的结果拒绝作为原文证据导出。核心保存框及事务继续保护旧目标，显示真实进度与取消，成功完成才报告；移动页面前完成或取消导出。

每页近期最多 1 万条/约 16 MiB，固定阅读最多 5 万条/约 32 MiB，插件日志数据合计约 128 MiB，包括仍被窗口/搜索/导出持有的原文与索引预算。核心捕获额度与日志扫描总量分开计数。达到预算保留当前阅读并说明恢复动作，不静默淘汰正在看的记录。页面同一时刻一个历史任务，全插件最多两个；不提供用户缓存或批次配置。

断线保留正文与原来源，有限尝试恢复读取；恢复前核对服务器、endpoint、Engine 和完整容器 ID，不以名称自动换到重建对象。容器重启不跳走固定阅读；已知缺口、可能重复、未知退出与观察失败分别说明。Docker CLI 没有跨请求稳定日志 ID，不承诺轮转、同时间戳大量记录和源时钟变化下恰好一次或无缝衔接。只读取 Docker 可提供的 stdout/stderr，不读取应用日志文件，不配置轮转、清理磁盘或永久归档。

## Docker 连接与操作语义

远端程序通过统一 API 的 session.program.prepare 编码。远端执行环境与 Engine 系统分别识别：Windows OpenSSH 用原生 Docker CLI 访问当前账号的本机命名管道，Desktop 的 WSL2 Linux Engine 使用 Linux 容器规则；POSIX 会话访问 Unix socket。显示实际 Client/Server 系统、版本、架构和 Docker Root，保留 Windows 盘符路径，不换算 WSL 虚拟磁盘。Windows Engine 已实现对应程序默认值和系统网络保护，暂停/恢复不提供；真实兼容验收范围见 [CHANGELOG](../../plugins/docker/CHANGELOG.md)与[待验收范围](../plans/docker-windows.md)。

新服务器默认“自动识别”：DOCKER_CONTEXT 优先于 DOCKER_HOST，未覆盖时读取当前 Context 的 Docker endpoint。一次识别共享 30 秒期限，只读取发现所需环境变量。仅接受远端绝对 Unix socket 或远端本机 npipe（如 `npipe:////./pipe/dockerDesktopLinuxEngine`）；不自动回退其他端点、开放 TCP、进入 WSL 或提权。Docker Desktop 必须已启动，当前 SSH 账号必须能访问 CLI 和 Engine。

“手动指定”只使用填写的端点。可选远端 CLI 绝对路径（允许空格/中文，不带参数），留空按远端 PATH 查找。旧 endpoints.json 的保存端点迁移为手动配置，升级不切换目标；新配置使用 schemaVersion 2，保留原文件备份，损坏或保存失败不覆盖原配置。

“测试连接”只验证表单；“保存并连接”重新验证后提交，失败保留旧配置和目标。编辑后旧测试结果失效，后台刷新保留草稿。自动识别成功后固定实际端点和 Engine；外部 Context 变化不会重定向普通刷新。主动“重新识别”、切换模式、改端点或 CLI 前需关闭该服务器日志页，并等待在途请求、拉取与终端创建结束。Engine 身份或系统改变时旧快照标为待核对，停止维护，要求重新识别；旧页面不自动接管新目标。

命令清除 Docker host/context/TLS/API 环境覆盖并显式指定 socket，不自动安装 Docker、不修改用户组、不添加 sudo。每次采集核对 Context、Engine ID 和完整容器 ID；Engine 更换后旧资源快照要求重新选择。

变更请求按操作 ID、序号和完整输入去重。发送前失败明确拒绝，发送后中断显示结果未确认；刷新不重发操作，取消本地等待不承诺撤销远端变更。停止/重启的宽限为 10 秒，命令沿用核心短任务期限和输出预算。

侧栏提交明确携带 Context、socket、Engine ID、实际资源身份与范围代次，后台先检查已读身份，再在执行前重读远端对象。侧栏确认固定其创建时的目标；选择其他对象、改筛选、切换 Context 或关闭来源会取消尚未提交的确认。刷新导致身份改变时，旧确认会被后台拒绝，不作用于新对象。删除成功使空闲的同身份日志页面标为已删除。

## 容器端口隧道

Docker 0.7.0 提供端口快捷隧道，需启用网络隧道 0.5.0 及核心 commands.v1/sharedState.v1/ui.background.v1。容器对象菜单「端口隧道…」打开树内端口页签，每条实际发布绑定分别显示容器端口、服务器发布地址和远端连接目标；多个地址、HostPort 和 IPv4／IPv6 不自动合并。

「创建隧道」一次保存并启动普通 TCP 规则，默认本机 127.0.0.1、自动分配端口；不继承手动新建的 SOCKS5／固定端口默认值。实际监听确认后显示入口，支持复制和「查看隧道」。不自动打开浏览器，也不根据端口猜测 HTTP／HTTPS。网络隧道侧栏不因创建被打开，关闭 Docker 来源后已交接的隧道继续运行。

目标使用实际 NetworkSettings.Ports 的 HostPort；0.0.0.0／空 HostIp 转为远端 127.0.0.1，:: 转为 ::1，明确网卡 IP 保留。不是直接连接容器端口、容器 IP 或 Engine API。提交前重新核对完整 Context、endpoint、Engine ID、完整容器 ID、运行状态及原绑定；变化时拒绝，不追随同名容器或新端口。未发布、暂停／未运行、非 TCP、非法／缺少作用域地址及没有发布绑定的 host 网络不给快捷创建。

同服务器同明确目标的回环规则优先复用：唯一运行项显示入口，唯一停止项启动原规则，多条同优先级候选明确选择。非回环监听不自动启动或复用；配置目标／绑定与实际运行不一致、其他连接占用、停止／清理中或状态未知时引导管理，不补建替代监听。仅改名不改变运行目标。

命令完成只表示保存及启动已接纳；监听状态和一次 TCP 检查分别显示。保存失败不启动，已保存但启动失败保留规则；目标不可达不关闭正常监听。超时保留原请求，重挂载查询原票据；未知结果不换编号重发。持续状态由网络插件通过核心共享状态发布，失效或过期时停用入口复制及新建／启动。

规则是固定服务器端点，容器停止、删除、重建或映射变化不会自动修改／删除它，该端点以后也可能由其他服务占用。编辑、停止、删除、固定本机端口继续由[网络隧道](network-proxy.md)管理；断线释放监听，重连后手动启动。创建已交给处理者后，关闭 Docker 不承诺撤销保存或启动。

端口目录最多保留 100 条完整绑定、64 KiB，每页最多 5 条，并受集合字节预算约束；不完整条目不操作，超限标注。缺少提供插件／核心能力时解释原因，Docker 其他功能继续使用。发行与真实验证范围见插件 [CHANGELOG](../../plugins/docker/CHANGELOG.md)。

端口隧道摘要分别显示本机入口监听和目标检查结果、检查时间；失败原因来自网络插件共享的结构化说明。复制入口不表示目标可达，原始诊断由“查看隧道”进入网络详情。

## 容器终端

容器终端已在 Docker 0.2.0 发行，侧栏入口在 0.3.0 新增，来源与范围见 [CHANGELOG](../../plugins/docker/CHANGELOG.md)。

需启用支持 terminal.open.v1 的终端插件，Docker 插件初始化要求核心 commands.v1。请求固定当前 Context、socket、Engine ID、完整容器 ID 和 shell；后台在提交前重读 Engine/容器状态，终端启动命令在 exec 前再次核对 Engine。命令清除 Docker 环境覆盖并显式指定 socket，不自动换 socket、容器、shell 或提权。容器已经停止、暂停、更换 Engine 或 shell 不存在时明确失败；提交后的容器状态仍可能变化，实际结果以终端输出为准。

创建期间显示等待，重复点击不提交新意图；UI 重挂载从 Docker 后台继续查询原票据。回执完成只表示终端页面已登记，不保证容器 shell 已成功启动。通信超时保留原编号继续查询；已发送但结果未知时不自动补建。

同一终端请求编号不能更换容器、连接身份或 shell；完成后的同编号查询也不会补建页面。待确认票据查询优先于侧栏自动刷新，避免列表刷新推迟回执。请求失败或完成后可以用新的明确意图再次打开终端。

终端使用指定命令模式并关闭主机目录集成，容器 OSC 目录不会导航主机文件页。已创建终端独立于 Docker 来源视图，关闭来源不结束终端；关闭终端才释放对应 PTY。命令及重开语义见[终端](terminal.md)，不是 Docker 对终端进程的直接调用。

| 内容 | 当前上限 |
| --- | --- |
| 逻辑视图与排队请求 | 64 个视图、16 个请求，worker 顺序执行 |
| 四类索引 | 每类 1000 个、2 MiB，超限标明不完整 |
| 对象观察 | 32 个对象、每项 256 KiB、合计 2 MiB；闲置观察按读取顺序清理，引用不完整时禁止删除 |
| 单容器 inspect | 校验输出 1 MiB；展示观察使用限定字段，集合前 100 项、单值 4096 字节；截断明确标注 |
| 日志原始捕获 | 近期32MiB滚动；尾部4MiB/次，完整范围48MiB；核心View固定捕获与pin合计64MiB |
| 日志Worker窗口 | 近期最多50000行/估算16MiB，历史或固定窗口最多200000行/估算64MiB；正文仅渲染可见记录 |
| 全部视图数据 | 16 MiB |
| UI 分页 | 树页／集合页 16 KiB、完整响应 24 KiB，仅渲染资源行窗口及一个行内区域；日志正文通道每块最多 16 KiB |
| 树导航 | schema 3，8 KiB、64 个分组展开键；兼容旧导航，旧详情 View 不再声明 |

断线保留已读内容并标为待刷新。UI v2候选只读，不轮询或提交业务操作；日志候选可恢复原捕获正文。交接等待在途交互，取消后恢复输入。关闭视图或退出插件清理资源，Context改变取消旧远端命令但保留日志捕获，旧结果不能覆盖新状态。

普通日志只记录动作、对象与结果，重要失败消息默认不弹出；不记录环境变量、inspect 或日志正文。参数、状态检查和远端操作系统权限继续生效，不引入插件授权步骤。

## 操作反馈

资源树仅对主动展开、收起解释可见行变化，滚动窗口与后台刷新保持安静。资源菜单共用锚点定位、边界翻转及关闭行为；确认面板立即可操作。日志详情的按钮、Esc 和回到最新共用收起入口，换记录只反馈详情内容；实际宽度、阅读锚点和日志正文仍由原布局管理。操作票据及候选页面输入权不受动效改变。节奏和减少动态效果规则见[界面规范](../../DESIGN.md#动效)。
