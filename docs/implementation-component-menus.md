## 复现与原因

修复前读取实际 DOM 几何，面板菜单的计算定位为 `relative`，在 1100×720 窗口中落到 y=546，底边正好到窗口底部，并产生双向滚动范围。服务器页签菜单也计算为 `relative`，落到 y=642。仅验证菜单项目可点击会漏掉此问题，浏览器自动滚动还能掩盖错位。

同一 CSS 层内，后加载的共享 `.sd-menu` 装饰规则设置了 `position: relative`，覆盖工作区 `.workspace-menu` 的 `fixed`。组件菜单自身的 `overflow: auto` 又把共享描边的负向外扩伪元素纳入滚动范围，让短菜单出现滚动条。

工作区样式用明确的组合选择器保留固定定位。组件菜单外框与内部列表分离，仅内部列表滚动；固定搜索框，长标题允许收缩并省略。定位以实际菜单尺寸计算上下展开和左右边界，搜索后重新计算。
