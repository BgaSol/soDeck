## 复现与回归

主壳导航回归在原正式前端上失败：切换设置页后焦点落到 BODY。修复后以真实正式前端、核心夹具和计算样式核对，而非仅测试设置值保存。

| 缺陷 | 复现与原因 | 回归落点 |
| --- | --- | --- |
| R01 | 设置导航/主题重绘替换无稳定 ID 的控件，焦点丢失；弹窗 Tab 集合漏掉 summary、链接和 textarea，正常顺序被提前截断 | 正式前端上的导航、主题、展开/收起、首尾 Tab、Esc 返回和 retained 字段焦点 |
| R02 | 网络快照更新重建列表/详情 DOM，导致按压、焦点、展开和检查输入被刷新打断 | 跨两个实际快照周期核对节点身份、输入、焦点和展开；按住停止只触发一次，移出按钮不误启动 |
| R03 | 浅色选中文字使用强调色，在既有选中背景上对比不足 | 三主题实际计算颜色与对比度，选中文字使用正文色后达到 4.5:1 |
| R04 | 文件名称的第二条固定 12px 规则覆盖组件字号设置 | 六组合法字号/密度检查真实目录和文件节点的计算字号、行高及裁切 |

R05 的新增 720×480 正式前端断言暴露连接按钮低于视口；原因是窄窗详情仍占用目录筛选栏高度。隐藏该栏后，浅色、深色、多巴胺三主题的连接按钮都在视口内，返回列表仍可使用筛选。

网络测试跨实际快照周期检查节点身份、焦点、展开、检查输入、复制反馈和 pointerdown/up；文件测试读取实际树的字号/几何，并区分远端字节与未保存草稿；终端测试以真实 SSH shell 的退出验证新 PTY 与旧输出。

文件夹具原先把 Windows 本地 `C:/…` 与 SSH 返回的 `/C:/…` 混用，已改为读取实际远端节点路径再筛选。Windows 测试运行时锁定同一 Rust 可执行文件，因此这些集成入口顺序执行；UI 专项可复用隔离 OpenSSH，不重复已经通过的协议压力测试。
