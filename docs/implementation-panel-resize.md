# 面板拖拽与终端尺寸同步实施记录

记录日期：2026-11-08。基于核心 0.12.2、提交 `8770130ae825879e85a335b1b6fdd0d4046f52af` 之后的本次改动。本文保留方案实施与初次本机验证证据；随后独立发行的核心 0.12.3、终端 0.2.3、五平台验收和包来源统一记录在[核心版本说明](releases/v0.12.3.md)及[终端 CHANGELOG](../plugins/terminal/CHANGELOG.md)。目标与原始原因见[方案](plan-panel-resize.md)。

## 1. 修改与职责

### 布局状态和拖拽

`Workspaces` 统一维护手势预览、已发送及等待合并的宽度修改。刷新继续更新其他工作区状态，预览和待确认字段不被旧快照覆盖。核心确认只结束对应操作；后续拖拽和键盘连按取最新展示宽度，不使用按下时的整份旧布局。

手势登记工作区、侧、指针、实际起始宽度和另一侧实际宽度。正常松手提交最后坐标；Esc、失焦、pointercancel、意外捕获丢失、侧栏失效、工作区切换、关闭和销毁撤销未提交预览。捕获、拖动光标和 RAF 通过同一出口结束，松手后的捕获丢失不重复提交。

拖动时暂时把焦点交给分隔线，使原来聚焦终端 iframe 时 Esc 也由宿主处理；结束后若用户没有转向其他目标，恢复原焦点。失焦或原节点消失时不强制恢复。

`panel-layout.ts` 集中计算左右宽度与空间显隐。两侧最小宽度能放下时先约束宽度；拖动保持另一侧当前实际宽度，达到边界停止增宽。只有空间不足以容纳最小宽度才暂时隐藏侧栏，不改写偏好；从压缩状态开始拖动以实际宽度为基线。可用空间向下取整，避免高 DPI 的小数宽度被核心整数参数拒绝。

`Components` 每个工作台最多保留一个待执行布局帧，统一写 Grid、测量槽位并更新 iframe 位置；相同几何不重复写样式或发送可见性消息。删除刷新、外层渲染和直接拖拽分别写宽度的路径，以及被覆盖的旧 CSS 宽度公式。现有 iframe、view、终端对象和 PTY 继续复用。

### 核心提交

宿主内部 `workspace_layout` 改为 `{ id, side, width }`，返回已确认布局与 revision。核心 `workspace_resize()` 先检查方向、宽度、归属、移动和关闭冻结，按现有顺序持有工作区与组件状态锁，保存后完成内存更新。

只更改请求侧，分别保留工作区及全局默认偏好的另一侧最新值。拒绝或落盘失败不改变两份状态；移窗不能在保存与内存更新之间改变归属。测试夹具调用正式服务，验证真实偏好文件，不再绕过保存。

响应失败后读取快照核对；实际已接受的值按确认处理，未接受则恢复已确认状态并提示。核对失败保留尚未确认的展示值，下次快照或操作继续归并。移窗等待布局保存归并；宽度偏好错误不新增关闭内容确认。

### 终端尺寸同步

本地 fit 合并到下一帧，独立于尺寸请求等待。远程 resize 使用原输入顺序链，最多一个在途请求和一个可替换的等待位置，发送时读取最新行列；持续调整不会在输入前无限追加旧尺寸任务。

进一步原生验收发现容器盒模型与 FitAddon 的尺寸读取约定不一致：`border-box` 把内边距算进计算尺寸。真实 xterm 回归中，可用内容区 568×428px，却生成了 583×464px 的屏幕，存在横向和底部裁切。将测量容器设为 `content-box`，让 FitAddon 直接读取正确内容尺寸；新增横、纵屏幕不超过实际内容区的验收，不手工扣除行列或额外改库。

最终截图核对又确认了底部黑条的来源：宿主 `.xterm { height: 100% }` 强制撑满可用高度，而 xterm 只能绘制完整行，未被实际屏幕覆盖的旧 viewport 背景露出。新增真实 xterm 回归先稳定失败（屏幕 406px、外框 428px），随后删除这条高度覆盖，让外层提供可用尺寸、xterm 外框随完整行高度结束。原生验收同时记录节点几何并检查外框与屏幕高度一致，避免通过隐藏溢出或修改背景遮住尺寸问题。最新独立终端包的实际 WebView2 复测通过，外框和屏幕均为 567px，两次原生流程截图均无该黑条。

隐藏、恢复、零尺寸、接续、断线、退出和卸载通过尺寸代次与统一清理处理；旧结果不更新新状态。忙碌进行有界重试，永久失败提示而不阻止本地绘制。外观应用等待本地几何生效；显示快照固定序列化时的行列元数据，避免异步发送期间 fit 改变元数据。

插件 UI v1、现有配置文件格式和生产依赖保持兼容。核心宿主命令与前端同时更新；终端插件独立打包。

## 2. 回归证据

修改前先加入并运行两个失败回归：工作台真实按压期间刷新会覆盖宽度；真实 xterm 在尺寸请求阻塞时无法继续适配容器。修改后通过，并补充以下覆盖：

- 左右拖拽、松手保存、刷新中预览保留、一次在途保存后再次调整、键盘连按合并与保存失败恢复。
- 1000px 工作台中两侧各 280px，左侧拖到上限 316px，两侧仍显示；缩小后取消手势，放大恢复偏好。
- Esc、失焦、取消、意外捕获丢失、工作区切换和宿主销毁，无额外保存或残留拖动状态。
- iframe 节点保留、关闭取消保留内容、移窗布局保留，以及三主题、窄窗口和显示比例检查。
- 真实 xterm 下阻塞 resize、连续 20 次容器变化，本地行列继续改变，屏幕宽高适配实际内容区，外框随完整行结束；放行后仅发送在途及最新尺寸，输入文字顺序正确。
- 隐藏期间不继续 fit 或发送旧尺寸，恢复重新测量；卸载时在途请求的迟到结果不产生新的尺寸工作。
- 核心偏好落盘、另一侧值保留、保存失败不变更内存、移动和关闭冻结拒绝，以及小数可用空间仍产生合法整数宽度。

## 4. 尚未完成与边界

- 后续发布已完成本次源码的 GitHub Actions、五平台原生包及实际远程业务组合验收，来源见对应版本说明；本表保留初次本机验证范围。
- 其他四目标的实际分隔线拖动尚未专项验证；五平台包启动退出和远程业务不能替代手势与绘制验收。Windows x86_64 MSI 仅在初次本机阶段构建，正式包沿用 NSIS。
- 实际跨显示器、100%／150%／200% DPI 切换、原生窗口失焦及各平台的长时间拖动仍需设备验收；浏览器比例模拟和本机 WebView2 不能替代这些证据。
- 本次未对用户已安装程序、用户的远程服务器或远端大型交互程序做帧率测量。正常终端重排与远端程序自身重绘仍应在最终设备上区分，不能承诺所有渲染场景永远不闪烁。
