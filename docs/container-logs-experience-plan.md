# 容器日志体验与生命周期功能规划

日期：2026-10-20
状态：功能与交互规划 v2，已据此实施；实际交付与验证边界见 `container-logs-implementation.md`。
设计依据：apple-design 技能；适配现有 Windows 桌面应用与项目主题体系。

## 1. 用户意图

日志窗口应当是排查容器问题时可以持续依赖的观察窗口：打开后能看到最新输出，重启期间知道发生了什么，恢复运行后继续看到新日志；翻阅、查找和复制时保持阅读位置，并清楚知道后台是否仍在接收。

本轮优先解决状态与操作语义混杂的问题，保留独立日志窗口、本地存档、虚拟列表与原文导出能力。

## 2. 当前实现与结论

本次依据源码和已有测试定义分析，未运行桌面应用或真实 Docker 重启实验。

| 项目 | 当前行为 | 对体验的影响 |
| --- | --- | --- |
| 日志采集 | 首次先读取 Docker 当前可提供的全部历史，再进入实时跟随 | 历史较大时，新日志可见性受历史同步耗时影响 |
| 同一容器停止与启动 | 日志流正常结束后等待 5 秒，再 inspect 并继续读取；停止状态也持续检查 | 已有自动恢复基础，不必每次手动重新打开 |
| 网络中断 | 对 network、ssh、timeout 和部分 io 错误进行 1、2、4、8、16、30 秒退避重试 | 可以恢复，但状态主要靠一条文本表达 |
| Docker 命令错误 | 当前统一视作不可自动重试，采集结束并显示重试按钮 | 重启或 daemon 恢复期间若出现暂态 Docker 错误，也可能停止自动恢复 |
| 历史接续 | 从最后时间戳前 1 秒回读，已有按记录出现次数等条件去重的实现 | 可以避免普通重连重复追加；不能据此保证所有异常下日志完整 |
| 自动滚动 | 与采集独立；向上滚动、部分键盘操作、正文任意 pointerdown、打开查找均可关闭 | 单击正文也会意外停住，用户很难判断是否断流 |
| 查找 | 固定本地日志快照，需要手动更新结果 | 后台有新日志，搜索结果也可能不变 |
| 关闭查找 | 仅隐藏搜索栏，保留关键词和其他条件 | 隐藏的条件继续限制显示 |
| 跳到最新 | 同时清空关键词、输出流、时间范围和上下文，并开启滚动 | 导航与清除条件耦合，恢复跟随后丢失排查条件 |
| 容器重建 | 来源绑定连接身份、Docker endpoint、完整容器 ID | 新 ID 不会被旧窗口自动接管，同名容器也不例外 |
| 窗口关闭 | 停止该窗口的采集，本地数据保留 | 不是持续运行的后台日志服务 |
| 界面布局 | 标题、工具栏、两行搜索、正文、常驻序号范围、底部统计 | 排查工具同时展开，正文空间被压缩 |

结论：同一容器普通重启后，现有逻辑会尝试自动恢复采集；仅在自动滚动开启且没有筛选或上下文模式时，前端才会自动追加并滚到末尾。不能无条件承诺“重启后一定继续滚动”。

关键代码：

- `src-tauri/src/logs.rs`：`collect_logs`、`read_logs`、`retryable`、`logs_start`、`logs_stop`。
- `src-tauri/src/log_store.rs`：`Source::new`、`since` 与接续去重测试。
- `src-tauri/src/log_ingest.rs`：历史同步标记、接续游标、记录落盘与去重。
- `src/ContainerLogsApp.tsx`：采集事件、`pause`、`latest`、筛选快照及日志区域输入事件。
- `tests/features.spec.ts`：已有历史同步、重开去重、模拟网络重连、停止后启动的测试定义；仍需补真实重启与可视滚动验收。

## 3. Apple Design 的具体约束

本方案期望的体验是平静、可控、可靠。按 apple-design 的 Purpose、Agency、Familiarity、Simplicity、Craft、Flexibility 原则组织功能，以下为本项目的设计决策，尺寸与动效参数为待原型验证的起点，并非平台硬性标准。

| 原则 | 在日志窗口中的具体落点 | 验收方式 |
| --- | --- | --- |
| 目的与克制 | 日志正文占据主要空间，正常接收仅用一条状态；序号范围、存储目录、设置按需展开 | 默认打开时无需理解存档和技术参数即可观察输出 |
| 用户掌控 | 翻阅、文本选择、查找期间不抢动视图；重连不重置阅读意图 | 同样的操作在运行、等待、恢复时行为一致 |
| 即时反馈 | 按下按钮立即出现按压反馈，释放后执行；网络操作独立展示真实进度 | 界面响应不等待 SSH 或查询完成 |
| 空间一致性 | 菜单从触发按钮附近展开，搜索固定在工具栏下方，阅读控制固定在正文右下方 | 展开和收起使用同一路径，焦点可返回原入口 |
| 渐进呈现 | 常用功能可见；显示设置、范围复制、存档详情各自有明确入口 | 不将所有操作塞进一个无标签的“更多”菜单 |
| 熟悉感 | 保留现有 Windows 窗口控制、系统字体、原生滚动与常用键盘习惯 | 无仿 macOS 交通灯、额外滚动物理效果或接管惯性滚动 |
| 包容性 | 浅色、深色、高对比度、减少动态效果和字体放大均可使用 | 状态无需仅凭颜色辨认，键盘可完成核心流程 |

设计来源：`C:/Users/bgaso/.codex/skills/apple-design/SKILL.md`。本规划不引入新的视觉组件体系，优先复用 `src/theme.css`、`WindowTitlebar` 与现有 Lucide 图标。

## 4. 信息架构与布局

### 4.1 默认窗口

从上到下保持固定的信息层级：

1. 标题栏：容器名为主，服务器名与短 ID 为次；右侧显示一条采集状态，可展开连接详情。
2. 工具栏：查找、筛选、显示、导出。查找是最常用入口，其他按钮使用次级视觉权重。
3. 条件区：仅在存在条件时出现，显示关键词、输出流、时间范围等可移除标签。搜索输入展开在此区域，收起后标签仍在。
4. 正文：连续日志列表，保留原文、时间戳、弱化的序号与必要的错误标识；系统事件使用独立的轻量分隔行。
5. 底部阅读栏：左侧为保存概况和阅读状态，右侧为一个随阅读状态变化的主要动作。存储体积与目录从详情入口查看。

布局示意（示例数据，非实际运行状态）：

```text

生产服务器 · a18c2d4e6f90

[查找]  [筛选]                         [显示⌄] [导出⌄]
[关键词：timeout ×] [stderr ×]               清除条件

14:32:18.310  INFO   Application started
14:32:19.084  ERROR  Request timeout after 30s
──────────────── 14:32:20 日志连接中断 ────────────────
──────────────── 14:32:24 连接恢复 ────────────────────
14:32:24.512  INFO   Connection established

已保存 12,480 条 · 已暂停滚动       [继续跟随 · 新增 23 条]
```

### 4.2 布局收缩

- 常规窗口优先以现有 1100 × 720 尺寸验证，不增加常驻侧栏。
- 650 × 400 的现有最小窗口仍能看到日志和主要阅读动作。服务器详情收起，工具栏缩减次级文字，图标按钮保留可访问名称与提示。
- 条件标签可以换行，较多时折叠为“筛选 3 项”；至少保留活动条件数量与一键查看入口。
- 高度不足时存档统计移入详情，搜索收起后归还空间；不把正文压成几行。
- 弹出层约束在窗口内，长内容内部滚动。普通查找、筛选、显示设置不使用全屏遮罩，不中断看日志。
- 字体放大时先重排和收拢次级信息，不缩小字体或裁掉操作；日志原文可以水平滚动或选择自动换行。

## 5. 状态模型：逻辑分离、展示简洁

内部区分三组状态，界面不同时陈列三个同等醒目的徽章。

| 状态维度 | 取值 | 默认展示位置 |
| --- | --- | --- |
| 容器 | 运行、停止、重启、删除、未知 | 标题详情；影响接收时提升为可见提示 |
| 采集 | 连接、同步历史、实时接收、等待启动、重连、需要处理、仅本地存档 | 标题右侧主状态 |
| 阅读 | 跟随最新、翻阅暂停、手动暂停、选区暂停、搜索快照、上下文 | 底部阅读栏 |

状态文案和动作：

| 场景 | 主状态 | 反馈与操作 |
| --- | --- | --- |
| 正常接收 | 实时接收 | 安静的状态标识；无持续转圈或脉冲 |
| 没有新日志 | 实时接收 | 详情显示最近输出时间；日志安静不等于连接失效 |
| 首次同步 | 正在同步历史 | 展示已读取数量；总量未知时不编造百分比 |
| 容器停止 | 等待容器启动 | 保留日志，说明启动后自动接续 |
| 已确认重启 | 容器正在重启 | 保留日志与阅读模式，自动检查恢复 |
| 网络中断 | 正在重连 · 8 秒后重试 | 单条非阻断提示，错误详情按需展开，允许立即重试 |
| 不可恢复错误 | 采集已停止 | 常驻原因与明确动作，如重试、查看连接详情 |
| 原容器删除 | 原容器已不存在 | 保留存档，提供查看容器列表入口 |
| 离线查看 | 本地存档 | 明确无实时接收，提供返回服务器连接入口 |

容器状态无法确认时显示“状态暂不可确认”，详情保留上次确认的状态与时间。不能从日志流关闭直接推断重启，也不能把采集失败显示成用户主动暂停滚动。

## 6. 核心交互契约

### 6.1 跟随与暂停

默认在线打开后跟随最新，后台采集始终独立于阅读控制。底部只保留一个主要阅读动作，不再并列“自动滚动”复选框与“跳到最新”。

| 用户动作 / 事件 | 阅读状态变化 | 底部动作与规则 |
| --- | --- | --- |
| 正在跟随，用户单击正文或聚焦正文 | 不变化 | 显示“暂停滚动” |
| 用户向上滚动、键盘翻页、拖动滚动条离开底部 | 翻阅暂停 | 显示“继续跟随”，有新增时附带数量 |
| 翻阅后回到底部 | 恢复跟随 | 仅翻阅暂停可自动恢复；须无文本选区、搜索快照或上下文 |
| 用户点击“暂停滚动” | 手动暂停 | 到达底部也不自动恢复，直到点击“继续跟随” |
| 用户形成非空文本选区 | 选区暂停 | 稳定选区与阅读锚点；清除选区后仍保持暂停，显式继续才恢复 |
| 连接中断再恢复 | 保持原阅读状态 | 原来跟随就继续；原来暂停就保留位置和新增提示 |
| 内容加载、换行设置、字体变化导致布局改变 | 保持原阅读意图 | 不把程序滚动或布局变化误认为用户翻阅 |
| 用户点击“继续跟随” | 跟随最新 | 定位最新匹配记录并保持兼容的筛选条件 |

“新增 N 条”表示暂停后尚未追到的记录，不因重复渲染而累加。无筛选时可计算全部新增；有筛选时若未完成匹配统计，文案用“有新日志”，不把全部新增数冒充匹配数。

不按每条新增日志执行平滑滚动。连续输出批量更新并贴住底部；用户一旦开始翻阅，立即让出滚动控制。跨大量记录回到最新时直接定位并作短暂位置提示，避免长距离飞越动画。

### 6.2 查找、筛选与上下文

- 点击“查找”或 Ctrl/Cmd+F 仅展开并聚焦输入；空输入不冻结日志，也不改变当前阅读位置。
- 提交有效关键词后进入历史查找快照，正文稳定，底部显示“搜索结果截至 HH:mm:ss”。输入过程即时反馈，查询可去抖并取消旧请求，不阻塞输入。
- 关键词默认查询本地已保存记录。快照期间采集继续，出现新数据时提供“更新结果”；更新结果保持原条件，并尽量保持锚点。
- 关键词条件提供显式“实时筛选”切换。开启后新匹配记录持续追加，遵循相同的跟随与暂停规则；未匹配的记录仍正常保存。
- 输出流筛选默认可实时使用。设置固定时间范围后进入历史快照，显示时间范围和时区，不伪装成实时视图。
- 收起搜索面板保留条件标签；清空输入移除关键词条件，但不自动清除输出流、时间范围或用户的暂停意图。
- 搜索快照中的主动作是“实时筛选并跟随”，保留关键词及输出流。有固定时间范围时改为“退出时间范围并跟随”，明确该动作会移除时间范围；无需额外确认弹窗。
- “清除条件”只清除条件，不隐式恢复滚动。恢复跟随由显式动作或翻阅返回底部完成。
- 查看命中上下文时保留原查询、快照和阅读锚点，提供“返回搜索结果”。因条件变化失效的旧请求不得覆盖当前视图。

### 6.3 复制与导出

- 原生文本选择和 Ctrl/Cmd+C 保持熟悉行为，复制所选文本不弹窗。
- 点击序号选择记录，Shift 点击扩展范围。有效记录范围出现后，在底部阅读栏的固定区域提供“复制原文”“导出所选”“取消选择”，避免额外常驻一排输入框。
- “按序号选择”作为高级入口，继续支持精确范围；正文截断的长行可以通过记录选择复制全文。
- 导出菜单明确区分“全部已保存”“当前筛选结果”“选中记录”；不可用项显示原因。
- 筛选导出由后端读取固定快照中的全部匹配记录，不只导出已加载的前端缓存。
- 成功提示靠近触发动作，以轻量文字反馈；导出失败常驻到用户处理，不自动消失。
- 容器原文与系统事件分开。默认原文导出不混入“连接恢复”等应用生成的标记；需要时独立导出采集事件。

### 6.4 关闭与重新打开

- 关闭日志窗口停止该窗口采集，本地记录保留。连接详情与存档说明明确这一边界，不把本地保存称为持续后台采集。
- 重新打开在线容器时读取本地记录并从可用游标接续，默认跟随最新。
- 保存用户的字体、换行、时间戳、高亮偏好；第一期不跨窗口恢复隐藏查询和暂停状态，避免下次打开后看似没有新日志。
- 独立窗口失去焦点不停止采集，不改变阅读模式。

## 7. 容器重启与日志完整性

### 7.1 同一容器重启

流程：保留内容 → 等待或重连 → 检查容器 → 补读并去重 → 按原阅读模式继续。

- 第一阶段复用现有 5 秒轮询与网络退避机制；5 秒是检查间隔，不是恢复时间保证。
- 分类处理网络、daemon 暂态不可用、权限不足、容器不存在、驱动不支持、磁盘写入失败。暂态错误自动重试，明确不可恢复错误停止并提供处理入口。
- 事件行只表达已经确认的信息：日志连接中断、恢复、检测到新的启动周期。重复重试只更新状态，不向正文每秒插入一条提示。
- 事件保留实际检测时间；容器启动时间可确认时另存实际时间。显示顺序采用稳定锚点，补读历史不能使用户正在阅读的事件上下跳动。
- 接续保留合法重复行，对回读范围做去重。日志轮转或远端记录已不可取回时，说明能够确认的覆盖范围，不承诺无条件零丢失。
- 不把 SSH 采集批次当作容器启动周期，不凭断流次数推断重启次数。

### 7.2 容器重建

- 第一阶段识别旧 ID 已不存在，保留旧存档并提供查看容器列表入口。
- 第二阶段按可信的 Compose 项目、服务和实例身份查找替代容器；名称相同不足以自动确认，多个候选需要选择。
- 发现替代目标后提供“查看新容器日志”，展示新旧短 ID。切换保持来源清晰，各 ID 的存档独立保存。
- 自动跨重建跟随不作为第一期默认行为，后续仅在身份规则明确后提供可选设置。

### 7.3 启动周期与大历史量

- 第二阶段增加“全部已保存 / 本次启动 / 上次启动”，附明确时间；无法可靠归属的历史记录保留为“未确定启动周期”。
- 当前 runs 代表采集批次，不能直接用于启动周期筛选，需补充生命周期元数据。
- 首次全量同步耗时先测量。确有阻塞实时排查的问题，再引入最近日志优先、历史后台补齐；实施前处理排序、稳定锚点、单一写入协调和去重。

## 8. 视觉、动效与可访问性规格

### 8.1 视觉层级

- UI 使用现有系统字体栈，正文日志沿用 `--mono`。复用 `--font-title`、`--font-body`、`--font-secondary`；不要为了容纳更多信息继续缩小正文。
- 标题靠字重和留白建立层级；日志行初始建议 `--font-body`、约 1.5–1.65 行高。序号和时间戳弱化但可读，正文保持近零字距。
- 间距、圆角、控件高度复用项目 token，以 rem 随文字缩放；在原型中验证正文密度，不另建大圆角卡片包围每个区域。
- 顶部工具层和浮动菜单可使用一层轻质半透明材质；正文保持稳定实底，避免多层玻璃叠加干扰密集文字。
- 内容与悬浮工具层接触处用柔和滚动边缘提示。正文留出足够可视内边距，第一行、最后一行与键盘焦点不能被工具层遮挡。
- 正常状态使用中性文字与小型状态标识，动作使用项目蓝色；警告、错误保留颜色并配文字或图标，日志等级与采集错误分别表达。
- 不为新日志逐行加入弹入、闪烁或颜色脉冲，不让正常运行持续吸引注意力。

### 8.2 动效契约

| 交互 | 反馈方式 | 中断与降级 |
| --- | --- | --- |
| 按压按钮 | pointer-down 立即改变背景或轻微按压，释放后提交动作 | 拖离可取消，不在按下阶段执行远端操作 |
| 搜索栏展开与收起 | 在固定位置出现，保持当前正文锚点；初始淡入约 120–160ms | 不等待动画才聚焦；快速切换可立即反转 |
| 显示、筛选、导出弹层 | 从触发点附近展开，同一路径收起；需要位移时使用无回弹、可重定向的弹簧 | 从当前显示值继续，输入不被过渡锁住 |
| 状态更新 | 稳定布局内短暂交叉淡化，初始约 120ms | 高频重试不反复做入场动画 |
| 实时追加 | 批量渲染、保持底部或阅读锚点 | 无逐行动画，不劫持原生滚动 |
| 回到最新 | 直接定位；必要时做一次克制的位置提示 | 不做跨几千行的平滑滚动；可立即再次翻阅 |

若使用弹簧，初始参考 damping 1.0、response 0.3–0.4；由所用库语义映射，不能将 response 直接误当成固定动画时长。对这类密集工具默认无回弹，不为日志滚动引入自定义弹簧。

优先动画化 opacity 和 transform；搜索栏尺寸变化只在必要时布局一次并恢复锚点。模糊材质以静态层为主，性能测量支持时再考虑轻微材质过渡。

### 8.3 可访问性与平台适配

- 减少动态效果：移除位移、弹簧与强调动画，采用静态切换或短淡化，状态反馈继续可见。
- 减少透明度：工具层与弹层使用不透明背景；高对比度使用清楚边界。除媒体查询外，复用现有主题设置，并为运行环境不支持的偏好提供可靠实底回退。
- 键盘可访问所有操作；Esc 关闭最上层弹层并将焦点还给触发按钮，不暗中清掉查询。无弹层时 Esc 收起搜索面板，条件标签继续可见。
- `aria-live` 仅播报重要状态变化、复制或导出结果，不逐条播报日志或每秒倒计时；容器故障和普通暂停使用不同语义。
- 正文虚拟化需要验证键盘浏览、选区和屏幕阅读器体验；聚焦记录不能因裁剪缓存突然失去位置，必要时提供可访问的分页阅读方式。
- 检查 200% 文字缩放、浅色和深色主题、系统高对比度；焦点、错误和选中状态不依赖透明度或单一色差。

## 9. 实现边界与技术落点

| 位置 | 规划中的职责 |
| --- | --- |
| `ContainerLogsApp.tsx` | 分离采集、查询和阅读状态；跟随原因、稳定锚点、选区、活动条件与上下文返回 |
| `logs.css` / 既有主题 | 布局层级、按需呈现、弹层材质、响应式与偏好降级 |
| `logApi.ts` | 结构化采集事件、查询快照与筛选导出接口 |
| `src-tauri/src/logs.rs` | 错误分类、恢复策略、容器生命周期观测、系统事件 |
| `log_ingest.rs` / `log_store.rs` | 持久化游标、去重、系统事件与启动周期元数据、完整范围导出 |
| 现有日志与桌面测试 | 状态转换、视图锚点、搜索和导出语义、真实 Docker 生命周期验证 |

实现时须注意：

- 用结构化状态码和 retryAt、reason 等字段表达采集状态，文案在前端映射，不依赖中文字符串决定行为。
- 新增类型可放入单独模块，避免继续把所有状态塞进一个组件；保持已有原文与序号的可追溯性。
- CLI 诊断可能与容器 stderr 共用通道。需要可靠区分命令诊断和应用输出，不能简单删除所有无时间戳行；实现策略需先用失败夹具验证。无法确定时保留原始信息并标明来源不确定。
- 新增元数据采用兼容迁移，旧存档可读；没有启动周期信息时显示未知，不伪造历史。
- 前端继续采用有界缓存和虚拟列表。裁剪旧缓存、历史补入、设置换行与重连不能破坏当前锚点和选区；数据不可保留时显式提示。
- 第一阶段不新增后台常驻采集服务，也不改变关闭日志窗口即停止采集的生命周期。

## 10. 交付阶段与验收门槛

| 阶段 | 交付内容 | 完成标准 |

| P1：排查效率 | 实时关键词筛选、筛选导出、范围操作、启动周期与来源切换 | 条件与数据范围一致、导出完整、旧存档兼容、新旧 ID 可辨认 |

P0 的关键词查找先保留稳定快照；“实时筛选并跟随”在 P1 的实时查询能力完成后启用。此前返回实时的操作明确写为“清除关键词并返回实时”，预先表达副作用，并保留可兼容的输出流条件。第一期不能展示尚未实现的实时关键词承诺。

本轮交付为规划文档。交互原型作为进入业务实现前的首个验证产物，需用可控模拟数据明确标记其演示性质；原型通过不替代真实 Docker 验证。

## 11. 验收矩阵

| 场景 | 必须验证的结果 |
| --- | --- |
| 跟随时重启同一容器 | 内容保留、状态变化可见、启动后自动接续并跟随 |
