## 1. 目标与边界

让用户在服务器工作区内查看目录结构、文件大小和目录背后的挂载信息。用户要求来自 [P-32](../../product.md)；首轮推荐 Windows 客户端访问 Linux/OpenSSH，文件浏览和挂载解释作为独立官方插件交付。功能范围、平台及默认布局均随 T-008 评审。

核心负责服务器、认证、SSH 租约、SFTP/远端读取与执行通道、取消、调用记录和工作台承载；插件负责目录树、文件显示规则、Linux 挂载数据解析、路径匹配、容量解释、加载与缓存状态。不能把文件树加入终端插件或把挂载业务判断写进核心。

首轮只读；编辑、上传、下载、删除、移动、目录递归大小、挂载/卸载、自动修改终端路径和容器卷管理留待实际需求。按 P-13 不调用终端或 Docker 插件。

## 3. 视图与状态

遵循 [UI 规范](../../standards/ui.md)及 [F-CORE-004](../../core/workbench.md)，采用 apple-design 的熟悉树形操作、即时反馈、稳定空间位置、清晰排版和键盘可达性。

| 视图类型建议 | 作用域与数量 | 支持位置及默认 | 尺寸建议 |
| --- | --- | --- | --- |
| `files.explorer`：文件 | 每服务器工作区一个逻辑实例 | 左/右停靠，默认左；随完整工作区移动到其他窗口。本轮不单独弹出文件窗口、不占中央终端 Tab | 默认宽 320 CSS px，最小 260×240，按系统文字缩放适配；窄窗可收起 |

每个已打开服务器 Tab 都有“文件”工具入口。新工作区按声明默认展开；侧栏位置、宽度、显隐属于本工作区本次创建期间的临时状态，切换/收起/移窗时保留，结束工作区或重启后不恢复。不从旧布局迁移文件入口或侧栏现场。实例不按终端 Tab 复制，自动文件读取只针对可见面板；用户新建后台工作区所触发的首终端连接仍遵循 P-34。

默认文件面板拟通过已有 `workspaceEntries` 单实例视图声明接入；不另注册一个自动建连的文件初始化动作。T-009 的 `workspaceInitializers` 继续驱动首终端。文件面板只从核心获取连接可用性并独立申请租约，不等待终端业务回执或借用终端句柄；连接就绪时可见面板读取根目录，未就绪显示等待/手动读取入口。取消终端认证不会由文件自动重试；侧栏加载、失败或恢复不得阻塞首终端初始化或抢输入焦点。

核心持有视图、窗口、宽度和显隐；插件按工作区持有路径、展开集合、选择、滚动位置及数据快照。移窗保持逻辑实例和数据归属，重新挂载不新建业务会话。收起/切换保留状态、停止新增读取；明确关闭释放本视图请求和租约。再次使用通过工具入口恢复视图。

## 4. 运行、数据和依赖

每个启用插件一个业务实例，文件与终端分别运行；文件实例内部按工作区隔离。T-008 使用通用注册、路由、生命周期和故障隔离承载两个实际插件，不使用文件专用加载分支。

文件插件只经公开且有版本的核心 API 工作，使用自己的连接租约；不从终端取得句柄、密码或滚屏内容。核心能力声明表达兼容依赖，不是插件权限表。每次调用保留来源、目标、时长、数量和结果等摘要。

按 P-33/P-34 已确认且由 [T-009](../../tasks/T-009-clean-start.md) 实施的 [F-CORE-010 r2](../../core/clean-start.md)，插件持久数据仅保存隐藏文件等明确偏好；当前路径、展开集合、选中/滚动及侧栏现场只在同次运行的当前工作区创建期间维护。关闭服务器再打开是新工作区，重新从 `/` 开始；App 重启为空工作台，不恢复文件视图或自动读取。同次运行切换、收起、移窗和托盘恢复保留现场。文件内容、文件清单、挂载详情及句柄不持久化。

接入基线为 T-009 核心 dev.4，当前配套核心 dev.5、原终端 0.4.0、插件 API 4.1 / `workspace.v4`。工作台内存提交的 `persisted:false` 是正常结果，不触发保存布局或恢复旧快照。工作区 generation、远端连接代次与视图呈现代次分别校验；关闭再打开后旧读取不能更新新工作区。首版没有旧文件工作现场需要迁移；本次实施授权来自 T-008 自身确认。

## 5. 构建、兼容和更新

`plugins/files/` 独立构建和签名，随 core `2.0.0-dev.5` 开发目录包附带；构建入口为 `node scripts/pack-plugin.mjs --plugin files --out resources/files.sodeck-plugin`。要求 API/SDK `^4.1.0`、`workspace.v4` 及 `remote.files.read.v1`、`remote.exec.v1`、`connections.observe.v1`、`workspace.multiplugin.v1`、`workspace.presentation.v1`。现有终端 0.4.0 原包保持哈希，通过旧响应形状投影兼容严格 SDK 校验；API 3 及更早包继续拒绝。缺少文件所需能力时明确提示不兼容，终端继续工作。

核心承担通用字节路径适配，避免 Windows 路径转换破坏远端名称；插件使用公开字节路径契约、BigInt 大小、分批目录和有界缓存。具体模块、接口、预算和 Linux 采集前提以代码方案为准；实际脚本与结果见开发入口及任务。文件持久 schema 1 只保存隐藏文件等明确偏好，不迁入工作现场。

文件插件更新遵循现有包验证和重启生效机制，不热替换；首轮需用两个真实文件插件版本验证只更新文件 UI/业务、核心和终端包不变。坏包、启动失败及回退不能把终端一并禁用。
