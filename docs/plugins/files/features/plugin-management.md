## 1. 本次边界

覆盖SFTP目录树、挂载容量读取、工作目录跟随与观察订阅。完整性、签名状态、启用存储和加载门禁由核心负责；本插件不实现自己的启用开关、签名审批或核心管理页。启停完整重启生效，停用不执行任何插件代码、保留包与业务配置；原功能与资源归属不改。

核对文件：plugins/files/src/worker.ts、state.ts、view.tsx、manifest.json。预计不改业务实现、不提升manifest要求、不重编译现有有效包；用当前API6.1原包验证新核心兼容。如发现确有需要修复的生命周期缺陷，先记录落点及其属于已确认结果的依据，再改代码。新核心API6.2不意味着每个插件必须重编译。

## 2. 本插件测试流程

适用r1，关联公共AC-03/04/06/07。使用.qa/t028下的独立App数据与插件副本，已有隔离SSH/Linux环境；协议夹具与真实服务证据分别记录，不接触日常服务器。三项均在Windows原生宿主验证，必要计数用测试入口，不把UI按钮消失当成worker已停证据。

| 用例 | 准备与步骤 | 预期 |
| --- | --- | --- |
| FILES-PM-01 | 隔离服务器打开文件树并与终端共享连接；取消文件启用应用，再退出重启 | 应用后树仍可用；重启无文件worker/侧栏/文件SFTP和容量任务，终端继续独立可用 |
| FILES-PM-02 | 保持文件启用、仅停用终端，重启后手动浏览目录 | 文件插件独立工作，不等待终端或自动启动终端；没有目录来源时沿用原回退规则 |
| FILES-PM-03 | 重新启用文件，重启浏览含挂载目录并打开/关闭工作区 | 保留插件配置，目录/容量恢复；订阅与SFTP使用关系按所属工作区释放，不影响其他插件连接 |

共同清理：停止测试业务、关闭工作区并完整退出，核对本插件进程/核心租约/监听/订阅释放；恢复隔离副本启用状态，保留日志/版本/包哈希。不得通过清空用户配置模拟停用。实际结果统一写T-028实施记录，当前均未运行。
