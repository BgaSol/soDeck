用户明确要求：每个服务器 Tab 都有磁盘目录树；文件节点能看到大小；挂载目录能看到挂载详细信息。本方案推测用户主要想回答“文件在哪里、多大，这个目录实际位于哪份存储、还有多少空间”。

推荐首轮：Windows 客户端浏览 Linux/OpenSSH 远端当前账号可见的文件系统，按实际目录层级展开，并识别当前有效挂载。这里的“磁盘目录树”以 `/` 为根，不把 Linux 的磁盘强行呈现为 Windows 盘符；挂载目录自然出现在树中。

挂载查询依赖 procfs、POSIX sh、cat/readlink 及可核对的 SFTP 根句柄，无需远端 Agent 或 Python。容量优先使用 stat，命令不可用或不兼容时尝试 POSIX 格式 df；支持 GNU/Linux 与具备上述能力的 OpenWrt/BusyBox，能力按实际探测，不按发行版名称假定。SFTP 与 exec 的根目录、进程/命名空间无法可靠对应时按第 3.3 节降级；能力缺失不阻止可用的目录浏览。具体兼容和验证见 COMPAT-FILES-002，历史 GNU 基线见代码方案第 7 节。

包含目录浏览、直接输入路径、文件大小、挂载标记和详情、手动刷新、复制路径及每工作区状态恢复。首轮不做文件正文预览/编辑、传输/删除/移动、全盘搜索、递归目录用量、挂载配置修改、物理磁盘拓扑或容器内部卷浏览。该范围已随 T-008 r4 获确认。

“目录挂载”按广义操作系统挂载理解，包含块设备文件系统、网络文件系统、目录 bind 挂载及系统虚拟文件系统；不是仅指 bind，也不把符号链接当成挂载。若用户实际指 Docker 卷与宿主目录对应关系，需要另行明确容器范围。

## 2. 入口、布局与日常操作

### 2.1 每服务器一个文件面板

- 位于服务器工作区左侧，工具入口名称“文件”，面板内显示当前服务器和路径；默认宽 320 CSS px，可在核心支持范围内调整及移到右侧。详见插件视图声明。
- 每服务器在本次运行的当前工作区创建期间独立保存展开位置、选中节点、滚动位置、侧栏位置/宽度和显隐。切换终端 Tab 时目录树不变；切换服务器 Tab 时切换所属文件视图；同一服务器不会为每个终端重复生成文件树。
- 默认在新工作区展开；可以收起，恢复后回到原位置。完整工作区拆到新窗口或合并时一起迁移；单独弹出的终端窗口保持原有单视图用途。关闭服务器工作区再打开是新创建，从 `/` 和默认布局开始；重启只显示空工作台。取消“旧布局增加文件入口”的迁移计划，不从插件设置恢复侧栏现场。
- 按 P-34 / [F-CORE-010 r2](../../../core/clean-start.md)，新建服务器工作区会自动创建首终端并连接。文件面板同时出现但不再发起另一轮自动认证；核心连接尚未就绪时显示“等待连接”，文件不订阅终端私有状态。已有匹配配置的有效连接且面板可见时，文件通过核心取得自己的租约并按需读取；不以终端页/PTY 成功为必要条件。
- 没有可用连接且首终端尝试结束、失败、取消或不可用时，保留“连接并读取”入口；用户触发可单独建连，仍不调用终端。自动读取只能取得现有连接，连接在检查后失效也不能回退为新建/重新认证；由核心提供原子复用或等价语义，避免检查与申请之间的竞争。文件显式取消后暂停自动读取，直到用户重新触发。后台面板不因存在入口而自动读取或弹认证；用户新建工作区的首终端自动连接仍按 T-009 执行。
- 第一次成功读取只展开根目录一层；后续沿用户展开动作逐层读取。恢复可见面板可重新检查当前层和已选节点，其他缓存分支在展开时检查；不递归刷新整棵树。

文件侧栏沿用 `workspaceEntries` 默认视图；首终端沿用 `workspaceInitializers`，不再为文件注册重复自动连接动作。默认侧栏的创建/加载失败局部显示，不阻止首终端初始化；文件加载、刷新及表面恢复不自动获焦点。只有用户主动进入文件面板才转移输入焦点，首终端完成连接也不能抢走用户已经进入文件面板的焦点。核心按实际活动视图和用户操作分派，不能依据多个 WebView 的显示先后决定；保留 apple-design 的可预测焦点与即时反馈，原生验证见 FT-09/13。

### 2.3 树形交互

- 单击行选中并更新详情；点击展开箭头或双击目录行展开/收起。双击文件仍只查看属性，不读取正文或执行文件。展开反馈即时出现，加载状态放在对应分支。
- 路径框接受绝对路径，`~` 可由明确的远端账号 home 信息展开；不做命令、变量或通配符求值。Enter 定位并逐级展开必要祖先；目标是文件时选中该文件。失败保留原位置并说明原因。
- 工具栏提供路径、刷新和“显示隐藏文件”；推荐默认显示隐藏文件，过滤只影响当前目录展示。刷新当前展开且可见的目录与所选详情，并重取挂载快照；不读取折叠后代。
- 目录优先，同类按名称稳定排序；大目录分批载入，明确标出“尚有条目未加载”，只对已载入集合排序，不把分批结果伪装成完整清单。提供“继续加载”，精确路径定位不依赖先遍历所有兄弟节点。
- 右键提供复制完整路径、刷新此目录、查看详情；折叠/展开适用于目录。没有上传、删除、挂载/卸载或“在终端执行”入口。菜单使用核心公共服务，遵循现有关闭和焦点恢复规则，无省略号更多按钮。
- 键盘上下移动，右键方向展开/进入子项，左键方向收起/返回父项；Home/End 定位已载入可见列表首尾；Enter 查看文件详情或切换目录展开；F5 仅在文件面板内刷新，Shift+F10 打开节点菜单。路径框的方向键保留文本编辑语义，终端快捷键不被全局拦截。

## 3. 节点和挂载的显示规则

### 3.1 文件、目录及特殊节点

| 节点 | 树行显示 | 选中详情 |
| --- | --- | --- |
| 普通文件 | 名称、文件图标、右对齐大小；采用 B/KiB/MiB/GiB/TiB，0 字节显示 `0 B` | 完整路径、类型、格式化大小与精确字节数、修改时间和可取得的账号权限信息 |
| 普通目录 | 展开箭头、名称；大小栏留空 | 完整路径、目录属性；可显示“所在文件系统”，明确其自身不是挂载点 |
| 挂载目录 | 目录图标加挂载标记与“挂载”标签；只读可加文字标记 | 第 3.2 节的挂载详情；目录照常可展开 |
| 符号链接 | 独立链接标记和目标提示，大小栏显示“链接” | 链接目标；不自动递归跟随，可明确“定位目标”；目标是文件时另列其大小，失败显示失效/无权限 |
| 设备、socket、FIFO 等特殊文件 | 真实类型标记，大小栏显示 `—` | 类型和可用属性，不尝试读取或打开设备 |

普通文件大小是逻辑字节长度，不是实际磁盘占用；稀疏文件和压缩文件可能不同。普通目录不把 inode 的目录项长度当成内容总大小，不自动执行递归统计。动态文件/虚拟文件的长度可能为 0，按远端属性显示并提示其不等于实时内容长度。大整数不经过会丢失精度的 JavaScript 数值转换。

挂载到普通文件的情况保留文件大小并加挂载标记，不误画成可展开目录。文件名按数据处理，特殊字符安全显示，真实路径独立保存，不从经过裁剪/转义的显示名反向拼接操作目标。

### 3.2 挂载详情

主信息直接展示；复杂信息放在“高级信息”，可展开、选择及复制。信息缺失显示“不可用/未提供”并解释原因，不能填 0 或猜测。

| 字段 | 含义与展示 |
| --- | --- |
| 挂载位置 | 当前目录的完整路径，例如 `/srv/data` |
| 挂载来源 | 块设备路径、网络导出/共享，或可确认的源目录；例如 `/dev/mapper/vg-data`、`nas:/exports/backup` |
| 文件系统类型 | ext4、xfs、btrfs、nfs、cifs、tmpfs、overlay 等，展示服务端实际结果 |
| 挂载性质 | 本地文件系统/网络/目录绑定/虚拟等；只有证据足够时标为 bind，无法确认时保留类型和源信息 |
| 容量与使用 | 文件系统总量、已用、空闲、当前账号可用；已用比例 = `(总量 − 空闲) / 总量`，总量为 0 或统计无效时不计算百分比 |
| 访问模式 | 挂载级别只读/读写；说明“读写挂载”不保证当前账号具有目录写权限 |
| 更新时间 | 详情观测时间及过期状态；不同来源采集不是原子快照，变化时允许重新读取 |
| 高级：挂载参数 | 有效挂载选项、文件系统选项；敏感参数值及来源中的凭据脱敏，不能把原始含密输出放进日志或复制结果 |
| 高级：源内路径和标识 | 文件系统内根路径、挂载 ID、父挂载 ID、设备号等可可靠取得的数据；不承诺总能还原 bind 源目录、UUID 或卷标 |

容量表示该挂载对应的文件系统统计，不是这个目录所有文件的总和。bind 挂载通常共享底层文件系统容量；重复挂载不能相加形成“服务器总容量”。保留空间/配额可能使当前账号可用小于空闲；字段按实际来源解释，不承诺通用方式得到所有配额。网络/虚拟/overlay 不强行归到某一物理硬盘。

容量降级：df 回退只显示实际报告的总量、已用与账号可用，按 1 KiB 单位转换并注明精度；未独立提供的空闲字段显示“不可用”，不从四舍五入后的值推算。负的可用量或未提供值同样显示不可用，不冒充 0。使用率统一为已用/总量，不能套用 df 基于账号可用量的百分比；总量为 0 不画比例。df 输出不完整、单位不明、目标无法唯一匹配时，只将容量标不可用，挂载来源/类型继续可见。

### 3.3 判断边界

- 以当前连接账号执行上下文能看到的运行时挂载为准；仅写在配置文件但尚未挂载的项目不显示成有效挂载。不能宣称看到宿主机或所有容器命名空间。
- 目录路径与挂载目标精确相等才标成挂载点；普通后代只显示所属挂载。所属挂载采用路径段边界匹配和最长匹配，`/data` 不能匹配 `/database`；根 `/` 也可为挂载点，嵌套挂载优先。
- mountinfo 的挂载目标必须是绝对路径；源内根是文件系统提供的原始元数据，可能为 `nsfs` 的 `net:[inode]` 等特殊标识，不要求以 `/` 开头。保留其字节和转义，不用于目录定位、容量命令或绑定来源推断；`nsfs` 按虚拟文件系统解释。合法特殊记录不能使整张挂载表不可用；空根、非法目标、损坏转义和重复 ID 仍明确报错。
- 符号链接的显示路径与解析目标分开；定位目标后判断目标挂载，不给原链接伪造挂载身份。不自动展开链接环。
- bind 不能只凭“源内路径不为 `/`”判断，btrfs 子卷等可能类似；源目录不可可靠还原时显示“源内路径”及限制。同目标存在叠加挂载时只把可确认的当前可见挂载作为摘要，不能按记录顺序猜测；不确定时列候选并提示无法确认。
- 目录浏览与挂载数据必须属于同一可核对的远端路径视图。SFTP chroot、不同 mount namespace 或 exec 受限导致无法对应时，目录树可继续使用，挂载详情显示不可用；不能把两份不同根目录的数据按字符串硬拼。
- 无权访问目录不代表没有挂载，挂载信息不可取得也不代表普通目录；未知情况显示“挂载信息不可用”，保留可用部分。

## 4. 状态、异步与资源

| 状态/事件 | 可观察行为 |
| --- | --- |
| 首次未连接 | 新建工作区的首终端在连接时文件显示等待；该尝试结束仍无连接时显示“连接并读取”。文件显式连接复用核心认证，取消后只允许明确重试 |
| 展开/详情加载 | 只在相应节点或详情区显示进度，可以取消；重复展开合并同一代次的请求 |
| 空目录 | 显示“空目录”；与无权限、读取失败及未加载分开 |
| 局部失败 | 分支显示原因和重试；挂载失败不抹掉已成功的文件列表，容量超时不抹掉来源/类型 |
| 刷新/远端变化 | 旧数据暂留并标刷新中；新结果保留仍存在的选择/展开；节点消失则选择最近存在祖先并提示 |
| 断线 | 保留本次运行内已读快照，标为过期和最后读取时间；暂停请求，提供重新连接，不伪称实时 |
| 重连/配置改变 | 新连接代次，旧请求/目录游标失效；新目标或账号不能沿用旧缓存，重新核对路径和挂载 |
| 收起或切换服务器 | 不再发起隐藏内容读取，取消不再需要的查询，保留有界快照及已有租约；不会中断其他插件 |
| 移窗/合并 | 状态和业务请求仍归原工作区；撤销旧表面绑定，目标从快照恢复，不能因重挂载重复查询或建连 |
| 明确关闭/插件停止/退出 | 取消所属读取、关闭目录句柄/执行通道、释放本插件租约；终端的租约与 PTY 不受文件面板关闭影响。关闭工作区删除所属文件现场，重新打开是新代次；退出 App 按公共规则全部结束 |

所有响应绑定服务器配置、工作区 ID 及其创建 generation、插件实例、连接代次、路径和请求代次；选中 A 后立即选 B，A 的迟到详情不能覆盖 B。关闭服务器后立即重新打开，即使 ID 相同，旧代次的目录/挂载响应、租约和认证回执也不能绑定新视图。移窗仅前进呈现代次，保留工作区创建身份。没有周期性全盘扫描；挂载信息在首次读取、手动刷新、重新连接时刷新，返回面板先核对所选详情并标明旧信息是否仍有效。

底层通道与取消由核心持有，插件只消费公开能力；接口及限制见 F-CORE-009。文件和终端各自申请租约，可复用核心连接，不依赖“终端必须已打开”。内存目录列表、挂载快照和进行中请求有界，准确限额、超限行为与受控性能标准由代码方案第 8 节维护；目录分批显示、缓存淘汰和过期句柄必须有可见反馈，不得宣称已加载全部数据。

按 P-33/P-34 已确认的 [F-CORE-010 r2](../../../core/clean-start.md) / [T-009](../../../tasks/T-009-clean-start.md)，持久化仅保存隐藏文件等明确 UI 偏好；当前路径、有界展开集合、选择/滚动及侧栏现场只在当前工作区创建期间维护，不保存目录快照或文件内容。App 重启不恢复文件视图、路径或连接；用户重新打开工作区后从默认入口开始，未读数据不显示成实时。同次运行切换/移窗/托盘恢复仍保持状态。无需新增插件授权弹窗，不自动 sudo、安装远端工具或修改远端配置。

接入以已实施的 API 4 / `workspace.v4` 为基线，计划通过 API 4.1 兼容扩展新增能力；工作台 `persisted:false` 表示正常的内存提交，不报保存失败或重试写布局。现有终端 0.4.0 原包是兼容与回归基线，API 3 包不纳入兼容承诺。多插件注册、初始化归属和取消路由仍待 T-008 扩展；方法/动作 ID 以插件身份限定，不能让文件与终端的动作、资源或回执混用。

## 5. 视觉与可访问性

使用已读取的 `apple-design` 技能，落实为：

- 熟悉与可预测：标准树形选择/展开，详情紧邻所选对象，收起和恢复保持相同位置；不加入无关跳转或弹窗。
- 即时反馈：按下即显示反馈，选择和展开不等待网络；任何动画都不阻塞切换、取消或键盘输入。
- 清晰层次：沿用系统字体与 13px 正文、至少 12px 次要文字；建议行高 28px，图标 16px，缩进 16px；大小等宽数字右对齐，挂载用图标和文字共同表达。

- 日期/状态：2026-10-26，待验收。用户在只读调查和具体建议之后明确答复“可以，你做吧”，确认内核挂载数据、保留一致性校验、df 容量回退及缺失字段不可用的实现；本规格 r10。下文调查阶段事实保持，具体实现细节及测试在授权范围内自主完成，无需再次确认。

- 结论：此设备有挂载和空间数据，失败是当前依赖 GNU stat 的采集基线不满足，不能据此声称 OpenWrt 本身不提供挂载信息。证据 `.qa/openwrt-mount-diagnosis/1792999969187/result.json`；隔离 App 已停止，复制的加密凭据和数据库已删除，未安装或修改远端软件。
- 实施方案（编码前保存）：`linux-collector.ts` 在 exec shell 中以只读方式保持 `/` 的 fd，读取自身 fdinfo 与 readlink；同一 mount namespace 下与 SFTP 根句柄的 mount ID/inode 逐项相等，同时核对前后进程 starttime、namespace 和完整 mountinfo。以此替代 GNU stat 的设备/inode 对应，缺任一证据即拒绝关联。fd 随命令退出或取消关闭，SFTP 目录句柄继续 finally 释放。
- 容量方案：一次有界 exec 内尝试 stat 固定数值输出，失败后才尝试 `df -Pk -- "$p"`，用固定模式标识区分来源。路径沿用八进制 printf + 引号 + 哨兵，不作 eval。df 只接受明确 1024-blocks 表头、单条记录和已核对的挂载目标后缀，从后向前提取数值列，源名称中的空格不参与数值列推测；无法无歧义还原的换行/转义目标降级。BigInt 转换，容量前后挂载表仍须一致；超时/取消/读取失败不追加客户端重试。
