## 1. 目标与两项功能

用户希望以插件方式把远端网络资源接到本机。既要直接访问一个确定服务，也要让浏览器和其他支持代理的软件访问远端多个服务。推荐一个“网络隧道”官方插件承载两个明确模式；一个插件还是两个独立包属于本稿组织建议，用户明确要求的是两项功能均插件化。

| 模式 | 用户配置 | 本地怎么用 | 目标选择 |
| --- | --- | --- | --- |
| 端口转发 | 本地入口、SSH 路径、固定目标 IP/域名与端口 | 客户端直接连接本地入口，如 `127.0.0.1:13306` | 每条规则固定一个服务，支持多个并发连接 |
| 内网代理 | 本地代理入口、SSH 路径和最终访问节点 | 浏览器/工具配置 HTTP 或 SOCKS5 代理，再使用服务原始地址 | 每次请求指定目标，同一个入口可访问多个服务 |

用户已明确“经过多台 SSH 主机中转，入口在本机”，例如 `本机 → A → B → C → 目标服务`；目标服务可以就在 C，也可以是 C 能访问的另一台机器，后者不需要 SSH。两种模式建议共用同一套路径能力。本次不提供远端机器监听入口。

“把局域网映射到本地端口”在本需求中指通过该端口提供 HTTP/SOCKS5 代理，访问范围由最终 SSH 节点实际可达性和服务策略决定。不会让所有本地软件自动获得整个网段的 IP 路由；HTTP/HTTPS、SOCKS5 TCP 是本次建议协议范围，UDP/广播/ICMP/VPN 不据此自动纳入。

v1 的 `PortForward` 与 `NetworkProxy` 仅提供功能参考；本次同时包含两个功能，替代旧r1～r3的单功能建议。界面按v2重新设计。本地协议入口配合远端SSH目标通道，无需部署远端HTTP/SOCKS程序；`.16 → .18`场景见[内网代理§1.1](features/network-proxy.md#11-用户具体场景与连接位置)，具体协议载体/接口已按代码方案r1实施。

## 3. v2 界面方向

采用当前已读取的 apple-design 原则：清楚的功能标签、按下即时反馈、路径与其配置相邻、稳定排版、键盘可达、减少动态效果。主题和控件复用公共 `@sodeck/ui`，本稿不新建配色，不制作可执行原型。

推荐在服务器工作区提供“网络隧道”入口，新建时选择“端口转发”或“内网代理”。固定转发显示固定目标字段，内网代理显示客户端配置方式和目标测试；运行列表明确显示类型、入口、路径/最终节点和状态，避免把两类地址复制成同一种用法。

建议每工作区一个逻辑管理视图，默认中央 Tab，可随工作区移动或作为独立视图弹出；不自动抢占首次连接的终端。再次点击入口定位已有视图，不重复启动规则。此方向替代 r1 的右侧默认停靠建议，尚未获得实施确认。

运行中显示连接数、发送/接收、阶段和失败位置；“SSH 路径就绪”“目标服务连接成功”“网页/数据库业务成功”分开表达。复制、保存、启动分别提供原位结果。配置编辑不能被运行状态覆盖；配置改动默认下次启动生效，主动重启才影响当前连接。

### 3.1 本轮功能界面建议

- 顶部显示“网络隧道”、所属最终 SSH 服务器和“新建”；下方规则列表统一展示名称、类型、本地入口、目标说明、状态及启停。固定转发显示目标地址/端口，内网代理显示“目标由客户端请求指定”，不填虚假的固定目标。
- 选中规则后展开详情，按“本地入口 → SSH 路径 → 目标”顺序展示。短路径直接可见，长路径复用核心完整路径查询，显示总数与当前失败节点；不复制核心的服务器/密码编辑器。
- 新建/编辑使用一份表单：先选类型，再填写名称、本地端口；最终节点来自工作区。仅固定转发显示目标主机/端口。入口首版绑定 IPv4 回环 `127.0.0.1`，固定端口为1～65535；可显式选择自动分配并在运行后显示真实端口，禁止静默换端口。内网代理预填10808；固定转发端口由用户填写或显式自动分配。
- 表单底部区分“保存”与“保存并启动”；已有运行时显示“保存，下次启动生效”和独立“应用并重启”。重启按钮说明会断开当前连接，不用普通保存隐式重启。名称空白、地址/端口无效在字段旁提示；运行时错误显示实际端口、失败节点及可用动作，保留草稿。
- 详情提供复制入口、连接检查、启停/重连、编辑和删除；运行中删除动作明确标为“停止并删除”。内网代理另外提供浏览器和 curl 使用指南，固定转发提供“客户端直接连接”的说明。测试输入不写入代理固定目标。
- 空列表直接呈现两个用途说明及新建入口；加载、连接中、等待认证、就绪、重连、失败和停止均有文字，不只依赖颜色。按下即时反馈，耗时操作可取消，后台状态不抢焦点。
- 视图内容以900×600逻辑窗口为验证基线，宽度不足时详情改为列表下方；页面与长路径可滚动，表单底部动作始终可达。使用公共三主题、系统排版、焦点和菜单；Esc关闭编辑或返回详情，未保存草稿按公共对话框处理。200%缩放、键盘/IME、减少动态及高对比纳入 PF-05/NP-04。

### 3.2 共同运行与恢复建议

配置可保存，多条规则可同时运行；每条规则只允许一个有效运行，端口冲突提示占用地址。启用不改变浏览器/系统代理。关闭视图默认停止它管理的全部运行，删除配置是另外的动作；切换 Tab、移窗、隐藏、主窗口收起到托盘保持运行。本轮首版不增加关闭后托管入口，需要继续使用时保持视图存在或将主窗口收起；将来提供保留必须同时具备核心查看、定位和停止能力。

自动重连默认关闭，可在规则高级选项开启；关闭时 SSH 路径断开进入“连接中断”，保留本地端口直到停止或手动重连，新请求立即失败。开启时对可重试传输故障最多自动重试3次，间隔1/3/10秒，每次建立路径的时限沿用核心；需认证/信任确认或配置失效时停止自动尝试，显示“需要处理”。同次恢复使用原运行路径快照，不因后台修改配置悄悄换出口；主动“应用并重启”才采用新配置。成功后接受新的客户端连接，原 TCP 会话已断开，不能续传或重放旧请求。失败/重连期间 HTTP 返回适用的代理错误、SOCKS 返回失败；固定转发关闭新接入连接，不积压等待。

停止会取消重连，先结束监听再关闭本规则所有连接及租约；明确退出 App 停止全部规则。下次启动仅保留规则配置，不自动恢复运行。单目标拒绝/超时不触发整条规则重连，其他目标及规则继续工作。

## 5. 生命周期与兼容原则

- 一个运行绑定规则 ID、配置快照、完整路径、工作区/实例和连接代次；不能只按目标私有 IP 复用或定位。
- 各规则独立持有依赖租约，停止一条不误停另一条或终端/文件；核心原语变化保持既有消费者兼容。
- 隐藏、切换、移窗和收起到托盘保持运行；明确关闭视图默认结束其运行，额外保留需完整托管入口另行设计；真正退出 App 释放全部本机监听和通道。
- 端口冲突明确报错，不静默改端口；路径失败不改为直连、不自动替换出口；恢复后由客户端重新连接，不重放业务请求。
- 调用记录只留来源、资源、阶段、计数和必要诊断；不记录业务正文、Cookie、认证头或 SSH 秘密。
- 插件独立构建、更新重启生效；两个功能的普通业务修改应能随插件更新，公共 SSH 能力由核心更新。构建入口为 `node scripts/pack-plugin.mjs --plugin network-proxy`，独立包位于 `resources/network-proxy.sodeck-plugin`。

## 6. 验证与接续

各功能在各自规格维护 PF/NP 流程；公共能力在 F-CORE-015 维护 NT 流程。重点验证多跳实际可达性、固定目标与动态目标区别、相同私有 IP 不同网络隔离、两种模式并存、Windows/Linux 节点、资源清理及独立更新。使用隔离环境，不将用户例子地址当作可连接测试服务器。

本次完整方案包含两功能/界面、[公开API/资源/预算与NT-01～09](../../core/dynamic-proxy.md)、[代码模块/二进制流/独立更新/实际环境](../../technical/network-tunnel-implementation.md)。建议一个0.1.0独立插件包，最低API4.7及network能力；最多保存256规则，单实例最多同时运行16条，容量细则见代码方案§6/核心§9。网络物理池与终端/文件分开，复用核心路径和身份，超时不误关其他流。恢复时原路由修订已变化则等待明确应用并重启，避免悄悄换出口。方案已确认并实施，当前验证和交付以 T-014 结果为准。
