## 1. 本次边界

覆盖固定端口转发、HTTP/SOCKS监听、网络池与规则管理。完整性、签名状态、启用存储和加载门禁由核心负责；本插件不实现自己的启用开关、签名审批或核心管理页。启停完整重启生效，停用不执行任何插件代码、保留包与业务配置；原功能与资源归属不改。

核对文件：plugins/network-proxy/src/worker.ts、manager.ts、run.ts、view.tsx、manifest.json。预计不改业务实现、不提升manifest要求、不重编译现有有效包；用当前API6.1原包验证新核心兼容。如发现确有需要修复的生命周期缺陷，先记录落点及其属于已确认结果的依据，再改代码。新核心API6.2不意味着每个插件必须重编译。

## 2. 本插件测试流程

适用r1，关联公共AC-03/04/06/07。使用.qa/t028下的独立App数据与插件副本，已有隔离SSH/Linux环境；协议夹具与真实服务证据分别记录，不接触日常服务器。三项均在Windows原生宿主验证，必要计数用测试入口，不把UI按钮消失当成worker已停证据。

| 用例 | 准备与步骤 | 预期 |
| --- | --- | --- |
| PROXY-PM-01 | 隔离端口建立固定转发与HTTP/SOCKS代理，发起请求；取消启用应用后继续请求，再正常退出 | 应用不打断当次服务；退出释放监听和连接；重启后无隧道worker或监听 |
| PROXY-PM-02 | 停用状态给插件准备更新，重启两次检查端口与初始化计数 | 候选保持待启用；无试运行、无端口抢占、无后台重连；其他插件不受影响 |
| PROXY-PM-03 | 重新启用并重启，打开规则界面，由用户启动测试转发/代理 | 规则与配置保留；不擅自改变既有自动运行规则；HTTP/SOCKS和固定转发可用，停止后资源回收 |

共同清理：停止测试业务、关闭工作区并完整退出，核对本插件进程/核心租约/监听/订阅释放；恢复隔离副本启用状态，保留日志/版本/包哈希。不得通过清空用户配置模拟停用。实际结果统一写T-028实施记录，当前均未运行。
