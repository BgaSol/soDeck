## 1. 目标与范围

P-45 最新要求将本功能与[点对点端口转发](port-forward.md)一起插件化。本稿只维护 HTTP/SOCKS 内网代理，两个功能各有测试、共用路径和资源，替代旧稿将固定转发后置的范围。

用户希望通过 SSH 连接的 Windows 或 Linux 主机访问其所在网络中的多个服务，避免为每个服务创建一条固定端口转发。v1 已证明的用户能力是一个本地代理入口按请求选择目标；本功能沿用该能力，v2 重新设计插件视图和工作区承载。

本功能对应 v1 的 `NetworkProxy`（内网代理）。v1 的另一个模式 `PortForward`（固定端口转发）先在规则指定目标，再把一个本机端口直接映射到它；内网代理则由每次 HTTP/SOCKS5 请求指定目标。两者有共同的 SSH 传输，但产品功能和协议入口不同；核实依据见 [T-014 §1.1](../../../tasks/T-014-network-proxy.md#11-v1-两种模式的源码复核)。

用户具体流程：浏览器代理设为 `127.0.0.1:10808`，地址栏输入 `http://10.10.1.223` 或该服务实际使用的端口/HTTPS 地址；请求经过所选 SSH 主机，到达它所在局域网的目标。SSH 主机与网页服务可以不同；换访问其他内网地址不需要新建代理。仅代理入口在本机，不把目标解释为本机局域网的同一地址。

推荐通过 SSH 为每个目标建立 TCP 通道，由最终 SSH 节点访问目标；与固定转发共用多层路径，例 `本机 → A → B → 最终节点 C → 请求目标`。中间节点不应误作业务出口，最终服务不需要 SSH。多级路径已由 T-013 r2 实现，本功能复用核心任意有限、无循环的路径与实际运行资源预算，不另设固定业务跳数；插件公开 TCP 入口及协议运行载体仍需新增。

“局域网映射”指客户端经过此代理访问 C 可达的多个服务，不承诺网段全可达或为全部软件创建系统路由。范围建议 HTTP/1.1、HTTPS CONNECT 和 SOCKS5 CONNECT（TCP）；UDP/广播/ICMP 不自动包含。无需为每个目标配置固定映射。本次设计推荐在本机处理 HTTP/SOCKS 协议，通过核心 SSH 通道让远端建立目标连接，无需 curl 下载或启动额外远端代理程序；本机业务载体仍须在代码方案明确，不能因此把协议业务全部移入核心。

### 1.1 用户具体场景与连接位置

本机为 `10.100.77.166`，最终 SSH 主机为 `192.168.1.16`，网页服务位于该远端网络的 `192.168.1.18`。这些是需求示例，不能据此连接用户网络。

```text
本机浏览器：代理 127.0.0.1:10808；地址栏 http://192.168.1.18
  → 本机协议入口读取请求目标 192.168.1.18:80
  → SSH 路径（可直接到 .16，也可经多台跳板）
  → 192.168.1.16 上的 SSH 服务建立目标 TCP 连接
  → 远端局域网中的 192.168.1.18:80
```

监听端口及协议处理在本机，连接目标服务的 socket 在远端 `.16`；`.18` 通常看到 `.16` 或远端网络 NAT 的源地址，不能仅凭源 IP 断言路径。域名原样送入 SSH 目标通道，由最终节点解析；客户端提前解析为 IP 时只能使用其提交的 IP。若客户端把私网地址列入不走代理的例外，请求不会进入本插件，使用指南须明确这一点。

前置条件是本机能经配置路径建立到 `.16` 的 SSH 连接、各相关 SSH 服务允许所需 TCP 转发、`.16` 能访问 `.18` 的实际服务端口。临时性由插件启动/停止本地入口及 SSH 通道实现；没有常驻远端代理需要卸载。

## 2. 操作、界面与业务规则

### 2.1 创建与启动

1. 在服务器工作区打开“网络隧道”工具视图。
2. 新建时选择“内网代理”，最终 SSH 节点为所属服务器工作区；自动读取该服务器在核心保存的完整路径，并提供“编辑服务器连接”入口。插件不另存一串中转配置、不复制 SSH 凭据编辑；访问另一最终节点时在相应服务器工作区创建规则。
3. 输入名称；本地绑定默认为 `127.0.0.1`，建议默认端口 `10808`，用户可修改或显式选择自动分配。`10808` 来自用户示例，不是必须占用的端口。保存配置和启动运行是两个动作。
4. 提交后核心实际绑定 listener；端口冲突显示具体地址并保留用户输入，不静默换端口。
5. 就绪后显示一个可复制的本地地址，并注明同一端口支持 HTTP 代理、HTTPS `CONNECT` 和 SOCKS5 `CONNECT`。

新建入口可选择“端口转发”或“内网代理”，各自维护表单草稿。本模式不显示固定目标字段，测试目标只用于检查。保存后配置类型固定，要用另一功能则新建配置；不能原地改写正在运行的语义。规则列表、编辑与关闭行为见[插件总览 §3](../README.md#3-v2-界面方向)。视图关闭默认释放所属运行；隐藏、切换、移窗和托盘收起保持运行。

### 2.2 使用与测试

详情首屏显示：运行状态、本地地址、SSH 路径、活动连接、发送/接收、本次运行时长、使用指南和连接测试。

使用指南提供浏览器和命令行两个入口：

- HTTP：客户端代理填写 `http://127.0.0.1:<port>`，HTTP 与 HTTPS 均通过该入口，HTTPS 使用 `CONNECT`；
- 浏览器：分开的主机/端口字段填写 `127.0.0.1` 和实际端口，地址栏仍输入远端服务原地址；确保该目标没有被浏览器的“内网不使用代理”等例外绕过。此设置由用户完成，不能假称 SoDeck 已检测到浏览器配置；
- SOCKS5：支持的客户端填写 `socks5h://127.0.0.1:<port>`，让最终 SSH 节点解析域名；
- 命令行：根据示例 shell 生成 `curl.exe` 或 `curl` 命令，仅展示和复制，不自动执行；
- 停止后：客户端连接会失败，重新启动代理或恢复原代理设置；SoDeck 不修改系统或浏览器代理设置。

连接测试输入一个目标主机和端口，默认通过实际本地 listener 发起 HTTP `CONNECT`；可选 SOCKS5 测试。成功只表示代理握手和目标 TCP 通道成功，不推断网页、TLS 证书、登录或业务接口成功。测试结果绑定运行代次，停止、重连或编辑后过期结果不能覆盖新状态。

### 2.3 状态与失败

规则状态：`stopped / starting / ready / reconnecting / needs-attention / stopping / failed`。单个代理连接另有协商、连接中、已连接、失败和关闭状态。手动及有限自动重连、保留端口和取消行为见[插件总览 §3.2](../README.md#32-共同运行与恢复建议)，本功能与固定转发分别执行公共 NT-05。

远端目标拒绝、超时或 DNS 不可用只影响对应请求；SSH 路径断开才影响规则级状态。不能在失败后自动本机直连、重放 HTTP 请求或把最近失败目标写成规则固定目标。协议错误返回简短的 4xx/5xx 或 SOCKS5 错误码；诊断显示阶段和时间，不记录正文和秘密。

HTTP/1.1 正向代理必须正确处理绝对 URI、Host、消息边界、chunked、`100 Continue`、请求/响应流式传输、逐跳头和连接复用；普通 HTTP 支持 WebSocket Upgrade 与 SSE，CONNECT 成功后透明传输客户端协议，HTTPS 不解密。SOCKS5 首期只支持无认证 `CONNECT`，拒绝 BIND、UDP ASSOCIATE 和不支持的认证方法。普通 HTTP、CONNECT 或 SOCKS5 成功回复不得早于远端通道打开。

## 3. 接口、状态与数据

采用[代码方案r1](../../../technical/network-tunnel-implementation.md)的QuickJS插件协议与[核心r6公开网络契约](../../../core/dynamic-proxy.md#8-公开契约与资源归属r6)，不采用旧proxy.*专用核心业务API。核心提供资源组/listener/目标TCP/ByteSession/splice；协议及规则随插件包更新。以下操作为插件业务命令含义，底层仅调用公开原语。

| 操作语义（非已存在 API） | 用途 | 结果要点 |
| --- | --- | --- |
| 启动 | 建立本地入口和代理运行 | 运行 ID、实际绑定、协议、状态与完整路径快照 |
| 观察 | 查看/订阅运行与连接状态 | 状态、计数、流量、诊断摘要、代次 |
| 检查 | 经实际本地代理入口验证目标 | 测试 ID、协议、目标、阶段、时间和结果 |
| 停止 | 幂等停止运行并释放依赖 | 清理结果及必要诊断 |

核心持有 listener、SSH 连接、TCP 通道、配额、取消和租约；插件拥有代理业务/规则、配置草稿、指南、测试输入、视图和诊断含义。所有调用经核心记录来源及有效资源代次，不直接持有底层 SSH session 或互调其他插件。

持久数据保存规则id/revision、名称、服务器ID、类型、绑定/重连偏好和schema版本；不保存旧运行句柄、代理连接、请求历史或业务内容。详细模型、并发保存和上限见代码方案§6。保存失败不能改变正在运行的实例；启动失败不能伪装成配置保存失败。

### 3.1 本次代码与协议约束

HTTP/SOCKS运行在插件worker；CONNECT/SOCKS成功握手后通过核心splice传输，普通HTTP解析/逐跳头/消息边界留在插件，通过有额度二进制ByteSession传正文。HTTP保持下游keep-alive和请求顺序，每个普通请求独立上游通道，响应结束释放，避免跨目标复用错误。100 Continue/提前响应与请求体并行处理，正确区分HEAD/204/304、chunked/trailer及close-delimited；收到101后才升级为透明流。预算、解析限制、兼容和错误映射见代码方案§3/5及核心§9，不能用一次性读全响应或无界字符串实现。

网络数据池与终端/文件物理会话分开，使用同一核心身份/路径能力。单目标open超时会隔离待清理成员，其他有效流继续，新请求可使用健康成员；资源耗尽明确失败。路由修改后现有流保持快照，恢复需要原修订仍有效，否则进入“需要处理”，不自动切换新配置。检查经实际listener完成CONNECT/SOCKS握手，仅证明目标TCP连接。

## 4. 验收标准

- AC-01：在 Windows 客户端连接 Windows OpenSSH 服务器时，创建代理并配置 `curl.exe`，应通过远端可达的 HTTP 服务；停止后该地址不可用。
- AC-02：在 Windows 客户端连接 Linux OpenSSH 服务器时，HTTP、HTTPS `CONNECT` 和 SOCKS5 `CONNECT` 均能通过同一个本地端口，远端域名由最终 SSH 节点解析。
- AC-03：通过多个 SSH 节点时，代理使用完整路径访问仅最后节点可达的目标；各跳和目标失败显示正确阶段；直连和原单跳兼容。
- AC-04：一个目标超时或拒绝连接时，其他已建立连接继续工作；规则保持就绪，诊断只标记失败目标。
- AC-05：端口冲突、认证失败、转发被拒及创建取消不遗留半成品资源；断线恢复期间按插件总览保留本地端口并关闭失效 TCP 会话；明确停止、视图关闭和 App 退出释放 listener、通道与本规则租约，不遗留远端代理进程。
- AC-06：用户无需修改系统代理或打开终端即可完成创建、复制地址、查看指南、测试和停止；界面符合 v2 工作台、主题、键盘焦点、减少动态效果和高对比度要求。
- AC-07：插件更新后需重启 App 才生效；坏包或能力缺失只使代理插件不可用，不影响核心、终端和文件插件。
- AC-08：浏览器配置示例代理 `127.0.0.1:10808` 后访问远端内网目标，由所选 SSH 主机建立连接；可继续访问另一内网目标，无需新增配置。必须验证 §1.1 的 `.16 → .18` 等价隔离拓扑，本机存在同地址网络时仍命中远端服务；发送至代理的请求在断线时不能退回本机直连。

## 5. 本功能的测试流程

适用规格修订：r6。使用隔离 Windows/Linux OpenSSH 主机、HTTP/HTTPS/WebSocket/SSE 测试服务及独立凭据；不读取或修改用户业务服务器。真实平台结果与模拟/契约结果分开记录，拟建入口和环境见代码方案§9。以下均为待实施流程，不是已存在脚本或通过记录。

### NP-01：直连 HTTP 与 HTTPS

关联验收项：AC-01、AC-02  
准备条件：隔离 SSH 主机和远端可达的 HTTP、TLS 服务；本机无冲突代理端口。  
操作步骤：创建并启动代理；用 `curl` 经 HTTP 代理访问 HTTP 服务；经 HTTP `CONNECT` 访问 HTTPS 和非标准端口。  
预期结果：请求、响应、流式内容和 TLS 证书验证符合客户端预期；SoDeck 不解密 TLS。  
清理及恢复：停止代理，确认 listener、SSH 通道和测试服务连接均关闭。  
验证方式：自动化与真实操作结合。

### NP-02：SOCKS5 与远端 DNS

关联验收项：AC-02  
准备条件：仅隔离 SSH 主机能解析/访问的测试域名。  
操作步骤：经 `socks5h://` 访问目标；另测客户端传入 IP 的情况。  
预期结果：域名请求由最终 SSH 节点解析；不发生本机直连或隐式本机 DNS；不支持的方法明确失败。  
清理及恢复：关闭客户端连接并停止代理。  
验证方式：自动化与真实操作结合。

### NP-03：跳板、并发和单目标失败

关联验收项：AC-03、AC-04  
准备条件：本机只能访问 SSH A，A 可访问 SSH B，B 可访问 SSH C，仅 C 可访问目标服务；并准备一个拒绝或延迟目标。  
操作步骤：通过跳板启动代理；并行建立成功目标、失败目标和长连接；停止或恢复路径。  
预期结果：路径阶段、错误和活动连接正确；失败目标不结束其他连接；重连后客户端重新建立请求。  
清理及恢复：停止代理，核对所有本机/SSH/目标资源归零。  
验证方式：真实隔离集成。

### NP-04：界面、配置和生命周期

关联验收项：AC-05、AC-06、AC-07  
准备条件：工作区、多个代理配置、主题切换和插件包版本。  
操作步骤：创建、保存、启动、复制地址、展开指南、测试、编辑、关闭视图、重启 App、替换插件包；在900×600、200%缩放及三主题下验证列表/详情、两模式草稿、长路径、等待认证和端口冲突。  
预期结果：草稿不被状态流覆盖；保存与启动结果分离，运行快照与下次启动配置清晰；焦点、键盘/IME、主题和减少动态效果正确，底部操作可达；代理详情无固定目标字段；关闭默认停止所有所属规则，隐藏/移窗/托盘继续，坏包不拖垮其他插件。  
清理及恢复：删除测试配置，停止运行，恢复插件包和隔离数据。  
验证方式：UI、原生桌面与更新验证。

### NP-05：浏览器访问远端局域网的多个目标

关联验收项：AC-08  
准备条件：隔离网络内的 SSH 主机 A 可访问两台有独特响应标记的网页服务器 B/C，客户端无法直接访问；测试浏览器使用独立配置，并明确把测试地址发送到代理。用等价隔离拓扑重现 §1.1 的本机、`.16` 与 `.18` 角色，不探测用户网络；在隔离客户端网络构造同地址的不同标记服务。  
操作步骤：启动代理，浏览器设为 `127.0.0.1:10808`（该测试端口须空闲）；访问 B 再访问 C；核对 B/C 的响应及连接来源；再以同地址隔离网络验证目标归属；最后断开 SSH 并重复请求。  
预期结果：两次均访问远端正确服务，通过 A 上的连接记录和服务端独特响应确认目标连接由 A 发起，一份代理配置服务多个目标，配置中没有预设 B/C 固定目标；不能用两条固定端口转发冒充此用例通过。同地址时仍命中远端标记；断线后请求失败且本机服务没有收到请求。对比启动前后远端进程/临时文件，确认没有部署 HTTP/SOCKS helper。代理 bypass 设置错误与代理本身失败分开记录。  
清理及恢复：移除测试浏览器代理配置，停止 listener、测试网页服务和隔离网络，核对无残留端口。  
验证方式：真实浏览器与隔离网络，Windows/Linux SSH 主机分别执行；当前未运行。
