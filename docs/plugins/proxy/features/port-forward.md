## 1. 目的、明确要求与推荐范围

用户明确需要以插件方式实现点对点端口转发，允许跨多机器。推断目的：从本机使用处于多层网络后面的某个确定服务，例如数据库、SSH、RDP 或 Web 服务，无需手动在每台中转机启动转发命令。

用户已明确“经过多台 SSH 主机中转，入口在本机”。据此以“本机监听入口，经一条有序 SSH 路径，到达一个固定 TCP 服务”整理。例子仅说明行为，不访问这些地址：

```text
本地数据库客户端 → 127.0.0.1:13306
  → SSH 中转 A → SSH 中转 B → 最终 SSH 节点 C
  → C 可达的 10.10.1.223:3306
```

一条规则固定一个目标地址和端口，可以服务多条并发连接；不是只允许一个 TCP 会话。目标服务可以就在 C 上，也可以位于另一台不具备 SSH 的机器 D。客户端直接连接本地入口，无需支持 HTTP/SOCKS 代理。双向字节传输属于同一连接，不代表已经提供远端监听或反向转发。

本次不提供在远端 A 绑定监听入口的方向。复用已实现的 F-CORE-014 / T-013 r2：每台服务器引用一个前驱，核心展开任意有限无循环路径；不添加固定业务跳数，运行仍受核心实际资源预算约束。核心路径与本插件端口转发均已实现，测试层级见 T-014 结果。

## 2. 配置与操作需求

| 配置项 | 需求 |
| --- | --- |
| 名称与用途 | 明确为“端口转发”，与内网代理配置分型保存 |
| 入口 | 本机监听地址/端口，推荐默认回环；固定端口可指定，自动端口由用户显式选择 |
| 访问路径 | 最终节点为所属服务器工作区，读取其已保存核心路径并有序显示；通过“编辑服务器连接”修改路径，插件不保存第二份中转列表，凭据由核心管理 |
| 目标服务 | 从最后一个 SSH 节点看见的主机/IP 和端口，例 `10.10.1.223:3306` |
| 恢复偏好 | 手动重连始终可用；自动重连默认关闭，启用后的规则见插件总览，不重放业务字节 |

流程：选择工作区 → 新建端口转发 → 配置入口、路径和固定目标 → 保存或保存并启动 → 复制实际绑定的访问地址 → 使用 → 停止。

主机名由最终节点解析；中间节点地址由它的前一跳访问。目标填 `127.0.0.1` 表示最后一个 SSH 节点自身。每跳具有自己的主机指纹与认证；不得把最终目标凭据复制到中转机。禁止环形路径，不默默跳过失效中转或改为直连。

地址冲突时保留用户端口并报错，禁止静默换端口。SSH 路径就绪与目标服务已实际连接分开显示；提供经过实际本地入口的 TCP 检查，不以成功绑定端口宣称数据库/网页已正常。普通 TCP listener 可在目标服务暂不可用时继续等待后续连接，目标失败与路径失败分别诊断。

规则运行时保留实际配置快照；编辑默认下次启动生效，明确重启才应用到新运行。重复启动不得创建第二个 listener。停止先拒绝新连接，再回收已有连接和属于本规则的路径租约，不中断其他规则、终端和文件。手动及有限自动重连、保留端口和取消行为见[插件总览 §3.2](../README.md#32-共同运行与恢复建议)，本功能与内网代理分别执行公共 NT-05。

## 3. 展示、插件及核心边界

沿用[插件总览](../README.md)中的新 v2 视图方向与 apple-design 原则。固定转发详情突出“本地入口 → 中转路径 → 固定目标”，显示状态、活动连接、流量、检查与停止。不能把本地入口标为 HTTP 代理地址；只有规则有明确 Web 使用意图时才考虑“打开网页”，数据库等不提供误导按钮。

插件负责规则、表单、列表、路径展示和诊断解释；核心提供服务器/认证、路径、TCP listener/通道、连接租约、流控与资源清理。[代码方案r1](../../../technical/network-tunnel-implementation.md)和[核心r6](../../../core/dynamic-proxy.md)定义已实现的公开net.*接口。运行创建资源组/暂停listener/网络路由，再开启accept；每个接入流按固定目标打开direct-tcpip后交给核心splice。业务字节不经过UI/JSON，不借终端PTY。

网络池与终端/文件物理会话分开，同路径两种规则可共享池并持有独立租约。目标open超时隔离待清理成员、保留其他有效流；预算/半关闭/帧交接与NT-06～09共同适用。运行中改路由不改变已有连接，需重连且原修订已变化时等待明确应用并重启。

固定转发检查通过net.listeners.connectSelf进入真实listener，用probeId关联实际accept和目标open成功；仅本机connect返回不能认定远端服务连通，不发送应用业务内容。

配置与运行分开，运行不跨 App 重启恢复。隐藏、切换、托盘收起不停止；视图明确关闭默认停止所属运行，移窗保留同一逻辑运行。本轮不增加关闭后托管入口，继续运行时保持视图或收起到托盘，具体交互见插件总览 §3；未来显式保留需完整核心托管能力。

## 4. 验收要求

- PF-AC-01：本机使用入口端口即可访问固定目标，普通 TCP 客户端无需代理设置，内容透明往返。
- PF-AC-02：在“本机 → A → B → C → 服务”隔离拓扑中，只有相邻节点可达仍能成功；C 的本机服务和 C 可达的另一台服务机均覆盖。
- PF-AC-03：两条规则可使用不同路径访问两个网络里的同一个私有 IP，返回正确标记；不串路、不本机直连。
- PF-AC-04：端口冲突、节点认证失败、转发拒绝、目标拒绝、超时、取消和断线能够区分；停止/退出后端口和资源实际释放。
- PF-AC-05：多规则与内网代理、终端/文件并存，停止一条只释放自己的使用权；配置保存不意味着自动启动。
