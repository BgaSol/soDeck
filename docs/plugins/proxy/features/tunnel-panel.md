# F-PROXY-003：网络隧道侧栏与简化创建

文档就绪：可评审 · 修订：r4 · 日期：2026-10-27
所属：[网络隧道插件](../README.md) · 任务：[T-015](../../../tasks/T-015-workflow-polish.md)  
本节替代 T-014 UI 中默认中央页、名称必填、代理默认 10808；[端口转发](port-forward.md)与[内网代理](network-proxy.md)的协议、路径、预算及生命周期继续适用。

## 1. 入口与列表

T-017 r2视觉返修已获用户直接实施授权：以文件面板为样式基准，宿主保留唯一“网络隧道”标题，插件工具行放“名称”与创建。工作面、全宽连续行的hover/选中轮廓、实底有边界的底栏与文件共用公共规则；移除r1的图标底色、逐条淡分隔及透明状态栏。底栏左侧数量/运行状态，右侧版本，详情按需展开。业务语义不变，专属测试见[T-017 R2-01～04](../../../tasks/T-017-identity-tunnel-ui.md)。

每服务器一个逻辑管理视图。右侧工具轨显示“网络隧道”图标及悬停文字，默认收起；按下即时反馈，点击展开/收起对应右侧面板，键盘 Enter/Space 等价，辅助技术可读展开状态。初次查看只读取配置，不自动启动规则。

默认宽 360px、最小 320px，采用工作台已有拖动/键盘调宽能力；宽度受窗口和中央最小内容区限制。与左侧文件可并存；宽度不足时临时收起另一侧工具，恢复由用户控制，不写成永久偏好。标题“网络隧道 · 服务器名”，创建按钮固定，规则列表独立可滚动，底部无多段技术说明挤占空间。

每行显示自动/手填标题、用途、运行状态、本机实际入口；固定转发再显示目标。主要动作只留启动/停止、就绪时复制入口；行点击进入侧栏内详情，顶部返回列表并恢复滚动位置。详情容纳连接检查、用法、路径、连接数/流量、编辑、删除和错误诊断。已停止的自动端口规则显示“启动后分配”，不能把上次端口伪装为可用。

列表加载、空态和失败可辨；空态只有短用途提示和一个创建入口。沿用既有有界分页，创建新规则后定位其所在页，不能选中不可见的规则。轮询/状态更新不抢焦点、不覆盖编辑草稿；只在用户动作时切详情。

## 2. 创建与编辑

1. 标题“创建网络隧道”；先选“内网代理 / 端口转发”，默认内网代理。副标题明确当前服务器，路径可展开查看；创建中不能改成另一台服务器。
2. 内网代理默认只需确认用途即可创建；端口转发必须填目标主机和端口，两项同排。回环监听地址 `127.0.0.1` 为说明，不增加可编辑地址项。
3. 名称可选，留空以“内网代理”或“转发至 主机:端口”生成稳定显示名；可手动命名。同名允许，以入口/目标区分，内部仍使用规则 ID。手填去首尾空白、最多 128 字符，控制字符拒绝。名称策略在插件业务层归一化，不能只移除表单 required 而被 worker 拒绝。
4. 两模式默认勾选自动分配端口；取消勾选才显示手动端口，范围 1～65535，空值不可提交。提示“启动后显示实际端口，重新启动可能变化”。分配通过核心实际绑定完成；失败/冲突显示原因，手动端口不静默改成其他端口。
5. “更多设置”收起自动重连（默认关闭，最多 3 次，沿用 T-014）。常用必填字段不隐藏。两模式切换保留各自草稿，不把转发目标带入代理配置。
6. 创建底部为“取消”“仅保存”“创建并启动”（主动作）。未修改的默认代理表单可直接提交；成功返回列表并突出新规则，就绪后才开放复制。保存成功但启动失败时保留该规则并在原行显示重试，不再创建一条。
7. 编辑运行中的规则继续区分“保存，下次启动生效”与“应用并重启”；后者在操作前明确会断开该规则当前连接。删除运行规则使用“停止并删除”，单次确认，不连带其他规则。忙态防重复，认证/连接中有取消；字段校验失败保留草稿。脏草稿取消时确认放弃；Esc 不进入远端终端。

既有规则的名称/固定端口原样保留；缺少新名称策略标记的旧规则视为手填名。自动名可在新规则保存时生成并记录策略，后续修改目标同步自动标题；不将实际临时端口写成规则固定端口。迁移验证独立存储副本和插件回退，旧 worker 不能被直接喂入其不接受的空名称。

## 3. 承载、恢复和资源

工作台负责按钮所在边、容器、调宽、焦点和原生窗口承载；插件负责列表/表单及业务。增加右停靠声明，默认 right；保留 tab/window 显式移动能力，取消 Tab 工具栏的常驻网络入口，避免重复导航。旧规则配置不改，跨重启工作现场仍不恢复。

侧栏“收起”只隐藏，维持运行资源；切服务器、移窗及托盘同样保持。当前服务器按钮以运行数量/异常标记提示后台规则，不把消息变成自动弹窗。明确关闭逻辑视图、关闭所属工作区或退出 App 按已有规则停止；无隐藏后台进程或新的托管机制。

每个工作区的列表、详情、草稿与运行属于原服务器/视图，切换后迟到结果不能作用于新服务器；同次运行隐藏面板保留浏览位置。返回后先获取当前状态，不使用旧快照冒充运行中。插件崩溃/更新仍由现有核心清理兜底。

表单必须完整出现在所属窗口可见范围，不能被限制在320px插件侧栏或压到终端下层。[代码方案r1 §5](../../../technical/workflow-polish-implementation.md)已选定ui.dialog.v1临时原生模态表面，表单/提交留在插件，宿主管容器/焦点/屏障；不新增逻辑视图、worker或业务资源。关闭/来源换代/窗口销毁必须回收；核心认证可暂时挂起表单，恢复时校验原来源，不重建终端。侧栏本身仍在工作台内，这个原生承载仅用于模态表单。

侧栏几何变化通过原生布局同步；不对插件 WebView 祖先施加 transform/filter。能保证原生内容与命中同步时采用短而可中断的展开反馈，否则即时几何切换加内容淡入；减少动态直接切换。收起后焦点回入口，鼠标操作终端不被侧栏抢走。

## 4. 功能测试流程

准备：Windows 主/工作区子窗口，三主题、缩放和窄窗；独立规则数据库及旧插件包；隔离 Linux/Windows SSH、A/B/C 多跳及受控 TCP/HTTP 服务，禁止使用用户示例地址。浏览器、原生和真实网络结果分开，证据与限制统一归 T-015。

| 编号 / 验收项 | 步骤 | 预期 |
