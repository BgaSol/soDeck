## 1. 监控应有的行为

面板继续绑定最终SSH服务器T的工作区，只采集T的CPU/内存/磁盘/网络。A/B/P只是访问过程，不成为新的采集对象；P不需要SSH登录。自动打开面板只观察已有目标连接，显式“连接并监控”才发起整链。

路线或connection generation改变时结束旧采集，旧样本不得拼入新连接速率差分；新连接首个计数样本重新建立基准。保留原采集间隔、历史长度、Linux支持范围及单worker调度，不扩展为整条链的多机器监控。

## 2. 代码修改

| 文件 | 计划 |
| --- | --- |
| `plugins/monitor/src/connection.ts` | 使用API6 RouteStatus类型和核心timeout预算；verify检查connectionId/generation/routeRevision。保留显式acquire与只观察acquireExisting分离，以及未知结果后核对/释放的所有者锁，不能因新认证结果提前释放锁造成重复链。 |
| `plugins/monitor/src/view-client.ts` | monitor.connect命令读取新预算；拒绝旧能力/坏DTO，不回落固定超时。迟到连接状态不抢另一工作区面板。 |
| `plugins/monitor/src/controller.ts`、`model.ts`/`validation.ts`相关状态分支 | 统一认证错误分类，preset确认进入可继续认证态；取消/断线清楚反馈。以已有连接代次机制触发采集基准重置，缺口可见；实际逻辑已覆盖时保持并补有意义用例。 |
| `plugins/monitor/src/scheduler.ts`、`metrics/counters.ts`及连接交接点 | 核对旧采样在途取消、迟到丢弃和新连接首点不算速率，避免上游断链后的旧样本“补回”。不改CPU/内存等公式。 |
| `plugins/monitor/src/connection.test.ts`、`scheduler.test.ts`及原生monitor-routes用例 | API6 typed fixture，旧generation/未知acquire、认证确认/取消、混合链新旧样本隔离。 |
| manifest/package及包锁 | SDK6、`pluginApi:^6.0.0`、`connections.route.v2`；候选版本0.2.0，保留独立插件。 |

`collectors/linux.ts`、采集脚本、图表和Linux/BusyBox解析不因路径类型变更；重点验证它们拿到的是T的lease。插件不订阅核心每跳密码、不新增代理管理或路径编辑UI。

## 3. 插件专属测试

适用r1，对应MR-AC-01/03/04/05。使用隔离混合拓扑，A/B/T具不同主机标识与可核对资源状态；真实Linux目标和Windows原生面板，模拟时钟/迟到样本单独验证。

| 用例 | 步骤 | 预期 |
| --- | --- | --- |
| MON-MR-01 被动观察 | 无终端/连接时打开监控面板，再通过终端连T；观察自动接入 | 最初不发起整链或提示密码；目标连接可用后使用已有lease，采集只发生在T |
| MON-MR-02 显式连接 | 点击连接并监控，经历A/B/P/T认证及preset确认，取消其中一步后重试 | 状态准确、宿主统一认证、不新建终端，取消结果核对与lease清理完成；最终只采集T |
| MON-MR-03 断线与迟到 | 采样中断B/停止P，延迟旧结果；改路线后同serverId重连，再放行旧结果 | 图上出现缺口，旧generation样本丢弃；新速率首点为待基准而非巨大峰值；不切到A/B监控 |
| MON-MR-04 生命周期/包 | 监控移窗、托盘、同时保留终端，关监控；核心预算内慢链；API6环境单插件更新A→B重启 | 采集租约不误关终端、无多计时器/迟到复活；新预算有效，只有监控包hash变化 |

清理采样任务、lease、面板及测试凭据/数据；恢复系统主题/缩放。此专项不是T-024已停止的大规模压力测试，不把此前未完成长测写成通过。

## 2026-10-29 验收修订计划（已实施）

继续只获取既有连接；确认期间不主动另弹认证，完成后按正确连接代次恢复一次采样。补与终端/文件并存时的重复状态通知测试，独立构建验证公共 UI，插件不读取认证秘密。

来源：[整体修订 r2](../../../design/connection-editor-refinement.md)，对应 REF-01/04～08；与下方诊断增量合并评审。包版本核对在途版本后递增，不能只更新宿主而宣称本插件完成。具体方案已获确认并实施，结果由T-027 r9及实施记录维护，原r2交付记录保留。

## 逐步诊断增量（r4，已实施）

公共行为见[诊断方案 r1](../../../technical/connection-diagnostics.md)。`connection.ts` 的被动观察补充诊断摘要/引用，`controller.ts`、`model.ts`/`validation.ts` 和 `view.tsx` 区分未发起、正在连接、等待确认、上次失败及已取消，避免目标已失败仍只显示“等待已有连接”。被动信息带来源/时间，显式操作只关联自己的 attempt；已有 lease/采样优先，不借网络隧道池或无关终端失败覆盖成功采样。通过公开宿主入口查看详情，不拨号、不触发密码、不采集中转。声明所需新能力并更新独立包，采集脚本和公式保持。

准备：隔离混合路径、真实 Linux 目标、终端+文件+监控同工作区，错误 SOCKS/迟到样本夹具，沿用 MON-MR；具体执行证据见T-027结果。

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| MON-DIAG-01 | 被动监控观察终端从未连接→等待身份确认→代理失败；点查看详情 | 状态和失败站点可解释，非永远等待；没有新建连接/挑战/采样请求，来源指向终端实际尝试。 |
| MON-DIAG-02 | 显式连接失败后重试成功，期间另一个终端或网络池失败；放行旧采样/旧诊断通知 | 当前操作引用准确；已有采样不被其他用途错误覆盖，旧结果丢弃，新连接首速率点待基准。 |
| MON-DIAG-03 | SSH 成功但远端不支持采集/采集超时；关闭、移窗与单包更新 | 采集错误不改写建连成功，无第二套确认或重复计时器；三主题详情/焦点正常，独立包验证且其他包不变。 |

停止采样/观察、释放 lease 并关闭测试工作区，恢复显示设置；结果写 T-027-results。不恢复 T-024 已暂停的大规模压力长测。

插件 0.3.0 已独立构建和打包，使用SDK6.1/UI1.8，声明公共诊断与统一确认能力。被动只list诊断而不拨号；显式连接失败保留自己的引用，快照校验/去重，已有采样不被无关用途错误覆盖。 本插件定向状态/worker测试、真实混合链原生流程和独立单包更新均有本轮证据，统一见 [T-027结果](../../../tasks/T-027-results.md)。测试候选包只用于隔离更新验证，交付仍使用本段版本；用户验收和发布未发生。
