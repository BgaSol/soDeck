## 1. 意图与范围

用户说“看到当前tab页连接远端服务器的资源占用情况”。明确要求是新增插件、以当前Tab关联的远端为对象、先做理解和设计。

已确认的解释：Tab指顶部服务器工作区；用户希望边使用终端边观察机器状态，省去反复运行top/free/df等命令，并能看出刚执行的操作是否引起资源变化。不是只统计某个终端会话的消耗。

首版包括四类资源、机器基本信息、最近10分钟趋势、暂停/继续、刷新频率和局部失败状态。推荐Windows客户端与Linux远端；OpenWrt/BusyBox按探测到的内核文件/工具提供子集。其他远端OS显示明确未支持，不显示全零。远端处于容器/受限命名空间时标为“当前SSH可见环境”，不得宣称一定覆盖物理宿主机或已经按cgroup配额归一化。

不纳入本期：进程结束/重启服务、进程排行、GPU/容器视图、后台长期监控、跨启动历史、告警/通知、导出、安装Agent和自动sudo。进程排行可作为下一项独立功能，只读还是允许管理须另定范围。

## 2. 目标绑定与入口

1. 每个服务器工作区拥有自己的 `monitor.resources` 视图和数据；重复打开定位已有视图。插件仅绑定核心提供的serverId、workspaceId、工作区创建代次和连接代次，不用一个全局activeServer替换旧模型。
2. 切换顶部服务器Tab，呈现相应工作区的监控；同一服务器内切换终端Tab，仍观察同一服务器。终端内手动执行ssh、docker exec或进入另一命名空间不会改变监控目标，标题始终写明档案名称和“SSH目标环境”。
3. 经SSH跳板连接时只采集最终目标，SOCKS5代理本身不是监控对象。需要看跳板资源时应打开其自己的服务器工作区。
4. 视图默认右侧，与终端并排。支持移到中央Tab或弹出独立窗口，最小尺寸及默认打开规则见插件总览；不同窗口独立选择当前服务器，弹出的监控固定原服务器。
5. 收起不等同关闭；进入后台/收起停止后续采样并释放本插件临时I/O及租约，保留有界内存快照。重新显示只复用仍存在的有效核心连接；没有则显示“等待连接”。不让自动监控重新触发已取消的认证。明确“连接并监控”可调用核心连接流程，认证和指纹仍由核心处理。

## 3. 指标与计算口径

| 区域 | 首版显示 | 口径与边界 |
| --- | --- | --- |
| CPU | 总使用率、逻辑CPU数、1/5/15分钟负载；可展开iowait说明 | `/proc/stat`相邻有效计数差，整机归一到0～100%；busy排除idle与iowait，后者单列；guest已包含在user/nice，不重复加总。负载是队列压力指标，不写成百分比 |
| 内存 | 已用/总量、使用率、可用量；Swap已用/总量 | 首选 `MemTotal - MemAvailable`；缺MemAvailable时，可用量估算为 `MemFree + Buffers + Cached + SReclaimable - Shmem`，缺可选字段按0且标估算，估算范围限定到0～MemTotal；缺MemTotal/MemFree则不可用。没有Swap显示“未配置Swap”，不视为错误 |
| 磁盘容量 | 挂载路径、已用/总量、当前账号可用空间和占用率；概览默认根文件系统 | 区分文件系统容量和块设备；不累计所有挂载点为“整机总容量”。使用 `used / (used + available)` 的可用容量占用口径，分母为0时不可用；总量仍单独显示文件系统总量并解释保留块差异。公共容量组件接收相同分母，不从显示舍入值倒算；重复/bind挂载标明共享来源。默认隐藏proc/sysfs等伪文件系统，tmpfs单独标明内存文件系统 |
| 磁盘I/O | 按块设备列读/写B/s及短期趋势 | `/proc/diskstats`计数差与采样间隔；分区、dm和底层设备分层，不无条件求和；显示设备名，未可靠对应文件系统时不暗示“根目录写入速度”。没有块设备信息仅容量可用 |
| 网络 | 按网卡列接收/发送B/s；选中网卡趋势 | `/proc/net/dev`的远端视角RX/TX，含所有程序流量。默认隐藏loopback，可展开虚拟接口；桥/veth/隧道可能重复观察同一流量，不把所有接口相加成整机带宽。网卡速率未知时只显示B/s，不虚构带宽占用率 |
| 概况 | 系统/内核、主机名、在线时长、最后成功更新时间 | 系统信息低频采集；无权限/缺字段单独降级，不从用户自定义服务器名推断OS。远端uptime减少或boot身份变化触发采样基线重建 |

CPU、磁盘I/O和网卡速率需要两次同代有效样本。首个样本显示“计算中”；重连、重启、接口/设备身份变化、计数回退或间隔无效时重建基线，不产生负值或尖峰。使用单调时间；若具备可靠远端uptime则优先作差值时间依据，否则用本机单调采样间隔并标记高延迟样本。墙上时间仅用于显示更新时间，不参与速率分母。

容量/计数使用无损整数传递和计算；显示使用KiB/MiB/GiB和B/s，百分比1位小数，详细值可查看。无效数据不能夹成“合理”数值；缺失、截断和真实0分别表达。采样是近似同时的快照，不声称跨所有指标严格原子一致。

## 4. 界面与操作

顶部固定服务器名称、连接/采集状态和更新时间。正文从上到下为CPU、内存、磁盘、网络四组概览；每组显示主要数值及小趋势，点击后在同一视图展开明细。磁盘概览容量默认 `/`，未识别则显示“选择文件系统”；I/O和网络趋势分别选择一个块设备/网卡，多个候选时不擅自合计，首次要求选择或展示逐项列表。

工具栏提供暂停/继续、手动刷新和2/5/10秒刷新选项（默认2秒）。CPU/内存/速率按选定周期，容量至少间隔30秒、机器静态信息至少60秒；容量优先根/选中项和展开明细中最多8个可见挂载，不提前查询全部挂载。手动刷新合并在途请求，不创建并行重复轮次，仍受慢容量节流/失败退避约束并提示下次可采时间。暂停冻结当前数据并明确标记时间；暂停中“刷新一次”更新后仍保持暂停，需要两点但没有有效基线的速率仍显示“计算中”。改变刷新频率重建速率基线，避免混用采样口径。

趋势默认最近1分钟，可选5/10分钟；只包含本次逻辑视图存在期间实际采集到的数据。暂停、不可见、断线和异常处显示空档，不插补零、不跨断点连线。时间窗按真实时间滚动，内存保留最多10分钟；隐藏过久后旧点自然过期。首次打开不伪造历史，关闭或App退出清空曲线。

右面板窄布局为纵向分组，中央/独立窗口宽布局可形成两列；文字放大后退回单列，不挤压标签。明细表头固定、长路径可滚动查看，刷新保留滚动位置、选择与焦点。网卡/挂载/设备消失时原选择标为不可用，不静默换成另一个对象。

apple-design落点：

- 层次与排版：先给核心数值，再给趋势/明细；系统字体、等宽数字、固定数值列宽，避免每次刷新抖动。使用公开`@sodeck/ui`及主题令牌，适配浅/深/多巴胺。
- 即时反馈与可中断：按下立即反馈，切Tab立即显示目标身份和缓存状态；采集期间仍可收起、暂停或切页，不用全屏遮罩，也不自动抢焦点。
- 克制与可访问性：周期采样不做数字滚动动画、不持续弹跳；曲线有文字数值/时间替代，键盘可进入明细；不每2秒向屏幕阅读器播报全部数据。减少动态关闭空间动画，高对比不只依赖色线。
- 容量等级：内存/磁盘容量复用公共容量组件及等级来源，颜色统一来自主题；不在插件重定义阈值。CPU高占用和网卡高流量本身不是故障，首版只展示数值/趋势，不自动发告警。

## 5. 采集、资源与状态

采集解析和调度由插件worker承担；通过核心独立非PTY通道读取固定系统信息，必要时使用有界远端文件读取。优先内核数据和系统自带基础工具，避免依赖top输出格式、Python、sysstat或常驻Agent。命令为有限只读操作，不写用户终端、不修改远端文件、不安装服务。

快指标与慢容量查询分开限流，慢/失效挂载不能阻塞CPU与内存。默认不主动轮询网络文件系统容量，用户展开后可显式读取并受超时限制。每类最多一轮在途；未完成则跳过周期，不排出无限任务队列。输出截断只将受影响指标标为不完整，不接受截断的部分字段为完整成功。

确定缺少的能力在当前连接代次内缓存，用户重试或新连接才重新探测；瞬时采集失败按5/10/30秒上限退避，成功后回到所选周期。新一轮只读采样须先结束/核对上一轮操作，不把响应丢失当作自动重复执行的理由。其他成功指标维持其刷新，不因单项失败一起退避。

| 状态 | 用户可见结果与恢复 |
| --- | --- |
| 未连接/等待认证 | 不显示伪造数值；等待已有核心连接或明确连接操作；认证取消后不循环弹窗 |
| 初始采集/速率预热 | 各指标独立加载，内存等可先显示，速率待第二个样本 |
| 实时/部分可用 | 成功指标继续刷新，缺项说明原因和时间；采集失败不能使整页不可用 |
| 暂停/不可见 | 停止新轮次，取消在途并释放所属临时资源/租约；保留有限快照和缺口 |
| 更新延迟/已过期 | 单项超过其 `max(3×周期, 10秒)` 无有效结果即标过期；保持最后值及时间，不能仍显示“实时” |
| 断线/重连 | 立即标连接断开；仅等核心恢复，不自行无限重连；新连接代次清速率基线，趋势可保留并标断点 |
| 命令不可用/拒绝/解析失败 | 单项给具体短说明；不把权限不足变成“0%”；不会自动提升权限 |
| 关闭/禁用/工作区结束/退出 | 取消采样与订阅，清内存状态并释放所属I/O/租约；不关闭其他消费者的连接 |

同工作区的挂载切换只更换有效呈现绑定，采集器不重复启动。对真实隐藏则执行暂停规则；重新显示恢复调度，旧轮次结果须经过工作区、连接、采样及呈现代次校验才可更新。全App收起托盘且没有可见监控时不后台采样；仍可见的独立监控窗口继续工作。

公共调用记录和观测事件见插件总览。监控会产生少量SSH流量与远端开销，T-019可以按插件来源计量这些流量；资源监控数值不能再混入其SoDeck流量统计。不承诺“零开销”。[代码方案§8](../../../technical/server-monitor-implementation.md#8-预算取消与降级)固定输出/时间/缓存预算：每目标最多64网卡、64块设备、128挂载；最多64个完整控制器、8个同时采样目标；多余目标明确等待名额或显示容量上限。每controller缓存4MiB、插件32MiB，先驱逐隐藏历史并明示；对象超限标partial，不能静默当作全量。可通信环境取消反馈≤100ms、5秒内回收，失联时清理待决必须可见。以上为本稿建议上限，未经实测不能写成已达标。

## 6. 验收标准

- AC-01：当前工作区看到正确目标，切换/多窗口/跳板不串机器；终端内二次ssh不改变目标。
- AC-02：四类指标可独立显示，速率/内存/容量口径明确，缺失和真实0有区别，计数重置无负值或尖峰。
- AC-03：实时/暂停/刷新/趋势范围行为一致；缺口、过期和局部失败可见，隐藏不持续采样。
- AC-04：复用核心连接与独立通道；不打断终端，不安装远端依赖；故障/取消/关闭及时回收且隔离其他插件。
- AC-05：三主题、文字缩放、键盘和减少动态可用；密集刷新不挤动布局或抢焦点。
- AC-06：插件可独立构建/更新，真实Linux和BusyBox降级有证据；客户端/远端平台、模拟及原生结果分别报告。

## 7. 本功能测试流程

适用r2，所有用例目前均为计划，自动化和监控包尚未建立。结果记录在T-024；模拟数据只验证计算/状态/UI，不代替真实SSH或原生桌面。代码方案MCODE-01～10进一步固定实现验证，不能替代本表业务预期。

共同准备：隔离Windows数据与可区分的Linux A/B；专用跳板与SOCKS测试路径；BusyBox/OpenWrt guest；有已知CPU/内存/挂载/接口计数的夹具。禁止对业务机制造负载、写满磁盘或断网。真实指标在相同采样窗用内核计数/系统工具交叉核对，工具口径差异解释清楚，不强求不同时间的瞬时数值完全一致。
