## 1. 目标与范围

让用户在当前服务器工作区内看到远端机器的资源占用，判断机器是否繁忙、内存是否紧张、磁盘是否将满以及网络是否有流量。指标、界面位置、刷新周期和平台范围已随代码方案整体获得确认。

推荐首版提供 CPU、内存/Swap、文件系统容量、磁盘读写和网卡收发，以及本次查看期间最近10分钟趋势。客户端先验证Windows；远端先支持常见Linux，OpenWrt/BusyBox按能力降级，不要求安装组件。Windows/macOS远端、GPU、进程排行、容器指标、告警、长期历史和导出留待后续。

与[T-019通信监控](../../tasks/T-019-connection-metrics.md)分工：通信监控计量SoDeck连接的通信，资源监控解释远端OS资源。远端网卡流量包含其他程序，不能标成SoDeck流量；本插件也不承担SoDeck自身内存/CPU诊断。

## 3. 界面与工作区

遵循[F-CORE-004](../../core/workbench.md)、[UI规范](../../standards/ui.md)及apple-design。建议只贡献一个服务器级单实例视图 `monitor.resources`：支持右停靠、中央Tab和独立视图窗口，默认右停靠，推荐宽度320px、最小宽度280px/高度240px，内容可纵向滚动。工具入口名称“资源监控”，不在服务器Tab标题塞入持续变化的数字。

新建工作区默认创建视图并展示；若右侧已有用户选择的工具，尊重当前工具，保留资源入口，不强制抢占。收起后点击入口重新显示，明确关闭后由入口重开；完整重启遵守P-33，不恢复上次服务器或曲线。

核心负责容器、归属、窗口、焦点和呈现状态；插件负责全部指标语义、采样、图表、筛选和错误说明。独立窗口固定原服务器，其他窗口切换Tab不改变其目标。移窗/重新挂载保留逻辑视图、图表范围和选择，不创建第二份采集器。

状态快照建议版本1，仅含本次运行的选中指标、网卡/设备、趋势范围、暂停标记和滚动位置；采集器与曲线由插件worker持有，不塞入核心布局快照。暂停状态随逻辑视图移动，重开视图恢复默认实时模式。

## 4. 核心依赖与资源

复用现有API 5工作区上下文、贡献入口、呈现状态、连接观察、`connections.acquireExisting`、非PTY执行、取消与资源管理，以及公开UI/主题和观测协议。代码方案将新插件最低要求定为API/SDK5.2，新增公开`runtime.clock.v1`、SDK有界exec客户端，指标仍由插件解析；确切manifest能力见代码方案§2。本期通过exec采集，不需要SFTP；不把旧规格中API 4字样当作当前实现事实。

插件不借终端发送命令、不读取终端私有状态、不调用文件插件，不持有密码、不自行建立SSH。普通Linux指标解析留在插件；确需新公共原语时，先给出独立契约、消费者和测试，不能把业务采集移入核心。网络路径按核心选择的直连、SSH跳板或SOCKS5处理。

同一工作区创建代次、目标连接代次和本插件业务实例共用一份采集器。隐藏/暂停/关闭的资源规则由F-MON-001维护；释放本插件租约不影响终端、文件或隧道。调用依P-14逐次留痕，不新增插件授权弹窗。日志记录采样类型、来源、目标、时长、字节数和结果，不写原始输出、完整挂载列表或凭据；不把每个采样点重复写入诊断事件历史。

首版曲线只驻内存；刷新选项和对象选择只保留本次逻辑视图，不增加数据库或设置窗口依赖。T-023设置provider仍是另一项设计，不能假称本插件已接入。采样输出、对象数量、曲线缓存、并发与超限行为已由代码方案§8固定并纳入MCODE-06；不把内存计费预算当作JS进程RSS。

## 5. 构建、兼容与更新

源码位于`plugins/monitor`，界面和业务共同独立打包；构建及测试入口、实际包与验证证据见[T-024结果](../../tasks/T-024-results.md)。复用官方插件验证、版本兼容、重启启用及失败回退流程。不热替换运行中的采集器；重启后不保留历史。远端缺少某项能力只影响对应指标；不自动安装工具或请求sudo。

## 6. 插件级测试流程

以下为计划，结果归T-024。共同环境：隔离Windows开发数据、专用Linux/BusyBox目标、现有终端/文件/隧道插件；所有临时负载和故障只在专用测试机执行。

| 用例 | 准备、步骤 | 预期 | 清理与方式 |
| --- | --- | --- | --- |
| MON-P-01 独立接入 | 建立首个监控包；启动核心并打开终端/文件/监控；检查依赖和调用来源；仅改变监控解析/界面并重建插件 | 业务变化无需加入核心监控专用命令；调用身份真实、无需插件授权、逐次留痕；其他插件可继续操作 | 关闭测试工作区并检查资源回收；静态、集成和原生结合 |
| MON-P-02 独立更新 | 准备两个可区分的监控版本；旧版运行时准备新版；退出重启；再试损坏或不兼容包 | 当前版本不热替换；重启启用新版本；损坏/不兼容版本按公共机制拒绝或回退；其他插件版本不变 | 恢复开发包/数据副本；真实包及Windows原生验证，不等同安装器测试 |
| MON-P-03 生命周期与故障隔离 | 运行三插件与监控，反复移窗/返回、关闭、使worker失败并尝试恢复 | 单一有效呈现绑定和采集器；失败可见，清理所属资源；终端/文件/隧道不被误关；退出回到资源基线 | 清除注入、关闭App；结合F-MON-001 MON-02/08/09/10 |

单项功能按F-MON-001的MON-01～12执行，不以插件级检查代替指标准确性和远端兼容验证。
