## 1. 目标与范围

2026-10-26 启动与首终端修订：[F-CORE-010 r2](../../../core/clean-start.md) / [T-009](../../../tasks/T-009-clean-start.md) 定义不恢复旧终端、新建工作区自动首终端连接。TERM-12 中“重启仅恢复占位”由 CS-01/03/05/08 替代，字号等明确设置保留；TERM-08 的当前运行断线重连与表面恢复不变。r7 补 TERM-13/14 的首终端流程；实施确认与新版本验证见 T-009，原任务实测不改写为新版本通过。

用户创建服务器工作区时，终端插件经公共初始化动作自动创建一个首终端，完成核心认证后进入可用的远端 shell；后续点击“新建终端”增加会话。创建/定位矩阵和边界以 F-CORE-010 §2.4 为准。首批包含多会话、中文输入、选择与复制粘贴、尺寸/字号、断线后手动重连、每服务器上下文、双区域与窗口迁移，旧分屏等覆盖关系见文首。核心 PTY 的真实边界和失败流程由 F-CORE-005 负责，本规格维护终端业务行为。

默认会话命名“终端 1、终端 2…”，窗口/Tab 由核心持续显示所属服务器；可以修改显示名，不把远端输出中的标题控制序列当作服务器身份。会话列表与终端视图的支持位置以插件总览为唯一声明来源。

## 2. 操作及状态

| 状态/操作 | 具体行为 |
| --- | --- |
| 新建工作区 | 自动创建并选中一个首终端页，进入连接/认证；不显示需要另点新建的正常空态。插件不可用或额度不足由核心显示真实未完成状态，不能冒报成功 |
| 用户关闭全部终端后的空工作区 | 显示新建终端入口；仍能编辑服务器和使用其他插件，不自动补建/连接，不隐式关闭服务器 Tab |
| 新建/连接中 | 首终端初始化或用户额外新建各对应一个操作；重复同一请求不重复创建。首终端未结束期间新建入口定位该操作。显示可取消状态，未就绪不缓存用户输入以便日后自动发送 |
| 等待认证 | 使用核心统一认证层；终端显示等待状态，关闭这一新建操作释放自己的等待 |
| 首次失败/取消 | 网络、认证或 PTY 失败/取消保留本次终端逻辑页、原因及重试入口，重新尝试复用视图并使用新操作代次；不跨启动保存，不循环自动重试。已有 PTY 仅渲染表面失败时走表面恢复，不重复建连 |
| 运行中 | 渲染真实 PTY 字节；光标、ANSI 色彩、Unicode、滚屏及交互程序可用；状态栏标明服务器和连接状态 |
| 选择/复制/粘贴 | 拖动选区；Ctrl+Shift+C/V 和菜单复制/粘贴。Ctrl+C 仍发送终端中断；复制不发送命令；剪贴板错误就地反馈，不向日志写入正文 |
| 字号与尺寸 | 插件提供字号减/增和恢复默认，10–24、默认 14；核心容器变化后按真实可用内容区 fit，再发送 rows/cols。0 尺寸隐藏面板不发送非法 resize |
| 会话结束/断线 | 保留本次内存中的屏幕和原因，禁用输入，提供“重新连接”及关闭；重新连接产生新 PTY并清空旧活动屏幕，不重放旧输入 |
| 隐藏/切换 | 收起列表、切 Tab 或工作区、主窗口托盘都保留会话；后台输出受预算控制，重新显示按序续接或明确报告缺口 |
| 关闭终端 | 默认结束该 PTY；列表中移除条目，其他会话继续。不增加每次关闭确认框；本批无关闭后托管功能 |
| 关闭列表 | 只关闭导航视图，可再从工具按钮打开；不结束被引用的终端 |

初始环境使用 `xterm-256color`，默认远端 shell；不推断服务器工作目录，不为保持目录自动发送 `cd`。不自动检测并运行初始化脚本。终端输出不自动写入历史或诊断日志。

## 3. 工作台与窗口

终端默认中央 Tab，可移到底部面板或独立窗口；会话列表在左/右侧停靠。中央最多两个区域，支持左右或上下布局；以上位置/分屏按文首 T-006 覆盖。移动终端不会另开 shell；新建工作区的首终端初始化或用户额外新建才创建新会话。

跨窗口复用 v1 的准备、冻结输出交接、目标就绪、提交/回滚机制，并改为插件视图契约。保持会话 ID、PTY、当前目录和远端进程，恢复终端屏幕/滚屏和选择等插件视图状态；抓取状态仅在本次迁移内存中传递，不持久化正文。每次提交只有一个有效输入表面。

其他窗口切换服务器后，独立终端窗口仍显示并操作原服务器。独立终端窗口“×”关闭其中终端；返回保留会话并回到原工作区，必要时激活该工作区。弹出/返回有菜单和键盘路径，工作区内拖动提供落点；跨原生窗口拖动复用 v1 已有入口并在本批实测，不以菜单通过冒称拖动通过。

T-004 的待确认设计按 [F-CORE-006](../../../core/server-tabs.md) 扩展：顶部服务器 Tab 与内部终端 Tab 分层；整工作区可移到另一工作区窗口，终端仍使用原有展示位置与资源。已弹出的单终端保持位置，按钮从“返回主窗口”改为“返回所属工作区”，实际回到该工作区当前承载窗口。关闭服务器工作区涉及它全部终端，包括单独弹出的视图。T-003 r1 原实现与实测不自动覆盖此变化。

T-004 r3 进一步建议维持一个 App 内一个终端业务实例，通过公共视图/命令/生命周期契约完成新建、标题与状态同步、关闭及迁移；核心增加工作区窗口不导致再启动 worker。实例事实、现有外壳专用耦合及终端适配范围见 F-CORE-006 第 6 节；本轮仍是设计讨论，未授权这部分重构。

T-004 r4 的[代码修改方案](../../../technical/server-tabs-implementation.md)将适配细化到命令/工作区入口声明、views 元数据与资源绑定、关闭/恢复生命周期、认证来源路由及 API 2 配套升级；保持全部现有终端业务功能。旧包兼容、独立更新测试组合及开发包版本以该方案第 9 节为准，尚待用户确认。

视图加载失败显示核心恢复外框，资源状态仍可从核心查询。表面崩溃不把 PTY 误称断线；可重建表面并取得当前有效绑定，若屏幕缓冲无法恢复则清楚说明缺口。业务实例崩溃按资源规格回收其普通会话，不声称重新启动实例能复活旧 PTY。

## 4. apple-design 与 Windows 输入

已读取并使用 apple-design。终端内容保持稳定、清晰、不透明；层级依靠服务器标识、选中 Tab、文字权重和留白。外壳默认系统字体，终端默认 `Cascadia Mono, Consolas, monospace`；字号放大不能导致操作消失。

按钮按下立即反馈，连接结果异步显示。拖动保持抓取偏移及目标预览，Esc 回原位置；收起/展开可中断，开启减少动态效果时改用即时切换或短淡化。透明材质限于不影响内容可读性的外框。

输入只进入聚焦终端。中文 IME 组合不得被快捷键或迁移重复提交；候选窗口跟随输入点，跨 DPI/窗口切换后正确定位。容器快捷键有清楚优先级和菜单替代，不能吞掉常用远端程序控制键。上述落点对应 TERM-02、TERM-03、TERM-09、TERM-10。

## 5. 状态、数据及接口

业务实例维护 `sessionId → workspaceId/serverId/viewId/ptyId/generation/status`，PTY 句柄不写入持久数据。视图只持有当前挂载代次、xterm 实例、滚动/选择和输入法状态；连接与资源由核心维护。初始化/更新迁移仅处理本地设置，不自动打开 PTY。

上述“初始化”指 App 启动时插件 prepare/activate；P-34 的工作区创建动作另行声明，不能混淆。首终端由插件先建立带准确服务器上下文的连接中视图，再申请资源，失败/取消时没有有效 PTY 也可呈现状态；重试前完成本次资源补偿，旧工作区代次失效后不更新新页。额外新建沿用公共命令与资源流程。总量预算仍按整个 App 的真实会话/正在创建操作计算，不能借初始化绕开。核心负责通用去重、路由和关闭，不持有终端业务模型。

使用 F-CORE-005 的连接/PTY 方法、公共流/快照/资源方法、工作台扩展点及插件设置存储；不直接访问 Tauri 旧命令、SSH 库或服务器秘密。字节流不必经插件业务 JS 逐字节转发，原生通道仍需绑定当前插件/视图/代次；每次 `pty.write` 和其他公开调用由核心留痕，只记录摘要。

迁移状态 schema 1 包括终端渲染器兼容版本、屏幕/滚屏快照和展示状态。核心只协调不透明状态，重新绑定资源通过权威会话注册完成。快照过大、版本不兼容、目标失败或取消时不提交迁移，源视图仍可用；提交响应丢失则查询操作结果，不能重新创建会话。预算及确切契约在[实施技术方案](../../../technical/first-terminal.md)维护。
