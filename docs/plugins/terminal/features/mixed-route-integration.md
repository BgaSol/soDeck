## 1. 终端应有的行为

用户打开混合路径的最终目标，只有一个目标工作区和首终端。每台中转SSH与代理的挑战由核心/外壳处理；终端保留当前会话为等待认证，完成后继续同一个打开操作。中转节点不创建PTY、终端Tab或目录集成。最终PTY的输入、输出、关闭、目录报告和字号业务仍由本插件负责。

本计划为API6接入，不是新增终端连接引擎；不兼容API5包或在插件中复制路径配置。核心执行器修改不能代替本插件状态、声明和测试的修改。

## 2. 代码修改

| 文件 | 计划 |
| --- | --- |
| `plugins/terminal/src/worker.ts` | 当前open catch手写6种认证错误，改用SDK统一 `isConnectionAuthenticationError`，覆盖新的预设凭据归属确认。等待认证继续保留sessionId/viewId/operationId，释放失败attempt的lease/PTY；重复继续去重，取消后的迟到lease释放，不创建第二个首终端。 |
| `plugins/terminal/src/terminal-view.tsx` | 重连及继续认证使用API6预算helper；不能丢掉预算读取失败，也不能用旧nodeCount公式。继续/取消按钮按原操作状态显示，代理确认不被绘成普通失败，终端输入不透传到认证对话框。 |
| `plugins/terminal/src/observation.ts`及相关调用点 | 认证等待沿用非完成态，最后成功/失败/取消只记录实际终态；不读取/记录密码或全链地址，不把SOCKS误报为额外PTY。仅在新错误分类需要时调整状态事件。 |
| `plugins/terminal/tests/worker.test.mjs` | 替换API5夹具，补多轮不同节点挑战、preset确认、取消/迟到结果、最终PTY仅一次创建的断言。 |
| `plugins/terminal/manifest.json`、`package.json`及包锁/构建引用 | SDK6、`pluginApi:^6.0.0`、实际使用的`connections.route.v2`能力；候选版本0.12.0，不覆盖其他任务已占版本。四插件仍分别打包。 |

`directory-reporter.ts`和PTY输入协议不因路由类型增加新实现；保留最终连接generation绑定，按下面用例回归。如发现本插件有旧hopIndex/nodeCount假设，改为新SDK类型，而非本地兼容分支。

## 3. 插件专属测试

适用r1，对应MR-AC-01/03/04/05。准备F-CORE-031隔离A→B→P→T拓扑和新API6终端包；给A/B/T不同认证，P用账号认证，设置一份待归属确认的代理preset。模拟worker验证状态与并发，真实OpenSSH/Windows原生验证最终PTY及界面，分开记结果。

| 用例 | 步骤 | 预期 |
| --- | --- | --- |
| TERM-MR-01 首终端 | 新建并连接T，逐一完成A/B指纹/登录、P确认/登录、T登录；在T执行无副作用身份/目录命令 | 始终同一终端view，只有T创建PTY；最终主机确为T，A/B无PTY，P无SSH登录 |
| TERM-MR-02 取消与迟到 | 在每种挑战阶段取消、快速重复继续、关闭Tab后让旧调用返回，再显式重连 | waitingAuth/取消准确，旧结果不重建Tab、不交付旧lease；同操作去重、无自动重放用户命令 |
| TERM-MR-03 多会话 | 打开T两个终端和文件；切换/移窗/托盘，关闭一个终端；更改路径后新建连接 | 原消费者按旧快照继续，单终端关闭不误关其他lease；新连接用新revision，cwd报告不串代次 |
| TERM-MR-04 包和预算 | 用新模型直连/纯SSH/单SOCKS/混合，模拟超过旧180秒但在核心预算内的建立；API6环境单独更新终端A→B并重启 | UI/worker外层不先超时；新旧API主版本互拒；只终端包hash改变，字号/输入/目录既有功能可用 |

每例关闭所有终端/lease/测试工作区，移除测试preset/context；原生检查恢复缩放/主题。记录取消清理的实际资源和截图；不把模拟测试视为真实终端可用。

## 逐步诊断增量（r4，已实施）

公共契约、UI及核心事实来源见[诊断方案 r1](../../../technical/connection-diagnostics.md)。`worker.ts` 的连接 catch、session 状态与视图快照保留 `diagnosticRef`，不能只存 `session.error` 文本；插件业务 attemptId 与核心 attemptId 分开。`terminal-view.tsx` 在现有错误条提供精简摘要与公开宿主详情请求，移窗快照保留引用并核验工作区代次。业务事件只附安全 ID/错误码，不记完整路线/密码。新包声明诊断与组合确认所需能力；旧 PTY/输入/目录行为保持。

准备：隔离 A→B→P→T 和两个终端、受控错误代理，沿用 TERM-MR 环境；补充以下用例，具体执行证据见T-027结果。

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TERM-DIAG-01 | 同工作区两个终端分别新建/重连，一成功一失败；从失败条打开详情，随后移窗/切 Tab | 绑定该终端实际 attempt，旧记录不被另一终端覆盖；等待/失败/已取消区分，查看详情不创建 PTY。 |
| TERM-DIAG-02 | 代理方法回复 EOF；确认/双击继续/取消/重试；连接成功后 PTY 请求失败 | 前者显示第几站和未执行目标；一次继续仅一个 PTY，重试不重放命令；PTY 业务失败不篡改 SSH 建连成功。 |
| TERM-DIAG-03 | 独立更新终端包，三主题和原生详情遮挡、键盘/焦点/复制检查 | 能力声明正确、仅终端包变化；报告无秘密，错误条可关闭而详情仍可从状态打开，其他消费者不受影响。 |

结束后关闭两终端和测试连接/订阅，核对 PTY/lease 回收；截图、实际协议及模拟竞态分开记录到 T-027-results。
