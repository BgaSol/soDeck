## 1. 目标与范围

### WIN-SHELL-01：Windows 默认禁用集成（2026-10-29）

用户在排查Windows CMD被Bash脚本终止后明确“先暂时默认不要让windows开启shell集成了，你直接改一下”，授权本项实现与验证。保留全局集成偏好，新增每次新建/明确重连前的能力门槛；只改终端插件及独立插件包，不改数据库、核心API、远端配置和监控插件，不热改现有会话。

在已取得的目标lease上，用独立有界exec执行只读的Bash版本与`uname -s`探测。只有完整、成功、未截断的Linux+Bash结果才发送现有集成启动脚本；Windows、未知Shell、拒绝exec、超时或输出无法核对一律使用普通`pty.open`，不把探测错误显示成连接失败。探测不占用交互PTY、不向现有终端输入命令，不能在PTY启动结果不明后重放登录。远端执行预算2秒、本地等待3秒、输出1KiB，复用SDK有界exec的取消、回执核对和清理；用户取消后禁止创建PTY。探测会多经过一次非交互Shell启动，原自定义启动副作用限制仍需说明。全局关闭时跳过探测。

复用现有终端底栏Checkbox：本次判定不支持时显示未勾选、禁用，旁边明确“本会话未启用”；不改全局已保存值和其他Linux会话。按apple-design的清晰反馈与稳定布局原则，不加弹窗或新设置页。Linux支持路径保持原偏好与下次会话生效语义。普通Shell不启用PTY目录observer，目录跟随按既有unsupported降级，手动文件浏览可用。

原生回归补充：明确重连建立新PTY后，重建表面时清除旧PTY已关闭的残留错误，新绑定/初始化错误仍正常显示。回归输入须等待实际提示符；输出标记按独立结果行核对，不能要求命令回显不发生终端换行。Linux使用专属T-027测试虚拟机的22373管理SSH服务验证Bash；A/B转发服务刻意配置`MaxSessions 0`，不适合作为交互终端目标，保持其配置。

检查终端类型/worker测试、仓库静态检查，原生Windows及Linux分别保存证据。原生入口为`tests/desktop/windows-shell.mjs`，明确传入源开发包和已授权Windows服务器ID；`core-snapshot.py`只读备份v7及其引用的加密文件。存活断言接受worker刚创建的`running`及随后PTY通知的`active`/`connected`，与终端既有状态语义一致。测试结束退出隔离应用、回收测试PTY和服务；交付同core/API/v7的独立开发目录，用户原r8保持。交付时只复制当前激活终端数据代次的settings.json，核对两端schema相同、目标未运行，再通过普通启动读取设置核对；不复制旧插件安装或缓存。结果写[T-027实施记录](../../../tasks/T-027-results.md)，不创建Git提交或发布。

将每个实际交互 shell 最近确认的工作目录作为该终端会话的状态提供给核心，供工作区工具使用。终端负责 shell 协议识别和目录语义；核心持有原始 PTY、来源绑定、公共上下文和生命周期。终端不调用文件插件，不知道文件树的展开、选择和加载规则。

目标体验是在受支持的 Linux 登录 shell 中自动可用。[代码方案 r1](../../../technical/terminal-directory-follow-implementation.md) §5 推荐先验证 Bash 5.1/5.2 的进程环境注入，保留真实 login shell；配置覆盖/限制集成时保留原配置并准确降级。Zsh 5.9 本批验证普通终端降级，自动跟随列为后续候选。PowerShell、fish 等其他 shell、tmux/screen 内部 pane、嵌套 SSH、容器 shell、身份切换及 chroot 不默认支持；它们仍可正常作为终端使用。此支持范围已随 T-010 与 Shell 补充获确认并实测，实际结果见任务记录。

## 2. 目录判定与报告

按用户已确认的[启动补充 r1](../../../technical/terminal-shell-startup-review.md)，新增默认开启的“Shell 目录集成”设置。集成使用 SSH exec 入口，明确可能额外执行一次非交互 `.bashrc`；这是已知兼容边界。关闭后仅后续新建/明确重连会话使用原 SSH shell，目录不可跟随；偏好持久化，当前会话不热改。此条替代 r2 对启动文件次数严格相同的要求，其他配置/历史/退出码与无 dotfile 修改约束保留。

以 shell 在提示符就绪时报告的实际结果为准。首次报告定位初始目录；之后仅真实目录变化产生导航意义。成功的 `cd`、别名、函数、`pushd/popd` 同样处理；失败 cd、不改变父 shell 的 `(cd …)` 或脚本不改变父会话目录。复合命令在返回提示符时报告最终目录，不承诺命令内部每一步 cd 都立刻同步。

不通过输入字符串匹配 `cd`、提示符正则或历史命令推断 cwd；不在用户正在输入、运行程序或使用全屏应用时注入 `pwd`；另开的 SSH exec 通道有自己的进程目录，其 `pwd` 不能作为现有 PTY 的目录依据。

推荐采用会话内私有有界 OSC 报告，由 Bash prompt/PS0 提供“提示符就绪/执行中”的上下文证据。新的受支持会话在交互开始前建立集成；原登录配置/提示符/钩子继续生效，退出码不变，避免显示额外控制文本或污染历史。不得自动改写远端 `.bashrc`、`.profile`、`.zshrc`，不安装远端常驻服务。启动文件执行次数/顺序和既有 hook 是前段验证关口；候选破坏原行为时不得默认采用，需新增临时 rc 文件或改变登录语义则先更新方案确认。

已运行但尚未集成的旧终端不插入初始化命令；提示该会话目录不可用，后续新建/明确重连时建立报告。升级遵循现有重启生效，不热改正在运行的会话。

报告应区分“当前 shell 刚确认”“执行中，最后确认”“未知/不受支持/已失效”。长命令和全屏程序中可保留最后确认值但不伪称持续观测其内部 cwd；回到受支持的外层 shell 提示符时恢复确认。

## 3. 路径身份、来源和资源

- 路径按远端字节保真传递，逻辑路径与可用的物理路径分开；非法编码、非绝对路径、NUL、超长或截断报告返回未知，不把显示转义作为操作路径。
- 候选 OSC/报告内容是终端输出数据，不是命令执行指令。仅凭任意进程输出的 `file://host/path` 不能证明它是外层登录 shell 的 cwd，也不能仅比较 hostname 就认定命名空间相同。
- 可靠报告必须绑定当前 shell 集成、实际 PTY 会话及其路径视图证据。内层 shell 不继承可冒充外层的有效导航身份；无法判定时不消费其路径，保留外层“上次确认/暂不可用”。普通终端输出本身不作为安全认证凭据。
- PTY 与文件服务账号/根/命名空间不一致或未知时，报告必须携带不可映射状态，不能默认映射到宿主同名路径。仅仅验证 SFTP 和独立 exec 一致不够。
- 会话、PTY/连接代次和视图归属由核心核实；报告序号单调，旧表面、旧 PTY、关闭后的迟到报告无效。背景会话可更新其自身快照，不选择自己成为活动来源。
- 观测不能依赖前台视图持续存在；采用同所有者独立 PTY observer，由 worker 解析；UI 保留原显示 read/ack，观察绝不能推进显示 ack。移窗不重新初始化 shell；观察缓冲丢失显式降级，等下一完整有效报告恢复。
- 最多保留每活动会话的最新有界目录状态，流解析必须支持跨帧、超长输入和取消；具体字节/频率预算在代码方案固定。不保存 cwd 历史、控制序列正文或命令正文到调用日志。

若集成失败，终端连接、正常输入输出继续可用，标记目录能力不可用。目录报告是增强能力，不能使用户登录停在初始化流程中，也不能通过重复执行远端命令自动重试。

## 4. 验收和测试流程

AC-01：报告实际 cwd，覆盖初始目录、成功/失败与非字面 cd，错误命令不制造导航。
AC-02：提示符、用户配置、历史、退出码和交互不受损，普通终端仍独立可用。
AC-03：字节路径/身份/命名空间可靠绑定，不能把不明输出当作可导航目录。
AC-04：隐藏、多窗、重连、关闭及版本不匹配的报告有正确寿命和降级。

适用 r2；尚无本功能脚本。准备隔离 Linux 真实 Bash 5.1/5.2 与降级验证用 Zsh 5.9，含自定义提示符、既有 hook 和多 PTY；受限环境只在 guest 建立，用户服务器不用于初始化实验。模拟帧只证明协议处理，不能代替真实登录兼容。预算/协议/路径视图核对见代码方案 §4～6/9。

| 用例 | 步骤 | 预期与关联 |
| --- | --- | --- |
| DR-01 目录语义 | 连接读初始 cwd；执行 cd、cd -、pushd/popd、别名、函数、失败 cd、子 shell 和复合命令 | 与同一交互 shell 的对照结果一致，返回提示符才报告最终状态。AC-01 |
| DR-02 Shell 共存 | 在已支持版本矩阵下使用既有提示符/hook、补全、历史、非零退出、长命令和全屏程序 | 无额外可见控制文本，原配置/退出码保持；运行中不插入 pwd。AC-02 |
| DR-03 字节与帧 | 真实空格/换行/非 UTF-8/软链目录；模拟控制序列跨帧、截断、超长、无效 URI | 路径不改写；无效报告只降级，不执行文本、不阻塞输入。AC-01/03 |
| DR-04 内层与映射 | 输出伪造目录序列，进入 tmux/SSH/容器/sudo shell/chroot，再返回外层 | 不把未知内层路径映射到外层；返回后新报告恢复。必须验证无法判定时的降级。AC-03 |
| DR-05 视图与会话 | 后台终端改变目录；移窗/表面重建；断线重连后送旧报告；关闭 PTY | 新鲜度/代次正确，旧报告拒绝，未重复初始化或消费/ack 数据。AC-04 |
| DR-06 缺能力与失败 | 不支持 shell、无法建立集成、原包与新版组合、初始化报告超时 | 终端可继续正常使用，目录状态明确不可用，不重复执行 shell 命令。AC-02/04 |
| DR-07 启动关口 | 分别记录普通 shell 与候选启动的 profile 执行次数/顺序、login 标志、hook 数组/字符串、PS0 覆盖、退出码/PIPESTATUS、历史、补全与退出；测试 exec 拒绝/回执不明 | 常规 Bash 两版本保持原交互；配置覆盖时保留原配置并降级；行为受损候选不得发布，回执不明不重放。AC-02/04 |
| DR-08 独立观察 | 原子建 observer 后启动；冻结 UI/移窗；填满 256 KiB ring、8 PTY 并发、跨帧切断及关闭 | 首帧不漏；显示 ack 不受影响，gap 清除半帧/可信状态，下一完整报告恢复；控制/内存预算有效且释放。AC-03/04 |
| DR-09 集成设置 | 默认新建；关闭开关后再新建/明确重连；重启 App；观察原有会话 | 默认集成；关闭后原 shell 登录与不可跟随状态准确；当前会话不热改，偏好重启保留。集成模式启动顺序按补充方案记录，不再要求次数与普通登录相同。AC-02/04 |

每例退出临时 shell 并关闭 PTY，核对目录观测资源释放；检查 dotfiles 的内容/时间没有被隐式修改，恢复故障夹具，结束隔离 App。用户环境未运行此功能。结果仅记 [T-010](../../../tasks/T-010-terminal-directory-follow.md)。
