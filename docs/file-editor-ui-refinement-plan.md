# 文件编辑页面输入体验整改方案

状态：用户已确认，前端实现与浏览器验证已完成（2026-10-21）；原生实机验收待补。下文保留整改前的问题与设计依据，实际结果见[实施记录](C:/Users/bgaso/Documents/works/soDeck/docs/file-editor-ui-implementation.md)。

## 1. 对需求的理解

“输入框难看”不只是边框或圆角问题。目标是让远程文件编辑页面呈现为统一、安静、可靠的桌面文档编辑环境，而不是主程序里嵌入一个默认样式的编辑插件。

本方案覆盖正文编辑区、查找/替换输入和底部语言选择器；不将正文继续包装成大型表单输入框。遵循 apple-design 的内容优先、熟悉性、克制、及时反馈和可访问性原则，不堆叠玻璃材质、阴影或装饰动效，也不在 Windows 上仿造 macOS 窗口按钮。

## 2. 已核实的问题与保留范围

检查依据：当前 `src/FileEditorApp.tsx`、`src/files.css`、`src/styles.css`、`src/theme.ts` 和 CodeMirror 已安装版本；参考仓库已有的 `.qa/window-chrome-editor-overlay.png`。新的本机预览未完成：常规启动遇到权限限制，隔离配置的预览页面加载超时，因此不将本轮结论表述为新的实机视觉验收。

### 需要整改

1. **查找/替换存在明显的默认插件痕迹。** 目前使用 CodeMirror 原生 SearchPanel，默认位于底部，英文按钮、匹配复选框和替换操作同时出现；CSS 主要覆盖了输入框最小高度、间距和按钮边框，没有统一结构和交互层级。
2. **控件尺寸和字体缺少一致性。** 查找框及按钮使用 25px 最小高度；主程序控件约 32–34px。默认面板的标签还使用相对百分比字号，容易出现字号、基线和点击区域不统一。
3. **暗色主题接入不完整。** 应用通过 CSS 变量切换颜色，但编辑器没有同步 CodeMirror 的 `dark` 配置。其默认 `.cm-textfield` 浅色规则仍可能生效；不能只依赖主背景变暗来认定输入框、提示层等全部适配。
4. **正文排版缺少编辑器专用规范。** 正文字号固定为 13px，行文本仍使用 CodeMirror 默认横向内边距；应将字体缩放、正文与行号间距、选区及焦点状态作为一个整体定义，而不是追加零散覆盖。
5. **底部语言选择器视觉偏重。** 在窄窗口历史截图中，其完整表单边框和控件高度明显突出于相邻状态文字。需要降为紧凑的状态栏控件，但保留可发现性和键盘操作。

### 明确保留

- CodeMirror 引擎、等宽字体、行号、语法高亮、现有文档画布结构。
- 已有标题栏、保存入口、窗口控制和主题设置。
- 撤销/重做、加载/保存、脏状态、关闭保护、远端冲突处理、UTF-8 与 1 MB 限制。
- 当前合理的行距和主要布局；不为了“换风格”全部重排。
- 不修改 Rust 后端、SFTP 协议或其他页面的公共输入框。

## 3. 推荐方案：视觉优化 + 查找面板局部重构

### A. 正文：保持连续的文档画布

- 保留铺满可用空间的正文，不加第二层圆角卡片、厚边框或大阴影。
- 行号区与正文保持低色差；弱化非必要分隔，但不能以降低可读性为代价。
- 保持等宽字体；字号采用相对单位，以现有阅读密度为基线。正文与行号之间预留约 12px 的起始间距，再由长行、中英文混排实测确定。
- 当前行使用轻微底色；光标、选区、搜索匹配和错误提示分别有明确含义，不能全部使用同一强调色。
- 不给整块正文画持续高亮的大蓝框。正文通过光标、选区和当前行体现编辑状态；工具栏及表单控件保留清晰的键盘焦点环。
- 打字、选字和滚动不添加动画。长行维持现有滚动行为，不借视觉整改擅自改变自动换行规则。

### B. 查找/替换：改为顶部按需展开的工具条

在原工具栏下、正文上方展开，位置与“查找”入口一致；不浮动遮住匹配行，也不使用模态弹窗。

默认结构：

```text
[展开替换] [查找内容________________]  2 / 8  [上一处][下一处] [匹配选项] [关闭]
```

展开替换后增加一行：

```text
           [替换为__________________]         [替换当前] [全部替换]
```

- 查找为默认路径；替换按需展开，已有功能不删减。
- 中文标签和无障碍名称一致；区分大小写、正则、整词及选中全部匹配仍可访问，不用没有解释的图标代替功能。
- 输入框、图标按钮统一约 32px 高度、6–8px 圆角和 8px 基础间距。这是项目建议值，不宣称是 Apple 的强制尺寸。
- 输入框用中性色实底、细边界；聚焦时采用清晰但克制的强调色焦点环。取消默认插件的渐变按钮风格。
- 提供结果数量、当前项、无结果和无效正则反馈。没有可用匹配时禁用对应导航/替换操作，不仅改变颜色。
- Ctrl/⌘ F 打开并聚焦查找；Enter/Shift+Enter 跳转；Esc 关闭并将焦点还给编辑器，不改文档或清空撤销历史。
- 中文输入法组合期间不劫持 Enter；替换是可撤销编辑，不额外弹出不必要的确认框。
- 窄窗口采用明确的分行布局，不能依赖默认 inline 元素自然挤换行；输入框和关闭按钮始终可用。

### C. 底部状态与主题

- 保留语言选择的原生 select 语义和键盘行为，改为低强调度的紧凑外观；显示当前语言和下拉标识，hover/focus 时加强边界。
- 状态栏优先保证保存状态和当前语言可见；窄窗口将次要信息合理分行，不让内容挤出窗口。
- 编辑器内部主题与现有应用主题订阅同步，通过 Compartment 重配置，不销毁 EditorView、不重建文档状态。
- 字段、选区、补全/提示层、搜索高亮均使用成对的浅/深色变量。高对比模式保留明确边界，减少透明度模式使用实底。
- 输入响应即时；本次没有需要弹簧或弹跳的手势交互。若面板有过渡，减少动态效果时改为即时切换。

## 4. 代码实施边界

1. `src/FileEditorApp.tsx`：接入专用主题与搜索面板配置；保留现有文档读写流程。
2. 新增 `src/file-editor.css`：收拢编辑器专用外观，限定在编辑器作用域；只从 `src/files.css` 迁出相关规则，不更改全局 input/button 样式。
3. 新增 `src/editorTheme.ts`：封装编辑器主题扩展与必要的暗色重配置，沿用 `src/theme.ts` 的主题来源，不创建第二套主题状态。
4. 新增 `src/editorSearchPanel.ts`：使用 CodeMirror 官方 `search({ top: true, createPanel })` 接口替换展示层，复用 SearchQuery、查询状态及查找/替换命令，不自写第二套搜索引擎。
5. 新增独立编辑器 UI 测试；补充现有窗口关闭、设置快捷键和跨窗口主题测试。

搜索匹配统计只在文档/查询变化时更新，不能在每次光标移动时全文重扫；靠近 1 MB 的文件需要验证响应时间，必要时显示有上限且明确标注的计数。面板事件、主题订阅与 DOM 生命周期必须随 EditorView 销毁释放。

## 5. 验收标准

- 浅色/深色；默认/聚焦/禁用/无结果/无效正则状态视觉一致，暗色模式不残留浅色输入背景。
- 1000×700 和既有最小尺寸 560×360 下，正文、查找、展开替换、状态栏不被裁切；正文长行可以内部滚动，但不制造页面级横向溢出。
- 文字缩放到 200% 后功能仍可到达；正常文字对比度目标至少 4.5:1，必要控件边界和焦点提示至少 3:1。
- 中文输入、Tab 缩进及键盘离开编辑区路径、查找跳转、替换撤销和焦点归还验证通过。
- 切换主题、语言或展开/关闭面板不丢未保存内容、光标和撤销记录；首次查询跳到匹配位置属于预期行为。
- 保存、重新加载确认、远端冲突及关闭保护不回归。
- Chromium/WebKit 做布局与交互验证；Windows Tauri 实机另验输入法、窗口焦点和快捷键。浏览器模拟不能替代实机验收。

实施顺序：先确定正文与字段基线，再替换搜索展示层，最后完成主题、可访问性与编辑安全回归。已按确认后的代码方案实施；未完成的实机验收单独记录，不以浏览器测试代替。
