# 文件上传与服务器直传功能设计 v2

状态：实现中的功能基线。新执行器取代旧直传协议；不迁移旧任务或自动清理旧资源。实现与验证记录见 `feature-design.md`、`validation.md`。

## 1. 设计结论

本机上传使用 SFTP。服务器直传使用 A 上的 rsync，通过 SSH 把数据发送到 B；密码认证明确依赖 A 上的 sshpass，密钥认证使用 A 上可用的密钥。首版服务器直传面向 Linux。

直传沿用目标服务器 B 已有的“真实地址”和“直连端口”，不新增另一套主机地址配置。客户端到 A、B 的管理连接继续使用现有普通地址、端口和跳板策略。

两种传输均先写本任务的独立临时目录，确认完整后才提交最终文件。传输失败、临时资源待清理和最终文件结果不确定分别处理，不能因为一条旧任务异常而禁止向整台服务器上传。

客户端是最终提交的唯一发起者。首版不承诺退出客户端后继续传输并自动提交，不部署常驻服务，也不重建旧的 guard、心跳续租和监督脚本协议。

## 2. 已发现的问题及对应要求

| 已发现的问题 | 新设计要求 |
| --- | --- |
| 系统文件拖入未进入正确的原生事件入口 | 保留已修复的拖放入口，主窗口和拆分窗口行为一致 |
| 自定义远端脚本因 CRLF 无法执行，连停止与核对也失败 | 使用成熟传输工具；任务结束不依赖再次执行同一套监督脚本。确需生成的短启动命令也必须规范编码和换行 |
| 旧直传状态未确认，导致本机上传永久排队 | 将传输执行、最终提交和临时清理分离，仅实际冲突的目标路径受限制 |
| “等待目标上的任务结束或完成状态核对”没有具体对象 | 显示等待的任务、目标路径和原因，提供取消、改名或更换目录等操作 |
| 原来默认 A 已能免交互登录 B | 密码认证作为正式能力；明确工具依赖、凭据来源与认证失败处理 |
| 启动失败被清理失败覆盖 | 保留主错误，停止或清理错误作为独立说明 |
| 把本机到 B 的连接能力当作 A 到 B 的连接能力 | 从 A 实际检查 B 的真实地址、认证、指纹和写入权限 |

## 3. 功能范围

首版包括：

- 本地文件、文件夹、多选上传；支持资源管理器拖入和文件选择入口。
- A 的文件、文件夹、多选复制到 B；支持跨窗口拖放、工具栏及右键入口。
- 隐藏文件、空目录、零字节文件、大文件和多级目录。
- 自动改名、跳过、覆盖三种同名策略。
- 进度、取消、失败重试、结果核对、已确认停止后的断点复用和临时资源清理。
- 任务在应用内独立于终端 Tab；切换会话、拆分窗口、关闭来源 Tab 不改变任务或目标。

首版不包括：移动后删除源文件、目录镜像删除、定时同步、关闭客户端后自主完成提交、自动安装远端工具、提权/sudo、完整系统备份、任意 MFA/交互式认证以及 SFTP-only 服务器之间的 rsync 直传。

本地私钥和本地 SSH Agent 的转发不作为首版直传认证能力；普通 SSH 连接继续支持它们。后续如需要，单独设计受限 Agent 转发，不把私钥复制到 A。

## 4. 地址、账号与连接路径

### 4.1 复用“真实地址”策略

| 连接用途 | 地址与端口来源 |
| --- | --- |
| 客户端连接 A，浏览和启动传输 | A 原有普通连接配置，允许已有跳板路径 |
| 客户端连接 B，浏览、检查和提交 | B 原有普通连接配置，允许已有跳板路径 |
| A 直接连接 B，发送文件 | B 的 `directHost`（真实地址）和 `directPort`（直连端口） |

具体规则：

1. 真实地址是 A 能访问的 B 地址，支持 IPv4、IPv6、域名；域名由 A 所在环境解析。直连端口默认 22，独立于普通 SSH 端口。
2. 不隐式回退到 B 的普通地址，不自动走客户端中转，也不把本机的跳板配置应用到 A → B。
3. 缺少真实地址时，在确认框提供现有填写入口；保存到服务器已有字段，重新展示本次目标再开始。
4. 保留“使用当前连接地址”的显式复制操作，仅由用户触发。
5. A → B 使用 B 的配置用户名。首版不另设一套直传账号，避免传输账号与客户端提交账号看到不同文件系统。
6. 开始前固定源、目标目录、真实地址、直连端口、用户名、已验证主机身份、同名策略及认证选择。后续修改服务器配置不改变本次执行。
7. B → A 则使用 A 的真实地址。A 作为发送方时，不要求填写自己的真实地址。
8. A 直连看到的 B 必须与客户端确认的 B 身份一致。不同 SSH 服务、不同 chroot 或不同文件系统映射不按同一目标处理；预检用同一临时位置的探测验证两条连接的可见性。

### 4.2 任务与凭据快照

任务历史记录地址、用户名和认证方式，不记录密码或私钥内容。每次执行固定使用当次取得的凭据；失败重试时重新取得凭据并检查配置，连接目标变化时重新确认，不静默转向其他服务器。

## 5. 直传认证与工具依赖

### 5.1 首版支持的认证方式

| 方式 | 用户操作 | A 上的要求 | 凭据行为 |
| --- | --- | --- | --- |
| B 的密码 | 选择使用 B 已保存的密码；没有则输入本次密码 | rsync、OpenSSH 客户端、sshpass | 经客户端到 A 的加密控制连接传入任务专用文件描述符，不写入命令参数、日志或远端密码文件 |
| A 上的私钥文件 | 填写或选择 A 上可读取的私钥绝对路径 | rsync、OpenSSH 客户端 | 私钥留在 A；首版要求可非交互使用，加密私钥自动解锁不在本期范围 |

共同要求：B 具备 SSH 服务、rsync，以及供客户端检查和提交使用的 SFTP；账号可执行 rsync 并写入目标目录。A 必须允许 SSH exec。本地上传只需要目标的 SFTP，不依赖 rsync 或 sshpass。

密码认证时，确认框明确显示“源服务器 A 将在本次传输中使用 B 的密码”。这是密码交给 A 使用的真实信任边界，即使不落盘也不能宣称密码不会到达 A。默认不新增密码持久化；若要保存新密码，沿用现有服务器配置的明确保存操作。

本机能用私钥或 Agent 登录 B，不代表 A 能使用这份凭据。不能自动把本机私钥路径当作 A 的路径，不能偷偷复制私钥，也不能暗中启用通用 Agent 转发。

### 5.2 非交互与主机校验

- rsync 是自动化传输命令；交互提示来自 SSH 认证，密码模式由 sshpass 处理。密钥模式认证条件不足立即失败。
- 传输过程不等待一个不可见终端中的密码、指纹或口令输入。认证失败回到应用内的明确操作入口，不无限自动重试。
- B 的主机身份使用现有已验证记录。首次信任通过客户端确认，A 上使用本次可信记录；不关闭主机指纹检查。
- 指纹不匹配、需要 MFA、密码过期、必须改密等返回具体原因，不尝试用密码回答任意提示。
- SSH 不分配承载文件协议的终端；sshpass 为认证使用的终端机制不能混入文件数据。密码通道与文件数据通道明确隔离。
- 不依赖 A 的个人 SSH 配置中的隐式跳板、自动命令或连接复用来改变本次连接目标。

缺少工具时说明缺少哪台服务器上的哪项工具，不自动安装，不默默切回旧脚本。必要的版本和能力组合通过预检与真实环境测试确定。

## 6. 用户操作流程

### 6.1 创建任务

1. 拖入本地项目，或者把 A 的选中项目拖到 B。
2. 拖到目录行上，以该目录为目标；拖到列表空白处，以当前目录为目标。普通文件行不作为接收目录。
3. 显示确认框：来源、项目数与路径摘要、目标服务器、目标目录、同名策略。直传额外显示 B 的真实地址、直连端口、账号和认证方式。
4. 默认同名策略为“自动改名”。选择覆盖时，按钮明确显示“确认覆盖并开始”。
5. 一次确认创建一个任务，重复点击不生成重复任务。任务目标固定，随后切换目录不改变它。

### 6.2 准备检查

本机上传检查本地来源、目标 SFTP、目录和权限。服务器直传额外检查：

- A/B 的工具及所需能力；A 的源文件可读。
- A 能连接 B 的真实地址和直连端口，身份与认证通过。
- B 的目标路径是可用目录；以最终目标所在文件系统创建任务私有临时目录。
- A 直连写入的探测数据，客户端能从 B 的同一临时位置读取并确认。
- 可获取时检查剩余空间。首版先完成本次暂存再提交，需为待传输内容预留额外空间，覆盖期间旧文件也仍占空间；预检不能保证传输期间空间一定充足。

建议连接/认证阶段超时为 15 秒，可配置；等待用户输入与网络超时分开。传输无进展持续 60 秒时显示停滞诊断，不仅凭“字节没增加”就断定进程停止或删除临时文件。

### 6.3 扫描与计划

扫描来源，确定项目映射、文件数、逻辑字节数和同名处理计划。扫描期间显示已发现项目数，不把未知总量显示成 0%。失败项有具体路径和原因。

默认复制选中的目录本身。例如把 A 的 `/data/images` 拖到 B 的 `/backup`，结果是 `/backup/images`，不能由 rsync 参数末尾斜杠偶然决定语义。

同一来源列表中的重复路径去重；同时选择父目录和其子项时只复制一次。不同来源映射到同一最终路径时，按同名策略生成确定结果，不互相覆盖。

### 6.4 传输、校验和提交

1. 内容写入本次执行的独立临时目录。
2. 本机上传通过 SFTP 写入并关闭文件；直传由 A 上的 rsync 发送到 B。
3. 上传确认写入字节数、文件关闭成功和远端文件类型/大小。直传须取得 rsync 成功退出、核对计划中的项目类型和大小；rsync 自身负责实际传输的数据校验。
4. 提交前重查源文件变化、目标冲突和必要权限。发现源文件变化，该项目不作为成功结果提交。
5. 客户端逐项提交最终文件，记录已提交结果。只在文件正式提交后增加“已完成文件数”。
6. 刷新受影响的目标目录，显示完成、部分完成或失败，并单独列出临时清理结果。

首版按一次传输执行成功后才提交该次结果；rsync 非零退出不把临时目录中的文件自动当作成功。多项最终提交发生失败时，已经提交的项目保留，剩余项单独列出并可重试。以后可优化分批提交，但必须沿用相同确认条件。

## 7. 内容、同名处理与完整性

### 7.1 复制规则

- 默认保留源文件；不删除目标目录中的额外文件，不启用镜像删除。
- 复制普通文件、隐藏文件、目录与空目录。符号链接、设备、管道、套接字及本地重解析点默认跳过并列出原因，不跟随链接递归。
- 保留可支持的修改时间；服务器直传尽量保留普通权限。本机上传不把 Windows 权限机械映射成 POSIX 权限。
- 不承诺保留所有者、组、ACL、扩展属性、硬链接关系或特殊权限位，不能简单以 `rsync -a` 的全部行为代替产品定义。
- 元数据保存失败与内容失败分开显示。对用户事先选择为必需的属性，失败应影响该项目结果。
- 空格、中文、引号、换行及以连字符开头的有效文件名须被当作路径处理；不通过拼接命令或解析逐行文件名处理。无法支持的名称在扫描时明确拒绝。

### 7.2 同名规则

| 情况 | 自动改名（默认） | 跳过 | 覆盖 |
| --- | --- | --- | --- |
| 文件对文件 | 生成确定的新文件名 | 保留目标，计入跳过 | 完整传输后原子替换目标文件 |
| 目录对目录 | 为冲突的选中根目录改名，复制其完整目录树 | 合并目录，跳过内部同名项目 | 合并目录，替换内部同名普通文件，保留额外文件 |
| 文件与目录类型冲突 | 为来源项目改名 | 跳过并说明 | 拒绝该项目，不能递归删除目标来腾位置 |
| 目标项目是符号链接 | 为来源项目改名 | 跳过并说明 | 拒绝替换或跟随，提示处理冲突 |

自动改名保留扩展名，例如 `export-docker-images (1).sh`。提交前再次检查，出现新的竞争冲突时重新分配名称或报告冲突，不擅自改用覆盖。

目标父目录可在开始前解析到真实路径并展示固定目标，但提交时必须重查其路径关系，不能在父目录被替换为其他链接后继续写入。

### 7.3 提交与校验保证

- 临时数据位于最终目标的同一文件系统，确保具备重命名提交的条件；跨挂载点的目录合并按最终文件所在文件系统重新安排临时位置。
- 覆盖要求服务器具备安全的原子替换能力，不能先删除旧文件；不具备时明确拒绝覆盖。
- 新建、跳过、改名不应因竞争而变成覆盖。后端须具备对应的非覆盖提交能力；不能仅凭“先检查不存在”就宣称并发安全。
- 保证单文件提交语义；不承诺合并整个目录是一笔可回滚事务。
- 提供可选的逐文件 SHA-256 复核，明确额外读取开销。远端需有经验证的摘要计算能力；缺少时显示该选项不可用，不静默跳过。直传在 A/B 上各自计算摘要，只传回摘要，不为校验而把文件内容下载到本机。不能把文件大小相同当作内容一致证明，也不能把 rsync 的大小/时间快速比较当作严格校验。
- rsync 恢复传输时必须验证复用数据与当前源文件的一致性，不能只信任大小/mtime 或盲目追加。
- 成功表示内容传输和最终提交获确认；不把普通 SFTP 关闭/重命名成功夸大为服务器断电后的持久性保证。
- 对正在修改的源文件，进行前后版本检查并报告变化；普通传输不提供数据库或整棵目录的时间点一致性，要获得该保证需先使用快照或应用备份。
- 应用内任务可协调。应用外程序仍可能修改目标，提交前应检测已知版本变化；不宣称能够锁住其他 SSH 客户端或提供跨所有程序的条件替换事务。

## 8. 并发与冲突

建议默认全局最多 3 个数据传输任务；达到数量限制时明确显示“等待传输名额”。这个限制是资源管理，不是对服务器的故障封锁。

数据传输期间，各任务使用不同临时目录，可以并行。最终提交按已验证的目标主机身份和规范化最终路径协调，不能只按服务器配置 ID，也不能仅因用户名不同就假定路径不会冲突。

| 关系 | 处理 |
| --- | --- |
| 同一服务器，不同目标文件 | 可以并行传输和独立提交 |
| 同一目录，两个不同文件 | 可以继续，不锁整个目录 |
| 同一最终文件或目录整体替换与子路径重叠 | 串行提交，等待方显示具体冲突任务和路径 |
| 旧任务只剩独立临时数据 | 允许新任务，清理作为另一项操作 |
| 旧执行是否停止未知，但只能写自己的临时目录 | 允许新任务使用新临时目录；旧目录不能复用或删除 |
| 最终提交回复丢失 | 只限制结果不确定的文件；目录整体操作按实际受影响子树限制 |

同一任务取得多个路径协调权时采用固定顺序，避免互相等待；长时间传输不持有整个服务器的提交锁。目标路径别名无法可靠辨认时，须明确保守处理相关路径，不能把所有历史未知任务一律扩大为服务器级隔离。

等待用户核对的冲突使用“需要处理”状态，提供核对、改名重试、更换目录或取消。不得用无期限轮询伪装成正常排队。

## 9. 任务状态与界面

| 主状态 | 含义 | 用户可执行操作 |
| --- | --- | --- |
| 等待传输 | 等待实际并发名额或正常进行中的冲突提交 | 查看等待对象、取消 |
| 检查连接与权限 | 工具、连接、认证、身份和目标检查 | 取消；按明确提示补充凭据 |
| 扫描项目 | 建立文件清单及同名处理计划 | 取消 |
| 正在传输 | 内容写入本次临时目录 | 查看进度、取消 |
| 正在校验 | 检查传输结果及可选内容复核 | 取消后保留尚未提交数据 |
| 正在提交 | 将完整文件提交为最终项目 | 请求取消，等待当前提交操作结果 |
| 正在取消 | 已请求停止，尚未确认执行结束 | 查看进度；超时后转为中断说明 |
| 已完成 | 所有应处理项目均已提交或按策略跳过 | 查看结果、清理可安全清理的残留 |
| 部分完成 | 部分项目已提交，其他项目失败 | 查看逐项结果、重试未完成项 |
| 失败 | 当前任务没有成功提交项目，执行已明确失败 | 修正原因后重试 |
| 已取消 | 停止已确认，取消之前的已提交文件保留 | 查看结果、重试未完成项 |
| 已中断 | 控制连接丢失，尚不能确认执行结果 | 重新连接核对；允许使用新临时目录重新执行 |
| 需要处理 | 具体最终文件结果不确定或等待用户决策 | 核对该文件、改名/更换目录或取消等待 |

“临时文件待清理”是独立附加状态，不代替主结果，不阻止新任务。已确认内容完成但清理失败时显示“已完成，有待清理内容”，不能变成“状态待确认”。

任务卡显示来源、目标、直传实际地址、总量、当前阶段、当前文件、已传输字节、已提交文件数、速度和可用时的剩余时间。rsync 断点复用时，逻辑处理量与网络实际发送量要区分。

扫描结束前总量显示“正在统计”。传输阶段达到 100% 后仍显示校验/提交阶段，只有最终提交完成才显示整个任务完成。不能仅解析 rsync 的可读进度文本来判断文件成功，进度解析失败不影响退出码和结果检查。

主要错误保留阶段、服务器角色、地址、路径、工具退出码和经过脱敏的诊断。停止、清理失败单独显示，不覆盖认证失败、磁盘已满等最初原因。

## 10. 取消、重试、恢复与清理

### 10.1 取消

正常取消通过本次执行的活动控制连接请求终止，并等待传输执行退出。不能通过一个旧 PID 文件去杀可能已被复用的进程。关闭 SSH 通道或 socket 本身不是远端进程已经停止的证明。

建议停止等待 15 秒后给出明确中断结果，不无限显示“正在取消”。未取得结束证明时保留旧临时目录，显示“远端可能仍向本任务临时目录写入，尚未提交到最终位置”。具体的退出证明和取消控制方式是实现前必须验证的技术项，不能预设所有 SSH 服务都支持同一种 signal 行为。

已经提交的文件保留；未提交的文件不再自动提交。不可中断的单次原子提交等待结果；回复丢失时只核对该项目。

### 10.2 重试与断点复用

“重试未完成项”保留已成功项目，重新检查来源、目标、凭据和同名情况。源文件发生变化时重新传输该项目，不能把旧部分数据当作完整文件。

只有确认旧执行已结束，才能复用其临时数据并由 rsync 校验、恢复。无法证明旧执行停止时，不提供“复用旧数据继续”；可以重新执行到新的临时目录，旧目录留作稍后处理。首版本机 SFTP 上传重试未完成文件时从头上传，不承诺与 rsync 相同的字节级续传。

自动重试仅用于尚未写入或已证明安全的短暂操作，限制次数并可取消。密码错误、主机指纹变化、权限问题、源变化和提交结果不确定不进行盲目自动重试。

### 10.3 断线和应用重启

分别保存任务主状态、已提交项目、每次执行的临时路径和待确认提交项目；凭据不写入任务记录。成功的提交应及时记录，单次提交前也记录操作意图，支持回复丢失后的精确核对。

启动后不把所有历史记录统一改成未知。完成记录仍是完成；仅临时清理未完成的保留清理提示；未结束执行显示中断；只有提交意图未获结果的路径进入结果核对。

核对先读取相关文件与临时数据，判断已完成、未提交或仍不确定。不凭大小相同就确认成功，不自动删除目标文件或重做一次覆盖。最终结果仍不明确时，清楚说明具体路径，并允许用户改名传输到另一路径。

退出应用时说明正在运行的任务，允许返回或取消后退出。异常退出不能保证远端立即停止，但旧执行只会写本次临时目录，客户端重开后不能未经核对自动提交。

### 10.4 清理

确认执行停止或完成后，清理该执行明确登记的临时资源；清理失败允许稍后重试。可以从任务卡查看临时位置和大小。

未知执行的目录不能只因“时间过去很久”就判定安全并删除。手动清理同样需要确认执行已结束；不提供伪装成普通清理的一键强制终止所有进程。

清理操作只处理本任务专用资源，验证归属与路径，不递归删除任意用户目标目录。临时数据占用空间应明确提示，但这不是服务器级的传输禁用条件。

## 11. 上线前的验证条件

以下技术条件由实现和集成测试验证：

1. A 上 sshpass 能通过专用输入通道完成密码认证，密码不进入命令参数/日志，且不干扰 rsync 协议流。
2. 活动 SSH exec 的退出状态、取消行为及连接丢失能被准确区分；未确认停止时不会提交或清理旧临时目录。
3. B 的 SFTP 能满足需要的原子覆盖与非覆盖提交语义，尤其在目录合并及不同挂载点下。
4. rsync 的版本/能力组合支持有效文件名、断点复用校验和明确退出结果；不依赖易变的可读输出作为成功证据。
5. 本地仅有私钥的用户能清楚看到首版直传认证边界，不能误以为应用会自动把该密钥交给 A。

这些条件若无法满足，应调整明确的支持范围或认证方案，不隐藏降级，也不重新引入一套未经验证的远端监督协议。

## 12. 验收清单

| 场景 | 预期结果 |
| --- | --- |
| Windows 资源管理器拖文件、目录、多选到主窗口或拆分窗口 | 正确命中目标并创建上传任务 |
| A → B 使用不同于普通地址/端口的真实地址/端口 | 从 A 访问真实地址；客户端管理连接仍沿普通路径 |
| B 没有真实地址 | 明确要求补齐，不回退普通地址 |
| 已启动后修改 B 配置 | 原执行目标不变，后续新任务使用新配置 |
| A 未安装 sshpass，使用密码认证 | 预检明确指出 A 缺少 sshpass，不一直等待密码 |
| 密码错误、需要 MFA、主机指纹变化 | 分别说明原因，无无限重试、无绕过指纹检查 |
| A 上密钥认证；本机只有私钥 | 前者可正常使用；后者明确显示当前首版不支持该直传凭据来源 |
| B 只有 SFTP，或 B 缺少 rsync | 直传明确不支持；本机上传仍然可用 |
| A → B 文件传输失败，随后本机上传到 B 的另一个文件 | 新上传正常执行，甚至目标目录相同也不被旧临时任务阻塞 |
| 两项任务提交同一文件 | 按同名策略和提交顺序处理，等待方能看到具体任务和路径 |
| 一项任务的最终提交回复丢失 | 仅相关路径需要核对，其他文件仍可上传 |
| 单文件传输中断、目标磁盘已满或取消 | 源文件及目标旧文件保留，不把部分内容提交成完整文件 |
| 执行结果未知时重新执行 | 使用新临时目录，不与旧执行共同写同一个临时文件 |
| 已证明停止后恢复大文件 | 验证旧数据并复用，最终内容正确 |
| 目标文件在确认后被其他程序修改 | 检测到的版本变化作为冲突处理，不静默沿用过期判断 |
| 非零 rsync 退出、源文件变化 | 不把该次临时结果直接标为成功并提交 |
| 清理失败、重启应用 | 原任务的内容结果和待清理状态分别保留，不重新封锁服务器 |
| 中文、空格、引号、换行、零字节、隐藏文件、空目录、多级目录 | 正确复制或在明确支持边界内给出具体拒绝原因 |
| 同名文件夹合并与自动改名、文件/目录类型冲突 | 与设计表一致，不删除目标额外文件或目录 |
| 同一主机别名、不同用户名共享目录、跨挂载点目标 | 不绕过冲突协调或提交能力检查 |

验收必须包含真实 Windows 原生拖放、真实 A/B Linux SSH 环境和断网/磁盘满/取消注入。浏览器模拟 IPC 测试只能覆盖界面行为，不能替代真实传输与故障恢复验证。

## 13. 实现边界

新执行器、独立任务存储和界面按上述规则实现。普通服务器配置及真实地址字段沿用现有结构。旧 JSON 回执、旧远端任务目录不迁移、不自动执行或清理。

取消使用当前控制连接取得的进程身份，请求终止前验证 Linux 进程启动时间和独立进程组；不持久化 PID、不在重连后按旧 PID 杀进程。无法取得两端退出记录时保留中断状态，允许新目录重试。进度来自 rsync 的逻辑处理量，不等同于实际网络流量。

支持范围为普通文件与目录复制，不承诺应用级快照一致性、跨客户端互斥或服务器断电后的落盘保证。目标版本复查仅检测可观察的大小、mtime 和权限变化。
