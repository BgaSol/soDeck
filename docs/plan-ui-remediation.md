# 全页面体验修复方案

日期：2026-11-07。状态：R01–R22 及末轮独立复查发现的问题均已修复并复验，Windows x86_64 最终构建及原生冒烟通过；五平台发行与升级验收正在收尾。实际结果与未完成项统一见 [实施与验收](implementation-ui-remediation.md)。R23 继续暂缓。

本方案承接 [impeccable 逐页评审](../.impeccable/critique/2026-11-06T22-06-41Z__src-main-ts.md)，并核对当前源码与测试入口。目标是修复真实操作问题，再优化任务入口、空间分配和恢复提示；不替换现有工作台、浅色、深色和多巴胺主题。

职责边界继续执行 [开发约定](../AGENTS.md) 和 [架构说明](architecture.md)。核心负责通用焦点、主题、连接、组件宿主和诊断入口；文件、终端与网络隧道的业务交互留在各自插件。本文只维护本轮 UI 整改及验收。

## 1. 目标、范围与方法

### 用户任务

- 运维熟手：迅速找到服务器、连接、切换组件；刷新不打断键盘或鼠标操作。
- 首次用户：看懂新增、连接、插件安装和恢复入口，完成真实操作，不增加强制教程。
- 键盘及低视力用户：Tab 顺序完整、焦点持续、选中文字可读、字号设置实际生效。

### 方案取舍

1. 先修已复现的缺陷，再做 P2 布局与文案；此前没有发现独立问题的页面只回归，不为覆盖页数制造改动。
2. 使用 impeccable 的 harden、layout、onboard、clarify、audit 和 polish 指导相应阶段。当前已有产品范围和明确问题，不重复访谈、不重做视觉方向；实施前读取 craft-floor，修改后查看实际渲染结果。
3. 按 ponytail 采用最小完整修改：复用已有渲染函数、组件设置、Clipboard、openView、日志与更新入口，不新增生产依赖、UI 框架或通用表单/错误处理平台。
4. 每个 R 项对应一个用户可见问题，单独实施、验证和提交；阶段用于排序，不合并成一个巨型提交。
5. 不修改认证存储策略、远程路径规则、插件启停/升级的重启语义，也不增加插件市场、签名链、权限声明或审批。

## 2. 第一阶段：恢复可靠操作

建议首先完成 R01–R04。三个 P1 根因和文件字号缺陷都能稳定复现，应补行为回归。

### R01 / P1：设置弹窗键盘操作完整且不中断

**问题：** [main.ts](../src/main.ts) 的 Tab 循环名单漏掉 `summary`、链接和 textarea，未在名单内的焦点被送回关闭按钮；[ui.ts](../src/ui.ts) 的 `replace()` 仅按元素 ID 或特定 summary 保存焦点，设置导航/主题按钮在内容变化后会失焦。未变化的 HTML 已有跳过处理，不能把它误判为持续刷新问题。

**改动：**

- 保留现有弹窗结构，只修可聚焦集合与首尾循环判断。包含原生按钮、输入、select、textarea、链接、summary 和显式可聚焦元素；排除隐藏、禁用、inert、负 tabindex 及关闭 details 内不可见的子项。
- Tab 在最后一项循环、Shift+Tab 在第一项循环；焦点不在集合中时采用明确入口，不提前截断正常原生顺序；无可操作项时给弹窗本身焦点，避免落到背景。
- 对应用导航、组件导航、主题选择等稳定控件优先补稳定 ID，复用 `replace()` 已有恢复逻辑；只在无法由稳定 ID 表达的已知重复控件上按现有 data 标识恢复，不增加通用 DOM diff 系统。
- 返回插件列表等主动导航到不同页面时进入新页可用入口；刷新、切换选中主题时保留对应控制焦点；关闭仍回原入口，入口不存在时回设置按钮。
- 检查 settings 页新布局后的 DOM 顺序；不改变状态浮层允许背景操作的现有行为。

**验收：** 插件来源/技术信息、更新说明/原因/待应用清单、四类组件偏好能仅用键盘完成；Tab/Shift+Tab 首尾循环正确；关闭 details 后不进入隐藏控件；点击或键盘切换主题后焦点不回 BODY；Esc 和关闭返回有效入口；输入选区、展开状态和滚动不丢失。

**验证落点：** 在 `scripts/test-production-ui.mjs` 覆盖真实主壳的焦点循环、导航/主题切换及刷新；`scripts/test-settings-ui.mjs` 保留草稿和实际字段节点回归。现有设置专项夹具没有完整主壳，不能单独证明 main.ts 的焦点循环正确。

### R02 / P1：网络规则刷新不打断交互

**问题：** [网络 view.js](../plugins/network-proxy/ui/view.js) 每 800ms 无条件重建管理列表或详情；规则取得焦点后约 900ms 焦点落到 BODY。详情只对两个检查输入作特殊保护，其他控件仍被替换。

**改动：**

- 保留现有请求节奏、可见性判断与 pending 互斥；本轮不改变网络协议或请求服务。
- 按现有规则 ID 保留列表行，只增删变化的规则；状态、地址、流量、按钮文字/可用状态原位更新。
- 同一规则详情保留 DOM，只更新动态字段；用户切页或选择另一规则时才建立新结构。
- 现有事件委托继续使用；保留 scrollTop、展开区、检查输入、删除确认对象和键盘焦点，不在每次刷新时重置。
- 按压期间避免布局更新移动目标；正常抬起只执行一次，拖出或取消不执行。规则真正被删除时取消旧操作，并将焦点落到邻近规则或新建入口，不能转到别的规则。
- 先在网络插件内完成小范围更新；只有核心与该插件确实需要同一能力时再评估共享，不能直接依赖宿主内部模块。

**验收：** 聚焦规则、启动/停止、分页、summary、复制入口和检查控件后，连续多个刷新周期焦点/输入/滚动保持；刷新穿过 pointerdown/up 仍执行一次；相同快照不替换当前规则节点；切页和规则移除有合理焦点；收起、移窗和断线不改变监听生命周期。

**验证落点：** `scripts/test-network-ui.mjs` 在实际插件 iframe 中加入节点身份、键盘、按压刷新和检查输入回归，经 `npm run network:test` 运行。等待以实际刷新/状态事件为准，不仅靠一次固定900ms截图。复用现有隔离 OpenSSH/回环服务，不新增测试服务器框架。

### R03 / P1：浅色选中文字达到对比度要求

**问题：** [themes.css](../src/themes.css) 的 `#7661d1` 与 `#f0ecfc` 组合约4.11:1；[shell.css](../src/shell.css) 的选中导航、主题文字使用该组合。

**改动：** 不修改全部紫色；优先让这些选中文字使用现有、对比度达标的文字颜色，并保留选中背景、边线、勾选和焦点提示。若实际仍需紫色文字，再增加一个用途明确的强调文字 token，覆盖三主题与 forced-colors，不建立新色板。

**验收：** 已报告12/13px文字及所有使用同一组合的小文字至少4.5:1；选中状态不只靠颜色；浅/深/多巴胺及高对比模式焦点可见；主按钮和其他状态颜色无意外变化。

**验证落点：** 正式前端测试读取实际 computed styles 并计算对比度；核对背景透明度/叠加，不能只比较 CSS 字面量。已有主按钮、链接、禁用和 hover 状态同时目视检查。

### R04 / P2：文件名称字号真实生效

**问题：** [文件 style.css](../plugins/files/ui/style.css) 的 `.tree-name` 末尾固定12px覆盖变量；偏好设18px时实际仍12px。

**改动：** 删除覆盖，沿用 [tree.js](../plugins/files/ui/tree.js) 的设置应用；检查合法字号与行密度组合，必要时只调整名称行高，不能静默改写用户保存的密度或全局字号。

**验收：** 合法最小/默认/最大字号均体现在真实文件、目录、选中和深层节点；紧凑/普通/宽松密度不裁切文字；隐藏/展开、切服务器、重挂载、保存重开仍生效；原有名称截断与完整路径提示有效。

**验证落点：** `scripts/test-files-ui.mjs` 在实际文件插件树节点上检查计算字号及几何；`scripts/test-settings-ui.mjs` 继续验证保存，但不能以设置值保存成功代替真实树生效。

## 5. 第四阶段：让用户看懂状态并能恢复

### R17 / P2：连接失败有持续、就地的下一步

- 保留现有失败站次、阶段和技术原因，优先在连接卡/工作台中展示“什么失败、哪里失败、现在能做什么”。toast继续提供即时提醒，但不承载唯一错误信息。
- 复用现有重新连接、继续确认和编辑资料动作；不增加自动重试/自动重连，避免重复执行业务操作。
- 凭据失败沿用重新补填；取消继续是取消，不显示为服务器故障。断线只对已有保留草稿作准确说明，不能承诺恢复原shell/应用重启恢复任务。
- 验收DNS/TCP/SSH认证/跳板失败、取消和断线；五秒后仍能找到错误与重试，成功后旧错误消失，迟到结果不覆盖新会话。
- 主要文件：`connections.ts`、`server-views.ts`、`components.ts`；扩展连接UI与SSH集成回归。

### R18 / P2：主机指纹易于核对

- 在首次/变更指纹旁提供复制；旧、新指纹分别标明，使用既有核心Clipboard能力。
- 复制不表示信任；信任仍只通过现有确认动作。失败显示复制失败，不自动继续连接。
- 验收复制内容准确、Tab顺序完整、窄窗长指纹换行可读，取消/不信任仍终止相应流程。
- 主要文件：`connections.ts`；连接UI回归，真实SSH确认流程保持。

### R19 / P2：插件和应用状态错误有适当恢复入口

- 先复用现有插件详情、日志、重试应用/下载和统一重启；按实际状态选择入口，不能给不存在的“热重启插件”。
- 一般异常直接说明操作失败并保留原始详情；未知错误不能凭字符串猜成密码错误或承诺重试必成功。网络客户端连接失败与整条规则停止区分展示。
- 终端/文件/网络的业务提示留在各插件，不在核心新建全球错误码翻译框架；分别提交受影响模块，复用其已有错误状态。
- 验收查看日志确实定位相应插件；插件关闭/待重启/异常区别清楚；重启前现有任务/连接结束提示仍有效；普通error日志不自动变通知；未知错误仍可复制或查日志。
- 主要文件：`views.ts`、`plugin-settings.ts`、`main.ts`及需要补提示的各插件view；真实插件错误和更新回归。

### R20 / P2：统一容易误解的名称和介绍

- 代理目录说明为“用于服务器访问路径的SOCKS5代理资料”；网络组件说明为“在本机启动的SOCKS5入口”。保留运维熟悉的SSH、SOCKS5、PTY术语。
- 官方文件插件介绍与已实现的目录浏览、上传下载、文件管理和小文本编辑范围一致；不宣称断点续传、任意大文件编辑或跨服务器复制。
- 核心/插件消息空态统一为“核心和插件的重要消息会保留在这里”；空未读与无历史消息分别说明。
- 验收介绍与现有能力相符、三主题小窗口不挤压按钮；不增加安装或启用确认。
- 主要文件：`server-views.ts`、`src-tauri/src/official_plugins.rs`、`views.ts`；格式/类型、正式前端渲染和功能说明核对。

### R21 / P2：日志筛选能一键复位且便于阅读

- 增加“清除筛选”，一次复位来源、级别、正文、开始/结束时间；暂停状态保持，不偷偷恢复实时显示。
- 时间、来源等关键元数据统一提高到适合当前桌面密度的12px附近；正文/行间距同步目视核对，不把全应用改成大字号。
- 复位刷新仍遵守现有请求代次，旧筛选结果不能迟到覆盖新结果；操作后焦点落在有效控件。

- 主要文件：`views.ts`、`main.ts`、`shell.css`；真实日志服务加界面集成。当前 `catalog-fixture` 未暴露 read_logs/read_messages/mark_read，需按测试需要转发已有核心方法，不能拿“不支持测试命令”作为产品缺陷或用永久空数组替代回归。

### R22 / P2：固定的使用帮助入口

- 主要文件：`views.ts`、`main.ts`；正式前端链接分发回归。若现有打开函数限定Release用途，增加一个明确的帮助动作复用相同底层能力，而不是扩大成任意URL接口。

### R23 / 后续增强：消息跳转到相关业务任务

此项是评审中的增强建议，不是已复现缺陷。当前 [Message/PublishMessage](../src-tauri/src/model.rs) 只有插件/实例来源，没有服务器、视图、资源或任务定位字段；不能按标题/正文解析或按当前选中服务器猜测跳转。

## 7. 验证和交付顺序

### 每项修改的最小验证

1. 对稳定缺陷先保存复现，然后补能在修复前失败、修复后通过的行为回归。不要只测模板字符串、保存值或截图存在。
2. 执行相关格式、类型、构建和测试：核心TS/CSS改动使用 `npm run check`、`npm run web:build` 和相关界面入口；改Rust/测试夹具时运行相应 `npm run test`；改构建/测试脚本时运行 `npm run scripts:test`。没有现成的 `npm run format`，不在计划中编造入口。
3. 插件修改运行 `npm run plugin:check` 与该插件构建；终端/文件/网络分别通过 `npm run terminal:test`、`npm run files:test`、`npm run network:test` 进入实际插件界面与远程集成。OpenSSH及既有测试工具前提以 [开发指南](development.md) 为准，不能直接无环境运行 test-*-ui.mjs 并称已验收。
4. 低影响文案/图形调整复用现有行为测试及目视核对，不单独写逐字镜像测试。焦点、竞态、任务分组、草稿内容与链接边界必须有行为回归。
5. 完成相关检查后再推进下一项；只有后续改动或新失败影响先前行为时重跑对应测试，不每项重复全部远程/弱网测试。

### 阶段整合与场景矩阵

核心整合运行 `npm run ui:test`；实际xterm输入保持 `npm run terminal:input:test`。网络协议未改时不重新跑全部netem配置；新结果表明协议/资源有影响时再选相关配置。

| 维度 | 必须覆盖的实例 | 完成标准 |
| --- | --- | --- |
| 窗口/主题 | 1100×720、720×480；浅、深、多巴胺；跟随系统切换 | 主动作可见/可达，弹窗字段能滚动，无意外横向溢出 |
| 字号/DPI | 已支持的字段边界；桌面100%、125%、150%、200%可获得的原生缩放 | 命中区、文字和布局正常；CSS zoom结果不能替代原生DPI验证 |
| 输入 | 鼠标按压期间刷新、Tab/Shift+Tab、Enter/Space、Esc、输入法 | 不漏动作、不重复、不抢焦点，终端控制键与编辑行为保持 |
| 内容 | 0/1/多条；长中文/英文/emoji名称、长IPv6/路径/指纹；联合筛选无结果 | 对象明确，截断有可访问完整信息，错误/首用/无结果不混淆 |
| 异步/故障 | 等待、失败、取消、保存冲突、旧响应迟到、部分任务失败/结果未知 | 输入/草稿不丢，旧结果不覆盖新状态，恢复入口真实有效 |
| 生命周期 | 插件未安装/关闭/待重启/异常；隐藏/移窗/断线/重连 | 不跨工作区执行旧动作，不改变端口、PTY、任务所有权与清理 |
| 可访问性 | 对比度计算、可见焦点、原生高对比、减少动画、屏幕阅读器 | 状态不只靠颜色；动态数据不反复播报整个页面；焦点顺序符合布局 |

五个正式支持目标的实际发行验证继续采用现有 GitHub Actions 和 [分发流程](distribution.md)：Windows x86_64/ARM64、Linux x86_64/ARM64、macOS ARM64。每个受影响核心或插件产物分别原生编译、打包，并验证实际包内程序启动/退出；ARM64不用x86仿真产物。真实桌面键盘、剪贴板、混合DPI等行为另记录设备证据，浏览器夹具不能代替。
