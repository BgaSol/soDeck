# SoDeck 0.23.0

核心新增文件操作、编辑草稿与网络监听的结果确认能力，配合文件插件 0.10.0 和网络隧道插件 0.4.0 使用。核心 API 主版本保持 1，新增能力分别为 `files.operations.v2`、`files.editor.v1` 与 `net.listenerLifecycle.v1`。旧插件仍可加载，但其旧业务决策不属于新协议保证；新插件遇到缺少能力的核心会明确拒绝初始化。

- 文件批次保留原操作身份。回执丢失时暂停并查询原请求，结果记录持久化后再释放回执，避免把通信错误变成重复操作。
- 编辑器按接纳时的固定修订保存和导出。旧保存不清除后续输入，分片失败可恢复；提交回包丢失标为未知，成功提交后属性查询失败仍保留成功事实并阻止继续覆盖。
- 网络监听分开记录实际资源状态与查询错误。停止请求不是清理完成；监听、流和后台任务全部退出后才允许重新启动或删除规则。
- 关闭与跨窗交接检查原 Surface 身份，迟到的输入同步回执不能完成后来的交接。导出对话框和写入也参与资源清理。

## 功能边界与升级

文件插件 0.10.0 在当前后端禁用移动、剪切和改名，删除复制后删源的回退。复制、上传和下载保留源；提交未知时保留原身份和临时路径供核对，不自动重放或回滚。保存与明确覆盖仍面向没有其他写入者的普通文件操作，不提供原子版本比较或协同编辑。

网络隧道插件 0.4.0 将保存、启动、停止和删除分成独立动作。保存新规则不替换正在运行的监听；先停止并确认清理完成，再启动应用配置。

先升级核心并重启，再升级上述插件并重启。核心安装包仍不包含业务插件，各组件独立版本和更新。没有新增生产依赖、插件授权体系或发布状态机。

详细行为统一维护在[文件](../features/files.md)、[网络隧道](../features/network-proxy.md)、[生命周期](../features/lifecycle.md)与[插件 API](../plugin-api.md)。本轮也收敛了文档职责，完成的设计归入功能文档，临时计划仅保留未完成项，旧设计历史通过 Git 查询。
