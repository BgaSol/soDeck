# SoDeck 0.18.0

发行日期：2026-11-09。

## 更新与插件下载加速

更新检查、官方插件目录、发行清单、核心更新包、插件首次安装和升级共用下载线路。GitHub 直连失败后自动切换启用的备用地址；内置 7 个地址，文件专用线路只参与文件下载，近期成功线路优先。单个节点失败不会阻止后续下载尝试。

设置 → 软件更新 → 下载与网络支持添加最多 10 个自定义 HTTPS 转发前缀，以及编辑、排序、启用/停用和删除地址。单地址测试检查 API、目录、清单和包首段，结果只代表该地址当前的连通情况，不代替完整包校验。保存冲突时保留输入。

下载失败清理临时文件后重新尝试，不拼接不同节点的内容；核心继续使用 Tauri 官方签名验证和安装，插件继续使用 SHA-256、解包与清单检查。缓存保留原始 GitHub URL，已准备包继续支持离线恢复。未新增生产依赖，业务插件版本与独立分发保持不变。

## 升级与限制

已安装客户端可按原更新流程升级核心。旧客户端需要先能够访问 GitHub 或手动下载安装本版本，升级后才具有备用地址功能。

公共代理可能限流、失效或缓存旧资源，多个域名也可能共享上游；本轮没有覆盖大陆不同运营商网络。核心签名保护核心包，插件哈希保证包与清单一致，代理仍参与元数据传输。

## 验证与发行来源

功能实施阶段在 Windows x86_64 完成类型、格式、90 项脚本与 219 项 Rust 测试、正式前端更新专项及实际 NSIS 包程序启动/重开/退出。公网验证完成真实核心 0.16.0 下载和官方验签、终端 0.6.0 下载/哈希/解包/登记；这些历史结果不代替本版本的合并后和五平台发行验收，详见[实施记录](https://github.com/BgaSol/soDeck/blob/8115fdcd5bed4108021a729da605fbde77afc2af/docs/implementation-update-acceleration.md)。

整合最新 main 并升至 0.18.0 后，本机重新完成类型/格式、文档、91 项脚本、207 项 Rust 测试（12 项远端用例按标记跳过），以及正式前端更新专项（8 类验收、无页面错误）。

同一包来源的 [Check #42583439980](https://github.com/BgaSol/soDeck/actions/runs/42583439980) 全部通过：类型、格式、前端、脚本、五平台原生核心测试、完整 Windows UI/SSH，以及 Linux x86_64/ARM64 普通网络与所选插件业务回归。netem 未选择。

五平台原生正式构建、updater 签名、实际安装/解包、架构、启动、工作台移窗、资料重开及退出通过；Windows x86_64 包内 SSH 通过。首次 Windows 两架构下载 NSIS 辅助 DLL、Linux ARM64 下载 AppRun 时遇到 GitHub HTTP 504；首次 metadata 在创建草稿后报告 `Core release changed while uploading`。只重跑同一运行的失败目标和汇总，保留已通过的 macOS ARM64、Linux x86_64 包，第二次完成全部验收和附件上传，没有创建第二份打包来源。

本机授权下载草稿的全部 16 个附件，逐个核对大小/SHA-256，确认五目标更新清单使用该版本的原始 GitHub URL，签名字段与对应附件一致。草稿的公开下载 URL 对公共代理不可见；一次较大 AppImage 授权下载超时后重试通过。发布收尾只同步版本说明与更新清单的 notes，不改变包、下载 URL 或签名。
