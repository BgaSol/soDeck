# SoDeck 2.6.0

- 配置使用同目录独占临时文件提交；失败保留原目标，核心保留已有文件模式，改进 Windows 长路径兼容。登录项短时文件写入复用同一机制，流式导出/更新包保留原生命周期。
- Windows 数据目录安全简化，长路径和特殊名称保留扩展形式；本地来源支持相应普通文件，仍拒绝设备、数据流和重解析文件。
- SFTP 扩展参数统一使用 SSH 协议库编码，保留保存/复制的确认与未知结果边界。
- 修复 macOS 保留旧版登录项时，进入“设置 → 应用与数据”触发原生崩溃：旧项状态查询改用系统实际的 Objective-C 方法 `statusForLegacyURL:`。页面读取不迁移、删除或重新启用登录项。

边界见[架构](../architecture.md)，依赖与基准入口见[开发指南](../development.md#解析依赖与性能基准)。MCP、Docker、文件和网络插件独立发行，核心包不含这些插件。

## 验证与发行

待发行。包来源、原始打包、五平台源码/实际包、远程组合、升级和公开附件摘要在本次验收后补齐。

原生 macOS [修复前回归](https://github.com/BgaSol/soDeck/actions/runs/45724980642/job/139592556440)直接执行旧项状态查询，验证错误的方法名会导致原生调用失败。2.5.2 的线程假设未得到证实，其隔离探针未执行系统查询；本版撤回该调度，保留原有后台系统 IO。新的包验收在迁移前用真实登录启动服务读取旧项，并核对读取不修改原文件或主应用登记；随后验证迁移、重复开关和关闭后进程继续运行。

## 性能范围

文件树优化已加载节点重复刷新；核心日志保留 500 条和完整正文；Docker 保留现有可变行高虚拟布局，仅调整分页预算。局部浏览器与真实插件 RPC 数据保存在本目录 JSON，不代表原生 WebView、远端 IO、磁盘扫描、持续吞吐或长期内存专项。
