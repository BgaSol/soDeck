# SoDeck 1.8.1

- 新增 session.program.v1：当前会话有界环境探测，POSIX/Windows 程序参数编码，复用原 exec/stream/PTY 的归属、票据、期限和回收。
- 非交互模式以明确启用的启动前导区分身份检查失败、程序未启动与原始业务输出；Windows 保留字节和实际退出码，兼容 cmd/PowerShell 默认 shell。
- 探测原始输出与 JSON 转义后的结果均受同一 16 KiB 预算限制；超限直接失败，不继续尝试其他平台方案。
- 原 command 接口、插件 API 主版本和现有插件保持兼容；Docker 0.6.0 独立提供自动/手动端点发现及 Windows CLI/npipe。无新增生产依赖。

契约见[插件 API](../plugin-api.md#sessionprogramv1核心-181)，业务边界见[Docker](../features/docker.md)。[1.8.0 候选](v1.8.0.md)因环境结果预算遗漏而放弃，没有正式发布；本版使用新的固定源码打包。

## 发布与验证

包来源：[6743fec01c2df632ba6755aefdb01842b9396de5](https://github.com/BgaSol/soDeck/commit/6743fec01c2df632ba6755aefdb01842b9396de5)；[来源 Check](https://github.com/BgaSol/soDeck/actions/runs/44517855421)；[原始五平台打包与实际包验收](https://github.com/BgaSol/soDeck/actions/runs/44517860276)。

Windows x86_64/ARM64、Linux x86_64/ARM64、macOS ARM64 均使用原生 runner，安装器/更新归档的来源、大小、SHA-256、资源、官方 updater 签名、包内启动、资料重开与退出均通过。核心包与 Docker 插件分别打包、分别验证。

来源 Check 的全部选中检查通过：五平台源码、类型/格式/脚本、浏览器、Windows 桌面、网络及真实 SFTP/PTY/系统状态/Docker/MCP/组件通信。首次 Linux 业务 job 在 Ubuntu 镜像同步期间遇到包索引大小不一致，依赖安装退出 100，业务测试尚未开始；只重跑该失败 job 后通过，同一源码和已经成功的包均保留。netem skipped。

发行：[SoDeck 1.8.1](https://github.com/BgaSol/soDeck/releases/tag/v1.8.1)。直接发布原始 run 的同一草稿附件，程序与签名字节不重建、不覆盖；草稿阶段同步说明与更新清单 notes。[永久发行证据](v1.8.1-assets.json)保留原生包报告、来源、附件摘要和全部公开附件的匿名下载核验。Docker 0.6.0 独立发布并按用户要求标记为 GitHub Latest。

本机 Windows 类型/格式、190 项工程脚本及完整核心测试（306 通过、14 项专项 ignored）通过，核心 1.8.1 的 Windows x64 正式构建完成。已稳定复现 JSON 转义膨胀：探测原始数据不到 16 KiB，序列化后超过预算。新增解析回归验证恰好 16 KiB 成功与多一字节失败；SSH/RPC 集成回归验证超限结果不提交，且只尝试一次探测。

最终源码的真实回环 OpenSSH/Docker Desktop 4.96.3（CLI/Engine 29.9.2，Windows amd64 客户端、WSL2 Linux amd64 Engine，desktop-linux/npipe、Root /var/lib/docker）完整流程在 394.95 秒通过：四类资源、详情/指标、中文历史日志、容器 PTY、来源关闭后独立终端、维护/删除/拉取及断线捕获保留。隔离 OpenSSH/Linux Docker Engine 24.0.9 的同一完整业务流程通过，保留自定义 Root 与挂载卷。Windows Server Engine 的进程模拟不计为真实 Engine 验收。

未执行 Windows Server Engine、ARM64 Docker 远端、五平台实际包 SSH 组合、旧版安装升级、netem 或新增物理 IME/DPI/读屏专项，剩余要求见[待验收计划](../plans/docker-windows.md)。
