# SoDeck 0.13.0

核心提供事件驱动的共享运行状态，插件通过版本化 RPC 或真实页面挂载贡献和订阅同工作区的事实。晚打开的组件先取得当前快照，再接续变化；来源、服务器、重连与窗口边界由核心校验，插件停止时清理其贡献。条件写入、分帧确认、租约、积压与内存限额保证慢消费者不会阻塞生产者。

本次同时独立发布终端 **0.3.0**、文件 **0.5.0**、系统状态 **0.3.0**。文件侧栏默认跟随当前活动终端的可靠目录，开关可保存；手动浏览、隐藏、移窗与重连按当前状态接续。系统状态在后台提供挂载和容量，文件树原位标注，过期和未知数据明确区分。请先更新核心，再更新这三个插件并重启。

终端目录需要正确配置 OSC 7，并在“目录报告主机名”中填写同一文件系统的远端主机名；留空禁用。没有自动修改远端 shell 配置。同主机名容器、chroot 和嵌套 shell 无法自动识别，进入前关闭跟随；UNC 和未知文件系统视角不做路径猜测。Linux 挂载拓扑使用 mountinfo，Windows 与 macOS/BSD 仍声明部分覆盖。

没有新增生产依赖、插件权限系统或持久状态数据库；核心和业务插件继续独立打包、升级，旧核心或生产插件缺席时保留原独立功能。详细设计及本机证据见[实施记录](https://github.com/BgaSol/soDeck/blob/8115fdcd5bed4108021a729da605fbde77afc2af/docs/implementation-component-communication.md)。

## 验证与交付

本机 TypeScript/Rust 格式、87 项脚本、167 项核心测试、SDK 与插件源码、工作区/连接/设置 UI、真实 SSH/PTY/SFTP 三插件组合、正式前端与 Windows x86_64 EXE 启动/移窗/重开/退出通过。核心 10 项 ignored 中的终端、文件与系统状态用例通过各自专项执行；Linux Docker、netem 和历史版本对升级本次未重复。

同一提交的 Check 全部相关检查通过：五平台原生核心与四插件源码、Windows 完整 UI/SSH、Linux 两架构网络，以及 Linux x86_64 真实终端、文件、系统状态和三插件共享联动。Linux 组合实际验证 bash 的 OSC 7；netem 按配置 skipped。

Windows x86_64/ARM64、Linux x86_64/ARM64、macOS ARM64 核心原生构建、updater 签名、实际包启动、资料重开与退出通过。三个新插件的五平台原生包通过；系统状态各目标另验证包内 initialize、重复 mount、pause、dispose 和 shutdown。五平台实际包组合使用本次核心、终端、文件与正式网络隧道 0.2.2，验证 SSH、PTY、文件、网络与退出。系统状态与真实核心的组合另在本机 Windows 实包验证，没有把源码夹具当成五平台原生界面证明。

发布前下载 Windows 核心及三个插件草稿包，核对 GitHub SHA-256、包内版本、架构与共享资源；隔离 WebView2 与 localhost SSH 验证左右拖动、刷新、宽度落盘、保留 iframe、关闭取消保留草稿/PTY/转发，以及放弃后四个插件、SSH 和端口全部释放。核心 16 个附件、三个插件各 6 个附件的五平台清单与签名/摘要均已核对。

核心 macOS 首轮在重开拆窗后读到按钮中心 14pt（要求 22pt）；编译和签名成功，源码和校验未改，仅重跑失败的 macOS 与汇总。原条件重跑及随后独立实际包组合均通过；成功平台和插件没有重复构建。

同主机名容器/chroot、UNC 和未知文件系统映射不支持；真实 macOS/zsh 目录报告、用户设备 DPI/多显示器、netem 与历史版本对在线升级未在本次验证。客户端五平台通过不代表所有远端 shell 和设备通过。
