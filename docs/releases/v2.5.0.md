# SoDeck 2.5.0

- 设置增加“开机启动并驻留托盘”，默认关闭；当前用户登录后在后台运行，手动打开显示主窗口，已有实例直接唤出。
- 启动先取得数据独占，再初始化核心、插件与清理；首次窗口和异常恢复共用呈现链。登录来源不跨普通或更新重启残留。
- 系统登记以实际状态为准，失败保留可读原因；不增加自动连接、会话恢复、后台守护或生产依赖包。普通日志与消息不主动唤出窗口。

行为、系统差异和安装路径限制见[设置](../features/settings.md#登录后自动启动)，职责见[架构](../architecture.md)。

## 验证与发行

已正式发布 [SoDeck v2.5.0](https://github.com/BgaSol/soDeck/releases/tag/v2.5.0)，设为仓库 Latest。正式附件沿用原始打包 run 中已验收的同一批包。

本机类型/格式、218 项脚本、349 项完整核心回归（17 项 ignored）、完整浏览器、新增设置交互与 Windows 原生启动/第二实例/普通重启通过；真实 SSH/PTY、编辑草稿和隧道在收起、恢复、取消退出、再次退出中保留或正确释放，使用 tray-only 模式。首次定位的路径与重开时序问题、夹具编码和重试范围见[本机收据](v2.5.0-local.json)。[包来源 Check](https://github.com/BgaSol/soDeck/actions/runs/45682072110) 的五平台原生核心、完整浏览器、Windows 桌面与所选网络/业务检查全部通过，netem 按配置跳过，见[源码检查收据](v2.5.0-checks.json)。五平台实际包验收已通过，见下方来源与恢复范围。

本轮回归已发现并修正数据目录规范化暴露 Windows verbatim 路径的问题：插件继续得到普通本地路径，避免其斜杠拼接失效。浏览器测试夹具补 UTF-8 声明后可正确核对中文错误反馈。

真实系统注销/登录、用户机器系统策略、托盘鼠标、全屏/多 Space、IME/读屏/DPI 与系统结束会话不由参数启动或包烟测推定通过；尚未完成范围继续保留在[启动专项](../plans/login-startup.md)和[托盘专项](../plans/system-tray.md)。

包来源 [d1ccdc9](https://github.com/BgaSol/soDeck/commit/d1ccdc9c95724fd0eb9da34b07f848072ec830cf)，[原始打包 run](https://github.com/BgaSol/soDeck/actions/runs/45682116182)的五平台 package 均成功；[恢复验收 run](https://github.com/BgaSol/soDeck/actions/runs/45687340829) 的五份 verify 全部通过，确认原生架构、官方更新签名、实际包启动/退出、登录来源后台、第二进程唤出、隔离系统登记 IO 和经关闭协调器的替换重启，Windows 两种安装范围均通过。15 个包/签名已全部下载并核对大小与 SHA-256；正式发布后 16 个公开附件（含更新清单）均再次匿名下载，大小和 SHA-256 与原包/清单一致，见[包与验收收据](v2.5.0-assets.json)。

原始 Linux Xvfb 没有窗口管理器，补 Openbox 后又定位到重启时显示会话被脚本提前关闭；修正验收环境与会话生存期后，两次恢复运行直接复验原包，最终五平台通过。原始 Windows ARM64 验收失败后报告上传停滞且日志未完成，取消收尾后同一原包在两次恢复运行均通过。恢复 run 的 metadata 创建标签与 Release 分别遭 Actions token HTTP 403，本机已登录账户沿用仓库标准发布准备脚本，以同源原包和五份报告完成收尾。

手工补建标签意外触发[额外打包 run](https://github.com/BgaSol/soDeck/actions/runs/45687883335)，其旧版 Linux 验收环境再次因登录启动未最小化而失败，metadata 跳过。这轮另建的包未用于发布；正式附件仍与原始 run 的大小及摘要一致，未覆盖已发布附件。

后续仅修改验收脚本的提交 [4ee8bc2](https://github.com/BgaSol/soDeck/commit/4ee8bc2e561b758397bac6934a9d18f5da31e6e1) 对应 [Check](https://github.com/BgaSol/soDeck/actions/runs/45687338558) 首次因未修改的 Docker 日志进程夹具等待状态超时而失败；仅重跑失败业务任务和依赖汇总后全部通过，Docker 代码与测试未修改。原始失败和第二次结果保留在[源码检查收据](v2.5.0-checks.json)，不替代包来源提交的检查。
