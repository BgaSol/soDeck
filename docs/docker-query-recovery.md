# Docker 查询超时与恢复

容器列表、详情的数据新鲜度与操作可用性分别判断。监控查询超时不会撤销同一有效会话中已经确认的 Docker 目标。

## 状态与操作

- 引擎正常：允许发起操作。
- 引擎探测过期且结构化错误为 timeout：保留绑定，允许操作请求进入独立连接上的身份核验。
- 首次探测未成功、认证/权限错误、明确不可达、会话结束：不使用旧绑定放行。
- 详情超时：保留数据，允许启动/停止等操作；其他详情错误、已删除容器仍阻止管理动作。
- 修改命令继续使用已有 verify_engine、实时 inspect、确认指纹、请求 ID 去重和任务互斥。查询重试不重发修改命令。
- 只有成功探测确认 endpoint 或 daemon ID 改变，才增加引擎代次并清空旧目标数据。失败探测缺少 daemon ID 不代表目标改变。

## 查询与调度

- Docker 引擎、列表、基础详情查询采用每条远端命令 12 秒预算；通用远端读取默认仍为 6 秒。
- 资源统计预算为 6 秒；基础详情在统计完成前发布，统计加载和错误有独立标记。
- 列表读取完成后先发布，健康检查随后更新汇总，不影响列表新鲜度。
- 前台查询失败后等待 3、10、30、60 秒，随后上限为 60 秒；后台保持 60 秒。成功后列表回到 15 秒、详情回到 5 秒的正常周期。
- 认证、主机密钥、权限错误停止快速重试；手动重试不要求引擎已经 ready。进行中的请求合并，避免并发堆积。
- 失败或耗时超过 2 秒的 Docker 读取向诊断输出记录查询阶段、耗时、错误类型，不记录命令、地址、输出和凭据。

## 验证

- Vitest：dockerAvailability、dockerManagement、resourceMonitoring。
- Playwright：docker-management-ui 在 Chromium/WebKit 覆盖超时后操作、自动恢复、列表入口、统计失败、权限错误和容器删除；resources-ui 中 Docker 用例覆盖缓存、列表位置和窄窗口。
- Rust：monitor 和 docker 单元测试覆盖绑定、退避、实时状态校验与原有操作约束。
- 真实本地 SSH 协议 + 模拟 Docker 的 jump_docker 集成测试：制造 12 秒超时并确认自动恢复；过期监控状态下执行操作；慢统计期间先发布详情；确认未知结果不会自动重发。

SSH 集成夹具在 Windows 上按字节保存环境文件，并验证 SFTP 请求的 0600 创建模式；Unix 额外验证实际文件模式。
