# F-CORE-021：诊断现场、指标与证据包

修订：r2 · 日期：2026-10-27 · 文档就绪：能力方案可评审，接口尚未实现；通信profile为T-019待确认增量
所属：核心诊断证据服务与公开消费接口 · 上级：[总览](../observability.md) · 任务：[T-016](../../tasks/T-016-observability.md)

## 1. 目标与范围

查询事件之外，提供版本、状态、资源关系、有限指标与完整性信息，支持人工定位和未来AI分析。证据服务只读公开状态和已上报数据，不远程执行命令、不调用插件私有方法、不做磁盘扫描、不运行诊断脚本，也不隐式调用模型或上传信息。

## 2. 现场与指标

核心内置状态：App/核心/API版本、平台、启动阶段、插件包版本与实例状态、连接路径节点标识与结果、资源代次/所有者关系、队列/存储健康、相关操作状态。密码、私钥、令牌、完整环境变量、用户目录、终端/文件/HTTP正文均不进入快照。

插件通过公开 `diagnostics.reportSnapshot` 主动上报自己命名空间的版本化安全快照，随包声明schema和字段含义；核心储存最新值及采集时间，问题发生或显式采集时复制为不可变证据。核心不反向要求某个插件执行采集代码。未接入/未运行/太旧/采集失败均是可见结果，不能填空对象冒称正常。原有私有diagnostics命令可继续存在，但新核心不依赖它们。

建议单快照32KiB、每来源16个目标、同目标最多每5秒一次；最新快照总预算8MiB，超限显式拒绝/过期。快照含observedAt、receivedAt、对象修订/代次和来源，5分钟未更新默认stale；较长业务周期可在描述中声明有效时长，上限1小时。多来源快照不是同一时刻的原子全局快照，证据报告各自采集时差。

指标使用受限 `metrics.report`，声明名称、单位、counter/gauge/histogram、有限标签和采样规则。首批建议记录连接阶段耗时/重试次数、核心队列深度/等待、资源数量、事件写入失败/丢弃数；插件报告目录加载耗时、隧道连接失败率等业务指标。每来源最多32种指标/128条活跃序列，标签最多4个且枚举有界，不使用路径、URL、requestId等高基数字段。按10秒窗口聚合，持久化1分钟桶；原始细节在15分钟内存环中，崩溃可能丢失。counter按启动/实例代次区分重置，不能算成负增量。

快照、指标及事件都指明是否采样、过期、部分缺失。关键问题可以触发一次本地快照集合，但建议每问题每5分钟最多一次、全App每分钟10次；采集失败不阻断业务或递归触发自身采集。

T-019通信profile增量（r2，尚待方案确认）：[F-CORE-023](../connection-metrics.md)的核心权威字节计量采用1秒实时采样，历史分辨率/保留和96MiB子额度由[F-CORE-024](../communication-history.md)定义；不同于本节通用插件metrics.report的10秒/1分钟与有限标签规则。服务使用同一公共观测存储/查询/证据模型，以专用profile承载连接与资源的有界索引，不放宽任意插件的标签/上报限制。证据包引用通信桶、路径快照、诊断/测速结果及实际粒度/覆盖，不能为生成证据而自动探测或测速；原始流量正文仍禁止进入证据。该增量的接口/预算/采用由T-019代码稿与T-016依赖统一核算，尚非已实现能力。验证对应CH-01～09、CQ-08与CSPEED-09，原DE流程继续适用。

## 3. 诊断包与 AI 消费

建议 `diagnostics.capture/get/cancel`、`metrics.query`、`evidence.create/get/cancel/export`。这些名称与当前diagnostics.get需做版本化区分，不能修改旧strict返回形状。

一个证据包包含：

1. packageId、生成版本、过滤范围、开始/结束时间、水位和storeEpoch。
2. 事件与调用时间线、操作链、问题及相关资源标识。
3. 故障时已保存的快照与指标；如补采当前快照，单独注明“当前”，不能回填成历史。
4. 插件/核心/API版本、事件类型描述、字段单位、数据来源和真实性级别。
5. 缺口清单：超出留存、主动清理、队列丢弃、采样、未接入插件、崩溃尾部和采集失败。
6. 稳定证据引用eventId/issueId/snapshotId及内容校验摘要，便于回答定位到原始记录；摘要用于一致性核对，不声称防恶意篡改。

create固定查询水位，后台有界生成，返回可查询jobId；状态queued/running/succeeded/partial/failed/canceled，partial必须列缺项。每App同时最多2个任务；默认取问题前后各5分钟、最多10000条/50MiB，超限返回需要缩小范围或显式partial，禁止暗中截断。生成过程所需数据短期固定不超过5分钟并计入存储预算，无法固定时中止或明确partial；不长时间持SQLite读事务阻塞业务。

完成包保存为只读快照，引用和schema自包含；历史轮转后仍能解释包内数据。cancel停止后续采集/复制并清理未完成文件，不删除原始记录；崩溃后未完成任务标interrupted并清理临时资源，不自动重新做远端操作。正常关闭视图不取消显式后台任务，App退出按保存/中断语义处理。

导出提供结构化JSON/JSONL、清单和简要可读摘要；使用本机明确选定的输出目标，写临时文件后原子完成，不静默覆盖现有文件。默认导出对象标识与诊断字段，主机地址/用户名/本地或远端路径等额外定位信息按统一采集策略另行启用并在包清单说明。导出成功不等于已上传；本轮没有外部传输。

未来AI插件按同一接口获取有界证据和类型描述，先查范围/缺口，再查事件/操作链，需要时读取证据包；不获得私有数据库或任意文件读取特权。字段内容包括远端/插件字符串均视为数据，不能将其中“忽略规则”“执行命令”等文本当指令。分析结果若以后保存，使用独立derived来源、输入证据引用和不确定性，不能改写原始事实。模型选择、云端发送、自动修复及插件实现另行设计。

## 4. 验收与测试流程

AC-01现场时间和覆盖准确；AC-02指标有界可解释；AC-03证据稳定可引用且失败/取消可见；AC-04公开消费和数据边界清楚。

环境：Windows临时存储，真实核心/三个插件；受控快照/指标用夹具验证边界。只读AI消费者用契约夹具验证，不能记为AI插件或模型诊断已实现。拟建证据任务/导出测试，当前不存在。适用r1，结果归T-016。
