## 1. 本轮目标和实际起点

把“核心提供公共能力、插件报告自己的业务”落实到具体输入、结果、责任和失败规则。本轮细化服务与已有终端、文件、网络隧道插件的接入，不创建UI/代码原型，不恢复T-019已撤下的问题/知悉/通知入口。问题服务保留为独立后续能力，不能成为三个插件接入事件记录的前置条件。

2026-10-27只读核实当前工作区（实际验证范围另见[T-019结果](../../tasks/T-019-results.md)）：

| 已有实现 | 本轮如何使用 / 仍缺什么 |
| --- | --- |
| API 4.9.0；终端0.8.0、文件0.6.0、网络隧道0.2.2，均以当前manifest核实 | 新能力单独协商，不把4.9记成全量观测API；不预占后续版本号 |
| `crates/core/src/observability/`、facts/logs/traffic/diagnostics分区、调用事实与calls投影 | 复用写入所有者、预算、启动重建；不新建第二份插件审计库 |
| `events.query/get/aggregate`、`observability.health.get/policy.get`及strict schema | 已有窄查询，不含完整来源/级别筛选和通用插件上报；保持现有请求/返回兼容 |
| `AuditScope`及连接路径阶段记录 | 已有局部call/trace关联，不能宣称UI→worker→异步任务已完整关联；补可信上下文传播 |
| `communication.*`计量/历史与SSH响应 | 核心继续拥有物理/逻辑流量计量，插件不得再报一份字节数叠加 |

## 2. 核心具体提供什么

本表固定功能需求，正式方法、版本/schema及传输编码以本轮代码方案§3～4为准。新方法不代表现在可调用。单项功能语义以对应F-CORE规格为来源。

| 能力 / 所属规格 | 公开入口建议 | 输入与可观察结果 |
| --- | --- | --- |
| 能力和覆盖发现 / F-CORE-018 | `observability.describe` | 返回协议/类型版本、采集策略版本、限额、存储epoch、当前插件采集覆盖和可用状态；区分未支持、暂不可用、已过滤 |
| 事件目录 / F-CORE-018 | `events.types.list/get` | 分页读取当前或历史的来源、稳定类型、字段/枚举、默认级别、数据分类、类型版本；不运行插件代码 |
| 事件批量提交 / F-CORE-018 | `events.v2.appendBatch` | 结构化事件及clientEventId；逐项返回persisted/duplicate/filtered/rejected、eventId/sequence或稳定错误，persisted只指提交完成 |
| 操作与阶段 / F-CORE-018 | `traces.begin/stage/end/get` | 开始根操作/子阶段、继承可信上下文、报告阶段结果、查询时间线；关联请求/资源，不替代业务operationId、取消或执行回执 |
| 资源诊断标识 / F-CORE-018 | `observability.targets.resolve` | 活动核心资源/代次 → 不具执行能力的diagnosticRef；插件私有目录/目标用SDK内存随机entityRef，不能保存可逆路径ID |
| 历史筛选和统计 / F-CORE-019 | `events.v2.query/get/aggregate` | 支持来源/级别/对象/trace筛选、固定水位分页、类型化字段与完整性报告；旧events.*查询保持strict投影 |
| 事件历史订阅 / F-CORE-019 | `events.v2.open/ack/close` | 过滤器、起点/游标 → 有界已提交事件批次；可补读、重复可去重、缺口明确；不合并事实、不传命令 |
| 公开诊断快照 / F-CORE-021 | `diagnostics.snapshots.report/query/get` | 插件主动报告声明过的安全状态，查询返回观测时刻/版本/代次/过期信息；对象结束标失效，故障时固定副本可保留 |
| 通用业务指标 / F-CORE-021 | `metrics.report/query` | 带单位、类型、区间和有限标签的数值；核心有界聚合并返回覆盖/采样；不重复核心通信计量 |
| 证据任务 / F-CORE-021 | `diagnostics.capture`、`diagnostics.capture.get/cancel`、`evidence.create/get/cancel/export` | 固定范围组装事件/现场/指标/版本/缺口，返回任务ID与完整/部分/失败状态；不调用插件私有接口或执行远端命令 |
| 策略、健康和清理 / F-CORE-022 | 保留旧health/policy；新增observability.v2.health.get/policy.get/set、events.v2.cleanup.start/get/cancel | 明确策略修订、真实范围、预算、丢弃/失败计数；清理可报告部分完成；改变现有DTO时另设v2投影 |
| 独立问题能力 / F-CORE-020，后续 | `issues.query/get/acknowledge`及规则投影 | 从领域事件生成问题状态，恢复由真实所有者事实驱动；不要求插件主动创建/关闭问题，不引入新的插件提醒界面 |

建议按`observability.events.v2`、`observability.context.v1`、`observability.snapshots.v1`、`observability.metrics.v1`、`observability.history-feed.v1`、`observability.evidence.v1`分别协商。只有实现及检查通过的能力才能进入核心capability清单；描述/采集并不要求证据包、问题通知同时可用。capability用于兼容发现，不限制某插件能否调用核心。

## 3. 核心自动记录，插件只补业务含义

| 事实所有者 | 必须采集的语义动作/结果 | 不能由它代报的内容 |
| --- | --- | --- |
| 外壳/工作台 | 服务器/分组配置提交、工作区创建/关闭、显式命令派发、逻辑视图移动/关闭、退出 | 插件会话实际就绪、远端命令已执行 |
| 核心网关 | 每次调用接收、校验/拒绝、结果/错误、来源、耗时和安全摘要 | 用参数字符串伪造用户已授权的动作 |
| 核心连接/资源服务 | 连接各跳阶段、等待认证、认证结果、租约/PTY/SFTP/TCP生命周期、实际断开/释放 | 插件协议语义、目录映射成功、代理应用层成功 |
| 插件宿主/管理器 | 包校验/兼容、prepare/activate/stop、异常退出、启用版本、采集描述加载状态 | 在插件崩溃后补造其未完成业务成功 |
| 启动/存储 | 启动阶段、版本检查、备份重建、写入退化、恢复与采集缺口 | 将无持久回执写成已存储 |
| 各业务插件 | 真实状态机变化、用户请求的业务完成、受影响的会话/规则/目录操作、可恢复性 | 再生成同一条核心call记录或自称核心观察事实 |

配置变更记录字段名、对象ID和前后修订，秘密与自由文本值不自动记录。终端输入/输出、文件正文/完整路径、代理URL/头/正文不纳入。关闭/移窗仅在逻辑动作完成时记一次，原生重挂载不是新业务会话。调用审计与语义动作可同链存在，但查询用户活动默认按kind=action筛选，不把底层RPC数量当操作次数。

## 4. 插件统一接入流程

### 4.1 随独立包声明采集目录

建议包内新增`diagnostics/observability.json`，通过后续版本化manifest字段引用并纳入现有包哈希/签名。它定义本插件的事件、动作、快照、指标schema和稳定展示键；宿主在激活前加载并注册，不提供任意运行时注册脚本。字段描述包含类型/长度/可选性/是否可公开记录，未知字段拒绝。类型名建议`plugin.<pluginId>.<domain>.<fact>`，版本与包版本分开。

有描述的新包声明相关required capabilities，旧核心按已有兼容规则拒绝该新包；旧包在新核心继续运行，标记`audit-only`，不伪称业务事件齐全。描述不合法在暂存/包验证时报告并保留当前可用包；存储暂时不可用是运行降级，不当成包不兼容或触发热回退。历史描述与事件一起留存，卸载后仍可解释。

### 4.2 SDK持有采集客户端，业务显式持有上下文

建议公共无DOM SDK提供类型化采集客户端：event/logger、action/trace、snapshot、metric、query/subscribe及flush/dispose。WebView和QuickJS分别适配transport，输出同一契约；不依赖React、Node全局或跨插件共享内存。当前终端直接用runtime.sodeck、文件/网络已用workerClient，后续接入允许保留各自业务client，只增加同一公共采集适配。

UI在业务动作入口开始action；SDK携带上下文派发给自己的worker，worker创建子阶段并通过带该上下文的client调用核心。宿主命令/工作区初始化已带操作上下文时继承，不再另起“用户点击”根事件。定时重连、自动目录跟随、后台采集标system/plugin，并关联触发事件或原操作，不冒充新用户动作。

上下文通过经协商的请求元数据/宿主invoke上下文传递，不塞入各业务params破坏strict schema。SDK采用不可变context-bound client或显式参数；并发异步调用不能依赖JS全局currentTrace。Rust已有线程局部AuditScope只覆盖当前作用域，跨工作队列必须显式capture/resume，不能靠同一线程假设。最终wire字段与旧帧协商在代码方案固定。

宿主只确认真实调用来源；普通插件UI自报点击为`initiator=user, assurance=reported`。只有宿主拥有的明确外壳命令路径可记`verified`，浏览器事件或任意sodeck.call本身不证明用户授权。trace上下文仅用于关联，不是授权凭据。

### 4.3 受理、完成与重试

- 一次逻辑动作一个actionId/trace；每次显式重试新attempt/span，附retryOf，不覆盖旧失败。
- `accepted:true`、开始排队、等待认证都不等于成功。插件在业务状态机实际终态结束action；取消请求和取消已完成分别记录。
- 诊断失败不能自动重放业务，不将成功的业务结果覆盖为日志错误；沿用核心既有“审计开始不可写则拒绝新操作”的规则。新增附加事件失败只降级采集，并在describe/health中可见。
- 每实例一个采集队列，UI/worker端点共用宿主配额；事件/快照/指标总计最多1个在途采集请求，默认最多250ms批量等待，error/关键终态立即请求排空。flush总预算1秒，正常App退出总排空上限仍2秒；剩余项明确未提交，不能阻塞释放PTY/隧道。
- 对声明可重送的上报，传输超时/暂时容量失败最多按100/300/1000ms有界重试，保持clientEventId；明确rejected/filtered不重试。显式业务调用从不因上报失败重试。队列/字段/速率沿用F-CORE-018，更小的实际宿主总预算优先。
- 宿主必须为既有控制/关闭/ack留容量，网络插件现有12/8/4调用lane不因诊断侵占清理额度；日志风暴测试覆盖三插件同时工作。
- instance stop后禁止新生产；已进入宿主的安全事件可排空，剩余生产者缓冲算丢失。表面重挂载保留业务worker，不重新上报会话created；上报来源仍保存原surface/实例信息。

## 5. 三个现有插件的接入边界

| 插件 | 业务事件与上下文 | 主动快照/指标 | 原有机制处理 |
| --- | --- | --- | --- |
| [终端 F-TERM-004](../../plugins/terminal/features/observability.md) | 新建/重连/取消/关闭、等待认证、会话状态、目录集成健康；sessionId与PTY代次 | 会话数量/状态、目录集成状态、创建/重连耗时 | 保留既有会话业务；不捕获按键/命令/终端正文，不重复报核心SSH认证事实 |
| [文件 F-FILES-003](../../plugins/files/features/observability.md) | 连接/刷新/定位/取消、目录读取结果、自动跟随结果、挂载/容量降级 | 缓存/队列/节点量、跟随状态、加载/映射/容量耗时 | `files.diagnostics`暂保留私有兼容；新公开快照由worker主动上报；不靠查询轮询产生业务事件 |
| [网络隧道 F-PROXY-004](../../plugins/proxy/features/observability.md) | 规则保存/删除、启动/停止/重连/检查、协议/目标失败、运行状态 | 规则/运行计数、连接错误分布、启动/重连耗时 | 本地200条诊断暂留展示缓存；核心持久事件为历史权威，不重复上报通信流量 |

三个插件默认作为生产者，不订阅全局事件再驱动彼此业务；只有实际诊断查看功能才查询/订阅所需范围。未来AI是另一个公共消费者，读取describe→范围/覆盖→事件/trace→快照/指标/证据，无须插件配合运行。

## 6. 跨插件场景和完成定义

打开工作区：外壳action → 初始化终端attempt → 核心SSH/PTY → 终端ready；文件自动读取继承“初始化工作区”来源或以明确的资源/目录修订关系另起后台链。文件就绪不能由“终端ready”直接推断。共享连接断开由核心保存一次事实，终端/文件/隧道分别记录真实影响并关联公共资源标识；仅时间相近不足以证明共同根因。

目录跟随：终端只向既有核心目录服务报告cwd，文件继续订阅该状态契约；新增诊断记录directoryRevision和sourceSessionRef。不为了串联trace新增终端→文件调用；暂无causeEventId时用已验证资源/修订关联，并说明证据类型不同。

首个接入交付必须同时具有：可信核心事件和上报、操作关联、版本化查询、三插件采集目录与失败/生命周期处理、覆盖/健康可见性、真实链路验证。可靠补读、证据任务和问题服务各自完成各自测试后独立声明可用；本次功能细化不提前批准上述任何编码，不因表已存在跳过验证。

## 7. 接入验收与测试流程

AC-01核心与插件单一事实所有者；AC-02并发/重试/生命周期正确关联；AC-03兼容与降级明确；AC-04公开读取可独立使用。

准备：Windows隔离App/数据、三个真实签名插件包和未重编译旧包；两个隔离SSH目标及共享连接/跳板；记录当前API/包版本。身份、延迟、写入失效、时钟和队列测试可用夹具，真实SSH/原生窗口/独立更新分别验证。下列入口拟建立，尚未运行；EV/HQ/DE/ST已有规划继续适用，结果归T-016。

| 用例 / 验收 | 操作 | 预期 |
| --- | --- | --- |
| INT-01 / 01、02 | 打开两服务器，并行创建/取消终端、刷新文件、启动隧道 | 各action/attempt/调用来源与目标一致；受理和终态分开；无全局trace串用 |
| INT-02 / 01 | 断开一个共享核心连接，读取三插件影响与资源关系 | 核心断开事实不重复；插件仅报告自身影响；相邻无关失败不被错误归因 |
| INT-03 / 02 | 操作中移窗/重挂载/关工作区/强杀worker，延迟完成后返回 | 无重复created；原动作归原实例/代次，中断不写成功；业务资源清理不被flush阻塞 |
| INT-04 / 03 | 新核心装旧包；新包装缺capability旧核心；坏描述新包更新；仅升级一个插件 | 旧包audit-only，新包兼容拒绝明确；旧版本保持；其他插件无需重编译，历史类型仍可读 |

清理：终止采集/读取夹具，取消feed及证据任务、关闭测试App和SSH、释放端口/原生窗口；恢复故障注入，保留脱敏版本/事件ID/数量/预算测量证据后删除临时目录。本轮仅文档检查，不能把用例列出等同功能通过。
