## 1. 目标和范围

为文件插件提供读取目录/属性和运行有界非交互命令的公共能力。T-008 在既有 SSH/PTY 上实现本文件的 SFTP 和通用 exec 增量，随 dev.5 开发包提供；这不等于正式发布。

T-009 的接入基线为核心 dev.4、终端 0.4.0、插件 API 4 / `workspace.v4`，已具备空工作台启动、创建 generation、显式初始化动作和内存提交。T-008 复用这些机制并扩展多插件来源及资源路由，不重复建设跨启动恢复或工作区初始化。

首轮推荐在现有 Linux/OpenSSH 连接上增加 SFTP 目录、属性、路径解析与有界读取，并提供通用非 PTY 执行通道，供插件取得 Linux 系统信息。核心只传输数据和报告协议/执行状态，不解释 mountinfo、bind、磁盘类型或容量业务含义，也不返回专用于文件树的 UI 模型。

不建立文件写入、上传/下载任务产品、任意本地文件访问、挂载/卸载或终端命令注入接口。通用执行能力本身可以运行远端命令；“只读”是本次文件插件的使用范围，不声称 SSH 协议提供只读沙箱，也不新增插件权限分配。

## 2. 公开能力的功能契约

以下维护功能语义；具体方法、字段、错误和机器契约见代码方案第 3/4 节，限额见第 8 节。能力为 `remote.files.read.v1`、`remote.exec.v1`、`connections.observe.v1`，通过 API 4.1 兼容扩展提供；机器契约位于 `contracts/remote-read-v1.schema.json`，生成 Rust/SDK 类型和校验。

| 能力 | 输入与结果 | 关键行为 |
| --- | --- | --- |
| 连接就绪查询/通知与仅复用现有连接 | 工作区及创建代次、服务器/配置修订 → 就绪状态及本调用者租约，或明确不可复用 | 采用 `connections.observe` 有界观察与 `connections.acquireExisting` 原子复用；失效不可回退为新建或触发认证。显式“连接并读取”仍可走普通 acquire；租约归文件插件，不转交终端句柄 |
| 打开/读取/关闭目录 | 有效租约、远端路径、分页预算 → 目录句柄、条目批次、是否结束 | 句柄归调用实例/工作区/连接代次；逐批读取，不伪称文件系统事务快照；结束、取消及关闭释放句柄 |
| 查询属性 | 有效租约、路径、是否跟随链接 → 类型、字节长度、可得权限/修改时间 | 默认不跟随链接；缺字段与 0 分开，大小以可无损跨语言表达的整数形式传递 |
| 路径与链接 | 有效租约、路径 → 规范化路径/链接目标及原路径 | 不改变调用者持有的逻辑显示路径；支持字节路径或等价无损标识，不能用 lossy 显示文本重新定位 |
| 有界文件读取 | 有效租约、路径、偏移及限额 → 字节批次、结束/截断状态 | 用于必要系统数据，不预读用户文件正文；不把无界内容放进事件或日志；取消关闭文件句柄 |
| 非交互执行 | 有效租约、命令及目标 shell 语义、超时和输出预算 → 操作句柄、stdout/stderr、exitStatus/结束原因 | 不分配终端、不发送到现有 PTY；分别报告远端退出码、通道错误、超时和截断；不静默自动重放 |
| 操作取消和资源查询 | 操作/资源句柄 → 当前状态 | 沿用核心统一取消和资源管理；可重复关闭；只终止所属通道，不关闭其他租约仍使用的连接 |

方法均通过公开网关及调用记录。宿主绑定真实来源，用户参数不能伪造插件身份。路径不是命令文本；SFTP 路径不经 shell。必须使用命令取得信息时，先明确远端执行语义并采用对应参数编码，不能把 `argv` 外观当成 SSH 无 shell 保证。包含空格、引号、换行、前导连字符等路径作为边界测试。

路径采用原始字节的 base64 对象，禁止 NUL；大小/时间/块数使用十进制整数字符串。Windows 宿主不经 PathBuf 改写 Linux 名称，ssh2 0.9.6 增加有限字节入口的依赖补丁属于核心。本次公开 `files.openDirectory/readDirectory/closeDirectory`、属性/链接/真实路径、`files.openRead/read/close` 与 `exec.start/read/ack/cancel/close`；操作回执用 `remote.operations.get/forget`，取消沿用统一 operationId。

目录游标不能跨连接代次、工作区创建 generation 或插件实例使用；刷新建立新读取代次，旧游标不参与新结果。工作区 ID 可在关闭重开后相同，公共网关/资源登记必须绑定并校验创建身份，旧成功结果未交付时回收资源，不能只比 ID。服务器边读边变更时允许明确的不一致/重读提示，不保证列举期间的原子快照。

相同 operationId/cursor 的目录页重放返回同一结果，不再次推进远端；参数冲突、回执/游标过期明确失败。响应丢失先查询回执，不以新 ID 盲重试资源创建或 exec。结果 TTL 到期清理未领取资源；主动关闭、scope 撤销及实例停止不等待 TTL。exec 输出用有界帧与确认游标回收，输出超限明确截断，不能算完整成功。

## 3. 资源、失败与调用记录

- 文件插件独立申请租约；核心按现有服务器、配置及凭据修订复用连接或连接池。终端的存在不是前置。新工作区的首终端正在认证时，自动文件读取仅等待核心连接就绪，不创建另一轮认证。多个显式消费者的认证协调、取消及回执按真实来源隔离。
- 原 `connections.acquire` 在找不到可复用连接时会新建；先查询再普通 acquire 会存在竞争。新增“仅复用”方法在核心原子登记有效现存连接的租约，按 RI-07 验证；显示连接状态不等于开放插件互调。
- SFTP 会话、目录/文件句柄和 exec 通道均入资源管理；慢网络挂载或堵塞读取不能长期占用整个工作区的调度。并发、缓冲、页大小、总缓存、超时及取消回收期限统一采用代码方案第 8 节，按 RI-03/05 验证；非阻塞续调和取消不得关闭仍承载终端的共享 socket。
- 取消立即反馈“正在取消”，收到终止结果后再写“已取消”；超时结束本机通道并释放所属资源。不能保证关闭 SSH 通道后任意远端派生进程都结束，文件插件只使用有限、非后台采集命令。
- 断线、实例结束或工作区结束使所属句柄失效；创建已成功但响应未交付时也须回收。移窗只改变呈现绑定，不转移远端目标或重复执行命令。
- 无 SFTP、exec 被拒、无权限、路径消失、输出超限、格式不支持和网络断开分别报告；不把能力不足映射为空目录。挂载数据能否解析、路径视图能否对应由插件判断。
- 调用摘要记录身份、服务器/工作区、操作及资源 ID、时长、条目/字节数、结束原因；不记录文件清单、正文、完整命令输出、原始挂载参数或认证秘密。敏感参数遵循现有脱敏策略；记录存储故障时新增资源仍按公共规则处理，但关闭/取消必须允许尽力清理，不能因此泄漏。
- 能力探测只列出实际支持的方法；新增 I/O 及连接协调能力以 API 4 基线做版本化扩展，验证现有终端 0.4.0 不改包仍可运行。API 3 及更早包已由 T-009 拒绝，不纳入旧包兼容承诺。插件缺能力应被明确标识，不回退为偷偷控制终端。`persisted:false` 是运行现场仅存内存的正常回执。

## 4. 验收标准

- AC-01：通过真实 SSH/SFTP 列目录、读取属性、解析路径并取得有界系统数据，特殊路径与大整数不失真。
- AC-02：执行状态、非零退出、stderr、截断、超时、断线和取消可区分，不能假报完整成功。
- AC-03：资源和异步身份独立，文件查询的失败、取消或停止不会误伤终端；有界预算有实际证据。
- AC-04：公开契约兼容、真实来源和逐次记录有效，日志/快照不泄露秘密或文件正文。

### 5.1 T-013 单层跳板基线与专属回归

依据 [F-CORE-014 r1](ssh-jump.md)，SFTP/exec 仍只消费最终目标租约，不解析跳板或借用终端。`connections.observe` / `acquireExisting` 保持旧响应形状，核心内部按完整路径依赖（含跳板修订/凭据修订）判断，跳板变更推进观察版本；旧 active 不代表新路径就绪，仅复用失败不回退认证/新建。已有 I/O 保持原连接快照；新申请不得附着已过期路径。

准备/清理共享 F-CORE-014 §6 的隔离 A/B 与独立数据；该单层基线已随 T-013 r1 确认，实际结果见 T-013-results，不代表下方多级用例通过：

| 用例 | 步骤 | 预期 |
| --- | --- | --- |
| RI-JP-01 | A 禁用 session channel、只许转发；经 A 取得 B 租约，执行目录/属性/有限 exec；同时运行 B PTY，取消一项 I/O | 全部原语访问 B，A 无 shell；取消只结束本项，PTY 不被误断；对应 JP-AC-01/03 |
| RI-JP-02 | 文件观察连接就绪后、acquireExisting 前修改 A 或断线；重新显式连接；对新代次发送旧句柄和回执；旧插件原包接新核心 | 竞争返回未就绪/过期而不建连；旧结果不污染新路径；严格 DTO/原包兼容、全部资源回收；对应 JP-AC-03/04 |
