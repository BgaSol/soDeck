## 1. 目标与确认边界

第三方可以分发符合公开契约的插件，核心严格检查包完整性，设置展示来源状态，用户选择启用哪些插件。用户已认可上一轮理解，包括设置统一管理、无签名不重复确认、实际停用且保留数据、完整重启生效；本轮要求功能和代码方案，尚未授权编码。

包含：本地安装/更新入口整合、强制完整性检查、可选签名、所有插件独立启停、状态与异常、第三方无签名打包、四个现有插件回归、独立 Windows 开发目录包。
排除：市场、联网下载/自动升级、证书申请或密钥管理界面、运行中热启停、卸载/删除数据、插件互调、权限分配、任意原生插件、Linux/macOS交付、Git提交/推送及发布。沿用现有公开API、脚本运行容器和资源归属。

首装默认勾选启用、未知签名来源放行、已知密钥验签失败拒绝、损坏启用配置恢复流程是本稿明确提出的细节，随整体方案评审。

## 2. 加载与校验规则

### 2.1 完整性是硬条件

包仍是 ZIP 封装的 `.sodeck-plugin`。必须包含有效的 `manifest.json`、`integrity.json` 和声明的入口；清单逐文件 SHA-256 必须与实际字节完全一致。除完整性清单本身和可选签名文件外，每个文件都必须列入清单，清单不得指向不存在的文件或自身/签名文件。

缺少/重复清单键、错误哈希、缺文件、多文件、入口缺失、无效路径、大小写冲突、越界链接及超限包均拒绝。保留现有32MiB包、128MiB展开、2000文件上限，以及核心/API/平台/能力兼容检查。能力声明用于兼容，不是权限申请。

导入时验证、启动选择时验证、恢复故障实例时重新验证。实际执行的worker、UI和描述文件来自同一份已验证字节快照，防止校验后重新读取另一份文件。完整性未通过前不得执行任何插件代码或创建插件UI。已运行实例继续使用已验证的内存快照，不承诺持续监视磁盘或实时卸载；下次重新加载必须重新验证。

一个包失败只隔离该插件/候选版本。更新候选失败保留可用旧版；若旧版也不完整，两个版本均不得运行。用户勾选启用不能覆盖校验失败。

### 2.2 签名与加载判定

以下均以完整性、包结构和兼容检查通过为前提：

| 包状态 | 设置显示 | 是否可在启用后加载 |
| --- | --- | --- |
| 没有 signature.json | 未签名 | 是 |
| 签名格式正确，keyId不在本机信任集 | 签名来源未验证 | 是 |
| 已知公钥验签通过 | 签名已验证；开发密钥另标“开发签名” | 是 |
| 已知公钥验签失败 | 签名校验失败 | 否 |
| 签名文件损坏、字段/编码/长度无效 | 签名文件无效 | 否 |
| 完整性失败 | 文件不完整或校验失败，并给出具体原因 | 否 |

未知签名来源不是验签成功，不展示“可信/官方”。签名验证成功只表达与已知密钥匹配；开发签名不包装成官方认证。无签名/来源未知仅有条目旁的持久提示，不额外弹窗，不要求开启全局放行开关。

本期只有用户明确从本地选择包的安装/更新。按pluginId识别安装或更新，同ID不自动获得“官方”身份；包内显示名称仅为声明。当前版本与待更新版本分别显示签名状态；不实现发布者密钥绑定、自动信任包内公钥或签名降级拦截。已签版本后手动导入无签名新版也可准备，明确显示新版本“未签名”，不能继承旧版验证徽标。这符合无签名可加载的规则，不宣称发布者连续性验证。

### 2.3 启用、运行与版本分开

每插件保存一个应用级启用偏好，各服务器工作区共用；所有官方和第三方业务插件都有勾选，没有永久启用的业务插件。

| 状态 | 当次运行 | 设置显示 |
| --- | --- | --- |
| 已启用且启动成功 | worker及声明入口可用 | 已启用 |
| 已启用，保存为停用 | 原实例与会话继续 | 重启后停用 |
| 已停用，保存为启用 | 不提前启动 | 重启后启用 |
| 已停用 | 不执行初始化、worker、设置provider或后台任务，不注册可操作贡献 | 已停用 |
| 勾选启用但包/启动失败 | 不加载失败实例；其他插件继续 | 启动失败/校验失败及原因 |
| 已停用且有新版本 | 仅保留验证后的候选包，不执行候选初始化 | 已停用；更新待启用后生效 |

启用偏好不等于运行成功。失败不偷偷取消用户的勾选。取消勾选不卸载、不删除插件包或配置；重新启用使用保留配置，沿用既有数据schema校验和更新失败回退。故障恢复也服从本次启动时确定的启用集合：本次仍运行但“重启后停用”的插件可恢复；本次停用但“重启后启用”的插件不能被恢复入口提前启动。

完整退出再启动才生效；关闭设置窗、关闭主窗收托盘或关闭某个插件视图均不算重启。不新增自动强制退出按钮，沿用正常退出与活动任务/草稿协调。

首装有效包默认勾选启用，完整重启后运行；既有包升级保持原启用偏好，随附插件补装不能覆盖停用选择。第一次升级到本功能时，现有插件保持启用。重复导入相同版本相同内容为幂等；相同版本不同内容拒绝，须修改版本号。已停用插件仍可导入更新，重新启用并重启时才试运行候选。

所有插件停用是合法状态：服务器档案、代理配置、设置、插件管理、诊断及正常退出仍可用。服务器工作区可创建，显示“当前没有启用的插件”，可进入设置；不自动重启终端，不产生“初始化失败”假错误。已启用但全部失败时显示失败原因，与主动全部停用区分。

## 3. 设置交互

### 3.1 统一入口

在既有非模态设置窗中新增核心页面 `core:plugins`，导航“应用 → 插件管理”。现有菜单“插件”、设置左下“管理插件”、应用与数据中的入口统一打开/定位此页，不再打开另一套插件弹窗。插件自有配置页仍在“插件 → 名称”分组，和核心管理页职责分明。

管理页是一张连续列表，每行提供：启用复选框、名称、pluginId、当前选定版本、实际运行状态、签名提示；需要时追加待更新版本/签名、生效说明和错误原因。坏包仍能以已登记pluginId显示，不为了取名字读取或执行未验证内容。停用行保留可操作复选框，不整体变灰而阻止重新启用。

搜索按名称、ID和状态筛选，隐藏行的草稿保留；列表分页加载，选项不因翻页消失。空列表提供安装入口；读取失败显示原因与重试，不把错误伪装成空列表。超限信息明确可见，不静默漏插件。

### 3.2 保存和导入

启停勾选是草稿，与现有底部“取消 / 应用 / 确定”一致。切页/搜索不丢草稿；未应用关闭按已有流程选择放弃或继续编辑。应用成功后显示“已保存，重启后生效”，不提前隐藏正在使用的插件。勾回本次状态并应用可撤销待启停，不强制重启。

插件启用选择作为一组原子保存；与主题、插件业务设置仍沿用已有分组提交和部分成功语义。不增加全设置跨组事务。保存失败保留草稿；冲突要求载入最新后再编辑；超时核对operationId回执，不盲目重试。关闭与退出必须包含此页草稿及在途保存。

“从文件安装/更新”调用原生文件选择器，选择后校验并准备包，显示目标插件及候选版本。取消选择无副作用。准备包是独立动作，不属于底部启停草稿，页面提前说明“导入后即准备，下次启用并重启时生效”；取消设置不撤销已准备包。准备期间仍能查看页面，同一时刻只允许一个导入；已开始保存时暂禁导入。已有插件的启停草稿按ID保留，不能被导入完成后的列表刷新覆盖。

导入失败保留原active/pending和启用偏好。准备新候选不替换当次实例。没有有效清单的未知包只显示导入错误，不登记虚构插件。较新的有效候选替换同插件原pending是一次显式本地导入的结果，原运行版本不变。

### 3.3 停用后的业务设置

管理页始终可用。停用插件若已有有效设置描述，保留其设置分类和“插件已停用”说明，字段不可编辑；不为读取设置自动启动provider。坏包不读取其描述，管理页显示失败。待停用的仍运行插件在重启前继续可编辑；新装/待启用插件说明“重启后可配置”。

### 3.4 apple-design与可访问性

使用已读取的apple-design控制感、熟悉性、清晰层次、就近反馈：列表与复选框映射直接；按下立即反馈；保存/待重启说明留在对应位置；未签名使用次要文字提示，错误使用明确文案，均不只靠颜色。复用现有公共Checkbox/Button/Notice和主题令牌，不另造卡片体系、颜色或玻璃背景。

沿用现有设置窗尺寸、关闭/焦点/IME语义。Tab和空格可勾选，复选框可访问名称包含插件名；筛选后焦点不跳到隐藏项；三主题、200%文字缩放、高对比及减少动态验证。无新的大幅动画，不为交互原型提前编码。

## 4. 数据、错误与恢复

核心管理启用偏好，存于数据目录的 `plugins/enablement.json`，不属于插件自己的settings.json，不增加core.sqlite表，不改当前core v7或凭据。当前选定版本、候选版本和业务数据继续由已有管理器持有。

启用文件包含格式版本、修订、偏好和有界操作回执，保存原子替换；正常首次不存在时按既有插件启用初始化。文件损坏/不可读时保留原文件，进入“启用配置不可用”：本次不启动任何插件，但核心和管理页可用，不能静默恢复全部启用。针对损坏文件提供明确的“备份并重建启用配置（全部停用）”；先成功备份原文件再写新文件，失败保持不可用。新格式高于本机支持版本保持只读，不提供降级重建。

修复后用户重新勾选并应用，完整重启生效；插件业务数据不清除。导入、选择、保存和恢复结果纳入已有调用记录，记录ID/版本/错误码/变更数量，避免记录包正文、设置正文、密钥或完整本地路径。格式与接口细节见代码方案。

## 5. 验收标准

- AC-01：有效未签名包可安装/更新/启动，设置持续标识未签名；完整性失败在所有加载入口均被阻止。
- AC-02：签名五种状态与§2.2一致，当前/候选版本来源状态不串用。
- AC-03：每个官方及第三方插件可独立勾选，应用后完整重启才生效；停用无代码执行，保留包与配置。
- AC-04：更新、停用、重启和恢复组合可靠，故障候选不破坏旧版或其他插件。
- AC-05：统一设置入口、草稿/应用/取消、冲突/超时、原生关闭与可访问性正确。
- AC-06：全部停用和启用配置异常时核心仍可管理；四插件与旧有效包保持公开接口兼容。
- AC-07：第三方可对任意已编译插件目录生成完整无签名包；独立单包更新与Windows开发目录验证有证据。

## 6. 本功能测试流程
