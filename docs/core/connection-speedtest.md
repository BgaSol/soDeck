## 1. 测试目标与含义

由用户主动测量“此客户端沿所选SSH路径到目标服务器”的上下行应用吞吐。它包含SSH、加密、客户端与远端处理的影响；结果不是网卡线速、运营商承诺、全网容量或某一跳的独立带宽。

测试内网代理所属SSH节点时，只测到该节点，不代表它到网站/数据库的剩余链路。目标卡片明确“客户端 → 路径节点 → SSH目标”；不允许输入任意目标域名后误称同一测量。逐跳定位瓶颈需要额外独立测试及条件比较，本批不自动下结论。

包含顺序上/下行测试、单向选项、限时/限量、取消与清理、结果保留和同条件比较。打开页面、连接服务器、恢复网络、跨启动均不自动测速；没有定时测速、后台跑满、多流极限压测或自动安装程序。

## 2. 用户流程与默认值

1. 在单服务器“测速”页查看目标、当前保存路径与实际运行路径。若不一致，必须在开始页选择“当前运行路径”或“新配置路径”，默认当前运行路径；没有运行路径则选保存路径。结果锁定快照，不能中途换路径。
2. 页面显示测试方法、支持状态、现有活跃业务数，以及“测试会占用该路径带宽，可能影响当前终端/传输”。这是一条与选择有关的说明；点击“开始测速”就是明确启动，不再叠加通用确认弹窗。
3. 默认“发送后接收”，可改“仅发送/仅接收”。普通参数固定，提供“标准”和“节省流量”两档，避免让用户编辑原始命令。
4. 创建独立测试租约和任务；认证/指纹检查仍走已有核心流程。认证等待不产生测试负载，取消认证即结束任务。相同操作ID重试只返回原任务，全App同时1个测速，其他窗口可定位/取消它。
5. 依次显示准备、发送、校验、接收、校验、完成；显示实际字节、有效时长、实时速率、剩余时间/流量预算。两个方向顺序执行，避免彼此争抢影响解释。
6. 完成页展示每方向平均/分段峰值、测试量、持续时间、采样与校验、方法版本/路径/并行业务，以及“正常完成 / 样本较短 / 部分完成 / 已取消 / 失败”。可查看对应历史区间、对比旧结果或导出。

| 参数 | 标准（建议默认） | 节省流量 |
| --- | --- | --- |
| 每方向预热上限 | 2秒 | 1秒 |
| 每方向正式测量上限 | 10秒 | 5秒 |
| 每方向负载总上限（含预热） | 256MiB | 32MiB |
| 双方向负载总上限 | 512MiB | 64MiB |
| 控制数据上限 | 每任务64KiB，不含SSH封装 | 同左 |
| 每阶段准备/校验时限 | 准备15秒、每次校验5秒 | 同左 |
| 总执行时限 | 认证完成后60秒，包含准备、传输与校验 | 同左 |

时间或字节任一先到即结束该方向，不为了凑时长突破流量上限。SSH/协议开销另计，页面写明表中是“测试负载上限”，实际连接传输可能略高。高速路径在预热内触顶时可保存实际数据和校验，但标“样本较短，未形成正式测量窗口”，不能给稳定容量结论。

测试默认单条通道/单流，结果叫“SSH单流吞吐”。预热和正式阶段独立标记，历史记录两者的流量，平均结果默认只用正式且成功校验的区间；持续不足3秒标短样本。没有足够正式样本时显示已验证字节/实际时间而非编造正式均值。峰值采用1秒区间，末尾不足1秒的样本独立标注，不抬成瞬时峰值。

## 3. 候选方法与兼容

推荐采用SSH exec的内存生成/接收协议：上传由客户端产生低可压缩度的测试块、远端接收校验并回报；下载由远端产生、客户端接收校验。全程不写测试文件、不开放新监听端口、不启动持久服务。独立测试会话禁用SSH压缩，不能改变已有业务连接的压缩设置；不能禁用时方法不可用，不用易压缩数据假测速。

远端只执行随核心固定版本的短命令模板，用户输入不参与拼接Shell脚本；不上传可执行文件、不下载依赖、不自动安装Python/iperf、不索取管理员权限。准备阶段探测解释器/exec能力并显示实际方法，已缓存能力需在本次开始时轻量验证。

| 远端 | 候选适配 | 不支持时的表现 |
| --- | --- | --- |
| Linux | 已安装的Python 3，通过SSH非交互执行固定内存收发逻辑 | 无Python/exec受限则主动测速不可用，普通监控仍可用 |
| Windows OpenSSH | 已有Windows PowerShell 5.1或PowerShell 7，使用二进制标准流；方法必须标明具体运行时 | 禁止执行、二进制通道或运行时不满足则不可用，不能用文本编码模拟二进制计数 |
| OpenWrt/精简Linux | 满足Linux适配所需能力时启用 | 缺少解释器时说明能力缺失，不默认安装软件 |
| 其他SSH系统 | 只有经验证的同方法适配才启用 | 明确不支持，不假定SSH可连就能测速 |

该矩阵是拟定兼容范围，不是已经实测的支持声明。不同适配性能会受解释器、生成与摘要校验成本限制；结果显示方法，并建议只比较相同方法版本/参数。代码稿必须先验证二进制吞吐、远端硬截止/取消、无磁盘写和非压缩数据行为，再确定采用；不可行时提出替代，不自动切成磁盘读写或部署agent。

## 4. 测量、归因与数据完整性

成功发送到本机缓冲不等于远端已接收。每方向以有序帧/长度与内容校验完成后的可验证字节为准，上传必须有远端接收回执，下载在本地校验；总回执丢失则标“未完成校验/结果不完整”，不得将已排队字节当已达吞吐。

计时使用客户端单调时钟，正式阶段从首个正式数据动作到该段最后有效交付/回执结束，包含背压和必要应答耗时；记录原始时间边界及远端辅助区间，不能混用未同步的两端墙钟相减。正式算法及分段回执频率需在代码稿固定，确保计时口径可重算。

测试字节统一归“核心 → 测速任务”，与日常业务分开展示但默认计入全局总量；本机内存生成/校验不算网络字节。上/下行校验控制字节归测速控制子类，并且与大流量方向分开，不抹去反向回执流量。共享跳板不重复计，后台其他业务不会暂停或被测速强停。

数据记录包含taskId/operationId、serverId、路径修订和快照引用、连接代次、方法/运行时版本、参数、开始/结束、状态、每方向预热/正式/验证字节与时间、摘要校验状态、超时/取消原因、当时可观测的其他业务速率。运行时用户名字/凭据/数据正文不记录。

## 5. 取消、失败与清理

- 随时可取消，重复取消幂等；本机1秒内停止新数据并关闭测试专属流。释放专用租约，不断开其他消费者；公共父连接按实际剩余租约处理。
- 监控窗口关闭会取消正在准备/传输的测速，最小化和切页面保持；窗口关闭动作不等于停止普通监控或业务。工作区结束/目标被删除/App退出同样取消。单纯在后台切换工作区或编辑配置不修改已经锁定的测试路径。
- 远端适配必须有独立硬截止（任务启动后最多60秒），即使控制通道丢失也不无限生成数据/等待输入；正常取消期望5秒内远端进程结束。无法核实远端已退出时显示“本地已停止，远端结束未确认”，不能假报资源已全清理。
- 准备失败、权限/exec受限、断线、超时、摘要不符分别保留稳定原因，不自动重新跑负载。不因一次测速失败推断日常连接不可用。
- 默认先上传，若上传因路径断开或方法失败则停止后续；若用户取消则整体取消，已成功方向仍可读。某方向触及预算并完成校验属于达到预算，不是错误；短窗口另标质量。
- App异常退出后任务标interrupted，保留已持久结果和缺口，不自动恢复。历史关闭/存储失败时结果仅内存可读并提示；执行仍受原预算和取消控制。

接口建议：speedtest.prepare/start/get/cancel/results；prepare只返回实际能力/路径摘要，不跑负载。start绑定operationId、pathRevision和档位，返回taskId；重复操作返回同任务，明确错误为BUSY/UNSUPPORTED/ROUTE_CHANGED/AUTH_CANCELED/TIMEOUT/VERIFY_FAILED/RESULT_PARTIAL。路径在开始前变化返回ROUTE_CHANGED并要求刷新预览；开始后锁定原快照。

任务进度复用最新状态订阅，终态及可查询回执可靠保存；持续负载不是逐帧API调用，控制调用仍审计、任务起止/字节/结果留痕，数据正文不进入审计。测速专属额外工作内存建议≤16MiB（不含已有SSH库基线）；内存、日志和回执队列有界。

## 6. 结果比较

最近结果卡显示时间、路径、方法、双向均值及完整性；30天留存及预算遵循F-CORE-024。没有历史时显示操作引导，不填0。删除服务器仍可看旧结果但无法直接重测。

“与上次比较”只在方法版本、路径、方向、档位、压缩设置相同时默认选择上次可比较结果；并列业务负载与短样本标记。条件不同可以人工选来并排看，但不生成“带宽提升/退化百分比”的确定结论。测试结果只能作为该时间条件下的参考，实时页不拿它作永久容量分母显示占用百分比。

## 7. 验收与专属测试流程

AC-01明确启动/预算；AC-02测量与校验真实；AC-03取消清理不伤业务；AC-04方法兼容/失败诚实；AC-05历史与UI闭环。

适用r1；Windows客户端、隔离Linux Python3/Windows OpenSSH+PowerShell、缺工具的OpenWrt夹具、多跳链和可控速率服务；不在业务服务器上测速。专属入口尚未建立，自动化和原生结果分开存T-019。

| 用例 / AC | 准备与步骤 | 预期 | 清理 |
| --- | --- | --- | --- |
