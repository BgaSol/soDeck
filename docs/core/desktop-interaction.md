## 1. 目标与范围

用户反馈右键仍能看到“检查”等浏览器入口，希望屏蔽 WebView 的体验，并明确要求先设计、确认后再改。本方案将目标定义为：用户操作只呈现 SoDeck 的业务菜单、标准文本编辑和 Windows 窗口行为；底层继续使用现有 WebView。

推荐将它实现为核心内置的桌面交互模块，随核心启用并覆盖所有受管 WebView。它属于宿主公共能力，不在业务插件列表增加可卸载项；首期使用已有 Tauri/Wry/WebView2 接口，不引入第三方插件依赖。模块归属、具体交互与调试规则均属于本次待确认方案。

本期交付 Windows 行为和独立可试用目录包。范围包括主窗口、服务器工作区窗口、独立插件窗口、设置/通信监控窗口、应用菜单浮层、插件对话框的空白宿主及其实际内容 WebView；同文档内的连接首页、认证和管理界面自动继承。新建、移动后的重挂载和故障重建都走同一策略。

本期不重新设计已有业务菜单，不新增通用快捷键配置或开发者设置页，不改变 SSH/PTY、文件业务、插件权限、数据库与主题协议；不替换渲染引擎。macOS/Linux 保留适配边界，另行定义及实测后才宣称支持。

## 2. 右键、文本与键盘规则

### 2.1 右键优先级

| 对象 | 可观察行为 |
| --- | --- |
| 服务器/视图 Tab、服务器条目、文件条目等已有业务对象 | 继续打开已有菜单，使用被点击对象的稳定 ID，不重复出现第二个默认菜单，不改变原来的选中/激活规则 |
| 终端正文 | 保留复制、粘贴、字号和适用时的重连菜单；远端鼠标报告启用时普通右键交给远端，Shift+右键或菜单键打开本地菜单；不再叠加浏览器菜单 |
| 普通可编辑文本框、文本域、contenteditable | 提供原生标准编辑项：撤销/重做、剪切、复制、粘贴、全选中平台实际提供且当前适用的项目；可用/禁用和撤销栈由原生编辑器决定 |
| 只读文本及页面中已选择的普通文字 | 保留复制选中文字；只读文本框可保留原生全选，不出现写入操作 |
| 密码框 | 保留平台允许的编辑/粘贴行为，不额外实现复制或导出隐藏密码 |
| 无选择的页面空白、图片、普通链接 | 不弹默认菜单；不出现检查、重新加载、前进/后退、打印、另存为、搜索、翻译、分享或浏览器链接/图片操作 |
| 窗口拖动区域、托盘 | 保留既有 Windows 系统窗口菜单及 SoDeck 托盘菜单，关闭/收起/退出规则保持 |

应用已有菜单先处理事件，未被处理的原生上下文菜单由宿主按目标过滤。编辑菜单沿用 Windows 原生呈现，不强行套用三主题的自绘样式；沿用现有原生菜单的外观例外。无可用菜单项时直接取消，不显示空壳。

Shift+F10/菜单键与鼠标右键使用相同的对象和菜单规则；菜单支持方向键、Enter 和 Esc。Esc、点击外部或切换窗口取消后，不发送粘贴、不丢选区、不把操作作用到其他窗口，焦点按原交互恢复。禁用/只读控件不因菜单获得写入能力。

### 2.2 浏览器快捷行为与业务按键

| 输入 | 本期行为 |
| --- | --- |
| F5、Ctrl+R、Ctrl+Shift+R、Ctrl+F5 | 不触发 WebView 重新加载；原业务处理继续，例如终端 Ctrl+R 搜索远端历史、F5 交给远端程序 |
| F12、Ctrl+Shift+I/J/C | 普通启动不打开开发工具；Ctrl+Shift+C 仍可在终端复制；其他按键按原业务路径处理 |
| Ctrl+P、Ctrl+S、Ctrl+F、F7 等浏览器专用入口 | 不启动浏览器打印、网页保存、浏览器查找或插入光标浏览模式；已定义的业务处理保留，未定义时无浏览器动作 |
| Alt+左/右、浏览器后退/前进键、触控板历史手势 | 不切换 WebView 历史页面；保留原有业务按键处理 |
| Ctrl+加/减/0、Ctrl+滚轮、触控板捏合 | 不改变整个 WebView 的页面缩放；已有业务处理保留 |
| Ctrl+C/V/X/A/Z/Y、Shift+Insert、Backspace、中文 IME、AltGr | 标准编辑及终端各自的输入语义保持，不被全局拦截 |
| Windows DPI/系统文字缩放、已有终端字号设置、窗口缩放/贴靠/Alt+F4 | 保持原行为；关闭页面缩放不冻结字体大小或窗口几何 |

禁用的是 WebView 内建动作，不在全局键盘捕获阶段吞掉这些按键。若底层某条快捷路径未被原生设置覆盖，补充处理只能针对该默认动作，并验证业务仍接收到事件。终端的输入来源、一次发送、粘贴和远端鼠标规则继续由 [F-TERM-002](../plugins/terminal/features/terminal-input.md)维护。

### 2.3 导航与拖放

受管 WebView 只载入该角色的应用入口；不会因普通链接、浏览器新窗口请求、拖入文件/网址而把 SoDeck 替换成网页、打开浏览器子窗口或弹网页下载 UI。现有应用内导航、明确的宿主恢复/重建与开发 HMR 保持；开发 URL 仅在已有开发模式有效。原生文件选择器及插件通过核心执行的文件传输不属于浏览器下载。

保留已被业务接收的拖放；仅阻止未处理拖放的默认导航，不关闭所有 drag/drop，也不影响文本框内部移动文字、Tab 拖动与窗口拖动。本期不新增外部链接打开服务；已有明确的系统外链能力如存在则沿原路使用，不从被拦截的导航隐式打开外部程序。

### 2.4 默认运行与调试

普通启动包含双击的调试构建目录包：默认不开放开发工具，不因包名含 Dev 或编译为 debug 就显示“检查”。移除 Cargo 依赖中让 release 恒定拥有 devtools 的 feature；运行时同时显式配置。

开发测试沿用现有启动门槛：debug 构建且 `SODECK_DEV_MODE=1`，再为相应表面显式配置既有调试端口/参数，才保留该次运行的调试能力。调试通过既有外部调试通道进行；本方案不恢复浏览器右键菜单/默认快捷键，不新增持久化开关。release 不采纳 SoDeck 的开发环境覆盖；不得将开发端口、WebView 参数写入交付包启动入口。显式调试中的工具 reload 与普通用户快捷键刷新分开验证。

### 2.5 apple-design 的应用

## 3. 接口、所有权与失败处理

策略由核心桌面宿主持有，分别适配 Tauri 外壳窗口和 raw Wry 插件表面；不把实现下放到每个插件的启动代码。现有 `ui.menu`、剪贴板及插件输入调用保持原契约；本期不新增公开核心 RPC、SDK 字段、权限或数据库结构，不升级 API 版本。当前已兼容核心的独立插件包无需为此重新接入。

原生菜单过滤只保留原有标准编辑命令，让 WebView 执行当前文档的编辑和撤销；不读取输入框正文/选区内容转发到后台，不模拟按键完成粘贴。业务复制粘贴继续使用原有公开调用和记录。策略安装/失败只记录表面角色、所属窗口、生命周期代次和阶段，不记录密码、剪贴板或选区正文，不为每次鼠标移动/按键增加事件日志。

表面创建流程为：生成角色与策略 → 以不可交互状态创建 → 安装原生设置/菜单处理 → 确认成功 → 按既有生命周期显示/挂载。主窗口也必须在策略就绪后显示，避免加载期间短暂露出默认菜单；不以延时器猜测完成。

每个原生 WebView 只安装一次策略，相关事件 token/句柄随所属表面释放。移动新建表面使用新的生命周期代次；关闭中的迟到安装结果不得显示窗口或保留回调。Tauri 主线程和 raw Wry 原生线程分别操作自己的 COM 对象，不跨线程转交 COM 句柄或同步等待自身消息循环。

初始化/接口不可用时清理尚未显示的受影响表面，经现有窗口/插件加载失败路径报告可重试错误；主窗口失败走现有启动错误路径，不能假装初始化成功。若一次菜单过滤失败，则取消该次默认菜单并记录阶段，不回退成完整浏览器菜单。退出取消仍由原草稿确认流程处理，策略不主动终止 SSH、PTY 或其他窗口。

## 4. 实现方案与源码依据

2026-10-28只读核对发现：`apps/desktop/src-tauri/Cargo.toml` 对 Tauri/Wry 均固定开启 `devtools`；`native.rs` 已限制插件导航、新窗与下载，但未设置统一菜单/快捷键策略；外壳分散使用 `WebviewWindowBuilder`。这是源码依据，尚未原生复现用户当前运行包。

本机锁定依赖提供可用接口：Wry 0.57.0 的 `with_browser_accelerator_keys`、`with_default_context_menus`、`with_hotkeys_zoom`、`with_back_forward_navigation_gestures` 与 `with_devtools`；Tauri 2.12.5 的 `devtools`、`zoom_hotkeys_enabled`、`with_webview`、导航/新窗/下载回调；webview2-com 0.39.1 包含 `ContextMenuRequestedEventHandler`、目标 `IsEditable/HasSelection`、菜单集合和设置接口。源码存在不等于运行已验证。

| 拟修改位置 | 责任与约束 |
| --- | --- |
| `apps/desktop/src-tauri/src/desktop_interaction/`（拟新增） | 统一角色/策略、Tauri builder 适配和 Windows COM 设置/菜单过滤；必要的初始化脚本集中随模块保存，不导入插件业务实现 |
| `app.rs` | 主窗口、独立视图窗口接入；主窗默认隐藏直至策略成功，保持原恢复位置/显示职责 |
| `workbench_services.rs` | 工作区窗口接入；保留新窗取消、移动失败回退与焦点机制 |
| `settings_window.rs`、`monitor_window.rs`、`application_menu.rs` | 设置、通信监控和应用菜单表面接入；不改变各自 ready/显示及取消规则 |
| `plugin_dialogs.rs` | 空白原生宿主接入，实际插件内容继续由 raw Wry 通用路径处理 |
| `native.rs` | 所有插件正文/对话框在 `load_url`、呈现前应用原生策略，保存及释放事件注册；现有导航/下载限制继续保留 |
| `startup_config.rs`、桌面 `Cargo.toml` | 基于已解析的开发输入导出本次运行/表面调试策略，去掉 release 恒定 devtools；不新增普通设置或绕过现有开发门槛 |
| `main.rs` | 注册内置模块；不新增可安装业务插件 |
| `plugins/terminal/src/terminal-view.tsx`（仅如原生验证需要） | 远端鼠标报告分支若仍让默认上下文菜单出现，只取消该浏览器默认动作；不阻断 xterm 鼠标事件，不改变 PTY/快捷键/菜单业务 |
| 测试及独立目录包脚本（拟新增或复用） | 覆盖下节 DI 流程，输出原生证据；不得引用尚不存在的测试入口作为已建立能力 |

Windows 统一设置关闭浏览器 accelerator、页面缩放/捏合及历史手势，并按运行方式设置 DevTools。原生编辑菜单通过 `ContextMenuRequested` 过滤原菜单集合：依据目标和命令标识白名单保留编辑项，移除其他项/多余分隔符，保留原有 enabled 状态。不能用显示文字匹配菜单（受系统语言影响），不能按索引硬删“最后一项”。实际命令标识及中/英文表现必须在 DI-03 验证；未知项不放行，密码字段遵守引擎现有能力。

菜单事件默认保留给原生系统绘制，只在集合为空或处理失败时标记 handled 取消。业务 DOM 已取消的上下文事件不再另弹菜单；不额外注册一个会抢在业务前吞事件的全局 `contextmenu` 监听器。导航入口以角色定义允许的源/路径及必要查询参数，避免宽泛放行 `http:`；由宿主发起的合法初始加载/重建要单独通过。实现必须兼容当前注册协议与开发 URL，不改 profile 目录。

本方案不要求修改已 vendored 的 Tauri runtime；优先用公开 builder 和原生 COM 接口。若接口在当前实际 WebView2 Runtime 不支持，不以整页禁右键/禁复制替代约定体验；记录原生结果，提出影响明确的修订。普通内部实现细节不重新请求确认，改变本规格结果才更新方案。

## 5. 验收标准

- AC-01：所有覆盖表面的普通右键不出现浏览器项目，现有业务/系统菜单保持，无重复菜单。
- AC-02：标准文本编辑、只读复制、密码字段、中文 IME 和键盘菜单可用，取消/切换不会把操作作用到错误对象。
- AC-03：刷新、开发工具、打印/保存/浏览器查找、历史导航及整页缩放不由普通输入触发；终端/业务接收原有按键与鼠标事件。
- AC-04：普通双击启动、显式调试、release 各自符合调试规则；各类新建/重挂载/重建表面一致。
- AC-05：初始化失败及菜单失败有明确处理，事件释放、窗口取消/退出无残留；原会话、数据、插件契约保持。
- AC-06：独立 Windows 目录包真实运行通过必需测试；浏览器模拟、原生操作、真实远端服务及安装结果明确区分。
