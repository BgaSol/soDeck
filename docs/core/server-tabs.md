## 1. 对用户意图的理解

2026-10-26 启动与打开规则覆盖：[F-CORE-010 r2](clean-start.md) / [T-009](../tasks/T-009-clean-start.md) 定义完整重启主窗口空态、新建服务器工作区自动首终端连接。本文 §5 最后段及 ST-12 的旧服务器顺序、子窗口和结束占位恢复由新规格替代；ST-10 的持久化部分与 ST-17 的重启验证按新规格 §6 调整。§3.3/ST-02 以 r7 的首终端规则替代原来“打开不连接”；定位、拆合、托盘、关闭和唯一归属保持，T-004 原确认及实测仍只证明原修订。此次确认、实现及验证见 T-009。

用户明确要求：不显示顶部标题栏；服务器列表作为顶部 Tab；可以在新窗口打开，也可以合并回主窗口；本轮先理解并给出功能设计。

推荐把“服务器”作为窗口中的一级工作单元。一个顶部 Tab 对应一台服务器的完整工作区，带着工具面板、内部页面、分屏和会话一起移动。用户可以把服务器 A 放在主屏，把服务器 B 拆到副屏，之后将 B 合并回来继续工作。

本轮推断及推荐细节：

- 顶部 Tab 是已打开的服务器工作区；全部已保存服务器通过“＋”选择器查询，不必同时铺在顶部。
- 一个服务器档案在同一个 App 中只有一个工作区承载位置；再次打开时找到已有位置。
- 主窗口和新增工作区窗口采用相同工作台结构，每个窗口都可容纳多个服务器 Tab。
- 切换、拆出、合并是布局操作，保持连接和会话；关闭服务器 Tab 才结束该工作区。

以上推断随后连同代码方案获得用户确认；不是用户最初需求的逐字复述。产品方向记录在 P-20、P-21，确认记录见 T-004。

### 3.1 顶部融合窗口控制

- 移除独立原生标题栏，不再另外显示“SoDeck”标题行及重复的大号服务器标题行。服务器 Tab 行贴近窗口顶部，Windows 最小化、最大化/还原、关闭固定在同一行右端。
- 建议顶部高 44 个逻辑像素，服务器 Tab 常规宽度 120–220；名称超长省略，悬停/键盘聚焦可查看完整名称、账号与地址。字号采用系统字体 13–14，选中项用字重、背景和边界共同区分，不能只依靠颜色。
- 系统按钮保留 Windows 顺序、命中区和关闭按钮反馈。顶部空白区域拖动窗口、双击最大化/还原、右键打开系统菜单；Tab 内容拖动服务器，按钮只处理点击。所有交互区域排除窗口拖动命中，避免点击变成拖窗。
- Tab 溢出时仍保留至少一段约 48 逻辑像素的窗口拖动区域及系统按钮。窗口边缘缩放、任务栏操作、Alt+Space、Windows 快捷键、拖窗贴靠与最大化按钮的 Snap 布局需原生验证。
- 系统窗口标题与无障碍名称仍存在：如“生产 A — SoDeck”，用于任务栏、Alt+Tab 和辅助技术；它们不占一行可见标题栏。
- 全局菜单位于左端，整理服务器管理、插件、资源及退出等现有入口，并提供“显示主窗口”和“召回所有窗口”。设置入口随其自身功能范围提供，本轮不扩建设置页面。全局页保持 App 作用域，不冒充某台服务器页面。工作区工具入口留在工作区内，随活动服务器切换。

上述数值用于本功能初版评审，在 100%/150%/200% 缩放和系统文字放大下检验，不自动成为全应用主题规范。终端内容保持不透明；窄窗口优先溢出菜单与滚动，不隐藏关键窗口操作。

### 3.2 两层 Tab

| 层级 | 对象 | 切换时发生什么 | 拖出对象 |
| --- | --- | --- | --- |
| 窗口顶层 | 服务器工作区 | 切换该窗口内的工具、内容页、分屏与焦点 | 整份工作区 |
| 工作区内部 | 终端及其他插件视图 | 切换当前区域中的具体页面 | 按该视图声明弹出单页 |

取消左侧常驻服务器列表；左侧空间用于当前工作区工具和可收起面板。现有会话列表仍是终端插件的停靠视图。内部工具栏与页面 Tab 合理对齐，不再加一层重复服务器大标题；需提示操作目标时在对应对话框、菜单及状态位置明确服务器。

### 3.3 服务器选择器与大量 Tab

- “＋”打开可搜索的服务器选择器，显示全部已保存档案，提供已有“添加服务器”入口。按名称、地址、账号过滤；列表区分“未打开”“本窗口已打开”“其他窗口已打开”。不展示秘密。
- 选择未打开档案：在当前工作区窗口末尾建立并激活一个 Tab，自动创建一个首终端并连接；阶段、认证、失败/取消和原位重试见 F-CORE-010 §2.4。选择已有档案：激活其 Tab 并聚焦承载窗口，不增开终端；即使原终端已关闭/断线也不自动补建。
- 条目菜单提供“在新窗口打开”。未打开时新建工作区窗口；已在其他位置打开时菜单改为“移至新窗口”，移动已有工作区，避免暗中复制。
- “＋”选择器与“▾”已打开页签列表职责不同；后者可搜索所有窗口的已打开工作区，条目标明所在窗口，选择即定位。Tab 过多时单行横向滚动，当前 Tab 自动进入可见区域，不换行挤占内容高度。
- 主窗口没有 Tab 时显示轻量空态与“打开服务器”“添加服务器”，不自动创建测试档案或连接。新增服务器推荐“保存并打开”，成功创建工作区即自动首终端；编辑既有档案仅保存。删除服务器仍走已有引用检查，关闭 Tab 不等于删除档案。
- Tab 状态来自已有连接/会话事实，不主动轮询探测：无活动连接、连接中、存在活动连接、存在异常分别说明；混合状态优先显示异常，并在详情列出活动/失败数量。“有活动连接”不表示该服务器全部工具健康。

## 4. 拆出、移动与合并

### 4.1 基本操作

| 操作 | 行为及完成反馈 |
| --- | --- |
| 点击服务器 Tab | 仅激活当前窗口内工作区，恢复其面板、分屏、活动内部 Tab 和最后有效焦点；其他窗口不切换 |
| 同行拖动 Tab | 移动约 8–10 逻辑像素后进入拖动，保留抓取偏移，显示插入位置；松手提交排序，Esc 取消 |
| 将 Tab 拖出窗口 | 显示工作区标签预览；松手后在释放位置建立独立工作区窗口，迁移成功才从源窗口移除 |
| 将 Tab 拖入另一个工作区窗口顶部 | 显示目标插入位置；松手后把工作区移动到该窗口并激活。不能把服务器 Tab 放进内部终端 Tab 组 |
| Tab 菜单“移至新窗口” | 与拖出等价，不要求鼠标拖动；新窗口默认出现在当前显示器的可见区域 |
| 子窗口 Tab 菜单“合并回主窗口” | 移至主窗口最后一项并激活；若主窗口在托盘，则显示并聚焦主窗口 |
| 子窗口菜单“全部合并回主窗口” | 按子窗口当前顺序将全部服务器追加到主窗口；保留主窗口原顺序，并激活子窗口原活动服务器。整批成功后关闭空子窗口 |

通过拖动合并时采用明确预览的插入位置；通过菜单合并时追加到尾部。释放规则以当前预览为准：

- 在服务器 Tab 行：按插入线排序或跨窗合并。
- 在任一 SoDeck 窗口的内部内容区、单视图窗口或窗口控制按钮上：显示不可放置，释放后回到源位置，不拆窗、不触发业务页面操作。
- 移出 SoDeck 窗口，在系统允许的位置（桌面或其他应用上方）：明确预览“移至新窗口”，释放后在当前显示器可见区域建窗；不向其他应用发送内容或放置操作。
- 操作系统不允许放置、取消拖动或按 Esc：保持原位置，不创建窗口。

主窗口身份固定：移走最后一个服务器后仍保留主窗口空态与托盘入口；子窗口移走或关闭最后一个服务器后回收空窗口。不会因某个窗口最后剩下一个 Tab 而自动改变主窗口身份。

### 4.2 “整份工作区”包含什么

一起移动：工作区标识、该工作区中的侧边工具/面板、内部 Tab 顺序、两区域分屏及比例、活动页、可恢复的筛选/选择/滚动状态和焦点。终端会话、PTY、连接租约、当前远端目录与进程保持原有身份；迁移不新建 shell、不重放命令。

工作区整体移窗只改变外层宿主。一个只支持左侧停靠的视图，到新工作区窗口仍然停靠左侧；不要求插件为了整工作区移动而声明支持“单视图独立窗口”。

已经单独弹出的终端视图保持原位与同一工作区归属，不自动吸回或再拆出。其按钮统一改为“返回所属工作区”，返回到该工作区当前承载窗口。单视图窗口以紧凑的“服务器 · 视图名”与窗口控制共用顶部一行，不冒充完整服务器 Tab 窗口，也不接受服务器 Tab 落入。

### 4.3 唯一归属与失败处理

- 同一档案只对应一个打开的工作区，工作区只归一个工作区窗口。重复点击、拖动与菜单同时触发不能产生副本；同地址不同账号用不同档案区分。
- 迁移期间源位置保留可恢复占位，显示“正在移至新窗口/正在合并”与取消入口；目标就绪前不移除源工作区。其他服务器仍可操作，不全应用阻塞。
- 工作区内所有待搬移表面作为一批准备。任一必要表面准备失败，整个工作区回到原位；全部合并操作则以该批全部工作区为单位。业务已失败的视图可搬移其明确错误占位，不把错误占位假装加载成功。
- 仅在交接阶段短暂冻结受影响视图的新输入，旧输入法组合按既有契约完成或取消，不重放原始事件；输出使用有界缓冲/序号续接。每个逻辑视图只允许一个有效输入表面。
- 用户取消、创建失败、目标窗口销毁、超时或插件状态无法迁移：显示明确原因，未提交则保持原归属和会话。若源表面也失效，核心保留权威资源状态与恢复入口，不声称会话已关闭或已恢复。
- 提交回执丢失先查询同一操作结果，不重建窗口。已提交但保存失败时保留已完成位置，提示“移动已完成，但布局未保存”；下一次保存可重试，不能谎报移动失败。
- 同一工作区的移动、关闭、归属变更串行执行；其单视图弹出/返回纳入同一协调范围。迁移中再次关闭记录一次请求，迁移提交或回滚后执行；明确 App 退出先取消迁移再清理。
- 连接中或认证对话框尚未完成时允许切换其他工作区，移窗先提示“请完成或取消当前连接操作”；待操作完成可再移动。当前账号与认证请求不能被路由到另一服务器。

## 5. 关闭、收起与重启

以下关闭细节属于本轮建议，主窗口托盘与 App 退出沿用 P-18、P-11：

| 操作 | 结果 |
| --- | --- |
| 切服务器、最小化、拆出、合并 | 会话继续运行；布局移动不执行关闭回调 |
| 顶部服务器 Tab 的“×”/菜单“关闭服务器工作区” | 结束该工作区内全部普通会话及所属视图，包括之前单独弹出的视图；不删除服务器档案 |
| 主窗口右上角“×”/系统关闭命令 | 收起主窗口到托盘，其他窗口及所有会话继续 |
| 独立工作区窗口右上角“×”/系统关闭命令 | 结束该窗口内全部工作区及它们所属的单视图窗口；其他窗口的工作区继续 |
| 独立视图窗口“×” | 只关闭该视图及其按现有规则持有的会话 |
| “合并回主窗口” | 保留会话；成功后空子窗口被回收，不执行工作区关闭 |
| “退出 SoDeck” | 结束全部窗口和 App 持有资源，包括明确保留的运行资源 |

服务器 Tab 关闭按钮的提示写明“关闭工作区并结束其会话”，子窗口系统关闭按钮提示说明范围；主窗口关闭提示“收起到托盘”。批量关闭先收集各视图已定义的未保存检查，任何取消都发生在实际释放之前。现有终端关闭不增加逐次确认弹窗，也不新增尚未实现的关闭后会话托管。

关闭活动 Tab 后优先激活其右邻，否则左邻；无相邻项按主/子窗口空态规则处理。关闭非活动 Tab 不改变当前焦点。托盘不可用时主窗口保持可访问，不能将唯一管理入口藏掉。

保存窗口角色/位置、每窗服务器顺序与活动项、工作区内部布局、独立视图位置。正常重启恢复布局及结束占位，不自动连 SSH，也不宣称旧 PTY 复活。显示器减少时将窗口移回当前可见区域，提供“召回所有窗口”。旧布局升级后已有打开工作区按原顺序归主窗口、保留原活动项和独立视图，升级先备份，失败保持原文件并给出恢复入口；损坏条目不能静默清空全部布局。

## 6. 核心状态与插件边界

此处定义功能契约含义，具体接口、schema、运行预算及迁移方式已在[代码修改方案](../technical/server-tabs-implementation.md)提出；新契约尚未实现，不是已发布 SDK。

### 6.1 插件业务实例、会话、视图和窗口

用户进一步询问每个终端窗口是否为独立插件实例，以及本次 Tab 改动对终端和核心的影响。本轮推断：用户在检验公共工作台是否具有可复用边界，希望明确实例成本、状态归属与故障范围；不把提问视为对新方案的确认。

2026-10-25 在 `b1da221` 源码核实：

| 对象 | 当前事实 | 拆出服务器 Tab 时的建议行为 |
| --- | --- | --- |
| 终端插件包 | `sodeck.terminal` 的一个激活版本，含 UI 与 worker | 包和版本不变 |
| 插件业务实例 | App 的 `State.loaded` 持有一个长期运行的终端 `PluginProcess`；所有窗口调用该进程 | 实例 ID 与 worker 进程不变，不按窗口/服务器再启动 |
| 终端会话 | worker 的 `sessions` Map 按会话 ID 存放，记录 serverId/workspaceId；每个终端有自己的 PTY 与租约 | 会话、服务器目标及资源身份不变 |
| 逻辑视图 | 会话列表每工作区一个，终端会话视图可多个；各有 viewId | viewId 不变，改变外层窗口归属 |
| 渲染表面 | 每个已挂载视图有独立 UI 上下文；可能初始化新的 xterm / React 根 | 可以重建 UI 表面，通过快照和新挂载代次接回同一会话 |
| 原生窗口 | 现有为主窗口或单视图窗口；完整工作区窗口尚未实现 | 新增外层容器，仍使用同一 App 与插件业务实例 |

证据：`apps/desktop/src-tauri/src/app.rs` 的 `State.loaded`、`spawn_plugin`、`worker`、`create_binding` 和启动流程；`plugins/terminal/src/worker.ts` 的会话 Map；`plugins/terminal/src/main.tsx` 的按视图类型渲染。更新启动校验可临时创建并停止候选 worker，不计为按窗口常驻实例。当前加载入口针对 `sodeck.terminal`，不能由此宣称完整多插件运行注册及真实并行运行已经验证。

同一业务实例不等于共享一个会话或一份画面。例如 A 两个终端、B 一个终端分布在两个窗口，仍为一个业务实例、三个会话与三份终端视图，另有各工作区会话列表。已有终端总量预算按 App 计算，拆窗不重置计数。WebView 的操作系统进程分配不等同于插件业务实例粒度。

建议本次维持每插件一个业务实例，按工作区隔离业务数据。该粒度的限制也必须说明：终端 worker 真正崩溃时，当前宿主回收它的普通资源，可能影响全部服务器终端；单个表面失效走视图恢复，两者不能混为同一故障。每服务器/每会话独立 worker 属于另一项运行隔离设计，不由本次 Tab 功能自动引入。

### 6.2 窗口与工作区的权威状态

| 核心状态 | 拟持有信息与约束 |
| --- | --- |
| 窗口记录 | 稳定 windowId、main/workspace/view 角色、边界和显示状态；主窗口身份不漂移 |
| 工作区窗口 | 有序 workspaceIds、该窗口自己的 activeWorkspaceId；取代 App 唯一活动工作区对所有窗口的控制 |
| 工作区记录 | serverId、ownerWindowId、内部布局及修订；服务器目标不因移动改变 |
| 逻辑视图 | viewId、workspaceId、展示位置、挂载代次；浮动单视图的归属仍可查 |
| 布局操作 | operationId、源/目标、批次、预期修订、准备/提交/回滚及持久化结果；可查询、可去重 |

拟需命令语义：打开/定位工作区、按窗口激活、Tab 排序、移动一个工作区、整窗合并、关闭工作区/工作区窗口、查询布局及迁移结果。响应区分未提交失败、已提交、已提交但未持久化；事件携带窗口/工作区与布局修订。旧修订、已关闭对象、忙碌、目标不兼容、目标失败、存储失败需可辨认。

窗口身份由宿主绑定；命令按触发窗口与工作区路由，不读取“主窗口当前服务器”来操作其他窗口。底层连接/PTY 仍由核心资源层持有，插件业务实例和版本不因增加工作区窗口而再启动一份。插件调用核心继续统一留痕，不引入插件授权。

布局不保存秘密、终端正文和有效运行句柄。工作区批量移动复用单视图迁移能力，增加协调与原子归属提交；原生视图可能重建，不承诺把 WebView/DOM 原地搬动。

本设计不放宽已存在的 8 个终端与 2 个单视图独立窗口预算；完整工作区窗口与单视图窗口分别计数。本次不新增工作区子窗口的产品数量上限，最低验证场景为主窗口、两个工作区子窗口和两个单视图窗口；窗口创建失败回源。每视图/批次快照额度、时限和压力场景见[实施方案第 8 节](../technical/server-tabs-implementation.md#8-运行预算性能与边界)。若需新增用户可见数量限制，在实施前提供具体影响，不能编码后以限制缩减本方案。

### 6.3 当前缺口与建议补齐的公共契约

核心持有 SSH/PTY、流和租约符合既定边界。需收敛的是工作台对终端业务的直接识别：现有 `workbench.openTerminal` 调用 `sessions.create/bind/close`，`plugin.invoke` 的分派直接识别 `sessions.rename/reconnect`，工作台 `View` 含 `session_id/pty_id`，激活/挂载/移回路径多处固定使用主窗口。会话列表视图虽按 workspaceId 查询，仍依赖终端专用开页入口。独立插件包与 UI/worker 已存在，通用工作台接口尚未完整实现。

以下是本次提出的实施增量，尚待确认；名称描述语义，不作为可调用 SDK 方法清单：

| 公共能力 | 已有基础 | 建议本次补齐 |
| --- | --- | --- |
| 窗口与工作区服务 | 单主窗口活动工作区、单视图弹窗 | 每窗活动工作区、Tab 顺序、归属查询、打开/定位、整工作区拆合；按实际源窗口路由 |
| 通用视图与命令注册 | manifest 视图声明、移动/关闭、终端专用新建入口 | 插件声明命令与工作区入口；宿主携带明确上下文调用所属 worker；按视图类型打开/激活，插件提交标题/状态等元数据；移除外壳对终端业务命令名的分支识别 |
| 生命周期与批次迁移 | 单视图准备、快照、就绪、提交/回滚、挂载代次 | 统一的关闭准备/取消/提交与资源归属，迁移与业务关闭分开；整工作区多表面协调，不逐个提交出半迁移状态 |
| 上下文与事件 | viewId/workspaceId/serverId/挂载代次，统一变更通知 | 窗口身份由宿主绑定；按工作区/视图/窗口明确事件作用域和修订、支持快照恢复；激活事件不改写已存在会话目标 |
| 视图与资源绑定 | 核心 PTY、租约、绑定及输入代次 | 插件建立逻辑视图与所属业务/资源的关系，宿主按公共生命周期通知并协调释放；终端会话模型留插件，PTY 适配留核心能力层，工作台布局不解析终端业务字段 |
| 原生服务与契约兼容 | 单视图窗口、托盘、部分输入恢复和版本声明 | 统一融合顶栏、DPI/焦点/窗口操作；公开契约的版本与支持范围明确，缺失能力给出准确兼容提示，不靠私有外壳接口接入 |

“调用所属 worker”指宿主路由外壳命令，以及插件自己的 UI 与自己的业务实例通信；不开放 P-13 排除的插件互调，不新增权限清单。资源归属用于关闭正确性，不是权限审批。当前只有一个实际业务插件，本轮不因此扩建市场、多插件调度平台或引入第二个产品插件；通用契约可用测试夹具检查，不把夹具写成真实跨插件交付。

终端的具体适配：保留现有 SSH/PTY 会话业务和渲染；把新建、重命名、重连后的视图元数据更新及关闭处理接入公共契约；列表按自身工作区查询和定位，视图按挂载协议交接屏幕、滚动与输入状态。服务器 Tab、窗口按钮、拆合、保存窗口布局继续由核心完成。仅改变外壳导航的部分原则上不应要求终端改业务；当前补齐契约可能需要核心与终端一次配套升级，不能承诺本次完全零改动或旧插件自动支持未提供的能力。支持版本须在实施方案中明示。

## 7. apple-design 的应用与键盘行为

已读取并使用 `apple-design`：

- 即时反馈：Tab 按下立即响应，切换不等待服务器网络；迁移进度与异步完成分开呈现。
- 直接操作与空间一致性：拖动跟手、保留偏移，插入线对应真实落点；迁移失败回到源位置；弹出和合并都有明确来源与去向。
- 克制且可中断：位置吸附从当前呈现状态继续，默认不反弹；建议响应约 0.3 秒的临界阻尼，仅用于收尾，不延迟输入或提交。减少动态效果时即时切换/短淡化。
- 清晰层次：服务器为一级、插件页面为二级；内容区稳定，透明只用于不损害对比的外壳。高对比与减少透明偏好使用实色和可辨边界。
- 平台熟悉度：Windows 控制位于右上；原生移动、缩放、Snap、任务栏、输入法保留。跨屏尺寸使用正确坐标与 DPI，不把逻辑像素直接当屏幕物理像素。
- 键盘可达：Tab/Shift+Tab 可进入菜单、选择器和页签组；组内方向键/Home/End 定位，Enter/Space 激活，Shift+F10 打开菜单，Esc 取消选择/拖动。菜单提供移窗、合并、关闭等价路径。焦点停在页签与菜单时才处理这些外壳键，终端已聚焦时保留其业务按键映射。
- 焦点恢复：迁移后恢复原活动视图；若不可恢复则落在目标服务器 Tab。需要认证或错误处理时明确聚焦相应对话框/恢复操作，不能把输入送往后台终端。
