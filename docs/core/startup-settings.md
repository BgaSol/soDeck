## 1. 目标与范围

用户在收到 T-004 开发包后询问：“怎么是一个启动脚本？这些参数，可以放到 app 内部设置吗？你理解一下我的意思，推断一下我的意图，出一个后续设计方案。”本次授权为核实、推断和设计，未授权本功能编码。

推断目标：用户双击应用即可运行，启动所需的常规配置由 App 负责；需要查看或调整的项目有明确入口，用户无需理解环境变量。启动自动化、用户设置、插件业务设置应分别由原有责任模块承担。此推断及以下推荐方案待用户确认。

首轮包含：

- Windows 目录包以 GUI EXE 为直接入口，自动定位随包资源与数据，不依赖 CMD、开发机源码路径或当前工作目录。
- 当前交付继续采用便携目录包的数据隔离方式；保留系统用户目录作为非便携模式的既有默认。
- 提供 App 级“设置”入口，显示实际运行方式、数据位置、版本及插件管理入口；可打开数据文件夹、复制路径，查看必要诊断信息。
- 启动失败可见且可恢复；保持已有插件独立更新、数据目录锁及退出生命周期。

后续范围：自定义数据目录及迁移、正式安装器/快捷方式/签名、更多应用偏好。它们不是本轮默认实施项；见第 7 节。不会借本轮改造插件实例模型、工作台、SSH、存储 schema 或建设通用配置平台。

## 2. 现有启动参数的去向

| 当前脚本项 | 当前用途 | 推荐处理 | 首轮用户入口 |
| --- | --- | --- | --- |
| `SODECK_DATA_DIR` | 将数据固定到目录包的 `data/`，隔离开发环境 | 核心启动时按运行方式确定；当前便携包延续 `data/` | 显示实际位置、打开文件夹、复制路径；自定义迁移后续设计 |
| `SODECK_PLUGIN_PACKAGE` | 指定出厂终端包 | 发行资源目录自动发现；插件管理器验证及安装，已激活版本仍由其管理 | “插件管理”；不暴露每次启动的原始包路径输入框 |
| `SODECK_PLUGIN_KEYS` | 指定出厂开发签名公钥文件 | 随核心交付的信任材料，由插件管理器使用；保持现有验证规则 | 显示插件校验/失败状态；不作为普通可编辑设置 |
| `SODECK_SHELL_DEBUG_PORT` | 指定外壳调试端口；脚本将其清空 | 日常启动关闭，仅显式开发/测试运行可覆盖 | 诊断信息显示是否处于调试运行，不新增普通端口设置 |
| `SODECK_WEBVIEW_ARGS` | 为插件 WebView 注入调试参数；脚本将其清空 | 同上；日常启动不从继承环境隐式启用任意参数 | 不提供任意 WebView 参数文本框 |

“由 App 管理”包含自动默认、应用设置和内部配置，不等于将所有环境变量做成表单，也不意味着把用户路径写死进 EXE。终端字号等插件偏好仍由终端拥有自己的存储和规则；本轮不搬到核心设置中。

## 3. 启动和数据规则

### 3.1 目录包与资源

交付包含 EXE、`resources/`、便携标记及说明；用户只需双击 EXE。打包工具生成便携标记，用户无需手工编辑它。该标记只声明便携运行和 schema 版本，不承载任意插件、数据或公钥路径。

- 所有包内路径相对实际可执行程序/框架资源目录解析，绝不相对终端或快捷方式的工作目录。
- 目录包从 EXE 相邻 `resources/` 取得配套出厂插件与公钥；缺失时报出缺失项目及“恢复完整应用文件”的处理方式。交付模式不回退读取编译时源码仓库。
- GUI EXE 不弹出黑色控制台。内部插件 worker 的启动与管道通信照旧；仍须回归其启动、故障和退出，不能为去掉控制台而破坏 worker。
- 保留插件管理器现有的签名、兼容、重启激活及回退。重新启动不会用出厂包覆盖已激活的兼容新版插件。
- 这仍是开发目录包，不据此宣称完成安装器、签名或公开发布。

### 3.2 数据位置和优先顺序

正常运行：有效便携标记 → EXE 同目录 `data/`；无标记 → 当前应用标识对应的系统用户数据目录。开发版本继续使用 `com.sodeck.v2.dev` 隔离身份，不修改 v1 或日常数据。

显式开发/测试运行可在上述默认前采用原有环境覆盖，但必须同时满足调试构建和明确开启开发覆盖模式；普通双击不受遗留 `SODECK_*` 环境影响。测试路径覆盖只替换启动输入，不走另一套插件或资源生命周期实现。覆盖只提供一组集中解析规则，错误、来源和实际值可查询；部分缺失的包/公钥覆盖应报错，不能悄悄忽略。正式发行构建忽略开发覆盖。

一个进程启动完成后数据根固定，所有窗口读取同一结果。首轮设置页不提供运行中换目录或便携/标准模式切换。

失败规则：

- 数据目录不可写、标记损坏或版本未知：显示明确启动错误和实际目标位置，结束启动；不静默改用另一个空目录，不新建第二套数据库。
- 同一数据目录已有实例：沿用目录锁，不开启第二个写入者；显示已有实例运行的提示。本轮不新增跨进程唤醒服务。
- 核心数据无法打开：保留原文件，显示错误，不能把损坏当作首次空启动。
- 插件缺包/无效：核心可运行时进入现有降级界面，保留服务器与插件管理入口，显示失败原因；不绕过校验、不自动连接 SSH。
- 启动早于工作台时发生的错误用原生可见错误界面承接，不依赖已经失败的数据库或插件来显示错误。可复制错误摘要、关闭；不自动重试循环。

### 3.3 对当前 T-004 数据的影响

当前脚本用户继续使用同一 `data/`；新版本补上便携标记后直接启动仍解析为这个位置。更新目录文件时不覆盖或清理 data。新输出使用独立目录，保留旧包；如验证旧数据，先复制并关闭旧实例。开发包移动时应用与 data 一起移动，不能承诺只拷贝 EXE 就包含插件和数据。

便携在这里指应用与普通数据可放在同一目录；现有 Windows 保护的凭据仍受当前账号/机器约束，不承诺跨机器携带密码。本轮不导入 v1 数据、不自动扫描其他旧包。

## 4. 应用设置与 UI

入口为现有应用菜单中的“设置”，App 作用域，复用现有管理对话框承载规则。任何窗口打开都展示同一个运行环境；关闭设置返回原窗口和焦点，不触发工作区迁移、断线或重连。不新增服务器 Tab。

首轮为三个紧凑分组，不建设空的多级设置导航：

| 分组 | 内容及操作 |
| --- | --- |
| 应用与数据 | 应用版本/开发渠道、运行方式、当前数据位置；“打开文件夹”“复制路径”。首轮位置只读，标签明确，不出现不能使用的“更改目录”按钮 |
| 插件 | “管理插件”跳转已有插件页，仍在 App 范围；返回设置时恢复焦点。版本、更新和失败状态只由插件管理器提供，不维护第二份状态 |
| 诊断信息 | 默认折叠，显示资源位置、配置来源和调试运行状态；可复制版本/模式/错误摘要。完整路径只在明确的复制路径操作中进入剪贴板，不自动采集或上传环境变量 |

本轮设置页是应用信息与管理入口，不假设新增了一组尚未定义的偏好；没有编辑项时不出现“保存/应用”按钮。后续加入确有需求的可编辑项时分别定义所有者、默认值、生效时机、持久化和失败处理。

按 `apple-design` 应用：

- 熟悉与简洁：用户先看到数据在哪里、如何打开；资源布局与诊断折叠一层，避免展示内部变量名作为主标签。
- 即时反馈：打开文件夹与复制操作显示完成/失败；不关闭弹窗或改变当前服务器。重复点击打开操作在进行中禁用，完成后恢复。
- 层次与空间：复用系统字体、现有颜色和间距；长路径可折行/选取，不挤压按钮；在现有最小窗口及 200% 显示缩放下可用。
- 键盘与可访问性：有可读标题、状态与错误，Tab 焦点留在弹窗，Esc 关闭并返回入口；折叠项有展开状态，加载/禁用行为可感知。
- 克制动效：沿用现有短淡入或无动画，遵守减少动态效果与高对比度；本轮不新增弹簧库或视觉体系。

## 5. 模块、接口与状态所有者

| 层 | 本次职责 | 不承担的职责 |
| --- | --- | --- |
| 核心启动适配 | 解析运行方式、确定路径、检查标记/覆盖、持有不可变启动结果、获取数据目录锁 | 终端业务设置、插件私有会话数据 |
| 核心存储 | 在已确定的根目录打开现有数据库/配置，处理原有错误和资源释放 | 根据 UI 当前状态偷偷切换根目录 |
| 插件管理器 | 使用解析后的资源和数据位置，验证/选择/激活/回退独立插件 | 让终端组件决定包位置或签名者 |
| 外壳设置组件 | 读取公开环境信息、呈现状态、发出打开目录/复制请求 | 直接读取环境变量、扫描磁盘、修改核心路径或读取插件私有文件 |
| 业务插件 | 继续使用原 SDK 和自己的设置存储 | 感知便携标记、管理 App 启动或携带核心配置副本 |

拟增量契约（尚未实现）：

- `app.info` 保留已有字段，增加 `environment`：`mode`（portable/user/development）、`dataPath`、`resourcePath`（未定位时 null）、`source`（portable/default/development）、`diagnosticsEnabled`、`channel`。数据来自本次启动的有效结果，不直接回显全部进程环境。既有消费者可忽略新增字段。
- `app.openLocation({location:"data"|"resources"})` 打开已解析、存在的目录，成功为 `{opened:true}`；不接受任意命令或调用者拼接的路径。目录不存在返回 `NOT_FOUND`，参数不合法返回 `INVALID_PARAMS`，系统打开失败返回 `INTERNAL`。检查后目录消失仍须明确报错。
- 复制路径复用 `clipboard.writeText`；插件管理复用既有页面和 `plugins.*`。不新增终端专用核心命令或更改插件 API 2 的生命周期。
- 调用走现有 RPC/记录路径，App 操作不伪造服务器或工作区。遵守 P-14，无插件权限表；来源/参数校验用于正确归因。日志摘要记录方法、location 枚举、结果与错误，不录入剪贴板全文或秘密。
- 环境在本进程不变，无需新增环境广播、配置订阅中心或配置数据库。启动失败在 RPC 可用前的记录使用最小本地错误信息，不假装经过尚未打开的调用数据库。

## 6. 验收与本功能测试流程

适用 r1。使用 Windows、独立目录与测试账号/数据；不访问日常服务器。静态/浏览器、实际 GUI 启动及 SSH 回归分别记录。新入口在确认后建立，当前不能视为可运行；结果只记入 T-005。

| 验收项 | 可观察结果 |
| --- | --- |
| BOOT-AC-01 | 无启动脚本、无预设环境，从资源管理器或其他工作目录启动 EXE，得到相同运行结果且没有控制台窗口 |
| BOOT-AC-02 | 同一便携目录始终使用包内 data；旧数据保留；路径失败不静默创建另一套数据；目录锁有效 |
| BOOT-AC-03 | 设置显示真实环境并可打开/复制；App 作用域与核心/插件边界清晰，打开设置不影响现有会话 |
| BOOT-AC-04 | 出厂资源缺失或无效有可操作反馈；已激活插件独立更新、回退与退出行为保持 |
| BOOT-AC-05 | 普通启动不会被遗留调试环境改变；开发测试可显式使用隔离覆盖，且仍走同一核心路径 |

拟测试入口：启动解析的 Rust 单元测试、SDK 正反例、设置页浏览器测试；新增目录包启动检查（拟 `tests/desktop/startup-settings.mjs`）及真实 Windows 操作。无调试覆盖的直接启动须实际验证，不能仅使用设置了环境变量的旧 harness 证明。

| 用例 | 准备及操作 | 预期 / 对应验收 | 验证层 |
| --- | --- | --- | --- |
| BOOT-01 | 将全新目录包复制到含中文和空格的位置；清除本次进程的覆盖；实际双击 EXE | 直接显示应用，无 CMD/控制台；出厂插件可用、无 SSH 自动连接 / 01、04 | Windows 实际运行 |

| BOOT-06 | 在测试副本移走/损坏出厂包及公钥；另用已有活动版本副本启动 | 报出实际缺失/校验错误，无源码目录兜底或绕过验证；可用核心保留管理入口 / 04 | 管理器 + 原生 |
| BOOT-07 | 仅替换目录包程序资源，保留有较新兼容插件的测试 data；运行原独立更新/回退用例 | 已激活新版不被出厂包覆盖；仍重启后生效；旧核心、坏包与签名规则不变 / 04 | 包/原生回归 |
| BOOT-08 | 主窗和子窗分别打开设置，切换服务器，复制/打开目录，进入插件管理再返回 | 相同 App 信息；路径和模式正确；按钮反馈、焦点返回；不增加 worker/连接、不串服务器 / 03 | 浏览器 + 原生 |
| BOOT-09 | 长路径、最小窗口、200% 显示缩放、键盘 Tab/Esc、减少动态效果/高对比度 | 内容可读可操作，无裁切；折叠和状态有语义；原终端输入焦点可恢复 / 03 | 浏览器 + 原生 |
| BOOT-10 | 普通启动前仅给子进程设置旧数据/包/公钥/调试环境；再显式开启开发覆盖及测试不完整覆盖 | 普通模式忽略；调试构建显式覆盖可隔离且可查询来源；不完整覆盖可见失败；非调试构建忽略覆盖 / 05 | 单元 + 进程/端口检查 |
| BOOT-11 | 使用隔离 loopback SSH 打开终端，打开/关闭设置、工作区拆合，随后明确退出 | 插件职责、单 worker、PTY 身份及资源清理保持；正常退出码 0 / 03、04 | 现有原生回归 |
| BOOT-12 | 对公开信息/打开位置接口发合法与非法参数，模拟路径被删除、系统打开失败 | schema/错误/调用记录一致；不执行任意命令，失败不影响 SSH；重复只读调用无持久副作用 / 03 | Rust/SDK 契约 |

每次结束停止本次 App、worker、loopback SSH 和测试监听；正常退出核对资源及锁释放。恢复本次修改的目录权限与剪贴板、关闭本次打开的文件管理器窗口；只清理测试副本，保留脱敏截图、错误与哈希。设置了环境的测试仅影响所启动子进程，不改系统环境。无调试 EXE 的 UI 运行证据与调试夹具证据分别记录。

## 7. 后续阶段的范围与待决项

第二阶段可提供“设置 → 数据位置 → 更改”，但需单独细化并确认：选择空目录还是接入已有数据、复制迁移与取消、目标冲突、空间不足、崩溃恢复、重启及旧数据保留。推荐新位置下次启动生效，运行中不切数据库；迁移由核心统筹，设置组件只提交意图，插件不自行搬家。

定位数据所需的最小启动记录必须位于一个先验可定位的位置，不能只放在尚未找到的数据目录里。标准模式可使用固定的用户配置位置，便携模式可使用应用旁的版本化启动记录；具体格式、优先级与恢复在该阶段定义。后续可编辑设置保存在配置文件/数据库中，不修改 EXE。

正式安装器和快捷方式后续设计；是否统一采用标准用户目录、便携版与安装版并存/导入规则、签名渠道由相应任务确认。首轮不靠一个大迁移向导来完成“直接打开应用”的目标。
