# F-CORE-001：调用与状态通信

所属模块：核心调用网关及公共通信契约
关联任务：[T-002](../tasks/T-002-core-design.md)
上级：[核心设计](design.md) · 通用要求：[插件协议](../technical/plugin-protocol.md)

## 1. 目标与范围

让每条跨边界调用都能回答：谁调用谁、操作哪个对象、由谁改变状态、何时结束、失败后如何查询结果。按产品 P-14，不分配插件调用权限，每次调用由核心留痕，细则见[调用记录规格](call-records.md)。本文定义逻辑契约和验证流程；具体序列化、传输、schema 工具及数值限制由后续实验方案确定。

包含插件到核心的请求、响应、状态事件、字节流，以及外壳使用应用服务的边界。核心内部可通过有类型的本地接口调用，不要求经过同一条 IPC。按产品 P-13，第一阶段不开放插件互调，不提供插件服务注册/发现、调用或跨插件句柄转交；插件分别使用核心的公开能力。

能力发现只列出首阶段真正支持的核心接口。请求未支持的插件服务应明确拒绝，不能借通用事件转发、私有通道或共享可写状态实现隐式互调。共享核心连接是不同消费者分别申请租约，不是插件之间传递句柄。

## 2. 调用经过哪些边界

1. 插件通过 SDK 发起调用，提供方法、参数和请求标识。
2. 可信宿主根据通信通道绑定真实插件、运行实例及适用的视图身份；不接受调用者自行覆盖这些身份。
3. 网关分配调用记录 ID，记录请求；检查契约版本、格式、容量、实例有效性及资源上下文，不检查插件能力或服务器授权。
4. 将经过校验的调用上下文交给对应模块；模块执行业务约束及资源检查，并维护自己的状态。
5. 返回结果、有效句柄或操作标识，并关联调用记录；需要通知时由状态所有者发布事件。连续内容进入独立流。
6. 视图只把仍属于当前上下文的结果应用到界面；已经执行的操作不因为界面忽略响应而撤销。

外壳也通过显式应用服务调用，来源与插件分别记录。插件可平等调用所有公开且已支持的核心方法，无需授权弹窗或能力白名单。排队期间若实例结束或资源代次改变，执行前重新检查运行状态；这是处理过期请求，不是撤销插件权限。

## 3. 最小逻辑数据模型

下列字段是待实现的逻辑要求，不是已经可用的 SDK 类型。单个操作仅要求实际相关的上下文，不强制全局操作携带服务器或工作区。

| 对象 | 主要内容 | 来源与规则 |
| --- | --- | --- |
| 请求 | `requestId`、契约版本、方法、参数、超时预算 | 调用方生成请求标识；核心校验大小、格式和方法是否实现 |
| 可信上下文 | 主体、插件版本与实例代次、App 启动标识；必要时含视图身份 | 由宿主绑定通道，用于归因与生命周期，不承载插件权限 |
| 资源目标 | 持久对象 ID 或访问句柄 | ID 定位对象；句柄使用关系和资源代次另行校验 |
| 响应 | 原请求标识、成功结果或结构化错误 | 不用空对象同时表达不存在、已失效和失败 |
| 异步操作 | `operationId`、执行阶段、取消能力和可查询结果 | 请求被接收不等于操作成功；结果由状态所有者更新 |
| 状态快照 | 目标对象、状态修订、对应事件游标 | 快照和游标来自一致的读取位置 |
| 事件 | 事件类型、对象 ID、状态修订、事件游标、必要上下文 | 发布已发生的变化；不携带秘密或完整输出正文 |
| 数据流 | 不透明流句柄、方向、会话代次、序号及结束原因 | 绑定调用者及所属资源；大小、缓冲和发送额度有界 |

超时预算由核心校验并换算到核心的单调时钟，不能依赖不同进程的墙钟完全一致。请求、操作、资源和流各自使用不同标识，不把一个 `id` 在不同生命周期中复用。

接口规格还应声明参数限制、支持的状态、调用记录摘要、错误、是否有副作用和测试编号。能力发现仅说明宿主实现什么，不据插件清单缩减可调用方法；记录规则与测试见 F-CORE-003。

## 4. 请求、重复、超时与取消

### 4.1 读取和写操作分别处理

读取可以在实例和上下文仍有效时重试；结果允许带修订。写操作必须定义提交点、可查询状态以及重复请求规则。

- 同一调用者实例使用相同请求标识重送相同参数，在该请求仍被追踪的范围内返回同一个进行中结果或回执，不启动第二次操作。
- 相同请求标识配合不同参数应拒绝，不能把第一次执行结果当作第二个操作的结果。
- 去重窗口和记录上限在具体实验中设定。记录过期后不能继续声称已去重；需要跨重启安全重复的业务必须单独设计持久幂等键与核对方法。
- 连接断开前远端可能已经执行写操作。核心不提供通用的“恰好执行一次”保证，也不自动重放写请求。

### 4.2 超时不等于失败已确定

| 超时发生位置 | 应返回或保存的结果 |
| --- | --- |
| 尚未进入实际执行 | 已停止排队/未发送，明确未产生该次执行 |
| 执行提供者已接收，可确认停止 | 取消或超时结束，记录被确认停止的范围 |
| 远端已发送，但没有最终回执 | 结果不明，保留操作标识，等待业务核对 |
| 操作完成但响应未到达调用方 | 保留可查询回执；不因响应丢失再执行 |

取消通过有效操作标识发起，由实际执行提供者落实，并记录取消者及受影响操作。返回“取消请求已接收”只表示进入取消处理；最终状态仍需确认。不能因为本机停止读流，就把远端写操作标记为未执行。

发起者在响应前退出时，网关仍跟踪已受理操作：需要创建资源的操作必须确认资源已被合法接管，或触发资源回收；不能因响应无人接收而遗留 socket 或通道。详细规则见[资源规格](resources.md)。

## 5. 状态事件与恢复

事件用于已经发生的事实，例如连接从 ready 变为 failed；用户要停止连接时调用明确方法，不能广播一个由未知监听者解释的字符串事件。

- 订阅按请求的对象和上下文过滤，不按插件权限过滤；订阅本身受调用者实例生命周期约束。
- 初次读取获得一致的快照及游标，再从该游标订阅后续变化；或者由等效的原子订阅机制提供同一保证。
- 保留区间内可以从游标补发。游标过期或队列丢失时，明确返回需要重新获取快照，不静默继续一个有缺口的状态视图。
- 对象状态修订和事件游标含义不同：前者判断对象新旧，后者定位订阅位置。不同对象之间不假定一个全局修改顺序。
- 取消订阅、资源结束和实例退出时清理相应订阅；队列保持有界。
- 视图切换上下文后丢弃旧请求和订阅结果，同时停止不再需要的订阅。旧操作的真实结果仍由核心保存，而不是转记到新服务器。

事件不能成为唯一状态来源；消费者能够通过公开查询获得当前状态，查询同样留痕。

## 6. 连续数据与背压

终端字节、命令输出和文件内容不能通过无界全局事件列表传输。每条流定义方向、帧上限、缓冲上限、发送额度、关闭原因及是否允许恢复。

- 消费者变慢时由发送额度或等效背压机制限制生产；达到上限时暂停上游，或按明确规则结束/截断，并报告原因。
- 终端输入不得静默丢弃；写入被接受、进入通道和被远端应用处理不是同一个保证。
- 命令输出或终端输出若无法继续保存，必须报告缺口或流失败；文件传输出现缺口不能报告完整成功。
- 每条流只保证其定义范围内的顺序；stdout 和 stderr 独立传输时不承诺可以重建所有字节的绝对交错顺序。
- 流关闭和操作完成分别记录。收到 EOF 不总是代表操作已成功，退出码和完整性依据需要另外确认。
- 断线后的新流使用新会话代次。PTY 输出不能假装无缝续接；恢复文件传输需要单独验证偏移及源文件身份。
- 控制请求、取消和健康检查不应被大流量饥饿；并发、内存和响应时限需要在实验前给出数值和测量方法。

## 7. 错误与运行条件

建议错误包含稳定错误码、可读摘要、关联操作及可提供的恢复动作；内部诊断与用户消息分开。错误码示意如下，编码前由 schema 固定：

| 分类 | 含义 | 调用者应如何处理 |
| --- | --- | --- |
| 无效请求/不支持 | 字段、版本、能力或方法不支持 | 修正请求或检查兼容，不能盲重试 |
| 执行环境拒绝 | 操作系统、远端账号或服务拒绝实际操作 | 明确错误来自哪个环境，按该环境处理；不是 SoDeck 插件授权失败 |
| 资源不存在/句柄过期 | 资源已释放、代次已变或句柄失效 | 重新查询并取得当前句柄，不能重用旧句柄 |
| 状态冲突 | 所需配置修订或资源状态已改变 | 取得最新状态后由业务重新决定 |
| 配额/背压 | 预算或并发上限已到 | 减少工作或等待可用额度，不无限积压 |
| 连接/认证问题 | 网络不可用、认证拒绝或主机信任需处理 | 按具体类别恢复，不能统一自动重试 |
| 已取消/已超时 | 在已说明的范围内结束 | 核查是否存在操作回执和已发生副作用 |
| 结果不明 | 不能判断远端最终结果 | 根据操作标识和业务状态核对 |

`remote.exec` 与 PTY 在相应远端账号下执行，不新增 SoDeck 插件权限层，也不把业务标签当作只读保证。所有正常和失败调用均按调用记录规格留痕。

## 8. 验收与测试流程

验收项：AC-01 调用平等开放且来源准确、实例有效；AC-02 重复及取消不制造额外执行；AC-03 状态可从事件缺口恢复；AC-04 流有界且不混会话；AC-05 失败和远端结果如实表达。逐次留痕的验收与测试独立见 F-CORE-003。

准备：首批使用真实终端插件、两个隔离 SSH 工作区和可注入延迟/断线的提供者。表中 A/B 为契约测试宿主绑定的不同调用者身份，仅作为测试夹具，不制作或交付样例插件。契约测试验证两种身份，真实终端原生通道另验来源绑定；不能将两种夹具身份或同插件多个视图写成多业务插件实测。远端副作用在隔离 SSH 服务验证；每次记录运行时、平台、版本、队列限额和超时参数。本批选择及预算见 [T-003](../tasks/T-003-core-terminal.md)，实际入口、已执行范围和剩余子场景见任务结果。

| 用例 | 操作步骤 | 预期结果 | 关联 |
| --- | --- | --- | --- |
| COM-01 | 无权限声明的 A/B 分别调用同一已支持核心方法；A 在参数内伪造 B 身份 | 两者均无需授权；伪造字段不改变宿主绑定来源，A 的调用不会记在 B 名下；结果按实际参数及状态处理 | AC-01 |
| COM-02 | 连续发送相同身份/请求标识/参数；查询操作；再用同标识改变参数 | 同一追踪窗口内只有一次执行及一个操作回执；参数改变被拒绝 | AC-02 |
| COM-03 | 分别在排队前、执行已受理、远端已发送后注入取消或超时 | 区分未发送、停止已确认和结果不明；不自动重放远端写操作 | AC-02、AC-05 |
| COM-04 | 取得快照后、建立订阅前制造变化；再让订阅落后超过保留区间 | 前一变化可由游标取得；过期明确要求重取快照，最终状态一致 | AC-03 |
| COM-05 | 在工作区一发起延迟请求，切换到工作区二，再交付旧响应 | 旧结果不更新新工作区；原操作仍可在正确上下文查询 | AC-01、AC-03 |
| COM-06 | 暂停流消费者，使其达到约定限额，同时发送控制请求；恢复消费者 | 缓冲不越界；执行已定义的暂停或报错；控制请求满足实验中预先约定的时限；不静默丢字节 | AC-04 |
| COM-07 | 连接断开后创建新会话，再提交旧流帧和旧句柄 | 旧会话数据被拒绝；新流没有混入旧字节 | AC-01、AC-04 |
| COM-08 | 在隔离远端记录一个可查询的写入标记，发送后切断回执路径，再查询业务标记 | 核心记录结果不明或后来取得的真实回执；业务核对只有一次标记，不自动重复写入 | AC-02、AC-05 |
| COM-09 | 排队期间结束 A 实例，再允许提供者执行 | 过期请求不产生新副作用并留痕；已执行操作按真实状态处理，无插件权限撤销流程 | AC-01、AC-05 |
| COM-10 | A/B 分别查询能力并调用核心接口；A 再尝试调用未实现的插件服务或通用插件转发 | 已支持核心调用按相同契约工作并留痕；插件互调返回不支持且不会送达 B，不能描述为 A 未获授权 | AC-01、AC-05 |

清理：结束 A/B 实例，取消订阅、关闭所有流和测试连接，确认提供者资源计数恢复基线；恢复网络故障注入，核查并移除隔离远端测试标记和进程，清除临时数据。COM-08 的结果不明不能当作已完成远端清理。

执行结果只写入实际实现任务。本轮仅检查文档，以上用例全部未运行。编码前还需确定具体方法 schema、数值预算、实验工具及用户确认范围。
