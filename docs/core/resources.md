# F-CORE-002：资源与生命周期

更新日期：2026-10-25 · 修订：r5 · 文档就绪：草案
所属模块：核心资源协调、任务及各实际资源提供者
关联任务：[T-002](../tasks/T-002-core-design.md)
上级：[核心设计](design.md) · 公共边界：[核心能力](README.md)

## 1. 目标与范围

确保连接、PTY、隧道、流和任务有明确的所有者与释放路径，关闭一个面板或一个插件不会偶然改变其他消费者的资源。全局管理入口在业务插件不可用时仍能查看和处理资源。

本文提出逻辑模型、状态与测试流程。按产品 P-11 和 P-12，明确退出 App 时结束全部 App 持有的本机连接和隧道；关闭面板默认结束其创建的会话，只有用户明确选择且已完成托管的资源可以在 App 运行期间保留。首阶段不建设退出后维持资源的独立后台服务。具体资源的保留能力、实现方式和时间预算仍需在相应功能方案中确定。

## 2. 六类对象分别管理

| 对象 | 示例 | 生命周期与使用关系 |
| --- | --- | --- |
| 持久配置 | 服务器、凭据引用、保存的转发规则 | 可跨启动存在；对象 ID 不表示运行会话或租约仍有效 |
| 工作区或视图 | 服务器工作区、终端面板 | 保存上下文/布局；界面存在不代表连接已建立 |
| 运行资源 | 物理连接、PTY、监听 socket、远端文件通道 | 由具体提供者持有，依赖本次 App 及相关会话 |
| 租约/访问句柄 | 某个消费者使用连接或 PTY 的引用 | 绑定调用者、范围和必要代次，便于释放与失效处理，不分配能力权限 |
| 操作 | 建连请求、命令执行、传输、启用隧道 | 记录执行过程和回执；完成后回执可以保留而资源已经释放 |
| 流 | PTY 输出、命令 stderr、文件数据 | 依附资源或操作，有独立方向、序号和缓冲预算 |

全局资源索引记录资源 ID、类型、提供者、来源插件、归属范围、依赖关系、使用者数量、当前状态修订及停止方式。秘密、完整命令和输出正文不进入通用资源描述。

实际提供者是资源状态的唯一写入者；资源索引维护引用与投影，停止操作交还提供者。租约的引用计数与失效由协调层维护，不能通过直接改索引中的“已关闭”字段代替实际释放。按 P-14，公开的查询与资源管理方法对插件平等开放，并按[调用记录规格](call-records.md)留痕。

## 3. 身份和代次

- App 每次启动产生新的运行标识；插件业务实例每次重新创建产生新的实例代次。
- 连接每次重新建立产生新的会话代次，所属 PTY 和通道属于明确的一代连接。
- 服务器 ID 可以稳定保留；`serverId` 相同不代表账号、配置修订和连接状态相同。
- 访问句柄绑定真实调用者、资源标识及该资源需要的上下文/代次，便于核对使用关系。全局对象不强制绑定工作区，临时会话不能只绑定稳定插件 ID。
- 新实例使用核心保留资源时取得新的有效句柄，无需授权审批。旧实例句柄在实例失效后不复活；持久配置恢复也不能复活旧运行句柄。
- 资源的创建来源和当前管理者可以不同：Docker 可以是某条用户保留隧道的来源，核心是它当前的生命周期管理者。

## 4. 归属范围和保留规则

| 范围 | 适合的资源 | 结束条件 |
| --- | --- | --- |
| 视图范围 | 只服务某个面板的订阅或交互会话 | 明确关闭该视图时默认结束；用户明确保留时需先转交到受支持的托管范围；隐藏不等于关闭 |
| 工作区范围 | 多个工具共同使用的工作区连接上下文或任务 | 工作区结束，且资源没有被合法转交到其他范围 |
| 插件实例范围 | 插件运行期订阅、临时缓存、实例自己的执行资源 | 实例停止或失效时撤销，不因同插件再次启动恢复 |
| 核心管理范围 | 用户明确保留的隧道等受支持资源 | 用户停止、策略到期、不可恢复失败或明确退出 App；保留不跨 App 运行周期 |

范围由资源类型允许的策略和用户操作决定，插件不能自行把所有资源标为永久。某些对象有多层约束，例如工作区 PTY 由插件租约访问；实例失效是否终止 PTY，仍取决于其是否已被核心明确接管。

保留分为两件事：**保存配置**使下次能够重新创建；**保留本次运行资源**使当前关闭视图后仍可继续。二者不能混用。App 重启后的自动建立连接或转发属于单独行为，不能因为保存了规则就默认启动。

用户选择保留运行资源前，核心应验证该资源类型能被托管、资源仍有效、存在查看和停止入口、预算允许，并接管必要依赖租约。不能只修改归属标签却仍依赖即将结束的视图或工作区连接。

关闭终端或插件面板默认结束它创建的会话并释放所属租约；不得自动把普通会话转为后台任务。受其他消费者使用的共享连接继续由其租约维持。需要保留时先由用户明确选择，再完成核心托管；不能仅因插件申请工作区范围就绕过默认关闭规则。资源不支持保留或托管失败时明确反馈，不得假装已成功保留。

明确退出 App 的规则覆盖全部运行范围，包括先前保留的资源；保存的配置仍可保留。隐藏、最小化、切换面板或工作区不等同于明确关闭，也不等同于退出。按 P-18，主窗口“×”收起到托盘，App 与独立窗口继续运行；具体操作由[工作台规格](workbench.md)定义。

逻辑视图与展示容器分离。移动、弹出、返回和分屏不触发资源关闭；核心协调挂载身份和访问关系迁移，撤销旧表面的输入/订阅而保留逻辑视图的有效资源。插件业务实例或底层连接真正失效时仍按故障规则处理，不能借“正在移动”隐藏真实断线。相关测试由工作台 WB-05、WB-06、WB-08 至 WB-10 覆盖。

## 5. 创建、使用和释放

### 5.1 创建

1. 按[通信契约](communication.md)受理请求并分配可追踪的操作标识。
2. 核对调用记录、配置修订、资源归属和统一容量规则；申请所需依赖租约，不要求插件能力授权。
3. 由实际提供者创建连接、通道或监听。监听端口以实际绑定结果为准。
4. 在核心登记资源、依赖、访问租约与状态，之后才向调用者交付句柄。
5. 任一步失败，按逆序释放该次已取得的依赖；不能留下未登记的监听或通道。

创建期间调用者取消、超时或退出，交付前再次核对：不能交付的资源按既定策略回收；只有先前明确建立的核心托管意图才继续保留。若资源已经登记并返回响应，但响应丢失，调用者可通过请求/操作标识查询结果，不能再次创建一份。

资源提供者需要在登记失败时保证清理；如果清理失败，把残留事实登记到诊断与恢复路径，不能直接遗忘。

### 5.2 使用与复用

- 多个消费者各有独立租约，实际连接可以在兼容上下文内复用。
- 子资源持有自己的依赖租约：打开的 PTY 或隧道不能只依靠某个已离开的面板间接维持连接。
- 每次使用检查句柄、实际引用关系和代次；对已经失效资源不能仅凭缓存的 `ready` 状态继续操作。这些检查不决定哪些插件获准使用某类能力。
- 配额分别覆盖实例、资源类型、流和并发操作，避免一个插件挤占全部能力。具体数值在实验前确定。
- 公开资源列表按调用方指定的查询条件过滤，不增加插件权限筛选。公开资源描述与插件内部业务对象分别维护；需要参与使用时取得自己当前有效的租约，不复制他人的引用。

### 5.3 释放

- 释放租约是幂等操作；重复释放不能误减其他使用者的引用，也不能复用旧句柄操作后来创建的资源。
- 当普通资源没有剩余租约、子资源或允许的保留策略时，提供者进入关闭流程。
- 先停止新输入和新消费者，再关闭流和子资源，最后释放依赖租约；顺序遵循资源依赖图。
- 回收有时限。失败时保留可诊断状态和有限重试/进一步清理途径，不能无限等待或把仍存活资源标为已释放。
- 公开的强制停止接口对插件一致开放，记录发起者、目标和受影响消费者；释放自己的租约不能等价为强制断开整个共享连接。接口必须区分这两种意图，不以创建插件身份决定能否调用。

## 6. 状态和故障处理

运行资源的通用展示可使用 `creating / active / degraded / closing / closed / failed`。各资源模块保留自己更精确的状态；“失败”不等于“所有本地资源已清理”，清理结果需要单独可查。

通用操作建议区分 `queued / running / cancel-requested / succeeded / failed / canceled / unknown`。其中 `unknown` 表示执行结果待核对，后续取得可靠证据时可以补充结论；审计记录保留原来的未知阶段。是否发生业务副作用不能由通用状态猜测。

| 事件 | 核心处理 | 不允许的推断 |
| --- | --- | --- |
| 视图隐藏 | 保留或降低展示订阅，按明确策略控制缓冲 | 组件不可见就自动销毁全部后台任务 |
| 视图迁移 | 保持逻辑视图及资源关系，协调新挂载并撤销旧绑定；失败可恢复 | 原展示组件卸载就代表用户关闭会话 |
| 工作区切换或主窗口收起到托盘 | 保持已打开工作区与独立窗口的资源，约束隐藏流缓冲 | 当前服务器切换就应终止旧工作区，或主窗口隐藏等于 App 退出 |
| 视图关闭 | 默认结束其会话并释放所属租约；明确保留且完成托管者继续；撤销视图身份及订阅 | 所有同服务器工具都应断开，或普通会话自动进入后台 |
| 工作区结束 | 结束该范围的资源；保留资源必须先完成核心接管 | 把保留标签当作已经取得独立依赖 |
| 插件实例崩溃 | 撤销身份及普通租约，关闭相关流；托管资源继续由核心处理 | 相同插件重启就继承旧句柄 |
| 连接断开 | 使所属通道/PTY 和流进入明确失效状态，记录操作结果 | 重连就恢复原终端进程与全部输出 |
| 实例停止或句柄释放 | 不再接收旧实例/旧句柄请求，按资源策略处理残留并记录 | 句柄字符串相同就代表仍在使用该资源 |
| App 退出 | 结束全部 App 持有的本机连接、PTY 通道和监听，包括托管资源；停止相关运行实例，记录未决结果 | 保留资源可在 App 退出后继续，或本地 socket 关闭证明远端进程已停止 |
| 操作结果不明 | 保存标识和已知证据，允许业务插件核对 | 自动重复写操作或宣称回滚成功 |

远端进程可能在 SSH 断开后继续运行，具体取决于服务器和进程行为。核心只能报告已确认的本机释放及远端回执；需要跨断线的任务/终端持久化时，应另行设计远端会话机制。

## 7. 全局管理应提供什么

核心至少能够按服务器、资源类型、来源插件和状态查找运行资源，查看实际地址/端点、用途、使用者、开始时间、可取消性及最后错误。停止操作由实际提供者确认，结果不明时明确说明。

核心托管资源不依赖原插件视图才能显示和停止。全局管理只提供通用描述，容器名称等来自插件的标签不变成核心业务模型。具体界面、确认交互和测试按 UI 规范使用 `apple-design`，本规格不决定布局。

## 8. 验收与测试流程

验收项：AC-01 资源可追踪且有唯一提供者；AC-02 多使用者互不误伤；AC-03 失效身份不能继续使用；AC-04 保留和清理符合显式策略；AC-05 远端未知与本地释放分别表达。

准备：实际终端插件在同一工作区创建两个会话和访问租约，使用隔离 SSH、临时数据目录及可注入创建/关闭失败的提供者。表中 A/B 表示不同消费者；涉及不同插件身份的 RES-05、RES-09、RES-11 用宿主身份夹具补充契约覆盖，不交付样例插件，也不冒称跨插件产品验证通过。隧道、监听和显式托管用例随相应功能实施；T-003 只执行其选择的真实 PTY/连接及公共契约部分，未覆盖项明确保留。每轮记录启动/实例代次、资源计数及预算；执行入口尚未实现。

| 用例 | 操作步骤 | 预期结果 | 关联 |
| --- | --- | --- | --- |
| RES-01 | A/B 获取兼容连接租约；A 打开并关闭自己的 PTY；释放 A 的租约；B 再执行查询 | B 仍可工作；A 的 PTY 已清理；只释放 A 的访问和依赖引用 | AC-01、AC-02 |
| RES-02 | 两次释放同一租约；尝试使用旧句柄；再新建同类型资源 | 重复释放无额外副作用；旧句柄拒绝；不能指向新资源 | AC-02、AC-03 |
| RES-03 | 在创建成功、交付前令 A 超时或退出；观察提供者及登记信息 | 未被合法接管的资源回收；没有未登记的端口或通道残留 | AC-01、AC-04 |
| RES-04 | 用默认设置创建会话，先隐藏再关闭面板；另对支持托管的资源明确选择保留后关闭面板及工作区；注入一次托管失败 | 隐藏不会触发默认关闭；默认会话在关闭时结束，不误伤其他消费者；保留成功者在 App 运行期间仍可查看和停止；托管失败明确反馈且不标记已保留 | AC-02、AC-04 |
| RES-05 | A 创建普通资源和显式托管资源后崩溃；重新启动 A，先用旧句柄，再取得新句柄 | 普通租约失效；托管资源按策略保留；旧句柄拒绝，新句柄按资源状态取得，无授权流程；调用均留痕 | AC-03、AC-04 |
| RES-06 | 断开连接，再建立新代次并发送旧 PTY/流句柄；查询此前已发出的写操作 | 旧会话失效；不伪装恢复；操作有真实回执或结果不明，无自动重放 | AC-03、AC-05 |
| RES-07 | 两个调用竞争同一固定监听端口；另申请自动端口；停止成功者后重新绑定 | 固定端口只一个成功；自动端口是真实占用值；释放后可实际重新绑定 | AC-01、AC-02、AC-04 |
| RES-08 | 在依赖申请、资源创建和登记各阶段注入失败；再让关闭暂时失败 | 已取得依赖按规则回收；清理失败可见且可诊断，不错误显示已释放 | AC-01、AC-04 |
| RES-09 | 达到 A 的约定资源/流配额，继续申请；同时让 B 发起允许的工作 | A 得到明确限额反馈，资源不越界；B 按预设共享预算仍可执行 | AC-02、AC-04 |
| RES-10 | 带保存规则、普通与明确保留的运行隧道、PTY 和未决操作选择“退出 SoDeck”；从 App 外检查监听与相关进程，再重启 | 全部 App 持有的连接、PTY 通道和隧道结束；端口可重新绑定，无继续托管资源的残留运行实例；持久配置仍在且旧句柄无效；未决远端操作如实记录，不把原会话当作自动恢复 | AC-03、AC-04、AC-05 |
| RES-11 | A 创建核心管理资源，B 通过公开接口查询并显式停止它；另测 B 仅释放自己的共享连接租约 | 公开管理调用不因创建者为 A 而拒绝，记录 B 和实际影响；仅释放 B 租约时 A 的使用不受影响 | AC-01、AC-02、AC-04 |

RES-04 与 RES-10 已按产品 P-11、P-12 固定默认关闭及退出预期。编码前仍需为各用例选定真实资源类型、保留操作入口、数值预算和注入方式，不能按事后结果调整通过标准。

清理：停止 A/B 及全部提供者，检查资源索引与实际 socket/通道数量均回到基线，释放测试端口并恢复故障注入；若有真实远端操作，独立核对远端进程及文件再清理。保存必要诊断证据后移除临时数据。不能以索引为空代替实际资源已释放的验证。

结果只在实际实现任务记录。本轮仅形成文档，以上用例全部未运行。
