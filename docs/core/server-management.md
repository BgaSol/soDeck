# F-CORE-016：服务器表单与分组管理

文档就绪：可评审 · 修订：r3 · 日期：2026-10-27
所属：核心服务器目录与外壳 · 任务：[T-015](../tasks/T-015-workflow-polish.md)

## 1. 目标与布局

添加/编辑服务器复用现有认证、跳板与“保存并打开”流程，密码默认记住、可留空；凭据单独保存和部分失败规则沿用 [T-007](../tasks/T-007-server-editor.md)，首终端遵循 [F-CORE-010](clean-start.md)。

弹窗约 600px 宽，以可用窗口留边限制最大尺寸；标题与底部动作固定，仅字段区滚动。显示名独行，主机/端口同行，分组选择/新建同行，认证方式后接用户名/密码同行；两列各有独立标签，错误在字段下，不挤压对方。字段区域可用宽度低于约 440px 时折为单列，Tab 顺序保持从左到右、从上到下。

密码的显示按钮位于同一控件内侧，只绘制一套边界和焦点；记住密码及说明位于密码下方。私钥模式隐藏密码项，用户名保留，不新增私钥上传流程。跳板仅在选择相应连接方式时展开，嵌套新增跳板仍可返回原草稿。

焦点采用内侧 2px 可见轮廓或等效内描边，不改变外部盒尺寸；配合字段留白，所有边缘均完整可见。鼠标和键盘聚焦、错误叠加、密码显示切换一致；不允许简单移除焦点指示。

## 2. 分组行为

- 平面分组，一台服务器属于零或一个组；“未分组”为虚拟项，不可删除/改名。分组只整理服务器，不影响连接路径、认证、已有会话或插件规则。
- 添加/编辑表单默认“未分组”或已有分组。新建分组打开小对话框，保存后返回表单并选中；取消保留服务器字段与焦点。分组保存即为独立数据，即使随后取消服务器表单也保留空分组；界面提示“分组已创建”，不声称全部回滚。
- 服务器选择器增加分组筛选（默认全部）与“管理分组”入口；每行显示所属组，搜索匹配服务器名称、地址、账号和组名，搜索/分组取交集；数量对应当前结果。
- “管理分组”是独立管理页，有返回、创建、改名、删除和服务器数量；不作为服务器表单的强制下一步。组内服务器可列出并跳转现有编辑器调整归属，不重复提供另一套服务器编辑器。
- 名称去首尾空白、1～64 个 Unicode 字符、拒绝控制字符；按 Unicode 规范化和大小写无关比较避免重复；显示保留用户写法。列表按名称排序，“全部”“未分组”在前，不增加颜色、层级或拖动排序。
- 删除空组直接执行；非空组显示“删除分组，N 台服务器移至未分组”并确认，原子完成，不删除档案、不关闭会话。失败保持原状态，可重试。
- 跨窗口同步组和归属；表单保存时若选择的组已删除，明确提示重新选择，草稿不丢，不能静默转成另一个组。重命名不改变组 ID。

## 3. 数据与边界

分组归核心持久化，使用稳定 groupId、名称、独立 revision；服务器归属为独立元数据关联。API 4.8候选的servers.catalog.v1能力、serverGroups.*及servers.catalog.*方法、SQLite v4建表/事务/回执和状态订阅，现已在[代码方案r2 §3～4](../technical/workflow-polish-implementation.md)固定。名称唯一键使用trim/NFC/Unicode小写/NFC。所有写操作仍审计、并发检查；当前只是设计，不将新增接口说成已可用。

分组/归属更新不得推进 SSH 连接配置修订或清空凭据、触发路径失效。同版本库中经旧API创建的服务器、旧插件无分组信息仍可用，缺少关联视为未分组；旧API档案更新不得清除归属。服务器新建/编辑与归属应在核心事务中一致落盘，凭据仍单独提交；失败重试不重复建服务器/组。删除服务器清理其归属，不删除组。

按P-52不做旧库迁移：启动时数据库结构版本不一致，先弹窗提示并完整备份旧库及关联加密凭据，再创建空v4库；新库不导入旧服务器、路径或分组。同版本正常重启保留分组，与临时工作区的全新启动规则不同。备份/初始化失败、中断恢复及独立文件范围由[启动规格r5](startup-settings.md)维护，先在隔离副本验证。界面在缺少分组API能力时保留旧添加能力并明确“不支持分组”，不假保存；数据库无需兼容不代表取消旧API兼容。

## 4. 功能测试流程

准备：Windows 原生及浏览器注入分别记录；独立数据副本，测试服务器 A/B，两个窗口，两组含中文/长名；三主题、900×600 与窄窗、100/125/150/200% DPI、放大文字。结果统一写 T-015。

| 编号 / 验收项 | 步骤 | 预期 |
| --- | --- | --- |
| SM-01 / 表单完整 | 首/末/密码字段依次聚焦，切认证、显示密码、错误状态、滚动；放大文字和缩窗 | 同行布局在合适宽度生效，窄时折行；焦点四边完整、无尺寸跳动，固定按钮可达 |
| SM-02 / 保存语义 | 填/不填密码，选择记住/不记住，新建跳板返回；注入凭据写失败后重试/取消 | 沿用 SE-01～05、CS-12/13；草稿/归属不丢、无重复档案、密码不泄露，不提前打开工作区 |
| SM-03 / 分组主流程 | 新建组，添加 A 到组，编辑 B 加入；在选择器筛选搜索，改名，重启 | 新建即选中、数量准确；重命名保留 ID，重启保留配置且不恢复工作现场 |
| SM-04 / 删除与取消 | 取消建组/服务器编辑；删除空组；删除非空组先取消再确认；注入写失败 | 返回原草稿；已独立保存的空组保留；删除只移动归属，服务器/凭据/会话不变；失败原子恢复 |
| SM-05 / 边界与并发 | 空白/超长/重复名；双窗口改名；A 开表单时 B 删除选中组，再提交 | 字段错误明确，过期修订不覆盖；组消失提示重选并保留草稿；无孤立引用 |
| SM-06 / 数据与API隔离 | 在副本验证不匹配库备份重建及失败保留；同版本重启；旧API更新服务器；修改运行中服务器归属 | 重建后服务器/分组为空，旧数据在完整备份；同版本保留数据；旧API不清归属；纯归属变更不触发认证、SSH重连或路径失效；缺能力时不假保存 |

代码设计增量回归：SM-04～06追加[代码方案CODE-01/G1](../technical/workflow-polish-implementation.md#10-测试关口与实施顺序)，覆盖同operationId重送、提交后凭据阶段失败、目录游标失效、旧API保留归属，并引用启动START-DB-01～06验证版本不一致备份重建。此规则替代r2的旧库增量迁移和降级恢复前提。

清理：退出隔离 App，停止测试连接，删除临时组/档案及秘密测试数据，恢复显示设置；保留脱敏截图、备份重建和资源证据。无需触碰日常数据库或业务服务器。
