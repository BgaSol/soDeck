## 1. 目标与范围

把参考图的柔和彩色、轻盈表面和细致层次转化为适合长时间工作的 SoDeck 界面；同时提供完整浅色和深色主题。沿用服务器 Tab → 插件 Tab、文件侧栏、单中央区域和独立窗口结构。

覆盖当前实际存在的主/工作区/单视图窗口、启动空态、服务器选择/新增/编辑、认证/主机指纹、已打开页面列表、插件/资源/调用记录、错误提示、原生右键菜单、终端及文件插件。新建仅包含外观选择的轻量对话框，不把 T-005 的完整设置和启动改造并入。

不增加业务插件、分屏、会话恢复、主题导入/编辑、终端独立配色设置或自动跟随系统。Windows 为本次验证平台；系统原生菜单的边框/阴影遵循平台能力，不承诺与 Web 浮层逐像素一致。两套内置主题和公开 SDK/主题协议继续独立于业务。

## 2. 操作和状态

### 2.1 外观入口与选择

- 各种窗口的“应用”菜单增加“外观”，打开同一 App 作用域对话框。标题为“外观”，说明“选择适合当前环境的界面颜色”，以并列的“浅色”“深色”单选卡片呈现。
- 单选卡片显示内置配色预览和文字标签；当前项具有勾选、边界和单选语义。键盘 Tab 可到达，方向键选择、Space 确认；焦点指示不依赖颜色。
- 点击即提交选择并保存，无单独保存按钮。成功后对话框保留，用户可继续比较。关闭按钮、Esc、外部点击均可关闭，焦点回到触发入口；关闭不撤销已完成的选择。
- 首次或没有合法偏好时默认深色，延续既有启动习惯；手动选择持久保存，完整重启沿用。偏好和工作现场分离，P-33 的空工作台启动不清除主题偏好。
- 终端背景、文字、光标、选区及 ANSI 16 色随全局主题调整。本轮不增加终端独立明暗选项，远端真彩色内容保持原样。
- 主题预览卡片来自同一主题数据，只向卡片局部注入颜色；不能为了显示另一个选项把它临时应用到全局。

### 2.2 加载、重复与失败

| 状态 | 可观察行为 |
| --- | --- |
| 打开/读取 | 使用当前已生效主题绘制窗口；读取选择状态时卡片暂不可提交，显示“正在读取外观设置” |
| 正常 | 标明当前选择；再次选择相同项不写文件、不递增修订、不重新渲染终端 |
| 提交中 | 当前窗口两项短暂禁用，显示“正在应用”；关闭仍可用，不锁住其他工作区域；关闭后已提交操作继续完成 |
| 成功 | 已验证且已保存的快照成为核心权威状态，所有当前版本表面订阅更新；新窗口直接读取最新快照 |
| 写入/校验失败 | 保持上一份有效主题和选择，显示“外观未更改”及可重试原因；不出现一半颜色更新 |
| 多窗口冲突 | 以核心修订检查串行提交；过期请求不覆盖较新的选择，显示最新选择并提示“外观已在其他窗口更改” |
| 超时/结果不明 | 查询最新选择和修订；不自动重放旧请求，不把超时当作已回滚；显示实际查询结果或重试读取入口 |
| 订阅缺口 | SDK 复用现有有界状态订阅恢复，保留最后有效完整主题；恢复失败显示诊断，窗口重新获得焦点或用户重试时重新获取 |
| 偏好损坏 | 使用内置深色，并提示偏好无法读取；用户下次选择可修复自己的偏好文件，不删除其他配置 |
| 系统高对比 | 系统颜色优先，关闭装饰、透明和渐变；仍记住所选明暗，退出高对比后恢复；外观页说明当前由系统高对比控制 |

初始主题在首屏显示前注入；切换时每个文档在一次应用中更新整份颜色，跨 WebView 依靠修订收敛，不声称多个进程同一帧绝对同步。未响应表面保留旧完整主题并在恢复后追上最新状态，不能阻塞其他窗口。

## 3. 接口、所有者与兼容

核心持有当前主题、选择偏好、App 运行代次及主题修订；外壳只请求修改，插件只消费公开契约。样式、颜色和主题订阅均不能携带 SSH 会话句柄或触发业务命令。插件仍可通过公开接口平等调用核心，能力声明只表示兼容范围。

拟新增能力 `ui.theme.live.v1`，API/SDK 4.3；具体代码落点和兼容投影在 [T-011 §3](../tasks/T-011-appearance.md)。以下接口已按本次确认方案实现，实测见 T-011 结果：

| 接口 | 参数/结果及约束 |
| --- | --- |
| `ui.theme.preference.get` | 无服务器上下文；返回选择 `mode`、当前主题 ID、非负十进制字符串 `revision`、是否处于系统高对比及旧插件兼容提示 |
| `ui.theme.select` | `{mode:"light"或"dark", expectedRevision:string}`；只接受内置模式；成功返回已提交选择/修订，重复选择幂等；失败不发布新状态 |
| `state.get/open`，`contract:"app.theme.v1"` | `target:{app:"current"}`；快照 `scope:{appGeneration:string}`、`objectId:"theme"`、字符串修订及完整主题数据；复用 open/ack/resync/close |
| `ui.theme.get` | 保留既有入口。旧消费者返回严格 v1 投影；声明新能力的消费者取得 v2 主题。旧结构不能增加未知字段 |

状态订阅增加 App 作用域；已有工作区 scope 字段与响应不改形状。真实外壳窗口通过宿主绑定身份进入公共状态服务，不能伪造插件实例或虚构服务器工作区。App 主题对象一直存在到明确退出；关闭某个工作区不销毁它。旧目录/视图订阅的身份检查、容量和清理语义保持。

主题数据 v2 扩展纯颜色令牌，旧 v1 文件继续校验/投影；所有派生色和兼容回退在主题模块内产生。公共控件的尺寸/排版/CSS 放入公开 `@sodeck/ui`，随各插件独立编译，不依赖核心 React 私有实现。颜色文件不携带交互逻辑。

选择偏好保存在独立数据根的 `appearance-preferences.json`，只包含 schemaVersion 与 mode；使用现有安全替换方式原子保存，不跟随目录外链接。主题通过完整验证、必要内存预留和持久化后才提交，提交临界区统一替换主题与状态快照；I/O 不持有工作台锁或订阅锁。失败保留旧文件和旧运行态。未知字段/模式/版本拒绝，单文件读取上限 16 KiB。

本轮随包交付的新终端/文件插件全部实时更新。兼容旧包时保持严格旧主题结构和业务可用；旧包没有实时应用能力，继续使用挂载时快照，新挂载使用最新主题。外观页提示“部分旧插件将在下次打开时应用外观”；不为换色强制重建旧会话，不给旧插件注入私有 JS。新包遇到旧核心按 API/能力拒绝，不静默半启用。

保留 `SODECK_THEME_FILE` 作为测试覆盖：启动时使用夹具而不写偏好，外观页注明测试主题；显式选择内置模式后本次运行切到内置并保存，若下次仍带该环境变量则继续按测试覆盖加载。测试启动器在验证偏好时清除该变量。

## 4. 验收标准

- AP-AC-01：全部现有页面和两个当前插件具有一致的浅/深配色、字号、间距、控件状态及表面层级；关键文字/焦点对比达标。
- AP-AC-02：用户可从任意窗口选择浅/深主题，所有当前版本表面更新，新窗口一致，完整重启沿用选择且仍为空工作台。
- AP-AC-03：切换不重建终端实例、会话、连接或文件控制器；滚动、选区、草稿、焦点和目录跟随保持正确。
- AP-AC-04：失败/竞态/缺口/损坏文件不导致半套颜色、旧请求覆盖新状态、不可恢复订阅或无界资源增长。
- AP-AC-05：Windows 键盘、IME、系统高对比及 100/150/200% 缩放下可操作；减少动态和减少透明生效。
- AP-AC-06：公共主题与样式经版本化接口复用，插件独立构建和包兼容有实际证据；旧任务历史结果不被覆盖。

### 7.1 选择、默认和迁移

外观页依次提供「多巴胺」「浅色」「深色」。主题标识分别为dopamine/soft-light/soft-dark；明暗mode分别为light/light/dark。新增的是完整风格，主题选择不再等同于明暗选择；本次不引入六种组合或自动跟随系统。

无偏好默认dopamine；有效schema1的light/dark迁移为对应soft主题，保留用户选择。建议schema2保存`{schemaVersion:2,themeId}`；首次迁移前保留原始副本，原子落盘失败时继续使用原已选soft主题并显示迁移未保存，不覆盖原文件。坏文件、未知ID完整回退dopamine并诊断，下次明确选择修复；不删除其他配置。重启空工作台不清理主题偏好。

高对比不改变所选ID；退出恢复所选主题。测试主题覆盖仍保留诊断和内置选择恢复入口。高对比/测试覆盖时分别区分记住的ID与实际生效ID；选择同一记住的ID也能结束测试覆盖或修复损坏偏好。没有覆盖/错误时只有同一ID才幂等：从dopamine选soft-light必须生效，不能因为二者mode均为light而被跳过。

三张预览卡的颜色和几何均局部注入；「默认」为固定推荐标签，「当前选择」由radio/勾表示。读取/保存状态、冲突、关闭、回焦点和错误恢复继续按§2.2。对话框640px，窄内容宽不足540px时改一列，底部可滚动且关闭始终可达。

### 7.2 契约建议与旧消费者

新增`ui.theme.catalog.v1`：`ui.theme.catalog.get {}`返回当前revision、selectedThemeId、effectiveThemeId、defaultThemeId、highContrast、testOverride、兼容提示列表及内置主题目录（id、label、mode、v2预览数据）；`ui.theme.choose {themeId,expectedRevision}`只接受上述三个内置ID，返回同形权威目录/偏好快照。修订为原App主题字符串修订；同一锁内检查、原子保存后发布，不能另建一套序列。冲突/写失败/超时语义沿用REVISION_CONFLICT、PERSISTENCE_FAILED及结果不明后查询；错误仍进入调用记录。

原`ui.theme.select {mode,expectedRevision}`保留，light明确选择soft-light、dark选择soft-dark；原get/preference.get保持原字段与类型，dopamine在旧接口呈现mode=light与实际themeId。主题schemaVersion保持2，id本就开放；继续使用app.theme.v1，不向严格v2消费者新增未知字段。公开UI按id选择静态受控profile和独立主题补充色板，color-scheme仍只写light/dark。

建议以`ui.theme.dopamine.v1`兼容能力标记完整风格支持。旧live但无此能力的插件继续实时换配色、控件保持其版本风格；旧静态插件只在自然重挂载更新。外观页相应提示「部分插件暂不支持完整样式」/「部分插件将在下次打开时应用外观」，不强制重启插件/会话。双新插件必须完整一致；旧核心缺少新能力时按既有规则拒绝新包。契约/清单版本建议由T-012维护。

应用入口与下拉在三主题中整体重设计，专用浮层、原生表面覆盖及AM-01～05见[F-CORE-008 §10](workbench-interaction.md#10-t-012-应用入口与菜单重设计)。终端/Tab右键和系统菜单沿用现有机制：内部配色/选中与当前主题匹配，切换取消旧菜单并恢复焦点；它们的系统阴影/外边界不要求复刻纸卡。首屏同步注入主题id、配色及高对比标志，避免先呈现soft样式再跳成硬边。未知测试主题id采用soft profile，损坏补充色板整体回退并诊断，不能半套应用。

## 8. T-012 公共设计系统与复用测试

用户要求样式尽量提前集中定义、插件以功能为主。T-012 r3已确认实施，外壳及当前终端/文件插件的通用控件、状态和排版由公开UI包维护；颜色来源和v2通信不变，几何/排版/profile通过受控设计参数生成。职责及例外以[UI §2.4](../standards/ui.md#24-t-012-公共设计系统与插件样式边界)为准，目录、组件/迁移和构建方案见[技术设计](../technical/design-system-implementation.md)。

组件目录为测试开发入口，不新增用户设置页或插件管理功能。公共UI不持有业务控制器或订阅，不决定远端重试/取消；表单草稿及异步结果仍属于各调用者。公共Dialog的本地焦点行为不取代宿主原生输入隔离；应用菜单仍按AM流程。升级UI需随插件重新构建，不承诺已有旧包自动获得新几何。

### 8.1 验收

- DS-AC-01：当前公共控件与全部适用状态在三主题中预定义；颜色、参数和组件规则有单一来源。
- DS-AC-02：外壳与两插件使用公共组件；插件无自写主题分支，剩余样式有明确业务几何/供应商用途。
- DS-AC-03：语义、焦点、IME、原生表面和业务资源稳定；可访问性与视觉稿一致。
- DS-AC-04：独立构建/升级及旧包兼容真实可测，检查能发现违规且允许必要例外。

### 8.2 准备、步骤与预期

准备：`.qa/t012/`隔离配置和证据；三主题、T-011旧静态/旧live插件副本、当前新包；Windows主/工作区/单终端窗，隔离Linux SSH/SFTP、长中文路径及大量文件节点。新增组件目录、生成/边界脚本和DS测试均在确认后建立，复用现有Playwright/原生harness；只在该隔离测试中运行App，系统设置测试须在finally恢复。
