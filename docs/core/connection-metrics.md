## 2. 用户流程与默认体验

1. 打开服务器并实际连接后，工作区底部连接状态旁显示“↑ 发送 / ↓ 接收”；首次采样显示“采集中”，1秒后开始有区间速率。下拉提示给出当前连接、本次App运行累计及计量口径。
2. 点击摘要打开“通信监控”独立工具窗口，定位此服务器；应用菜单也可打开并定位“全部服务器”。每个App进程仅一个监控窗口，重复入口聚焦并明确切换范围。
3. “概览”查看速率/累计、双向趋势和来源；“历史”回看；“诊断”查看事件/问题；“测速”主动检测同一目标路径。四分区共用服务器/路径上下文，历史与诊断保留选中时间区间；概览明确为实时，测速新任务明确为当前状态，历史筛选不改变其含义。切到全局时测速要求先选择单个服务器。
4. 监控窗口固定当前选择，不因背后工作区切换而自动换服务器。点击另一个服务器的摘要属于显式定位；窗口标题和面包屑同步更新。
5. 来源列表可定位仍存在的终端或隧道；历史/已关闭资源没有重新打开连接的隐式副作用。文件来源定位文件面板，不能从统计直接执行远端命令。
6. 监控窗口关闭只释放展示订阅，被动计量随真实业务继续；若正在测速，按测速规格取消并保留已完成部分。最小化/主窗口收起托盘不结束任务，明确退出结束全部资源。

默认每秒采样，实时概览显示最近5分钟，可切1/5/30/60分钟；不展示逐帧网络数据。当前速率用最近一个有效区间，不做隐藏平滑；曲线按所选窗口聚合并标明时间粒度。数字等宽，刷新不抖动布局。

## 3. 权威计量口径

### 3.1 方向、单位与身份

所有方向以客户端为参照：发送朝远端，接收朝客户端；本机浏览器经代理上传对应发送。默认速率 B/s、KiB/s、MiB/s，累计 B、KiB、MiB、GiB；可在公共监控偏好切换速率为 bit/s、Kbps、Mbps，8 bit = 1 B且比特单位十进制。切单位不改原始计数。

资源以运行ID、连接ID/代次、通道ID、插件实例、服务器稳定ID、路径快照和配置修订关联；显示名不作为主键。两条不同账号/路径的连接分开列。服务器重命名不丢历史，同名重建不合并身份；跨启动旧资源不可执行动作。

### 3.2 两种视角，不互相相加

| 口径 | 计量位置 / 包含 | 不包含 / 展示约束 |
| --- | --- | --- |
| 通道数据（默认） | 最终目标SSH业务通道成功读写的明文字节；PTY、SFTP、exec与direct-tcpip分别归因，包含所在协议的实际字节 | 不含SSH封装；不是文件大小或有效内容净荷；不包含本机SDK/IPC帧 |
| 连接传输 | 客户端对外SSH传输流成功读写的加密字节，握手/认证/保活/协议开销计入 | 不含TCP/IP头及TCP重传，不叫“网卡实耗”；内部loopback桥不计对外流量 |

通道数据的发送计成功写入通道的字节，接收计成功从通道读出的字节；并非对端应用已完成处理的保证。部分写只计成功部分，EAGAIN/重试同一缓冲不重复计；消费者重绘/重新读取已缓冲输出不计第二次。窗口关闭时后台丢弃但已读出的数据仍计入接收。

SFTP请求/目录元数据也属于通信，不能只累加下载文件长度；采集点须覆盖底层SFTP通道。内部协议适配的可行性须在代码方案核实，不能用DTO JSON长度估算补齐。任何尚未覆盖的路径明示“部分覆盖”，禁止用0或其他口径代替。最终工程验收要求本批声明的四类业务均覆盖。

代理按远端通道成功读写归因；HTTP/SOCKS本机握手、本机拒绝应答不算客户端至SSH目标的通道数据。本机接入字节作为可选详情沿用原字段，原网络插件累计不静默换口径；统一页面标清两者区别，后续插件采用统一字段需同时改其规格和版本。

核心持有权威计数，插件只声明用途标签/定位入口；不接受插件任意覆盖字节值。核心探测、测速、通用连接维护有独立来源，不塞入终端或文件。全局默认含所有来源，隐藏测速的筛选必须显示“已排除测速”，不能把筛选结果写成全部流量。

### 3.3 多跳和共享连接

“客户端 → A → B → C”上访问C，通道数据归目标C一次；A/B作为承载路径展示，不再按跳数加入全局。直接操作A的通道归A。全局通道累计等于全部目标服务器的累计之和，服务器累计等于同口径所有来源（含核心/测速/已结束资源）之和。

全局连接传输按唯一对外传输连接去重。多个目标共享外层连接时，服务器详情列出“共享传输：涉及A/C”等关系；不把无法准确归属的加密开销按比例伪装为精确服务器数据。逐服务器连接传输列表不能直接相加成为全局总量。跳板层内部计数仅作路径证据，不能多层累加。

转发流量代表客户端经SSH到达最终访问节点这一段的通道数据；最终节点到内网服务的独立链路容量不因此获得测量。无证据时不显示“B跳瓶颈”。

### 3.4 时间、统计与生命周期

- 累计量使用无损整数，公开跨语言表示需避免超过JS安全整数精度；速率以核心单调时钟计算累计差/真实有效时长。
- 本次运行累计以bootId分段；当前连接以connectionGeneration分段；历史所选区间累计来自区间增量，不能相减两个跨代次绝对数。
- 同口径同区间的平均速率=有效样本总字节/有效时长；峰值是已有最细保留区间的最大平均值，注明采样粒度，不声称瞬时线速。
- 关闭资源先结算最后增量，再移入已结束汇总；删除服务器不删除已产生统计。重复终态/迟到旧代次采样不能改变新资源。
- 睡眠、系统时钟跳变、采集停顿用分段及缺口表示；不能把跨睡眠的总差全部挤入唤醒后1秒。UTC存储、界面按用户时区显示，原始时区/UTC可查看。
- 已连接空闲=0；未连接=“未连接”；无法采集=“不可用”；不完整=“部分覆盖”；初始=“采集中”。状态与有效数字可同时呈现，断线后累计仍可读。

## 4. 核心与插件职责、接口及资源

核心提供计量、归属、时钟、采样/聚合、历史、探测/测速任务与生命周期。宿主绑定可信插件/工作区/资源身份；外壳提供公共通信管理页面和入口。插件仍拥有终端、文件、代理业务及自己的视图，核心不导入插件私有状态或协议业务。

新增能力是公共连接/任务/诊断原语，不为每个插件建立一套计量实现。不增加监控插件作为强制前置；未来服务器整机监控或AI插件仍通过公开接口消费。公共UI只渲染数据、事件回调和主题，不请求核心。

| 公开能力（本次代码方案命名） | 语义与关键返回 |
| --- | --- |
| communication.summary / sources | 当前范围快照、累计/速率、口径、有效区间、revision、覆盖信息；来源分页默认50/最多200 |
| communication.summary.v1 | 通过state Hub订阅类型化最新摘要；可合并，累计和interval用于识别跳样；不作为可靠历史 |
| communication.connections / resources.labels.set | 查询归属/共享路径/定位描述及代次；标签只能描述自身资源，历史没有可执行的旧资源句柄 |
| communication.history.* / communication.export.* | 由F-CORE-024定义；固定范围/水位及缺口，完整方法见代码方案第7节 |
| quality.* / speedtest.* | 由F-CORE-025/026定义；启动与取消有幂等操作ID及查询回执 |

服务端验证筛选、代次、预算和身份，不建立插件权限弹窗。公开调用逐次审计，数据流帧/内部周期采样不生成逐字节RPC或日志；不保存终端、文件或HTTP正文。旧strict返回形状保留，新能力通过版本/能力协商；旧插件可继续运行，未提供业务名则显示核心已知资源类型与短ID。

本子系统被动计量/实时环/聚合总内存32MiB，不含已有业务缓冲；导出、测速及公共依赖已在代码方案第9节合并核算，新增显式工作内存上限约71MiB。预算紧张先降低已结束资源的明细保留/曲线分辨率，保留目标/全局累计，报告降级；不得阻塞终端I/O或改成无界队列。高基数上限与“其他”降级见本稿r3补充及代码方案第3节。

控制取消/退出独立于统计处理进展；查看监控不新建远端连接。连接结束撤销相关订阅/探测，监控关闭取消视图订阅；资源残留和最后结算均由核心负责，不能依赖插件回调必达。
