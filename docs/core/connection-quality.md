## 1. 用户价值与诊断边界

在速率变化或用户感到卡顿时，展示相关路径、连接事件、SSH往返响应和影响资源，帮助判断下一步。所有结论有时间、来源、采样和关联证据；“事实”“可能原因”“未测量”分开。系统不会仅凭低速认定网络故障、高流量认定拥塞、或根据端到端指标推定某跳瓶颈。

被动诊断默认随已有连接工作：连接阶段/失败、断线/重连、路径变化、业务来源启停、统计/存储覆盖缺口。高频业务正文、终端命令和完整HTTP请求不记录。

主动往返探测为每服务器设置，默认关闭；开启前明确“仅在已有已认证连接上发送少量SSH探测请求，不自动连接服务器”。单次“检查响应”可在不保存开关的情况下运行同一探测方法。非响应式SSH保活发送成功不能伪装为对端响应。

## 2. 探测与质量指标

代码方案选用`ssh-channel-response-v1`：在现有SSH会话开不启动shell/exec的诊断channel，发送固定未知扩展请求、要求回复，按channel ID匹配SUCCESS或FAILURE；服务器拒绝未知请求也是有效往返响应。发送完成后才计时，通道创建/本机排队另计；超时/取消退役旧channel，防止迟到回复误中下一次。方法不执行Shell、不开放端口、不要求ICMP/sudo；MaxSessions或策略拒绝诊断channel时显示不支持。[代码方案§4/E2](../technical/communication-monitor-implementation.md)核实源码入口并定义真实采用关口，尚未进行运行验证。

每个不同目标/账号/路径修订选择一条既有可用连接作代表，显示所测连接ID；相同物理测量任务被多个视图共享，不为每个终端发一份。代表连接结束可切换到同范围其他既有连接并标记新分段，不因探测持有租约阻止最后业务断开。共享第一跳但最终目标不同不合并为同一端到端结果。

建议周期5秒，超时3秒，每连接最多1个在途请求；本机排队超过1秒或事件循环暂停导致迟发，记“未发出/调度延迟”，不计网络超时。超过周期不补发突发队列。全App同时最多8个在途探测、每秒最多8次发送，超额均匀排队/跳过并标覆盖；代码方案固定每次请求≤128B、有效回复≤16B，SSH封装另计。

| 指标 | 定义与展示 |
| --- | --- |
| SSH往返响应 | 最近一次有效往返毫秒，含网络、SSH处理/加密及远端调度；不称纯网络RTT |
| 近5分钟中位数/p95 | 至少10个成功样本才给统计，小于10显示样本不足；显示成功/发送/跳过数 |
| 响应波动 | 连续成功采样对的绝对差的平均值；跨超时/缺口/连接切换不配对；至少10对才显示，不称网络抖动标准值 |
| 探测超时率 | 近5分钟已实际发出并完成的超时数/完成请求数；取消/未发出/未完成不在分母；不称链路丢包率 |
| 已知连接阶段耗时 | DNS/连接/握手/认证等已经能可靠观测的实际耗时，等待用户认证独立标注 |

探测不开启或方法不支持显示“未检测/不支持”，仍可查看被动事件和流量。若底层不能可靠匹配响应，不得用发送耗时或应用RPC耗时填充；这是实施前技术关口。关闭开关停止排队任务并取消/放弃在途结果，旧结果只保留为历史，不污染新代次。

## 3. 异常条件、去重与恢复

本次先支持固定的可解释规则，不引入自由规则脚本。问题进入F-CORE-020的统一状态机，实际时间线保留全部必要事实；提示频率与记录频率分开。

| 规则 | 触发建议 | 恢复/结束证据 |
| --- | --- | --- |
| 意外断线 | 有活动消费者时连接意外断开；记录立即产生，持续10秒再给需关注提示 | 同目标同路径恢复可用并确认消费者影响；若用户结束对象则记对象结束而非已修复 |
| 反复重连 | 同目标/路径5分钟内至少3次意外中断 | 已连接且连续5分钟没有再中断 |
| SSH响应较慢 | 已开启探测；连续3次有效响应>500ms | 连续3次有效响应≤350ms；350～500ms保持原状态，避免来回跳 |
| 探测未响应 | 连续3个实际发送的请求超时 | 连续3次有效响应；明确仅说明探测恢复，不自动解决其他连接问题 |
| 指标不可用/历史未保存 | 有活动连接时核心采集或持久化持续失败10秒 | 核心采集/写入恢复且确认新数据有效；旧缺口仍保留 |

500/350ms属于可调整的服务器“SSH响应提醒阈值”，不是互联网质量标准；设置校验恢复阈值必须低于触发阈值，界面给“恢复到建议值”。周期/超时本批固定，避免将配置面板变成探针编辑器。事件未覆盖、低吞吐、空闲、高吞吐不产生故障规则。

主动关闭、用户取消、正常退出不当故障。若共享链已确认某节点断开，聚合该真实连接及受影响目标；没有对应节点证据则只写“路径中断，节点未确定”。一次断线派生的多个业务影响作为一个问题的影响列表，不能为每个终端各弹一次。

默认开启应用内提醒：工作区摘要出现状态标记、诊断列表列出问题，全局一次轻量提示可点击定位；不弹阻断对话框、不发系统toast/声音/邮件。持续同episode不重复弹提示，至少60秒合并；用户知悉后普通重复只更新次数，升级或新episode可再次提示。恢复更新状态并出现一次轻量恢复提示。可按服务器关闭非阻断提醒，事件/问题继续保存。

“已知悉”只改确认状态，不等于恢复。重启后未重新观测的问题显示“上次状态，当前未验证”，不自动补建连接验证，也不重复播放旧提示。

## 4. 界面操作与证据路径

“诊断”页顶部显示选中目标/路径、实际连接状态和探测开关；下方按“当前问题 / 时间线”组织。全局视角列服务器和影响数，进入目标后查看详情。问题详情包含首次/最近发生、重复次数、影响资源、恢复状态及关联的流量窗口。

提供“查看前后5分钟”“查看连接路径”“已知悉”“导出证据”；需要手动恢复时定位既有业务重连/启停入口，不从诊断页新增隐式重试。历史超出留存时仍显示问题摘要和证据缺口，不填补数据。

关闭监控窗口停止单次检查，用户明确开启的持续探测只随现有连接和开关生命周期运行；隐藏/托盘不改变设置。主窗口退出结束探测。探测所用字节归核心“连接诊断”，不算终端流量。

## 5. 状态、接口与依赖

公开quality.policy.get/set、quality.check.start/get/cancel以及quality.summary；问题确认、历史查询和证据走公共issues/events/evidence能力。请求绑定serverId、路径修订及代表连接代次，结果包含method/version、observedAt、duration、outcome、sampleCounts、覆盖及来源；操作ID幂等，迟到旧请求只能落其原历史。

状态为disabled/unsupported/waiting/checking/ready/degraded/ended，CHECK_TIMEOUT与SCHEDULING_DELAY、DISCONNECTED、UNSUPPORTED、CANCELED、CAPACITY分开。采集字段受白名单限制；公开控制调用留痕，周期探测作为一个持续操作记录起止/统计及异常，避免每5秒重复制造用户动作。

本功能负责连接领域规则与探测，公共问题服务负责投影、确认、去重、恢复历史；外壳负责提示显示。T-016未实现的公共依赖已纳入代码方案第6/10节的子集及交付顺序，不能以私有日志替代后宣称通用体系完成。

## 6. 验收与专属测试流程

AC-01探测语义准确；AC-02规则与恢复有证据；AC-03问题不刷屏/不串目标；AC-04资源/兼容/降级完整；AC-05操作与可访问性。

适用r1；Windows隔离SSH直连/多跳，真实延迟与断线注入、可控响应夹具、本机调度阻塞；远端业务机器不参与。CQ入口尚未建立，实际结果归T-019。
