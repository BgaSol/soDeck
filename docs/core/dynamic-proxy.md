## 1. 增量目标与现状

P-45 要求两个插件功能：固定目标端口转发与 HTTP/SOCKS 内网代理。用户已明确跨机器是“经过多台 SSH 主机中转，入口在本机”；本次不提供远端监听入口。多层 SSH 路径属于核心公共能力，建议两功能都能消费。

本轮复核实际代码 `crates/core/src/route.rs` 已取消固定跳数限制，T-013 r2 已实现任意有限无循环路径及逐跳传输、身份、资源、兼容接口。本任务复用这条基线；公开用户 listener/目标 TCP 能力仍未建立，不能把内部跳板桥接当作两个插件功能已完成。历史工程检查及其层级见[T-013多级结果](../tasks/T-013-multihop-results.md)，本轮未重新运行这些检查。

本次候选需要：

1. 复用既有核心路径运行 `本机 → SSH A → SSH B → SSH C`，新增向插件提供由 C 访问业务目标的 TCP 能力；沿用逐跳认证、指纹和取消，不在插件内创建第二套路径/凭据模型。
2. 核心实际绑定并持有本机 listener，返回真实地址和运行句柄，解决端口冲突与创建取消。
3. 在有效路径末端建立任意指定目标的 TCP 字节通道。固定转发的目标由规则给出；代理的目标由 HTTP/SOCKS 请求得出。
4. 有界双向数据、背压、半关闭、目标建立超时、通道隔离、幂等清理、运行状态和资源统计。

最终服务可以位于最后 SSH 节点本机或其可达的其他机器。目标域名从最后节点解析，中间节点从前一跳访问，不能按本机 DNS/同地址网络替换路径。

## 2. 边界与本次方案

核心负责服务器/凭据、逐跳信任/认证、路径配置/快照、SSH 连接、TCP 原语、listener/端口、依赖租约、状态和调用记录。插件负责两类配置、业务启停编排、HTTP/SOCKS 代理行为、指南和界面。

r1～r2 的proxy.*没有采用。本次建议插件QuickJS worker处理HTTP/SOCKS协议，核心提供通用listener/TCP/字节会话/splice，远端SSH建立目标socket；不部署远端代理。控制RPC继续JSON，正文走有额度的二进制帧，固定转发及握手后的CONNECT/SOCKS交核心透明转发；具体模块、帧格式、协议处理和实施顺序见[代码方案r1](../technical/network-tunnel-implementation.md)。

本轮API、操作语义和数值预算由§8/9定义。建议API/SDK4.7.0新增network.tcp.v1、network.stream.v1、network.resources.v1，schema拟新增contracts/network-v1.schema.json；Rust/TS同源生成。旧API4严格请求/响应和workspace.v4资源枚举不改形状。新接口尚未实现。

## 3. 多层路径与资源要求

- 路径有明确顺序和最后访问节点；沿用核心循环、自引用及缺失节点校验，不增加固定业务跳数。全链 session/桥与并发预算沿用 F-CORE-014 §7.4；容量不足属于运行资源错误，不把长路径当作无效配置。
- 每跳凭据和主机信任由核心管理，保留完整路径身份，防同私有地址不同现场误认；不上传最终节点秘密到中转机。
- 配置修改不悄悄改变已运行连接，运行保留完整快照；新运行使用新修订。保存引用和运行依赖均纳入删除/修改检查。
- 同路径兼容消费者可按核心规则复用，各自持有租约。停止某规则不能撤销其他规则或终端/文件使用权。
- 单个业务目标失败不导致整条路径重连；真正底层传输故障才按定义使依赖运行降级。失败不回退本机直连或擅自换出口。
- listener 与状态登记必须原子可回收，实际绑定决定端口；创建取消/响应丢失/迟到成功均可回收或查询，不产生重复监听。
- 断线重连后旧 TCP 流失效，不重放输入或业务请求；插件的手动/自动恢复行为见[总览 §3.2](../plugins/proxy/README.md#32-共同运行与恢复建议)。核心负责可取消、保留端口、原路径快照及预算，业务重试偏好由插件编排。
- 隐藏/移动不停止，真正退出结束全部本机资源。停止先拒绝新连接，再释放通道和所属路径租约；不能仅将索引置空而遗留 socket。

## 4. 公共验收目标

- NT-AC-01：两种功能都可在三 SSH 节点路径上访问最后节点及其后方服务；同时保持直连与单跳兼容。
- NT-AC-02：路径身份、配置修订、调用者/工作区/运行代次隔离，同私有地址不同网络不串用。
- NT-AC-03：异常可定位节点和阶段，失败/取消/迟到结果、半关闭和配额受控；目标失败不误伤其余连接。
- NT-AC-04：停止、插件失效、工作区结束和 App 退出释放实际资源；终端/文件及其他规则兼容与独立租约保持。

## 8. 公开契约与资源归属（r6）

组内调用带scope={workspaceId,workspaceGeneration}、group={id,generation}及相应资源句柄{id,generation}。创建组时宿主验证逻辑viewId属于实际worker实例和工作区；来源Caller由宿主绑定，插件不传凭据或自行声明身份。资源按核心view索引归属，移窗不改变group/流。关闭提交阶段、工作区销毁、实例失效及App退出有核心兜底，不能依赖worker回调成功；用户取消关闭时不撤销。

创建/连接/状态转换方法带operationId，快速受理后通过get查终态，SDK封装等待。同来源/方法/规范化参数重复返回同一回执，同ID不同参数拒绝。未认领成功资源30秒回收，claim或首次有效使用认领；响应丢失可查询，不能换ID重复创建。完成回执保留60秒、过期墓碑5分钟，容量全局4096/每实例512；达到容量拒绝新创建，清理和查询保留额度。pending操作不因回执过期直接遗忘。取消后迟到成功核对generation并回收，已发送业务数据不承诺未执行。

## 9. 网络池、流控和预算（r6）

网络数据池与PTY/SFTP物理传输分开；池键为workspaceGeneration、serverId、完整routeRevision及network-data用途。每池按需1～4条完整SSH路径，多规则独立租约，全部成员计入现有64目标连接、256session/桥预算；4是池容量，不是跳数。多余空闲成员30秒回收，存在租约时保留一条就绪成员。

常规连接复用必须按内部用途区分；共享的是核心建链/认证/预算服务，不能让connections.acquire误拿网络成员。删除依赖、信任/路径修改、挑战有效性和退出要包含网络池运行引用，不能因为独立池漏掉核心依赖检查。NT-01/02/04额外验证只开网络插件、无终端/文件时这些行为仍可用；删除被运行引用服务器时不能遗留无归属传输。

每成员的libssh2 channel-open串行续进，已打开通道公平I/O。目标open超时/取消后成员标draining，继续排空原调用、禁止新open，其他有效流继续；新请求选择健康成员或预算内新建。无有效流时可以关闭该成员自身传输；仍承载其他流时保留真实cleanupPending，不能重置其session。四成员全占用时明确容量不足，不无限扩容、不关闭健康长连接。普通目标失败局部化，物理传输故障影响该成员通道，规则恢复由插件决定。补建时原路由已变则等待明确应用并重启，不连接旧失效身份或偷偷换路径。

| 资源/阶段 | 首版预算与超出行为 |
| --- | --- |
| 同时运行组/规则 | 全局32、每插件实例16；超额CAPACITY，保存配置另计 |
| 网络端点 | 全局512、每组128，accepted/target/probe均计费；本地+目标一对占2，理论最多256对/每组64对 |
| 等待领取连接 | 每listener32、全局128，计入端点；满时暂停accept，无法纳管的已接受socket立即关闭 |
| 等待目标open | 每池16、全局64；排队≤5秒，开始open后15秒；新建池成员沿用核心全链时限，各阶段分开报告 |
| 原生网络数据 | 每端点每方向64KiB、模块全局64MiB；暂存/待发送均计量，达限停读不丢业务字节 |
| host二进制队列 | 每方向4MiB、payload≤64KiB；另保留64KiB控制预算，不挤占JSON普通RPC队列 |
| QuickJS字节副本/发送队列 | 每实例合计16MiB，计入128MiB总内存；SDK不能额外无界复制 |
| 代理解析（插件负责） | 首握手10秒；HTTP头64KiB/100字段、首行8KiB、chunk行4KiB、trailer16KiB；首响应头30秒 |
| 空闲/长连接 | HTTP请求间空闲60秒；已开始正文及CONNECT/SOCKS/WebSocket/SSE不统一闲置断开 |
| 取消/清理 | 1秒内撤销句柄/关闭本地监听，正常本地清理≤5秒；远端未确认drain如实保留，不谎报5秒内远端结束 |
| 状态/诊断 | feed≤32KiB、统计最多每秒一次；资源页≤64/256KiB；插件诊断200条、UI每页≤50 |

监听使用固定事件循环，网络池成员各一个SSH调度器；线程可随物理路径及既有跳板桥增加，不随每个TCP流或帧创建。数据轮转，QuickJS每批最多256KiB后让出事件循环，close/credit等独立控制调度。窗口只在consume后推进，投递不等于消费；splice核对owner/epoch/游标并保留未消费尾部，半关闭允许反向收尾。私有帧格式和TypedArray接入见代码方案§5。

控制RPC逐次Core::record，exchange作为持续调用记录开始/结束/累计计数，帧有校验和异常摘要。正文/秘密/URL路径不落审计；不能另开未留痕write方法。审计故障沿用既有策略，close/cancel继续并登记缺口，不让日志写入失败阻止关端口。
