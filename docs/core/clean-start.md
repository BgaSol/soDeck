## 1. 目标与范围

T-025启动呈现提案：[F-CORE-029 r1](connection-home.md) / [T-025](../tasks/T-025-connection-home.md)将§2.1旧欢迎按钮/弹框入口替换为启动直接显示的连接首页，推荐出现一个不绑定服务器的系统页Tab；“服务器工作区/插件视图/连接为零”仍保持，系统页不计入这些数量。空目录直接显示SSH表单，已有目录显示左列表。CS-01/04/09/12的界面入口和页签数量断言按CH-01/02/03/12更新，启动不恢复、配置保留、首终端和托盘边界保持。此为待确认设计，不回写旧CS实测结果。

用户反馈每次打开都有上次的空会话，希望“每次启动一个全新的程序，不要保留上次的历史”，本轮要求理解意图并完成功能设计。

用户继续明确：“每次创建服务器 tab 页的时候，至少要开一个终端，连接到服务器。”P-34 替代 r1 中“打开工作区后另点新建终端才连接”的建议。合并后的目标为：启动 App 时保持空白；用户主动打开服务器时，自动进入一个新的可用终端。用户随后明确要求“可以开始改了”，确认本规格 r2 的实施；授权、实际验证与验收分别由 T-009 维护。

明确目标：取消跨启动的工作现场恢复。已确认的解释：保存用户主动配置的内容，每次重新选择要开展的工作。服务器档案、已保存密码、主机信任、插件及偏好继续保留；不恢复服务器 Tab、终端页、独立窗口或其他上次的临时工作状态。“全新”不等于恢复出厂设置。

首轮覆盖 Windows 完整退出、异常终止和插件更新后的再次启动，以及旧工作台快照退役。由核心统一执行，适用于所有工作区和插件；终端负责自己的会话模型。无恢复历史开关、最近会话页、批量清空按钮或启动确认弹窗。直接启动路径/设置页仍由 T-005 独立负责，文件插件仍由 T-008 独立负责。

这里的“历史”是上一次工作现场。诊断与核心调用记录继续遵守 P-14，不在本轮清空；远端 shell 自己的命令历史、tmux/screen 或脱离 SSH 的远端任务不属于本地工作台，不发送清历史、杀远端全部进程或自动重新附着命令。本方案不承诺设备无痕或安全擦除。

## 2. 启动、界面与生命周期

### 2.1 每次启动看到什么

启动完成后只出现一个可见主窗口：服务器 Tab 为零、插件页面为零、独立窗口为零、待连接操作为零。主窗口保持既有融合顶栏、服务器入口、应用菜单及管理入口。

- 已有服务器档案：中央显示“打开服务器，开始工作。”，说明“打开服务器后，将自动新建终端并连接。”，主按钮“打开服务器”。点击打开已有选择器；不弹出选择器打断每次启动。
- 没有服务器档案：中央显示“添加第一台服务器”，主按钮“添加服务器”，进入已有服务器表单。
- 服务器数据加载期间显示简短加载状态，完成前不误显示“没有服务器”；读取失败给出真实错误和可用处理入口，不能用空档案伪装成功。
- 用户选择尚未打开的服务器后建立全新工作区，自动创建并选中一个首终端，立即进入原有认证/SSH/PTY 流程；无需再点“新建终端”。成功后可直接输入，更多终端仍由用户主动新建。
- 在选定服务器前取消选择器、或在保存前取消添加表单，回到启动空态，无新 Tab、视图或连接。若档案已保存但凭据保存失败，则保留档案并按既有规则提示部分成功，不创建工作区或尝试连接；取消不声称回滚已保存数据。
- 重复选择已打开服务器只定位已有工作区，不再次自动创建；工作区关闭后重新打开，属于新建，应再次自动创建一个新终端。具体触发与异常见 §2.4。
- 同一次运行内断开的终端仍显示实际断线/结束状态，保留手动重连入口。新规则不在断线时自动删除页面；完整退出后才不再恢复它。

### 2.2 什么算一次新启动

| 场景 | 目标行为 |
| --- | --- |
| 选择“退出 SoDeck”，进程结束后再打开 | 全新工作台；原连接、PTY 和本机资源按 P-11 结束 |
| 程序崩溃、强制结束、系统重启后再打开 | 同样全新，不出现“恢复上次会话”提示；不依赖上次退出清理成功 |
| 插件更新后完整重启 | 按原更新规则启用/回退版本，保留插件设置；工作台为空 |
| 主窗口“×”收起到托盘，再选择“显示主窗口” | 沿用 P-18，仍是同一次运行；保留当前会话、页面和窗口 |
| 最小化/恢复、切服务器、移窗/合并、单个渲染表面重建 | 保留本次运行的状态与资源身份；不触发启动清空 |
| 同数据目录已有进程运行时再次启动 EXE | 沿用现有目录锁，明确提示已有实例；不重置正在运行的工作台，也不宣称当前已实现唤醒已有窗口 |

不改变主窗口“×”为退出；若用户实际希望每次关窗也结束工作，须单独改写 P-18 并确认对应资源行为。普通明确退出沿用既有关闭检查，无未保存内容时不额外确认；取消退出时不提前清理任何正在使用的会话。未来插件的草稿保存由其独立规格定义，不由核心遍历私有数据清空。

### 2.3 apple-design 的应用

已读取 `apple-design`。采用目的明确、简洁、熟悉、用户可控和即时反馈原则：以一个主操作引导开始，复用已有服务器选择器，不加入历史卡片、启动向导或清理动画。首次绘制即使用空工作台，不能先闪现旧 Tab 再删除。

延续 T-006 的字体、间距和独立主题，正文与说明区分层级，Windows 系统字体与键盘行为一致。主操作有明确焦点，Tab 可到达顶栏/管理入口；打开选择器后焦点进入搜索或首个可用控件，Esc 关闭后返回原触发器。按下有即时反馈；空态无需入场运动，减少动态效果时保持静态；高对比和减少透明效果遵循公共规范。最小窗口及 200% 缩放下内容与主按钮可见可操作，对应 CS-09。

### 2.4 新建服务器 Tab 自动创建首终端

“至少一个”按**新建时默认一个**设计，不建立“必须始终有一个活动终端”的后台补足机制。默认首终端采用现有命名规则和中央 Tab 位置，不改变终端总量预算，不自动新建多个。

| 入口或动作 | 是否创建首终端 |
| --- | --- |
| 从启动空态、顶部＋或服务器选择器打开尚未打开的档案 | 是，工作区成功建立后仅触发一次 |
| 将尚未打开的服务器“在新窗口打开” | 是，在新工作区所属窗口创建同一个首终端流程 |
| 新增档案并完成“保存并打开” | 是，先保存档案及本次提交的凭据，再建立工作区并连接；建议新增表单主按钮明确为“保存并打开” |
| 编辑既有档案后“保存服务器” | 不因此打开工作区或连接；保存已有工作区配置也不重建终端。档案修改沿用原有连接与新建连接的配置修订规则 |
| 打开已存在的工作区、搜索已打开 Tab、切换、拆窗、合并或从托盘展开 | 否，仅定位或移动已有对象；包括其终端已独立弹出、已断线或已被用户全部关闭的情况 |
| 关闭服务器工作区后再次打开 | 是，新工作区代次创建新的首终端，不复活旧视图/请求 |

新增表单“保存并打开”与编辑仅保存是本次推荐细节；底层保存档案/凭据的 API 本身不连接，只有明确打开工作区的路径启动首终端。所有创建入口走同一规则，不能只在前端某一个按钮里补一次调用。

1. 工作区与宿主窗口成功建立后，立即显示所选服务器及首终端加载页，不经过“工作区已准备好，请新建终端”的空白中间页。正常情况下第一份可交互内容就是首终端的连接状态或画面。
2. 已保存且有效的凭据由核心使用；首次主机指纹确认、指纹变化、密码/私钥输入仍按核心 SSH 规则处理。自动连接不绕过认证或信任。等待期间状态显示“等待确认/等待认证”，并绑定准确服务器和所属窗口。
3. SSH、PTY、视图及输入表面均就绪后，才表示终端可使用。只有原窗口仍为前台、该服务器/首终端仍被用户选中且没有其他模态操作时自动聚焦终端；用户已切到 B 或其他应用时，A 完成连接不能抢焦点、切回 Tab 或弹到前台。连接前输入不缓存并在成功后发送。
4. 首终端成功后可继续新建多个；首次创建正在连接、认证或取消期间，重复触发首终端/新建入口定位当前操作，不并发再开一个。成功、失败或取消已明确结束后，额外“新建终端”是用户主动发起的独立操作。

| 首终端状态 | 界面与后续行为 |
| --- | --- |
| 连接中/等待认证 | 本次终端页展示真实阶段和取消入口；核心认证 UI 维持原信任顺序，不额外叠加“是否连接”的确认 |
| 成功 | 同一个终端页呈现真实远端 shell；连接与首终端完成状态均准确，不只把已建工作区视为已连上 |
| 连接/PTY 已成功，只有渲染表面失败 | 明确显示视图失败，保留当前有效会话并提供重新加载视图；沿用同进程表面恢复，不以“重试连接”再开一个 PTY |
| 认证失败、网络超时或 PTY 打开失败 | 保留新服务器 Tab 和同一个首终端错误页，显示原因及“重试连接”；可编辑连接信息，不自行无限重试。不能显示“会话已结束”冒充本次连接过程 |
| 用户取消连接/认证 | 保留服务器 Tab，首终端显示“已取消连接”和重新连接入口；释放本次未完成资源。再次选中服务器不自动重试，用户可关闭这一页 |
| 明确关闭首终端、服务器 Tab、独立工作区窗口或退出 App（主窗×收起除外） | 取消相应进行中操作，撤销输入资格并释放所属资源；晚到的成功结果必须清理，不能复活页面或向新工作区绑定。只释放本次租约，不误断其他消费者 |
| 终端插件不可用/不兼容，或总量预算已满 | 工作区可保留并明确显示“终端不可用”或“终端数量已达上限”及插件管理/释放资源后的重试入口；不得突破预算、偷偷关闭别的终端或伪装为连接成功。此时首终端目标未完成 |

连接失败和取消时保留的页仅说明**本次用户刚发起的操作**，同样不跨启动保存。首次重试复用其逻辑视图/位置，新建一次连接尝试，不再加服务器 Tab 或不断叠加失败终端页。释放失败明确报告，未知结果先查询/清理再允许重试，避免孤儿 PTY；超时沿用核心连接、认证和操作取消规则。

保留的首终端页和正在创建的首终端计入原有终端额度，失败/取消不变成绕过总量限制的入口；重试复用该槽位，明确关闭才释放。达到额度时不预建超额终端页，只显示工作区级失败状态；释放资源后由用户重试创建。插件不可用也不伪造终端业务实例。

用户主动关闭最后一个终端后，建议保留服务器工作区和“新建终端”入口，不立即重开、不自动关闭整个服务器 Tab；后续文件面板仍可独立使用。已经单独弹出的终端也属于该工作区，不因中央区为空补建。默认首终端仅为新建时便利，不阻止用户管理自己的页面。

## 3. 状态与数据边界

### 3.1 保留矩阵

| 数据 | 再次启动 | 所有者/说明 |
| --- | --- | --- |
| 服务器档案、连接参数 | 保留 | 核心服务器注册表；档案不是“已打开服务器” |
| 明确记住的密码/密钥引用、主机指纹 | 保留 | 核心凭据与信任服务；仅本次运行的密码仍按原规则到期 |
| 已安装插件、版本及待生效更新 | 保留 | 插件管理器按既有规则选择版本 |
| 已支持的用户偏好，如终端字号 | 保留 | 所属模块保存；不借此新增主题设置等未交付功能 |
| 主窗口尺寸、正常位置及最大化偏好 | 建议保留 | 仅通用窗口偏好；启动始终可见，不恢复最小化/托盘隐藏状态；移出屏幕时修正到可见范围 |
| 打开的服务器及其顺序、活动工作区 | 不保留 | 核心本次运行状态；不因服务器档案存在而自动建工作区 |
| 终端/插件 Tab、标题、实例键、已结束占位、焦点、临时面板布局 | 不保留 | 核心承载信息及插件临时状态；重新打开采用当前声明默认布局 |
| 子窗口和独立视图窗口数量、归属、位置 | 不保留 | 下一次只创建主窗口 |
| SSH/PTY/租约/流、操作去重缓存、认证请求、临时选择/筛选/滚动、终端正文与未执行输入 | 不跨启动恢复 | 资源和临时状态限定本次运行；正文和输入继续不写布局 |
| 诊断日志、逐次核心调用记录 | 按原规格保留 | 不作为重建工作现场的来源，不复制终端正文 |

只保留已列出的明确偏好，不以“布局偏好”之名保存整个工作区。未来文件插件可在同次运行切换服务器时保留树状态，新的启动不恢复上次目录展开/选择或自动读取远端；其首次打开默认行为由 T-008 定义。

### 3.2 核心与插件职责

核心在取得数据目录锁后建立新的运行状态，再加载持久配置、插件版本与明确偏好。启动状态源必须为空工作台，不从旧视图创建对象，再调用关闭接口清理；首次工作台快照即满足第 2.1 节。

本次运行中的工作区、视图、窗口归属、移动快照、焦点和资源绑定由核心内存维护；插件会话模型也限本次运行。保存设置使用既有存储能力，不删除整个插件存储命名空间。退出结束资源；意外终止时下次仍从空状态开始，不以退出钩子是否执行决定行为。

- 冷启动不为旧视图调用 `lifecycle.restore`，不恢复旧 `viewId`/`instanceKey` 或认证请求。
- 同次运行的移窗、表面故障恢复仍可使用内存快照及公开生命周期契约，不得误删这类恢复支持。
- 核心统一决定工作现场生命周期，不包含 `terminal.*` 特判；终端保留断线手动重连和字号等设置。未来插件同样不能在启动时私自恢复上次工作页面或创建远端连接。
- 不把旧句柄或旧请求关联到新建对象；启动创建新业务实例，迟到响应只按当前有效实例、对象及代次处理。

首终端初始化由通用工作区初始化动作与终端插件协作：核心在新工作区提交后，调度插件显式声明的初始化动作；终端以自己的公开新建命令创建会话/视图并调用连接、PTY 服务。默认首终端的产品选择可在官方插件配置/声明表达，核心不硬编码终端命令/视图名称、不直接维护终端会话，也不把所有 primary 命令自动执行一遍。

每个动作按“本次 App 运行 + 工作区创建代次 + 动作标识”去重；工作区 ID 即使沿用服务器 ID，关闭再开也须有新代次。核心统一协调创建、定位、关闭、取消和回执查询，重复事件/请求/渲染挂载不重新运行初始化。插件初始化、宿主窗口重建及当前工作区表面恢复均不等于创建新工作区。已提交工作区与首终端连接结果分开表示；连接失败不回滚已保存档案，不冒报工作区不存在。

“仅一次”指同一工作区的逻辑首终端动作不会被重复创建；显式重试可在前一次尝试已完成/取消并清理后生成新的尝试 ID，仍归原动作及逻辑视图。迟到回执只更新相应尝试，不能终结或覆盖新的尝试。

文件插件继续独立申请租约/读取，不能依赖首终端返回句柄或由终端调用它；文件默认侧栏不会抢首终端焦点。终端失败不清理文件所属资源；自动首终端也不表示文件插件已获得自动读取授权，仍遵守 T-008 的读取入口。

### 3.3 持久化与旧数据处理

推荐将明确的窗口偏好与临时工作台分开保存，停止将完整 `Workbench` 写入跨启动存储。仅在内存提交成功即可完成排序、激活、拆合等运行操作；这些操作不能再依赖“保存会话布局到磁盘”成功，也不能显示“重启后恢复原位置”的过期警告。

旧版本 `workbench.json` 的处理为一次性退役：

1. 持有当前数据目录锁后，仅读取并验证可识别版本的主窗口几何偏好；不实例化其中任何工作区、视图或窗口。
2. 新偏好文件存在时以其为准；首次提取采用白名单与原子写入，缺失、损坏、未知版本或超界值均使用默认/可见窗口范围，不阻塞空工作台。明确配置存储故障与旧快照无效是不同问题。
3. 仅清理该数据目录下确认为旧工作台产生的 `workbench.json`、`workbench.pending` 普通文件、`workbench.pre-v3-*.json` 与 `workbench.damaged-*.json` 快照。不会再为这些会话快照创建永久备份；不递归删除同名目录、不追踪链接、不处理用户另存位置或 v1 数据。
4. 清理失败仍保持空工作台，提示“旧工作记录未能清理，下次启动仍不会恢复”，允许重试；不声称磁盘记录已删除，不因清理失败恢复旧状态。
5. 清理幂等，中途终止、文件残留、旧快照重新出现后再次启动，都不恢复会话。未知格式不抽取业务内容，也不以旧快照回退启动。

新版本启动行为不依赖上述物理清理成功。服务器库、凭据、插件包/设置与调用记录不在清理范围；禁止清空整个 data、core 或 plugins 目录作为解决方式。清理仅针对工作台记录，不是安全擦除保证。已退役现场不为旧版本降级保留恢复承诺，其他配置的降级兼容仍按原版本规则处理。

### 3.4 公开契约与兼容影响

沿用工作台公开请求的打开、快照、移动、关闭、生命周期与事件职责；快照反映本次运行。`committed`、操作 ID 查询、重复提交去重及移窗回滚继续真实表达内存/原生事务结果。

现有响应含 `persisted`、`warning`，且 `workbench.persistence.retry` 针对整份布局落盘。停止保存工作现场后，不能将未落盘伪报为持久化成功，也不能把有意不保存当作每次操作故障。编码前的代码方案须固定它们的兼容处理、必要的版本演进、偏好存储格式及涉及的生成契约/SDK/消费者，更新本节并纳入确认；本轮功能设计不宣称已发布新 API。旧包兼容应实测，不能仅以类型未变为依据。

r2 另须固定：工作区创建代次、初始化动作声明和至多一次调度、初始化状态/取消/重试/回执查询、首终端先建视图后连接的失败补偿与兼容。现有 `workspaceEntries` 只是默认视图声明，`primary` 只是主命令呈现，不能将它们描述成已实现的初始化命令契约。旧包无新声明时须有明确兼容/不可用反馈，不能静默退回空工作区却声称完成首终端目标；确切 schema/API 版本在代码方案中确定。

## 4. 验收标准

- CS-AC-01：正常、异常及更新后重启，只出现一个可见主窗口，无旧服务器 Tab、旧插件视图、结束占位或子窗口，且从首个工作台快照起即如此。
- CS-AC-02：服务器、已保存凭据、主机信任、插件版本及已支持偏好可继续使用；临时密码不跨启动存活。
- CS-AC-03：启动及尚未选择服务器时无连接；明确创建服务器工作区即自动创建一个首终端并尝试连接，认证就绪后无需再点新建即可使用真实 PTY。取消选择器无副作用，不重放旧输入。
- CS-AC-04：托盘、切换、移窗、同进程表面恢复保持当前工作；明确退出清理资源，取消退出保持原状态。
- CS-AC-05：旧快照退役不恢复任何视图；损坏、未知版本、清理/偏好写入失败或中断不破坏配置，不阻塞空工作台，不误报成功。
- CS-AC-06：界面焦点、主题、缩放和错误反馈可用；运行状态提交、契约兼容和插件边界符合第 3 节。
- CS-AC-07：所有创建入口遵循首终端规则；已存在工作区的定位/切换/拆合及最后终端关闭不自动补建，关闭工作区再打开创建新代次和一个新首终端。
- CS-AC-08：失败、取消、重试、插件不可用和容量不足有真实可恢复状态；重复触发不多开、晚到结果不复活已关闭对象，后台连接完成不抢焦点，原有认证/信任与资源隔离保持。
