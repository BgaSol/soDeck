## 1. 目标和边界

核心维护一个有明确来源、代次和可用性的工作区目录上下文，使工具能依据用户当前选中的工作对象定位。首个生产者是终端插件，消费者是文件插件；核心只处理通用路径/来源/生命周期，不解析 Bash 提示符、判断 cd、展开目录或解释挂载。

公开能力是核心拥有的固定语义状态发布/读取/观察，不提供插件方法发现、对端 RPC、可执行回调或任意事件总线；不转交 PTY/租约，不破坏 P-13。全部启用插件按 P-14 调用公开能力，来源/作用域校验用于正确性，不新增权限审批。

## 2. 来源选择与焦点

工作区分别维护“用户选中的目录来源视图”和“当前键盘焦点”。选择一个可提供目录的终端 Tab 或主动聚焦它的独立窗口，核心切换目录来源；点击文件面板、应用菜单、路径输入或普通工具不撤销该来源。后续其他插件要生产此类上下文时需按公开契约接入，核心不能硬编码终端插件 ID 或命令名称。

目录来源的声明、身份注册及移窗关联由工作台拥有。来源切换先提交身份和新修订，随后应用新来源的目录快照；新来源未报告时立即发布未知状态，不能沿用上个终端路径冒充它。目录报告更新只改所属来源的快照，不能让后台生产者激活自己。

每工作区一份有效选择，不按全局前台窗口共享。多个窗口中同工作区的显式终端选择按核心单调用户操作修订排序；进入文件面板仍保持最近选择。操作系统隐藏/显示、迟到 UI ready 或普通报告不能当作用户选择。完整工作区迁移只更新承载，不新建选择或终端。

关闭所选来源：工作台若明确选中另一可提供目录的视图则切到它，否则发布“无来源”。断线保留身份但将目录作废，重连需要新会话报告；不自动改选后台可用终端来掩盖当前终端不可用。

## 3. 语义契约和生命周期

本节是待实现的语义要求；[代码方案 r1](../technical/terminal-directory-follow-implementation.md) §3 固定 directories.register/report/unregister、workspace.directory.v1、来源/路径修订和版本；查询/订阅采用[通用策略 r1](../technical/component-communication.md)的 state feed，当前没有这些 API。

| 信息 | 要求 |
| --- | --- |
| 来源 | 核心绑定的插件实例、逻辑视图、服务器、工作区及创建代次；实际远端会话代次/目标配置身份，不信任调用者自填其他所有者 |
| 目录 | 字节路径，必要的逻辑/物理路径与路径视图证据；未确认/不可映射时不提供可导航目标 |
| 可用性 | 未知、已确认、执行中仅最后确认、不可映射、不支持、断线/已结束等机器状态；面向用户文案由业务插件呈现 |
| 排序 | 来源快照序号及核心上下文修订；来源选择和报告更新不会倒退，重复内容不造成重复导航 |
| 查询/观察 | 先取当前快照，再从修订继续观察，不能漏掉快照与订阅之间的变化；隐藏消费者可停止观察，恢复只需最新状态 |
| 取消/释放 | 观察可取消，关闭视图/实例/工作区及 App 退出自动撤销；不会关闭其他消费者 SSH/PTY |

核心校验源视图及真实会话属于同一所有者/工作区/连接目标；文件查询仅得到目录及可用性所需公共元数据，不获得终端输入、正文或操作 PTY 的句柄。核心不能替 shell 证明远端路径视图一致，无法核实的证据应传递未知，不能因为 hostname 相同而判为已确认。

只保存当前运行中每个现存来源的一份有限快照，不保存路径历史；每逻辑视图最多一个来源，单报告最多 16 KiB、单路径最多 4096 字节，每来源最多 10 次/秒；订阅和总容量按代码方案/通用策略。工作区关闭/重开清空，App 重启空台，旧代次不能发布或查询当前对象。

文件侧的“跟随开关/手动查看/待定位”归文件业务状态；工作台仅管理所选来源。调用记录保存来源、作用域、状态、大小、修订及结果等摘要，不记录完整目录路径/控制序列或命令正文。

## 4. 兼容与故障

新增公共能力需要 API/schema 和两个插件分别接入。新核心配原终端/原文件包继续运行基础功能；未提供目录能力的终端显示不可跟随，新文件仍可手动浏览；旧文件不消费上下文也不影响终端。新版插件遇到核心缺少必需能力应准确提示不兼容，具体版本组合在代码方案固定。

生产者故障撤销其目录报告，不关闭消费者独立租约；消费者故障不停止生产者 PTY。恢复后按新实例绑定，不能恢复旧目录为实时数据。操作回执、通知失败和异常记录策略复用现有框架，不另建跨插件重试通道。

## 5. 验收与测试流程

AC-01：来源选择与焦点分离，后台报告和非用户呈现不能抢来源。
AC-02：数据绑定实际身份/代次，无跨服务器/会话串用，快照/观察无倒退或空隙。
AC-03：迁移、关闭、故障、重连和重启释放上下文，资源隔离正确。
AC-04：旧包及缺能力准确降级，调用有记录且不记录路径正文，不引入插件互调。

适用 r2；实际实现与分层结果见 T-010 结果记录。核心契约用身份/乱序夹具验证，真实终端+文件验证生产者/消费者，Windows 原生验证焦点和多窗口；测试只使用隔离 data 和 SSH 账号。

| 用例 | 步骤 | 预期与关联 |
| --- | --- | --- |
| DC-01 选择与焦点 | A/B 发布不同目录；选 A 后点文件/菜单，再选 B；后台 A 更新 | 只有明确终端选择改变来源，文件焦点不丢来源。AC-01 |
| DC-02 快照与观察 | 获取快照期间连续切换/报告；重复/乱序投递；取消后重新观察 | 只见单调有效状态，恢复拿最新值，无无限积压。AC-01/02 |
| DC-03 来源和代次 | 伪报另一插件/视图/服务器/PTY；重连和关闭重开后发送旧报告 | 明确拒绝或失效，不更新另一上下文；真实使用权仍保留。AC-02 |
| DC-04 多窗口 | 完整工作区拆合；激活同工作区终端弹窗；恢复旧表面；切换另一服务器 | 来源随明确操作、归属保持；旧表面不能激活或覆盖当前选择。AC-01/03 |
| DC-05 故障与寿命 | 关闭来源、停止生产者/消费者、结束工作区、退出并重启 | 正确发布无来源/失效，新实例不复活旧 cwd；无观察/资源残留，重启空台。AC-03 |
| DC-06 兼容/日志/边界 | 原包与新版组合、缺能力加载、报告含假秘密路径；检查依赖和调用链 | 基础终端/文件可独立使用，缺能力清楚；摘要不泄露正文，无插件直接调用。AC-04 |
| DC-07 来源提交 | 注册延迟时切换 A/B；报告和选择交错；合并交付 A→B→A；相同路径反复 ready | 不把旧路径标成新来源；迟到注册不抢来源；selectionRevision 反映明确选择，pathRevision 不因重复报告增加。AC-01/02 |
| DC-08 容量/幂等 | 同序号重报/改内容、旧代次、超长/超频报告；同时撤销来源；关闭工作区 | 相同报告幂等，其余按契约拒绝；失效不被限频阻挡，公共状态/订阅资源回到预算基线。AC-02/03 |

每例关闭创建的观察/视图/工作区并核对基线，恢复故障和测试插件包；模拟来源不能替代真实双插件集成。实际结果、修订和限制统一写 [T-010](../tasks/T-010-terminal-directory-follow.md)。
