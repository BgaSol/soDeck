## 1. 两种代理的明确边界

T-027后续增量：[F-CORE-031 r1](mixed-route.md) / [T-027 r1](../tasks/T-027-mixed-route.md)针对P-68的SSH→SSH→SOCKS→目标场景提出完整混合路径。下文“三种互斥”“本次不做链”保留为T-020原实施范围；新方案确认后按新规格扩展，不把这些限制解释为永久约束。SOCKS与SSH的协议身份区别继续成立，代理端点的访问来源、每段DNS和凭据前缀由新规格定义；当前仅功能设计。

本功能必须区分两类路径：

| 类型 | 作用 | SoDeck 做什么 | 是否登录中转主机 |
| --- | --- | --- | --- |
| SSH 跳板 | **主机隧道代理** | SSH 登录跳板主机，确认主机密钥，使用该 SSH 会话的 `direct-tcpip` 到下一台 SSH 主机 | 是；每台跳板都有自己的 SSH 账号/认证 |
| SOCKS5 | **网络代理** | 连接 SOCKS5 服务，协商方法并发送 CONNECT，把目标 SSH 的 TCP 流交给 SSH 客户端 | 否；代理只有网络端点和可选 SOCKS 账号 |

SOCKS5 代理不是服务器档案、不是 SSH 跳板、没有 SSH 主机指纹、没有 SSH 用户名/私钥、不会产生服务器工作区或终端。SOCKS 只负责“网络能否到达目标”；最终目标仍单独做 SSH 主机身份确认和 SSH 登录。

这里“进入主机”指建立已认证的 SSH 连接并使用该主机的转发权限，不要求打开终端、创建 PTY 或启动 shell。

本次建议只提供三种互斥访问方式：直接连接、SSH 主机隧道、SOCKS5 网络代理。上一版提出的“SSH 与 SOCKS 任意有限级混合路径”不纳入本次方案。这是范围建议，并非两类协议在技术上不能组合，也不是用户已明确禁止组合；未来需要时另立规格。

## 2. 用户流程与界面

### 2.1 目标服务器配置

服务器表单的“访问方式”显示：**直接连接 / 通过 SSH 主机隧道 / 通过 SOCKS5 网络代理**。

```text
目标服务器    内网开发机
主机地址      dev.internal                         端口 22
SSH 登录      deploy · 密码 / 私钥

访问方式      通过 SOCKS5 网络代理
网络代理      公司 SOCKS · 127.0.0.1:1080          [选择]

连接路径      本机 → SOCKS5 网络代理 → 目标 SSH
              代理只转发网络，不登录代理主机

                                        取消   保存并打开
```

- 选择“SSH 主机隧道”时，显示有序 SSH 跳板列表；每一台都显示主机、账号和“需要登录此主机”。继续沿用多级 SSH 主机跳板，但每一级都是主机隧道节点。
- 选择“SOCKS5 网络代理”时，只能选择网络代理配置，不从服务器列表选择；代理部分不显示 SSH 账号/私钥或主机指纹。目标 SSH 账号/认证字段始终保留。目标主机名默认原样交给 SOCKS5 代理解析。
- 网络代理配置可复用到多台目标；代理管理是核心配置入口，不创建代理 Tab、工作区或终端。
- 添加/编辑代理使用父表单子步骤，保留目标草稿、焦点和滚动；“保存并选用”只保存代理配置，不连接代理、不打开工作区。
- 代理配置变更只影响新连接；已有目标连接继续使用不可变快照。删除有保存或运行依赖的代理时列出依赖并阻止误删，不停止外部代理服务。

### 2.2 网络代理配置

| 字段 | 规则 |
| --- | --- |
| 名称 | 用于选择和状态显示；不代表主机身份 |
| 地址、端口 | SOCKS5 服务端点；默认端口 1080，支持域名、IPv4、IPv6 |
| 认证方式 | 无认证 / 用户名密码；凭据与目标 SSH 凭据分开保存 |
| 密码 | 核心加密保存或只在本次运行使用；列表和路径不回传明文 |

代理地址是本机要连接的网络服务地址，不是“要登录的服务器”。SOCKS 用户名密码只用于代理协议协商；目标 SSH 用户名、密码/私钥只用于最终目标。

DNS 是目标服务器的访问路径设置，保存在 `accessPath.resolve`，放在目标表单的 SOCKS 选项下；默认“由代理解析目标”，可选“本机解析后发送 IP”。共享代理档案不保存 DNS，避免修改一台目标的解析方式影响其他目标。

### 2.3 连接状态与错误

SOCKS 路径状态依次为“连接网络代理”“协商 SOCKS5”“通过网络代理连接目标”“确认目标 SSH 身份”“登录目标 SSH”。成功后只显示“目标已连接 · 经由 SOCKS5 网络代理”。

| 情况 | 用户看到的结果 |
| --- | --- |
| SOCKS 服务不可达 | 标明代理名称/地址、DNS/拒绝/超时；建议检查代理服务，不提示登录主机 |
| SOCKS 方法或账号失败 | 标明网络代理认证失败；可重新输入代理凭据，不改变目标 SSH 密码 |
| CONNECT 被拒绝 | 按代理的 REP 返回码显示拒绝、网络不可达、主机不可达等原因；不能区分 DNS 失败时不猜测原因，也不伪装为 SSH 密码错误 |
| 目标主机指纹未知/变化 | 只显示目标 SSH 指纹确认；不显示 SOCKS 主机指纹 |
| 目标 SSH 登录失败 | 标明目标账号和目标服务器；代理状态保持为已建立或随连接释放 |
| 取消或断线 | 释放 SOCKS TCP 和目标 SSH 资源，不回退直连、不重放命令 |

SSH 主机隧道继续使用现有逐节点“连接主机、确认指纹、登录主机、转发下一节点”状态；这套状态不能复用为 SOCKS 状态。

### 2.4 apple-design 与可访问性

本方案使用 `apple-design` 的熟悉性、清晰层次、即时反馈、稳定焦点和可访问性原则：常用访问方式先显示；选择 SOCKS 后只展开网络代理字段；帮助文本紧邻选择器，明确“无需登录代理主机”；状态按实际阶段变化，不用装饰动画代替原因。

复用现有 `@sodeck/ui` 的字段、选择器、密码框、弹窗和路径状态组件。覆盖 Tab/方向键/Enter/Esc、IME、900×600、200% 缩放、三主题、高对比、减少动态/透明。节点类型用文字和图标同时表达，不能只靠颜色区分。

### 3.1 访问路径模型

服务器保存一种互斥的 `accessPath`：

```text
direct
hostTunnel { jumpServerIds: [A, B, ...] }
networkProxy { proxyId: P, resolve: "proxy" | "local" }
```

`hostTunnel` 的数组是有序 SSH 主机 ID；每一台跳板都需要独立主机身份和认证。`networkProxy` 只引用一个 SOCKS5 配置，不引用服务器 ID。禁止把 SOCKS 代理写入服务器跳板列表，禁止把 SSH 跳板写入网络代理配置。

`jumpServerIds: [A, B]` 完整表达“本机 → A → B → 目标”。只读取 A/B 的 SSH 主机地址、账号及认证信息，不递归继承 A/B 自己保存的 `accessPath`。第一台由本机连接，后续地址由前一台 SSH 主机访问。选择器明确提示“只使用此主机的 SSH 信息，连接顺序以当前列表为准”；保存时拒绝目标自身、重复和缺失 ID。多级能力保留，旧的递归路径配置方式由显式列表替代。

本次不做 SOCKS 链、SSH 后接 SOCKS、SOCKS 后接 SSH 跳板或系统代理/PAC。保留未来扩展空间，但实现和测试不为这些未确认组合预留可执行路径。

### 3.2 网络与 SSH 资源

- 直接连接：本机 TCP → 目标 SSH session。
- SSH 主机隧道：本机 TCP/SSH session → `direct-tcpip` bridge → 下一台 SSH session；N 台 SSH 主机需要 N 个 SSH session 和 N-1 个内部 bridge。
- SOCKS5 网络代理：本机 TCP → SOCKS5 协商/CONNECT → 目标 SSH session；代理不占 SSH session、主机指纹或工作区资源。

SOCKS CONNECT 成功后得到的单一 TCP 流只属于一个目标连接，不能跨目标复用；目标 SSH 就使用这条流，不再创建到目标的 TCP 连接。终端、文件和网络隧道仍只申请最终目标 lease；保留现有会话连接与独立网络池的隔离，不承诺所有消费者共用一条物理连接。插件不实现 SOCKS、不接收代理密码。取消、断线、关闭消费者和 App 退出只释放 SoDeck 建立的 TCP/SSH/lease，不停止外部 SOCKS 服务。

### 3.3 身份、秘密与 DNS

SSH 主机隧道使用逐节点主机密钥和 SSH 凭据。SOCKS 没有主机密钥确认；代理凭据绑定代理 ID、地址、端口、认证模式和用户名，与目标 DNS 设置无关。修改代理端点或账号后，不自动向新端点发送原先保存的秘密。目标 SSH 信任与凭据绑定目标身份及有效访问上下文；代理端点、账号或目标 DNS 模式改变后重新确认，名称修改或密码轮换不构成新的主机身份。

默认 `resolve=proxy`：目标域名以 SOCKS5 DOMAIN 地址类型发送，目标名称只由代理解析。`resolve=local` 才由本机解析后发送 IP；两种模式不自动切换。代理服务端点本身由本机解析/连接，不把代理所在机器当作 SSH 主机。

IPv4/IPv6 字面量直接使用对应地址类型；本机解析得到多个 IP 时，按解析结果在总超时内尝试，每次重新建立 SOCKS CONNECT，不尝试目标直连。代理认证严格使用配置指定的方法，不静默降级为无认证。

配置/秘密修订纳入连接复用键。已建立连接保持原快照，新建或重新取得连接必须匹配最新快照；正在等待认证的旧尝试在相关配置变化后结束，旧答复不能写入凭据或继续连接。与连接无关的跳板自身 `accessPath` 修改不使显式列表的连接失效。

## 4. 验收标准

- SK-AC-01：SOCKS5 路径只建立网络代理 TCP 通道和目标 SSH session，不出现代理主机 SSH 登录、主机指纹或工作区。
- SK-AC-02：SSH 主机隧道和 SOCKS5 网络代理在配置、凭据、状态、错误和资源中清楚分离。
- SK-AC-03：无认证及用户名密码 SOCKS5 均可按配置连接目标；目标 SSH 仍独立确认身份并登录。
- SK-AC-04：取消、断线、多消费者、修改配置和退出正确释放资源，不回退直连或停止外部代理。
- SK-AC-05：终端、文件和网络消费者共享目标连接能力；UI、键盘、缩放、主题和辅助路径可完成配置和纠错。

## 5. 本功能测试流程

适用规格 r4。准备独立 `.qa/t020/`，使用 Windows 客户端、隔离 SOCKS5 服务 P、目标 SSH T；P 能访问 T，客户端不能直达 T，P 不提供 SSH 服务。另准备 SSH 主机隧道拓扑 A→B→T，证明两种路径分别工作。代理服务和 SSH 主机使用不同凭据与日志，不使用日常代理或业务服务器。

| 用例 | 步骤 | 预期 |
| --- | --- | --- |
| SK-01 配置分流 | 在目标表单切换 direct/hostTunnel/networkProxy，保存、编辑、取消；代理从独立管理入口添加和复用 | 三种模式字段不串；SOCKS 选项只显示代理配置，不显示跳板主机字段；代理不产生工作区 |
| SK-02 网络代理无登录 | 仅配置 P 与 T，连接终端、SFTP、exec；检查 P/客户端/目标日志 | 只见 SOCKS 协商和目标 SSH；没有 P 的 SSH session、主机指纹挑战或终端 |
| SK-03 代理认证 | P 分别使用无认证、用户名密码、错误账号、未提供的认证方法；取消或超时后提交旧答复 | 只触发网络代理凭据挑战；不降级、不串用 T 的 SSH 凭据；取消释放通道；过期答复无副作用 |
| SK-04 DNS 与 CONNECT | 目标名仅 P 可解析；测试 proxy/local、多 IP、IPv4/IPv6、各 REP、短读/分片、畸形回复及 CONNECT 回复与 SSH banner 连续到达 | 默认本机不解析目标；协议严格校验；读取不吞掉 SSH banner；错误如实映射且不回退直连 |
| SK-05 主机隧道对照 | 使用显式 [A,B]→T，混合密码/私钥/未知指纹；改变 A/B 自己的访问方式；检查 session、PTY 和转发 | A/B 逐节点指纹/认证，均无 PTY；不递归展开自身路径；与 SOCKS 状态和秘密分开 |
| SK-06 资源与消费者 | 两终端、文件、独立网络池访问 T；关闭一个、取消全部、移窗、托盘、退出；50 次连接/取消 | 按各池实际物理连接计数；全部关闭后 SOCKS TCP、目标 SSH、lease 归零；代理进程继续运行；无迟到结果或旧 cwd 串用 |
| SK-07 修改与依赖 | 并发保存、修改/删除共享代理；运行中改端点/账号、目标 DNS、名称或密码；认证等待中改配置 | 旧连接保持快照，新申请不复用旧池；相关旧挑战失效；名称/密码轮换不误触身份变化；一台目标的 DNS 不影响其他目标 |
| SK-08 契约与空库 | fresh v6 数据库，代理 CRUD、自引用/缺失/重复跳板；旧 API 调用与旧插件；版本不一致备份重建及中断/恢复 | 坏配置事务拒绝；旧 API/插件明确不支持；备份核验失败不发布空库；旧文件不导入；不执行兼容投影 |
| SK-09 原生界面 | Windows 900×600/200% DPI、三主题、键盘/IME、高对比、减少动态 | 访问方式、代理说明、错误、取消和焦点可完成；代理不显示为服务器 |

每例清理目标 SSH、租约、SOCKS TCP、临时凭据和测试服务；记录真实 SOCKS、真实 SSH、桌面原生与模拟结果，不能用模拟连接证明“无需进入代理主机”。
