## 1. 用户要完成什么

用户希望配置并直接打开如下目标连接：

```text
本地 SoDeck
  → SSH 192.168.1.16
  → SSH 192.168.1.104
  → SOCKS5 127.0.0.1:12021（运行在 192.168.1.104 上）
  → SSH 65.11.10.24（最终目标）
```

用户已明确回答代理运行在 `192.168.1.104` 上。示例未指定 SSH 端口和账号；图稿使用常用端口 22，仅作默认值建议，不推定实际配置。本轮不连接或探测这些示例地址。

意图推断：用户需要的是**一份可保存、可编辑、可解释的完整访问路径**。建立目标连接时，SoDeck 自动依次经过 SSH 主机和 SOCKS 网络服务；用户不用先打开各跳板终端、逐层运行 ssh、手工维护本地端口映射或启动代理插件。终端、文件及其他连接消费者都能使用同一目标配置。

已核实的现状：`connection-home/access-path-fields.tsx` 将直连、SSH 跳板、SOCKS5 设为互斥选项；`model.ts` 和核心 `route.rs` 使用相同三分模型。纯 SSH 列表允许多级；`RoutePlan` 只持有一个独立 proxy，`ssh.rs` 仅在首段连接分支协商 SOCKS。因此本问题涉及界面、配置和核心传输，不能只增加一个界面按钮。

### 1.1 本轮推荐范围

- 统一顺序路径，允许 SSH 与 SOCKS5 任意有限级组合，包括纯 SSH、单 SOCKS、SSH→SOCKS→SSH、SOCKS→SSH 和连续 SOCKS。具体网络是否可达由真实连接判断。
- 不设置两层、三层等固定业务跳数；保存校验与运行容量分别处理。实际连接仍受核心 session、bridge、socket、内存和总超时预算约束。
- 最终目标仍是一台 SSH 服务器；中转 SSH 与 SOCKS 保留不同身份、认证和资源语义。
- 沿用 T-025 的连接首页、已存 SSH 节点选择、代理内联保存、草稿和可靠提交。不另建一套窗口/服务器目录。
- 本轮不增加 HTTP CONNECT、UDP、PAC、自动选路/故障切线、远端代理部署、路径模板库、SSH Agent 转发或终端内嵌套 ssh 的自动识别。网络隧道插件自己的监听与转发规则仍归该插件。

这是待确认的功能增量。T-020/T-025 的三种互斥方式是既有实施基线；本提案确认后才替代其相关限制，不追溯改写历史结果或继承其编码授权。

## 2. 路径到底怎样工作

### 2.1 顺序和地址含义

路径由“本机起点 → 有序中转节点 → 最终 SSH 目标”构成。每一节点的地址都通过紧邻前一个节点到达；不递归拼接该服务器自己保存的路径。

| 当前节点 | 下一地址从哪里访问 | 行为 |
| --- | --- | --- |
| 本机起点 | 本机网络 | 核心打开到第一站的 TCP |
| 已认证 SSH 主机 | 这台 SSH 主机的网络 | 核心在现有 SSH 上请求 `direct-tcpip`，目标可以是下一台 SSH 或 SOCKS 服务 |
| 已连接 SOCKS5 服务 | 该代理的出口网络 | 核心请求 CONNECT 到下一站，下一站可以是 SSH 或另一个 SOCKS 服务 |

**`127.0.0.1` / `::1` 永远属于实际发起下一段连接的那一侧。** 例子中的代理由 `192.168.1.104` 的 SSH 转发访问，所以是 `.104` 自己的回环地址。它无需对本机暴露 `12021`，也无需把 `.104` 的 `12021` 预先映射成本机端口。

如果把同一个 SOCKS 节点移到第一位，`127.0.0.1` 就改为本机；如果紧跟另一个 SOCKS，回环属于前一个代理的出口环境。界面必须实时写出此含义，不将“最近出现的 SSH 主机”误当成所有后续节点的访问来源，也不从 SOCKS 回复的绑定地址猜测出口机器身份。

### 2.2 本例的逐段执行

1. 本机连接 `.16`，确认其主机密钥并完成它的 SSH 认证。
2. 通过 `.16` 的 SSH 转发到 `.104`，确认并登录 `.104`。
3. 通过 `.104` 的 SSH 转发打开 `.104` 本机 `127.0.0.1:12021`。
4. 在这条字节流上协商 SOCKS5，使用独立代理认证（如有），请求连接 `65.11.10.24:22`。
5. 在 CONNECT 成功后的同一条流上与 `.24` 做 SSH 握手、主机密钥校验和目标账号认证，交付目标连接。

每一台 SSH 的客户端握手由 SoDeck 核心管理；中转主机只需允许 SSH TCP 转发，无需 PTY、shell 或远端 helper。SOCKS 节点不产生 SSH 会话、指纹确认或服务器工作区；只为最终目标创建工作区及按既有规则创建首个终端。

### 2.3 名称解析

- 本机直达的第一站由本机解析；SSH 后的下一站默认由该 SSH 主机解析。
- 每个 SOCKS 节点的高级选项叫“下一站域名解析”，默认“由此代理解析”，可选“本机解析后发送 IP”；这里“本机”明确指运行 SoDeck 的电脑。该选项属于路径中的这次代理使用，不属于共享代理档案。
- SOCKS→SOCKS 时，前一个代理解析后一个代理的地址；后一个代理再按自己的设置解析下一站。最终目标与中间服务的 DNS 不混用。
- IP 字面量无需解析；失败不自动切换解析位置或绕过代理。IPv6 回环同样显示归属；本轮不增加依赖网卡 scope ID 的 IPv6 链路本地地址支持。

## 3. 界面方案

### 3.1 统一为“直接连接 / 经由中转”

在连接首页的目标 SSH 表单内，用这两个选择替代三种互斥方式。默认直接连接；选择经由中转后展示纵向路径编辑器。目标地址和登录信息仍在表单上方填写，底部目标行只读引用，不填两遍。

```text
目标地址   [65.11.10.24                    ]  端口 [22]
SSH 登录   [目标账号与认证信息                         ]

连接方式   ○ 直接连接   ● 经由中转

  本机
    │
  1  SSH 跳板   192.168.1.16                    [↑ ↓ ⋯]
     账号@192.168.1.16:22 · 由本机访问
    │           [在此添加中转]
  2  SSH 跳板   192.168.1.104                   [↑ ↓ ⋯]
     账号@192.168.1.104:22 · 由 192.168.1.16 访问
    │           [在此添加中转]
  3  SOCKS5     127.0.0.1:12021                 [↑ ↓ ⋯]
     由 192.168.1.104 访问 · 此地址指该服务器自身
     无认证 / 代理账号认证     [下一站域名解析 ▾]
    │
    [＋ 添加中转：SSH 跳板 / SOCKS5 代理]
    │
  目标 SSH      65.11.10.24:22
                通过上方 SOCKS5 代理访问

                                [取消] [仅保存] [保存并连接]
```

本图是文档结构示意，未编写可执行原型，不代表实际截图。节点采用连续列表和轻分隔，避免每层一个大卡片、无限嵌套弹窗或横向画布。类型、地址、访问来源三层信息保持稳定；账号及长地址可换行，错误紧邻对应节点。

### 3.2 添加、编辑与排序

1. 添加时先选类型，再选已保存条目；末尾添加位于目标之前，行间入口在指定位置插入。每个草稿节点有稳定标识，异步选择或内联保存不能按可能变化的数组下标错插。
2. SSH 只选已保存服务器，显示名称、账号、地址；不隐式继承其 `accessPath`。缺少服务器时仍按 T-025 从左侧新建并“仅保存”，目标草稿保留，回来手动选择。
3. SOCKS5 从共享代理目录选择，允许在该节点内“新建代理 → 保存并选用”。保存后可复用，取消目标不删除已保存代理；共享代理不添加 SSH 字段。
4. 每项可更换引用、上移、下移、移除，目标行不可拖走或作为中转复选。本期以按钮和键盘等价操作完成排序，不把拖拽作为必需入口。
5. 移动或删除节点后立即重算后续“由谁访问”、DNS和路径预览；行内提示受影响的回环含义，例如“此代理现在访问本机的 127.0.0.1”。编辑本身不发起连接，保存前路径完整可见；不增加每次移动都确认的弹框。
6. SSH 节点重复/目标自身/缺失引用拒绝保存。代理允许重复引用，使用稳定步骤ID和有效前缀区分每次出现，不仅以proxyId判定成环；重复步骤ID拒绝。显式有限列表不递归展开，不声称仅凭端点文本就能判断远端网络环路。
7. 经由中转下零个节点显示“请添加中转，或选择直接连接”，不静默退回直连。切换到直接连接暂存非秘密节点草稿，返回可恢复；提交直连时只保存直连设置。内联代理草稿先保存或取消，沿用 T-025 的局部提交、去重和未知结果核对。
8. 编辑行只修改目标如何引用节点；改共享 SSH/代理档案需进入既有管理表单并展示依赖影响。已有连接使用旧快照，新连接使用新配置。

代理档案只保存端点和认证配置，访问来源由具体路径决定。因此复用同一个 `127.0.0.1:12021` 配置不等于所有服务器指向同一个代理实例；选择器结果在当前插入位置预览访问来源，凭据按 §5.2 隔离。

### 3.3 保存、打开和路径查看

沿用“仅保存 / 保存并连接 / 保存修改”语义，不新增常驻“测试连接”按钮。仅保存不探测任何节点；保存并连接使用核心已提交的完整路径快照，不先连接跳板再偷偷创建额外工作区。

服务器列表使用“经 2 台 SSH · 1 个 SOCKS5”等紧凑摘要，目标工作区连接状态提供“查看路径”。详情以同一顺序列表显示全部节点、实际阶段和失败位置；长路径可滚动，当前失败/认证节点自动定位一次，不随状态刷新反复抢滚动。

已经运行的连接显示“当前连接路径”；编辑后可显示“新配置将在下次连接生效”，不能把新配置冒充当前运行路线。目录加载失败、空目录、失效引用各有文字及重试/重新选择入口，不把失败显示成零节点。

### 3.4 apple-design 与输入

使用已读取的 apple-design：顺序列表映射真实路径（理解与空间一致性）；在插入位置就地选择（渐进展开）；按下即反馈、可取消操作（控制感）；稳定地址/状态位置及系统字体（可读性）。不引入装饰性玻璃、弹跳、飞入和全页缩放。

复用公共 Field、SearchSelect、Button、IconButton、Disclosure、Notice 和三主题参数，不在页面另配颜色。列表排版归外壳，通用状态仍归公共 UI。动作条保持可达，正文独立滚动；900×600 与 200% 文字缩放可折行，完整路径不依赖横向滚动。

Tab 按视觉顺序移动，节点具名；上移/下移后焦点保留在该节点的操作，删除后移到下一项或添加按钮。Esc 先退出选择层/内联编辑，不能丢弃整个目标；IME Enter 不提交，Ctrl+Enter 沿用 T-025。状态用文字和图标表达，不单靠颜色；减少动态即时切换、高对比有实边，原生插件表面祖先不施加 transform/filter。

## 4. 连接进度、失败和恢复

本节原则保持；2026-10-29 用户要求把此前笼统信息变为可见逐步记录，具体待确认行为、契约与用例见[逐步连接诊断 §2～6](../technical/connection-diagnostics.md)。无法仅凭 EOF 认定端口未监听；开始事件不代表成功，SSH 通道打开不代表后续代理可用。方案状态与原真实排查结果分别由任务维护。

本例共 4 个协议节点（2 SSH 中转 + 1 SOCKS + 1 SSH 目标），序号包含 SOCKS，不能将“第 3 步”误报为第三台 SSH。

| 位置 | 显示的阶段/例子 | 失败后可执行动作 |
| --- | --- | --- |
| SSH 节点 | 连接 → 确认主机身份 → SSH 登录 → 已就绪 | 查看节点/账号、更新凭据、编辑路径、取消 |
| `.104 → SOCKS` | 从 192.168.1.104 连接 127.0.0.1:12021 | 检查该服务器上的代理端口和 SSH 转发许可；不可提示检查本机该端口 |
| SOCKS 节点 | 协商协议 → 代理认证（如有）→ 连接下一站 | 重输代理凭据或编辑节点；不要求输入 SSH 密钥 |
| `SOCKS → .24` | 代理连接 65.11.10.24:22 被拒绝/不可达/超时 | 查看代理返回原因；不能证明时不猜测是 DNS 或目标密码错误 |
| 最终 SSH | 确认 65.11.10.24 身份 → 目标 SSH 登录 | 更新目标凭据、核对指纹；与代理认证清楚分离 |

错误至少包含最终目标、路径快照、节点序号/类型、失败阶段及已知的来源→目的段。上游失败时后续节点显示“未执行”，不全部标红或提示所有密码错误。无详细协议原因时如实写“此段无法建立”。

单次连接全过程可取消，重复连接按钮合并为已有尝试。失败/取消释放本次未交付资源，再由用户显式重试；不自动跳过节点、回退直连、恢复原 PTY 或重放命令。重试按最新完整路径重新建立，已完成的合法凭据/信任可按上下文复用，不保留半条无主链。

配置页保存遵循 T-025 的草稿生命周期；运行中的连接进度归工作区，切 Tab/托盘不取消。明确关闭工作区和退出按现有租约/资源规则释放，中转主机自己的独立工作区关闭不影响本路径。

## 5. 核心与数据设计方向

### 5.1 统一路径模型

目标档案持有一个有序中转列表，元素明确区分 SSH 引用与 SOCKS 引用。SSH 引用仅取主机连接身份；SOCKS 引用包含此处的下一站解析设置。目标 SSH 由档案自身提供，不复制为可编辑中转。以下是概念数据，尚非已发布接口：

```text
目标：T（65.11.10.24，自己的 SSH 登录信息）
中转：
  SSH   → serverId A
  SSH   → serverId B
  SOCKS → proxyId P，下一站解析=代理
```

外壳负责编辑，核心原子校验所有引用、修订及依赖，生成不可变类型化路径。运行器依次把现有字节流交给下一协议；SOCKS CONNECT 后交给 SSH 时不能丢失预读的 banner，也不能重新直连目标。纯 SSH 和单 SOCKS 归入相同执行语义，避免混合路线另走一套生命周期。

核心负责 TCP/SSH/SOCKS、凭据、信任、取消、资源预算与错误；插件继续只请求最终目标的连接/远程操作。网络隧道插件不负责启动此路径，不需先运行它生成本地代理；其现有网络池也必须消费相同的路径解析。终端、文件、资源监控不得复制路径实现。

### 5.2 身份、凭据和资源

- 每台 SSH 都核验自己的主机密钥；SOCKS 只有网络服务和可选账号认证，无主机密钥。
- 凭据、信任和连接复用纳入**到当前节点为止的有效路径前缀**、节点身份、相关修订与解析方式。后缀变更不应让已确认的上游身份无故变化；同地址不同到达路径不得串用秘密。
- 特别是共享回环代理：从 B 访问的 `127.0.0.1:12021` 与从 A 或本机访问的同地址不是同一个凭据上下文。不能继续只按 proxyId 自动发送旧密码。改变上游、端点或账号后，提示重新提供/确认该上下文的代理凭据；不会覆盖其他上下文的凭据。仅改显示名称不改变身份，密码轮换只改变秘密修订和新连接复用条件。
- 对路径尚未确定时预填的代理密码，先按既有核心安全存储方式保存为预设；首次用于新的路径上下文必须显式确认其归属，绝不向未知上下文静默试密码。确认上下文后的重复连接可以自动使用，不每次重复询问。此增量影响 T-025 凭据条件提交，需在后续代码方案中细化契约。
- 挑战绑定 operation、路径修订、稳定步骤 ID 和工作区代次；取消、改配置或窗口失效后的答复不得保存秘密或继续建连。
- 本例每条物理路径需要 3 个 SSH session；代理不算第 4 个 SSH。所有桥、socket、缓冲和等待者均计入预算。不同消费者仍按现有会话池/网络池边界分配，不承诺只用一条物理连接。
- 先核算整条链所需资源，再开始建立；超预算明确说明容量不足，不以“最多只能加三层”冒充约束。各阶段和整次尝试都有有限时限；长路径不能靠无限延长每跳超时占住资源。
- 失败逆序释放本次未交付载体；已交付连接由租约持有。退出释放 SoDeck 资源，不停止外部 SSH/SOCKS 服务。不新增用户管理的本地监听口。

### 5.3 影响、既有配置与后续技术关口

影响服务器路径契约与 SDK、依赖查询/删除阻断、配置可靠提交、代理凭据上下文、逐节点挑战和状态、连接池键、资源计量、连接首页及路径详情。按源文件定位至少包括 `connection-home`、`route.rs`、`route_store.rs`、`route_services.rs`、`ssh.rs`、`socks5.rs` 及生成契约；实施时以最新工作区核对。

用户在代码设计阶段明确“不需要做兼容，数据库要简单明了”。本次只保留新模型：空节点列表为直连，SSH列表为纯SSH，单SOCKS列表为单代理，其他为混合。删除旧三模式DTO/解析/投影，不读取旧路径并转换；这些基本连接方式仍需用新配置测试，未知格式明确拒绝，绝不能默认直连。

[代码方案r1](../technical/mixed-route-implementation.md)具体建议API/SDK6.0.0、core数据库v7。新库使用一张有序路径步骤表作为配置和依赖的唯一来源，不同时存路径JSON与重复引用索引。P-52继续适用：旧核心库及关联加密凭据完整备份后重建，服务器、代理、分组、核心设置、主机信任和核心回执在新库为空；不导入旧数据。独立插件文件及其他同版本分区按其现行规则保留，不把旧库挂回新核心。确认范围见T-027 r2，当前未执行任何重建。

代码方案落实类型化执行器、现有socket桥复用、代理凭据上下文、契约/数据库/插件替换、有限预算和分层验证。原计划模块/API/测试现已实施，实际覆盖与限制见T-027。网络隧道插件既有规则可自行请求同一路线的有界重连；核心不自动替换路线或重放业务请求，这不取消该插件原有显式autoReconnect选项。
