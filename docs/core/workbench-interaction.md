## 1. 目标、意图与范围

用户希望服务器和终端成为清楚、稳定的两层导航，内容区留给实际工作；界面有一套视觉语言，常用操作符合桌面习惯，低频操作能找到、能退出。减少重复控制面，让打开、切换、复制粘贴、拆出窗口成为顺畅的主流程。

用户明确要求：统一视觉；去掉左侧终端会话列表；Tab 不出现省略号字符或更多按钮；终端不再左右/上下分屏；必要操作转入右键菜单，修复弹出层无法关闭。配色、尺寸、长标题策略、右键内容以及终端取消底部停靠已随 T-006 r2 获得确认；实际实现与测试结果由任务维护。

本次包含现有主窗口、工作区窗口、单终端窗口、服务器选择器、认证/编辑对话框、现有插件/资源/调用记录管理页的公共样式，以及导航、菜单和旧布局适配。终端复制粘贴的独立行为和测试由 F-TERM-002 维护。

保持 P-22 的整体架构与插件独立更新。T-005 的直接启动和设置功能单独评审，本次不依赖设置页；浅色主题、主题编辑器、新业务插件、会话托管、历史录制和新的批量关闭操作不进入本次。

## 2. 布局与主流程

以下是文档示意，不是已运行界面或编码原型：

```text
┌────────────────────────────────────────────────────────────┐
│ [生产 A ×] [测试 B ×]  ＋  ▾   拖动空白     应用    ─ □ × │
├────┬───────────────────────────────────────────────────────┤
│工具│ [终端 1 ×] [部署日志 ×]   ＋                    ▾   │
│入口├───────────────────────────────────────────────────────┤
│    │                                                       │
│    │                    终端内容                           │
│    │                                                       │
├────┴───────────────────────────────────────────────────────┤
│ user@host:22                  已连接             字号 14   │
└────────────────────────────────────────────────────────────┘
```

- 顶部保留服务器 Tab 与 Windows 控制，第二行是当前工作区的插件页面 Tab。移除独占一行的分屏/新建工具栏；终端页的新建按钮放在第二行。只有终端时直接新建终端；未来多个主命令时按通用声明呈现明确选择，不在核心识别终端命令名。
- 终端插件不再贡献会话列表，也没有“显示终端会话”的工具按钮。左侧只保留约 44px 的公共工具入口；没有展开工具时不预留空面板，现有 App 管理入口仍可到达。
- 中央只有一个 Tab 组，一个终端占据当前内容区。删除左右/上下分屏按钮、分隔条、第二组落点及“移到另一区域”。推荐终端仅支持中央 Tab 和独立窗口，移除终端底部停靠；其他插件的通用停靠契约保留，未来是否提供新的并列视图另行确认。
- 同服务器可打开多个终端 Tab；不同终端可各自拆出窗口，完整服务器工作区也继续支持拆合。切换、移动和返回保持原会话，关闭才按原规则释放。
- 终端正文不再有常驻的复制、粘贴、字号及更多按钮栏。复制/粘贴与字号操作进入终端右键菜单；保留一处轻量状态区显示连接状态/字号，异常时就地显示原因和“重新连接”。服务器地址只出现于明确上下文位置，不再增加大标题。
- 独立终端顶部融合服务器与终端名、窗口控制及“返回所属工作区”；保留一个清楚的拖回抓取区域，不再叠加重复标题/Tab/工具栏。标题区域右键提供移动与关闭，正文右键提供终端操作。
- 空工作区显示“新建终端”；无服务器时显示“打开服务器”。新建期间保留现有进度和取消；成功后聚焦新终端，失败留在原上下文并显示原因。关闭最后一个终端回到空工作区，不关闭服务器 Tab。

## 3. Tab 名称、溢出与操作入口

### 3.1 无省略号的规则

两层 Tab、独立终端标题和相关工具按钮均不生成 `…`、`...`、`⋯` 或 `⋮` 作为截断或更多入口；加载使用状态图标和“正在连接”等文字。用户自行填写的名字和远端输出按原文保留，不擅自改写其中的字符。

- 普通标题按内容自适应，服务器 Tab 建议 120–320px，终端 Tab 100–280px；不因数量多将所有标签压成几字。
- 单行超长标题在完整字形边界裁切，不补省略号；悬停或键盘聚焦显示完整标题，服务器另含账号/地址。可访问名称始终完整。
- 页签多时整条横向滚动，提供左右滚动箭头；仅溢出时出现带提示“已打开页面”的下拉箭头 `▾`。下拉列表完整显示名称、允许换行和搜索，不使用省略号，服务器列表标记所在窗口。
- 当前 Tab 自动进入可见区域；系统按钮与至少 48px 的拖窗空白保留，不被超长名称挤出。关闭按钮保持可发现且占位稳定，hover 不造成名称跳动。
- `＋` 始终表示打开/新建，`▾` 只列已打开页面，不混入“更多操作”。关闭按钮 `×` 保留。

### 3.2 右键菜单

右键只确定操作对象，不隐式激活另一个服务器或终端；操作始终使用被点中的稳定 ID。菜单首行可显示完整目标名称，重名服务器附账号与地址。

| 位置 | 菜单内容及规则 |
| --- | --- |
| 服务器 Tab | 移到新窗口、移到已有工作区窗口、合并回主窗口、编辑服务器、关闭工作区并结束会话；只显示当前适用的移动目标，现有“当前窗口全部合并”保留 |
| 终端 Tab / 独立终端标题 | 修改显示名称、移到独立窗口或返回所属工作区、关闭终端并结束会话；断线/结束时才显示重新连接；业务操作来自插件声明 |
| 终端正文 | 复制、粘贴、字号减/增/恢复默认，断线时提供重新连接；具体输入规则见 F-TERM-002；不混入服务器关闭 |
| 顶部拖窗空白 | Windows 系统窗口菜单，保持平台行为 |
| “应用”入口 | 用明确文字替换当前省略号图标，保留管理插件、运行资源、调用记录、找回窗口、退出等已有全局入口；设置入口只随 T-005 的独立确认引入 |

终端重命名改为轻量输入框：预填并选中现名，Enter 保存、Esc 取消，IME 组合中 Enter 不保存；沿用 1–80 字符、不含控制字符及去首尾空白规则。失败保留草稿，可重试；成功更新 Tab 和窗口标题，不重建 PTY。

键盘聚焦 Tab 时 `Shift+F10` / 菜单键打开同一菜单；方向键选项、Enter 执行、Esc 关闭。两层 Tab 保留组内方向键/Home/End 导航；终端正文聚焦时不被外壳抢走普通远端控制键。

## 4. 弹出层的完整生命周期

菜单、已打开页列表、服务器选择器与现有对话框遵守同一套可退出规则，同时区分临时菜单与有表单的模态对话框。

| 场景 | 必须发生的行为 |
| --- | --- |
| 点击菜单外，包括终端原生内容区 | 关闭临时菜单；用于关闭的这次点击不向远端透传，也不顺带触发后面的关闭按钮；下一次点击正常生效 |
| 按 Esc / 再点相同触发器 | 关闭当前最上层弹出层；无未提交操作副作用 |
| 再右键另一个对象 | 关闭旧菜单，在新对象处打开唯一菜单，不叠多层残留 |
| 选择可执行项 | 立即收起菜单，再执行一次操作；异步失败用非阻塞提示报告，不把菜单锁住 |
| 点击禁用项 | 不执行，菜单仍可通过外部点击或 Esc 关闭；能说明禁用原因 |
| 切换工作区/Tab、开始拖动、原生窗口失焦或最小化、对象关闭、表面卸载 | 收起关联临时菜单并释放遮挡/焦点状态，重新激活窗口时不突然重开 |
| 触发对象消失或操作期间窗口已关闭 | 丢弃迟到选择，不把操作改投当前活动终端；错误可追踪，屏障一定释放 |
| 靠屏幕边缘/缩放后打开 | 菜单向可见区域避让，长菜单可滚动；所有项目与关闭路径可达 |

菜单关闭后，键盘触发者回到原 Tab/终端，鼠标在外部关闭后按明确目标交还焦点；原对象已消失时回到有效相邻 Tab 或空态入口。Esc 只消费一次，不同时作为远端输入。

模态表单提供显式取消/关闭和 Esc，失焦不会自动丢草稿；包含未提交修改时按其表单规则处理，不因为“点外面关闭菜单”改成无提示丢数据。服务器选择器是选择弹层，可点外部关闭；认证取消使用已有新建操作取消与资源清理。

原生插件表面与外壳是不同 WebView。必须由核心协调跨表面命中、菜单互斥及焦点交还，不能只给外壳 DOM 加点击监听。临时菜单打开时终端画面继续可见，输出正常推进，不把整个终端变空白或建立永久输入屏障。真正模态的认证/编辑仍保留自己的输入隔离。

## 5. 视觉与 apple-design

颜色的完整独立定义与默认色值只维护在[主题规范](../standards/theme.md)及独立主题数据，排版/尺寸仍在 [UI 规范第 2.1 节](../standards/ui.md#21-t-006-统一视觉方案)。按用户 P-29，组件、样式和业务代码不硬编码配色，状态色、阴影/遮罩及终端调色板同样纳入主题；以后替换主题数据即可改变配色。本次采用中性石墨深色、单一低饱和蓝强调色；背景靠明度形成三层，避免每块不同蓝色、渐变和成片描边。终端 ANSI 输出颜色保留语义，不强行改为单色。

采用 apple-design 的简洁、熟悉、即时响应、空间一致性和可访问性：点击即时反馈；菜单从触发点出现，退出路径清楚；选中 Tab 结合字重、底色和边界；窗口操作遵守 Windows；终端不透明；仅浮层使用轻阴影。动效不阻塞输入，减少动态时即时切换，高对比及减少透明时使用实色和清晰焦点。

## 6. 所有权、公共接口及兼容

| 责任 | 所属模块及约束 |
| --- | --- |
| 主题、Tab、菜单呈现、临时层互斥、原生焦点、布局和窗口 | 核心工作台/共享 UI；业务命令通过既有 `commands.execute` 调用，核心不解释终端复制或会话重连 |
| 会话、新建/重命名/重连、选区、粘贴、字号与远端鼠标模式 | 终端插件；使用既有公共视图、PTY、剪贴板和设置存储接口 |
| 原生剪贴板与共享连接/PTY | 核心持有；每次调用仍留痕，不记录剪贴板/终端正文 |
| 取消终端列表与底部位置 | 插件贡献声明及版本迁移；核心用通用视图声明/布局兼容规则处理，不写 `terminal.sessions` 特判 |

拟增加最小的公开 UI 呈现能力，供独立插件表面复用：版本化主题快照（颜色/排版令牌、系统可访问性偏好）及按窗口/挂载代次绑定的上下文菜单请求。菜单请求包含局部坐标或键盘锚点、稳定项目 ID、文字、启用状态、快捷键提示、分组；结果只返回选中 ID 或取消，插件执行自己的业务。宿主绑定来源，拒绝过期表面；取消和失焦只产生一次结束结果。主题/菜单载荷不包含剪贴板正文、资源句柄或业务状态。具体 schema、错误码与最小兼容版本须在本任务编码方案中固定并补契约用例，不能将本节描述为已有 API。

主题由核心通过公共版本化协议注入独立表面，终端按语义令牌映射 xterm；不能靠跨 WebView CSS 继承、导入外壳内部 React 组件或复制另一套配色来假装统一。后续终端业务更新仍可单独发布，本次新增公共能力可能需要核心与终端包配套版本；不兼容包必须明确拒绝并保持旧包可恢复。

旧布局处理在新版本启动、创建表面前完成，更新仍遵守“重启生效”：

1. 备份原布局，双区域按原第一组顺序、第二组顺序合成一个中央组；有记录的最后聚焦页优先成为活动页，否则原第一组活动页优先。只改变展示位置。
2. 已存底部终端按原顺序追加到中央；独立终端窗口保持原位置/归属。缺失显示器按已有召回规则处理。
3. 通过插件提供的版本化退役声明移除旧会话列表布局条目；该导航视图无会话关闭责任。未知缺失视图仍按既有故障占位处理，不静默删除其他插件布局。
4. 已结束终端保留占位、名称与顺序，重启不恢复旧 SSH/PTY，不自动执行命令。迁移不能用“关闭所有终端再新建”代替。
5. 先保存候选布局再提交，失败不覆盖原文件，给出重试/恢复备份入口。重复迁移不重复追加页面；保留必要 schema 版本，回退使用备份，不假定旧版本能直接读取新格式。

当前中央单组策略下，旧接口的非单组请求应明确返回不支持且不改变布局；保留旧格式读取用于迁移，不保留隐藏的分屏入口。插件不支持的底部/侧边目标亦按声明拒绝。

## 7. 验收与功能测试流程

验收：UX-AC-01 两层导航且无列表/分屏/省略号入口；UX-AC-02 公共视觉一致且内容可读；UX-AC-03 右键与键盘菜单可操作、可退出；UX-AC-04 拆合/关闭保持原资源语义；UX-AC-05 旧数据迁移可靠、插件边界清楚；UX-AC-06 颜色完全独立，替换主题无需修改组件或业务代码。

准备：Windows 原生开发包、独立数据目录、A/B 两个测试服务器工作区，每个至少两个终端；20 个无会话档案、80 字符终端名及长/重名服务器档案；T-004 旧布局副本含双组/底部/会话列表/独立窗口；隔离 Linux/OpenSSH 用于真实会话回归。只用脱敏数据。浏览器可验证布局与状态，不能代替原生 WebView/窗口命中。
