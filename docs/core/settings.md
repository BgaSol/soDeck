## 1. 目标与本期范围

T-028增量：[F-CORE-032 r1](plugin-management.md)新增应用→插件管理核心页，整合已有插件弹窗与所有入口；含签名/校验/运行状态和每插件启停草稿。与底栏应用/确定/取消、冲突/回执及原生关闭统一，PM-05/06/11/15/19/20/21验证本增量。具体列表/签名/启停不在此重复维护；下文“管理插件打开现有入口”为T-023历史范围，本次由新页替代。r2既有确认及结果保持，r3增量仅由[T-028](../tasks/T-028-plugin-management.md)确认，尚未编码。

用户明确要求：右上角提供设置按钮；参考 IDEA，左侧分组、右侧组内设置；插件声明自己的配置，核心提供接入方式。本方案推断目标是统一查找、编辑和反馈，同时让普通插件配置增量随插件独立更新。

本期建议包含：独立设置窗口、分类与搜索、声明式表单、草稿/校验/应用、修订冲突、插件不可用状态；接入现有主题和终端字号/Shell 目录集成；显示应用版本、运行方式与数据位置，并提供已有插件管理入口。终端是实际接入插件，不建设另一个产品样例插件。

后续范围：服务器级覆盖、配置导入导出/同步、快捷键编辑、复杂自定义插件页面、秘密字段编辑及迁移配置的通用脚本。服务器档案、认证、SSH/SOCKS 路径、隧道规则继续由对应业务编辑器管理。通信监控已有设置保留原入口，其接入另细化，不因建设框架扩展监控范围。没有具体设置的插件不展示空页面；未实现 AI/Docker/NetBird 不出现在本期导航。

## 2. 窗口、导航与视觉

### 2.1 入口与生命周期

- 所有现有工作台主/子窗口右上角增加齿轮“设置”，置于现有应用菜单按钮左侧、窗口控制按钮之前；独立点击区与拖动区分离，至少 28×28px，tooltip 与可访问名称为“设置”。保留应用菜单其他功能。
- 全应用单个、非模态的原生设置窗口；不占服务器 Tab，不属于某台服务器或插件业务视图。重复点击、其他窗口点击均聚焦同一实例。主窗口收起到托盘时，设置窗口继续运行；明确退出 App 时随 App 关闭。
- 新窗口建议 1000×720 逻辑像素，普通缩放下最小 760×540，始终限制在屏幕工作区。左导航约 220px，内容区自适应，正文独立滚动，头部和底部操作固定；高文字缩放/小工作区时允许内容与导航各自滚动，不以最小尺寸强迫窗口超出屏幕。
- 设置窗口“×”只关闭设置；Esc 走同一关闭流程。关闭后回到最近有效的来源窗口并恢复设置入口焦点；来源已关闭时不重建服务器或会话。保存中暂缓关闭，明确显示状态；超时后允许核对结果，不能把关闭误当撤销已提交操作。
- 本次运行内记住上次分类和窗口几何；完整重启不自动打开设置、不恢复草稿，沿用全新工作现场规则。

### 2.2 信息组织

左侧顶部放“搜索设置”，下方为分组树，最多两层。本期结构：

```text
设置                                  [关闭]
┌──────────────────┬─────────────────────────────┐
│ 搜索设置         │ 插件 › 终端                 │
│                  │ 终端显示                    │
│ 应用             │ 字号       [14       ]      │
│   外观           │ 默认 14，范围 10–24          │
│   应用与数据     │ 应用后更新已打开的终端       │
│ 插件             │                             │
│   终端           │ 目录集成                    │
│                  │ [✓] Shell 目录集成          │
│ [管理插件]       │ 对新建/明确重连会话生效      │
├──────────────────┴─────────────────────────────┤
│ 有未应用的更改        [取消] [应用] [确定]      │
└────────────────────────────────────────────────┘
```

“外观”使用现有三主题选择卡片；“应用与数据”显示实际应用版本/渠道、运行方式、数据位置，支持复制路径与打开文件夹，位置只读。其信息来自现有启动配置及原生服务；不显示任意环境变量或提供修改数据目录按钮。“管理插件”打开现有插件管理入口，复用管理器状态，不复制安装/启停/升级流程。

设置项用标题、控件、必要说明组成连续表单，相关项按小节分组。右上标识所属插件及版本；默认值和生效时机放在相关项旁。避免每项一个卡片；选择、错误、未应用标记同时使用文字/形状，不只靠颜色。

搜索覆盖分类、字段名称、说明和插件声明的关键词，不索引当前值或秘密。空白查询还原树；多词按各词均匹配处理，中文按子串匹配，不要求拼音/模糊纠错。搜索时树保留命中页面及祖先，右侧列出字段结果与完整分类路径；点击结果进入原页并滚到字段、短暂标记，清空搜索后恢复原分类和展开状态。无结果显示可清空的空态；搜索/切页不丢草稿。无障碍名称使用原始文本，不把高亮标记读进名称。

### 2.3 apple-design 与现有设计系统

采用熟悉性、层次、控制感和即时反馈：稳定的左导航与右内容；pointer-down 即时反馈；校验贴近字段；加载/保存不遮盖整窗；所有动效可中断。沿用系统字体、13px 正文/12px 辅助/18px 标题、4px 间距步长和公共控件，颜色/圆角/边框来自现有主题与公开 `@sodeck/ui`。三主题完整适配，多巴胺按现有 profile，不强加玻璃材质。浮层可用 120–180ms 淡入，减少动态时即时切换；减少透明用实底，高对比使用系统语义与明确焦点。

Tab 可访问搜索、导航、表单和底栏；树支持上下/Home/End、左右展开收起及 Enter 选择。Ctrl+F 聚焦设置搜索，仅在设置窗口处理；不截获终端快捷键。IME 组合期间 Enter 不触发确定。错误通过关联说明和状态播报呈现；200% 文字缩放仍能操作。

## 3. 编辑、保存与异常规则

1. 页面按需读取当前值、默认值和配置修订，加载失败只阻塞该页，支持重试；无须先打开一个终端。切页不自动保存，草稿保留在本窗口内，导航标记有更改的页面。
2. 字段先做声明类型/范围校验，应用前再由所属 provider 校验整组业务约束；错误项定位到具体字段。没有改动或有已知错误时“应用”不可用；“确定”无改动时直接关闭，有改动时按应用流程成功后关闭。
3. “恢复本页默认”只将本页可编辑字段改为默认草稿，仍需应用；无可编辑字段的页面不显示。取消或带未应用草稿关闭时，提示“放弃更改 / 继续编辑”，默认继续编辑；已成功应用的值不受取消影响。
4. “应用”先对全部脏 provider 做校验，校验全通过后按稳定顺序逐组提交，每组一个原子保存、一个修订和操作 ID。跨 provider 不承诺事务，也不自动回滚已生效业务；部分失败明确列出成功组与失败组，只保留失败组草稿，重试仅提交尚未成功的组。“确定”遇到失败留在窗口。
5. 每次提交携带读取时的 expectedRevision；页面外快捷入口也走同一 provider 写路径并更新修订。有草稿时收到新修订，显示冲突、停止覆盖，提供“载入最新并放弃本组草稿 / 保留草稿继续查看”，后者不解除冲突；必须读取最新后重新编辑才可保存。无草稿时自动刷新，迟到读取不得覆盖较新修订。
6. 超时或窗口通道中断时显示“保存结果待确认”，按 operationId 查询结果和当前修订；不盲目重发。相同 ID/相同载荷返回同一结果，相同 ID/不同载荷报错；单组最多一个在途写。读取/校验默认 5 秒、提交默认 10 秒后转结果核对，不能把超时当成未写入。业务生效通知失败时报告“已保存，部分视图尚未同步”，重试同步不重复提交。
7. 普通关闭先处理在途操作，再处理剩余草稿。明确退出 App 的现有入口先汇总本窗口草稿，确认放弃后执行原退出清理；在途写等待有限时间并记录操作 ID，存储原子提交保证重启读到完整旧组或新组。强制结束进程不保证保留草稿，不自动在下次启动打开窗口。
8. 首期所有编辑字段均为应用级偏好。主题改为先选中草稿，按“应用/确定”后才全局换肤，取消不改变主题；这会替代旧外观弹窗的点击即保存。旧菜单“外观”改为打开本窗口外观页，不能保留第二套不同保存语义的编辑器。其他页面的既有快捷操作可继续立即保存，并通过修订机制协调。

## 4. 核心与插件契约

### 4.1 声明和责任

源码核实：当前 `settings.v1` 已用于旧 `settings.get/set` 数据库键值接口，本次不重用其含义。[代码方案§3～5](../technical/settings-implementation.md#3-文件与模块改动)建议API/SDK 5.1.0，新增 `settings.contributions.v1`、`storage.preferences.v1` 和 `ui.settings.v1`；旧接口保留。manifest可选 `contributes.settings` 固定引用包内 `settings/settings.json`，声明随已验证插件包交付。只读取本次启动已激活版本，待更新包的设置不得提前出现；具体严格DTO及固定provider回调按代码方案执行，当前尚未实现。

| 声明内容 | 语义 |
| --- | --- |
| descriptorVersion / schemaVersion | 接入格式版本 / 插件配置结构版本，二者独立 |
| pageId / title / keywords / order | 稳定页面身份、中文标题、搜索关键词和排序；核心决定“插件”父组，插件不能覆盖其他插件页面 |
| sections / fields | 小节及稳定字段 key、名称、说明、类型、默认值、顺序、范围/长度/选项 |
| effect | 每项标识立即生效、新建或明确重连会话生效、重启 App 生效；实际承诺由插件保证 |
| conditions | 受限的同页字段等值可见/可用条件；不接受脚本表达式或远端代码 |

首期控件支持布尔、整数、单行文本和固定枚举，限制字段/文本/描述体积并校验 ID 唯一、默认值合法、条件引用无环；四种控件完成契约/UI验证，终端实际集成使用布尔和整数，其他类型以明确标识的夹具验证。外观以核心自有页面复用主题卡片，但仍使用相同草稿/provider 流程。普通声明由核心公共表单渲染器呈现，插件无需重写常规样式。一页对应一个原子设置组；插件多页时左侧仍为插件入口，右侧提供页选择，当前终端只有一页。

**插件拥有配置含义、默认值、业务校验、存储布局、迁移和生效逻辑；核心拥有注册、统一呈现、搜索、编辑会话、调用路由与通用记录。** 默认值只有插件声明这一份，worker 和快捷入口共同消费，不另写第二份常量。核心既不认识 `shellIntegration` 的业务含义，也不把终端规则写进核心；底层持久化继续复用核心公开的插件命名空间存储，不为设置中心复制一套配置库。

### 4.2 Provider 与状态路径

provider 提供读取快照、无副作用校验、带修订提交、操作结果查询及变更订阅。请求包含 page/provider 标识、配置结构版本、修订、变更字段和操作 ID；响应包含新快照/修订、字段错误、保存状态及实际生效状态。错误区分声明无效、插件不可用、校验失败、修订冲突、写入失败及结果待确认；可展示脱敏原因与重试入口。

设置 UI → 核心设置服务 → 宿主绑定的所属插件 provider → 插件命名空间存储/插件业务状态；核心自有页由自己的领域 provider 承担。设置调用是核心发起的受限宿主回调，不开放插件互调、不伪造服务器/工作区上下文、不注册任意跨插件主题。来源身份由宿主绑定而非信任描述文件；无权限审批，遵守 P-14，命名空间用于配置归属与避免串用。

字段变更订阅复用既有有修订状态/feed机制，作用域为应用+provider+当前运行代次，带快照恢复与退订；窗口销毁释放订阅。成功写入后由插件更新自己的权威状态并通知所有视图；核心不借 DOM/React store 控制插件业务。配置变更记录仅含来源、page、字段 key、操作 ID、修订与结果，不写自由文本值、秘密或完整路径。

### 4.3 兼容与故障

- 没有设置声明的旧插件照常运行，导航不生造页面；未支持接入能力的新包由既有兼容检查处理。普通增加已支持类型的设置，只更新插件声明+worker+配置版本，不修改核心。
- 禁用、故障插件保留所属页名称和不可编辑原因，不能为了改设置自动启用它；坏声明只隔离该页/贡献，完整性及可选签名检查依[F-CORE-032](plugin-management.md)。包不完整时不读取未验证描述，管理页仍显示登记ID与失败原因。插件卸载后移除入口的规则保留为历史背景，T-028不实现卸载。
- 插件更新遵循重启生效；升级迁移由插件负责，在数据副本验证后发布，迁移失败保留旧数据并禁用本组编辑。回退不得让旧版写坏较新配置；遇到更高结构版本保持只读并说明原因。核心不清除未知 key，不把 schema 升级解释为恢复默认。
- 首期终端沿用现有 `fontSize` / `shellIntegration` 数据，不更改整个业务数据库结构或触发其备份重建；[代码方案§6](../technical/settings-implementation.md#6-成组存储冲突和结果确认)在原插件settings.json增加组修订/有界回执，并通过同文件原子替换保存。插件整体dataSchemaVersion保持1，当前管理器对其不匹配的拒绝规则保持，不建设通用迁移执行器。普通值与未知键保留；秘密未来以秘密引用+专用流程设计，不进入当前声明式文本框。
- 核心外观独立文件按[代码方案§7](../technical/settings-implementation.md#7-核心外观与应用信息适配)由v2扩为v3，在实际应用前保留旧文件备份，将主题选择和操作回执原子保存，并分开配置/呈现修订。core.sqlite结构不变；旧核心不识别v3，不能直接拿本轮新数据目录降级运行，回退使用关闭后的旧包/数据副本。这个新兼容影响随本次代码方案一并确认。
- 后续需要账户列表/复杂映射等时，可设计插件自绘设置页嵌入槽，仍须接统一读取/草稿/校验/提交/主题契约。本期不提供可绕开保存流程的任意 WebView 注入。

## 5. 验收标准

- AC-01：任一工作台窗口点击右上齿轮，打开/聚焦同一应用级设置窗口，关闭不改变现有会话。
- AC-02：分组、搜索、草稿、默认值、应用/确定/取消和错误定位符合§2/3，搜索切页不丢输入。
- AC-03：主题和终端实际配置经统一入口完成保存；取消无副作用，已应用项可跨重启保留，生效时机可观察。
- AC-04：保持核心二进制不变，仅更新终端插件新增一个受支持的实际设置声明及实现，重启后能发现并使用；不含插件互调或权限弹窗。
- AC-05：修订冲突、部分失败、结果不明、无声明/坏声明/不可用插件可恢复且不静默覆盖值；不记录配置正文。
- AC-06：三主题、键盘/IME、200%文字缩放、高对比、原生多窗口/托盘/退出和资源释放符合约定。
