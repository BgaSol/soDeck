## 可验收行为与实现

`preflight` 在编译前读取唯一版本和非空发布说明；标签必须匹配版本。准备草稿时核对仓库可访问、既有 Release 草稿状态及标签的源码提交，鉴权、限流、网络和服务端错误均使前置检查失败。

五个原生目标继续执行 Rust 测试、编译、官方 updater 签名及实际安装/解包后的启动退出。平台任务仅有仓库读取权限，tauri-action 仅构建本机文件。烟测成功后 `collect-core.mjs` 按本次版本的明确文件名收集安装/更新包与签名，写入 `core-artifact.json` 的 ID、版本、平台、提交、大小和 SHA-256；拒绝合并旧收集目录。

汇总任务只下载当前运行的 `SoDeck-*` Artifact，核对来源、文件名、完整性和签名配对后生成现有更新器使用的 `core-update.json`。保持 NSIS、DEB/AppImage、DMG/app 更新归档及原有附件名称；Linux 在线更新继续选择 AppImage。缺少目标列入结果，不抹掉其他已验证包。

核心同版本草稿写入使用 job concurrency 串行且不自动取消。只有汇总任务能写 Release；写入前再次检查草稿与标签，同名包已有摘要必须一致，未知旧附件拒绝混入。上传后响应丢失可重新执行汇总，已存在且一致的附件直接复用；清单最后上传并核对 GitHub 摘要。正式版本拒绝写入。

分支手动运行默认只生成 Artifact 和清单；`publish=true` 显式准备草稿。`core_run_id` 可复用本仓库已结束的核心运行，核对 Artifact 有效后跳过原生构建，汇总按原运行的提交验证。这也允许修复发布脚本后恢复旧运行的产物。普通核心标签同样准备草稿，正式发布继续由维护者完成。核心与业务插件的独立构建入口保持原有关系。
