> 状态更新：Hello 和组件交互示例现已退役，源码、官方来源和发行配置已删除；本文有关保留或发行示例的描述属于历史方案。宿主回归改用仅测试夹具，真实业务由终端、文件、网络隧道插件提供。

状态：代码已实现，正在验收，尚未发布。设计基线为核心 v0.6.1、终端插件 0.1.1、文件插件 0.2.0。`net.tcp.v1` 与 `ui.dialog.v1` 为兼容 API v1 的新增能力；实际调用参数以 [插件 API](plugin-api.md) 为准，验证范围见 [实施记录](implementation-network.md)。五平台实际包验证完成前不视为正式交付。

## 1. 本轮交付范围

新增独立官方插件 `sodeck.network-proxy`，界面名称“网络隧道”，首版版本从 0.1.0 开始，与旧仓库的 0.7.2 不构成原位升级。

本轮完整交付：

- 固定 TCP 端口转发：本机入口经当前服务器的完整混合跳板路径，访问固定的远端目标。
- SOCKS5 CONNECT 代理：本机客户端按请求选择远端目标，支持 IPv4、IPv6 和域名，无认证协商，与旧版相同。
- 按服务器保存规则，提供增删改查、启动、停止、复制实际入口、状态、错误、连接数和流量。
- 侧栏默认右侧收起，可改到左侧；创建和编辑使用宿主弹窗。
- 收起、切换和移窗保持运行；工作区关闭、连接断开、插件退出或应用退出后释放资源。
- 通过实际本地入口检查到目标的 TCP 连通性。
- 核心与插件分别打包和更新，覆盖五个正式目标。

HTTP 普通代理与 HTTPS CONNECT 放到下一轮。首版明确显示“SOCKS5 代理”，不显示“HTTP/SOCKS 通用代理”。自动重连、开机恢复隧道、反向监听、UDP、VPN/TUN 和系统代理接管不在本轮。规则启动/停止立即生效；插件启用/关闭/升级仍按重启生效的现有约定。

## 2. 当前代码能复用什么

| 当前代码 | 已有能力 | 本轮处理 |
| --- | --- | --- |
| `connections/route.rs` | 按顺序执行 SSH/SOCKS5 路径，持有最终 SSH 会话 | 增加内部远端 TCP 通道接口；不重新实现路径执行 |
| `connections/mod.rs` | 按工作区 Context 获取有效会话、断开和重连 | 复用；旧运行固定到创建时的会话，不自动接到新连接 |
| `terminal.rs` | `Owner`、`resource_owner()` 与资源归属校验 | 将这两个公共部分移至 `resource_owner.rs`，保留行为 |
| `plugins/dispatch.rs` | 有界的插件到核心控制请求 | 增加薄路由，不在分派线程等待远端建连或长期读写 |
| `plugins/process.rs` | 插件退出清理及第二次竞态清理 | 在两个清理位置都接入网络资源 |
| `component_ui/host.rs`、`close.rs` | 视图绑定、关闭协调、移窗重挂载 | 扩展通用弹窗容器，接入网络资源关闭 |
| `network_metrics.rs` | 服务器 socket 与插件有效载荷、约 3 秒速率 | 接入远端 TCP 有效载荷，增加规则级运行快照 |
| `crates/plugin-client` | 持续读取响应、有界并发和嵌套调用 | 增加可克隆的客户端句柄，供插件后台管理线程使用 |
| `scripts/package-plugin.mjs`、`plugin.yml` | 通用的独立插件五目标打包 | 直接复用，不添加专用发布框架 |

当前 `plugins/ui-example` 的网络转发面板仍是示例，保持示例用途；正式功能新建插件目录，不在示例中继续堆业务。

## 3. 职责和代码目录

核心持有本地监听、远端流、复制任务、取消信号和计数；插件持有规则、SOCKS5 状态机、运行编排和界面。插件只传目标 `host:port`，不接触 `russh`、SSH 密码或跳板实现。

```text
src-tauri/src/

  network/
    mod.rs                       # 对 AppCore 的入口、参数和所有权检查
    runtime.rs                   # 监听/流/任务状态、后台任务与取消
    relay.rs                     # 有界复制、半关闭、按远端边界计量
  connections/route.rs            # Session::open_tcp(host, port)，仅核心内部使用
  network_metrics.rs             # 复用插件和服务器统计，采样规则流量
  component_ui/                  # 新增 dialog 容器的通用行为

plugins/network-proxy/
  Cargo.toml, Cargo.lock         # 自己的版本、依赖和锁文件
  release.json, CHANGELOG.md
  README.md
  src/
    main.rs                      # initialize、UI 方法与消息接线
    rules.rs                     # 规则校验、串行保存和修订冲突
    manager.rs                   # 后台轮询、每条规则运行状态和启动/停止
    socks5.rs                    # 增量协议解析、响应与错误映射
    checks.rs                    # 经过真实入口的连通性检查
  ui/
    index.html, bridge.js
    view.js, style.css           # 列表、详情、弹窗表单与草稿同步
```

目录随对应功能建立，不先创建空框架。初期不增加通用资源注册中心、通用工作流引擎或独立协议包。本轮复用仓库已有的 Rust/JSON 工具和原生 DOM，不引入新的第三方库或前端框架。

## 4. 保存配置与运行状态分开

### 4.1 规则文件

保存到核心初始化时提供的 `dataDirectory/network-rules.json`。插件只在自己的数据目录读写，不复制核心的服务器资料。概念结构如下：

```ts
type Rule = {
  id: string;
  revision: number;
  serverId: string;
  name: string;                    // 可空，由界面生成显示名称
  bind: { host: string; port: number }; // 默认 127.0.0.1；0 表示自动端口
} & (
  | { type: "tcpForward"; target: { host: string; port: number } }
  | { type: "socks5" }
);

type RuleFile = { schemaVersion: 1; rules: Rule[] };
```

不重复保存 `bindMode`，端口 0 已能表达自动分配。固定目标端口必须为 1～65535。保存基本格式、端口、长度、服务器归属和修订检查，不增加权限或审批字段。建议最多 256 条规则、名称 128 字符、规则文件 512 KiB；列表每页 20 条，并同时受控制帧字节上限约束。

不自动导入旧仓库数据；旧版和新版服务器 ID 不可按名称猜测对应。服务器资料缺失或当前工作区不匹配时明确拒绝启动，不回退到其他服务器。

插件进程串行提交：构建下一份有效数据 → 写同目录临时文件并同步 → 替换正式文件 → 更新内存 → 返回成功。采用可在 Windows/Unix 覆盖既有文件的实现，不能先删除正式文件再写入。保存失败保留上次有效数据和编辑草稿；解析失败或 schema 不支持时保留原文件并显示错误，不自动覆盖为空库。

`revision` 防止旧弹窗覆盖新修改。超时导致保存结果不明时，重新读取对应规则确认；不盲目重复新增，也不引入旧版的持久提交回执、哈希账本或复杂协调状态机。规则 ID 在保存前已生成，重复查询能定位同一条记录。

### 4.2 运行记录

```ts
type RuleRun = {
  runId: string;                  // 插件生成，每次重新启动均不同
  ruleId: string;
  ruleRevision: number;
  managerViewId: string;
  context: Context;              // 核心提供，固定本次 connectionId / generation
  listenerId?: string;           // 核心生成的资源 ID
  state: "starting" | "running" | "stopping" | "stopped" | "failed";
  actualAddress?: { host: string; port: number };
  lastError?: { stage: string; code: string; message: string };
};
```

实际端口、资源句柄、连接数和流量不作为恢复运行的数据写入规则文件。应用重启只恢复规则；用户显式启动后才监听。

运行使用规则快照。编辑时提供“保存”和“保存并重新启动”；前者不改变现有连接，详情提示有待应用配置。后者先保存成功，再停止旧运行并创建新运行；新启动失败时保留新配置并显示失败，不假装旧连接仍然可用。删除运行中的规则先停止并确认端口释放，再提交删除；删除保存失败时保留已停止的规则。

## 5. 核心 TCP 能力设计

新增可选能力 `net.tcp.v1`，保持 API 主版本 1；旧终端、文件和无 UI 插件继续工作。新插件在 initialize 时检查所需能力。以下名称在编码时与协议文档一起固定，不对外暴露 SSH 类型。

### 5.1 控制接口

| 拟新增方法 | 主要入参 | 返回及语义 |
| --- | --- | --- |
| `net.listener.open` | `viewId, operationId, bind` | 立即返回 `listenerId` 和 starting 状态；后台绑定，成功后给出真实地址 |
| `net.poll` | `viewId, limit` | 不等待 I/O，批量领取本视图已接受的连接及资源变化；限制条数和总字节 |
| `net.tcp.open` | `listenerId, clientStreamId, operationId, host, port` | 立即返回 connecting 的 `streamId`，与所属客户端关联；使用监听创建时捕获的服务器会话后台建连 |
| `net.stream.status` | `streamId` | connecting/ready/relaying/closed/failed、结构化错误和小量状态 |
| `net.stream.read` | `streamId, maxBytes` | 非阻塞领取有限协商字节；无数据返回 pending，EOF 单独表示 |
| `net.stream.write` | `streamId, bytes` | 排队写有限协商字节，返回 queued；失败反映到资源状态 |
| `net.stream.splice` | `leftId, rightId, operationId` | 校验同一监听归属后接管两个流，后台双向转发；成功入队前不消费句柄 |
| `net.listener.snapshot` | `listenerId` | 状态、真实入口、活动连接、有效载荷、速率和最近错误；必要的子项有界分页 |
| `net.listener.probe` | `listenerId, operationId` | 后台通过实际本地入口建立自检连接，返回 probeId；对应 accept 带同一标识 |
| `net.close` | `id` | 幂等停止监听/流/复制任务，先禁止新增工作并发出取消；通过状态确认资源已释放 |

`operationId` 是插件为本次创建或转发生成的内存幂等键，作用域为插件实例及父资源。在有效重试窗口内，迟到重试返回同一对象，不额外监听或建立第二个远端流；同一键搭配不同参数明确失败，资源关闭后同一键不复活资源。不做磁盘请求账本。幂等记录有界且覆盖控制请求的有效期；超出重试窗口插件只查询状态，不自动重发创建请求。用户明确再次启动时使用新的 runId 和 operationId。

现有插件客户端等待约 4 秒，核心 RPC 期限约 5 秒；不为隧道提高全局超时。监听绑定、远端连接和停止都在原生后台任务中进行，RPC 不等待完整结果。远端 TCP 建连使用独立的有界期限，首版建议 10 秒；停止或会话断开可以提前取消。

### 5.2 协商小包与正文

本轮只实现 SOCKS5，握手是有限的小包，可以复用现有控制 RPC：每次读写最多 512 字节，每条客户端流在移交转发前累计读写最多 1 KiB，协商总期限建议 10 秒。这些字节只在核心和插件原生进程之间传递，不经过 iframe、`ui.event` 或普通日志。

`read` 最多消费调用方请求的字节数；插件按当前协议阶段精确请求所需长度。核心的预读缓冲同样有上限，达到上限即背压，客户端提前发送的业务正文必须留在缓冲或 socket 中。移交时先发送已排队的响应，再转发剩余字节；不得丢掉与 CONNECT 请求粘在一起的首段正文。

`write` 返回 queued 不代表对端已经收到；`splice` 在原生任务内等待之前的写队列完成后再复制，保证 SOCKS5 成功响应在正文之前。错误响应后的关闭也要提供有期限的排空，不能排队后立即丢弃响应。数据调用结果不明时不重试读取/写入，结束这一条客户端连接，避免重复消费或发送。

SOCKS5 成功后的正文，以及固定转发的所有正文，均由核心直接在本机流和远端流之间复制，不通过 JSON-RPC。当前已有视图数据桥不是原生插件数据桥，不能拿来承载代理流量。

这个有限接口不承诺完整 HTTP 正文处理能力。下一轮 HTTP 插件需要边读边改写请求和响应，应另行设计适合正文的原生数据通道，不能扩大这里的协商预算来长期传正文。

### 5.3 原生任务和资源边界

- `Session::open_tcp()` 在最终 SSH 会话打开 direct-tcpip，目标域名原样交给远端；本机只解析到达连接链第一站所必需的地址。
- 监听绑定当前 `Owner`、工作区 Context 和实际 Session，不在新连接到来时重新查询“最新会话”。
- 每个监听持有自己的已接受流、远端流和复制任务。停止一条规则只取消这棵资源，不关闭共享 SSH 会话或其他插件。
- 核心接管复制时使用有界缓冲和半关闭：一侧 EOF 后仍允许另一方向完成；错误、超时或显式停止可取消两侧。复制任务结束后回收全部句柄。
- 建议初始上限：插件 32 个活动监听、16 个待协商连接，单监听 64 个活动业务连接，核心 256 个活动业务连接；超限给出具体原因，不无限创建线程或缓存。
- 未被插件接管的已接受连接也有期限；插件没有领取、丢失响应或协商超时都由核心关闭。远端建连失败只结束对应客户端，不使整个监听失败。
- `net.poll` 是有界事件提示，每次最多 16 项且编码后不超过 24 KiB，超出部分下一页领取；资源状态仍可查询。事件队列有界，未领取连接到期关闭并计数，不能让客户端无限悬挂或使运行状态不可恢复。
- 本地端口占用明确失败，不自动换一个固定端口。绑定成功与目标可达分开报告，监听 running 不代表固定业务目标一定在线。

## 6. 插件业务流程

### 固定转发

1. 保存或读取本服务器规则，捕获规则版本和工作区 Context。
2. 创建监听；只在绑定成功后展示可复制的实际入口。
3. 后台领取本地连接，为每个连接请求远端 TCP 流。
4. 等待远端流 ready，再将两端交给核心 splice。
5. 目标失败时关闭这对流，增加失败计数并更新最近错误，继续接受其他连接。

### SOCKS5

1. 领取本地连接，由插件的增量状态机读取方法协商。
2. 仅接受 no-auth CONNECT；BIND、UDP ASSOCIATE、不支持的认证和地址类型返回相应失败。
3. 解析客户端给出的 IPv4、IPv6 或域名和端口，经核心建立远端流。
4. 只有远端建连成功才回复成功，然后交给核心 splice；拒绝、超时等映射为 SOCKS5 响应。
5. 单个异常客户端只清理自身，不能让插件进程或整个监听退出。

插件启动一个后台管理线程，使用可克隆的 `plugin-client` 句柄驱动有界状态机，处理所有工作区的运行；不为每个客户端创建常驻线程，也不占用 UI handler 等待完整握手。`net.poll` 按活跃视图批量查询，空闲时降低频率；侧栏不可见只停止 UI 刷新，后台管理继续。

克隆客户端只共享现有 writer、pending 和序列号；EOF/shutdown 将共享句柄标为关闭，并结束所有 pending。现有 `run(handler)` 和旧插件调用方式保持兼容，不重写 RPC 框架。

## 7. 生命周期、关闭与竞态

| 事件 | 运行规则 | 保存配置 |
| --- | --- | --- |
| 侧栏收起、换到另一侧、切换服务器 | 继续 | 不变 |
| 工作区拖出或移回、目标表面重新挂载 | 同一运行继续，不重新监听 | 不变 |
| 关闭创建/编辑弹窗 | 只释放草稿，不停止已启动隧道 | 已保存配置保留 |
| 停止或应用新配置 | 仅结束该规则的监听和客户端 | 保留 |
| 服务器断开、原会话失效 | 核心关闭本次运行，插件显示已中断 | 保留 |
| 服务器重连 | 旧运行不接到新会话；用户再次启动 | 保留 |
| 工作区真正关闭、插件停止/崩溃、应用退出 | 核心兜底停止全部所属资源 | 保留 |

网络资源归属于稳定的侧栏 manager view，不能归属于短期表单 dialog view 或 iframe surface。移窗只变更展示归属，不更换 runId、listenerId 或会话。

在 `core.rs` 的应用停止、`plugins/process.rs` 的两处退出清理、`component_ui/close.rs` 的视图销毁中接入网络取消。监听和流同时观察会话 cancellation。创建在注册后再次确认归属，补上与关闭交错时的清理；已进入停止状态的对象禁止重新创建子资源。

关闭的两个阶段要分清：准备/确认阶段不关闭正在使用的隧道，取消关闭后保持原运行；提交关闭后才停止监听并等待有界释放。准备阶段禁止用户新建运行，但已存在监听的正常客户端业务继续，不能因 UI 冻结误断流。

持续运行的监听不标记为 `metadata.busy=true`，该字段只用于有限的保存/切换操作。否则现有关闭代码会把服务当成“尚未保存完成的任务”持续等待。表单未保存使用 dirty；监听在真正 dispose/退出时关闭。

## 8. UI 容器及业务界面

### 8.1 通用弹窗能力

现有清单只支持 sidebar/editor，本轮增加可选 `container: "dialog"` 和能力 `ui.dialog.v1`，不复刻旧版整个对话框系统：

- 继续用现有 `openView` 打开已声明的本插件 dialog；新增页面桥 `closeView` 关闭自身，复用关闭协调。
- 弹窗有独立 viewId 和同一服务器 Context；不出现在中央 Tab 或左右工具条，不参与启动默认展开。
- 核心负责遮罩、尺寸边界、滚动、焦点、Escape、关闭协调和窗口归属；插件负责内容、字段校验和业务按钮。
- `ui.mount/event/beforeClose/save/disposeView` 保持原职责。保存配置不隐式启动；“保存并启动”是明确的业务按钮。
- 每工作区最多一个本插件编辑弹窗；再次打开定位现有草稿，不能悄悄覆盖正在编辑的规则。
- 每窗口只呈现当前活动工作区的弹窗；切换和移窗保留其他逻辑草稿，不在一个窗口叠加多个模态层。
- 表单使用现有 flush 机制将有界草稿同步至插件。移窗重挂载恢复同一弹窗、焦点意图和草稿，旧 surface 事件继续按现有机制失效。
- dirty 弹窗关闭走现有保存/放弃/取消流程；保存错误保留内容。取消不得停止侧栏管理的隧道。

插件声明 manager 为 sidebar/perWorkspace、右侧固定入口、默认隐藏；rule-editor 为 dialog/perWorkspace。表单触发“保存并启动”时，插件从自身工作区记录查找 manager view，核心仍按真实归属校验，不能让页面随意指定其他服务器的资源拥有者。

新增网络插件依赖上述两项能力，旧核心不支持新插件。旧插件在新核心继续工作；旧核心可能在新 dialog 清单校验时就拒绝，不能承诺一定进入 initialize 才提示升级。

### 8.2 页面内容

- 列表：名称、类型、状态、本机入口；悬停显示启动/停止和复制。大量规则有界分页，不传整个运行树。
- 详情：实际入口、固定目标或 SOCKS5 用法、状态、活动连接、上下行速率与累计量。
- 次要区折叠展示：本次实际连接路径、TCP 连通性检查、最近错误。核心在监听创建时从真实连接尝试投影中保存不含秘密的路径摘要，供 snapshot 查询，不增加第二个路径编辑器；不能用最新编辑值冒充当前路径。
- 表单：类型、可选名称、绑定地址、自动/固定端口；固定转发再填目标主机和端口。绑定地址默认 127.0.0.1，其他地址放更多设置；不增加授权步骤。
- 主题使用现有宿主 tokens，保持文件面板的紧凑列表、奶油底、粉色/黄色/薄荷点缀与深色描边，支持浅色和深色。弹窗内容可滚动，底部动作始终可达。

旧版最新“规则列表 → 详情 → 弹窗编辑”的信息结构可参考；不复制其 SDK、React、完整诊断系统和保存回执实现。

## 9. 统计、日志和连通性检查

### 带宽

核心在远端 TCP 流读写成功的边界计数：向远端写入为上传，从远端读取为下载。同一段数据不在本地和远端重复计量，失败或部分写入按实际已传字节计算，不能只在完整复制成功后统计。

服务器沿用最外层 socket 总量；插件有效载荷聚合到 `(serverId, pluginId)`；每个 listener 的计数通过运行记录对应到规则。复用约 3 秒采样窗口，累计量使用十进制 u64 字符串。

规则显示本次运行累计量，重启规则后清零；插件/服务器保留当前应用进程内的累计口径。SOCKS5 本地协商报文不算远端有效载荷。SSH/SOCKS 封装等共享开销保留为服务器总量和未归属，不伪造精确分摊。更新 `network_snapshot` 的说明，不能继续写“仅文件和 PTY”。

### 错误和通知

错误至少分 listen、targetConnect、protocol、sessionLost、cleanup；日志附 ruleId/runId，核心补插件实例和接收时间。不记录代理正文、认证秘密或完整访问内容。

单个目标不可达更新对应错误/计数，避免每个失败请求弹通知；整个运行因会话中断停止时发布合并的重要消息，使用现有 dedupeKey。普通 error 日志不自动弹窗。

### 检查

检查代码在插件原生进程内，使用本机真实监听入口；监听 `0.0.0.0`/`::` 时选择对应地址族的回环地址，绑定具体本机地址时连接该地址，不能直接把通配地址当连接目标。

- 固定转发：核心给一次自检连接分配关联标识，插件将该 accept 与 `net.tcp.open` 的客户端流关联，必须确认对应远端 TCP 建立结果；本地 connect 成功不算通过。
- SOCKS5：插件用标准 TCP 客户端对实际入口完成 no-auth CONNECT；目标由用户提供，收到成功响应才通过。
- 核心的 `net.listener.probe` 在发起本机连接前登记其本地端点，再将真实 accept 的对端匹配到 probeId；不能把“下一个 accept”默认认作自检。probe 有期限并在完成后关闭两端，避免固定转发在无 banner 服务上误报成功。正常业务不依赖它。
- 结果绑定本次 runId、规则版本及目标；停止/重新启动后旧检查失效。只说明 TCP 可达，不宣称 TLS、HTTP 或数据库登录通过。

## 10. 改动清单与实施顺序

| 批次 | 主要改动 | 完成标准 |
| --- | --- | --- |
| A 核心 TCP | `resource_owner.rs`、`network/*`、`connections/route.rs`、`core.rs`、`lib.rs`、RPC 分派和 capability、退出清理、计量 | 测试进程可创建监听，经真实 SSH 通道转发，停止后端口释放；终端/文件回归通过 |
| B 固定转发插件 | `plugins/network-proxy`、客户端可克隆句柄、通用 dialog、规则存储和列表/详情/表单 | 保存/启动/停止/编辑/删除完整可用；切换和移窗保持同一运行；取消表单不误停 |
| C SOCKS5 和检查 | 增量协议状态机、错误映射、probe、自检、规则流量与消息 | 真实客户端经混合路径访问仅远端可达/可解析目标；失败和取消清理正确 |
| D 分发与实际包 | 官方来源列表、相关检查脚本、原生包验证入口和现有 CI 接线、API/产品/分发文档 | 五目标核心和独立插件实际产物可安装、启停、转发及退出；具备独立在线更新路径 |

批次按依赖执行，每批形成可验证的完整改动。只做必要的 Owner/客户端提取，不连带大规模改造 PTY、SFTP 或整个窗口框架。新增命令与其脚本同时落地，再接工作流，本文阶段不写调用不存在入口的 workflow。

宿主弹窗对应 `component_ui.rs`、`component_ui/layout.rs`、`host.rs`、`close.rs`、`src/components.ts` 和 `src/components.css`。如现有拖窗代码按容器枚举视图，需要一并补齐 dialog 的目标就绪和 flush，不能只在前端叠一层弹窗。

## 11. 验收与交付

| 用例 | 必须验证的结果 |
| --- | --- |
| 固定转发 | 多客户端双向传输，目标在最终服务器及其内网均可；包含大于缓冲区的数据与半关闭 |
| 混合路径与 DNS | SSH/SOCKS5 交替多跳，目标只允许最终服务器解析/访问；绝不回退本机直连。SOCKS 客户端使用域名模式，例如 socks5h |
| SOCKS5 协议 | 分片、粘包、握手尾部正文、IPv4/IPv6/域名、拒绝不支持命令；目标未连通不得提前回复成功 |
| 规则与表单 | 自动/固定端口、冲突、保存失败、修订冲突、停止后删除保存失败、异常规则文件保留；弹窗滚动和三主题 |
| 独立性 | 停止一条规则不影响另一条规则、文件或终端；多个服务器的流量和操作不串 |
| 生命周期 | 收起/移窗不重新监听；断线、旧 Context、停止与建连交错、插件崩溃、退出和重启均释放端口；重新连接后手动启动 |
| 关闭协调 | 持续监听不导致保存等待；取消工作区关闭保持原运行；关闭表单不关闭已启动规则 |
| 统计与检查 | 已知大小流量只计一次，部分失败仍有计数；本地监听成功但目标失败的检查必须失败 |
| 有界并发 | 慢协商、慢目标、并发超限和无响应插件时内存/任务有界，停止不被控制队列长时间阻塞 |
| 五目标实际包 | Windows x86_64/ARM64、Linux x86_64/ARM64、macOS ARM64 原生包真实转发、停止和退出；不能只验证编译 |

复用当前格式、类型检查、Rust 测试、脚本测试及终端/文件集成测试。新增 SOCKS 状态机测试、网络运行集成测试、弹窗/移窗 UI 回归与包内真实流量验收；这些测试验证实际行为，不只比较方法名或静态页面字符串。

插件标签沿用 `plugin-network-proxy-v<版本>`，构建使用 `node scripts/package-plugin.mjs --plugin network-proxy`。核心只发布新增通用能力及来源入口，安装包不带插件，也不依赖插件构建成功。先提供支持能力的核心，再发布对应插件；独立构建和发布，不增加全平台联动状态机。

实际包验收扩展现有 `remote-integration.yml` 及 `validation/remote_plugins.rs`，允许现有终端/文件验收继续独立运行；网络验收可选择额外的独立插件包及运行 ID，不让未提供网络包的旧流程失效。正式发布前分别完成五目标业务验证，不将编译成功写成验收通过。

实现入口与真实测试已落地；尚未创建网络插件的正式 Release。Windows 本机结果与五平台验收分开记录，不用本机通过代替其他目标验证。
