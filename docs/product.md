# SoDeck 产品定义

## 一句话定义

SoDeck 是一个面向运维人员的远程服务器工作台。它把服务器连接、文件、终端和网络通道统一到一个桌面应用中，同时让 Docker、NetBird 等能力以插件方式安装和演进。

## 用户和场景

主要用户是需要管理多台 Linux 服务器的运维人员、开发运维人员和小型团队管理员。典型任务包括：

1. 选择一台服务器并建立连接。
2. 查看或编辑远程文件。
3. 打开交互式终端并执行命令。
4. 查看 Docker 容器、镜像和日志。
5. 查看 NetBird 状态和节点信息。
6. 建立本地端口转发、远程端口转发或 SOCKS 代理，访问服务器所在网络中的服务。

## 核心原则

- 核心稳定，具体功能插件化。
- 任何高权限动作都能看见、能停止、能审计。
- 先保证单机可用和可恢复，再扩展插件生态。
- 插件不能绕过核心的连接、凭据和网络权限模型。

## MVP 范围

### 必须完成

- 保存和选择 SSH 服务器连接配置。
- 使用 SSH 建立会话并显示连接状态。
- 终端插件：创建、关闭和重连 PTY 会话。
- 文件插件：浏览目录、上传、下载、创建、重命名、删除和编辑文本文件。
- 核心网络能力：本地端口转发和动态 SOCKS5 代理；默认只监听 `127.0.0.1`。
- 插件管理：发现、安装、启用、停用、升级、卸载，并显示权限。
- 本地审计：记录连接、命令会话、文件操作和网络通道的开始与结束。

### 第二阶段

- Docker 插件：容器、镜像、日志、启动和停止。
- NetBird 插件：状态、节点、路由和常用操作。
- 远程端口转发和反向连接。
- 插件签名校验、更新源和团队分发。
- 多用户策略、集中审计和共享连接配置。

### 暂不承诺

- 一开始支持所有远程协议。
- 一开始允许插件拥有任意本机权限。
- 一开始提供完整的脚本编排平台。
- 一开始把所有厂商 CLI 的差异隐藏起来。

## MVP 验收标准

- 用户可以添加一台 SSH 服务器，在 30 秒内建立连接并看到清晰的失败原因。
- 用户可以在终端执行命令、调整大小、发送 Ctrl-C，并正确关闭会话。
- 用户可以浏览远程目录、编辑一个文本文件并保存，重新打开后内容仍然正确。
- 用户可以启动一个本地 SOCKS5 代理，使用代理访问服务器可达的地址，并能从界面停止代理。
- 停用终端插件不会影响文件插件和核心连接；插件进程崩溃时核心能显示错误并允许重启。
- 每项连接、文件和网络操作都能在审计记录中找到时间、目标、插件和结果。
