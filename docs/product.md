# SoDeck 产品定义

网络功能按 [网络隧道设计](plan-network-proxy.md) 提供固定 TCP 转发、SOCKS5 代理和按服务器管理的规则。默认右侧收起，编辑使用可滚动的宿主弹窗；显示实际入口、连通性检查和本次运行流量。核心网络原语与外置插件分别交付，规则启停立即生效，插件启停及升级继续在重启后生效。断线后手动重新启动，HTTP 代理后续再接；五平台实际包验证进度见设计文档。

当前版本 v0.6.0 已接入真实终端/文件插件、SFTP、分块正文桥和服务器/插件业务流量。核心与两个独立插件已正式发行，验收与限制以 [实施记录](implementation-remote-plugins.md) 为准；下文版本段落保留历史范围。

本轮范围为：[混合多层跳板、真实终端、文件查看/单文件下载/小文本修改及按服务器和插件统计带宽](plan-remote-workbench.md)。这些能力已进入源码；核心与终端、文件插件分别独立发行。带宽提供真实 socket 总量和插件有效载荷，未实现逐跳分摊。

代码整改第一批完成插件控制通信的模块拆分、有界双向请求分派、停止取消和错误区分，第二批实现真实连接，第三批接入正文桥和终端/文件插件；现有 UI 宿主继续兼容。连接的实际范围与验证见 [连接实施记录](implementation-connections.md)。

## 已发行基础：混合连接与组件宿主

v0.5.2 补齐官方插件首次在线安装：在设置的插件管理中查看固定官方来源，点击后自动下载本机版本、解压并注册，重启启用。该版本的 Hello 和组件交互示例只供验证基础能力。v0.6.0 登记真实终端和文件的独立来源，两个插件各自以 0.1.0 正式 Release 分发，可在线安装。
在一体化无独立标题栏工作台、日志和重要消息基础上实现核心与插件在线更新。插件管理位于右上角设置，启用与关闭通过重启生效。核心应用版本唯一来源为 `src-tauri/tauri.conf.json`。Docker、NetBird 和用户创建网络转发仍待实现；本轮不扩展为文件上传、删除或批量管理。

v0.2.0 已发布核心与插件在线更新。v0.2.1 新增旧版多巴胺主题：设置 → 外观即时切换、保存并在重开后恢复；升级保留当前外观偏好，仍提供跟随系统、浅色与深色。色板沿用旧版奶油底、粉色导航、黄色主动作和选中、薄荷绿点缀，2px 深色轮廓且无装饰阴影。插件协议保持 [API v1](plugin-api.md)，更新流程见 [在线更新实施计划](plan-online-updates.md)。

v0.3.0 实现核心服务器与 SOCKS5 代理目录：沿用旧版表单，支持增删改查、复制、搜索、分组与有序的 SSH/SOCKS5 混合多层路径。该版本只管理资料，不建连、不探测在线状态。用户选择记住的 SSH/代理密码及私钥口令直接在本机文件保存、不加密，不接系统凭据库。详见 [服务器管理设计方案](plan-server-management.md)。

## 一句话定义

v0.4.0 实现 [服务器 Tab 与可拆合工作区](plan-server-workspaces.md)：核心维护唯一归属和固定会话上下文，支持顶部排序、原生独立窗口、菜单移出/返回、左右组件空槽和宽度。移动先等待目标就绪，再一次性交接；关闭子窗口只释放该窗口工作区。该版本尚未实现 SSH 和真实组件，正式界面不提供模拟连接。Wayland 全局坐标受限时使用菜单移动；原生拖拽和混合 DPI 的人工验证范围见版本记录。

SoDeck 是一个面向运维人员的远程服务器工作台。它把服务器连接、文件、终端和网络通道统一到一个桌面应用中，同时让 Docker、NetBird 等能力以插件方式安装和演进。

## 用户和场景

v0.5.0 按已确认的 [组件与核心 UI 交互设计](plan-component-ui.md) 提供 UI 宿主：左右工具条、侧栏、中央混合 Tab、默认打开、资源去重、布局偏好、保存关闭和跨窗重挂载。外置 UI 示例插件验证文件列表默认展开、终端默认一个、网络转发默认隐藏，不包含真实业务。SSH/SOCKS5 混合连接由核心提供，五目标发行与验证见 [v0.5.0](releases/v0.5.0.md)。

主要用户是需要管理多台 Linux 服务器的运维人员、开发运维人员和小型团队管理员。典型任务包括：

1. 选择一台服务器并建立连接。
2. 查看或编辑远程文件。
3. 打开交互式终端并执行命令。
4. 查看 Docker 容器、镜像和日志。
5. 查看 NetBird 状态和节点信息。
6. 建立本地端口转发、远程端口转发或 SOCKS 代理，访问服务器所在网络中的服务。

## 核心原则

- 核心稳定，具体功能插件化。
- 第一版同时支持 Windows x86_64 / ARM64、Linux x86_64 / ARM64 和 Apple Silicon macOS ARM64。核心独立分发，业务插件全部外置。
- 插件按可信扩展运行，不实现插件授权、权限清单、审批或角色权限系统。
- 插件运行状态可见，日志统一记录，重要消息由核心展示。
- 先保证单机可用和可恢复，再扩展插件生态。
- 插件优先复用核心的连接和网络服务，避免重复实现通用基础设施。
- GitHub 打包和分发属于产品交付要求：核心与插件各自版本化，能在干净的 CI 环境构建，用户从 Releases 下载即可安装。

## MVP 范围

### 必须完成

- 保存和选择 SSH 服务器连接配置。
- 使用 SSH 建立会话并显示连接状态。
- 终端插件：创建、关闭和重连 PTY 会话。
- 文件插件：浏览目录、上传、下载、创建、重命名、删除和编辑文本文件。
- 核心网络能力：本地端口转发和动态 SOCKS5 代理；默认监听 `127.0.0.1`，可配置其他绑定地址。
- 核心安装和升级：标准发行包首次安装，设置中检查、下载、安装并重启，保留用户数据和外部插件；Linux 应用内升级使用 AppImage，DEB 使用系统包管理器。
- 插件管理：从外部目录添加插件，保存启用状态，启用/关闭在重启后生效。插件独立检查和下载更新，启用项在重启后切换，完全关闭的插件更新后保持关闭。新版初始化失败恢复旧程序，数据保留。
- 无插件也能正常启动核心进入工作台，插件管理统一在右上角设置内，不把终端等业务插件作为启动或打包前提。
- 插件日志：核心记录生命周期、异常退出并接收插件日志，支持按插件、级别和时间筛选。
- 重要消息：插件可以调用核心发布成功、提示、警告或错误消息，核心统一在消息中心展示，并按消息的重要程度显示即时提示。
- GitHub 交付：普通提交运行相关检查，核心版本标签生成五目标核心发行包并上传 Release；插件按需单独生成可下载目录归档，不与核心版本或发布流程联动。详见 `distribution.md`。

### 第二阶段

- Docker 插件：容器、镜像、日志、启动和停止。
- NetBird 插件：状态、节点、路由和常用操作。
- 远程端口转发和反向连接。
- 日志导出、消息聚合和共享连接配置。

### 暂不承诺

- 一开始支持所有远程协议。
- 一开始提供完整的脚本编排平台。
- 一开始把所有厂商 CLI 的差异隐藏起来。

## 日志与重要消息

普通日志服务于问题排查，例如连接重试、任务耗时、插件内部错误。重要消息服务于用户感知，例如上传完成、容器意外退出、网络隧道断开。插件通过两个不同接口表达意图，普通错误日志不会自动变成弹窗。

核心负责标注消息来源、保存本地历史、提供筛选和跳转到相关插件的入口。高频重复消息需要合并，日志文件需要轮转和容量限制。第一版不引入独立消息中间件，也不要求记录每条终端输入或全部文件内容。

## MVP 验收标准

- 用户可以添加一台 SSH 服务器，在 30 秒内建立连接并看到清晰的失败原因。
- 用户可以在终端执行命令、调整大小、发送 Ctrl-C，并正确关闭会话。
- 终端支持平台约定的复制/粘贴和本地右键菜单；Windows 有选区 Ctrl+C 复制、无选区仍中断。粘贴不自动执行命令，延迟读取不跨视图或连接输入。工作台三主题共用页签、工具栏和底栏规则，多巴胺粗描边不改变终端尺寸。范围与验收见 [工作台实施记录](implementation-workbench-design.md)。
- 用户可以浏览远程目录、编辑一个文本文件并保存，重新打开后内容仍然正确。
- 文件侧栏支持多分支目录树、路径定位、目录独立分页和键盘操作，单击选中、双击文件进入中央编辑器；切换服务器、隐藏侧栏和移窗后恢复同一工作区的导航状态。视觉与范围见 [文件树设计](plan-file-tree.md)。
- 用户可以启动一个本地 SOCKS5 代理，使用代理访问服务器可达的地址，并能从界面停止代理。
- 插件启用、关闭、启用项升级通过应用重启统一生效，重启会结束全部连接和任务；插件异常退出后错误与日志可见。
- 测试插件写入一条日志后，用户能在日志面板按插件找到它，并看到时间和级别；普通日志不会弹出通知。
- 测试插件发布一条重要消息后，用户能在核心消息中心看到标题、内容、级别和来源；重启应用后仍能查看已保存的历史。
- 插件异常退出后仍能查看已写入核心的日志，并能通过核心管理界面重启插件。
- 五个系统与架构组合的干净 CI Runner 检出代码后能按已提交的工具链、依赖和构建入口生成发行包，无需开发者手工准备文件；在各自未配置 Rust、Node.js 的测试环境中能启动。Linux 按发布规范声明的发行版和系统库基线验证。
- 核心能够在不安装任何业务插件时启动，覆盖升级后配置、消息历史和外部插件目录保持。
- 外置插件在重启后按配置加载并写日志、发布重要消息，退出或重启后释放进程、端口和会话资源。验证重点放在实际流程，不建立穷举版本兼容矩阵。
- 核心发布包含对应平台的发行包和简短版本说明；插件单独下载和加载，不要求重新发布核心，也不阻塞核心打包。
