# 主题与颜色定义规范

更新日期：2026-10-25 · 修订：r1 · 文档就绪：可评审
依据：[产品 P-29](../product.md) · 关联：[UI 规范](ui.md)、[F-CORE-008](../core/workbench-interaction.md)、[T-006](../tasks/T-006-workbench-interaction.md)

## 1. 颜色完全独立

用户明确要求：“颜色完全抽出单独定义，后面更换主题有用。”应用控制的颜色必须从布局、组件和业务逻辑中完全分离，主题定义是唯一维护来源。更换配色只更换主题数据，不逐个修改核心或插件组件。

T-006 r2 已获实施授权，默认采用石墨深色；主题选择设置、用户导入/编辑、自动跟随系统和运行时切换入口不纳入本次。确认和实际验证统一见 T-006，历史颜色补充指令本身只确立分离原则。

## 2. 定义结构与使用边界

采用独立主题数据 `themes/graphite.json` 与公开契约 `contracts/presentation-v1.schema.json`；核心 `theme.rs` 校验，SDK `presentation.ts` 映射，具体实现见[实施方案](../technical/workbench-interaction-implementation.md)。主题定义包含版本、主题 ID、明暗类型和完整颜色映射。

- **基础色板**：具体 HEX/RGB/HSL/带透明度颜色只在主题定义内出现。
- **语义令牌**：按用途命名，如页面/面板/浮层背景、主/次文字、边框、强调、焦点、成功/警告/错误；组件不使用 `darkBlue` 之类颜色名表达职责。
- **状态颜色**：hover、pressed、selected、disabled、拖动预览、选区、遮罩、阴影、滚动条、链接及破坏性操作状态均独立定义。不能只抽离常规背景，却在状态 CSS、SVG、Canvas、原生外框或 JS 中留下另一套色值。
- **终端颜色**：默认前景/背景、光标、选区、ANSI 16 色及扩展调色策略由主题数据和统一适配层定义；终端组件只映射令牌到 xterm。远端程序显式输出的真彩色、图片等属于内容，不能为了“统一主题”改写远端内容。
- **派生与回退**：透明度、混色及颜色派生集中在主题定义/解析层，组件不得自行推导新的主题颜色；缺失令牌的回退也由主题层提供，不在组件写固定兜底色。
- **资源与系统**：可着色图标使用语义令牌/当前文字色，应用自行绘制的窗口控制同样接入主题；操作系统原生控件由平台适配层使用系统主题/高对比色，不在业务组件仿制另一套固定颜色。固定图像本身的像素颜色属于素材。

布局、间距、字号、交互逻辑不随颜色文件改变。公共颜色由核心主题模块管理；插件通过公开协议消费同一份解析结果，不引用核心私有样式，也不复制主题文件。未来插件需专用语义色时通过公开扩展约定增加，不在插件组件内绕过主题。

## 3. 默认配色建议

以下保留初始设计的基础值说明；全部实际色值及完整状态、终端和回退映射以 `themes/graphite.json` 为唯一维护来源，本表不作为运行时兜底。

| 语义 | 推荐值与用途 |
| --- | --- |
| `canvas` / `terminalBackground` | `#17191D` 外壳底色 / `#111316` 终端正文 |
| `surface` / `elevated` | `#202329` 导航与表单层 / `#292D34` 菜单与对话框层 |
| `text` / `secondary` / `muted` | `#E8EAED` 正文 / `#B1B6C0` 次要信息 / `#8C929D` 辅助说明 |
| `border` / `accent` / `focus` | `#373C45` 结构边界 / `#84AEED` 强调 / `#94BAF3` 焦点 |
| `success` / `warning` / `error` | `#86C69A` / `#E4BA76` / `#E59696`，搭配文字或图标 |

每个主题覆盖相同的语义契约，不能以组件分支判断具体主题 ID 决定配色。对比度、系统高对比与减少透明规则引用 UI 规范，系统偏好通过主题解析/平台适配处理。

## 4. 加载、分发与异常

核心统一加载并校验主题，输出带主题 ID、契约版本和修订的完整只读快照。CSS 变量、JS/xterm 参数及应用绘制的原生颜色都从该快照生成。主窗口、工作区窗口、独立终端与后来挂载/恢复的插件表面读取同一有效主题，不能各自决定默认颜色。

无效版本、缺失必要令牌或非法颜色应在应用前拒绝，保留上一份有效主题；首次加载失败使用主题模块内完整的默认主题并提供可诊断原因。不能只更新一半颜色，或让某个插件掉回自己的硬编码色。颜色定义不包含业务状态、凭据或会话句柄。

本轮只要求独立定义、统一加载与分发，不承诺已有运行时主题切换能力。未来增加主题选择/热切换时复用此基础，另细化用户设置、通知、持久化与失败恢复。
