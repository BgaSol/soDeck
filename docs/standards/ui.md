# UI 规范

更新日期：2026-10-29 · 修订：r23 · 状态：公共规则基线；各任务增量依所属任务记录确认与结果。

## 1. 职责与适用范围

适用于核心外壳、插件面板、独立窗口及公共组件。用户决定视觉和交互方向，AI 负责实现、补齐状态和验证。各功能的页面布局、操作与状态写在其功能规格中，并引用本规范。

新规则或设计变化先按[文档更新流程](../documentation-workflow.md)更新本规范和受影响功能，本次方案经用户确认后再修改界面代码。既有确认范围内的实现不增加逐步确认；方案变化是否重新确认，统一按该流程判断。

### 1.1 必须使用 apple-design

**所有 UI 设计必须读取并使用 `apple-design` 技能。** 此要求覆盖核心外壳、插件面板、独立窗口、公共组件和原型界面的视觉、布局、交互及动效设计；对应实现与设计审查同样依据该技能和已确认规格。

- 开始相关工作前，从当前会话的技能清单定位并读取 `apple-design` 的 `SKILL.md`，按需读取其引用资料；不能仅凭技能名称或记忆代替实际使用。
- 在本次 UI 方案中说明适用的设计原则及具体落点，例如即时反馈、空间一致性、清晰的层次与排版、可中断且克制的动效、可访问性；相关行为写入该功能的测试流程，适用时覆盖减少动态效果、对比度和键盘焦点。
- 结合目标平台适配系统字体、窗口操作、鼠标、键盘和输入法行为。技能中的参数、库和代码示例作为设计参考；本项目的具体视觉参数及技术采用仍由相应规格和选型文档确定。

技能使用纳入既有的文档与方案确认流程：先完善设计和测试流程，经用户确认后再编写 UI 或交互原型代码。临时界面同样使用该技能，并按实验范围明确设计深度。

## 2. 公共视觉基线

颜色、字号、间距和组件规则使用统一来源，插件通过版本化主题协议接入。下面的项目须在对应界面开始编码前明确适用值或设计参考，当前不虚构最终参数。

按用户最新明确要求 P-29，**全部应用配色从组件/布局/业务逻辑抽离，单独维护主题定义**。颜色的唯一规格来源为[主题与颜色定义规范](theme.md)，含状态色、终端色、透明度/阴影、默认回退及跨表面分发；本文维护排版、尺寸和交互规则，不再复制具体色值。

公共基线随即将实现的界面逐步收敛，不要求先完成整个组件库。插件架构原型可采用范围明确的临时界面，先写清验证所需布局、状态和操作；临时值不自动成为产品视觉规范。

| 项目 | 需要确定的内容 | 当前状态 |
| --- | --- | --- |
| 主题与颜色 | 主题范围、背景层级、文字、边框、强调色、语义色和对比要求 | 待设计 |
| 字体与排版 | 中英文及等宽字体、字号、行高、字重和截断规则 | 待设计 |
| 尺寸与布局 | 间距、密度、圆角、边框、工作区布局、窗口和面板尺寸规则 | 工作台结构见 F-CORE-004；视觉尺寸待设计 |
| 公共组件 | 按钮、表单、列表、表格、标签、菜单、对话框和通知的状态与行为 | 随首条流程建立 |
| 动效 | 适用场景、反馈时机、持续时间及减少动态效果的处理 | 涉及后先确定 |
| 插件主题协议 | 令牌名称、注入方式、变更通知及兼容规则 | 待技术验证 |

公共组件已存在时优先复用；出现新变体先更新组件规则，不能在插件内各自解释同一交互。功能专属展示规则留在功能规格，不把业务含义放进全局组件。

### 2.1 T-006 统一视觉方案

用户要求统一样式与颜色；首轮采用中性石墨色和单一蓝色强调。以下值是随 T-006 r2 获确认的 [F-CORE-008](../core/workbench-interaction.md) 基线，取代该任务范围内上表的“待设计”。实现与验证见[任务结果](../tasks/T-006-results.md)，不增加主题切换或个性化配置范围。

| 语义令牌/规则 | 推荐值与用途 |
| --- | --- |
| 配色 | 使用[独立主题定义](theme.md)；所有普通/交互/异常状态均引用语义令牌，组件不写具体颜色 |
| 字体与层级 | Windows 系统字体 `Segoe UI, Microsoft YaHei, system-ui`；界面正文/Tab 13px、说明至少 12px、对话框标题 18px；常规行高 1.4–1.5，选中项 600、正文 400；终端继续默认 14px 等宽字体 |
| 间距与尺寸 | 4px 基础步长，常用 8/12/16/24；顶部约 44px、内部 Tab 36px、底部状态 24px、工具轨 44px；按系统文字缩放扩展，不固定高度裁字 |
| 控件 | 图标统一线性风格、常规 16px；点击区至少 28×28px；窗口系统按钮遵守 Windows；按钮圆角 6px、菜单 8px、对话框 12px |
| 选中与悬停 | 选中 Tab 同时用较亮文字、字重和稳定底色/边界表达；悬停只小幅提亮，不改变宽度；焦点用清楚的 2px 轮廓 |
| 材质与动效 | 常驻区域不使用装饰渐变和阴影，浮层使用轻阴影；按下立即反馈，短淡化约 100–140ms，不锁住输入；拖动延续直接跟随、可取消机制 |
| 可访问性 | 普通文字对比度至少 4.5:1，关键控件/焦点至少 3:1；高对比用系统色/实边，减少透明时实色，减少动态时即时切换；令牌需实际测量组合后验证 |

终端 ANSI 调色板属于输出语义，保持不同颜色可辨；终端背景、默认前景、选区与光标与公共主题协调。插件通过版本化公开呈现协议接收同一套语义令牌；不能从外壳私有 CSS/React 导入，也不能各自另配一套近似色。

本轮清理适用于现有主/子窗口、单终端、选择器、编辑与认证、插件/资源/调用记录页及错误/空态。Tab 文本与更多按钮规则、菜单关闭和长名称策略以 F-CORE-008 为唯一来源。实际视觉与原生验证对应 UX-02/03/05/06、IN-07，颜色独立及替换验证对应 UX-10；本节不能替代真实渲染检查。

### 2.2 T-011 整体样式方案

本节与[双主题色板](theme.md#12-t-011-双主题配色方案)共同用于 [T-011](../tasks/T-011-appearance.md)，确认后在本次覆盖界面替代§2.1的单一石墨深色、控件尺寸及“常驻区域无装饰渐变/阴影”规则；不改变既有Tab/输入/窗口业务。T-011 r1已获实施确认；实现及验证状态见该任务结果。

| 规则 | 本次具体落点 |
| --- | --- |
| 整体层次 | 基础背景→文件/导航面板→内容→浮层四层。主要工作内容保持实色，侧栏通过轻微明暗区分；浮层轻阴影，避免每行/每按钮都浮起 |
| 字体 | `Segoe UI, Microsoft YaHei, system-ui`；正文/Tab13px、辅助12px、对话框标题18px、空态标题24px；正文行高1.45，标题1.2，正文400/选中600。终端继续14px等宽默认字体和独立字号功能 |
| 密度 | 4px步长，8/12/16/24常用间距；服务器栏44px、内部Tab36px、工具轨44px、状态栏24px为基准。用最小高度和文字缩放适配，不用固定高度裁字 |
| 圆角 | 按钮/输入/Tab8px、菜单10px、对话框16px；文件行4px或无角以连续阅读为先。窗口原生裁切遵守Windows能力 |
| 点击区 | 普通按钮最小32px高，图标按钮至少28×28px；图标常规16px，工具轨18～20px，统一Lucide线性样式。原生窗口按钮遵循Windows尺寸 |
| 选中与焦点 | Tab用稳定底色、字重及细强调线；树行用背景+字重，不只依靠颜色。focus-visible为2px轮廓，键盘和高对比都可辨；hover不改变宽度 |
| 表单/对话框 | 输入36px基准高度，标签与帮助文字分组；弹窗内边距24px、窄窗16px，头/体/底部层次统一；服务器选择与外观选择卡片保留文字，不只展示图形 |
| 文件布局 | 目录行28px基准、大小列等宽数字；按根字体测量实际行高并统一驱动虚拟列表、滚动和命中区域。标题/路径和详情可滚动，不遮挡工具栏 |
| 终端布局 | 正文无渐变、无透明、无阴影；外框/状态/错误提示与公共控件一致，切主题不改字体/行高/PTY尺寸，也不重建xterm |
| 材质 | 同文档工具栏/浮层可用轻微半透明及12～20px模糊；底层没有可见内容时使用实色。禁止依赖WebView之间的backdrop-filter，不对承载原生插件表面的祖先施加transform/filter |
| 动效 | 按下立即反馈；hover/颜色100～140ms，浮层opacity120～180ms，均可中断。主题文档整份颜色同步应用，避免独立插值破坏对比。现有拖动保持直接跟随；本次无新增惯性手势，无需为装饰引入弹簧库 |
| 无障碍 | 普通文字4.5:1、关键边界/焦点3:1；减少动态关闭空间动画，减少透明采用实底，forced-colors使用系统语义与实边。保留IME、Esc、Tab、窗口菜单及键盘等价入口 |

尺寸可在相同密度和布局约束下因字体/平台测量小幅调整；改变两层导航、窗口行为或终端/文件业务需按变更流程另行处理。颜色仍唯一来自主题模块，公共排版/控件CSS由公开`@sodeck/ui`提供；插件专属布局留在插件，不引用外壳私有class或组件。

检查来源：F-CORE-012 AP-01～09、F-TERM-002 TERM-THEME-01/02、F-FILES-001 FILES-THEME-01/02；实际截图与结果只存T-011。T-006的历史验证仍适用于原版本。

### 2.3 T-012 多巴胺样式profile

颜色唯一来源见[主题规范 §6](theme.md#6-t-012-多巴胺主题色板提案)，视觉对应与逐页面图稿见[多巴胺设计](../design/dopamine.md)。本profile不替代现有soft-light/soft-dark的视觉规则，仅在第三主题选中时生效；高对比优先于所有profile。

公共UI统一管理2px控件/主要卡片轮廓、无投影、8/12/16px圆角、600控件标题/700弹窗标题、圆头图标笔画及按下底色反馈。多巴胺不偏移按钮视觉层，命中盒、Tab拖动目标或原生WebView祖先始终保持稳定。渐变/玻璃关闭，正文保持奶油实色背景。

保留T-011基准尺寸和文件28px行高；盒尺寸包括边框预算，切换风格不引起PTY额外resize。文字放大仍重新测量布局，不能为满足“不resize”阻止用户改变窗口/字号。三主题预览必须分别呈现各自profile；关闭/禁用/加载/错误/焦点均按设计稿测试。应用按钮和下拉跨三主题重设计，统一入口尺寸与菜单分组，浅/深保留细边柔影，多巴胺使用粗边无投影；行为、专用浮层和AM测试见[F-CORE-008 §10](../core/workbench-interaction.md#10-t-012-应用入口与菜单重设计)。终端/Tab右键及Windows系统菜单的外观能力例外见F-CORE-012 §7。

apple-design适用：pointer-down即时反馈、交互可中断、稳定命中区与焦点返回、系统排版/缩放、减少动态及高对比；不强行加入玻璃或新惯性手势。验收来源DP-01～08、BR-01～05、AM-01～05及两插件专属用例；实施与真实检查记录见T-012结果，不将测试通过视为用户验收。

### 2.4 T-012 公共设计系统与插件样式边界

本节来自用户2026-10-26“样式提前定义、插件少写样式并以功能为主”的要求，已获[T-012 r3](../tasks/T-012-dopamine.md)实施确认；代码组织、组件清单和迁移顺序见[公共设计系统代码方案](../technical/design-system-implementation.md)。三主题外观按最新设计稿r3，功能职责与插件独立更新不变。

1. 公共设计参数提前定义排版、间距、尺寸、描边、圆角、阴影几何、图标笔画、焦点和动效；颜色唯一来源仍为主题目录。普通/悬停/按下/焦点/禁用/加载/选中/错误及状态组合由公共组件统一处理，插件不得各自补一套。
2. `@sodeck/ui`提供基础控件、语义容器和当前产品所需组合模式；外壳与插件均优先使用。组件接收值、语义variant/tone/size、回调与内容插槽，不调用SDK、不订阅业务状态、不接受业务命令后自行请求。
3. 插件负责页面组合、业务状态、数据和交互流程。通用视觉迁入公共UI；虚拟滚动定位、xterm适配和独有内容布局可保留少量局部样式，使用公共设计参数。是否提取按真实复用和职责判断，不以CSS行数或“零样式”作为硬门槛。
4. 公共组件采用显式`sd-`作用域和固定CSS层序；插件不导入外壳私有CSS、不按主题ID分支、不重写公共变量或组件内部选择器。新需求优先增加语义variant或公共组件，特殊布局例外须说明来源及测试。
5. 明暗与多巴胺切换只变外观，预留一致控件盒尺寸；原生WebView祖先不施加transform/filter。字号放大与真实resize仍重新测量。树行高等测量结果须同时供布局、虚拟滚动和命中使用。
6. 默认前置当前已知组件及其状态，不一次实现所有未来插件UI；新增页面先用现有组件组成，必要的新规则先补本次设计/测试。UI代码随插件独立构建，不通过宿主动态换掉旧包组件。

无障碍集中实现：IconButton有名称，Field有label/help/error关联，Dialog有唯一标题/焦点管理，菜单有角色/键盘导航，控件不只以颜色表示状态。原生select选项弹层、终端供应商绘制与Windows系统表面保留平台边界；应用菜单按F-CORE-008 §10的专用浮层要求执行。首屏、视觉、插件样式例外和兼容验收统一见[F-CORE-012 §8](../core/appearance.md#8-t-012-公共设计系统与复用测试)。

### 2.5 T-015 控件边界与反馈

本节为[T-015](../tasks/T-015-workflow-polish.md)可评审增量。输入/选择/组合密码框的焦点不改变外盒尺寸，在滚动容器边缘仍完整可见；优先内侧2px轮廓或等效内描边，确保与边界/底色对比，禁止通过去掉焦点解决裁切。字段错误与焦点叠加也只绘制一套清楚边界。实现归公共UI，组合框可使用公开variant，插件不私自重写内部选择器。

窗口控制使用独立公共变体和统一几何，hover/pressed不位移、不缩放；关闭保留危险色。加载指示统一尺寸/笔画，旋转只影响图标，减少动态提供静态状态；布局不随加载状态跳动。尺寸仍使用公共参数、颜色仅消费主题，三主题不改变命中尺寸。

apple-design落点：即时反馈、稳定空间关系、层次清楚、动效可中断、键盘可访问。原生表面祖先不做transform/filter；侧栏以同步几何为先，不能以装饰动画制造命中错位。详细验收分别引用SM-01、WB-UX-04、FT-UX-02、TN-06，不另建重复测试定义。

## 3. 每个功能必须说明的界面行为

T-026桌面交互增量提案：[F-CORE-030 r1](../core/desktop-interaction.md)统一宿主默认菜单/浏览器快捷行为，并保留现有业务菜单、文本编辑、IME与系统窗口操作。编辑菜单沿用Windows原生命令、可用状态与系统主题，作为既有原生菜单外观例外；不在各插件复制全局右键/键盘拦截。禁止用整页禁选择/禁复制或吞掉所有功能键实现“桌面感”。apple-design落点为熟悉的编辑/终端键位、稳定菜单锚点、可取消操作与焦点返回；三主题、系统缩放、高对比/减少动态及原生键盘覆盖见DI-02/03/04/07。此提案待[T-026](../tasks/T-026-desktop-interaction.md)确认，不改变其他任务的视觉与业务结果。

T-025公共表单增量提案：[连接首页代码方案§6](../technical/connection-home-implementation.md#6-公共ui与表单实现)在现有Field/InputGroup等基础上补PasswordField和SearchSelect，统一标签/帮助/错误关联、显示切换、加载/空/错误和键盘选择，不依赖SDK/目录服务。SSH跳板/代理/组只传值与回调；内联代理为section和显式按钮，不嵌套form。新页面只保留列宽/响应式/滚动等专用布局，公共状态/参数入UI包，颜色消费三主题令牌。若T-023已补页头/动作条则复用。apple-design落点为稳定位置、即时反馈、无焦点跳动、减少动态和高对比；CH-11/HCODE-10含实际渲染验证，当前仅设计。

T-024通用图表增量：[代码方案§7](../technical/server-monitor-implementation.md#7-ui趋势与公共设计系统)计划公共UI1.6提供SeriesChart/SeriesLegend，接受1～2条系列、真实标签、单位、nullable点和独立缺口；CPU/内存固定0～100轴，速率非负动态轴。紧凑/标准高度是公共变体，数字/焦点/键盘/表格替代集中实现；无SDK与业务请求。原TrendChart保留发送/接收兼容包装，通信图行为和颜色不变。主题别名来源见[主题T-024增量](theme.md#t-024通用系列颜色别名)，插件不写图表色值或改公共内部选择器。

apple-design沿用即时反馈、稳定排版、可中断交互、减少动态和多种输入方式：样本刷新不移动焦点/滚动、不连续aria-live播报，不对数字做滚动动画。测试由F-MON-001 MON-11及代码方案MCODE-08/09维护：单/双系列/缺口/固定轴、原通信参数兼容、三主题/200%文字/高对比/减少动态与Windows真实表面；清理恢复显示设置。此为待确认设计，不改写旧组件实测。

T-019待确认公共增量：MetricPair、TrendChart、ChartLegend、DataCoverage只接受显示数据/单位/回调，无SDK依赖。每图≤1200点，发送实线/接收虚线，缺口断开、峰值粒度可见，图形有键盘时间点/文字表格等价；每秒变化不持续aria-live播报。数字使用tabular-nums且盒宽稳定；普通图线2px、焦点3px。几何进入公共foundation/profile，颜色唯一来源为[主题§9](theme.md#9-t-019-通信图表语义颜色待确认)。[界面r2](../design/communication-monitor.md)与[代码方案r1](../technical/communication-monitor-implementation.md)维护原生单实例工具窗、查询/取消/焦点及CM-07/MCODE-10/12，不在插件私写图表颜色。

T-018公共容量展示：`@sodeck/ui`提供只依赖已用量/总量的容量分级与整行填充，集中定义正常（<80%）、偏高（80%～<90%）、紧张（≥90%）规则；精确整数比较，避免先舍入造成跨级。普通任务Progress不套容量规则。TreeRow可组合容量背景，整行从左端填充，缩进仅影响内容；保留选中轮廓、字重及可见键盘焦点。比例和等级同时提供文字说明/可访问meter，0%不加最小宽度，总量0或非法数据不产生meter。公开组件无SDK/业务读取；插件只提供数值和内容，不自行判断级别或定义配色。三主题颜色及高对比回退见[主题§8](theme.md#8-t-018-公共容量等级颜色)，功能测试见[F-FILES-001 FC-01～05](../plugins/files/features/server-file-tree.md#t-018正式整行容量与公共等级)。

T-017公共组合增量：身份摘要、可选择的等宽值/操作块、带独立行操作的资源条目、空态/状态栏、键盘可展开分区由公共UI提供。r2按用户指定的文件面板基准收敛：面板Surface用平面变体、资源列表复用文件行hover/选中边界和密度，状态栏直接复用默认实底款，入口值框可使用控件描边。无业务请求；标题/说明/状态/回调由消费者传入。三主题只换颜色与既有profile，几何与命中一致；颜色用现有语义令牌，多巴胺不增加投影。身份确认与隧道各自测试见[T-017](../tasks/T-017-identity-tunnel-ui.md)，不重写其他页面外观。

本节承接§2.4的公共组件，业务文档只补自身差异和状态，不重复定义通用控件的颜色、圆角或交互反馈。

- 入口、主要操作、布局和当前服务器或工作区上下文。
- 初始、加载、成功、空数据、失败、禁用等适用状态；异步或长任务还需说明取消、超时和恢复。

## 4. 插件与外壳

核心管理工作台框架，插件提供视图内容。核心拥有工作区切换、侧边工具入口与停靠、中央 Tab 和两个分屏区域、独立窗口、托盘、Tab/面板操作外框、焦点与布局持久化；插件拥有内容区、业务工具栏、业务状态与操作。每个插件可以提供多个视图，每个视图声明支持的展示方式和默认位置，用户在支持范围内移动。

T-006 适用覆盖：按产品 P-24、P-27，终端不再提供会话列表和左右/上下分屏。中央统一为单 Tab 组，终端仅中央/独立窗口，具体规则与旧布局迁移见 F-CORE-008；上述双区域为 T-003/T-004 历史基线。公共停靠/窗口职责继续归核心，不改变架构边界。

按产品 P-20、P-21，窗口不另占一行顶部标题栏，服务器以顶部 Tab 呈现并支持新窗口与合并。本轮具体设计以 [F-CORE-006](../core/server-tabs.md) 为有效来源：服务器 Tab 与 Windows 控制同一行；保留系统标题元数据、原生拖动/缩放/贴靠和辅助技术；分清完整工作区窗口与单视图弹窗。T-004 已获方案确认，实际验证另见任务记录，不能将旧单视图结果当作新外壳验证。

详细边界、容器与迁移契约、关闭和恢复行为、功能测试以 [F-CORE-004：工作台、插件视图与窗口](../core/workbench.md)为有效来源，不在各插件重新设计一套停靠或窗口框架。插件自己的详细文档必须列出视图、工作区/App 作用域、支持位置、单/多实例、状态恢复及关闭规则。

收起、切换、移动和明确关闭分别表达；主窗口“×”按产品 P-18 收起到托盘，明确退出按 P-11 结束全部 App 资源。插件独立窗口与主窗口的关闭职责不得混淆，界面行为必须对应资源策略。移动不能只依赖拖拽，提供菜单或键盘路径并验证焦点恢复。

插件与外壳遵循相同的公共视觉和交互规则；插件专属布局和业务状态在自己的详细文档中定义。插件更新、安装和启停的具体交互分别遵循已确定规格，其中更新必须重启 App 后生效。
