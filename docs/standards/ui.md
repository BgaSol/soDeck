# UI 规范

更新日期：2026-10-25 · 修订：r8 · 状态：公共规则基线；T-006 已确认该基线，实际实现及验证以任务记录为准。

## 1. 职责与适用范围

适用于核心外壳、插件面板、独立窗口及公共组件。用户决定视觉和交互方向，AI 负责实现、补齐状态和验证。各功能的页面布局、操作与状态写在其功能规格中，并引用本规范。

新规则或设计变化先按[文档更新流程](../documentation-workflow.md)更新本规范和受影响功能，本次方案经用户确认后再修改界面代码。既有确认范围内的实现不增加逐步确认；方案变化是否重新确认，统一按该流程判断。

### 1.1 必须使用 apple-design

**所有 UI 设计必须读取并使用 `apple-design` 技能。** 此要求覆盖核心外壳、插件面板、独立窗口、公共组件和原型界面的视觉、布局、交互及动效设计；对应实现与设计审查同样依据该技能和已确认规格。

- 开始相关工作前，从当前会话的技能清单定位并读取 `apple-design` 的 `SKILL.md`，按需读取其引用资料；不能仅凭技能名称或记忆代替实际使用。
- 在本次 UI 方案中说明适用的设计原则及具体落点，例如即时反馈、空间一致性、清晰的层次与排版、可中断且克制的动效、可访问性；相关行为写入该功能的测试流程，适用时覆盖减少动态效果、对比度和键盘焦点。
- 结合目标平台适配系统字体、窗口操作、鼠标、键盘和输入法行为。技能中的参数、库和代码示例作为设计参考；本项目的具体视觉参数及技术采用仍由相应规格和选型文档确定。

技能使用纳入既有的文档与方案确认流程：先完善设计和测试流程，经用户确认后再编写 UI 或交互原型代码。临时界面同样使用该技能，并按实验范围明确设计深度。

## 2. 公共视觉基线

颜色、字号、间距和组件规则使用统一来源，插件通过版本化主题协议接入。下面的项目须在对应界面开始编码前明确适用值或设计参考，当前不虚构最终参数。

按用户最新明确要求 P-29，**全部应用配色从组件/布局/业务逻辑抽离，单独维护主题定义**。颜色的唯一规格来源为[主题与颜色定义规范](theme.md)，含状态色、终端色、透明度/阴影、默认回退及跨表面分发；本文维护排版、尺寸和交互规则，不再复制具体色值。

公共基线随即将实现的界面逐步收敛，不要求先完成整个组件库。插件架构原型可采用范围明确的临时界面，先写清验证所需布局、状态和操作；临时值不自动成为产品视觉规范。

| 项目 | 需要确定的内容 | 当前状态 |
| --- | --- | --- |
| 主题与颜色 | 主题范围、背景层级、文字、边框、强调色、语义色和对比要求 | 待设计 |
| 字体与排版 | 中英文及等宽字体、字号、行高、字重和截断规则 | 待设计 |
| 尺寸与布局 | 间距、密度、圆角、边框、工作区布局、窗口和面板尺寸规则 | 工作台结构见 F-CORE-004；视觉尺寸待设计 |
| 公共组件 | 按钮、表单、列表、表格、标签、菜单、对话框和通知的状态与行为 | 随首条流程建立 |
| 动效 | 适用场景、反馈时机、持续时间及减少动态效果的处理 | 涉及后先确定 |
| 插件主题协议 | 令牌名称、注入方式、变更通知及兼容规则 | 待技术验证 |

公共组件已存在时优先复用；出现新变体先更新组件规则，不能在插件内各自解释同一交互。功能专属展示规则留在功能规格，不把业务含义放进全局组件。

### 2.1 T-006 统一视觉方案

用户要求统一样式与颜色；首轮采用中性石墨色和单一蓝色强调。以下值是随 T-006 r2 获确认的 [F-CORE-008](../core/workbench-interaction.md) 基线，取代该任务范围内上表的“待设计”。实现与验证见[任务结果](../tasks/T-006-results.md)，不增加主题切换或个性化配置范围。

| 语义令牌/规则 | 推荐值与用途 |
| --- | --- |
| 配色 | 使用[独立主题定义](theme.md)；所有普通/交互/异常状态均引用语义令牌，组件不写具体颜色 |
| 字体与层级 | Windows 系统字体 `Segoe UI, Microsoft YaHei, system-ui`；界面正文/Tab 13px、说明至少 12px、对话框标题 18px；常规行高 1.4–1.5，选中项 600、正文 400；终端继续默认 14px 等宽字体 |
| 间距与尺寸 | 4px 基础步长，常用 8/12/16/24；顶部约 44px、内部 Tab 36px、底部状态 24px、工具轨 44px；按系统文字缩放扩展，不固定高度裁字 |
| 控件 | 图标统一线性风格、常规 16px；点击区至少 28×28px；窗口系统按钮遵守 Windows；按钮圆角 6px、菜单 8px、对话框 12px |
| 选中与悬停 | 选中 Tab 同时用较亮文字、字重和稳定底色/边界表达；悬停只小幅提亮，不改变宽度；焦点用清楚的 2px 轮廓 |
| 材质与动效 | 常驻区域不使用装饰渐变和阴影，浮层使用轻阴影；按下立即反馈，短淡化约 100–140ms，不锁住输入；拖动延续直接跟随、可取消机制 |
| 可访问性 | 普通文字对比度至少 4.5:1，关键控件/焦点至少 3:1；高对比用系统色/实边，减少透明时实色，减少动态时即时切换；令牌需实际测量组合后验证 |

终端 ANSI 调色板属于输出语义，保持不同颜色可辨；终端背景、默认前景、选区与光标与公共主题协调。插件通过版本化公开呈现协议接收同一套语义令牌；不能从外壳私有 CSS/React 导入，也不能各自另配一套近似色。

本轮清理适用于现有主/子窗口、单终端、选择器、编辑与认证、插件/资源/调用记录页及错误/空态。Tab 文本与更多按钮规则、菜单关闭和长名称策略以 F-CORE-008 为唯一来源。实际视觉与原生验证对应 UX-02/03/05/06、IN-07，颜色独立及替换验证对应 UX-10；本节不能替代真实渲染检查。

## 3. 每个功能必须说明的界面行为

- 入口、主要操作、布局和当前服务器或工作区上下文。
- 初始、加载、成功、空数据、失败、禁用等适用状态；异步或长任务还需说明取消、超时和恢复。
- 操作是否允许重复、进行中能否切换或关闭，以及操作完成或失败后的反馈。
- 键盘操作、焦点进入与返回、快捷键冲突和适用的输入法行为。
- 长名称、大量内容和目标窗口尺寸下的截断、滚动及溢出处理。
- 涉及断线、操作系统/远端账号权限不足、插件缺失或结果不明时，用户看到什么、下一步可以做什么；按 P-14 不设计 SoDeck 插件授权提示。
- 涉及删除、覆盖、断开或服务操作时，按功能决定提示、确认和恢复方式；不统一追加无依据的弹窗。

不适用项可以说明原因；不能用“统一处理”替代尚未定义的交互。

## 4. 插件与外壳

核心管理工作台框架，插件提供视图内容。核心拥有工作区切换、侧边工具入口与停靠、中央 Tab 和两个分屏区域、独立窗口、托盘、Tab/面板操作外框、焦点与布局持久化；插件拥有内容区、业务工具栏、业务状态与操作。每个插件可以提供多个视图，每个视图声明支持的展示方式和默认位置，用户在支持范围内移动。

T-006 适用覆盖：按产品 P-24、P-27，终端不再提供会话列表和左右/上下分屏。中央统一为单 Tab 组，终端仅中央/独立窗口，具体规则与旧布局迁移见 F-CORE-008；上述双区域为 T-003/T-004 历史基线。公共停靠/窗口职责继续归核心，不改变架构边界。

按产品 P-20、P-21，窗口不另占一行顶部标题栏，服务器以顶部 Tab 呈现并支持新窗口与合并。本轮具体设计以 [F-CORE-006](../core/server-tabs.md) 为有效来源：服务器 Tab 与 Windows 控制同一行；保留系统标题元数据、原生拖动/缩放/贴靠和辅助技术；分清完整工作区窗口与单视图弹窗。T-004 已获方案确认，实际验证另见任务记录，不能将旧单视图结果当作新外壳验证。

详细边界、容器与迁移契约、关闭和恢复行为、功能测试以 [F-CORE-004：工作台、插件视图与窗口](../core/workbench.md)为有效来源，不在各插件重新设计一套停靠或窗口框架。插件自己的详细文档必须列出视图、工作区/App 作用域、支持位置、单/多实例、状态恢复及关闭规则。

收起、切换、移动和明确关闭分别表达；主窗口“×”按产品 P-18 收起到托盘，明确退出按 P-11 结束全部 App 资源。插件独立窗口与主窗口的关闭职责不得混淆，界面行为必须对应资源策略。移动不能只依赖拖拽，提供菜单或键盘路径并验证焦点恢复。

插件与外壳遵循相同的公共视觉和交互规则；插件专属布局和业务状态在自己的详细文档中定义。插件更新、安装和启停的具体交互分别遵循已确定规格，其中更新必须重启 App 后生效。

## 5. 界面验证

每个功能编码前写好自己的界面测试步骤和预期结果，按[测试规范](testing.md)选取实际影响的状态、主题、尺寸、键盘、焦点和平台路径。

交付时查看实际渲染，记录环境并提供可查看入口或截图。原型标明模拟数据，浏览器和原生桌面结果分开陈述。设计决定或发现的规格缺口先写回文档，再继续相应实现。
