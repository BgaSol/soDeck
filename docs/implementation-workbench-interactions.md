# 工作台按钮与文件菜单整改实施

2026-11-06。对应 [设计方案](plan-workbench-interactions.md)。源码已实施并完成本地检查、浏览器回归、真实文件流程和 Windows x86_64 打包验证，尚未发布或覆盖用户安装。

## 改动与原因

### 按钮与焦点

旧 `replace()` 把原始 SVG 模板与浏览器规范化后的 innerHTML 直接比较，相同输入仍重建按钮。局部复现中，正常点击执行 1 次；按下后刷新再抬起执行 0 次，旧节点和焦点同时丢失。

现在缓存渲染输入与实际输出，同时核对当前 DOM；外部写入不会被缓存掩盖。工作台两级标签、侧栏、标题栏和状态栏使用稳定节点，按工作区、视图和动作标识更新变化的内容。按压中的布局更新在点击确定目标后应用，异步创建入口仍立即禁用，防止重复提交。内部标签拖动监听只绑定一次，复用节点后不累积监听。

同一个菜单入口再次点击关闭，Esc 返回原入口，外部点击保留新目标焦点。普通鼠标打开面板菜单时不自动选中第一行；键盘打开和可搜索列表保留对应导航。新工作区默认展开使用勾选状态，面板菜单文案缩短。

异步打开/选择组件使用交互代次和工作区核对，旧结果不再抢焦点。共享插件 UI 转发不含输入内容的交互通知，宿主仍按原有来源和 surface token 验证；该增量通知随各插件独立更新，旧插件继续按原协议加载。

### 文件菜单与剪贴板

文件菜单按单文件、单目录、多选、空白和结构根项裁剪动作，保持右键选择和固定操作快照。常用剪贴板动作留在一级，“新建/上传”使用一级子菜单，展开/折叠直接复用目录行和键盘能力；重命名、删除位于末尾。

粘贴先禁用，状态返回后只更新按钮。菜单可见时最多一个查询在途，约每秒刷新一次，关闭后停止；旧菜单结果不能更新新菜单。第一次查询校验目标目录，执行时重新核对目标、连接、系统 revision 和远程 clipboardId。异步输入/对话框期间切换连接会取消旧操作，临时 selection/input 在取消路径释放。

核心 `input.revision` 兼容增加 hasFiles：Windows 查询 CF_HDROP，macOS 查询 public.file-url 格式，Linux 异步查询 URI-list/GNOME 文件格式。只查格式和 revision，不枚举本地路径、不创建 input 或任务。文件插件的只读 clipboardStatus 检查远程来源、上下文、revision、剪切消费状态和自身/后代目标；业务判断留在插件。

旧核心缺少 hasFiles 时保持状态未知，不根据 count=0 推断空剪贴板；已有有效远程来源及显式键盘粘贴保持兼容。仅有路径文字不启用文件粘贴；有效本地文件按上传处理，不删除本地来源。

### 外框、滚动与子菜单

旧文件菜单把外扩 2px 的共享描边放进自身滚动容器，出现横、纵各 2px 额外滚动范围并裁掉描边。现在外框和内层列表分离；外框负责背景、描边、圆角和定位，仅内层在确实超高时纵向滚动。

菜单以插件 iframe 可用尺寸定位，四边留出空间。子菜单左右放不下时改为向上或向下展开，避免遮住自己的入口；鼠标悬停后点击仍保持展开。通过真实鼠标回归发现并修复了这个窄面板问题，而不是只用程序调用 click 验证。

## 交付与边界

- 核心与文件插件独立构建，没有新增本次整改的生产依赖、配置字段、授权流程或 UI API 主版本。
- 新的 `interactions:test` 已接入 ui:test 和现有 GitHub Check 工作流，在安装 Chromium 后执行。源码与工作流尚未提交到远端，因此本轮没有新的 GitHub Actions 或 Release 结果。
- 本地 Windows x86_64 产物位于 `src-tauri/target/release/bundle/`；文件插件独立包位于 `artifacts/interaction-plan/plugins/`。应用和插件版本未提升，不能把这些验证产物当作已发布更新。
- Windows ARM64、Linux x86_64/ARM64、macOS ARM64 的实际产物和设备交互未在本轮执行。五目标原生设备上的首次聚焦点击、混合 DPI、系统文件剪贴板互操作仍待验证；Windows 包烟测和 Chromium 回归不能替代这些设备验收。
- 常规短菜单无滚动条，极小插件视口允许内层纵向滚动；长组件列表继续保留纵向滚动和固定搜索框。
