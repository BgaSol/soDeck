# 远端 NetBird 客户端 UI 与交互设计

日期：2026-10-18。状态：交互方案，不涉及业务代码。

本方案承接 `netbird-client-feature-design.md`。界面目标是让用户在当前 SSH 工作区里快速回答三个问题：客户端现在是否正常、哪些对端可达、我可以安全地做什么。

## 1. 总体结构

NetBird 作为服务器右侧服务栏的第三个一级页面：

```text
监控 | Docker | NetBird
```

页面内部不再常驻一排二级标签。默认显示概览，节点、诊断和详情通过同一侧栏中的前进／返回进入，保持窄侧栏的信息密度和空间连续性。

```text
NetBird 概览
├── 全部节点
│   └── 节点详情
├── 检测与日志
└── 更多菜单
    ├── 断开 NetBird
    ├── 启动／重启客户端服务
    └── 查看原始状态
```

推荐以“概览优先”为默认形态：先展示本机状态和异常，再给少量节点预览。节点很多或用户进入“全部节点”后，再切换为紧凑列表。不要把页面设计成全网拓扑图；当前数据只代表这台客户端可见的对端。

## 2. 页面框架

### 2.1 顶部一级导航

- 沿用现有 `监控 / Docker` 的标签样式，加入 `NetBird`。
- 标签使用图标加文字，不单独使用 NetBird 品牌色。
- 切换页面后保留各自的滚动位置和局部导航位置。
- 键盘继续支持左右方向键、Home 和 End。

### 2.2 NetBird 页面标题栏

从左到右：

1. `NetBird` 标题。
2. 综合状态文字：已连接、连接受限、正在连接、已断开、需要登录、服务未运行。
3. 刷新按钮。
4. 更多菜单。

刷新是普通图标按钮；写操作不与刷新并排常驻。已连接时不显示大号“断开”按钮，断开和重启放入更多菜单。未连接但可恢复时，标题下方只出现一个符合当前状态的主操作，例如“连接”或“启动服务”。

标题栏可随内容滚动吸附。滚动内容经过标题栏下方时使用轻微材质或阴影变化表达层级，不添加醒目的硬分割线。

## 3. 概览页面

内容顺序固定为“当前结论 → 本机身份 → 连接分项 → 对端摘要 → 诊断入口”。

### 3.1 状态摘要

摘要是页面最显眼但不过度放大的区域：

- 状态图标和“已连接”等明确文字。
- 一句解释，例如“8 个对端中 6 个已连接”。
- 当前 NetBird 地址，可复制。
- 最后成功更新时间。

颜色只作辅助：

- 绿色：已确认正常连接。
- 橙色：连接受限、查询结果待核对或部分组件异常。
- 红色：明确错误。
- 灰色：正常空闲、主动断开、无数据。

中继连接不使用故障红色；Idle 不默认使用警告色。

### 3.2 本机身份

采用紧凑的键值列表，而不是多张指标卡：

- 主机名／FQDN。
- NetBird IPv4／IPv6。
- 客户端版本和 daemon 版本。
- 当前 Profile，仅在可获取时显示。

IP 和主机名所在整行可选中；行尾提供复制图标。复制成功只在按钮附近短暂显示“已复制”，不弹全局提示。

### 3.3 连接分项

使用四行状态列表：Management、Signal、Relay／STUN、DNS。每行包含状态图标、名称和简短结果。

- 正常项保持安静，不展开技术描述。
- 异常项可点入“检测与日志”，并自动定位到对应检查项。
- Management 异常但已有隧道仍工作时，综合状态显示“连接受限”，不覆盖其他分项。

### 3.4 对端预览

显示最多 3–5 个节点，优先顺序：异常或连接中、最近活动、其他节点。每行内容：

- 第一行：节点名称和状态。
- 第二行：NetBird IP、`直连`／`中继`。
- 可选尾部：延迟；没有可靠值时不占位显示 `0 ms`。

整行进入详情。标题右侧的“全部”进入节点列表。列表底部不重复放第二个“查看全部”按钮。

### 3.5 诊断入口

概览底部放一个普通导航行“检测与日志”，右侧显示当前最重要的结果，例如“全部通过”或“2 项需要注意”。它是导航，不设计成主按钮。

## 4. 节点列表

### 4.1 顶栏

- 左侧返回按钮，标题“节点”。
- 次级文字显示 `6 / 8 已连接`。
- 刷新沿用当前快照，不在列表页重复增加更多菜单。

### 4.2 搜索与筛选

- 搜索框支持名称、FQDN、IPv4 和 IPv6。
- 筛选入口用一个紧凑按钮打开弹出菜单，避免状态、连接方式两组 Chips 长期占用窄栏高度。
- 已启用筛选时按钮显示数量，例如“筛选 2”。
- 清除搜索不清除筛选；返回概览后保留两者。

### 4.3 列表行

每行使用两层文本，不做卡片瀑布流：

```text
db-prod-01                         已连接
100.82.14.23 · 直连                  18 ms
```

- 行高保证鼠标和触控都容易点击。
- 状态必须有文字，不能只靠彩色圆点。
- IPv6 长文本允许截断，悬停／聚焦显示完整值。
- 列表刷新时不改变滚动、选中和键盘焦点。
- 无结果时区分“没有可见节点”和“筛选条件没有匹配”。

## 5. 节点详情

详情从列表所在方向进入；返回时按相反方向退出，并恢复列表位置。

页面结构：

1. 节点名称、当前状态、复制地址。
2. 连接方式：直连或中继。
3. 最近握手、延迟、累计收发量、最后状态变化。
4. 关联网络，仅在有数据时显示。
5. “连通性测试”区域。

连通性测试默认不自动执行。用户选择：

- Ping：单次检测。
- TCP：输入一个端口后检测。

检测按钮点击后立即进入进行中状态，但不锁住返回。结果明确写明“从当前服务器发起”，并显示测试时间。ICMP 无响应只写“未收到响应”，不把节点状态改成离线。

## 6. 检测与日志

页面按问题域分组：

- 客户端服务。
- Management 与 Signal。
- Relay／STUN。
- DNS。
- 对端隧道。

每个检查项有四种视觉状态：正在检查、正常、需要注意、无法检查。展开后显示证据、时间和建议，不显示泛化的“修复”按钮。

页面下方提供：

- 查看最近日志。
- 查看状态原文。
- 复制脱敏摘要。

日志和状态原文使用独立的等宽文本区域。加载更多日志由用户触发，不在后台无限追踪；离开页面后不保留原文到共享工作区快照。

## 7. 操作与确认

### 7.1 普通操作

刷新、复制、打开详情和单次检测直接执行。按钮按下时立即给予状态反馈，不等待 SSH 返回后才变化。

连接操作分为：

```text
连接中 → 正在核对 → 已连接
                 └→ 仍未连接／需要登录／失败
```

命令完成只代表进入“正在核对”，不能直接显示成功。

### 7.2 中断型操作

断开 NetBird 和重启客户端服务从更多菜单进入。选择后先展示路径预检结果：

- `当前 SSH 不依赖 NetBird`：显示影响说明，用户二次确认。
- `当前 SSH 依赖 NetBird`：阻止操作，主按钮变为不可用，并建议使用公网、局域网或控制台路径。
- `无法确认路径`：默认阻止，不提供“仍然执行”的弱确认选项。

确认面板必须明确写出将执行的动作，不使用“确定／取消”作为主标签。例如：

- 次按钮：取消。
- 危险按钮：断开 NetBird。

操作导致 SSH 消失时，页面保留任务记录并显示“结果待核对”。重新连接后只提供“检查当前状态”，不自动重试。

### 7.3 操作进行中

- 同一个客户端只允许一个写操作。
- 操作按钮变为进度文字，例如“正在重启…”。
- 其他写操作禁用，但状态浏览、复制和返回保持可用。
- 关闭页面或切换标签不取消已提交的远端任务。
- 完成反馈放在相关区域，不使用覆盖全应用的成功弹窗。

## 8. 页面状态

必须分别设计以下状态，避免全部退化成一个错误页：

| 状态 | 界面表现 | 主操作 |
| --- | --- | --- |
| SSH 未连接 | 不展示旧控制按钮 | 重新连接服务器 |
| 正在检测 | 骨架只覆盖尚无数据的字段 | 无 |
| 未安装客户端 | 说明未检测到 CLI | 重新检测／指定路径 |
| daemon 未运行 | 保留安装与版本信息 | 启动服务（有权限时） |
| 需要登录 | 展示已有客户端信息 | 在终端完成登录 |
| 主动断开 | 灰色状态，保留节点旧快照并标时 | 连接 |
| 查询失败、有旧数据 | 旧数据保持可读并标明时间 | 重试 |
| 权限不足 | 显示可读取部分 | 在终端处理权限 |
| 无节点 | 正常空状态，不显示红色错误 | 刷新 |
| 结果待核对 | 橙色状态和任务记录 | 检查当前状态 |

## 9. 动效和空间关系

- 概览进入节点列表、节点列表进入详情：沿水平方向短距离推进；返回路径完全对称。
- 弹出菜单从更多按钮的位置展开。
- 确认界面使用轻量侧栏内 Sheet 或应用级确认对话框；若操作会影响整个 SSH 会话，推荐应用级对话框。
- 普通导航使用无弹跳、可打断的短弹簧；状态变化主要使用交叉淡化，避免列表上下跳动。
- 刷新时保持旧内容，只让刷新图标和更新时间表达进行中，不整页闪烁骨架。
- 遵循减少动态效果设置：取消横向位移，改为短交叉淡化。

## 10. 键盘和无障碍

- 一级标签遵循标准 Tablist 键盘行为。
- 页面内部 Tab 顺序与视觉顺序一致。
- 列表行可用 Enter 打开；返回支持按钮和平台标准快捷键。
- 动态状态通过礼貌播报更新，但不播报每次轮询。
- 状态始终使用图标、文字和颜色共同表达。
- 所有图标按钮都有可见 Tooltip 和无障碍名称。
- 320px 宽度保持单列；长域名、IPv6 和错误文字可展开查看，不形成横向页面滚动。

## 11. 推荐默认方案

采用“概览优先、列表下钻”的结构，不为概览、节点和诊断增加常驻二级 Tabs。原因：侧栏空间窄，用户进入 NetBird 时首先需要判断是否正常；节点操作属于下一层任务，诊断只在出现问题时进入。

页面设计应保持克制：少量状态色、普通列表替代大量卡片、一个情境主操作、危险操作后置。整体感受应是“安静地报告事实，明确地阻止危险操作”。
