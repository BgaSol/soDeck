# 组件设置与终端外观设计

状态：2026-11-06 已进入源码，随 0.9.0 发行，结果见 [发行说明](releases/v0.9.0.md)。本文保留目标行为；实际完成范围与待验收项见 [实施记录](implementation-component-settings.md)。

完整的模块、数据结构、RPC/界面桥、实施批次及测试方案见 [代码修改方案](plan-component-settings-coding.md)。本文件以用户行为为准，具体接口以实施后同步的 API 文档为准。

## 1. 用户意图与设计结论

用户希望终端更美观，底部有一点留白，能自定义字体，并预置可直接使用的字体。随后明确：使用已有设置页面，为每个组件提供自己的设置入口，不把外观设置放进右键菜单。

本方案把现有设置扩展为“应用设置 + 组件设置”。组件设置面向使用偏好：终端的字体和间距、文件列表的显示、文件编辑器的排版、网络隧道的新建默认值。核心提供统一入口、声明式表单、基础校验、存储和变化通知，插件声明设置项并负责业务校验及生效逻辑。

2026-11-06 设计调整：根据用户提出的“核心提供设置功能，由插件声明”，普通设置改为核心根据声明渲染和保存。此前插件自建整页表单、自行写盘的提案被本版本替代；特殊示例预览可由插件提供，普通字段仍走统一设置能力。

第一版按**组件类型**设置，不按某个 Tab 设置。同一类型的所有服务器、主窗口和拆出窗口共用偏好。文件列表和文件编辑器虽然来自同一个文件插件，仍有各自页面；网络隧道的管理面板和规则编辑弹窗共用一个设置页。以后一个插件可以提供多个设置页，也可以让多个视图共用一个页。

终端默认采用 JetBrains Mono、14px、1.2 倍行高，左右 16px、顶部 12px、底部 24px。终端背景、前景、选区与 ANSI16 色继续跟随应用主题。预置字体随插件包分发，安装后离线可用；本机已安装的字体通过名称使用。

## 2. 现状与问题

设计时核对的改动前源码基线：

- 现有设置为 940×620px 浮层，左侧 160px 导航，已有插件管理、外观、应用更新、应用与数据。
- 组件 UI 按服务器工作区挂载，当前没有独立于服务器的组件设置宿主。
- 终端使用 xterm 6.0.0，字号固定为 13px，字体族和行高使用库默认值。正文内边距为顶部/左右 12px、底部 8px。
- 终端已接入三主题、平台剪贴板、多 Tab、跨窗显示恢复和 PTY 尺寸同步，这些能力需要继续保留。
- 文件编辑器使用固定的 13px 等宽字体、1.7 倍行高与 4 列 Tab 显示宽度；文件列表和网络隧道没有独立偏好页。
- 核心 UI 资源服务已支持本地 WOFF2，终端已有独立资源打包入口；核心包无需包含终端字体或 xterm。

“不够美观”在本轮解释为：正文排版偏紧、底部输入行贴近边界、字体无法选择。采用更清楚的排版和留白，不另建终端配色系统。

## 3. 设置页面的信息结构

```text
设置
├─ 应用
│  ├─ 外观
│  ├─ 插件管理
│  ├─ 应用更新
│  └─ 应用与数据
└─ 组件
   ├─ 终端
   ├─ 文件列表
   ├─ 文件编辑器
   └─ 网络隧道
```

- 入口仍为右上角“设置”。保留现有应用页面，在同一侧栏增加“组件”分组。
- 官方组件按上图排序；其他插件按声明顺序追加到组件分组，名称相同时通过来源名称区分，不靠显示名称确定身份。
- 组件页标题显示组件名，下面用小字显示所属插件和适用范围，例如“终端插件 · 所有服务器”。不把进程 ID、RPC 或存储字段放进日常表单。
- 插件管理仍负责安装、启用、关闭和升级。插件详情可提供“组件设置”跳转；有多个页时列出对应页面。这里只跳转已有设置页，不增加右键入口。
- 未安装的插件不出现在组件分组。已安装但关闭、启动中、失败或待重启的组件保留入口并显示原因。
- 旧插件没有设置声明时，由其视图生成合并后的提示页：“当前版本未提供组件设置”，可跳到插件管理升级。无 UI 且未声明设置页的插件不生成空入口。
- 核心从已安装版本的清单读取设置声明。关闭的插件也可调整符合静态声明的偏好，页面显示“保存后在下次启用时使用”；不为访问设置临时启动业务进程。首批设置全部满足静态校验。
- 未连接任何服务器时也能打开组件设置；打开设置不会创建终端、文件会话或网络监听。插件正在启动或已异常退出时，通用表单仍可使用，保存后的实际生效状态单独显示。

设置浮层建议保持 940px 基准宽度，左侧扩为 180px；正文与底部操作区分开。长页仅正文纵向滚动，保存动作一直可达。720×480px 桌面、125%/150% 显示比例需要可用；会话本身的内容区不会因打开浮层而改变尺寸。窄对话预览可纵向排布，实际桌面继续遵循最小窗口要求。

## 4. 统一的编辑、保存与生效方式

组件页面统一采用**局部预览 → 保存并应用**：

1. 打开页面，核心读取组件声明及最后一次成功保存的设置，建立本页草稿。
2. 修改字段，只更新设置页里的示例预览。远端会话和已打开的文件正文继续按原设置运行。
3. 底部显示“有未保存的修改”，启用“放弃修改”和“保存并应用”；没有修改时按钮禁用。
4. 保存时核心前端校验输入，核心后端按同一声明再次校验类型、范围和选项；如该页声明了额外业务校验，则先调用插件的无副作用校验。核心原子写盘成功后返回规范化值及修订号，再通知所属插件和组件更新。
5. 可即时显示的字段应用到全部相关实例；新建默认值只影响之后创建的实例或规则。页面按字段说明生效范围。
6. “恢复默认”仅把本页草稿重置为默认值，预览随之变化；仍需保存。不恢复其他组件，不修改插件启用状态或工作区布局。

保存反馈为“已保存并应用”或“已保存，用于新建规则”。如果某个运行实例应用失败，则说明“设置已保存，部分页面未应用”，保留旧显示并允许重试；不能用一次写盘成功冒充全部实例应用成功。隐藏实例在再次显示时读取最新设置，挂载时总是读取最新版本。

切换设置页或关闭浮层时，未保存的草稿保留在本窗口内存，重新打开继续编辑；应用退出后不持久化草稿，也不增加离开页面确认。选择“放弃修改”恢复最新保存值。插件进程退出不丢草稿或阻止静态设置保存；插件升级切换声明后，核心重新核对字段定义和修订号，旧声明下的保存不能覆盖新配置。

多个窗口可查看和编辑设置。保存携带读取时的修订号，核心串行检查并写盘；旧修订保存被拒绝，页面显示“其他窗口已更新设置”，提供“载入最新设置”，保留本地草稿供查看。不静默覆盖另一窗口的修改。

外观设置不要求重启。插件启用、关闭和已启用插件升级继续在重启后生效，沿用既有规则，不混成一个新的发布状态机。

## 5. 终端设置：具体功能

页面分为“文字”“间距”“光标”和“预览”，不另外增加终端工具栏。

| 设置 | 默认值 | 可选范围 | 生效方式 |
| --- | --- | --- | --- |
| 字体 | JetBrains Mono | 预置字体 / 本机字体名称 | 全部终端 |
| 字号 | 14px | 11–24px，步长 1 | 全部终端，必要时同步 PTY 行列 |
| 行高 | 1.2 | 1.0–1.6，步长 0.05 | 全部终端，必要时同步 PTY 行列 |
| 底部留白 | 24px | 8–48px，步长 4 | 全部终端，同步 PTY 可用行数 |
| 光标形状 | 方块 | 方块 / 竖线 / 下划线 | 全部终端 |
| 光标闪烁 | 开启 | 开 / 关 | 全部终端，减少动态效果时停止闪烁 |

左右 16px、顶部 12px，字间距固定为 0；常规字重 400、ANSI 粗体采用真实粗体。第一版不暴露描边、透明度、字间距和独立 ANSI 调色板，减少影响可读性与字符对齐的选项。

### 5.1 预置字体与本机字体

| 预置字体 | 建议用途 |
| --- | --- |
| JetBrains Mono | 默认；数字、标点和相近字符易辨认 |
| Source Code Pro | 偏传统、清晰的代码与命令排版 |
| IBM Plex Mono | 字形特点更鲜明，供用户按喜好选择 |

字体选择器展示真实字体名称与简短样例，不使用“字体 1”等名称。每套只带本轮使用的 Regular/Bold 字体资源，关闭编程连字，保留终端逐字符显示语义。构建前核对固定发行版本、许可证和文件校验值，资源与许可提交到仓库并随插件包分发；用户使用时不访问字体网站或 CDN。

选择“本机字体”后输入已安装字体的名称，并立即在示例中预览。输入被当成字体名称，不能接受任意 CSS 或远程地址。字体加载失败时就地说明并禁止保存新的无效选择，不把浏览器静默回退当成成功。

已保存的本机字体之后不可用时，运行实例使用预置 JetBrains Mono 回退，保留用户保存的名称，在设置页显示回退原因。本机字体可用性与字形测量须在三种系统的实际 WebView 验证；不把 `document.fonts.check()` 的结果单独作为字体存在的证据。

预置拉丁字体按需加载，未包含的中文、emoji 和符号由系统字形回退。预览包含 `0O 1Il {} [] | -> !=`、中文路径、表格线和 ANSI 示例；等宽检查覆盖代表性字符并提示明显的比例字体问题，不声称能证明所有字符等宽。完整字符列宽、中文和图标是否适配以实际 xterm 验收为准。

第一版支持用户安装 Nerd Font 后填写其名称；不内置整套 Nerd Fonts 或完整 CJK 字库。直接导入字体文件与在线字体目录不纳入本轮。

### 5.2 底部留白与终端网格

留白属于终端正文的内边距，位于 xterm 可用网格之外，颜色与终端背景一致。默认最后一行字符到正文底边至少有 24px 空间；整数行取整可能额外留下不足一行的余量。工作台 32px 底栏单独计算。

不能通过输出空行、插入远端换行、向上平移画面或覆盖最后一行制造留白。尺寸适配必须扣除上下内边距，再计算行列并向原 PTY 发送 resize。滚动条只覆盖可滚动网格，不占用底部留白。终端专有错误/退出提示沿用既有独立区域，不盖住字符或光标。

字体资源加载成功后才更新现有 xterm options 和 fit；不重建 shell、不重放命令、不清空显示快照。字号、字体和行高改变可能触发折行与远端全屏程序重绘，这是行列变化的正常结果。保持输出内容和浏览历史的意图；尺寸重排时不承诺原坐标选区完全不变，失效选区不能误复制另一段文字。仅颜色/光标变化应保持行列、选区和滚动位置。

## 6. 其他组件的首批设置

这些是本方案提出的设置项，不表示当前版本已有对应开关。各页只放足以形成真实用途的偏好。

| 组件 | 首批字段与默认值 | 范围与生效 |
| --- | --- | --- |
| 文件列表 | 显示隐藏文件：开；列表密度：紧凑；名称字号：12px | 隐藏开关即时过滤当前已加载条目，仍按原分页继续拉取；紧凑/舒适为 24/28px 行高；字号 11–18px；全部文件列表生效 |
| 文件编辑器 | 字体：JetBrains Mono；字号：14px；行高：1.5；自动换行：关；Tab 显示宽度：4 | 字体与终端各自独立保存；字号 11–24px、行高 1.2–1.8、Tab 宽度 2/4/8；只更新显示，不改文件正文、缩进、编码、BOM、LF/CRLF、草稿或保存冲突检查 |
| 网络隧道 | 新规则默认类型：TCP 转发；新规则端口分配：自动；固定端口：仅固定模式下填写 | 类型可选 TCP/SOCKS5；固定端口 1–65535；仅作为以后新建表单的初值，不创建、重启或改变已有规则 |

文件列表关闭隐藏文件显示时，如果当前选中的条目被过滤，清除该不可见选中并保留当前目录；已打开的编辑器和进行中的传输继续保持。再次显示隐藏条目不重新发起文件操作。

终端与文件编辑器的字体选择界面采用相同交互规则，各插件仍携带自己所需的资源。只有两处实际落地后再提取共享字体选择辅助代码或共享资源来源；运行时与各自发行包保持独立。

网络隧道的本机回环默认绑定和逐条编辑入口继续保留。第一版不在设置中提供自动启动、自动重连、自动覆盖文件或修改系统代理等额外开关。

工作区布局仍由核心现有布局操作管理。本轮不重新引入此前回退的默认组件持久化、自动打开策略或新的侧栏布局设置。

## 7. 核心与插件的职责

采用**核心提供通用设置能力，插件声明设置项**。终端、文件列表、文件编辑器和网络隧道构成多个真实使用者，值得统一基础表单与持久化。第一版只支持当前实际需要的字段，不实现任意页面编程或完整 JSON Schema 引擎。

| 核心负责 | 插件负责 |
| --- | --- |
| 应用设置入口、动态组件导航、稳定页面身份 | 声明页面、分组、字段、标题、帮助文字 |
| 统一表单、字体选择、草稿、默认值恢复和预览容器 | 声明默认值、类型、范围、选项、字段生效方式 |
| 核心后端基础校验、修订检查、原子持久化和错误反馈 | 必要时提供无副作用的业务校验 |
| 设置读取 API、初始化快照和所属组件变化通知 | 字体资源、特殊预览、终端 fit、文件显示和新建规则默认值 |

核心不按终端 ID 判断字号、不解释文件隐藏的业务规则；它根据声明把值保存为独立的插件/页面命名空间。终端字段不混入应用主题偏好，同一个文件插件的列表和编辑器分别保存。

核心在系统应用数据目录保存组件设置，键为 `pluginId:pageId`，内容含声明版本、修订号和有界值。用户偏好独立于安装目录，升级核心或插件不重置；移除插件记录仍保留设置，重新安装相同 ID 可恢复。损坏数据回退有效备份或默认值，保留原文件并在设置页说明。

插件声明的新增字段补默认值，既有字段保留用户保存值；删除字段不继续下发给当前组件，其存档值暂时保留以便回退。字段改名或类型不兼容时须提供明确迁移策略；没有迁移不能偷偷把用户值重置为默认。第一批字段均为新偏好，不需要建立通用迁移脚本系统。

### 7.1 最小契约提案

以下名称与结构均为待实施设计，不是当前可调用 API。

插件清单增加可选的静态设置声明，例如：

```json
{
  "settings": {
    "apiVersion": "1",
    "schemaVersion": 1,
    "pages": [
      {
        "id": "appearance",
        "title": "终端",
        "icon": "terminal",
        "viewTypes": ["terminal"],
        "groups": [
          {
            "id": "text",
            "title": "文字",
            "fields": [
              {
                "key": "fontSize", "type": "number", "title": "字号",
                "default": 14, "min": 11, "max": 24, "step": 1,
                "unit": "px", "apply": "live"
              }
            ]
          },
          {
            "id": "spacing",
            "title": "间距",
            "fields": [
              {
                "key": "paddingBottom", "type": "number", "title": "底部留白",
                "default": 24, "min": 8, "max": 48, "step": 4,
                "unit": "px", "apply": "live"
              }
            ]
          }
        ]
      }
    ]
  }
}
```

页面身份为 `pluginId:pageId`；pageId、字段 key、分组 ID 与关联视图 ID 必须在插件内有效。核心检查字段定义与默认值是否一致，不依赖启动插件发现基本设置。页面由核心生成，不要求 `ui/settings.html` 或专用设置进程。

首批支持 boolean、number、string、select 和 font 字段；简单显隐条件只引用同页字段，例如“固定端口”在端口模式为 fixed 时显示。条件用于显示，核心后端仍校验全部保存字段；不支持自定义执行代码、表达式语言或远端动态表单。

font 为终端和编辑器共用的通用选择控件。插件声明预置字体 ID、显示名称和包内资源路径，保存预置字体 ID 或本机字体名称；字体资源、许可证仍随各自插件包分发。核心支持字体加载与基础预览，不在核心包中内置业务字体。终端网格等特殊预览可声明可选的包内 preview 入口，由核心传入草稿值，不传服务器 Context，也不因预览打开 PTY。静态字体/预览资源可从已安装且未启用的插件加载，需相应调整现有只服务运行中插件资源的实现。

新增核心能力 `settings.v1`，通过应用设置前端及插件 RPC 使用；旧 workspace Context 和 UI v1 语义不变。核心统一拥有有效设置，插件按来源读取自己的命名空间，不直接读写核心数据文件。

| 交互 | 目标行为 |
| --- | --- |
| 清单加载（核心） | 读取静态声明，生成通用设置页；不连接服务器、不要求启动业务插件 |
| 设置读取/保存（应用前端 → 核心） | 按 pluginId/pageId 读取定义与有效值；保存携带声明版本、baseRevision、requestId 和有界值，由核心校验并写盘 |
| `settings.get`（插件 → 核心） | 读取调用插件自己的页面快照；核心从真实调用来源确定 pluginId |
| `settings.validate`（核心 → 插件，可选） | 持久化前进行声明要求的额外业务校验；纯校验，返回字段错误，不启动任务或产生资源 |
| `settings.changed`（核心 → 插件） | 持久化后发送 pageId、最新修订与有效值，插件按字段生效方式更新运行状态并回报结果 |
| `settingsChanged`（宿主 → 组件 UI） | 核心更新所属组件的已挂载 UI；其他设置窗口收到同一有效快照，不覆盖其未保存草稿 |
| initialize / mount / visibilityChanged | 初始化和挂载带最新设置快照，隐藏实例再次可见时核对修订；不会仅依赖一次变化通知 |

核心生成表单和管理草稿，“恢复默认”不直接写盘。首批静态设置在插件关闭或失败时仍可保存，稍后启动/挂载读取最新值；仅对未来确实声明了额外业务校验的字段，校验插件不可用时明确阻止保存相关页。第一版不为这类未来需求临时启动插件。

声明区分 `apply: live` 与 `apply: newInstance`。例如终端字号即时应用，新规则默认值仅用于新建；核心用这些元数据给出提示，插件负责兑现行为。保存成功后实际生效失败则分别报告“已保存”和具体应用错误，不自动回滚用户偏好或重启连接。

沿用 24 KiB 控制交互限制，限定声明字段数量和字符串长度；字体二进制、终端输出和文件正文不进入设置 RPC。核心串行化修订检查、写盘和提交次序，保存用 requestId 去重；通知带修订号，插件忽略过期通知，UI 按当前挂载身份接收。超时后重新读取实际修订核对结果，不仅按前端超时推断写盘失败。

插件的业务进程仍通过版本化 RPC 读取和接收设置，插件 UI 仍通过宿主桥获取快照；插件之间没有设置直调。缺少服务器 Context 的表单或预览不能执行需要服务器/资源句柄的操作，这是资源状态检查，不引入权限声明或审批。

### 7.2 兼容与分发

- 核心 API 保持主版本 1，通过 `settings.v1` 发现新增能力；旧插件继续原有业务，未声明设置时显示版本提示页。新清单增加可选字段，旧核心忽略；新插件缺少能力时保留原业务与默认设置。
- 新插件在旧核心上保持原业务可用，并采用已保存/默认偏好；设置入口不可用时在说明中标明所需核心能力，不为缺少偏好 UI 禁止终端连接。
- 老用户没有设置文件时补本方案默认值；已经保存过字体和字号的后续版本升级不重置。
- 核心、终端、文件和网络插件独立构建及发行。核心构建不依赖插件构建或字体资源；各插件包包含对应设置声明、必要的特殊预览、字体和许可证。
- 本次设计不引入生产代码依赖。实施时使用现有 xterm、原生 DOM、CSS 和字体加载接口；字体为用户明确要求的打包资产。若实际 WebView 需要新的系统字体适配依赖，另行说明真实用途和替代方式。

### 7.3 插件升级与设置演进

插件程序版本与设置的 schemaVersion 分开。修复终端连接或样式可以升级插件版本而不改变设置结构；新增、移除字段或改变字段含义时，声明版本按实际结构变化更新。偏好仍归属稳定的 `pluginId:pageId`，不能把插件版本放进存储键，每次升级也不重建一份默认配置。

已启用插件的新版下载完成后，运行实例和设置页继续使用当前版本的声明、字体资源及值。等应用按既有规则重启切换版本，再使用新声明核对设置；不提前把新版字段发送给旧进程。未运行插件按现有更新机制完成版本切换后，同样核对新声明。设置不是额外的发布门禁，不增加逐层确认或批次状态机。

| 新版声明发生变化 | 处理方式 |
| --- | --- |
| 新增字段 | 已有值保留，新字段使用新版默认值 |
| 修改标题、说明、分组位置 | key 稳定，保存值保持原样 |
| 修改默认值 | 已保存值保持；尚无保存值的字段采用新默认 |
| 移除字段 | 从新表单和下发快照移除，旧存档保留在有界备份中 |
| 缩小范围或删除选项 | 值仍有效则保留；失效值保留存档，运行快照暂用有效默认，设置页明确提示原因与原值 |
| 删除某个预置字体 | 保存其原 ID；运行时按字体回退策略显示，设置页说明字体不可用，不依赖原插件目录的绝对路径 |
| 改 key、类型或单位/业务含义 | 优先保持旧 key 只改显示名称；确需改变时由插件提供明确转换规则，核心校验转换结果并保存旧快照，不能把它当成普通默认值覆盖 |

核心区分“保存的用户值”和“按当前声明计算的有效值”。临时字体缺失、选项失效或不支持的字段不会把用户原始选择直接擦掉；表单与运行组件展示实际回退情况。恢复默认是用户主动操作，升级本身不代表恢复默认。

第一版只需兼容的增量声明演进，暂不实现通用迁移脚本引擎。发生第一个真实的破坏性设置变更时，增加针对该变更的纯配置转换：输入旧声明版本和有界值，输出新值；核心验证输出符合新声明后原子提交，并保留上一份有效快照。转换不能启动 PTY、修改远端文件或重启转发规则。迁移失败保留旧快照、报告具体错误，禁止提交部分转换结果。

若用户回退插件版本，兼容字段继续使用有效保存值；结构不兼容的字段从上一份相应声明可用的快照恢复。这里规定设置恢复行为，不增加自动回退插件程序的发布框架。

新版声明启用后，旧设置页面携带的声明版本和 baseRevision 会失效，核心拒绝该次旧保存，保留窗口草稿并要求载入最新页面。旧进程迟到通知同样按进程实例及修订检查丢弃。

## 8. 验收行为

### 组件设置宿主

1. 无服务器连接时，设置中可打开四个已安装组件页面，关闭的插件也能配置静态偏好；全过程没有新增业务进程或 SSH/PTY/SFTP/转发资源。
2. 同一文件插件提供文件列表与编辑器两页；不存在按插件名或终端 ID 硬编码表单的分支。
3. 插件未安装不生成入口；关闭、启动和异常退出仍可展示静态表单并说明生效状态；旧版本无设置声明时显示升级提示。重启后按保存的启用状态与核心提供的有效设置加载。
4. 修改只影响示例；保存后全部对应实例取得同一修订，隐藏/跨窗/新建实例取得最新值；其他组件保持自己的偏好。
5. 放弃和恢复默认只作用于当前组件；未保存草稿切页/关浮层可恢复，退出应用不把草稿当成有效设置。
6. 核心后端拒绝绕过前端的越界值；写盘失败保留草稿；两个窗口并发保存拒绝过期修订；声明升级和迟到通知不能覆盖新配置或新实例。
7. 设置页在三主题、720×480 和 125%/150% 缩放下可操作，长页只有正文纵向滚动，保存动作与关闭入口可达。
8. 下载待重启的插件更新时仍使用旧声明；切换新版后保留用户字号等已有值、新增字段补默认，字段移除和非法旧选项不丢原始存档。
9. 修改声明默认值不覆盖用户保存值；升级后的旧页面提交被拒绝。若后续实际引入结构迁移，须增加迁移失败保留快照和版本回退恢复的回归验证。

### 终端

1. 实际终端插件包断网后可选择三种预置字体；加载不依赖机器已安装同名字体或开发机绝对路径。
2. 自定义本机字体成功时使用实际字形；不存在时有明确反馈。已保存字体缺失后按指定回退，仍保留原选择名称。
3. 输出填满屏幕时，默认底边距至少 24px，字符和光标完整可见；改变底边距正确同步行列，不产生额外远端输入。
4. 字体/字号/行高变化不创建新 shell、不重放命令，恢复显示内容；`vim`/`top`、全屏备用屏幕、中文、emoji、ANSI 表格线及带图标提示符符合列宽要求。
5. 多 Tab、切页、移窗、输入法组合、Ctrl+C、复制粘贴和异步粘贴目标约束继续通过既有回归；打开设置不改变原 PTY 尺寸。

### 文件与网络

1. 隐藏文件过滤不丢分页元数据、不操作远端文件，过滤掉的选中不会继续被键盘操作误用。
2. 编辑器字体、换行与 Tab 显示宽度改变后，文件字节、未保存草稿、BOM、LF/CRLF 与冲突检查不受影响。
3. 新规则默认值只进入之后创建的表单；当前监听地址、端口和运行状态保持原值。

## 9. 实施顺序与验证边界

按三个可独立验收的问题推进：

1. **组件设置基础**：导航、最小字段声明与表单、核心存储/API/变化通知、统一保存动作、错误/并发与兼容；用仅测试夹具验证，不发行夹具。

3. **其他组件设置**：文件列表、编辑器和网络隧道按表格各自落地与独立发布，随后提取已出现第二个实际用例的公共辅助代码。
