# 工作台视觉体系与终端复制粘贴设计

日期：2026-11-05。状态：设计提案，未实施产品代码。基于 apple-design 的层级、空间一致性、即时反馈与平台习惯；保留 SoDeck 现有工作台结构和多巴胺主题性格。

## 1. 我对需求的理解

用户明确指出：终端复制粘贴不完善；终端页签整行及后方图标不协调；服务器工作区底栏难看，按钮粗黑边与组件之间的细黑分割线不一致；需要参照旧版多巴胺配色；样式应形成整体策略，组件尽量少定义。

据此推断，本次目标是：**建立一套能同时承载浅色、深色、多巴胺的工作台设计规则，让核心与插件呈现同一个产品，并把终端交互补到日常可用。**

这些是本方案的设计建议，不当作用户已经确认的细节：

- 保留紧凑桌面工具的密度；正文优先，工具与状态退居其次。
- 保留多巴胺的彩色块、2px 近黑轮廓、适度较粗字重和无阴影，不将所有主题都改成浅色玻璃风格。
- Apple 风格体现在对齐、分组、稳定空间关系和响应，不照搬 macOS 窗口装饰，不增加动效依赖。
- 终端默认提供符合 Windows 日常习惯的复制粘贴，同时保留终端中断语义，并适配 Linux/macOS。

本次只提交方案与交互示意。未更改应用版本、生产依赖或任何终端行为。

## 3. 整体视觉策略

### 3.1 三层关系

1. **导航层**：服务器页签、侧栏标题，回答“正在操作哪台服务器、哪个区域”。
2. **工具层**：中央组件页签和局部工具按钮，回答“当前内容是什么、能做什么”。
3. **内容层**：终端、文件树、编辑器，使用稳定实色背景，承担主要视觉面积。

底部状态栏是贯穿工作区的辅助信息层，不做第四条工具栏。菜单锚定触发按钮；关闭后回到原位置和合理焦点。左右面板标题与中央页签条共用高度和基线。

### 3.2 边框按用途定义

| 用途 | 浅色/深色 | 多巴胺 | 规则 |
| --- | --- | --- | --- |
| 结构边界：侧栏/中央、标题/正文、工作区/状态栏 | 1px 主题分界色 | 2px `#20211F` | 同一接缝只由一侧绘制，不叠成 4px |
| 独立控件：输入框、常规按钮、菜单/对话框外框 | 1px 控件边界色 | 2px `#20211F` | 轮廓围住完整交互单元 |
| 工具栏内动作：新建、列表、更多、底栏操作 | 无常驻边框 | 无常驻边框 | hover/按下使用语义底色；不逐个套黑框 |
| 同一组内的微分隔：未选页签之间、状态信息之间 | 优先间距，必要时弱分隔 | 优先间距 | 不出现装饰性的 1px 黑线 |
| 拖动分割器 | 静态沿用结构边界 | 静态沿用 2px 结构边界 | 命中区 8px；hover/focus 才显示强调反馈 |
| 键盘焦点 | 2px 焦点环 | 2px 紫色焦点环 | 焦点环不是另一圈常驻黑框 |

**保留粗边框，通过减少不必要的框控制重量。** 不能用把多巴胺所有边框改成灰色细线的方式解决。

结构线和控件边框预留统一 2px 几何预算；浅/深主题在相同盒内绘制 1px 线，多巴胺绘制 2px。可使用定位装饰线或等量透明边框，绘制方式在公共样式确定。切换主题不改变内容矩形、按钮宽度或终端行列。

### 3.3 配色分工

| 语义 | 多巴胺基准 | 使用位置 |
| --- | --- | --- |
| 画布 | `#FBF1E8` | 外围、留白 |
| 正文表面 | `#FFFBE6` | 终端、内容区域 |
| 输入表面 | `#FFFEF5` | 路径与输入框 |
| 导航强调 | `#FFB7CF` | 当前服务器页签、侧栏标题 |
| 工具强调 | `#42C69B` | 中央组件页签条；它是核心工具区语义，不按终端插件 ID 分支 |
| 选中/主要行动 | `#FFDE75` | 当前组件页签、主按钮、选中资源 |
| 状态背景 | `#D5F1E5` | 工作区底栏 |
| 正文/结构边界 | `#20211F` | 文字、必要轮廓 |
| 辅助文字 | `#62665C` | 次要信息，不用低透明度黑字代替 |
| 焦点/光标 | `#5346A6` | 键盘焦点、终端光标 |
| 终端选区 | `#C8BDF4` | 与黄色资源选中分开 |
| 成功/警告/错误 | `#176B4F` / `#7A4A08` / `#A12C38` | 搭配图标和文字，糖果色不直接充当小字号前景 |

浅色和深色沿用现有色相基础，按相同语义映射表面、选中、状态、焦点及终端 ANSI 色。跟随系统只是选择对应浅/深色板，不引入第四套几何规则。多巴胺所有工作区、菜单和按钮无投影；其他主题只允许菜单/弹窗使用克制阴影，正文不铺玻璃、渐变或纹理。

## 4. 页签整行重设计

两级 Tab 加号的旧实施方案已回退；新的范围与验收见 [Tab 新建交互方案](plan-tab-creation.md)，目前仅为提案。

```text
服务器层   [服务器管理] [● 开发环境       ×] [测试环境 ×]       全局工具  窗口控制
工具层     文件          [>_ 终端 1  ×] [>_ 终端 2  ×]     ＋  ⌄
内容层     文件树        终端正文
状态层     ● 已连接  dev@server:22                   ↓ 12 KB/s  ↑ 2 KB/s   ⋯
```

- 服务器层保持 44px；内部组件页签条和侧栏标题统一 36px。页签底部与内容衔接，活动页签使用完整的顶部/侧面轮廓与选中底色，不再叠加彩色上下指示线。
- 服务器与组件是不同层级，使用相同排版规则及主题语义，不做两套随意的 Tab 组件。
- 组件页签基准高度 30px，左右内边距 10px；文字 12px，主题字重 500/600。页签建议宽 112～200px，长标题截断且可查看完整名称。
- 当前页签有明确选中表面；未选项透明、无独立边框，用间距组织。关闭图标常驻，固定命中位，不随 hover 出现导致标题跳动。
- 右侧动作固定为“新建组件页面”“全部组件页面”，均为同一 SVG 图标体系，图标 16px、命中盒 28px、间距 4px。组件类型选择保留现有创建菜单；不把通用“＋”硬编码成“新建终端”。
- 全部动作从同一中线对齐；hover/focus 仅改变自身底色，按下即时反馈。不得移动整条工具栏、iframe 容器或内容区域。
- 页签多时只有页签列表横向滚动，右侧动作保持可见；列表菜单仍可完整访问所有页。支持现有排序及关闭检查，不新增分屏功能。

## 5. 服务器工作区底栏重设计

- 高度从 26px 调整为 **32px**，正文/状态字 12px，水平留白 12px；内部操作使用 28px 高的 `status-action`，不继承普通 32px 按钮。
- 左侧是一组连接状态和 `user@host:port`，仅作展示；右侧为收发速率。速率使用等宽数字与稳定最小宽度，更新时不挤动其他内容。
- 连接状态不打开弹出菜单，底栏也不提供“断开连接”和“更多”入口。“重新连接”在断线时原位显示为明确的文字动作。
- 底栏不显示“主窗口/独立窗口”。速率仍能打开现有应用状态信息，不改变统计归属。
- 窄窗口将端点末尾省略，并隐藏速率；连接状态和断线重连一直可见。完整端点可通过悬停提示查看。
- 多巴胺底栏统一浅薄荷底，顶部只有一条 2px 结构线，内部没有独立黑框和竖线。

终端的“远程终端 · 已连接”不再常驻第二条状态栏，避免上下重复。PTY 结束、输入失败、显示恢复中等**终端专有状态**在终端内部用共享通知样式就地展示；它们不能覆盖或冒充整台服务器的 SSH 连接状态。文件插件仍可显示其未保存/冲突等业务状态。

## 6. 终端复制粘贴行为

建议以 Windows 易用规则为默认，Linux 保留标准终端组合键，macOS 遵循 Command 键习惯。具体默认值是本次建议；旧版行为仅供参考。

| 操作 | Windows | Linux | macOS |
| --- | --- | --- | --- |
| 有选区复制 | `Ctrl+C`、`Ctrl+Shift+C` | `Ctrl+Shift+C` | `Cmd+C` |
| 无选区中断 | `Ctrl+C` | `Ctrl+C`，有选区也维持中断语义 | `Ctrl+C` |
| 粘贴 | `Ctrl+V`、`Ctrl+Shift+V`、`Shift+Insert` | `Ctrl+Shift+V`、`Shift+Insert`；`Ctrl+V` 保留给远端 | `Cmd+V` |
| 打开本地菜单 | 右键、`Shift+F10`、菜单键 | 同左 | 右键/辅助点按；键盘入口适配系统 |

所有平台都提供明确“复制 / 粘贴 / 全选”菜单，并标出当前平台快捷键。无选区时复制禁用；断线/终端退出后仍能复制已有正文，粘贴禁用并说明原因。

行为约定：

- 拖选、双击选词、三击选行沿用 xterm；不默认“选择即复制”或“右键立即粘贴”，避免无意覆盖剪贴板或输入。
- Windows `Ctrl+C` 有选区时只复制，不发中断。成功后清除同一份选区，下一次可中断；失败保留选区。复制在触发时取文本快照，不清掉异步等待期间新建的选区。菜单复制复用同一动作。
- 在远端程序启用鼠标报告时，普通鼠标动作继续交给远端；`Shift+右键`打开本地菜单、`Shift+拖动`进行本地选择。菜单打开后按键和点击不能穿透到远端。
- 粘贴只接收纯文本，交给 `terminal.paste(text)`，遵循 xterm 换行及 bracketed paste；复用现有有序输入队列，不额外添加 Enter、不裁正文、不双发。剪贴板自带换行仍可能被远端执行，不能承诺“多行绝不执行”。本轮不加多行确认或命令审查流程。
- 触发时记录 viewId、挂载身份、连接代次与焦点；剪贴板异步返回后，若已切页、失焦、移窗、关闭或重连，丢弃该次粘贴，不能发送到新的活动终端。返回原页也不自动补发。
- 同一粘贴手势的快捷键与浏览器事件只处理一次；同一视图最多一个在途读取。IME 组合中、AltGr 或无关控制键不抢占。打开菜单不预读剪贴板。
- 空剪贴板不操作；读取/写入失败就地说明，不能显示假成功；256 KiB 输入队列限制保留，超限整次拒绝并说明未发送。
- `Esc` 关闭本地菜单并归还原终端焦点，不再发一次远端 Esc。粘贴菜单先关闭、恢复原终端焦点，再校验原目标并输入。

终端插件负责选区、键位、目标有效性与 xterm 输入；系统剪贴板访问由核心通用服务承接，文件路径复制可复用，满足已有第二个真实用例。此服务不引入插件授权流程。

当前 UI 桥只有 `clipboard-write` iframe allow，没有可用的核心剪贴板服务。原生读取方式需在实际 WebView 核实后确定；不以添加 iframe allow 就承诺跨平台可靠。若需要 Tauri 官方 clipboard 插件等新生产依赖，实施前单独说明用途、维护状态和宿主 Web API 替代方案。本方案不新增依赖，也不把大段剪贴板文本直接塞入有 24 KiB 限制的控制 RPC；宿主提供现有上限内的分块读取/写入，插件最终一次交给 xterm。

## 7. 样式如何收敛

采用三层，避免为这次改造建立发布框架或生成系统：

1. **主题定义**：集中到 `src/themes.css`。维护颜色和外观参数，例如 `--sd-stroke-structure`、`--sd-stroke-control`、`--sd-icon-stroke`、`--sd-control-weight`、`--sd-shadow-overlay`，以及终端背景/前景/光标/选区/ANSI 16 色。只有这一层知道主题 ID。
2. **公共界面规则**：`src/ui.css` 维护 button 的 normal/primary/quiet/icon/status 变体、tab-strip/tab、panel-header、status-bar、separator、menu 和 inline-notice。集中定义尺寸、留白、圆角和各状态。页签、按钮和状态栏已经在多个真实位置存在，值得抽取；不预建未来未用的组件。
3. **业务布局**：核心与插件的组件 CSS 只表达排列、伸缩、溢出、业务密度和 xterm/编辑器适配。无需设置主题分支、裸色值、描边厚度或重复交互状态。

补充约束：

- 基础 `button` reset 不再代表“所有按钮都带框”；具体语义变体决定是否绘制轮廓，移除多巴胺对全部按钮的宽泛修补。
- 通过已有 mount/themeChanged 传递解析后的颜色和外观参数，插件使用同一份公共 CSS。插件构建时从仓库内公共来源复制并随自身包分发；核心打包不依赖任何插件构建，运行时不引用开发机路径。
- 新主题字段为 UI v1 增量，保留旧字段及含义；旧插件忽略新字段，新插件在旧核心缺字段时使用公共默认值。若新增剪贴板服务，显式报告宿主能力/最低版本；不伪装为已有 RPC，不直接调用其他插件。
- 不要求所有历史第三方插件立刻换肤；本轮保证核心、终端和文件这些现有使用者一致，记录旧插件兼容范围。
- 远端真彩色及标准 256 色保持原语义；默认 ANSI 16 色按主题校准。主题切换只更新现有 xterm 调色板，不重建终端、重连或清选区。
- CSS 层顺序继续在入口显式声明；正式 Vite 产物也要验证，避免再次出现开发正常、打包后主题失效。

## 8. 排版、反馈与可访问性

- 系统 UI 字体，正文 13px、辅助 12px；终端保留现有 13px 等宽默认值，本轮不改用户字号。避免 10px 底栏和以字形代图标。控件圆角 8px、浮层 12px、对话框 16px。
- 常规按钮 32px，工具命中盒 28px，页签条 36px；4/8/12/16px 间距阶梯。图标统一 16px、工具轨可用 18px，主题控制笔画 2/2.25px。
- pointer-down 即时显示按下反馈；hover/颜色反馈约 100ms，菜单约 140ms。菜单围绕触发点进出，不弹跳、不锁输入；复杂可拖拽弹簧不在本次范围。
- 减少动态时取消位移/缩放，保持即时状态变化；减少透明时使用实色。高对比模式使用系统语义色与明确焦点。
- 正文目标对比度 ≥4.5:1，可辨识控件/焦点 ≥3:1。当前与异常状态同时有文字/形状，不靠颜色独占含义。
- 宽度至少验收 1280、1024、800、640px，100/125/150/200% 缩放；真实桌面窗口最小尺寸以现有约束为准。方案内嵌预览可在更窄宽度折叠侧栏，不据此宣称产品支持 320px 窗口。

## 9. 实施顺序与可验收结果

每项是一个完整可验证主题，避免混成一个巨型提交。

1. **公共外观基线**：落地主题与公共规则、共享给插件。三主题所有必要结构线一致、无双线；切换前后面板矩形和终端行列相同；核心构建不依赖插件。同步 README、产品和架构/插件 API 文档的实际变化。
2. **工作台整行**：迁移服务器/组件页签、右侧图标、侧栏标题和分割器，再完成底栏。断线重连仍可直接访问；长标题、多页签、窄窗、拖动、关闭及移窗行为不回退。文件插件迁移公共规则，确保相邻区域一致。
3. **终端复制粘贴**：先在当前实际包复现快捷键/菜单/iframe/焦点问题，再实现通用剪贴板服务和终端操作。以无害输入接收器核对 UTF-8 字节、顺序与次数，添加稳定缺陷的回归测试。
4. **产品验证与独立分发**：按现有入口执行 `npm run check`、`npm run scripts:test`、`npm run test`、`npm run web:build`、`npm run ui:test`、`npm run terminal:test`，以及修改到的独立插件构建。之后运行核心实际打包与 GitHub Actions 五个原生系统/架构的编译、打包和包内启动/退出；不能以本机预览或交叉编译替代。

关键验收：

- 三主题 × 正常/hover/按下/focus/禁用/断线，页签关闭位不跳动、按钮不突破底栏、SVG 笔画一致；125/150% 缩放无双边和错位。
- 核心及插件在持续输出、选区和文件草稿存在时切换主题；不重建会话、不改真实输入、保留滚动与草稿。
- Windows/Linux/macOS 各自键位、系统外部编辑器互拷；中文、emoji、LF/CRLF、多行、空文本、队列上限、bracketed paste 开/关。
- 有选区复制不误中断，无选区中断仍有效；一次粘贴只有一份字节。错误不假成功，断线可复制且不可粘贴。
- 剪贴板读取延迟期间切页/移窗/重连/关闭、菜单取消、IME、鼠标报告及双终端交错操作，不能发生跨目标输入。
