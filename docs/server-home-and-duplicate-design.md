# 服务器首页与配置复制设计

状态：已实现，2026-10-19。下文保留设计约定；实施与验证记录见文末。

界面已在同日按新要求调整为列表与详情分栏，当前视觉方案见 [服务器界面第二版](server-ui-refinement.md)。本文的复制、连接和数据规则继续适用。

## 1. 需求理解

用户提出“服务器连接列表展示太小”“首屏可以优先看到列表”“缺少复制服务器配置”。对应的实际需求是：

- **看得清、找得快**：服务器名称、地址、标签和操作有足够空间；扩大区域的同时改善字号、行高和信息排列。
- **打开即可开始工作**：启动时首先选择服务器，不必从空终端再打开选择弹窗。
- **复用已有配置**：相似服务器通常只需更换名称、地址，账号、认证、跳板等信息应该能继承，保存为独立副本。

核心路径：启动 → 查找服务器 → 连接；找到相似配置 → 复制为新服务器 → 修改少量字段 → 保存或连接。

本方案针对本地已保存的 SSH 服务器配置。“复制”定义为应用内创建配置副本；不等同于导出、分享、复制到剪贴板或新建同一服务器的会话。

## 2. 改造前的实现依据

- `src/App.tsx`：`pickerOpen` 初始为 false；无会话时展示空工作区和“打开一个 SSH 连接”欢迎内容。
- `src/server-picker.css`：选择弹窗宽度 44rem，列表最高 45dvh。结合当前 14px 根字号，弹窗约 616px 宽、名称约 13px、地址约 11px。
- `src/ServerPickerDialog.tsx`：已有搜索、标签、连接、编辑和删除；没有复制，管理操作集中在底部和右键菜单。
- `src/types.ts`：搜索目前覆盖名称、地址；配置包含认证方式、私钥路径、跳板和直传地址。
- `src-tauri/src/model.rs`、`db.rs`：前端只能获知是否保存密码，不拿到密码正文；新 ID 配合 `passwordChange: keep` 不会继承源服务器密码。

## 3. 推荐方案：常驻服务器首页

### 导航和生命周期

- 主窗口顶部最左侧固定一个不可关闭的“服务器”入口，后方继续排列 SSH 会话标签。
- 启动默认激活服务器页，列表占据主内容区；未连接时不再展示空文件区、空资源区或大面积欢迎文案。
- 顶部“＋”返回服务器页并聚焦搜索，继续承担选择另一台服务器的入口。
- 连接成功进入会话；点击“服务器”返回列表，已建立会话继续运行。关闭最后一个会话自动回到列表。
- 保留端口转发、本地日志、终端历史和设置入口。本次改造主窗口，独立 SSH、编辑器、日志等窗口保持各自流程。

### 列表结构

| 区域 | 内容 |
| --- | --- |
| 页标题 | 服务器、配置数量、新增服务器 |
| 工具栏 | 搜索名称 / 地址 / 用户名 / 标签；标签筛选 |
| 主列表 | 名称与标签、地址与账号、连接路径、本窗口会话状态、连接和管理操作 |
| 必要反馈 | 加载、连接结果、保存结果、筛选无匹配等 |

- 宽屏采用对齐的列表行：名称 16px，地址和账号 14px，次要信息不低于 12px，行高约 76–84px，控件约 36px 高。扩大可用区域，同时提高可读性。
- 列表填满剩余高度，取消 45dvh 上限；列表滚动时工具栏保持可用。不增加大面积统计卡片或常驻详情栏。
- 860px 最小窗口宽度下把路径、认证并入次行；保留名称、地址、连接、更多操作，不出现整页横向滚动。
- 名称合理换行；长地址可复制，截断时能查看完整内容。标签直接显示两个，其余以 +N 提供完整展示。
- 默认按名称自然排序，状态变化不突然移动行；保存后采用同一排序规则。
- 搜索不区分大小写，多关键词按 AND 匹配，空白查询等同全部。
- 500 条配置作为首期性能验收规模；根据实测决定是否复用已有虚拟列表能力。

### 连接行为

- 单击选中，双击或行内按钮连接；搜索框按 Enter 连接当前选中项，列表支持方向键选择。快捷键仅在服务器页内生效，不拦截终端输入。
- 本窗口已有可用会话时主按钮显示“进入会话”，进入最近激活的一个；“更多 → 新建会话”建立额外连接。仅有断开会话时仍显示“连接”。
- 状态为“未连接”“连接中”“已连接 · N 个会话”“连接失败”，明确描述本窗口会话，不等同于服务器在线或离线。独立窗口会话首期不计入此统计。
- 发起连接先保留服务器页显示进度，指纹与认证沿用现有流程；成功切入会话，失败保留筛选、选择和滚动位置并支持重试。
- 延续当前一次一个待认证连接的模型，连接期间允许浏览和查找，暂不并发发起第二个连接。
- 等待期间用户主动切换到其他会话，后续连接成功只更新状态，不夺取焦点。

## 4. 复制配置：先编辑，再创建

### 入口和流程

1. 每行提供可见“复制”操作，右键和“更多”菜单也提供“复制配置”；窄窗口归入“更多”。
2. 打开“复制服务器配置”表单，显示来源并预填字段，不立即写入数据库。
3. 默认名称“源名称 - 副本”，同名时建议“源名称 - 副本 2”等；首次聚焦并选中名称。
4. 用户修改后点击“保存副本”或“保存并连接”；取消不创建记录。
5. 保存生成全新 ID，源配置与当前会话不受影响，副本后续可独立修改和删除。
6. 保存后选中新记录；若当前筛选隐藏了它，提示“副本已保存，当前筛选下不可见”，提供“查看副本”明确调整筛选，不静默清空搜索。

同地址可能有不同账号、认证或跳板路径，因此不以 host + port 拦截“重复配置”。名称建议避免重复，但沿用现有名称非唯一的数据规则。

### 继承规则

| 内容 | 默认规则 |
| --- | --- |
| ID | 保存时创建全新 ID |
| 名称 | 建议副本名称，可改 |
| 地址、端口、账号、标签 | 复制，可改；改副本不改源配置 |
| 认证方式 | 复制 |
| SSH Agent | 复制方式，不复制 Agent 内的密钥和临时凭据 |
| 私钥 | 复制本机文件路径，不复制文件正文，连接时校验可用性 |
| 已保存登录密码 | 源使用密码认证且保存了密码时，默认勾选“复用已保存的登录密码”；可取消或输入新密码 |
| 未保存密码 | 显示“连接时输入密码”，不伪装成已有可复用密码 |
| 临时密码、私钥口令 | 不继承上次会话临时输入 |
| 跳板机 | 保留对同一跳板配置的引用；不复制跳板本身，也不修改其他服务器对源配置的引用 |
| 直传地址、端口 | 初始继承；修改目标 SSH 地址后，清空尚未手动编辑的继承直传地址、端口重置为 22，并明确提示重新填写；手动编辑过的值保留 |
| 会话、历史、日志、传输任务 | 不复制 |
| 转发规则、Docker/Compose 关联、NetBird 任务等 | 不自动绑定到副本 |
| 主机指纹 | 不新增信任记录；仍按网络范围 + 地址 + 端口检查，相同端点可复用已有信任，新端点走首次确认 |

复用密码由 Rust 在保存时读取源配置当前已保存的密码，创建独立副本，原密码不返回前端。以后修改源密码不会同步修改副本。切换认证方式时关闭不适用的密码继承选项。

“保存并连接”先持久化再连接。连接失败保留已保存副本，重试不再创建新记录。

### 异常规则

- 取消或未保存关闭不落库；仅用户实际修改草稿后触发现有未保存提示。
- 提交期间禁用保存按钮，防止连点重复创建；必要时增加单次提交请求 ID。
- 源已删除：保留草稿并提示重新选择来源或按普通新建保存，不回退为更新源记录。
- 保存时源密码已被移除：提示选择连接时输入或填写新密码，不静默声称继承成功。
- 跳板被删除或变为不合法：标出问题、保留草稿，不静默改成直连。
- 沿用现有字段校验；保存并连接之前还需要检查用户名。

## 5. 空态和状态保持

- 初次使用无配置：页内“添加第一台服务器”及新增按钮，不同时展示多个空面板。
- 加载中：展示加载反馈，读取完成前不误显示空列表。
- 筛选无结果：保留输入，提供清除筛选，不切成首次使用引导。
- 数据库失败：沿用明确错误和已有恢复入口，不当成空列表。
- 返回首页、取消编辑、连接失败保留查询、标签、选择及滚动位置。重新启动默认显示全部，不沿用可能隐藏记录的过滤条件。
- 编辑与删除保留现有会话及关联检查；复制正在使用的源配置应当允许。

## 6. 首期范围和技术拆分

首期包括全尺寸首页、固定入口、列表可读性、搜索范围、连接状态、配置复制、凭据继承、保存并连接，以及上述空态和异常。

收藏、最近使用、拖拽排序、文件夹分组、批量复制、模板、导入导出留作后续候选。继续使用已有标签，避免同时增加另一套分组体系。

前端建议：提取 `ServerCatalog` 复用列表，新增 `ServerHome`；`App` 明确区分首页和会话，固定入口不计入会话数量和迁移拖拽。切换页面保持 `WorkspaceSession` 挂载，返回时重新适配终端尺寸。`ServerEditor` 区分 create / edit / duplicate，复制模式不提交源 ID 作为目标 ID。列表状态与连接生命周期分离。

原生建议：新增 `duplicate_server(sourceId, draft, passwordPolicy)`，目标草稿不带 ID，密码策略为继承 / 新值 / 不保存。复用主窗口权限、配置锁、字段与跳板校验；Rust 强制创建 UUID，读取源与写副本放在同一受保护流程中。仅返回 `ServerView`，不能仅靠前端清空 ID 并传 keep 来复制密码。首期复用现有表，无需为首页和复制新增字段。保存成功才刷新列表，失败保留草稿。

## 7. 验收

1. 启动直接看到服务器列表，无需额外点击；无空终端或文件区挤占空间。
2. 1360×860、860×580 及 Windows 125%/150% 缩放下内容可读、操作可用、无重叠和整页横向滚动。
3. 首页 → 会话 → 首页 → 原会话保持连接、输出及目录状态；关闭最后一个会话回首页。
4. 筛选、失败、取消编辑保持上下文；进入已有会话与新建会话可区分。
5. 副本与源 ID 不同；源不变，副本重启后仍在。
6. 覆盖密码保存/未保存、Agent、私钥、跳板、直传地址变化、源删除、源密码移除和连点提交。
7. 密码不进入前端响应、日志或剪贴板；源后续修改不影响副本；指纹校验仍正确。
8. 取消不落库；保存并连接失败只保留一份配置，重试不新增。
9. 编辑、删除、认证、标签、转发、独立窗口迁移及未保存提示无回归。
10. 500 条模拟配置、长名称、IPv6、长标签、空结果和数据库错误下验证可用性。

前端逻辑测试覆盖草稿、筛选与名称建议；Rust 测试覆盖独立复制与密码继承；扩展现有 Playwright 连接与数据库流程；真实 Windows 桌面验收缩放、焦点、会话保活与认证弹窗。


## 11. 实施记录（2026-10-19）

- `ServerHome` 替换原服务器选择弹窗；首页常驻，SSH 页面通过可见性切换保留实例。顶部首页入口不参与会话拖动、关闭或迁移。
- 普通连接进入本窗口最近访问的已连接会话；“新建会话”显式创建额外连接。只保留一个待连接流程，认证弹窗通过 portal 呈现，返回首页也能完成认证。
- `ServerEditor` 增加复制模式、密码继承开关、保存并连接及来源失效恢复。新配置受当前筛选隐藏时显示“查看配置”，主动点击后清空筛选并定位记录。
- `duplicate_server` 接收来源 ID、配置草稿及明确的密码策略；由 Rust 分配新 UUID，并在现有配置锁下读取来源和事务保存。无数据库结构变更；不克隆任何任务、历史、会话或转发规则。
- Windows 单元测试沿用项目 `tests/port-forwarding/common-controls.manifest` 的 Common Controls v6 清单处理方式。应用安装包本身已带此清单。

验证范围包括前端单元测试、Rust 数据库测试、Chromium/WebKit 连接与窗口交互、数据库异常恢复，以及 500 条配置在 1360×860、860×580 和 688×464 有效视口下的深浅主题布局。浏览器测试使用明确的 IPC 模拟；这不等同于真实服务器 SSH 验收或 Windows 系统级缩放测试。
