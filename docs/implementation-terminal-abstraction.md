# 终端会话与显示抽象实施记录

2026-11-09。对应[设计](plan-terminal-abstraction.md)。本次重构现有终端，Docker 留到后续；实际包与发布来源统一见[0.15.0 发行记录](releases/v0.15.0.md)。

## 实现

核心新增可选 `terminal.session.v1`：open 接收创建时 Context、互斥启动方式及初始尺寸，status 查询原会话，close 请求关闭并返回真实状态。PTY 和 shell/exec 分别等待 SSH 成功响应；拒绝不进入默认 Shell，未确认的启动结果为 unknown。普通关闭、断线和退出状态保留区别；只有退出码/信号才确认直接启动对象结束。历史 Replay 归逻辑 view，执行收尾不会释放历史；重连使旧执行失效，关闭 view 或停止插件才回收全部资源。

终端插件 `src/session.rs` 负责每 view 一次异步准备、Shell 集成、能力与重开策略；`main.rs` 仅处理生命周期和事件。共享 `plugins/shared/terminal` 提供 xterm、输入/尺寸队列、快照、外观、剪贴板和会话状态适配。它不生成启动命令、不安装宿主机目录模块、不固定业务重开目标。独立包携带共享源码、字体、xterm 和许可，原重复前端源码已删除。

StateHub 分别保存插件 `terminal.session.v1/current` 和核心 `terminal.runtime.v1/<id>`。本地修订为十进制字符串，较晚的 status 旧回复不能覆盖新终态。订阅失效时停止缓存输入，并以有界查询恢复；普通运行不常驻轮询。发布失败不把已创建的 Shell 改成准备失败。原数据桥继续有序交付末尾正文和 end，closed 先到不会丢弃尾部。

文件跟随先识别活动 view 的会话描述、同源位置能力和 PTY，再使用原文件系统证据检查；旧宿主机位置协议保留在一个兼容 helper。无位置能力时保留手动浏览，不能通过其他提供方同名路径猜测文件系统。组件 openView 重试沿用原 surface/request 身份，二级加号仍创建默认终端。

## 验收

本机类型/核心与插件格式、核心普通套件、92 项脚本、真实 xterm 输入/剪贴板/尺寸/外观、OpenSSH 实际终端界面及 Windows 三插件目录联动已通过。新增核心契约用例证明：重复 open 不重启、启动计划/Context 冲突拒绝、显式启动失败不回退、启动中取消保留 unknown、结束历史可读、退出码与无退出证据不同、重连后历史重挂载但旧输入拒绝。

共享显示反例使用无目录能力、不同目标标签及“重新进入测试目标”动作，实际 xterm 保留尾部并交给提供方的 viewType/params；没有引入第二个业务插件。适配器回归覆盖乱序修订、晚到恢复、原 Context 历史和能力识别。自动 Bash/Zsh 与五平台原生实际包验收结果以发行记录为准，未执行前不计为通过。

本机测试曾因同时构建正在运行的 catalog-fixture 遇到 Windows 文件锁；顺序执行后通过。静态 Impeccable 扫描未报告源码匹配问题，解析页规则未运行；已查看实际终端与三插件联动截图，保持原布局、主题和菜单。

## 边界

核心 API 主版本仍为 1，保留旧 terminal.open/close 和正文桥。新终端 0.5.0 要求核心 0.15.0 的能力，缺少时明确提示升级并沿用核心初始化回退。文件 0.7.0 兼容旧宿主机提供方；没有新增生产依赖或修改 Shell 启动文件。

本次没有实现 Docker、其他连接协议、本地 PTY、跨文件系统路径映射、持久会话或自动恢复进程。关闭通道或本机 worker 结束不能证明任意远端子进程退出。用户自定义服务器、所有 Shell 配置、DPI/多屏、netem 与历史版本对在线升级不由本机常规测试证明。
