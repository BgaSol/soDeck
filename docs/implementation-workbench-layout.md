# 工作台分屏与多窗口实施记录

日期：2026-11-09。状态：工作台实现与五目标发行包验收完成；发行核心 0.17.0、终端 0.7.0、文件 0.8.0、网络隧道 0.3.0、系统状态 0.4.0。目标范围见[完整设计](plan-workbench-layout.md)，可调用契约见[插件 API](plugin-api.md)，日常操作见[使用指南](usage.md)。

## 源码改动

- 统一工作台状态域：工作区 Context 与窗口显示部分分开；窗口投影从实际 Host 布局取得页面，连接与资源仍使用插件/view/Context 归属。
- 中央嵌套左右/上下二分树、独立标签组、空组、排序/移组/合并、组临时放大、工具中央/两侧停靠；同窗布局保留 iframe。
- 有效布局按整棵树递归计算 280×180 CSS px 的组尺寸与 6 px 分隔线；夹紧实际比例、临时收起侧栏、空间不足显示焦点组，扩大后恢复保存的树。工具可直接拖回侧栏，缺失插件的中央/侧栏位置显示不可用占位。
- 页面、标签组和整份工作台的跨窗交接：只读目标准备、源端 flush、调用和 PTY 队列排空、目标最终状态与输出水位恢复、共同提交和失败取消。正常移动保留实例；回执处理重试、参数冲突、完成与过期。
- 统一页面、组、Host、窗口、全服务器与应用关闭；局部冻结，单例工具在局部关闭时返回仍存在的显示部分，失联窗口恢复原 view。
- 终端、文件、网络隧道、系统状态四个外置插件声明 UI v2，并将 create/get、桥通道、候选只读、激活与 flush 接到既有业务实例。插件各自独立打包，不放入核心包。
- 页面交互更新服务器焦点；文件跟随最近操作的终端。核心返回已有工具/文件所在窗口，入口通过原生定位显示。
- 独立 `workbench-layout.json` 保存服务器与稳定布局槽的分屏结构、比例、工具定义位置和窗口尺寸；布局内容不含连接身份、viewId、正文和命令。主动连接恢复首份结构，菜单显式恢复额外窗口；损坏/未知版本保留原文件，正常保存保留上一份备份。
- Windows 跨窗落点使用系统窗口命中排除遮挡；物理坐标不按主屏 DPI 换算。Wayland 同窗使用 WebView 局部坐标，跨窗继续使用菜单。
- 运行期返回书签保存来源窗口、原组、前后邻接标签和工具侧栏；返回优先还原来源，失效时按仍有效的默认 Host 回退。默认 Host 替补按该工作区的显示部分创建顺序选择，不按窗口名称或旧窗口创建时间选择。
- 页面和整组可以选择已有独立窗口；工具菜单提供中央、左右侧栏、新窗口、其他窗口和返回来源。入口的展开状态与隐藏操作读取实际停靠位置，移动不修改新建工具的默认停靠偏好。
- “此窗口全部返回主窗口”在同一状态锁内准备所有 Host，任一准备失败取消全部成员；共同提交先验证和预演全部工作区，再一次更新运行期与 Surface。移走最后内容后回收空独立窗口。新窗口按来源组或工作台估算尺寸，限制在屏幕可用区域；返回显示并取消主窗口最小化。
- 紧凑显示与组切换入口汇总隐藏组的未保存和错误标记。原生边缘落点先预演树的最小尺寸，空间不足时拒绝新增分屏。
- 布局保存从统一状态锁内取得快照，由独立 IO 锁串行比较、备份和原子写入，磁盘操作不持工作台状态锁。

## 本轮复现与修正

1. 重复打开已有页面的回执遗漏 windowId，第一次与重试结果结构不同；共同登记路径现在都返回实际位置。
2. 页面拖拽捕获了标签外层和组菜单按钮，导致正常点击被重定向，拆分菜单打不开；标签在选择按钮捕获，组/面板按钮保留普通点击。新增真实浏览器分屏流程验证。
3. 普通插件事件与 Surface 归属检查分离，移窗排空可能遗漏已接纳调用；在统一状态检查时登记调用，冻结旧表面后等待实际调用结束。
4. 终端/网络旧测试直接提交工作区注册表，绕过实际 View/Surface 交接；测试改走生产共同提交，保持旧表面输入拒绝的断言。
5. 窗口级 Surface 层被后渲染的工作台背景遮住，正文不可见；明确 Surface 层级，并断言真实 iframe 的非零尺寸及中心点命中，重新检查三主题截图。
6. 默认行为创建中的按钮没有反映创建状态，未送达请求还会留下本地 pending；创建期间禁用，超时显示并查询原回执，确认未接纳后允许重试，保留传输不确定时的原请求。
7. 整工作台返回时空目标容器和原树组 ID 相同，合并错误地报重复；空容器先替换，只有保留两棵有内容的树时检查重复，新增保留原树/拒绝真正重复的回归。原生烟测改走正式宽度设置接口，比较真实 Host 投影。
8. 文件插件将普通草稿同步当作移窗冻结，导致后续下载按钮无法操作；UI v2 的 flush 明确 freeze 字段，普通同步保持输入，迁移/关闭冻结后等待激活或取消；终端对冻结/只读阶段同时停止 resize。增加同步后输入、冻结拒绝和取消恢复的真实 xterm 回归。
9. 整组移入空窗口时，准备阶段保留组结构，最终提交的重投影遗漏无指定目标组的分支，导致组和页面位置丢失。准备和提交现在均合入完整组，保留组 ID、顺序、活动页和返回书签。新增回归曾在持锁断言失败后因清理过程再次 panic，表现为 Windows `0xc0000409`；断言改用脱离锁的快照，修复后以默认并发执行的完整组件套件通过，没有通过串行或忽略测试绕开。
10. 单例工具停靠到另一侧后，入口与隐藏仍读取默认 preference，无法正确关闭实际面板；共同布局命令与前端入口改为读取实际 dock，新增核心和真实浏览器回归。
11. 新增原生指针验收起初使用 inspector 的 100% 视口计算物理屏幕落点，而本机原生显示器是 175%，实际点中了不同入口。验收驱动改为 `GetDpiForWindow` 和客户区原点，验证按下事件命中指定页面，再用真实系统鼠标拖动；只操作该测试进程的窗口并在完成后恢复鼠标位置。失败报告会覆盖旧成功结果，避免沿用旧程序或旧运行的通过状态。

## 实施差异与待验收范围

- UI v1 基础布局继续兼容；页面、组和整工作台的跨窗入口统一要求 UI v2，含旧工具的局部关闭若需跨窗返回，会提示升级插件或关闭服务器全部工作区。
- 当前保存采用独立 IO 锁同步串行写入，没有异步合并队列；比例拖动仅在松手时提交，焦点和数据变化不改写相同布局。慢磁盘可能延长一次布局命令的返回时间，但不会占住统一工作台状态锁。
- 五个正式系统/架构的原生安装包、启动退出与实际包远程组合已完成；真实副屏混合 DPI、macOS Spaces/全屏和 X11/Wayland 手势仍未验收，本机 Chromium 与 Rust 测试不能替代这些专项。
- macOS/X11 的跨窗遮挡仍沿用应用窗口最近焦点顺序，未通过真实 OS 前台窗口顺序证明；Windows 已接入系统命中。本轮不宣称全平台原生拖拽已经完成。
- 布局记忆不恢复终端命令、编辑文件或运行任务，不承担机器断电/插件崩溃后的业务草稿持久化。
- 没有新增生产依赖。

## 空标签组关闭补修（2026-11-09，未发布）

安装版 0.18.0 的实际日志显示，连续关闭同一空标签组时只有准备与取消记录，最后一次停在准备阶段。可验收行为：分屏后关闭空标签组应直接移除该组并结束对话框；取消后可以再次关闭，其他页面、草稿与服务器 Context 保留。

根因是输入参与窗口只从待关闭的 Surface 和将结束的工作区收集；空标签组两者都没有，`inputs` 为空。核心仅在收到输入回报时开始检查，45 秒超时也没有窗口可补报，因此永久等待。`close_prepare_internal` 现在始终登记发起窗口，沿用原有输入回报与决定流程。

新增核心回归在修复前稳定失败：输入参与窗口实际为 0，预期为 1；修复后验证取消保留空组、再次关闭成功及 Context 不变。真实浏览器回归点击“左右拆分 → 关闭标签组”，断言组和等待框消失、其他 iframe 与未保存正文保留，然后继续既有分屏与多窗口用例。

本轮 Windows x86_64 验证：`npm run check`、`npm run web:build`、`npm run scripts:test`（91 项）、`npm run test`（208 项通过、12 项按原规则 ignored）、`npm run layout:test` 全部通过。`npm run build -- --no-bundle -- --locked` 构建 release 程序成功；该程序通过 `scripts/smoke.mjs` 的隔离原生启动、工作台移窗、子窗口关闭、资料重开与退出，退出码为 0。

没有修改核心或插件版本，没有发布或替换正在运行的安装版；其他四个原生目标、安装包与实际插件远端专项未在本轮执行，前文发行结果不代表本次补修已通过这些范围。
