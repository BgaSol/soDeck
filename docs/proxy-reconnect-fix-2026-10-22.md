# 内网代理反复重连修复

用户报告浏览器使用内网代理时，规则持续断开重连。最新诊断运行 `c20d968f-82e5-45d6-80d9-88945baf252d` 包含 21 次两跳连接尝试，其中 20 次认证成功；后段多次在 ready 后约 12–13 秒转为 reconnecting。旧日志只保留状态变化，没有保存触发自动重连的错误，因此无法单凭它排除现场网络同时发生故障。

已在隔离 Paramiko SSH 环境复现一个与该时序吻合的实现缺陷：目标 direct-tcpip 打开超过 12 秒，`ForwardCore` 直接返回 network 错误，监督线程随即关闭所有客户端并重建整条 SSH 路径。浏览器的一个慢目标会影响其他已连接网页。

修复后，目标打开及排队受 12 秒期限约束，超时只结束该客户端并报告超时。已发出的 libssh2 请求保留原参数继续收尾，迟到的成功通道关闭，失败结果丢弃，终结通知只发送一次。libssh2 的共享 open 状态不允许同时打开下一通道，因此后续新请求可能等候收尾，但现有通道继续工作。真实传输断开、协议发送失败等仍按原策略处理。

自动重连前增加 `route.interrupted` 诊断事件，记录错误分类、来源、可用原生错误码和是否计划重试；不记录凭据、目标地址或业务正文。

验证：

- 修改前，新建的目标超时回归测试稳定复现整条路径被结束；修改后通过。
- 隔离两跳 SSH + HTTP CONNECT：一个目标延迟超过 12 秒返回 504，规则保持 ready、重连次数为 0；原 CONNECT 连接继续传输，后续 SOCKS5 请求成功，全局连接配额最终归零。
- 核心测试验证排队超时、迟到回复清理、终结事件不重复及同一 session 后续打开。
- Rust 转发专项 9 项通过，含并发、半关闭、慢读端、真实断线重连、固定身份、取消探测、IPv6 与观察者生命周期。
- Rust 默认测试 177 项通过，42 项需专用环境的测试按默认设置跳过。
