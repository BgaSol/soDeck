## 1. 问题与代码核实

用户反馈：关闭前配置确认弹窗样式错误；首次连接连续确认两次；连接表单排版、下拉透明和创建代理的边框需要重新设计。本轮实际收到两张图片，用户称“图3”的表单按第二张附件处理。用户不记得两次确认的标题，不据此认定两次都是指纹挑战。

| 观察 | 已核实原因 / 证据边界 |
| --- | --- |
| 关闭弹窗正文贴边、按钮落在左下边缘 | `connection-home/page.tsx` 向 Dialog 直接传 `p + Inline`；公共 Dialog 只给直接子 `form` 提供正文 padding，没有为这些内容建立正文和动作容器。 |
| 下拉内容透底 | `packages/ui/src/styles/components.css` 的 `.sd-search-options` 使用 `var(--panel)`；当前三主题没有 panel 颜色定义。菜单背景声明失效。目录面板也使用同一未定义变量，需一起纠正到已有 surface 语义。 |
| 组合选择框边缘被切成几段 | InputGroup 的外轮廓叠加禁用 Input/Button 的独立底色和圆角；内联创建时禁用原选择框，放大后尤其明显。需覆盖组合控件的禁用/焦点/错误状态，不能只修常态截图。 |
| 内联代理像一整张大表单嵌进另一张表单 | `.sd-inline-editor` 的单侧粗边框，叠加 `ProxyFields` 自带 FormSection 标题、节点标题、禁用选择器和重复说明；层次、缩进、主次动作不清楚。 |
| 首次连续确认 | `verify_route_node` 先要求 `HOST_KEY_REQUIRED`，信任后 `context_credential` 对未绑定 preset 再要求 `CREDENTIAL_CONFIRM_REQUIRED`。原测试明确断言 3 次信任 + 3 次 preset 确认。因此存在两段确认设计；用户那一次是否另有重复指纹通知，仍需用隔离环境复现核对。 |

## 2. 视觉方向

沿用 soft-light、soft-dark、多巴胺三主题。保留多巴胺奶油底与主要控件轮廓，但减少重复外框，以对齐、间距、文字层级组织表单。颜色继续来自主题；不增加局部硬编码颜色、玻璃透明或新的动效依赖。

使用 apple-design 的明确层级、稳定空间关系、贴近触发点的浮层、即时反馈及可访问性：节点操作位置固定，展开原位完成，取消恢复原值与焦点；状态反馈不挪动字段；减少动态时即时切换；高对比保留实底和清楚边界。

### 2.1 关闭确认弹窗

- 标准 440px 宽，自适应窄窗口；正文左右 24px、窄窗口 16px。标题、正文、按钮使用同一左右基线。
- 明确 `header / body / actions` 三段。正文到按钮 24px，按钮到底部 24px；没有额外大空白，也不贴边。
- 右对齐动作：“放弃修改”（危险次按钮）、“继续编辑”（主要按钮，默认焦点）。Esc、关闭图标和继续编辑均只取消关闭；不丢草稿。
- 正在保存、核对结果、放弃等待的既有语义保持。长内容在 body 滚动，动作区固定可达。
- 公共组件增加显式 `DialogBody` / `DialogActions`（或等价内容插槽），本轮修正关闭确认和同类无 form 弹窗；已有 identity-form 不被二次 padding。

### 2.2 连接路径和内联代理

页面内容最大宽度继续为 720px。主要分区间 24px，字段组间 16px，标签与控件间 8px；输入高度沿用 36px、按钮沿用 32px 基线。尺寸使用公共参数并允许随文字缩放。

每站使用一个紧凑区块，顺序号与类型放在标题行，右侧统一上移/下移/删除动作。下方是来源说明，再是选择控件；不重复显示多个大标题。最终目标用只读结尾行，不嵌进新增中转输入框。路径列表去掉多余 ol 缩进，与其他表单字段左边对齐。

- 内联创建只保留一个轻量容器：一致内边距和已有 field/surface 层次，去掉左侧粗竖线和重复 FormSection 标题。普通主题使用细分隔，多巴胺不再增加一圈嵌套粗框。
- 创建时原选择器不以一条禁用的大框留在上方；保留原选择作为取消恢复值，取消后焦点回“新建代理”。关闭父草稿不删除已保存代理。
- 地址与端口同行，端口基准 112px；以内容可用宽度响应，不按整个应用宽度误判。窄区域改为上下排列；认证为密码时用户名和密码跟随展开，名称在最后。
- “保存并选用”为明确主要按钮；取消为次按钮。保存中保持布局，错误紧邻字段，提交回执、重复保存和失效节点行为沿用原规范。
- 采用现有上下移动作，不增加拖拽系统。移动后焦点留在该节点操作，删除后落到邻站或添加按钮；IME Enter 不提交。

### 2.3 搜索选择器

- 弹层一律使用已有 `elevated` 实色底，alpha=1；选择器外框统一绘制，箭头无独立圆角块。只降低禁用文字/图标对比，不让内部禁用底色盖断外边框。
- 弹层紧贴触发器，宽度至少等于控件并限制在可视区；最大高度 320px，选项内部滚动。向下空间不足时向上展开；不被父级表单 overflow 裁掉。
- 在同一 WebView 的浮层根渲染，保留主题作用域。滚动/resize 时更新锚点，触发器退出可视区时关闭；不创建额外原生窗口。
- 主行名称、次行地址，选中状态带勾选标记；hover、键盘当前项、已选择项能区分，不能只靠文字颜色。保留输入筛选、空态、加载、有限 DOM 和已存节点过滤。
- 上下键/Enter/Esc、Tab 离开、点外部关闭和焦点返回使用统一组件行为。多巴胺菜单仍无阴影，软主题沿用已有浮层阴影，不引入额外玻璃材质。

## 3. 首次连接一次确认

目标是每个需要确认的 SSH 节点只出现一张“身份与登录”确认界面。不同节点分别确认；SOCKS 账号认证不冒充指纹确认。不是关闭身份校验，也不是全链只信任一次。

| 情况 | 修订后行为 |
| --- | --- |
| 未知主机 + 已保存凭据 | 同一弹窗展示主机/来源/指纹，以及“登录方式：使用此连接已保存的密码/私钥”；可改为重新输入。用户点击“信任并连接”明确同时同意当前主机身份和此路径使用所选凭据；成功后不再弹 preset 确认。 |
| 未知主机 + 没有凭据 | 同一界面显示必要密码或私钥字段；一次提交完成信任及登录输入。 |
| 已信任 + 当前上下文已有凭据 | 正常连接，不重复询问；已经保存的信任和凭据不因纯 UI 修复清空。 |
| 已信任 + 新路径上下文只有 preset | 只显示一次登录凭据选择确认，明确到达来源，不重复显示“首次指纹”。 |
| 指纹变化 | 显示旧/新指纹与既有警示；不能自动接受。按钮明确为“更新信任并连接”，当前凭据仍需在同一界面明确选择。 |
| 取消、凭据错误或配置变更 | 取消不保存未提交信任/凭据、不继续连接。凭据错误仅要求重新登录，不重复要求已完成的指纹信任；路径/凭据在提交前变化则拒绝过期答复。 |

“在此设备记住”从当前已保存凭据状态给出可见默认值；用户仍可改为仅本次 App 运行使用。不显示秘密内容。相同 `127.0.0.1` 经不同 SSH 前缀仍属于不同上下文，不能因减少弹窗而串用凭据。

除合并流程外，复现并检查同一 operation/step/fingerprint 的挑战是否被重复发布或重试两次。对同一 challengeId 去重显示，确认过程中禁止重复提交；不能按 host 文本全局去重，以免忽略不同到达路径或真实换钥。

### 核心与接口计划

- 增加公开的统一 SSH 答复入口（暂定 `auth.ssh.confirm`）：接收 challengeId、operationId、明确的信任决定、凭据选择（当前绑定/指定 preset/本次输入）及 remember。由核心从挑战读取对象、路径和指纹，客户端不得自带信任键或上下文哈希。
- 主机挑战生成时只提供所需凭据元数据和可选动作；私有挑战绑定观察到的指纹、完整已验证前缀、owner/preset revision、operation、attempt 和工作区代次。信任尚未确认前，绝不发送登录凭据。
- 用户提交后先准备不可变加密 blob，再在配置锁下重新检查挑战、路径、凭据 revision 和取消状态。host_keys 与 credential_bindings 在同一 SQLite 事务提交，失败清理未引用文件；提交成功后仅重试当前连接操作一次。不能由前端连续调用两个旧接口伪装成原子操作。
- 保持现有 SQL 表和 core v7，不重建数据库。本次为 API6 的增量接口/类型，具体 SDK minor 与 capability 在实施时分配；没有旧格式适配层。保留独立信任/凭据原语的合理用途，不将独立 API 调用等同于必须弹两张界面。
- 回执须绑定调用者和请求内容；重放相同答复幂等，冲突重放拒绝，响应丢失可查询/重试。秘密不进入日志、公开挑战或持久化回执。兼顾现有网络池与会话池认证继续。

## 6. 逐步诊断及真实故障反馈

按[诊断方案](../technical/connection-diagnostics.md)实施“简短错误 + 查看连接详情”：详情默认展开失败节点，显示此前已完成阶段、具体来源/目的/协议原因及后续未执行节点。复制报告去除秘密并保留已说明的端点信息。记录来自真实阶段完成回执，不根据最后下标推断前面全成功。

本次真实路径 `.104 → SOCKS 127.0.0.1:12021 → .25` 中，SSH 登录成功与转发通道建立，不能证明 SOCKS 服务已经可用；方法协商 EOF 只显示回复前通道关闭。远程 curl/监听表发现端口未监听是额外排查证据，不由界面擅自推断。修好诊断不等于已经恢复用户远端代理服务。

各消费者使用同一核心尝试引用；同一文件面板不重复显示红/黄同文错误，监控从被动等待补充为可解释的连接失败。不同终端/网络池的记录分开，旧快照可查；查看详情不拨号，重试仍由原插件负责。core v7 保持，详情是有界内存运行状态，安全事件复用现有观测库。与 REF 同轮执行 DIAG 和四插件自己的诊断测试。
