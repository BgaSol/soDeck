# 本地诊断使用与验证

实现日期：2026-10-21。设计依据：`app-diagnostics-design.md`。本次实现只保存本地记录和手动导出，不含上传、遥测、账号绑定或服务端收集。

## 用户怎样把日志交给开发者

1. 问题发生后进入 **系统设置 → 本地诊断**。
2. 点击 **打包日志…**，选择保存位置。默认包含最近 24 小时及最近一次未确认正常结束的运行；也可选择本次运行或全部保留日志。
3. 使用 **在文件夹中显示日志包** 找到 ZIP，再自行交给开发者。应用不会发送它。

也可以点击 **打开日志目录**，直接复制整个 `diagnostics` 目录，或 `runs` 中某一次运行的完整子目录。每次运行的 `summary.txt` 可用普通文本编辑器读取。不要求安装额外分析工具，不依赖原机器的业务数据库。

| 平台 | 常规诊断目录 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\com.sshworkspace.desktop\diagnostics` |
| macOS | `~/Library/Application Support/com.sshworkspace.desktop/diagnostics` |
| Linux | `${XDG_DATA_HOME:-~/.local/share}/com.sshworkspace.desktop/diagnostics` |

以设置页显示的实际路径为准。常规位置不可写时，尽力降级到系统临时目录中的 `SoDeck-diagnostics`，并在设置中显示；两个位置都不可写时显示“记录不可用”，不会因此阻止 SSH 等业务。若 Tauri 初始化前发生 panic，尽力写入系统临时目录的 `SoDeck-startup-<随机编号>.jsonl`；正常完成初始化会删除空的启动应急文件。

运行中手工复制可能遇到分片轮转或不完整末行，建议尽快打包 ZIP。没有正常结束标记只能说明“未确认正常结束”，不等于已证明发生崩溃。

## 开发者从文件中看什么

```text
diagnostics/
  README.txt
  latest.json
  runs/<开始时间>_<运行编号>/
    session.json
    summary.txt
    events-0001.jsonl
    events-0002.jsonl
    errors.jsonl        # 出现 WARN / ERROR 时生成的索引
    panic.jsonl         # 有界独立应急通道，通常为空
```

先看 `summary.txt` 和 `session.json` 中的版本、构建、操作系统、架构、WebView 版本、起止时间与完整性；再从 `errors.jsonl` 找到 `traceId`，检索 `events-*.jsonl`。连接错误界面的“诊断信息”可复制操作编号。异步任务通过 `taskRef`，连接通过 `connectionRef` 关联；前端 invoke 返回 `accepted` 表示请求被受理，最终结果以后台状态记录为准。

事件含 UTC 毫秒时间、写入序号、运行编号、进程编号、构建标识、模块、事件、trace/span、仓库内代码位置及白名单详情。后端时间在产生事件时采集；前端另带窗口内序号和单调时间。序号是单次运行的写入顺序，跨线程产生时间不保证严格递增。

| 范围 | 当前记录粒度 |
| --- | --- |
| 启动、退出 | 设置/数据库/服务/窗口初始化阶段，启动失败，正常退出与更新重启 |
| SSH、跳板、容器终端 | DNS、地址候选类别、TCP、握手、指纹校验、认证、PTY、就绪/关闭、取消；前后端连接 trace 贯通 |
| 文件上传/下载、远端删除 | 命令受理、任务匿名标识、状态变化，结束失败的安全错误类别和可用原生码 |
| Docker 管理、端口转发 | 命令与任务状态；主要后台失败路径记录安全错误原因 |
| NetBird、更新 | 命令调用结果与操作状态变化 |
| 编辑器、监控、窗口迁移等其余命令 | 前端统一记录命令名、耗时和结果；部分高频查询采样，不记录参数和返回正文 |
| 容器日志、终端历史 | 生命周期、历史存储错误；不复制容器日志或历史正文 |
| 前端异常、剪贴板 | 全局错误、未处理 Promise、React 错误边界、仅 bundle 位置的栈、剪贴板操作结果 |

优先保留 OS、SQLite、libssh2/SFTP 的原生码。系统没有提供数字码时，保留 `nativeKind`（如 `TimedOut`），不推断或编造错误码。外部错误原文不会进入诊断，因此有些第三方错误只有类别、阶段及代码位置，不能承诺还原所有内部细节。

## 内容与容量边界

- 不记录密码、Token、私钥、服务器真实地址、用户名、用户文件路径、终端正文、剪贴板内容或文件内容。对象引用使用带进程内私有随机盐的别名，盐不写入文件；不同运行之间的别名不用于长期追踪。
- 前端不序列化 invoke 参数、返回对象、异常消息或任意 rejection 对象；后端再校验事件名、命令名、错误类别和详情字段。
- 日志区目标上限 100 MiB，事件分片约 10 MiB。按最近 7 天清理已结束的运行和过期关闭分片；持续运行的当前分片在切换前保留。容量优先，不能保证完整保留 7 天。未知文件和链接不删除，也不打包。
- 后端队列限制为 4 MiB / 4096 项，单条事件上限 16 KiB；前端队列最多 256 项，分批传递。队列、磁盘或配额异常时明确计数/标记不完整；写入线程批量处理，不让业务等待日志落盘。
- 同状态进度和高频查询采样，状态切换立即记录。错误索引限制 1 MiB，达到上限后标记不完整，完整事件仍按正常轮转策略保留。应急记录有独立小额配额。
- 多实例独立运行目录和活动锁；维护、清理与导出使用跨进程锁。其他实例运行时拒绝全量清理。清理只操作应用管理的诊断文件，不删除业务数据或用户已导出的 ZIP。

## ZIP 一致性和失败处理

打包会请求各窗口提交前端缓冲，最多等待 2 秒；随后通过后端队列屏障提交记录，切换分片，复制固定快照再压缩。导出/清理保持互斥直到实际完成，不因前端等待超时提前释放。其他活动实例的内存缓冲不保证已提交，导出中明确说明；其文件按各自元数据截止序号裁剪。

`manifest.json` 包含 SHA-256、文件大小、快照时间、各运行的可用序号范围、缺失序号范围及完整性警告。取消或失败不覆盖已有目标文件；输出通过临时文件完成后再替换。快照暂存有 100 MiB 读取上限，可能额外占用约 100 MiB 磁盘空间，ZIP 还需要目标位置空间。空间不足时返回错误，不声称导出成功。启动会清理遗留的受管快照暂存。

Panic 独立于正常队列，保留安全位置和有限仓库内栈位置，跳过 panic payload。强制结束、断电、native crash 不保证有完整栈或最后若干事件，本版不生成内存转储。

## 构建定位

构建记录版本、Git commit、CI/工作区渠道及目标架构。前端 hidden source map 另存于 `.qa/diagnostic-symbols/frontend`，不进入 `dist` 或用户日志包。发布流水线按平台和 commit 归档 source map、PDB/dSYM 以及可用的带调试信息二进制，保存 90 天；这属于开发者构建产物，不是上传用户日志。Rust release 保留有限行号信息，跨平台符号还原能力需对应平台实测。
