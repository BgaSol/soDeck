# 文件树挂载信息与复制绝对路径

文件树中的目录如果本身是 Linux 挂载点，会显示挂载来源、使用率和容量条。容量属于整个文件系统，不是目录内容大小；不执行递归扫描。点击来源、使用率或右键“查看挂载详情”可以查看完整路径、文件系统、读写状态、总量、已用、可用和最后更新时间。

## 数据与查询

- `remote_mounts.rs` 保留 `list_remote_mounts(sessionId)` 和 `get_remote_mount_usage(sessionId, mountTableVersion, mountKeys)`，后者每次最多 16 项。工作区改由统一的 `monitor::mounts` 调度 `query_table`／`query_usage`，共享文件树和监控面板需要的结果；每次容量任务查询一个挂载点，每个实例最多两个容量任务，底层在所有窗口间限制最多两个磁盘查询。见 [资源监控](resource-monitoring.md)。
- 两个接口校验窗口对会话的所有权，沿用已验证的 SSH 路由、用户和主机密钥，建立独立查询连接，不接触交互终端。
- 挂载表取自 `/proc/self/mountinfo`，通过 exec 与 SFTP 分别读取并核对。无法确认两者的路径视图一致时不关联容量；不推测 chroot 的路径映射。
- 解析 mount ID、挂载位置、设备来源、文件系统内部根路径、类型和只读状态。路径按照 mountinfo 的八进制转义解码，不能使用桌面操作系统的路径分隔符处理远端路径。
- `/proc/self/mountinfo` 属于 procfs 的顺序生成文件，未到文件末尾也可能返回短数据块。SFTP 读取使用 4 KiB 缓冲，将 libssh2 的四倍预读限制在单个 READ 数据包内，避免后续预读偏移跳过数据或提前返回 EOF。挂载表仍完整读取并与 exec 结果核对，不通过删除校验掩盖截断。
- 绑定挂载和文件系统子卷以 `设备[文件系统内部路径]` 表达，不能仅凭内部路径认定为绑定挂载。相同路径出现叠加挂载时，通过 mount ID 与 parent mount ID 还原同路径父子链；完整、无分叉的链只展示最上层，不依赖 mountinfo 行顺序。无法证明唯一最上层时不猜测，返回带具体路径的结构化问题并隐藏该路径容量。
- 对准确匹配的目录才显示挂载摘要。普通后代不继承摘要，符号链接不标为挂载点。
- 容量通过 `LC_ALL=C stat -f -c '%S %b %f %a' -- <安全引用的路径>` 查询，只解析四个数字。总量为块数乘基本块大小；已用为总块数减空闲块数；可用使用用户可用块数。使用率为向上取整的 `已用 / (已用 + 可用)`，与常见 `df` 口径一致。保留空间可能使已用加可用小于总量。
- Rust 使用宽整数计算，IPC 使用整数字符串，前端使用 BigInt 格式化容量。零容量或无法定义的比例显示不可用。
- 表版本是完整挂载表的 SHA-256；容量查询前校验版本，查询后再次核验挂载表，防止卸载重挂后的旧结果错误归属。
- 单次远端读取或 exec 最长 6 秒，输出最多 2 MiB。SSH 连接使用现有连接层的超时和指纹校验。失败不阻塞 SFTP 目录操作。

## 前端状态与交互

挂载缓存与目录树状态独立，在 Rust 后端按已验证的完整连接身份共享。`useRemoteMounts` 从工作区统一订阅读取数据，向调度器上报已展开树中的目录路径；监控面板同时上报当前页挂载点，后端按并集去重查询。新出现的目录优先补查，所有消费者不可见时暂停磁盘查询；重新显示后补查未完成或过期数据。一次挂载表刷新完成后约 30 秒开始下一次自动刷新。无法解析的叠加挂载只在对应路径出现在当前文件树或磁盘总览时提示，不因无关系统挂载显示全局警告；已关注路径也会区分“层级无法确认”和“当前未挂载”。

失败保留上次容量并标注“上次”，悬浮提示和详情显示采样时间及错误。容量连续失败按 30、60、120 秒递增退避，上限 5 分钟；不支持的服务器每 5 分钟重新探测。手动刷新绕过退避。查询结果带采集代次及挂载表版本校验，窗口迁移重新订阅后端共享缓存，不再复制采集状态、计时器或进行中的请求。

普通目录保持原行高，挂载点增加来源行和磁盘／网络／内存图标。使用率从 80% 起橙色、95% 起红色，同时保留数字和详情文字。`proc`、`sysfs`、`autofs` 等不查询常规容量；`tmpfs` 标注内存文件系统。只读挂载仍能展示容量。

树行使用可聚焦的 `treeitem` 容器；来源与容量是独立按钮。详情操作不触发行选择、展开或拖拽，浮层通过 portal 避免被文件面板裁切，支持 Esc、外部点击、关闭后的焦点恢复及窄窗口定位。

## 复制绝对路径

菜单使用 `navigator.clipboard.writeText()` 写入系统剪贴板，复用现有文本复制方式。始终复制右键目标的 `FileEntry.path`，空白处使用当前目录。根目录允许复制，多选只复制右键目标，符号链接保留链接自身路径；不额外调用 realpath，不增加引号、换行或 Shell 转义，不修改应用内部的远端文件剪贴板。成功以短暂状态提示反馈，失败提供重试提示。Ctrl/Cmd+C 保持原有文件复制语义。

## 验证

```sh
npm test
npm run build
npm run test:mounts
npm run test:transfers
cargo test --manifest-path src-tauri/Cargo.toml --lib remote_mounts::tests
```

界面测试使用显式 IPC 模拟，覆盖 Chromium 和 WebKit 中的挂载摘要、嵌套挂载、详情键盘操作、容量过期、卸载、路径复制与失败反馈、窄窗口和自动刷新。Rust 单元测试覆盖 mountinfo 解码、只读、绑定挂载、叠加挂载、保留空间、大整数及非法容量。

真实 Linux OpenSSH 联调复用仓库已有的 Docker 镜像：

```sh
docker build -t ssh-workspace-rsync-fixture tests/rsync
docker build -t ssh-workspace-rsync-runner -f tests/rsync/Runner.Dockerfile tests/rsync
python3 tests/mounts/environment.py
# 更长的挂载表（超过单个 SFTP READ 数据包）
python3 tests/mounts/environment.py --mount-count 256
```

Windows 可在 WSL 中执行 Python 命令。脚本创建独立测试网络、SSH 容器、32 MiB tmpfs、只读卷和默认 48 个长路径挂载点，运行包括 ignored 联调测试在内的挂载测试，最后移除本次资源。仓库以只读方式挂载并复制到容器临时目录构建，Cargo 缓存卷保留。联调逐字节核对较长挂载表的 exec/SFTP 读取结果，并覆盖容量、只读挂载和查询超时后的恢复；不依赖用户保存的服务器或凭据。
