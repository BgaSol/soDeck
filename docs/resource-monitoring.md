# 服务器资源监控

Linux SSH 会话默认显示紧凑总览：CPU、内存、服务器网络、Docker 摘要、关注的挂载和默认折叠的 SoDeck 通信。终端底栏合并连接状态与资源摘要；点击指标或“展开”进入专注视图，“返回终端”恢复原工作区和触发控件焦点。连接进度、跳板路径和编码在底栏“会话连接详情”中查看。

布局使用工作区实际可用宽度：1200px 起文件、终端、检查器三栏；760–1199px 显示终端和检查器，可切到文件；低于 760px 用文件／终端／检查器单区域切换。默认文件栏 240px、检查器 360px，检查器可调 320–480px，多栏终端至少 320px。暂时缩小窗口不覆盖用户栏宽。布局和专注视图通过可见性切换，终端实例、连接和输出持续保留，隐藏区域不接收输入或拖放。

专注视图在宽度达到 900px 时并排显示三张趋势图，否则纵排。时间范围为 5 分钟、15 分钟和 1 小时；CPU 和内存固定百分比量程，网络两条线共用速率量程，以实线／虚线区分方向。移动指针冻结时间窗，点击或方向键固定同一实际采样点；离开未固定的图表、Escape 或“回到实时”恢复跟随，采集始终继续。缺失区间留空，不借用区间两端读数。每核和详细计数只显示最新采样。自动网卡变化会提示；显式选择的网卡消失后保留选择并显示不可用。

关注挂载最多三项，初始关注 `/`，按路径记录，容量按当前挂载身份取值。全部挂载支持路径／来源搜索、关注筛选和存储、系统、运行时、内存分组，8 项一页；根挂载和无法确定分类的挂载始终属于存储组。仅为实际可见的挂载与打开的详情申报容量需求，与文件树共用缓存。“在远程文件中定位”调用文件树路径定位，不向终端输入命令。绑定挂载、子卷与网络挂载的容量不相加。

Docker 使用容器／镜像分段和虚拟列表，提供名称、镜像、ID 搜索、容器状态筛选及名称／异常状态优先排序。后台刷新保持已有行位置，手动刷新或切换排序重新排列；筛选不会替换选择，删除的对象保留身份信息并禁用操作。侧栏详情在列表下方，专注视图宽度达到 900px 时左右排列，更窄时以“返回列表”切换详情页。日志和终端在现有独立窗口打开，只有运行中容器可进入终端；请求按引擎代际、容器和操作隔离。健康状态仅展示已有聚合结果，未知不记作零。

偏好只保存在当前会话内：栏宽、专注模式、时间范围、网卡、挂载关注、通信范围、Docker 搜索筛选／选择及滚动位置随标签与窗口迁移。关闭会话或退出应用后恢复默认；不写数据库、localStorage 或其他配置。迁移只传界面状态，实时指标和历史重新读取共享源，图表恢复实时跟随。逐容器健康、端口、资源占用、启停删除、长期历史、磁盘吞吐与告警不在本轮范围。

## 采集与口径

- 不安装 Agent，不写入远端文件，不执行 sudo。通过已验证的 SSH 路径和凭据建立专用持久连接；固定脚本用 `sh -c` 执行，不向交互 PTY 发送命令。普通 SSH 用户需要能读取对应 procfs 文件。
- CPU、内存和网络统一执行一次固定采样脚本。可见工作区约每 2 秒采集，所有订阅均在后台时约每 10 秒采集，回到前台立即补采。单次命令限制 6 秒，stdout/stderr 各限制 2 MiB；连接超时沿用现有传输层。
- CPU 使用 `/proc/stat` 前八项时间计数的差值，整机范围 0–100%；空闲与 iowait 不计入忙碌时间，guest/guest_nice 不重复相加。CPU 核心变化、计数回退、重连或服务器重启重新建立基线。负载独立来自 `/proc/loadavg`。
- 内存使用率为 `(MemTotal - MemAvailable) / MemTotal`。缺少 MemAvailable 不用空闲内存冒充可用内存。缓存显示 Cached + SReclaimable - Shmem；Swap 单独展示。
- 网络读取 `/proc/net/dev` 累计计数，用采样时远端 `/proc/uptime` 的实际差值计算速率；uptime 不可用时使用本机单调时钟。网卡 ifindex 用来识别同名接口重建，重启或计数回退不生成速率尖峰。速率以 B/s、KiB/s、MiB/s 等显示，方向以服务器为准。
- 累计字节数由 Rust 整数计算，IPC 使用十进制字符串，前端按 BigInt 格式化。网络速率与百分比为有限浮点数。每项指标独立报告成功时间和错误，部分指标缺失不影响其他指标。
- 数据反映 SSH 执行环境可见的 procfs／网络命名空间；不把这些值解释为 Docker 容器的 cgroup 配额。

## 模块和数据流

后端 `monitor/` 分为 `model`、`linux`、`history`、`mounts`、`docker`、`commands`，`mod.rs` 管理实例与高频采集。全局 `State.monitor` 按 `ConnectionContext.identity()` 共用实例，同一配置、账号、已验证主机密钥和跳板路径的多个标签／窗口只采样一次。重新连接时优先采用最近加入的已验证会话上下文。

`MonitorProvider` 在 `SessionWorkspace` 层建立一次订阅。`MonitorStore` 管理快照与增量，资源摘要、详细面板和 `useRemoteMounts` 适配层共用状态。前端只上报可见性和需要的挂载路径，不使用计时器轮询远端。文件树的路径匹配、图标、详情与错误交互保持独立。

IPC 接口：

| 接口                                                | 功能                                                        |
| --------------------------------------------------- | ----------------------------------------------------------- |
| `subscribe_monitor(sessionId, events, interest)`    | 校验会话归属，返回订阅 ID，通过 Channel 发送初始快照        |
| `update_monitor_interest(subscriptionId, interest)` | 上报可见性、挂载路径、Docker 摘要／容器／镜像需求及通信订阅 |
| `get_monitor_history(subscriptionId, minutes)`      | 读取 5/15/60 分钟的资源历史和独立通信历史                   |
| `refresh_monitor(subscriptionId, scope)`            | 刷新 all、metrics、mounts 或 docker                         |
| `unsubscribe_monitor(subscriptionId)`               | 幂等释放界面订阅                                            |

CPU/内存/网络更新与磁盘更新分别携带递增版本号，同时携带实例代次。初始快照、历史响应和实时推送即使交错也不会覆盖更新的数据。历史按序号合并去重，旧订阅在前端通过生命周期代次隔离。

## 磁盘融合

`remote_mounts.rs` 保留独立的 `query_table`、`query_usage` 采集函数和原有直接查询 IPC。生产工作区由 `monitor::mounts` 统一调度这些函数；文件树与监控面板不会各自调用旧 IPC。删除等业务需要实时挂载边界时仍使用原来的直接校验路径。

挂载表和容量约每 30 秒更新，查询集合为可见消费者路径的并集。同一挂载点只有一个进行中的任务，容量缓存以实例身份、完整挂载表版本与挂载点 ID 绑定。每个实例最多两个容量任务，底层继续执行所有窗口合计两个磁盘查询的限制。新出现的挂载点优先补查，失败退避为 30/60/120 秒，最长 5 分钟。手动刷新使旧执行代次失效，旧结果不能覆盖刷新后的挂载关系。

磁盘任务使用独立连接，不复用高频指标连接。SFTP 与 exec 挂载视图一致性、长 procfs 读取、查询前后挂载版本检查、保留块口径和大整数计算继续保留。慢挂载只影响自身容量状态，已成功数据保留并标为旧。挂载表失效时清除归属不再可靠的容量，而不是显示到新挂载点上。

## Docker 共享采集

Docker 前端不再轮询旧的检测／列表 IPC。后台按连接身份共享一条专用持久 SSH 连接，查询引擎、容器列表和健康异常摘要；总览与 Docker 视图共用结果。前台约 15 秒、全部窗口在后台时约 60 秒刷新，无有效订阅时暂停。引擎不可用或查询失败按 30/60/120 秒退避，最长 300 秒，手动刷新可立即重试。查询与 CPU、磁盘任务独立，使用可取消且限制时长、输出大小的 remote_read。

镜像仅在 Docker 镜像页可见时按需查询，使用独立任务和 60 秒缓存；同一实例至多一个镜像查询。失败的重试时刻与上次成功数据时间分开保存。引擎端点变更递增 engineGeneration，清除旧列表，旧端点请求即使较晚完成也不能写入新端点缓存。检测完成后查询显式绑定端点，不混用当前环境的 Docker context。

容器状态数量来自同一份列表；健康异常用 health=unhealthy 过滤查询，并与列表 ID 取交集。健康查询失败显示未知；已停止、未配置健康检查不推断为异常或健康。Docker 端点独立展示，非本地套接字不保证容器属于当前 SSH 服务器。Docker 事件有独立 revision，错误不会覆盖资源或通信状态。

## 本客户端通信与监控开销

`State.traffic` 和 `ConnectionContext.traffic` 持有应用生命周期的 TrafficManager。其账目按已验证连接身份汇总，覆盖所有窗口、后台文件任务、终端与日志。账目不持有凭据，不依赖 MonitorManager 生命周期；最后一个监控标签关闭后后台通信仍继续累计，重连恢复同一身份的累计量。应用退出清空，不写数据库。

计数发生在 libssh2 SEND/RECV 回调：调用原收发函数，仅累加正返回值。部分写入按实际返回长度统计，EAGAIN、错误及零返回不增加计数。`ssh_transport/meter.c` 只负责适配回调 ABI，使用同一 libssh2-sys 提供的头文件和链接库；新版本使用 callback_set2，旧系统库使用兼容接口。回调注册按 abstract 槽位地址关联，不修改槽位值，避免影响交互认证。注册寿命交给 Session 持有的 socket 包装器，覆盖 Channel/SFTP 持有底层 Session 引用的情况；包装器的 Read/Write 不参与计数。

握手前开始临时计数，完整目标路径通过主机身份核对后绑定账目；握手和认证开销纳入累计。身份未验证的失败尝试不混入已验证账目。绑定前字节不全部压进绑定后的一个速率点。用途由统一连接入口的必填 TrafficPurpose 指定，前端合并成监控查询、终端与日志、文件操作和其他／共享。监控查询包含自动采集及手动触发同类刷新，Docker 日志流属于终端与日志。

客户端 → 服务器表示客户端发送；服务器 → 客户端表示客户端接收。统计的是成功交给／读自目标 SSH 传输层的字节，包含 SSH 协议开销，不包括 TCP/IP 包头、ACK 和重传，不作为网卡线速或流量账单。跳板只累计目标层，外层封装不再次计入目标总量；突然断开时本地缓冲中的发送字节可能尚未抵达目标。服务器直传仅计本地控制和进度，不含服务器之间的文件主体。Docker CLI 从 SSH 服务器访问其他引擎的后续链路同样不在客户端统计范围。

本地采样约每 2 秒进行，按单调时钟实际间隔计算速率；前台约 2 秒、后台约 10 秒推送，无界面也不漏记累计。长时间休眠形成历史空缺，避免显示瞬时尖峰。通信历史与资源采样独立，拥有单独 epoch 和序号；远端采样失败或不支持 Linux 不影响本地计数。每个身份最多保留一小时、1801 点，所有身份的通信历史共享约 16 MiB 点数据预算，超限裁剪会标记 truncated；裁剪不清空累计。

## 生命周期和限制

同一身份还有关联会话时，关闭一个标签不会停止其他窗口的采集。窗口移动只改变订阅归属，后端连接与历史保留；旧窗口暂停接收，移动回滚后原订阅恢复。窗口刷新代次变化、会话结束和应用退出均释放对应订阅，最后一个会话结束取消全部该实例任务。退出等待后台任务释放。

采样断线保留最后的数值并标明更新时间，历史写入空缺；恢复后第一份 CPU／网络数据只建立基线。认证或主机密钥失败不自动确认，等待重连或手动重试。非 Linux 服务器显示不支持，并降低探测频率。

历史只在内存中保存，最长一小时，每个实例最多 1801 点，估算内存上限 8 MiB；大量网卡导致提前截断时界面说明。前端也使用同样的缓存上限。仅保留 CPU 总使用率、内存使用率和各接口收发速率的趋势，各核心只保存最新值。最后一个关联会话关闭后后端资源历史释放（通信累计与历史由独立 TrafficManager 保留），已断开的界面可继续显示已收到的数据。应用退出不保留历史，关闭客户端或连接中断期间无法补采。

```sh
npm test
npm run build
npm run test:resources
npm run test:connection
npm run test:transfers
cargo test --manifest-path src-tauri/Cargo.toml --lib
cargo test --manifest-path src-tauri/Cargo.toml --lib jump_resource_monitor -- --ignored --nocapture

```

单元测试覆盖计算口径、超大计数、重启、网卡重建、缺字段、时间空缺、历史合并和订阅取消。Chromium/WebKit 界面测试覆盖摘要、图表键盘操作、范围与网卡切换、共享容量、过期状态及窄窗口深色布局。

跳板联调使用本机隔离的 Paramiko A/B 服务和临时凭据，真实建立 SSH/SFTP 与跳板连接，系统统计为可控测试数据。检查多窗口共用持续连接、容量请求合并、慢挂载隔离、权限归属与回滚、断线恢复和任务释放。真实 Linux procfs 与文件系统能力验证可使用现有 Linux 挂载测试容器；原生桌面跨窗口拖动仍需对应平台验收。

通信验证还包括真实 TCP 回调的部分写入、EAGAIN、abstract 值保留与 Session 引用寿命；真实直连和跳板 SFTP 测试在有序关闭时逐字节核对客户端计数与服务器独立 socket 计数。Docker 联调覆盖多窗口查询去重、镜像按需加载、端点切换后的迟到镜像结果、权限错误恢复，以及最后一个监控标签关闭后的后台计数。
