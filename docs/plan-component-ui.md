# 组件与核心 UI 交互设计

> 状态更新：Hello 和组件交互示例现已退役，源码、官方来源和发行配置已删除；本文有关保留或发行示例的描述属于历史方案。宿主回归改用仅测试夹具，真实业务由终端、文件、网络隧道插件提供。

日期：2026-11-05。状态：设计已确认；当前源码实现组件 UI 基础，已发行版本仍为 v0.4.0。第 1–8 节保留设计意图，实际协议和验证边界见第 9 节及插件 API 文档。

## 1. 需求与设计结论

用户要求先做组件与核心的界面交互：参考 IDEA，两侧工具按钮展开侧栏；文件列表默认展开、编辑器占中央 Tab；终端在中央支持多 Tab、每个新服务器工作区默认一个；网络转发停靠侧栏、默认隐藏；侧栏可左右调整，组件增多后仍保持一致。

建议沿用“服务器工作区 + 内部页面”的两层结构，由核心提供统一容器。插件声明它提供哪些视图、视图属于侧栏还是中央、默认位置与初始打开方式；核心分配实例、管理布局并挂载插件界面。声明表示布局意图，不是权限清单，也不独占一整侧或修改其他插件的位置。

**插件、视图类型、视图实例分开：**一个文件插件可以提供“文件列表”和“文本编辑器”两个视图类型；每台服务器各有一个列表实例，以及多个不同文件的编辑实例。一个终端插件对应多个终端页面。不能以“一个插件只能占一个位置”建模。

本轮只设计并随后实现容器、登记、事件和生命周期。SSH、SFTP、PTY、转发规则及文件写回仍另行实现。正式发行版不伪造连接；验证使用外置 UI 示例插件与隔离测试会话。

## 2. 页面与默认布局

```text
[服务器管理] [生产 Web ×] [测试环境 ×]                 状态 消息 设置 窗口按钮
┌──────┬─────────────┬──────────────────────────────┬────────────┬──────┐
│ 文件 │ 文件列表     │ [终端 1 ×] [nginx.conf ● ×] [+]│ 网络转发    │ 转发 │
│ 终端 │  /etc        ├──────────────────────────────┤ （默认收起）│ …   │
│ …    │  /var        │ 当前服务器自己的终端或编辑器    │            │      │
│      │             │                              │            │      │
└──────┴─────────────┴──────────────────────────────┴────────────┴──────┘
 当前服务器 · 当前视图状态
```

| 插件提供的视图 | 容器 | 建议默认位置 | 实例数量 | 新工作区首次打开 |
| --- | --- | --- | --- | --- |
| 文件列表 | 侧栏 | 左；用户可改到右 | 每工作区一个 | 创建并展开 |
| 文件编辑器 | 中央 Tab | 中央 | 每工作区每个远程文件一个；不同文件可多个 | 用户打开文件时创建 |
| 终端 | 中央 Tab | 中央；创建/定位入口默认在左工具条 | 每工作区多个 | 创建一个并激活 |
| 网络转发 | 侧栏 | 右；用户可改到左 | 每工作区一个 | 只显示入口，首次展开时创建界面 |

默认打开只在**新建工作区时执行一次**。切换服务器、侧栏展开、组件重绘和移窗不重复执行；用户关闭最后一个终端后保留中央空态与“＋”，不自动补建。默认创建失败只显示失败项与重试，重试复用同一个初始化请求，不能重建另一份成功终端。

只有已安装、启用并完成登记的插件参与。没有终端插件就不出现假终端；没有文件插件就不展开空文件侧栏。打开转发面板不会自动创建任何监听端口。

## 3. 统一交互规则

### 两侧工具按钮

- 同一侧同一时间显示一个侧栏；左右可以同时展开。打开同侧另一个组件只替换可见面板，之前的实例、草稿和任务保留。
- 点击当前展开组件的按钮：收起。点击同侧隐藏组件：先切到该组件，再展开。选中状态由 `activeViewId` 与展开状态共同决定，不能只看某组件曾经打开过。
- 文件与转发按钮对应实际所在侧。面板标题统一有名称、来源提示、菜单和“收起”；插件工具按钮放在其内容工具栏内，不替换核心窗口菜单。
- 面板菜单提供“移到左侧 / 移到右侧”和“收起”。移侧保持 viewId、草稿和任务；目标侧原面板收起但不关闭。第一版用菜单完成移侧，不叠加组件独立弹窗和复杂拖放。
- 侧栏按钮顺序可调整；“从工具条隐藏”只隐藏入口，可从“更多组件”重新显示。固定入口、布局定制与设置中的插件启用/关闭是三个不同操作。
- 面板和更多菜单固定在入口附近，靠近窗口底部时向上展开，并保持在窗口内。短菜单无滚动条；长列表仅纵向滚动，搜索框保留在列表上方，筛选后重新定位。Esc 关闭并返回入口焦点。
- 终端按钮是**中央页面入口**：定位本工作区最近使用的终端，无终端则创建一个；连续点击不重复创建。按钮旁提示“定位终端”，不伪装成可收起的侧栏。创建更多终端使用中央“＋”。

### 中央页面

- 所有组件共享一条内部 Tab 栏，文件和终端可混排；不再为每个插件加第三层 Tab 栏。
- Tab 的选择、排序、关闭、完整标题提示、脏状态标记及溢出列表由核心统一提供。组件拥有自己的内容和内部工具，不自建外围页签。
- 文件列表双击文件打开中央编辑页；同工作区同一文件再次打开定位原 Tab。第一版不做单击预览/临时 Tab，避免修改内容被下一个文件替换。
- 文件身份由文件插件返回稳定 resourceKey，包含远程文件系统语义；不使用本机 Windows 路径规范化，不擅自忽略大小写，不将两台服务器相同路径合并。
- 中央“＋”列出声明可由用户创建的页面，按插件名称分组；只有一个动作时可直接执行“新建终端”。文件编辑器需要文件参数，不作为空编辑器创建项。
- 点击“＋”是一次明确的新建操作；每次操作有 requestId，IPC 重试复用它。多次真实点击允许多个终端，不能将不同用户动作全局去重。
- 关闭当前 Tab 后激活相邻页面；关闭最后一个保留空态、“＋”和侧栏。文件关闭不关闭文件列表，终端关闭不关闭服务器档案。

### 焦点、尺寸与组件增多

- 展开侧栏后焦点进入面板；收起时返回触发按钮，避免焦点留在隐藏组件。切换中央 Tab 将焦点交给对应组件，终端不会抢走刚打开的文件编辑焦点。
- 侧栏统一可调宽，键盘可调；建议 180–480px、默认 240px。中央至少保留 320px。空间不足时临时收起较早展开的一侧，保留其展开意图；窗口恢复后复原，不覆盖用户保存的宽度。
- 桌面最小 720×480，原型在窄预览中改为纵向排布，不把手机排布当成桌面产品要求。字体放大时工具按钮、更多入口与关闭仍可达。
- 两侧只显示用户固定的组件；其余放在该侧底部“更多组件”，可按名称查找、打开或固定。用户点击未固定项只打开，不自动塞满工具条。固定项溢出也进入更多列表，不能挤掉窗口按钮。
- 首次建立布局时采用当前已安装插件的推荐值；以后新装插件默认登记到“更多组件”，尊重已有顺序，不自动修改用户的默认打开策略。用户可在设置中为该组件启用推荐布局或自行设定。无论何时安装，已打开的工作区都不会因此被抢占侧栏/中央焦点。
- 文件/终端/转发的默认值由它们自己的声明及用户布局表达，核心不写 `if pluginId === files`。首次布局中的固定/自动打开动作需具有明确顺序；同侧冲突按用户顺序取首项，其余保持可从按钮打开，不能互相挤走。
- 高优先级消息用既有消息中心，计数用入口角标；后台事件不擅自打开面板、创建中央页或切换服务器。用户点击通知的“定位”后才转到正确工作区和实例。

## 4. 登记契约：定义与实例分离

建议在外置 `plugin.json` 添加可选 `ui`，旧 Hello 无此字段继续正常运行。核心在插件初始化成功后激活这些声明，异常退出时标记不可用。名称、图标、位置与默认动作属于静态声明；实例标题、脏状态、忙状态和角标通过运行时接口报告。

以下是文件插件示例，字段名为本次提案，**尚不是已发布 API**：

```json
{
  "ui": {
    "apiVersion": "1",
    "entry": "ui/index.html",
    "views": [
      {
        "id": "browser", "title": "文件", "icon": "folder",
        "container": "sidebar", "instancePolicy": "perWorkspace",
        "defaultSide": "left", "defaultPinned": true,
        "openOnWorkspace": "reveal", "startupOrder": 10
      },
      {
        "id": "editor", "title": "文件编辑器", "icon": "file-text",
        "container": "editor", "instancePolicy": "perResource",
        "openOnWorkspace": "none"
      }
    ]
  }
}
```

终端声明 `container: editor`、`instancePolicy: multiple`、`openOnWorkspace: createOne`，并声明一个用户创建动作及可固定的“定位终端”入口；网络转发声明 `sidebar/perWorkspace/right/none`。`defaultPinned` 是入口默认值，`openOnWorkspace` 是视图初始化默认值，两者不能合并为一个 visible 字段。只允许一个初始中央视图激活；用户偏好优先于声明，自动动作不依赖插件启动竞速。

`defaultPinned` 和 `openOnWorkspace` 只作为首次布局或用户选择“采用推荐布局”的输入；新装插件不会重算既有偏好。无 UI 插件不参与首次布局初始化，避免先启动一个空核心就永久错过文件/终端的推荐值。中央创建动作另声明稳定动作 ID、名称与目标视图定义；“定位已有实例”入口与“创建新实例”动作分别登记，核心不能通过名称猜测行为。第一版每个视图定义固定一种容器；同一插件需要侧栏和中央时声明两个视图，不先加入任意容器切换规则。

新工作区等本次启用插件完成初始化或明确超时后，按已登记定义一次性计算默认布局；晚到/失败后重试的插件只补登记，不自动夺取焦点。后续由用户主动打开。侧栏工具标题、图标及中央创建入口都是元数据，未知组件走相同容器逻辑。

建议的最小运行模型：

```ts
type ViewDefinition = {
  pluginId: string;             // 核心从注册来源附加
  localId: string;              // 插件内稳定 ID
  container: "sidebar" | "editor";
  instancePolicy: "perWorkspace" | "perResource" | "multiple";
  // 标题、入口、默认位置、默认打开方式等声明
};

type ViewInstance = {
  id: string;                  // 核心分配；移侧/移窗保持
  definitionKey: string;       // pluginId + localId，不用显示标题作键
  pluginInstanceId: string;    // 本次插件进程；拒绝旧进程回包
  workspaceId: string;
  resourceKey?: string;
  title: string;
  status: "loading" | "ready" | "error";
  dirty: boolean;
  busy: boolean;
};

type WorkspaceLayout = {
  left: { order: string[]; activeViewId: string | null; expanded: boolean; width: number };
  right: { order: string[]; activeViewId: string | null; expanded: boolean; width: number };
  editor: { viewIds: string[]; activeViewId: string | null };
};
```

侧栏定义归属哪一侧，用户可调整；活跃面板使用实例 ID。order 存定义键、editor 存实例 ID，避免“重装插件后旧实例 ID 当成偏好”的混淆。核心保留窗口归属与固定 Context；每次渲染挂载另分配 surfaceId，防止移窗后旧 WebView 继续发输入。连接 generation 只表示重连，不拿它充当界面挂载代次。

建议新增的 UI 操作：

| 方向 | 接口 | 作用 |
| --- | --- | --- |
| 插件 → 核心 | `ui.openView` | 携带 workspaceId、视图类型、参数及 requestId；返回稳定 viewId，可请求后台打开或用户触发的定位 |
| 插件 → 核心 | `ui.updateView` | 更新所属实例的标题、dirty、busy、角标和错误提示；不直接写全局布局 |
| 插件 → 核心 | `ui.requestClose` | 请求走统一关闭流程；不是直接移除 Tab |
| 核心 → 插件 | `ui.createView` / `ui.disposeView` | 为逻辑实例初始化/释放状态；隐藏不发送 dispose |
| 核心 → 界面 | `mount` / `visibilityChanged` / `focus` / `themeChanged` / `unmount` | 交付固定 Context、viewId、surfaceId、主题和尺寸；unmount 不等于销毁任务 |
| 核心 ↔ 插件 | `ui.beforeClose` | 查询 dirty/busy 和关闭决定，保存失败/用户取消先停止关闭，不先释放资源 |

核心从调用来源补 pluginId、pluginInstanceId，检查视图已声明、实例归属、参数和有效 Context；这属于基本 API 检查，不增加权限声明、审批或授权界面。插件不能传一个 activeServer 字段让核心猜目标，也不能直接向另一插件发消息。

## 5. 外置界面如何加载与通信

建议一个插件包继续包含自己的原生工作进程，并可附带预构建的 `ui/index.html`、脚本与样式。核心安装包不包含业务组件代码；核心更新不要求重新打包插件界面。插件 UI 也不要求用户运行 Node 或启动开发服务器。

- 采用核心提供的本地资源协议加载插件 HTML，每个可见视图实例用一个嵌入页面容器。以 iframe 为首个方案，第一项实施先用外置示例验证 Tauri 五目标的本地资源加载、焦点、尺寸、中文输入与移窗重挂载；有平台问题再定向修正，不先做多套渲染后端。
- 外置插件自带依赖并完成构建，不导入核心源码或主窗口的 DOM。一个 HTML 入口按 viewType 显示不同内容；不要求所有插件使用同一种前端框架。
- 页面通过小型 UI bridge 发结构化消息；核心绑定真实页面来源、viewId、surfaceId、pluginInstanceId，再转发插件业务请求。父窗只接纳已挂载页面，旧页面/错误 Context 的消息被拒绝。这是消息路由与正确性边界，不承诺插件被安全沙箱隔离。
- UI bridge 与进程 RPC 分开：终端流、文件内容等不逐块走已有 64KiB 日志/管理帧；UI 协议预留可替换的数据通道，真实 PTY/文件流接入时再设计分块、背压和容量。本轮只传打开、标题、状态与交互事件。
- 核心下发主题变量（背景、文本、边框、强调色、字号、间距）和主题变化，提供按钮、输入、工具栏的轻量 CSS 基础。插件内容可有自己的业务布局，外框、停靠、Tab、菜单与确认流程保持一致。
- 不要求插件签名、引入在线前端资源或从插件清单安装 npm 包。资源路径只能指向该插件包已有的文件，沿用基本入口、版本和平台检查。UI 可选能力由初始化结果报告；旧无 UI 插件继续运行。

## 6. 生命周期、关闭与移动

**隐藏 ≠ 关闭 ≠ 停用插件。** 收起侧栏、切服务器或切中央 Tab 只改变可见性；任务保持。关闭终端页释放该页 PTY 引用；关闭编辑页先保存或放弃；隐藏转发面板不停止任何转发。关闭服务器工作区才汇总本工作区的视图和资源，应用重启才应用插件启停与升级。

中央已创建视图和展开过的侧栏在同窗切换时保留容器，不用 innerHTML 整体重建。`visibilityChanged` 通知组件暂停无须显示的绘制，不要求停止后台任务。转发默认隐藏时可延迟挂载，其业务状态依然由核心/插件管理。

移侧只换容器位置；整个服务器拆到另一原生窗口时仍走已有 prepare/commit/cancel。目标容器及插件视图报告就绪后才切换 surfaceId、停止旧表面输入；逻辑 viewId、终端任务、编辑缓冲和文件定位不变。编辑缓冲/业务状态放插件进程，界面保留可恢复的光标/滚动等小状态；不能依赖搬运任意 DOM。目标加载失败源仍可用，不先 unmount 源。

核心只协调最小迁移接口，分别用终端输入草稿和文件未保存编辑验证；不预建任意插件万能快照系统。插件异常时单视图显示错误、日志入口和可用恢复方式；禁止把 error 当成自动关闭，不能用空白新实例覆盖旧草稿。

关闭 Tab、子窗口、服务器工作区、主窗口退出和升级重启都进入同一个关闭协调入口：先冻结新变更并收集所有目标视图的 dirty/busy；统一列出“保存并关闭 / 放弃并关闭 / 取消”；所有决定和保存成功后才 dispose。任何取消发生在资源释放前，不能先关闭一半终端才询问另一个文件。超时/插件失联明确显示无法完成，不静默丢弃数据；不需要关闭检查的视图直接返回可关闭。

## 7. 哪些设置落盘

| 数据 | 保存范围 | 重启后 |
| --- | --- | --- |
| 各视图的左右位置、固定入口、按钮顺序、默认展开/创建策略、侧宽 | 本机用户的组件布局偏好，独立 `ui-layout.json`，带 schemaVersion | 保留，并优先于插件推荐值 |
| 当前服务器侧栏活跃实例、中央顺序、当前页面、临时收起 | 当前 workspace 内存 | 不恢复已关闭会话 |
| 编辑缓冲、终端任务、组件业务草稿 | 所属插件；本轮测试只演示保持，不承诺崩溃恢复 | 各业务插件后续定义恢复机制 |

同窗切换与移窗保留当前工作区自己的状态。用户明确“移到右侧 / 固定入口”等布局定制会记录为新工作区的默认值；已打开的其他工作区不被瞬间重排。新插件只补缺失定义，升级保持稳定 localId；卸载后忽略不存在定义，不影响其他布局。重启不自动连接服务器或恢复终端进程。

## 8. 分步实施与验收

1. **先验证外置 UI 宿主。** 一个独立示例插件附带静态 UI，登记“侧栏 + 多个中央页面”，五平台验证包内资源、挂载/卸载、主题、焦点和进程消息。核心无该示例时仍能独立打包启动。
2. **再完成统一容器。** 用文件列表/编辑页、终端多页和转发面板的无网络示例，验收两侧按钮、移侧、更多组件、中央“＋”、默认打开和布局偏好；核心不识别具体插件 ID。
3. **补齐关闭与移窗。** A/B 服务器各有不同未保存草稿，验证同窗切换、跨窗重挂载、目标失败、退出/重启取消、插件异常和旧表面消息拒绝。
4. **随后接真实能力。** SSH 会话 → 终端 PTY → 文件列表/编辑 → 网络转发，逐项验收。组件 UI 交互阶段不顺带实现这些业务，也不再发只改标题的空版本。

关键验收：

- 新工作区默认文件展开、终端一个、转发隐藏；切换/移窗/关闭最后终端不会重新执行默认创建。
- 文件与转发放到同侧后，按钮选择与实际面板一致；切换面板不释放任务。改到另一侧后 viewId 不变。
- 同一路径跨 A/B 是不同编辑页，同 A 同文件再次打开只定位；两个终端的输入、标题和任务不会串服务器。
- 20 个组件、长名、很多中央 Tab、720×480 和四种主题下仍可从更多入口打开/固定，系统按钮始终可达。
- 文件脏状态、关闭取消、保存失败、多个视图的汇总关闭、子窗关闭、应用重启与升级均先检查再释放。
- 插件启动失败、界面缺文件、登记冲突、旧进程回包、目标窗未就绪均有明确错误，不破坏其他组件。
- 核心与插件独立打包；五目标本地 UI 资源、输入、移窗及实际包启动/退出分别验证并记录，不用浏览器示例替代平台运行结论。

## 9. 本轮交付边界

设计确认后已实现核心容器、可选 UI 清单、外置本地资源协议、进程 RPC、每工作区的逻辑视图、同窗保留 iframe、移窗重挂载/目标就绪检查、关闭确认和布局偏好。`plugins/ui-example` 独立提供文件列表、文件编辑草稿、多终端输入草稿及隐藏转发面板，均不访问服务器。核心版本维持 v0.4.0，本轮未发布新 Release。

实现采用更小的 `ui.mount/event/beforeClose/save/disposeView` 进程协议，mount 幂等创建或恢复状态，元数据随响应报告；没有另加运行时注册或 createView。中央创建动作第一版每视图一个名称，目标为该定义。实际字段见 [插件 API](plugin-api.md)。入口排序第一版提供“移到最前”，中央页面支持拖动排序；不加入组件自由浮窗和任意布局框架。

Windows x64 已使用独立插件包和 NSIS 安装后的程序验证：本地资源加载、默认文件/终端、编辑草稿、原生移窗返回、旧窗口写入拒绝、保存关闭、两次启动/退出。浏览器的真实 Rust 核心交互测试覆盖多终端、文件去重、侧栏移侧、iframe 不重建、关闭取消、保存失败以及 720×480 多主题。其余四目标的本轮 UI 原生验证尚未运行；已扩展五目标安装包集成工作流，不能把本机结果当成五平台通过。中文输入法与多 DPI 的人工验证尚未完成。

源码验证：34 项 Rust 测试、6 项打包脚本测试、12 组服务器表单与 13 组工作区/组件 UI 测试通过，类型与格式检查通过。工作区测试额外登记 20 个视图，验证更多入口查找与固定；侧宽沿用上一版 220px 默认值，位置/宽度/入口偏好落盘，窄窗口临时收起一侧，保留保存值。示例的光标/滚动事件只更新定位，不回写文本，原生草稿迁移用例覆盖此回归。

本轮原型使用无头 Chrome 脚本验证：默认布局、多终端草稿、混合 Tab 与文件去重、A/B 上下文隔离、移侧与同侧切换、更多组件与固定入口、脏文件关闭确认、关闭全部后不补建，以及 1040/720/360/320px 无横向溢出，共 9 组通过，无页面脚本错误；已检查默认与文件编辑页面截图。这些结果仅覆盖浏览器交互原型，不替代 Tauri 五目标的外置资源加载、真实组件输入或跨窗迁移验收。
