# 系统设置窗口功能设计

## 目标

将系统设置从一张连续堆叠的表单改成可扫描、可扩展的设置中心。用户打开窗口后能快速找到主题、终端行为、软件更新和诊断入口；每项设置都能在当前上下文中完成修改，并明确显示生效时机、保存状态和错误原因。

## 信息架构

窗口采用 Apple 系统设置常见的「分类导航 + 详情面板」结构：

| 分类     | 内容                                         | 生效方式                             |
| -------- | -------------------------------------------- | ------------------------------------ |
| 通用     | 外观主题、开发者模式                         | 主题立即生效；开发者模式下次启动生效 |
| 终端     | 便捷快捷键、选中即复制、右键直接粘贴         | 保存后立即生效                       |
| 软件更新 | 当前版本、检查更新、下载、安装、自动更新偏好 | 按更新流程反馈                       |
| 诊断     | 日志状态、打开目录、打包、清理               | 按操作即时反馈                       |

默认进入「通用」。从菜单或更新通知打开时，可以直接进入指定分类。

## 交互规则

- 左侧分类项同时显示图标、标题和一句副标题；当前项使用系统强调色背景和清晰的选中态。
- 设置按组呈现，每组只有一个主题，使用统一的行高、边界和留白，避免多层卡片嵌套。
- 开关使用即时反馈：按下时立即呈现按压态，保存期间禁用相关控件，成功或失败状态在控件附近显示。
- 主题选择立即切换界面，保留现有的系统、浅色、深色三种选项。
- 开发者模式继续区分「已保存的配置」和「当前窗口状态」，明确提示下次启动才生效；模式开启时显示当前窗口开发者工具入口。
- 保存失败时恢复到最后一次已提交值，并保留可读的错误提示；跨窗口事件按 revision 忽略过期更新。
- Escape、关闭按钮和底部关闭按钮执行同一个关闭流程，关闭后焦点回到系统设置入口。

## Apple Design 对齐

- **响应**：开关和分类按钮在按下瞬间反馈，避免等待 click 完成才变化。
- **可预测**：分类切换保持同一位置和层级；更新、诊断等长内容只在右侧面板滚动。
- **空间关系**：弹窗从设置入口进入，关闭回到原入口；分类导航始终固定在左侧。
- **克制**：使用现有系统色、细边界和单层分组，不使用装饰性渐变或大面积阴影。
- **可达性**：分类使用按钮和 `aria-current`，设置保留原有可访问名称；键盘可通过 Tab、Escape 操作，所有状态消息使用 live region。
- **动效**：仅使用短促的颜色、位移反馈，并在 `prefers-reduced-motion: reduce` 下关闭过渡。

## 响应式行为

- 桌面窗口使用约 760px 宽度，左侧分类栏约 194px，右侧内容独立滚动。
- 窄窗口将分类栏改为横向可滚动的分类条，详情内容占满下方区域。
- 设置行中的说明允许换行，控件保持稳定宽度，避免文本挤压开关或选择框。

## 验收标准

1. 打开系统设置后，默认看到「通用」且可以在四个分类之间切换。
2. 主题、开发者模式和终端设置的现有保存与同步行为不变。
3. 软件更新和诊断操作仍可完成，长内容不会撑破窗口。
4. 420px 宽窗口无横向溢出，分类和设置控件可操作。
5. 浅色、深色、高对比度和减少动效环境下均保持可读和可操作。
