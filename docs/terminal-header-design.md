# 终端顶部收敛：功能设计

日期：2026-10-22。状态：单行工作条方案已实现，见 [实施与验收记录](terminal-header-verification.md)。本文保留原设计依据和交互示意说明。

## 1. 需求判断

用户所说的“终端顶部太厚”，指向终端工作区的连续四排界面：服务器身份与工具连接、终端标签、当前终端身份与连接操作、历史与剪贴板操作。重复的信息和常驻的低频操作推迟了终端正文的起点。

核心需求：把空间和注意力还给命令输入与输出，同时保留多终端切换、连接恢复、历史和工具管理的可发现性。不通过缩小文字、压缩点击区域来解决。

保留“应用顶部服务器标签 → 当前服务器内终端标签”的导航层级；顶端窗口栏及左右工具窗口不在本次改造范围。

## 2. 推荐结构：单行终端工作条

```text
应用窗口栏：服务器入口  [● 192.168.1.16  ▾  ×]  ＋     全局工具 / 窗口控制
                       └─ 服务器菜单：工具连接、端口转发、工作区操作

中央终端： [● 终端 1 ×] [● 终端 2 ×] [● 终端 3 ×] [● 终端 4 ×]  ▾* ＋  历史  ···
          ────────────────────────────────────────────────────────────────
          dw@dw:~$ ▏
          …终端输出…

既有底栏：当前终端连接摘要 / 通信 / 资源；历史异常按需并入
```

`▾*` 为“全部终端”，仅在标签溢出时显示。服务器菜单是位于服务器标签的独立按钮，也可从标签右键进入；不要求用户发现右键才可管理工具。

正常状态下，中央顶部只有一排，基准目标高度 40 CSS px（14px 根字号下约 2.86rem）；触控目标扩大至至少 44px。高度随字号增长。四排变一排是验收目标，截图缩放和 DPI 未校准，不将示意高度差当作原生窗口实测结果。

## 3. 信息与功能迁移

| 现有内容 | 新位置和行为 |
| --- | --- |
| 中央再次显示的服务器名 | 由应用顶部当前服务器标签及既有底部连接详情承担 |
| “工具可用” | 服务器菜单内“工具连接：可用”；健康时不占中央横排 |
| “更新工具连接” | 服务器菜单的“更新工具连接”；验证过程、取消及错误仍完整可达 |
| 服务器级端口转发 | 保留现有全局入口；服务器菜单提供明确作用于当前服务器的入口 |
| 终端标签、状态标记、关闭、新建 | 保留并组成中央唯一常驻工作条 |
| “全部终端”下拉 | 改为按真实溢出条件出现；完整列表展示名称、状态和当前选中项 |
| 当前终端标题 | 删除重复的一排，由活动终端标签标识 |
| 当前终端“已连接” | 标签状态、辅助功能名称与既有底部连接摘要承担 |
| 断开 | 当前终端更多菜单和标签菜单，明确“断开当前终端”；不紧邻新建或关闭 |
| 重连 / 验证 / 取消连接 | 需要处理时在同一工作条直接出现；复杂原因用临时上下文条说明 |
| 历史 | 工作条尾部常驻“历史”入口；窄时使用有名称与提示的图标 |
| 全局历史搜索 | 当前终端更多菜单“搜索全部终端历史”；既有应用全局历史入口保留 |
| 复制 / 粘贴 / 清理显示 | 当前终端更多菜单、既有终端右键菜单及现有快捷键 |
| 正在保存 / 已保存历史 | 历史入口的提示与历史记录详情，健康时无常驻说明文字 |
| 历史保存异常 | 历史入口显示警告形状；既有底栏提示“历史保存异常”，可查看详情 |

本轮不重新定义剪贴板策略、快捷键或多行粘贴确认。菜单动作仍进入已有剪贴板处理流程，不能因为菜单拿走焦点就丢失终端选区或将粘贴错误禁用。

## 4. 交互规则

### 4.1 标签和溢出

- 即使只有一个终端，也保留标签、“＋”、“历史”和更多，形成稳定入口。
- 标签名称、状态和关闭范围不变；双击或菜单重命名、拖动排序、方向键切换沿用已有规则。
- “＋”紧跟标签区域，始终表示“为当前服务器新建终端”。应用窗口栏的“＋”继续表示打开服务器。
- 标签可横向滚动，活动项始终进入可见范围；溢出列表也能用键盘和点击打开。
- 不为凑下一排而换行。优先将“历史”等文字切为有提示的图标，再减少可见标签数量。
- 极窄时保留活动标签、全部终端、“＋”、历史、更多。所有终端仍能由列表访问。
- 标签长名称使用省略与完整提示；关闭按钮与切换按钮为同级控件。

### 4.2 当前终端更多菜单

菜单从右侧“···”锚定展开，标题显示作用对象，例如“终端 4”。

| 分组 | 菜单内容 |
| --- | --- |
| 编辑 | 复制选区、粘贴、清理显示 |
| 历史 | 搜索全部终端历史、历史记录状态与详情 |
| 会话 | 重命名、连接详情、断开当前终端 / 重新连接 |

菜单只作用于打开时绑定的终端；切换服务器或终端时关闭，避免对另一个会话执行操作。右键后台标签时，操作对象是该标签，不能沿用当前活动终端的控制器。

菜单打开、复制和关闭后恢复正确焦点；执行粘贴先恢复该终端的交互资格，再走原生剪贴板流程。禁用项说明原因，例如“未选择终端文字”“屏幕程序运行期间无法清理显示”。

“清理显示”保留当前输入和全部历史，现有完成反馈改为底部短反馈“已清理 · 查看此前记录”，不永久增加一行。

### 4.3 服务器工具菜单

在顶端服务器标签增加独立下拉按钮，不将箭头嵌套到切换按钮里。

- 分组显示当前工具连接状态、实际账号与地址、配置是否已更新。
- 提供“更新工具连接 / 连接工具 / 取消验证”和当前服务器“端口转发”。
- 更新失败保留失败原因和重试；验证对话框保持现有作用域与排队规则。
- 工具未验证、失败或配置不一致时，服务器标签出现可访问的注意标记；已打开的文件或服务面板在自身上下文中提供恢复入口。
- 终端连接状态和工具连接状态分别命名；不能将工具失败显示成当前 SSH 终端已断开。
- 连接后台逻辑不依赖菜单是否挂载；关闭菜单不能取消验证、清掉错误或释放工具连接。

### 4.4 连接状态

| 当前状态 | 常驻工作条 | 附加上下文 |
| --- | --- | --- |
| 已连接 | 状态点与可访问名称，历史、更多；断开在菜单内 | 不显示健康提示条 |
| 排队 / 连接中 | 标签进度形状和状态文本；“取消”可直接操作 | 队列或连接阶段需要解释时短条显示，不伪造进度百分比 |
| 等待身份或主机密钥验证 | 标签显示验证形状；“继续验证” | 显式进入既有认证对话框，不重复创建验证请求 |
| 等待自动重连 | 标签状态；“立即重连” | 一条临时状态条说明重试时间、原因和“停止重连” |
| 手动断开 / 重连停止 | 标签断开形状；“重新连接” | 保留输出，不自动重连；详情可展开 |
| 连接失败 | 标签失败形状；“重试连接” | 一条可展开错误详情，不同时堆叠多个重复错误栏 |
| 后台终端异常 | 对应后台标签显示标记；顶端汇总需要关注的终端 | 不抢焦点、不弹出当前终端错误条；进入后才展示其恢复操作 |

“断开”保留标签和输出，“关闭终端”结束会话并移除标签，两者继续使用既有不同语义及确认规则。连接恢复只恢复会话连接，不自动重跑命令。成功后移除临时条，将空间还给输出。

### 4.5 历史模式

点击“历史”进入当前终端的只读历史视图，入口呈选中状态。进入后可以显示任务所需的临时上下文条：“正在查看历史 · 返回实时终端”。这属于当前任务，不恢复原来的四排顶部。

实时终端继续接收输出并保存历史；新输出显示在“返回实时终端”旁。历史视图不接收终端输入，复制只作用于当前可见历史选区，粘贴与清理显示禁用并说明原因。返回实时恢复输入焦点、输出滚动状态及会话状态。

历史保存异常不等于 SSH 断开。异常标记保持到已知恢复，详情说明记录可能存在缺口；不承诺自动补齐。健康的持续保存不做闪烁、循环动效或逐次播报。

## 5. Apple Design 的具体应用

- **简洁与层级**：终端输出为主体；服务器身份在服务器层，终端切换在终端层，低频动作进入一次展开可达的菜单。
- **熟悉与控制**：保留桌面标签、关闭、新建、右键与快捷键习惯；异常时直接展示恢复操作，不强迫用户进菜单找“重连”。
- **视觉克制**：延续 SoDeck 系统字体、单色线性图标与深浅色语义变量。标签、工具条背景尽量连续，仅保留必要分界；活动项用柔和背景与字重区分。
- **尺寸**：14px 根字号下工作条约 40px，精细指针命中区约 32px，图标 15–16px，触控至少 44px；不缩小终端字体换取空间。
- **材质**：固定工作条使用稳定表面；有实际遮盖关系的菜单可用单层轻材质及阴影。终端文字不透过玻璃背景，不将多层磨砂作为风格目标。
- **即时反馈**：按下立即高亮，释放执行；展开、关闭、快速反向操作始终有效。菜单从触发点展开并沿原路径收起。
- **动效**：菜单按需要使用可中断、无回弹弹簧，参考阻尼比 1、响应约 0.3 秒；不弹跳标签，不为工具条高度变化增加逐帧终端重排动画。
- **适配与辅助功能**：支持浅色、深色、高对比、减少透明度和减少动态效果。颜色之外使用形状、状态文本、提示与可访问名称。
- **焦点**：菜单支持键盘关闭并返回触发项，执行终端命令后回到对应终端；仅菜单打开时处理其 Esc，不全局吞掉 Shell 的 Esc。

## 6. 备选方案及推荐

交互示意提供“单行工作条”“双行常用工具”和“现状对照”。备选“双行常用工具”用一排标签加一排紧凑的历史、复制、粘贴、清理显示，适合偏好鼠标常用动作可见的使用方式。

推荐采用单行工作条：现有粘贴快捷键和终端右键已承担高频编辑动作；历史保留直接入口，更符合本次减少顶部占用的诉求。双行方案作为对比供评审，不自动增加新的设置项或密度模式。

示意中状态选择器用于检查异常布局，不属于应用功能。连接与历史操作只改变预览，不连接服务器。

## 7. 实施落点和边界

已核对 `ServerWorkspace.tsx`、`TerminalTabs.tsx`、`TerminalSession.tsx`、`TerminalWorkspace.tsx`、`WorkspaceToolConnection.tsx` 及相关样式。

| 位置 | 预计改动 |
| --- | --- |
| ServerWorkspace / TerminalTabs | 组合唯一工作条；真实溢出检测；活动终端的操作入口 |
| TerminalSession | 将重复的标题栏拆为连接状态及动作能力；保留认证、错误与恢复流程 |
| TerminalWorkspace | 提供历史、剪贴板、清理与记录状态给工作条及菜单；历史上下文条按需显示 |
| WorkspaceToolConnection / WorkspaceTabMenu | 工具连接的展示移入服务器菜单，连接与认证生命周期留在稳定工作区层 |
| terminal-tabs.css / terminal-history.css / styles.css | 清除旧常驻行占位，统一尺寸、主题和响应式规则 |

不采用 CSS 直接隐藏旧工具栏的方式交付：动作入口、错误反馈与作用对象需要同步迁移。重组顶部不能重建 xterm 实例或改变终端、工具连接和后台任务的所有权。

## 8. 验收标准

1. 正常连接时，应用窗口栏下方中央区域只出现一排工作条；没有隐藏但占位的旧栏。
2. 1、4、12 个终端及长名称均可切换、关闭、新建；“全部终端”仅溢出时出现。
3. 覆盖中央可用宽度 900、640、480、320px，检查默认字号和放大文字；不出现水平溢出或第二排常驻工具。
4. 操作对象清晰：切换后菜单关闭；后台标签菜单不误操作活动终端；工具失败不误报为 SSH 断开。
5. 连接中、排队、验证、自动重连、断开、失败均有直接恢复或取消入口；成功后临时条消失。
6. 复制、粘贴和清理沿用现有能力、快捷键、确认与选区规则；通过原生 Windows 场景验收菜单焦点恢复。
7. 历史模式不向实时终端发送输入；返回实时后输入正常；历史异常持续可见且不与 SSH 状态混淆。
8. 菜单关闭、标签切换、尺寸改变不重建终端、不清掉输入、不丢历史、不取消后台任务。
9. 端口转发与工具连接更新在新位置可找到；配置变化、验证进度与错误不被收敛掉。
10. 键盘、焦点、深浅主题、提高对比度、减少动态效果与减少透明度均可用。量化空间收益在真实原生窗口中测量。

设计依据：用户提供的 SoDeck 截图与需求；现有服务器与终端分层设计；apple-design 的层级、熟悉性、用户控制、直接反馈、空间一致性与辅助功能原则。

## 9. 本次设计检查

交互示意已通过浏览器检查：历史与返回实时、断开与重连、关闭确认取消、服务器工具入口、历史搜索与 Esc 焦点恢复、验证 / 自动重连 / 历史异常状态、10 个标签的溢出列表、三种方案切换。单行方案在约 1012、724、468、308px 预览宽度下维持 40px 工作条，操作区未溢出；已查看深浅色截图，浏览器无运行错误。

上述结果只验证设计示意，不代表应用功能已实施或原生窗口已经验收。真实连接、剪贴板、终端尺寸调整与平台辅助功能需要在后续实现中按第 8 节完成验证。
