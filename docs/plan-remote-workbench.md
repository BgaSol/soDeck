# 远程工作台：混合跳板、终端、文件及带宽统计

> 状态更新：Hello 和组件交互示例现已退役，源码、官方来源和发行配置已删除；本文有关保留或发行示例的描述属于历史方案。宿主回归改用仅测试夹具，真实业务由终端、文件、网络隧道插件提供。

状态：设计提案，尚未实现。2026-11-05 按用户最新范围制定，替代“本轮只做 SSH 直连”的执行计划。

## 1. 用户最终得到什么

从已保存的服务器目录点击连接，核心按有序的 SSH/SOCKS5 路径到达目标服务器。连接成功后打开现有服务器工作台：文件侧栏默认展开，中央默认创建一个真实终端，允许多个终端和文件编辑页混排。工作台可以拖出、合回，操作目标和后台任务保持不变。

文件插件提供远程目录浏览、小文本文件查看与修改、单文件下载。核心同时展示每台目标服务器的传输速率和累计流量，并尽量归属到使用连接的插件。

交付三个独立组件：核心、终端插件、文件插件。两个业务插件均不包含在核心安装包中，独立版本、独立发行、独立更新；不把示例插件当正式终端或文件业务继续堆积。

本轮不增加文件上传、目录递归下载、新建/重命名/删除、权限编辑、sudo 提权、文件管理右键完整工具箱、Docker、NetBird 或对用户开放的端口转发/SOCKS 服务。SSH TCP 通道与 SOCKS CONNECT 作为连接链内部能力必须实现。

## 2. 推荐的首版范围

| 功能 | 本轮范围 |
| --- | --- |
| 连接 | SSH 直连；纯 SSH、纯 SOCKS5 及任意顺序混合的有序多层路径；密码/私钥；SOCKS5 无认证或用户名密码 |
| 终端 | 默认登录 shell、ANSI/VT 渲染、输入、中文粘贴、调整尺寸、Ctrl+C、多个标签页、关闭及进程退出状态 |
| 浏览文件 | 默认登录目录、路径栏、上一级、刷新、目录/普通文件/符号链接标识、名称/大小/修改时间、排序和名称筛选 |
| 查看和编辑 | 普通 UTF-8 文本，包含 UTF-8 BOM；按原始字节最多 1 MiB；保留换行及 BOM；只修改已有文件 |
| 下载 | 单个普通文件，流式写本地、选择保存位置、进度/速率/取消；不沿用 1 MiB 编辑限制，不一次性载入内存 |
| 带宽 | 每目标服务器收发速率/累计量、每插件业务收发量与传输量估算；当前运行会话和本次应用运行累计 |
| 平台 | Windows x64/ARM64、Linux x64/ARM64、macOS ARM64 客户端；远端首先验证 Linux/OpenSSH/SFTP |

1 MiB 是建议初值，开工前可直接调整，不为此增加复杂配置页。超限或二进制文件显示文件信息并提供下载；不做有损解码后保存。其他编码先下载处理，未来按真实需求增加。普通文本编辑器先提供撤销/重做、查找、保存快捷键、行列位置，不在本轮加入语言服务和大型 IDE 编辑能力。

本轮不承诺所有 SSH 服务端实现、远端 Windows 路径或任意编码文件名。目录项的原始路径由核心保留，无法无损表示的文件名明确标识，不把替换字符拼回路径操作错误文件。远端路径不经过 Windows 本地路径规则。

## 3. 整体职责

```text
核心界面：服务器目录 → 连接进度/认证/指纹 → 服务器工作台 → 状态和流量
                                │
核心：有序连接链 → 最终会话 → PTY / 远程文件 / 数据流 / 本地文件 / 计量
                                │ 版本化调用、事件、资源句柄
             ┌──────────────────┴──────────────────┐
       终端插件后端                              文件插件后端
       终端实例、显示状态                         导航、草稿、冲突、下载任务
             │                                        │
       中央终端页面                         侧边列表 + 中央编辑页面
```

核心实现如何连接、认证、收发字节和回收资源。插件决定用户执行哪种业务、界面如何展示、是否提示覆盖或保留草稿。两个插件复用同一工作台的目标会话，不各自登录，不取得服务器密码；插件不直接互调。

连接链首版由每个工作台独立持有，链内及最终 SSH 会话被该工作台的各插件复用。不同工作台暂不做相同跳板前缀的连接池和跨链去重，避免一条共享前缀的认证、重连和引用管理把首轮实现放大。不同工作台遇到同一跳板断开仍各自识别和清理。

以下接口名称都是提案，用于说明责任和调用关系，不代表现有实现。

## 4. 核心连接链

### 4.1 路径执行

沿用现有 `route[]`，不增加另一份嵌套路径，也不递归展开被引用 SSH 档案自己的 route。例如：

```text
本机 → SSH A → SOCKS5 P → SSH B → 目标 SSH C
```

1. 本机建立到 A 的 TCP 和 SSH 会话，检查 A 指纹并认证。
2. 通过 A 的 direct-tcpip 通道访问 P，执行 SOCKS5 协商及代理认证。
3. 通过 P 的 CONNECT 访问 B，建立嵌套 SSH，检查 B 指纹并认证。
4. 通过 B 的 direct-tcpip 通道访问 C，检查 C 指纹并认证。
5. 仅将 C 的最终会话交给工作台及业务插件；A/B 不创建业务终端，P 不创建工作台。

连续 SOCKS5 按顺序在前一通道里协商；连续 SSH 同理逐层打开通道。每一跳的 `127.0.0.1`/`::1` 属于其紧邻前站环境。本机只解析首站；SSH 通道或 SOCKS CONNECT 携带下一站域名，交给相应远端解析。不尝试本地解析后续域名，不静默直连或跳过节点。

失败说明具体节点、顺序及阶段，例如“第 2 站 SOCKS5 P：认证失败”。已经建立的后续依赖按逆序释放。路径不设 1/2/3 层业务上限；仍对内存、消息和连接等待设合理预算，超限明确报错而非截断。

### 4.2 认证与主机身份

- 核心统一取当前档案的密码、私钥路径和口令，缺失时使用核心弹窗补填；SOCKS 认证同样由核心处理。
- 未记住的秘密只在本次运行内存中存在，记住的值继续按用户选择写入本机明文文件，不增加系统凭据库或加密。
- 每个 SSH 节点都检查主机密钥，首次确认或变化提示在发送该站认证秘密前完成；SOCKS5 没有等价的 SSH 指纹机制，不虚构代理身份校验。
- 信任记录使用“访问路径前缀身份 + 节点端点 + 公钥”识别，同样的私网地址经过不同路径不能误当同一台机器。前缀由端点/协议及有关 SSH 账号构成，不包含密码；改名不失效，改变访问路径重新确认。
- 私钥最低验证 OpenSSH 格式 Ed25519、RSA 的加密及未加密文件。无法读取、格式不支持、口令错误和服务端拒绝分别反馈。不自动降级旧算法或切换其他身份。
- 不自动轮询 SSH agent、用户 SSH config、其他本机私钥，不实现多因素交互认证。

### 4.3 管理接口和 Context

| 调用方 | 核心能力提案 | 调用目的 |
| --- | --- | --- |
| 核心服务器界面 | `connections.connect(serverId)` | 生成 attemptId，快照资料，后台建立整条路径 |
| 核心界面 | `connections.cancel(attemptId)` | 取消等待/握手/认证，并释放部分路径 |
| 核心弹窗 | `connections.answer(attemptId, questionId, answer)` | 补填某站凭据或确认该站指纹，拒绝过期回答 |
| 核心工作台 | `connections.disconnect(context)` | 主动断开整条会话链，保留工作台和草稿 |
| 核心工作台 | `connections.reconnect(workspaceId)` | 手动重建链，成功后原位换会话和 generation |
| 插件 | `sessions.get(context)` | 取得已连接状态与实际能力，例如 terminal/files；不取得认证资料 |
| 插件 | 会话状态事件 | 得知断线、重连和 Context 更新，停止使用旧句柄 |

Context 沿用 `{ workspaceId, serverId, connectionId, generation }`。每个资源保存创建时 Context、pluginId、pluginInstanceId、必要的 viewId 和 taskId；核心从真实调用来源附加插件身份，不信任参数声称的归属。句柄用于正确路由和生命周期，不引入插件权限系统。

重复点击同一档案只保留一个尝试，已打开则定位现有窗口。取消、档案身份变更或工作台关闭后，迟到成功必须立即清理，不能冒出工作台。已连接会话使用当时目标快照；手动重连采用当前配置，身份或路径发生变化时明确展示变化后再连接。连接进行中修改所用任一节点的身份或凭据取消旧尝试，改名/分组除外。

单阶段网络等待初始建议 30 秒，用户输入等待单独计算且可取消；后台异步任务不持有目录/工作台锁等待网络。保活与传输关闭共同识别断线；不循环自动登录或重放业务操作。

## 5. RPC、数据通道及长任务

当前 JSON 行 RPC 上限 64 KiB、UI 事件上限 24 KiB、同步请求等待约 5 秒。现有示例把完整草稿放在小事件里，不适用于 1 MiB 文件，也不适用于持续终端输出。本轮必须一起补齐这些边界。

| 通路 | 传输内容 | 规则 |
| --- | --- | --- |
| 控制 RPC | 打开终端、读取目录的请求、资源句柄、状态、小参数 | 保持有界，长操作立即返回 taskId，不全局延长超时 |
| 核心 ↔ 插件数据通道 | 文件块、流式编辑正文、必要的后台数据 | 有序分帧、streamId/序号/长度、窗口额度、关闭与取消 |
| 核心宿主 ↔ 插件 UI 的视图数据桥 | PTY 字节、正文块、编辑增量、迁移快照 | 绑定 viewId/surfaceId/Context；有序、有确认及背压，不用全局广播承载大量数据 |
| 事件 | task/会话状态、进度、限频统计 | 可重新查询最新状态，不靠事件无丢失才能正确工作 |

核心到插件进程的数据管道优先采用每次运行的本机回环 TCP，入口由初始化交付，连接绑定随机会话标识和真实插件实例；不监听外网、不使用固定端口、不建立通用 HTTP/业务服务器。它用于连接正确归属，不形成额外授权流程。插件 UI 不直接拿认证资料或通用 TCP 地址，使用宿主数据桥。具体二进制帧格式在基础能力批次固定并验证五目标。

插件可以将自己持有的流通过核心 `streams.attachView` 绑定自有视图，核心只做字节桥接；无需让终端每一个输出字节经插件进程往返。文件正文和草稿按需进入插件进程，业务仍由插件管理。

必要的通用能力：

- `tasks.get/cancel` 与状态事件：pending/running/succeeded/failed/cancelled，保存提交另允许 outcomeUnknown。
- `streams.attachView/read/write/close`：按持有资源映射到数据通道；大块内容不出现在方法参数里。
- 有界数据缓冲、流量窗口、慢消费者反馈；目录使用有界游标分批返回，不能把大目录塞入一个 JSON 响应。
- 会话断开、插件退出、流关闭时结束等待；资源释放幂等。UI 隐藏不销毁资源，旧 surface 无法继续输入。
- 不把本地 UI 中转、同一流的重复读取或重放算作新的远程带宽。

当前核心在插件输出监督循环中直接处理 plugin_request，示例插件也同步逐行分派。接真实能力时必须让读响应循环持续工作：异步派发核心调用、按 ID 匹配响应、限并发，避免“处理 ui.mount 的插件等待核心，而核心等待 ui.mount”死锁。

`ui.mount` 返回正文/快照句柄和元数据；`ui.save` 可返回 pending taskId，由关闭协调等待任务、展示进度并允许取消尚未提交的操作。关闭前先 flush 编辑增量并确认草稿版本，不用现有 5 秒请求一次包办所有远端保存。旧插件的同步返回继续可用。

新增能力以 API v1 的向后兼容扩展提供。核心初始化交付自身版本和能力集合，业务插件声明所需最小核心版本，缺能力时明确报“不支持，需升级核心”；不把 API 主版本一致误认为旧核心已有新方法，也不建立逐项授权清单。

## 6. 终端插件

### 6.1 用户操作与调用关系

| 功能 | 核心提供 | 终端插件调用后负责 |
| --- | --- | --- |
| 默认一个终端 | 现有 UI 声明和工作台首次默认创建；`terminal.open(context, term, cols, rows)` | 在逻辑视图首次创建时打开 PTY，保存 terminalId；重挂载不重新开 shell |
| 终端显示 | `terminal.open` 返回有序输入/输出流，核心桥接到当前视图 | 渲染 ANSI/VT、颜色、光标、滚动及备用屏幕；不把终端输出当普通文本框 |
| 键盘与粘贴 | 有界、有序的终端输入流 | 编码输入、中文输入法、快捷键、括号粘贴；粘贴后顺序正确 |
| 窗口尺寸变化 | `terminal.resize(terminalId, cols, rows)` | 根据实际可见区域测量并节流；隐藏或旧 surface 不覆盖活动尺寸 |
| 多个终端 | 核心创建多个视图，各自持有 PTY 资源 | 命名、定位、复制文本、清屏/本地滚动等显示操作；不同页输入不串流 |
| Ctrl+C / 默认 shell | 核心打开远端登录 shell、透传 PTY 字节 | 正常发送终端控制字符，不用本机进程模拟远端 shell |
| 正常退出/关闭 | `terminal.close`、退出事件和退出状态 | 显示已结束；关闭页面释放 PTY；隐藏/切换保留运行 |
| 断线/重连 | 核心会话事件使旧 PTY 失效 | 保留已有屏幕并提示中断；重连后由用户新建 shell，不冒充旧进程恢复 |
| 插件故障 | 核心按 pluginInstanceId 清理 PTY | 保留故障信息；不影响另一插件使用目标会话 |

PTY 只在最终目标建立，跳板仅用于通道。终端插件不实现 SSH、SOCKS 或另一套密码表单。`terminal.open` 接收结构化参数，不把用户名、路径或数据拼成 shell 命令。后续 Docker 等业务的 exec API 本轮不提前开放。

### 6.2 移窗和持续输出

跨原生窗口会重新加载插件页面，维持 PTY 句柄还不足以保留显示。终端插件需要保存渲染器屏幕/滚动状态，并结合输出序号迁移：源视图在确定序号形成快照，核心有界缓冲后续输出，目标恢复快照并接续输出，目标就绪后才切换输入和尺寸控制。失败则保留源视图，不创建第二个 shell。

快照属于终端插件，核心只提供流序号、缓冲和视图交接，不解析终端业务。移窗重放不增加远程流量。持续输出超过有界缓冲时暂停读并反馈；确实无法恢复时明确显示缺口，不假装完整，不无限增长内存。对终端历史设置合理滚动行数和序列化大小上限。

终端渲染优先评估 `@xterm/xterm` 及必需的尺寸/序列化 addon，资源构建进插件，不使用 CDN 或运行时 Node。生产依赖需在实现前说明版本、维护情况、许可证及替代方案；不自己编写一套不完整的 VT 解析器。

## 7. 文件插件：浏览和查看

| 功能 | 核心提供 | 文件插件调用后负责 |
| --- | --- | --- |
| 默认展开侧栏 | 已有 UI 声明 | 首次取得登录目录并列目录，维护当前路径与导航历史 |
| 初始路径 | `files.home(context)` | 显示服务端登录目录，不硬编码 `/root` 或 `/home/用户名` |
| 列出目录 | `files.list(context, pathRef, cursor)` | 分批展示、名称筛选和排序、加载/错误/空目录状态；不声称部分加载就是全部结果 |
| 文件信息 | `files.stat/resolve(context, pathRef)` | 展示类型、大小、时间、可用属性；打开目录或普通文件，特殊文件只显示信息 |
| 打开文本 | `files.openRead(context, pathRef, maxBytes)` 返回读取任务、流及读取完成后的版本信息 | 校验文本编码与大小，创建中央 editor 视图，保留原始文本、BOM、换行和当前草稿 |
| 同文件去重 | 核心远端路径解析结果和现有 perResource 视图去重 | 按工作台和解析后目标资源定位已有页；重复打开不覆盖未保存草稿 |
| 刷新/重新载入 | 同样的读目录/读文件能力 | 无修改直接刷新；有草稿时先问是否放弃，不自动覆盖 |
| 超限/二进制 | 核心严格读取上限，路径保留 | 显示原因和下载入口，不把部分正文当完整文件允许保存 |

核心初始用最终 SSH 会话上的 SFTP 实现文件原语，接口不暴露 SFTP 库类型。服务端无 SFTP 时终端仍可用，文件面板单独说明不可用；不使用 `ls/cat` 输出或 shell 字符串拼接作为隐式回退。

符号链接显示目标。查看/下载跟随经核心解析的普通文件目标；编辑固定到打开时解析的目标，保存前再次验证链接及目标，发生变化返回冲突。不替换符号链接本身。设备、FIFO、socket 和目录不进入文本编辑或单文件下载，避免无界阻塞。

## 8. 文件插件：修改与保存

### 8.1 普通流程

1. 插件读取小文件，保存基线版本、原始编码信息和草稿；核心在有界读取中计算内容摘要，并检查读前/读后元数据是否一致。
2. 用户输入仅更新本地插件草稿，通过有序编辑增量或分块同步进入插件后端，不在每个按键时重新读写远端。插件调用已有 `ui.updateView` 更新 dirty。
3. Ctrl+S 或“保存”先 flush 当前草稿版本，插件编码正文并检查编码后仍不超过 1 MiB，然后调用 `files.beginWrite(context, pathRef, expectedVersion, size)`。
4. 核心返回 writeId 和输入流；插件分块发送正文。暂存完成后调用 `files.commitWrite(writeId, requestId)`，通过任务等待保存结果，不堵塞 RPC。
5. 核心检查当前文件版本，提交后返回新版本。插件只把此次提交的草稿版本标为已保存；保存期间继续编辑的较新内容仍为 dirty。
6. 失败保留草稿；只有得到明确提交成功才显示“已保存”。

### 8.2 冲突、写入方式及失败

| 情况 | 核心负责 | 插件负责 |
| --- | --- | --- |
| 打开后远端内容改变 | `expectedVersion` 不匹配返回 conflict，包含最新基本信息 | 提供保留草稿、重新载入、明确覆盖等选择；覆盖也绑定最新版本，不能无限期无条件写 |
| 普通可靠保存 | 先写同目录唯一临时文件、确认完成，尽量保留基本属性；支持原子替换扩展时再替换 | 展示保存中/结果；不把暂存完成当目标更新成功 |
| 服务端无可用替换语义或属性无法保留 | 返回明确的不支持原因，不静默删除原文件或退化为截断写 | 先阻止保存并说明，可下载草稿；有真实需求再设计显式兼容写入 |
| 权限不足/磁盘满 | 返回阶段及原因，尽量清理暂存 | 保留草稿，不自动 sudo，也不让用户误以为已保存 |
| 暂存期间取消 | 结束流并清理临时资源 | 返回可编辑状态，继续保留草稿 |
| 提交瞬间断线 | 标记 outcomeUnknown，不自动重试写入 | 提示结果待确认；重连后读取并比较目标与提交摘要，再决定是否已完成 |
| 关闭未保存页面/工作台/退出 | 现有统一关闭协调，等待异步保存完成后再释放连接 | 报告 dirty/busy，提供保存、放弃、取消；失败阻止关闭 |

SFTP 通常没有“对内容版本做原子 compare-and-swap”的能力。保存前内容校验能发现多数冲突，同目录原子替换能避免半文件，但两者合起来仍不能保证任意外部进程同时写入时绝无覆盖。产品不承诺分布式锁或强事务；检查到的冲突必须提示，极短竞争窗口作为已知限制记录。

临时替换会改变 inode，硬链接、ACL、扩展属性、所有者和特殊权限可能受影响。本轮先验证普通文件与可保留的基本权限；已知的多硬链接/特殊模式/无法保持必要属性情形阻止默认保存并解释原因。SFTP 未报告的 ACL/扩展属性不能保证原样保留，不宣传适用于所有系统配置文件。成功表示服务端已确认写入/替换，不承诺服务器断电后的持久性。

插件后端在视图和移窗期间持有草稿；本轮不承诺应用崩溃或强杀后的草稿恢复。原型中 20 KiB 整段草稿事件需要替换，不能只把常量提高到 1 MiB。

## 9. 文件插件：单文件下载

| 顺序 | 核心能力 | 文件插件业务 |
| --- | --- | --- |
| 1 | `local.chooseSaveFile` 核心适配系统对话框，返回本地目标句柄 | 选中远端普通文件，给出建议文件名；取消对话框不产生下载任务 |
| 2 | `files.openRead` 打开最终服务器的文件流，检查基本信息 | 建立插件下载任务，记录服务器、来源和本地目标显示信息 |
| 3 | `transfers.copy(remoteStream, localSink)` 流式写同目录临时本地文件 | 展示已传字节、文件总大小、当前速率、取消入口 |
| 4 | `tasks.cancel` 结束读取/写入，失败或取消清理本地临时文件 | 显示取消或失败，允许重新下载；本轮不做断点续传 |
| 5 | 文件结束、读前后状态检查及本地关闭后完成替换 | 显示完成和本地位置，按需发布重要消息 |

选择已有本地文件时先明确确认覆盖；下载完成前不截断原文件。远端文件下载中可被外部修改，核心对可观察变化返回“文件已变化”，不声称读取到文件系统快照。大文件下载只用固定大小缓冲；目录、设备和递归下载本轮不支持。

核心只管理字节复制和本地路径差异，下载列表、文案、重试入口属于文件插件。隐藏侧栏或切换标签页继续下载；关闭工作台/应用时提示正在下载，可取消关闭或明确取消任务后关闭，不额外创建下载管理插件或全局任务平台。

## 10. 带宽统计

### 10.1 用户看到的含义

用户要查看每台目标服务器当前上传/下载速率、本次运行累计量，以及终端、文件等插件的占用。方向统一按 SoDeck 本机视角：本机向远端发送为上行，远端向本机为下行。使用 KiB/s、MiB/s 及累计 KiB/MiB/GiB；零流量就是 0，不等于服务器不可用。

严格区分两个计量层，避免把不同层相加：

| 口径 | 在何处计数 | 能说明什么 | 限制 |
| --- | --- | --- | --- |
| 连接传输量 | 本机到首站最外层实际 TCP socket 成功读/写的字节 | 该目标连接链在本机收发的数据量，包含 SSH/SOCKS 协议及嵌套封装 | 不包含 TCP/IP 头、操作系统重传、链路头；不是网卡抓包精确计费 |
| 插件业务量 | 核心向远端 PTY/文件等原语成功收发的有效载荷 | 某插件在某服务器发送/接收了多少业务字节 | 不包含所有协议封装，不能直接当作其独占网卡流量 |
| 插件传输量估算 | 核心按同一会话、同一方向内业务量权重分配可归属传输字节 | 便于比较插件占用连接传输的比例 | 受缓存、协议、多路复用影响，必须标“估算”，无依据时归“核心/未归属” |

默认把插件业务量作为清楚可解释的明细，旁边按需展开传输估算；不暗示两层天然严格相等。能识别的建链/认证流量归核心；空闲保活、无有效载荷的区间归核心/未归属，不强摊给最后操作的插件。

分摊初值采用同一会话、同一方向、最近约 3 秒窗口的业务字节权重：先扣除可以确实单独识别的核心阶段传输，其余传输按 `插件业务字节 / 全部插件业务字节` 估算分配；缺少业务权重时全部保留未归属。分摊值会包含混合协议开销，缓存可能使本窗口贡献与实际发送错位，所以始终为 estimated，不用它覆盖原始计数，也不声称精确测得各插件的协议占用。

初始不启用 SSH 压缩，以减少性能和统计解释差异；即使不压缩，也不能用单个采样区间的“socket 字节减业务字节”宣称精确协议开销，缓冲和计数边界会错位。界面显示总传输、业务明细、估算标识和未归属项即可，不凑一份看似精确的账单。

### 10.2 如何自动归属

核心创建资源时附加 `{workspaceId, serverId, connectionId, generation, pluginId, pluginInstanceId, resourceId, taskId?}`，插件不需要自己汇报流量，也不能通过参数把流量算给另一插件。

| 业务 | 计量点 | 计入插件业务量 |
| --- | --- | --- |
| 终端输入/粘贴 | PTY 输入实际被连接通道接纳 | 终端插件上行 UTF-8/控制字节 |
| 终端输出 | PTY 输出从远端读入 | 终端插件下行输出字节，包含终端控制序列 |
| 文件查看/下载 | SFTP 文件内容实际读入 | 文件插件下行，读取一次计一次 |
| 文件保存 | 文件正文实际写入远端暂存/写入通道 | 文件插件上行，保存前重读校验产生的下行也计入 |
| 目录/属性/控制操作 | 相应文件子系统有可观察边界的请求及响应 | 能测则计量；只能近似编码时单独标估算，不用本地 JSON 大小冒充网络字节 |
| 重试、失败前已传数据 | 同样的实际读写点 | 已消耗的数据保留累计；再次传输继续增加，不按成功文件大小反推 |
| UI 草稿输入、移窗快照、终端重放 | 全部为本地桥接 | 不计远程网络流量 |

pty/文件资源计数后经过内部多层流不得再次计入同一业务总量。以核心接纳/读取为边界统计是观察事实，不代表远端应用已经消费或磁盘持久化。底层库确实无法暴露某项边界时记录 quality 为 estimated/unavailable，不伪造准确值。

### 10.3 多层跳板不重复累计

```text
本机 → A → P → B → C：文件插件从 C 下载 5 MiB

业务归属：目标 C / 文件插件，下行约 5 MiB，校验等额外读取另计
本机传输：只累计本机到 A 的最外层 socket 实际读取，包含各层开销
跳板详情：展示 A、P、B 的路径和状态，不把 5 MiB 在三层再相加
```

每个最终目标的链拥有自己的最外层连接，因此当前可以明确把该连接传输归到 C。A 自己另外打开工作台时拥有另一条独立连接和统计记录，不把“经过 A 到 C”误算成“A 自己的终端”。同地址不同档案不合并，多个链使用同一跳板也不把它们去重。以后引入跨工作台共享传输时再增加真实共享链的统计分摊，本轮不预做。

每个节点仍记录 `{connectionId, stepId, nodeId, protocol, direction}` 的通道计数。服务器详情展开路径时，显示 A/P/B 各节点本次连接承载的速率与累计量：能在嵌套流边界测到的为通道字节，只能按目标载荷推算的标“转发估算”。同一代理重复出现在路径中按 stepId 分开，不能只用 proxyId 合并。

客户端单侧无法测到 A/P/B 各自网卡的真实带宽。上述数字是该路径经由本站承载的量，不称为跳板网卡实际流量，也不混进远程连接总传输；多层数字不相加。GitHub 核心/插件更新下载属于其他联网，不计入某台远程服务器的终端/文件流量。

### 10.4 采样、数据与展示

- 核心维护 64 位累计字节数，成功读写时低成本更新；单调时钟每秒采样，通过实际间隔计算速率，界面默认显示最近约 3 秒平滑速率。
- 统计不持有网络锁、不逐字节写日志，也不为统计抓取/保存终端内容或文件正文。采样结果限频推送，面板关闭仍累计，重新打开可查询快照。
- 提供核心 `metrics.networkSnapshot({serverId?, connectionId?})`，返回传输总量、速率、按插件明细、quality 和统计窗口；更新事件约每秒一次。业务插件无需主动调用才能被统计，也可查询自己的任务指标。
- 内部以整数计数，向 JavaScript 提供累计整数的安全表示，超过安全整数范围不丢精度；不要用一个 32 位数累计大文件流量。
- 连接级统计随 connectionId 分开；服务器/pluginId 的“本次运行累计”跨手动重连继续累加。插件实例退出不删已消耗流量；重启应用从零开始。
- 当前速率在资源结束或断线后及时归零，累计保留；移窗不新建计数器。已结束资源只保留聚合结果，避免统计明细无限增长。
- 本轮不做历史数据库、日/月报表、网卡监控、带宽限速或额度策略。

展示使用现有两个位置：工作台底部显示该目标 `↓ 320 KiB/s  ↑ 8 KiB/s`，点击在核心状态浮层定位该服务器详情；右上角系统状态中增加服务器列表，可展开插件明细。首版用数字和简单占比即可，不额外做一个监控插件或复杂图表页。

示意：

```text
生产 C    已连接   经 A → P → B
连接传输   ↓ 326 KiB/s  ↑ 9 KiB/s     本次运行 ↓ 18.4 MiB
插件业务：
  文件     ↓ 320 KiB/s  ↑ 8 KiB/s     本次运行 ↓ 18.0 MiB
  终端     ↓ 1.2 KiB/s  ↑ 0.1 KiB/s   本次运行 ↓ 92 KiB
插件传输分摊：估算；协议与未归属流量单列，口径说明可展开
```

## 11. 跨业务生命周期

| 场景 | 核心处理 | 插件处理 |
| --- | --- | --- |
| 切换工作台/侧栏隐藏 | 保留会话、PTY、流和任务，继续计量 | 保留终端和草稿；隐藏不取消下载 |
| 移窗/合回 | 原 workspaceId/connectionId/generation 不变；换 surface，拦截旧输入 | 恢复终端显示和草稿；不重新登录或读文件覆盖草稿 |
| 上游任一跳断线 | 下游连接和资源失效，发布一次可定位的会话事件 | 终端显示中断，下载失败，文件草稿保留；不重复通知轰炸 |
| 手动重连成功 | 同工作台换 connectionId、递增 generation，旧句柄拒绝 | 文件可刷新；已有草稿重新检查远端版本后才保存；终端不自动重放命令 |
| 文件插件异常 | 回收其文件流/下载/暂存，保留终端和工作台会话 | 故障可见，未承诺进程崩溃草稿恢复 |
| 终端插件异常 | 关闭其 PTY，文件操作不受牵连 | 故障可见，不把已退出 PTY 伪装成可恢复 |
| 关闭终端页 | 统一视图释放调用 terminal.close | 停止其交互，其他终端保留 |
| 关闭编辑页 | 先检查 dirty/busy，保存/放弃/取消后释放 | 保存失败继续保留页面 |
| 关闭工作台/子窗口/退出/升级重启 | 汇总未保存及任务，确认后停止插件业务，再关闭链，最后退出 | 下载须明确取消或取消关闭；保存未确认不显示成功 |

退出停止新业务创建，保留必要的保存/收尾通路直到关闭协调完成。不允许先把 Context 全部设失效再询问是否保存。插件启用、关闭和升级依旧通过重启生效，不增加热加载方案。

## 12. 工程落点与依赖

核心建议逐步增加 connections（路径/认证/会话）、terminal（PTY 原语）、remote_files（文件原语）、streams/tasks、network_metrics。保持目录管理和工作台布局原有职责，按实际第二用例复用流与任务，不建立通用工作流引擎或多协议插件框架。

独立插件目录建议 `plugins/terminal`、`plugins/files`，各自包含 Rust 入口、预构建 UI、release.json、版本与锁文件。插件前端资源如需构建，在自己的目录声明工具和锁文件；核心打包不导入插件依赖。现有 ui-example 留作宿主测试，不混入正式业务。

依赖候选为 russh（SSH 与可嵌套流）、配套 SFTP 库、终端渲染器和所需异步/流工具。先验证五目标构建、所需算法、direct-tcpip、自定义流及 SFTP 扩展，不因“Rust 实现”假设不存在原生加密构建依赖。逐项说明用途、维护状态、许可证、精确版本和替代方案后才加入。当前计划不新增生产依赖。

保持核心 API/参数/资源状态检查；无需权限列表、审批或签名信任链。应用与插件发布沿用现有版本标签和 GitHub Releases，不新增发布批次框架。

## 13. 实施拆分与验收

这是一个完整版本范围，内部按六个可验证批次完成；不是先发布六个只加入口的版本。

| 批次 | 交付 | 核心验收 |
| --- | --- | --- |
| 1. 真实连接链 | 资料快照、SSH/SOCKS 组合、认证/指纹、取消和清理；最外层计数点 | 直连、SSH、SOCKS、SSH→SOCKS、SOCKS→SSH、连续代理、至少三层混合；后续 DNS 不在本机解析；失败指出具体站 |
| 2. 资源与数据通道 | 异步双向 RPC、流、长任务、视图绑定、插件归属、计量基础 | 不死锁；慢消费者内存有界；旧 Context/surface 拒绝；统计不因本地中转重复 |
| 3. 正式终端插件 | PTY、多个终端、渲染、尺寸、输入、窗口迁移 | 中文/粘贴/Ctrl+C/全屏终端程序；两服务器多终端不串；持续输出移窗不丢正常输入、不新开 shell |
| 4. 文件列表与读取 | SFTP 原语、侧栏导航、分页、元数据、文本页和去重 | 中文及空格路径、空目录/大目录、权限不足、无 SFTP、链接目标、超限与二进制；正文不受控制帧大小限制 |
| 5. 文件保存与下载 | 草稿增量、版本检查、可靠提交、流式下载及关闭协调 | 1 MiB 边界、外部修改、断线结果未知、磁盘满、取消、覆盖前保留本地原件；大下载内存有界 |
| 6. 统计展示与发行 | 服务器/插件明细、估算说明、核心及两插件独立包、文档 | 已知字节数校验；混合跳板不倍增；移窗/重连/插件故障后累计正确；五目标实际包集成 |

计量埋点随第 1/2 批实现，不等所有业务完成再猜测流量来源。后面的文件用例会验证同一流能力能服务终端之外的第二个真实业务。

### 自动验收重点

1. 用隔离 SSH/SOCKS 测试网络，构造仅远端能解析/访问的后续地址；验证没有本地 DNS 泄漏和直连回退。使用独立 OpenSSH 服务做互操作验证，不能只用同一库客户端/服务端互证。
2. 注入每站认证失败、断线、超时和取消，观察任务/流/线程及端口资源结束；重复点击和迟到回复不产生假工作台。
3. 用真实外置插件进程驱动 PTY 与 SFTP，覆盖双向 RPC 等待、输出压力、数据通道取消和插件异常退出。
4. 使用无头 UI 和原生包验证终端输入、尺寸、可见性、移窗/合回、草稿 flush、保存失败和统一关闭。中文输入法/跨 DPI 等人工项单独记录，不用浏览器自动化结果代替。
5. 保存测试包含编辑期间再输入、远端外部修改、链接改变、原子替换不可用、权限/磁盘错误和提交时断线，确认不误报保存成功。
6. 下载测试包含 0 字节、较大文件、取消、同名本地文件、远端变化和重试；校验输出字节及本地原件保持。
7. 带宽测试对已知大小内容、失败前部分传输、重试、终端控制字节、目录估算、无业务保活分别核算；控制时钟验证速率，跨跳只累计一次最外层传输。

沿用 `npm run check`、`npm run test`、`npm run scripts:test`、`npm run ui:test` 和构建入口，实施时把新用例加入实际命令，不在文档阶段创建调用不存在入口的工作流。

五目标分别原生构建核心与两个插件，安装/解包实际发行包后连接隔离测试端，验证终端、读写与下载、断线及退出。ARM64 使用原生程序，不能把交叉编译当作运行验证。各组件仍独立构建，组合验收在集成工作流完成；未运行的平台或人工场景明确记录。

## 14. 完成定义与已知边界

从目录通过混合跳板连接真实服务器，默认终端可用，文件可浏览/下载/修改小文本，同一工作台内两个插件复用最终会话；移窗不改变操作目标和正常运行资源，断线不丢未主动放弃的草稿，关闭能清理整条链。状态浮层可查看服务器总传输和插件明细，计量口径及估算明确。核心及两插件分别可安装、可升级，五目标验证有据可查。

已知边界：客户端计量不等于网卡计费；插件绕过核心自行联网无法自动归属到目标服务器；任意远端并发写入不具备强 CAS 保证；复杂 ACL/硬链接/特殊文件不承诺安全编辑；网络提交失联可能需要读取确认；不恢复旧远端进程、不提供应用崩溃草稿恢复或下载断点续传。所有这些边界在对应操作中准确反馈，不扩展成权限或审批体系。
