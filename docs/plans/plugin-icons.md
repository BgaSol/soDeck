# 插件图标归属修复方案

状态：实现完成，正在准备核心 1.5.2 与 Agent MCP 0.2.3 独立发行。

## 目标与边界

插件拥有图标文件和引用声明；核心提供通用解析、资源读取、显示尺寸、主题着色及失败回退。接入这套声明后，更换插件图标只需要重新打包、发行该插件。

当前问题贯穿整条链路：[ui.ts](../../src/ui.ts)保存机器人、Docker 等图形，[plugin-build.mjs](../../scripts/plugin-build.mjs)未将顶层图标声明写入安装包，[plugin-settings.ts](../../src/plugin-settings.ts)从官方目录查找已安装插件的图标。仅移动 SVG 或只改某个页面，不能解决归属问题。

本次覆盖插件管理、更新列表、侧栏、编辑标签及其选择列表、组件设置导航和官方目录预览。字体预览、共享字体仓库及其他构建耦合保留在各自任务中。

## 声明：现有引用加插件内映射

保留现有 `icon` 字符串作为逻辑名称，新增可选的 `icons` 映射。名称限定在声明它的插件内，不进入核心的全局图标表。

```json
{
  "icon": "bot",
  "icons": {
    "bot": "assets/icons/robot.svg"
  }
}
```

UI 视图和设置页面继续使用已有的 `"icon": "bot"`。不同视图确有不同图标时，在同一映射中增加相应项；机器人接口的三个入口复用一个文件。这个映射同时满足已有名称引用的兼容和多个入口的资源复用，不新增图标注册 RPC、全局名称、优先级或主题变体配置。

本轮资源契约为自包含的单色 SVG，路径相对于插件包根目录。SVG 自带 viewBox 和描边/填充几何；核心等比放入统一尺寸的显示框，以当前界面颜色着色。插件通过几何和透明区域定义外形，核心不改写图形。单文件上限为 32 KiB，映射最多 32 项。

`release.json`中的 `icon`、`icons` 原样进入生成的 `plugin.json`。打包脚本按映射复制图标，不依赖插件目录名或核心图标库。名称、相对路径、类型和大小在打包时检查；引用的文件缺失或越出插件目录时，打包失败。

## 资源读取与展示

核心从当前生效包解析图标名称。运行中的插件使用当前运行包，未运行的插件使用当前登记包；待重启升级的候选包遵循现有切换时机。图标可在插件关闭、未启动或启动失败时读取，不要求 UI 或设置声明存在。

复用现有 `sodeck-plugin` 本地资源协议及包内路径检查，提供独立于进程状态的图标读取入口。该入口只读取映射声明的图标；现有运行界面资源的生命周期检查继续保留。资源 URL 携带包版本，更新或回退后随当前包切换，避免沿用旧版本图片。

宿主统一把插件图标解析为可渲染的来源，再交给各页面；页面不自行读清单、查官方目录或拼接文件路径。核心按钮的加号、关闭等通用图标继续使用核心图标库。

外部 SVG 以浏览器图片/遮罩方式显示，不把插件 SVG 文本插入宿主 DOM，不实现 SVG 重写或清洗器。加载成功后显示主题色遮罩；加载或解码失败时显示通用插件图标。复用当前 CSP，精确允许所需的本地图片资源来源。

已安装插件的图标以当前包声明为准。官方目录不能覆盖它；文件缺失、读取失败、SVG 损坏仅影响该图标，记录原因并回退，不阻止插件业务运行。

## 官方目录预览

未安装插件没有本地包，官方目录从同一插件的 `release.json`读取默认图标名称及映射，再从本次已读取的 Git 树中定位对应 SVG blob。配置和 SVG 固定到同一树快照，不让浏览器追随任意远程图片 URL。

仅获取目录默认图标，不获取该插件全部视图图标。小型图标字节随现有官方目录缓存保存，复用既有 GitHub 请求及刷新流程；缓存读取上限随有界图标数据调整，不新增图片下载服务、数据库或独立刷新任务。单个图标获取失败只回退该项，目录本身仍可使用；离线沿用已有目录和图标缓存。

预览来源与安装包来源分别读取同一份插件声明，不在核心维护官方插件名单或另存一份业务图形。

## 兼容与迁移

新核心优先查插件的 `icons` 映射。某名称已在映射中声明但资源损坏时，使用通用回退，不用同名内置图案掩盖错误。未进入映射的名称沿用既有内置名称兼容规则，未知名称使用通用回退。

旧插件继续运行；旧核心会忽略新增的映射字段，沿用现有名称显示。机器人接口保留已有 `bot` 名称，新旧核心均可加载；不支持该名称的更早核心仍可运行插件，但会显示旧核心的默认图案。本次不改变核心 API/UI 主版本或插件技术 ID。

现有业务图形作为旧插件兼容数据冻结，不再随新插件图形变化扩展。新声明的正常路径始终使用插件文件；兼容按名称统一处理，不判断 `sodeck.mcp`、`sodeck.docker` 等具体插件 ID。

本次先迁移机器人接口，确认完整链路。其余插件可以在各自发行时接入同一声明，核心能力不等待它们联动升级。旧插件尚未迁移时仍使用兼容图标，不能因此宣布所有旧声明均已迁移。

## 实施顺序

1. 增加清单字段和通用图标来源解析，接入当前包选择及本地资源协议；补充资源路径和关闭插件读取的回归。
2. 打包入口复制声明资产并保留元信息；机器人接口添加自有 SVG，三个入口继续引用同一名称。
3. 所有宿主插件图标入口改用统一渲染来源，覆盖列表、侧栏、标签、选择列表、设置和更新页。
4. 官方目录读取同源默认 SVG，并扩展现有缓存；验证旧配置、旧缓存及单项获取失败。
5. 同步正式 API、架构、插件管理及机器人接口说明，执行检查与原生验收。实现和约定验收完成后，将规则归入正式文档并删除此计划。

## 验收行为

- 用具有任意插件 ID、核心未收录图标名的夹具，验证包内图标在所有入口正确显示；两个插件使用同名图标时互不串图。
- 关闭、未启动和启动失败的插件仍可显示包内图标；已安装插件在离线且没有官方目录缓存时也可显示自己的图标。
- 只修改插件 SVG 并升级插件版本，各入口更新；核心源码与版本无需变化。待重启升级不提前显示候选包图标，回退恢复对应旧包图标。
- 路径穿越、包外链接、超限文件、缺失资源和损坏 SVG得到明确结果；运行时图标失败保持通用回退，插件业务继续可用。
- 官方配置与图标使用同一树快照；单项图标失败不阻断目录，缓存可离线显示，旧核心/旧插件/旧缓存兼容得到验证。
- 三主题、禁用状态、选中状态、标签与侧栏不同尺寸下保持颜色、比例和可见性；不因图标加载重建 iframe 或远程资源。

按[开发指南](../development.md)运行相关格式、类型、构建、脚本、核心及 UI 回归，并检查真实插件包中包含声明资源。发行验收沿用[分发文档](../distribution.md)：受改动影响的核心和机器人接口插件各自完成五平台原生产物、实际包启动退出与界面验证，分别记录证据，不建立其他插件联动门禁。
