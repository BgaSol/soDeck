# MCP 交互执行

状态：实现完成，等待本次源码与发行验收。核心 1.10.0、MCP 0.7.0。

## 已确定边界

共同远端执行器已替代短命令、命令流和终端的重复通道循环；服务保留各自接纳、存储和额度。旧流入口适配同一进程资源表。交互使用原任务、连续序号和通用字节输入；没有提示识别、自动重跑、运行中 PTY 升级、跨重启恢复或新生产依赖。

已实现行为与契约分别维护在 [Agent MCP](../features/mcp.md)、[MCP API](../mcp-api.md)、[插件 API](../plugin-api.md)及[架构](../architecture.md)。

## 剩余验收与发布

- 核对本次类型、格式、工程脚本、核心/MCP 单元及受控 SSH 回归。
- 真实 OpenSSH 验证多轮 pipe、跨块输入、EOF、PTY 终端控制和持续 shell；Linux 使用一次性账号验证真实 sudo 的错误密码后同任务继续。
- 五平台原生核心源码及实际安装包启动/退出；MCP 五平台原始包的工具发现、输入/回包丢失、去重、查询、生命周期与退出。
- 完成所选终端输入/历史、Docker、系统状态与 UI 等共同执行器回归。来源 Check 的跳过项逐项保留实际范围。
- 固定 main 来源，分别运行 Package SoDeck 与 Package plugin，五平台验收后发布同一草稿附件。核心设为 Latest，插件保持独立版本发现。
- 把来源提交、原始打包 run、Release、五份验证报告及实际跳过范围回写 [核心发行记录](../releases/v1.10.0.md)和 [MCP CHANGELOG](../../plugins/mcp/CHANGELOG.md)，删除本计划。

Windows/Linux/macOS 的测试必须按实际远端行为验收，不能由 Linux sudo 推定其他系统。五平台包内控制测试使用实际插件包和匹配 process.v1 的受控宿主；真实 SSH 集成使用本次核心夹具，不冒充五平台已安装应用组合。真实 300 秒持续等待、物理 IME/DPI/读屏、netem 与已安装应用升级属于另行专项，发行记录明确其未执行范围。
