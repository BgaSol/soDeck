# 日志工作台验收与发布收尾

状态：实现和已选自动检查通过，剩余专项未执行，尚未发行。本文是本主题唯一执行计划。正式行为与配额以[Docker功能](../features/docker.md)和[插件API](../plugin-api.md)为准；既有源码、原始包run和实际证据见[待发行记录](../releases/log-workbench-candidate.md)，不重复算作新增验收。

2026-11-15设备条件：用户只有当前Windows x86_64，没有其他设备或双显示器。执行前记录OS、WebView2、CPU/内存、分辨率、系统缩放和输入设备。五平台原生CI继续使用；其他平台实体IME、触控板、混合DPI缺环境，不能记为通过，也不取消四个平台的正式支持。

## 1. 验收行为与结果

每项只记“未执行、通过、失败、缺环境”，附组件来源和证据。初始化失败、缺报告、超时、只有程序启动均不算业务通过；合成composition/pointer事件不证明系统输入法或设备手势。

| 编号 | 必须证明的行为 |
| --- | --- |
| L1 接收与阅读 | 跟随时保持最新；固定后后台继续接收，当前记录/行内位置不漂移；返回最新恢复跟随 |
| L2 查询与留证 | 搜索/筛选/上下文/详情/缩略只覆盖保留记录，复制/导出原字节正确；真实重复行保留，条件清除恢复正确窗口 |
| L3 有界与缺口 | 预览、完整区间、滚动和保护窗口遵守现有配额；容量/超时/gap明确显示，不能伪装为完整历史 |
| L4 生命周期 | 隐藏不停止采集，移窗不重执行，迁移取消保留原状态；断线保留旧捕获，关闭/停用/退出清理所属资源，独立终端保持可用 |
| L5 保存 | 选择/取消/成功/失败有真实结果；成功前保留旧目标，失败/取消不损坏旧文件；冻结结果不混入随后日志 |
| L6 设备 | Windows真实IME、选区、键盘、鼠标、单屏系统缩放可用；三主题/窄栏保留同一操作路径 |

可执行项失败先修复，不删除断言或只改文档放行。缺环境项单列，完整设备体验验收仍保持未完成；候选证据齐全后根据实际剩余风险决定是否发布，不预先把缺项改为通过。

## 4. 测试源与正确性对照

只使用自建测试容器/daemon、SSH账户、应用/保存目录，资源有本次唯一标识和清理登记。延续docker:test的隔离Engine24.0.9，固定镜像/驱动参数，限制fixture磁盘，不操作生产服务器或宿主Docker socket。清理只作用于明确登记的自身资源。

数据覆盖stdout/stderr、中文/emoji、JSON级别、ANSI、空行、无源时间、跨日、同时间密集记录、重复正文、超长单行。可对照记录带递增序号、来源、确定正文；另保留无序号的真实重复行。保存Engine输出及核心原始信封；导出以冻结时实际保留原字节为真值，分离元数据头部后核对正文SHA-256/数量/来源，不用UI格式化文本当真值。

无断线的保留区间检查序号与重复记录。断线/轮转/时钟变化按CLI限制验证缺口和提示，不额外承诺稳定日志ID、恰好一次或无缝衔接。跨平台原生页面可用受控SSH命令夹具检查客户端链路，不把它当作真实Engine/rootless兼容证据。

## 5. 日志、资源和压力用例

| 编号 | 场景/操作 | 通过标准 |
| --- | --- | --- |
| S1 历史密度 | 保留百万行有限尾部回归；补最近15分钟密集输出、完整区间及向前补读 | 预览不下载全文；条数/字节/范围上限真实；容量或超时明确部分读取 |
| S2 多轮轮换 | 近期至少轮换10次，固定可识别记录；另验证搜索/详情/返最新 | 固定ID和行内偏移不因后台接收漂移；用户导航/筛选的主动位置变化按操作核对；返最新释放保护，资源有界 |
| S3 ACK/隐藏 | ACK延迟0.2/2秒、暂停30秒再恢复；另隐藏30秒、撤销旧Surface、移窗重挂载 | 采集继续、积压有界、退出窗口明确gap；旧读者不影响新页，恢复不重执行 |
| S4 记录边界 | UTF-8/JSONL跨16KiB帧；1MiB边界及2MiB/8MiB单行；重复/纳秒半开边界 | 分片可重建，超长明确不完整且拒绝伪完整导出；不以stderr猜ERROR或按文本删重复 |
| S5 多页额度 | 两个日志页，固定与完整捕获接近/超配额，释放一页再试 | 拒绝原因明确，其他页/终端可用，释放恢复额度；不串对象/视图 |
| S6 生命周期 | 接收/补读/查询时断线、迁移取消、关View、停用、退出，再明确重连读取 | 旧捕获可读，旧命令不重放，迟到结果不覆盖新页；资源回收 |
| S7 Engine | TTY、空输出长连接、不可读驱动、rootless自定义socket、轮转、容器/Engine更换、源时钟跳变 | 支持场景符合文档，不支持明确错误/限制；不串旧对象，不提权或自动换socket |

负载初始参数：稳态1000条/秒、典型128字节正文运行30分钟；另8MiB/秒突发30秒。记录生成/传输/实际接收速率及丢弃边界，不把发送目标当接收结果。60分钟耐久交替跟随、固定、隐藏、搜索、开/关，至少经历10轮淘汰；运行前设fixture磁盘预算、超时和清理，不靠无限写盘制造压力。

分别计时点击→远端首字节、首正文块到UI→可读首屏、最后输入→结果/计数/高亮、导航→目标记录可见。交互至少30次，报P50/P95/最大值；同步采集长任务、各进程/Worker内存、保留行数/字节、捕获磁盘和速率，不只测Worker计算。长任务/Worker内存接口不可用时标未测，帧间隔与消息往返可作补充，不能冒充同一指标。

以下是待验证目标，不是已有结果或功能承诺：Windows参考环境可读首屏P95≤500ms（从首正文块到UI起），5万条搜索P95≤300ms、20万条≤1000ms，上一处/下一处或缩略定位P95≤100ms；持续交互无超过100ms的应用主线程任务。首次资源加载/SSH时间另记，先测同环境基线；未达先定位原因，不降低样本或事后改门槛掩盖问题。

配额以正式文档为准，不把Worker估算字节等同RSS，允许受限对象/引擎缓存及分段开销但记录实际峰值。固定保留规模最后10分钟的RSS/磁盘不能持续随累计接收量增长。20次开/关后采集通道、读者、pin、日志Worker和临时文件无遗留；无需内存立刻回到启动值，有界共享缓存单独说明。

## 6. 保存和故障用例

| 编号 | 场景/操作 | 通过标准 |
| --- | --- | --- |
| E1 OS保存框 | 中文/空格路径、新文件、覆盖、Esc/取消，取消后再保存 | 对话框真实返回所选路径；取消不生成最终文件，旧目标摘要不变；重试正常 |
| E2 冻结导出 | 筛选结果/选中行上下文导出，同时继续接收 | 元数据正确，正文与冻结原字节一致，不混入后续日志；复制另对照 |
| E3 写入/提交失败 | 无写权限、目标占用/锁定、受控短写/磁盘满、rename失败 | 不报完成，旧目标保留，临时文件回收；清理失败可定位，能够另选路径重试 |
| E4 竞争/来源 | 分块延迟/重复、取消与finish并发、目标外部改变、关闭来源/移窗/停用 | 顺序/原票据正确；未完成取消保留旧目标，已完成不撤销；来源失效不再写，移动遵守完成或取消规则 |
| E5 离线/期限 | 完整捕获后断线导出，OS框/接收等待超时，迟到选择回调 | 本地完整结果可留证，超时契约有效，迟到回调不复活旧任务或遗留临时文件 |

通用顺序、故障和所有者回归放核心并随五平台native-core执行，Docker只测冻结内容/范围/展示。磁盘满/短写用测试限定注入或专用小容量临时卷，绝不填满用户磁盘；注入不等于OS真实磁盘满，分别记录。Windows真实目标锁定/访问失败另实测。现有size/mtime目标检查不升级为所有外部并发写入的事务隔离承诺。

## 8. 证据、失败和发布闭环

每次报告含测试提交、组件版本/源码/run/target/SHA-256、OS/WebView/硬件/缩放、fixture参数、用例ID、实际结果、耗时/资源、截图/日志和清理。普通产物置于忽略的artifacts/log-validation/<本次run>/，防覆盖；必要证据迁入核心docs/releases/或插件CHANGELOG关联附件，不只依赖会过期的CI Artifact。

失败先保留输入/原字节/来源，定位核心捕获/导出、Docker索引/交互或系统适配，能稳定复现加回归，在正确归属处修复。重试成功仍记首次失败原因，间歇失败不能反复重跑筛一次绿色。只复跑失败目标/verify/汇总；源码变动后旧包不代表新代码，仅为受影响的独立组件形成新候选。
