# 服务器连接分享与导入整改方案

状态：2026-11-26，代码链路审查后的待实现方案。本次只编写方案，未实现功能、修改目录格式或执行发行验收。需求与实现规划统一维护在本文件；正式功能行为仍以[服务器与连接](../features/connections.md)为准。

## 1. 目标与边界

用户在一台电脑复制完整连接分享码，在另一台电脑的 SoDeck 粘贴、预览并导入。支持单台服务器和全部服务器；单台自动包含实际需要的 SSH/SOCKS5 中转、标签、可用凭据及私钥内容。导入形成独立资料，立即可见，由用户主动连接。

固定以下行为，避免实现时继续增加选项：

- 以已保存配置为准；不读取未保存表单、连接尝试中尚未接纳的认证输入或插件私有配置。
- 默认携带核心中已经保存或在本次运行中可用的密码、代理密码和私钥口令。密码缺失允许导出，摘要标明需要补填；已配置的私钥文件不可读、超限或格式不支持时，整份导出失败。
- 私钥尚未选择时保留“连接时选择”的状态，不编造路径；有加密私钥而无口令时保留原加密内容，摘要提示连接时补填。
- 单台包含目标及其显式路径节点，不带其他下游服务器，也不递归展开中转资料自身保存的路线。附带 SSH 节点的独立路线使用目标路线中位于它之前的前缀。
- 全部包含所有保存的 SSH 服务器及其引用的代理，不受当前筛选影响，保留每台服务器自己的路线。未被引用的独立代理不包含在内。
- 包内按原记录身份保留共用关系；相同地址、账号或名称不构成合并理由。私钥按文件内容在包内去重。
- 导入始终新增，不覆盖或自动复用接收端已有端点；重复导入再次新增。标签按现有名称规则复用，同名端点自动加“（导入）”及序号。
- 不自动连接，不带发送端主机信任记录。连接时继续使用接收端已有的主机密钥核验机制，包括已经存在的适用信任记录。
- 分享码采用 `SODECK1:` 加标准 Base64 编码的 UTF-8 JSON。Base64 不提供保密或真实性保护，界面在复制前直接说明包含认证信息。

不包含账号同步、远程分享服务、二维码、系统 URL 唤起、加密分享口令、覆盖合并、多选分享和插件业务配置。本次不新增生产依赖，不重写连接协议或认证系统。

## 3. 核心结构调整

主链路为：桌面命令 → 核心分享服务 → 当前目录候选构造及校验 → 受管私钥发布 → 现有目录提交 → 非敏感结果与现有变更事件。

### 保持稳定的部分

保留 `servers.json` schema v2、`Authentication::PrivateKey` 的路径式模型、公开目录的脱敏投影和现有插件 API。导入私钥由核心保存到接收端应用数据目录，目录认证字段仍然引用本机路径。因此普通连接、复制资料、认证补填及插件部分更新能够继续使用原模型，不需要让私钥正文穿过整个系统。

保留普通用户自选私钥文件的管理方式。受管副本与源文件分开：核心只能清理自己创建的受管文件，绝不删除用户选择的外部私钥。

### 只提取已经出现第二个用例的公共逻辑

1. 将目录结构校验与字段规范化从 `change.rs` 提取到 `servers/validation.rs`，供原读写与导入共用。建立 ID/标签索引，替换每条引用扫描整个数组的检查，避免批量导入引入明显的平方级查找；保留原错误和允许行为。
2. 提取核心可用凭据读取函数，供连接快照、复制沿用和分享使用。按现有实际连接的选择顺序读取临时值与持久值；不让分享另写一套选择顺序，不暴露取秘密的公开 API。
3. 将 SSH 私钥限长读取、OpenSSH 格式检查与解密解析中的公共部分放入 `connections/private_key.rs`。连接、导出和导入共用字节上限及格式支持；网络握手、认证失败重试和提示仍留在连接服务。
4. 提取很小的目录候选提交与提交后通知收尾，普通变更与整批导入复用。存储提交、取消过期连接尝试、工作区名称刷新与事件发布的顺序保持一致，释放状态锁后才通知。

新增 `servers/sharing.rs` 承担固定 v1 分享格式、单台/全部收集、纯解析、摘要及导入候选构造；新增 `servers/managed_keys.rs` 只承担受管目录、私钥准备、发布与保守清理。不引入通用导入引擎、事务框架或凭据仓库。

## 4. 分享格式与收集算法

分享格式是独立外部契约，不能直接序列化磁盘 Catalog，也不能从脱敏的前端 Catalog 拼装。

`ShareBundleV1` 只包含以下概念：

| 字段 | 含义 |
| --- | --- |
| `scope` | 单台或全部，用于摘要和校验 |
| `targets` | 用户主动分享的服务器在包内的标识，供导入后定位 |
| `servers` | SSH 端点、认证、标签和显式路线 |
| `proxies` | 被引用的 SOCKS5 端点及认证 |
| `keys` | 私钥正文，端点认证按包内标识引用 |

包内标识重新分配，只表达本包内的关联；不传本机路径、目录修订、来源设备 ID、创建时间或连接状态。标签直接使用名称，无须携带另一套全局标签 ID。版本由 `SODECK1:` 决定，不把应用发行版本当作格式版本。

单台导出的处理：读取目标的显式路线，依次加入中转和目标；附带 SSH 的路线设为它之前的显式前缀。全部导出：收集所有 SSH 资料，按原记录引用映射路线，再加入实际引用的代理。两者都先按原记录 ID 分配包内标识，再映射引用；不能按 host 去重。

核心在目录锁内复制本次所需配置和可用凭据，释放锁后限长读取私钥。相同文件只读一次，按实际字节去重。返回前再次确认相关配置、凭据及目录修订未变化；变化时提示重新生成，不返回混合时点的数据。对外部私钥使用一次读取获得的字节快照，不承诺冻结由外部程序修改的文件。

加密私钥保持原有加密字节，不为分享解密重写。共享格式解析能够判断 OpenSSH 结构和支持算法；缺口令允许通过，错误口令和已经过期的登录密码由正常连接处理，不在导入时探测远端。

边界与错误规则：

- 原始输入和最终分享码均限制为 8 MiB，解码 JSON 使用由 Base64 长度推导的至多约 6 MiB 预算；私钥仍为单份 1 MiB。先检查输入长度，再去除 ASCII 空白、解码和解析。
- 只接受带固定前缀的标准 Base64、合法 UTF-8 和 v1 结构；保留 serde 默认递归深度保护。v1 拒绝未知结构字段，未来不兼容变化使用新前缀。
- 检查包内重复标识、缺失引用、目标范围、认证与协议组合、主机端口、标签及密钥格式。允许明确的凭据缺失，拒绝结构上的依赖缺失。
- 所有端点和密钥必须属于目标所需集合，拒绝未引用的附带数据；不加载任意本机路径或外部资源。
- 出错只返回固定错误码、字段位置或端点标识，不转发可能含密码的 serde/密钥库原始错误，不打印输入、解码正文或私钥内容。
- 不增加压缩、签名、独立校验和或自动修复格式。格式正确也不等于来源可信，依靠复制前提示说明实际性质。

## 5. 导入预览与一致性

采用三个明确的桌面命令：

| 命令 | 输入 | 输出与副作用 |
| --- | --- | --- |
| `export_server_share` | 单台 ID 或全部、当前目录修订 | 分享码和非敏感摘要；不改目录、不连接、不写剪贴板 |
| `preview_server_share` | 分享码 | 当前目录修订、最终名称、目标/附带节点数量、路线、凭据状态；不落盘 |
| `import_server_share` | 与预览对应的分享码、预览时目录修订 | 新目录非敏感投影、目标 ID、全部新增 ID 和统计；整批提交 |

前端不提交自行修改的解码对象、私钥落盘路径或预览候选。预览和提交调用同一个核心解析、命名与映射函数；提交独立重新校验原字符串。最终 ID 在提交时由核心生成，包内所有引用一次映射。

前端把“预览对应的原字符串 + 修订号”作为不可变的一组状态。任何输入变化立即作废预览与导入按钮，使用请求代次忽略旧预览结果。目录修订变化时保留字符串，重新预览后再由用户点击导入，不静默改变名称或提交。

已有名称及本次已分配名称共用名称集合，按稳定输入顺序生成“原名”“原名（导入）”“原名（导入 2）”等结果。原目录中已存在的重复名称不改动。标签沿用现有 trim 和大小写比较规则，不能新增另一套 Unicode 或分隔符归一化。

不为预览创建服务端令牌、定时清理表或持久任务。修订号 CAS 防止同一次提交因连点或直接重试成功两次。桌面 IPC 的成功响应丢失时不自动重试、不自动更新修订号再次提交；刷新后明确提示核对结果。用户主动重新预览并导入，按新导入处理，不承诺跨进程的请求幂等去重。

摘要区分“分享目标数”和“附带 SSH/代理数”，例如“1 台目标服务器，附带 2 台跳板、1 个代理”，避免把单台分享误显示为分享三台目标。列表默认显示有限数量的摘要行，余项展开；保持完整数据，不创建树状勾选器或为此引入虚拟列表依赖。

## 6. 目录与私钥的一致性提交

导入不循环调用 `change_catalog(saveServer)`：逐条写入会增长多个修订、依赖插入顺序，并可能留下半份目录。应构造完整内存候选，校验一次，最终只提交一次。

受管目录建议为应用数据下的 `server-keys/<本次核心生成的批次标识>/key-<序号>`。这里的批次只用于本次本地文件归属，不是发布批次或长期业务对象。所有文件名由核心生成，分享码不能指定目录或文件名；同一包内共用密钥指向同一受管文件。

提交顺序：

1. 在状态锁外完成限长解析、格式验证和密钥准备；创建受管私有临时目录，写入密钥并同步。此时不创建目录记录。
2. 取得 `mutations → servers`，复查退出状态、目录可用性和预览修订。按同一命名规则构造完整候选，分配服务器、代理、路线步骤和新标签 ID，映射到本次生成的最终密钥路径。
3. 校验候选，发布整个私钥目录到唯一最终位置，再复用 `ServerStore::commit` 写备份与原子替换 `servers.json`。密钥先完整存在，目录才可能引用。
4. 只有目录提交成功才接纳内存目录、解除本次文件清理保护并发布已有变更事件。一次导入只增长一个目录修订。
5. 发布或提交失败，原内存目录和正式目录保持原状态，清理本次临时/最终密钥目录。清理失败单独保留可排查结果并在启动时重试，不能把失败说成已经导入，也不能删除其他导入的文件。

私钥读取和大份解析不占用服务器锁；最终目录发布和目录写盘的短临界区遵循现有锁序，不新增反向锁序或在持锁期间触发前端事件。

这种顺序不宣称文件系统提供多文件事务：进程在密钥发布后、目录提交前中断，允许留下未引用受管目录，下一次安全启动清理；目录已经提交时，全部引用文件已经发布。继续使用当前原子写入的崩溃耐受边界，不额外承诺所有文件系统上的断电持久性。

## 7. 受管私钥生命周期与备份

这是本功能必须一起完成的范围，不能只处理首次导入。

- 普通复制资料继续复用原私钥路径。多个资料引用同一受管文件时，不因删除其中一条而移除密钥。
- 编辑改为外部私钥、改用密码或删除资料，都不在运行中立即清理文件。这样也不会删掉当前连接尝试快照仍在使用的私钥。
- 仅在持有应用数据锁、有效目录载入后且连接/插件尚未启动时清理。以当前目录和可恢复备份的引用并集保留受管文件，保证恢复 `servers.json.bak` 后仍能使用对应私钥。
- 存在不可解析的当前目录、备份或本次受管密钥可能涉及的保留损坏目录时，保守跳过相关清理。缺失的备份与损坏备份区别处理；清理不能阻止用户先恢复现有目录。
- 只清理受管根目录下符合核心命名与结构的普通文件/目录，不跟随符号链接或 Windows 重解析点，不触碰外部路径、未知附件和来源私钥。无法判断归属时保留并记录问题。
- Unix 私有目录/文件使用 0700/0600。Windows 在核心适配层创建只供当前用户及系统管理主体访问的目录，文件继承其 ACL；现有 `private_directory` 在 Windows 仅创建目录，不能直接当作 ACL 已落实。使用现有 Win32 依赖完成必要的窄范围适配。
- 文档与删除提示区分用户自选外部文件和应用管理副本；备份中的有效引用可能延长副本保留时间。共享后接收端的副本独立存在，删除发送端资料不使分享码失效。

不新增运行时引用计数表、密钥数据库或跨包内容地址存储。备份保护和启动清理使用同一份目录解码/校验逻辑；旧版本备份读取能力保留。

## 8. 桌面接入与有限重构

在 `server-actions.ts` 的命令联合里增加单台分享、全部分享和导入。单台分享针对 SSH 资料自身保存的配置；从中转位置触发也不借用当前树分支替换它的保存路线，弹窗明确展示实际分享路线。SOCKS5 不增加独立分享入口。

工具栏显示“导入连接”，更多菜单提供“分享全部服务器”，空状态保留导入入口。详情和右键菜单的单台动作复用同一命令。目录不可用时拒绝导入提交和导出；空目录能够导入，全部分享禁用。

`ServerManager` 已集中树、菜单、编辑器、确认框和关闭收集，不能继续向现有可选字段 `Frame` 塞入分享状态。提取 `server-dialogs.ts` 负责现有原生 dialog 的栈、焦点返回、关闭保护和销毁；编辑与确认行为原样迁移。新增 `server-sharing.ts` 负责分享/导入状态，`server-sharing-views.ts` 负责视图，业务校验仍在 Rust。

对话框宿主只做生命周期，不变成通用表单框架。分享服务通过有限回调接收最新目录、接纳提交后的非敏感目录及定位目标，不获得整个 ServerManager 的可变内部状态。桌面命令类型和调用放在独立 `server-sharing-api.ts`，避免把秘密相关 DTO 塞进普通目录类型。

分享弹窗展示范围、实际路线、缺失认证摘要和只读分享码，唯一主操作为“复制分享码”。导入弹窗在粘贴后自动预览，展示名称调整、目标和附带资料，主操作为“导入”。失败保留输入，成功接纳新目录并定位目标；批量使用临时“查看导入结果”动作，不创建持久导入分组或自动标签。

生命周期要求：

- 打开、复制、解析、导入分别有明确忙状态。生成/解析结果迟到时以代次和弹窗存活状态判断是否接纳，不能重开已经关闭的弹窗。
- 解析时允许关闭；提交期间禁止重复提交，纳入现有关闭/退出忙状态。应用已有退出意图先开始时，核心最终写入检查拒绝新提交。
- 分享码和预览不算必须保存的资料草稿，关闭不额外弹放弃确认；正在提交的导入不能被“放弃草稿”取消成状态不明。
- 成功结果返回后才能显示“导入成功”；刷新、切页、撤销退出和重开保持当前已有流程。销毁清除分享码引用与临时状态，不写 localStorage、自动保存草稿或状态事件。
- 复用现有主题、原生 dialog、文本转义、键盘焦点和减少动态效果；分享字符串放在 textarea 的值中，不放进按钮属性、命令 JSON 属性或可执行 HTML。

## 9. 剪贴板链路补齐

使用已有 `clipboard_text` 命令，增加可选、固定枚举的用途参数：默认普通文本仍为 256 KiB，桌面连接分享用途采用 8 MiB。预算由 Rust 固定，前端不能指定任意数值。原生读写继续放在阻塞线程，不改成浏览器 Clipboard API。

分享“复制”按钮显式选择分享用途；右键文本菜单的读写也必须拿到来源元素，才能为分享 textarea 使用同一预算。对 `text-menu.js`/声明文件的回调追加可选来源元素参数，`main.ts` 根据宿主分享输入框选择用途；旧调用者不传参数时仍是默认预算。

插件的 `ClipboardBridge`、分块大小、控制帧和 SDK 协议维持原样。不能通过整体抬高终端和插件剪贴板限制来修复大分享码。键盘粘贴、右键粘贴、右键复制与主按钮复制都要验证；关闭或编辑输入后迟到的剪贴板读取不能覆盖新内容。

8 MiB 是明确的首版资源边界：超限给出“分享内容过大，请改为逐台分享”，不截断字符串、不暗中丢掉私钥。外部聊天工具自身截断由接收端格式错误提示处理，不引入服务器端上传作为兜底。

## 10. 插件、连接与错误边界

本次不新增插件 RPC 分享能力，不修改 `crates/plugin-protocol` 的发布契约，也不增加插件授权流程。普通 `servers.read`、`servers.create/update/delete` 和公开目录继续看不到密码、私钥正文或分享码。

导入生成新 ID，不改变已有服务器连接身份、主机信任、运行中的工作区或已有凭据。仍走公共目录提交收尾，以保持核心事件和现有会话状态一致。导入后的连接使用原 `connection_snapshot → credentials → route → ssh` 链路，私钥错误与认证补填由现有机制处理。

分享错误采用窄范围结构化结果，如 `invalidShare`、`unsupportedVersion`、`shareTooLarge`、`catalogChanged`、`keyReadFailed`、`persistenceFailed`。不为本次分享重构全应用错误系统。普通日志只记录操作、数量和非敏感错误码，不记录分享码、私钥、口令或完整输入；测试只使用合成凭据。

## 12. 验收与工程入口

### 核心集成

增加 `src-tauri/tests/server_sharing.rs`，复用隔离 AppCore 数据目录与现有测试方式：

- 单台密码、普通/加密 Ed25519 和 RSA 私钥；有无口令、缺密码、未选择私钥、不可读及不支持的私钥。
- `SOCKS5 → SSH → SOCKS5 → SSH`、重复 SOCKS5、长路线、端点互相引用但不递归的合法目录。
- 单台不泄漏无关路线；全部保留自身路线；相同地址但不同路径/账号的资料不被错误合并；包内共用节点和私钥保持共用。
- 两个独立数据目录 A/B 往返。B 导入后删除或屏蔽 A 的源私钥，再重开 B，确认仍能读取和使用受管密钥。
- 同名端点、同名标签、本包重名、重复导入、预览后并发变更、应用退出检查、响应丢失后不得自动重试。
- 在密钥写入、目录发布、备份写入和主目录替换处注入失败；主目录、内存状态与已有资料不改变，清理只涉及本次文件。
- 模拟提交前/后进程重开，验证孤立目录清理、已提交引用保留、备份恢复、损坏目录保守跳过及外部密钥不删除。
- 非法 Base64、截断、未知版本、重复/缺失引用、非法协议认证、超预算、路径注入、受管目录符号链接/重解析点。
- 验证普通目录投影、插件读取/更新结果、错误与日志不含合成秘密标记；受管路径继续兼容普通编辑、复制和认证口令保存。
