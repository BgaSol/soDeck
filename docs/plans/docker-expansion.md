# Docker 后续扩展与设备复核

状态：行内侧栏工作流已在 Docker 0.3.0 发行。当前行为以 [Docker 功能](../features/docker.md)为准，来源、五平台原生包与实际验证范围见插件 [CHANGELOG](../../plugins/docker/CHANGELOG.md)。本文只保留尚未完成的设备复核与待选扩展，不将设想当作当前承诺。

## 设备复核

在目标应用中复核新配置默认右侧、手动停靠恢复及真实键盘/DPI/输入法/读屏操作。当前默认停靠声明、五平台归档与浏览器回归已覆盖右侧元数据和三主题窄侧栏；不将这些结果算作真实设备交互验收。

尚未定位用户原安装为何位于左侧，不根据推测静默覆盖保存布局。复核时区分保存的手动布局、旧包和首次默认位置；只有复现具体缺陷后才另定修复范围。

完成后将实际范围写入插件 CHANGELOG，删去本节；通用原生设备验收与核心范围见 [原生验收计划](native-verification.md)。

## 保留的后续扩展：本轮不自动实施

| 方向 | 待确认行为与边界 |
| --- | --- |
| Engine 与对象浏览 | 镜像/网络/卷列表、详情及容器引用；浏览和符合条件的维护优先沿用侧栏，深详情进入主区域 |
| 日志与指标 | 时间范围、持续跟随、文本导出、短期趋势，不把快照伪装成实时流 |
| 对象维护 | 拉取镜像，删除符合条件的镜像/网络/未使用卷；重查身份与引用，不使用 prune 或隐式强制删除 |
| 批量与长任务 | 显式多选，确认固定对象集合，逐项结果，侧栏查看进度/取消/关闭；不误操作隐藏对象，未知不自动重发 |
| 通用能力 | 用真实需求证明有界 `session.exec.v1` 不足后才增加流式执行/文本导出，保留资源归属、版本和旧插件兼容 |

继续排除创建/编辑容器、镜像构建推送、Registry 凭据、Compose 文件编辑/up/down、Swarm/Kubernetes、自动部署和定时清理。项目关系展示不等于部署管理。容器终端已经发行，侧栏入口属于本轮改动；历史“排除容器终端”不再适用。

Docker 业务命令、对象身份、配额、幂等及错误由插件解释，核心只提供通用能力；不直接依赖 SSH 或其他插件，不自动安装 Docker、启动 daemon、修改用户组或加入 sudo。

## 选定扩展后的步骤

1. 在本文选定一个完整、可验证的用户问题，明确对象、操作、配额、失败、取消与验收；不一次实现全部候选。
2. 判断现有有界 `session.exec.v1` 是否足够，只有真实需求超出时才设计增量 API。
3. 对照 [历史完整设计第 1–18 节](https://github.com/BgaSol/soDeck/blob/8115fdcd5bed4108021a729da605fbde77afc2af/docs/plan-docker-plugin.md#后续完整设计尚未实施)补全字段、命令、身份及生命周期细则；过时条目不替代当前需求。
4. 验证真实隔离 Engine、UI、丢失回执与资源清理，按独立插件流程验收五平台实际范围。

完成选中范围后更新功能、必要的架构/API 契约与插件 CHANGELOG，删去本文对应完成部分。其余候选取消或全部落实后删除本文，不另建完成计划归档。
