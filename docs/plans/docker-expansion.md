# Docker 后续扩展提案

状态：待选定范围，尚未实施。当前已交付能力以[Docker 功能](../features/docker.md)为准，第一版不依赖新的核心运行能力。

## 候选范围

| 方向 | 待确认的用户行为和边界 |
| --- | --- |
| Engine 与对象浏览 | 扩展概览，镜像/网络/卷详情及容器引用，按 Compose 标签展示已有项目和服务 |
| 日志与指标 | 日志时间范围、持续跟随、缓存搜索和文本导出，按需短期指标趋势 |
| 对象维护 | 拉取镜像、删除符合条件的镜像/网络/未使用卷；删除前重新核对身份与引用，不使用 prune 或隐式强制删除 |
| 批量与任务 | 逐对象结果、长任务进度/取消/关闭，断线或丢回执保留未知，不自动重发 |
| 通用能力 | 用真实业务证明需要后，再设计流式执行或文本导出；保留核心通用资源归属、版本化能力与旧插件兼容 |

原完整设计仍明确排除容器终端、创建/编辑容器、镜像构建推送、Registry 凭据、Compose 文件编辑及 up/down、Swarm/Kubernetes、自动部署和定时清理。这些不因“Docker 扩展”自动进入范围。Compose 关系展示也不等于部署管理。

Docker 业务命令、对象身份、配额、幂等与业务错误由插件解释，核心只提供通用能力；插件不直接依赖 SSH 或其他插件，不自动安装 Docker、启动 daemon、修改用户组或加入 sudo。

## 后续步骤与验收

1. 选定一个完整、可验证的用户问题，明确本次对象、操作、配额、失败和取消行为；不一次实现整个候选清单。
2. 以现有有界 `session.exec.v1` 判断能力是否足够；只有实际需求超出时才确认增量 API，不能把提案方法当成现有接口。
3. 对照[历史完整设计第 1–18 节](https://github.com/BgaSol/soDeck/blob/8115fdcd5bed4108021a729da605fbde77afc2af/docs/plan-docker-plugin.md#后续完整设计尚未实施)补全选中范围的验收条件。该文含对象字段、配额、命令、身份/未知结果、生命周期和测试细则；未选中部分继续待定。
4. 验证真实隔离 Engine、UI、丢失回执与资源清理，按插件独立流程打包和记录五平台实际范围。

完成选中范围后更新 Docker 功能、必要的架构/API 契约与插件 CHANGELOG；删去本文对应已完成部分。其余候选明确取消或全部落实后删除本文，不另存完成设计。
