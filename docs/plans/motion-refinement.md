# 全应用动效收敛与连续性优化

状态：实施与本次发布验收中（2026-11-17）。已同步主分支 `0cc4667`，用户已授权完成后发布 Latest。本文是本主题唯一计划；前次动效发行与证据仍见[核心 1.3.0](../releases/v1.3.0.md)。

## 目标与范围

让快速、重复操作保持连续，让状态反馈准确且安静。覆盖管理台七页、工作台及终端、文件、网络隧道、系统状态、Docker 五个插件；按问题归属实施，不逐屏叠加特效。

主交互仍是工作台的真实边界调整。继续使用现有 DOM、morphdom、CSS 和 WAAPI，以及现有 100/160/100/200ms 节奏。先修责任重叠和公共机制，再补有实际意义的局部连续性。

本轮只涉及展示层和它的验证、打包选择。不改变 RPC、插件 API、后端任务状态、远端操作、草稿和结果确认机制；不新增生产依赖、动画队列、全局调度器、动效配置系统或物理引擎。

## 必须守住的边界

1. 业务状态先成立，视觉效果随后解释。认证、输入、保存、取消、资源清理、窗口关闭和焦点恢复均不得等待动画完成。
2. Shell 管一级导航；页面控制器管内部导航和业务反馈；Components 独占 Surface 的位置、可见性和输入权。公共动效不猜业务状态，不按插件 ID 分支。
3. 同一次变化由一个明确的容器负责。父页入场时子页不再次入场；布局容器和反馈文字使用已有的不同节点，避免同一节点上的动画互相取消。
4. 快照刷新不能重新挂载 iframe、Monaco 或 xterm。终端、编辑器和日志正文不缩放、不逐行入场；实时数字、曲线、字节数不补造中间业务值。
5. 拖动和调整分屏直接跟手；交接、只读候选、旧代次隔离继续由既有机制决定。视觉完成回调不能恢复输入权、提交操作或改变业务结果。
6. 隐藏、卸载和减少动态效果时直接展示有效最终状态，停止并清除临时投影。文字、选中、错误和键盘焦点仍可辨认。
7. 保留实体 key、输入法、选区、撤销、滚动锚点和按压队列。需要变更这些行为时另行界定问题，不借动效改造重写 DOM 协调或业务生命周期。

## 责任与代码入口

| 所有者 | 负责 | 边界 |
| --- | --- | --- |
| `src/motion.js` / `motion.d.ts` | 时长、可见性准入、可打断执行、有限退出投影、位置采集 | 不决定何时是成功、失败、新结果或首次打开 |
| `src/dom-update.ts` | keyed DOM 更新前后的位置和节点身份比较 | 不把任意文字变化当作需要提醒；不接管子控制器内部 DOM |
| `src/shell.ts` / `console.ts` | 一级与内部导航各自的唯一过渡入口 | 不引入第二套路由和导航状态机 |
| `src/components.ts` / `workspaces.ts` | 真实布局、Surface 同步及已打开页面的显隐 | 不用缩放正文代替调整实际边界 |
| 各页面与插件控制器 | 用户意图、业务阶段、实体身份及是否需要局部反馈 | 不各自复制动画算法、隐藏监听或节奏常量 |
| `packages/ui` 与现有插件打包脚本 | 同源样式及随组件独立发行的动效实现 | 插件不读取核心安装目录；旧插件沿用自己包内的版本 |

## 一、公共机制：一次修清调用合同

### 可见性与打断

- 在现有 `observeMotion` 的 document 级记录中保存插件可见、挂载/卸载状态；复用现有 Symbol，使同一文档里多个打包入口共享记录和监听。
- 准入同时考虑 `document.hidden`、已有 mount/visibility 消息和减少动态效果。收到隐藏或卸载后，迟到的异步更新可以写入有效最终内容，但不能再启动动画；再次挂载/显示才允许新效果。
- 保持现有控制器的实体、代次及请求有效性检查。动效可见性不能代替这些检查，也不能阻止真实后台业务继续运行。
- 动态尺寸与位置在取消旧动画、写入新目标之前读取当前呈现值。现有布局和 Surface 同步路径继续使用，不再加补偿定时器。

### 退出投影

- 保留有界的小型 chrome 退出投影，修正公共实现。以当前呈现的不透明度和可见位置作为起点，避免入场中途关闭时突然变实或重复叠加 transform。
- 菜单的必要边框绘制归到可复制的根样式，保持现有几何预算；不扩展成任意 CSS、伪元素和业务 DOM 的截图引擎。
- 保留最多 80 节点、无 iframe/canvas/video、无密码值、无业务标识、inert 和不可聚焦限制。不满足条件时即时移除，不强行为大面板生成快照。
- 创建投影的公共方法负责完成、取消、隐藏和卸载后的清除；同一浮层快速重开不叠旧投影。原生 dialog 的关闭、遮罩和焦点恢复仍即时执行。
- 若某种表面无法在以上边界内准确退出，则为该类表面统一采用即时退出，不增加按具体页面兜底的快照分支。

### 反馈按实际状态触发

- `setMotionText` 收敛为内容更新。控制器根据已有业务状态输出文案和状态样式；不能继续默认“改文字就闪一下”。
- 删除 keyed DOM 对 `data-motion="feedback"` 正文的比较及对应旧标记。状态色和提示底色需要过渡时使用现有样式与节奏；不另建一套 DOM 状态协议或反馈状态机。首次节点入场不再额外叠加状态闪动。
- 正常搜索的查询中、命中序号、总数，以及采集周期、速率、时间和字节更新保持稳定。错误、无结果、断线、过期、恢复、真实任务阶段和保存结果按对应控制器的实际状态触发一次。
- 同步检查所有旧调用，包括终端的文字 MutationObserver、编辑 SDK、文件状态栏、连接提示、更新状态及 Docker 日志；删除被替代的自动反馈路径，不保留两套机制。
- 移除通用的“压到 55% 不透明度再恢复”反馈及 `feedbackMotion` 的调用和导出。默认依靠立即更新的文案、状态色和已有控件反馈；新提示使用现有局部入场，布局改变使用已有布局过渡。样式过渡从当前画面接续，不额外发明一种高亮或闪烁效果。

上述变化是仓库内部帮助方法调整，不升级核心能力 API。ES module、普通脚本的 `SoDeckMotion` 导出、声明文件、夹具与包内消费者在同一批次对齐。

## 二、导航、页面显隐与浮层

| 范围 | 实施方式 | 可验收行为 |
| --- | --- | --- |
| 七个管理页与设置/插件详情 | 一级切换由 Shell 负责；仅内部实体变化时页面控制器负责。先投影目标内容，再启动选定的一层过渡 | 一次导航仅一层入场；重复刷新无重播；快速反向切换无旧页残影 |
| 已打开的工作台页面 | 区分首次呈现和重新显示，保留现有 View/Surface；返回已有页面直接恢复，布局改变仍走真实边界过渡 | 连续切终端/编辑器不反复淡入；输入焦点和滚动位置保留 |
| 列表到详情再返回 | 只在已有显式内部导航动作上表达前进/返回；修改原控制器，不从 DOM 变化推断导航 | 网络规则、窄窗连接目录及插件详情方向一致；窗口宽度变化不冒充导航 |
| Docker 资源菜单与确认面板 | 复用已有 `attachMenuPosition` 和公共动效；TreeMenu 继续持有目标、动作、校验和焦点 | 菜单边界翻转与锚点跟随一致；Esc、点击外部、执行动作均可立即生效 |
| 其他菜单、搜索条和小对话框 | 所有关闭入口进入各自控制器已有的单一 close 方法，再调用公共退出 | 按钮、Esc、外部关闭行为一致；快速开关不残留可操作旧节点 |

不让菜单定位模块承担业务确认、资源校验和操作执行；不把原生模态框改成自制模态框。

## 三、结构变化按实体处理

| 范围 | 实施方式 | 限制 |
| --- | --- | --- |
| 文件、连接、Docker 树 | 区分用户展开/收起、数据刷新和虚拟窗口更换；仅主动结构变化解释分支和相邻可见行的位置 | 收起立即更新焦点与可操作范围；滚动加载、后台刷新不重播展开；不新增列表虚拟化框架 |
| 连接路线 | 保持既有 SVG 几何计算，只反馈新选中的路线 | 普通连接线和整张图不反复淡化；不增加逐段描线时序 |
| 文件传输 | 按 task ID 保持行和进度节点身份，在已有分组内移动；阶段改变局部反馈，批量完成合并提示 | 不借动效重写任务同步、轮询和分组模型；仅同一文件的已知进度衔接 |
| 消息与通知 | 消息按 ID 更新；详情实体变化局部过渡；通知移除后衔接其余可见通知位置 | 已读和消息聚合语义不变；普通日志正文不套用列表入场 |
| Docker 日志详情 | 按钮、Esc、“回到最新”统一通过现有详情显隐入口；换记录只更新详情内容 | 宽度过渡保持真实布局和阅读锚点；日志流与正文渲染不参与动画 |
| 更新进度、原因和待重启区域 | 同一更新实体内处理辅助区域出现/消失后的布局变化 | 下载量来自原服务，未知总量不模拟百分比；重启不等待视觉完成 |

树行需要位移时复用现有 capture/settle，先核对实体身份；不能为触发动效重新创建本来应保留的节点。原生 details 继续立即展开并允许 Tab 进入，不恢复高度/可见性等待。

## 四、设置、状态及性能收敛

- 设置保存成功、部分应用失败，以及插件安装/更新的重要阶段，沿用第一批确定的显式状态反馈。编辑中的未保存提示不随每次输入闪动。
- 应用状态和系统状态的正常采集保持安静，断线/过期/恢复/告警变化局部提示。采集状态文字和数据仍完整展示。
- 主题选择即时应用；统一去掉造成局部渐变、局部瞬切的整页主题过渡，仅保留选择控件本身反馈。不建设跨 iframe 的主题动画或主题切换截图。
- 减少动态效果、文档隐藏或卸载时，在 DOM 更新的动效入口跳过位置采集、快照与效果创建；DOM 与状态更新照常完成。
- 可见项收集满 40 项后停止，不再先过滤全部节点再截断；一次采集复用同一几何结果，测量和动画写入分开。这个限制是动画数量上限，不宣称所有列表仅需 40 次测量。
- 对大树、多终端/编辑器分屏保留改前改后同机测量。只有定位到实际布局或绘制瓶颈，才继续优化现有布局循环；不预先建立缓存失效系统、通用调度器或新的观察器体系。

## 实施顺序与提交边界

1. **公共合同及全部消费者。** 先保存已复现问题的回归，再修可见性、打断/退出、显式反馈与采集边界。公共方法变化与消费者迁移各按完整问题提交，不能留旧语义兼容分支。
2. **导航与浮层。** 收敛父子页入场、已有 Surface 恢复、内部前进/返回和 Docker 菜单；每个提交同时删除对应重复入口并验证键盘关闭。
3. **实体连续性。** 树、传输、消息/通知、日志详情、更新辅助区域分别提交；共用能力足够时直接复用，业务差异留在原控制器。
4. **状态与性能收束。** 完成设置/状态语义、主题过渡收敛和测量，修有证据的剩余瓶颈；同步正式文档，核对实际包内容。

每个提交只包含一个可验收的用户行为。实施中发现已有逻辑不支持某个建议，先说明冲突并收窄范围；不增加临时旁路、插件特判、延迟重试或“先隐藏再显示”来掩盖原因。

## 验证与交付

### 长期回归

优先扩展现有测试，不另建动效测试框架：

- `scripts/test-workbench-interactions.mjs`：入场 10–30ms 后关闭/重开、退出外观、隐藏后迟到更新、重新挂载、运行中开启减少动态效果，以及临时投影回收。
- 既有 shell、production、workspace、layout 测试：父子页仅一层过渡、频繁切页、拖动中取消、左右停靠反向、分屏中的实际 Surface 几何和输入身份。
- 终端与编辑 SDK 的搜索测试：连续输入、IME、连续 F3、无结果与失败恢复，计数稳定且焦点/高亮正确。
- 五插件现有 UI 测试：主动树操作与滚动刷新区分；任务跨组和取消；日志阅读锚点；菜单键盘；网络启停/检查；周期采集与重要状态反馈。
- 核心与插件打包测试：验证同源实现、独立资源和许可证。修正现有检查选择器，使 `motion.js`、DOM 更新和共享样式变化覆盖真实消费者，复用现有检查分组，不新增依赖图或发布门禁。

公共机制的已复现缺陷必须有稳定回归；纯样式细节使用中间帧截图和键盘检查，不为每个动画参数编写镜像测试。至少检查三主题、常规与紧凑窗口，以及减少动态效果。

### 检查范围

每批运行相关格式化、类型检查、构建与既有 UI 测试；完整源码收束运行 `npm run check`、`npm run scripts:test`、`npm run test` 和 `npm run build`，并按实际受影响插件运行现有业务测试与独立 `plugin:build`。具体命令和 CI 归属见[开发指南](../development.md)。

共享动效随五个插件独立携带，因此共享实现变化需要核对五个包；不要求核心加载时同步插件版本。核心和各受影响插件仍各自完成五平台原生编译、打包及实际包启动/退出，按[分发流程](../distribution.md)保存证据。浏览器录制不替代原生 WebView、实际输入设备或 ARM64 验证。

本轮核心拟发行 1.3.2，五插件分别升补丁版本；不沿用历史运行作为本次验收。既有[设备专项](native-verification.md)、[DOM 输入专项](dom-updates.md)及[日志长期内存专项](docker-log-viewer.md)继续各自维护，不并入动效任务，也不因本轮通过而标记完成。

## 当前证据与未验证范围
