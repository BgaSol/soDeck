# MCP 侧栏职责整改

状态：2026-11-18，代码与本机回归完成，待固定源码的五平台发行验收；基线为已发行 MCP 0.2.0。用户明确要求完整 MCP 操作留在侧栏，并在整改后发布 Latest。

## 目标与验收

- MCP 只声明原有 `status` 侧栏视图，移除中央 `operations` 视图、新建入口、打开页请求及其后台代理分支。保留工作区后台目标和 MCP 六工具。
- 默认侧栏是当前服务器、接入设置折叠项、正在执行的真实命令/路径与最近输出、执行记录。配置不默认显示，密钥和配置在收起、查看任务、隐藏与卸载时清空。
- 点击记录或当前任务的“查看详情”只切换侧栏内容。详情支持完整命令、输出分页、实际状态、取消和证据信息；“返回记录”恢复列表位置与触发控件焦点。
- 定时刷新、任务插入、迟到回包与完成状态不切换已选记录、不重置输出页，不打开/选择中央页或改变其布局与输入。连接变化回到本连接的概览，不自动选择新任务。
- 200–640px 窄侧栏及 400px 矮面板可访问全部功能；复用三主题与宿主侧栏尺寸，不通过自动扩宽、浮层或全屏弥补布局。

## 设计与边界

单一侧栏内有“概览 / 任务详情”两个阅读状态；只有用户选择任务才进入详情。概览与详情共用页头的刷新/状态，详情与概览不同时堆叠。接入设置与证据信息按需折叠，端口继续复用已有组件设置及冲突机制。

任务、正文、等待额度与原生资源仍由已有服务管理。侧栏可见性只控制读取；隐藏侧栏不取消远端任务，关闭工作区才按原有生命周期释放目标。保留核心通用手动停靠能力；插件不主动打开或迁移到主区域，也不引入核心针对 MCP 的特殊布局限制。

## 剩余实施与验证

本机已通过类型/格式、187 项脚本测试、5 项插件单元、实际进程、独立插件构建与三服务器 SSH。侧栏回归覆盖三主题、200–1024px 宽度、400px 矮面板、列表位置/焦点返回、迟到读取、输出分页、设置冲突和秘密清理；同时核验主区域内容、输入、宽度与轮询中的焦点。真实核心验证中央贡献及旧入口缺席，侧栏隐藏/再显示复用同一后台目标，中央标签组及选择不变。已查看本轮实际截图。

本机首次 SSH 验收发现默认端口属于正在使用的 0.2.0，返回 401；夹具改为先添加插件、保存独立端口再启动，不访问现有桌面服务，修正后通过。此改动仅在测试夹具，不改变产品默认端口。
