# 日志与消息「精密工作台」整改

状态：软件整改已实施，本机源码、浏览器及 Windows release 程序验证通过；2.8.0 五平台打包/验包与正式发布待执行（2026-11-26）。用户已授权实施与核心发行。已实现行为归入[功能文档](../features/logs-messages.md)、[架构](../architecture.md)和[设计系统](../../DESIGN.md)，验证事实归入[2.8.0](../releases/v2.8.0.md)。

核对基线：`b96585e4da825c3a73266cb1ae26f5d3d9071ef8`。实现前核对分支差异，不用本次源码调查或交互预览代替实现后的验收。本主题只维护本文。

## 目标与验收

把日志和消息建成同一设计语言下的两个完整工作页面：日志用于连续扫描和排查，消息用于概览与阅读。采用紧凑列表、明确列对齐和右侧详情，把长 ID、实例和结构化字段移到详情；保留原有来源、查询、暂停、已读、去重及通知语义。

核心完成条件：

1. 两页各自拥有状态、请求及 DOM，管理台仅装配与导航；删除原有重复更新路径和失效样式，不能在 `shell.css` 后面继续堆覆盖规则完成交付。
2. 日志列表只呈现摘要；选中后可读完整正文、准确身份和结构化字段。暂停、筛选、刷新、复制和窗口切换有一致语义。
3. 消息列表呈现概览，详情呈现完整正文；消息读取、标为已读及新去重消息不会因为异步回包、列表移除或刷新而覆盖用户的新选择。
4. 多巴胺、晨曦和星夜共用布局，键盘、文本选择、长文本、跨日数据和窄窗口均可使用。
5. 源码、正式产物、原生包和文档分别验收；实现与约定验收未全部完成时，保留本文且不宣布整个整改完成。

## 现状与链路证据

### 已追查的完整路径

| 链路 | 当前实现与必须保留的事实 |
| --- | --- |
| 插件日志入口 | [RPC 分派](../../src-tauri/src/plugins/dispatch.rs)校验 `logging.write`，传入已接纳的插件与实例；[AppCore](../../src-tauri/src/core.rs)附加记录 ID 和接收时间，插件不能用 fields 冒充身份。 |
| 核心与生命周期日志 | `AppCore::log` 使用 `source=core`，仍可携带 pluginId/instanceId；“核心产生”和“关联某插件”是两个独立维度。 |
| 写入与查询 | [Store](../../src-tauri/src/storage.rs)截断过长正文、按序列化体积裁剪字段、写 JSONL 并维护内存回退；轮转约 10 MiB/份，最多五份，内存近期 5000 条。[LogFilter](../../src-tauri/src/model.rs)按正文、级别、来源及时间匹配；UI 查询最多返回 500 条，按接收时间升序。 |
| 桌面读取 | [Tauri 命令](../../src-tauri/src/main.rs)的 `read_logs` 使用后台阻塞任务扫描磁盘；`read_messages` 从核心取得倒序消息，`mark_read` 提交持久状态。[前端 core](../../src/core.ts)封装调用。 |
| 消息提交 | `messages.publish` 与核心失败消息进入 `Store::publish`，保存成功后才提交内存并发出事件。同 source/pluginId/dedupeKey 五分钟内合并，沿用 ID、增加 count、更新时间和内容，并再次成为未读；最多 1000 条。 |
| 通知与未读 | `messages-changed` 唤醒[原生托盘](../../src-tauri/src/desktop_shell.rs)的未读投影；`core-message` 只用于满足 notify/fresh 条件的短暂提示。`core-changed` 仍负责通用状态失效。普通日志不直接生成通知。 |
| 管理台更新 | [console.ts](../../src/console.ts)共用大 ViewState、根点击分派和刷新调度。进入页面、200ms 合并刷新、每秒 tick、筛选及已读动作都可能触发读取。 |
| 模板与 DOM | [views.ts](../../src/views.ts)同时放日志、消息和维护页状态；日志由 `renderPage` 与 `refreshLogs → logResults` 两条路径更新，消息通过整页更新。[updateDOM/DomRegion](../../src/dom-update.ts)已具备实体 key、details 保留和局部按压保护，应复用。 |
| 显示生命周期 | [Shell](../../src/shell.ts)拥有导航和实际窗口可见性，`visibleConsolePage` 才能判断页面是否真正显示；`currentPage` 可能仍是工作台或后台窗口之前的管理页。 |
| 外部入口 | 管理台导航、顶栏消息、托盘消息、toast 定位、插件详情“查看日志”、状态页“查看日志”和消息“查看插件”都必须接到同一页面控制器。 |

### 问题分类

| 分类 | 源码依据或本次验证 | 整改决定 |
| --- | --- | --- |
| 已复现缺陷 | 直接提取当前 `refreshMessages` 函数，以两个受控 Promise 颠倒完成顺序，旧请求最终覆盖新结果。函数没有读取代次、可见性及销毁判断。 | 页面控制器负责读取合并、过期结果丢弃和销毁；增加同样顺序的回归。此次是函数级复现，不记为真实 WebView 复现。 |
| 状态与渲染结构问题 | 日志/消息字段在维护页 ViewState 中；console 同时管理读取、事件、导航、动作和模板；日志存在两个 DOM 写入者。 | 按功能收拢控制器与模板，父级不得再 patch 子控制器内部。 |
| DOM 身份风险 | 实际编译执行 `logResults`，确认记录 ID 没有进入行 DOM，结构化字段直接进入每一行。窗口头部记录淘汰时只能依赖结构匹配。 | 行与详情都按记录 ID 建立稳定身份；这是已确认结构问题，不声称已复现任意一种现场错选。 |
| 更新开销问题 | 每条日志发 `core-changed`，宿主 tick 又可触发扫描；相同筛选没有单在途保护。视图每次排版全部正文与 JSON。 | 一次只读一个请求，合并后续失效；只渲染摘要与当前详情。暂不改变后端存储和事件协议。 |
| 显示与失败问题 | 消息全页刷新；日志查询失败多经五秒 toast 提示；页面缺少自己维护的首次加载、读取失败、旧结果及重试状态。 | 页面内保留可恢复状态，错误不冒充空结果，显示失效内容的时间/条件。 |
| 视觉问题 | `shell.css` 中日志每行包含完整日期、来源/实例、正文和 JSON，粗结构线与全行等宽字体并用；消息重复显示完整时间、摘要和元信息。 | 替换两页模板和局部样式，明确摘要/详情分工，不缩小文字来掩盖排版问题。 |
| 正常行为，必须保留 | 实际编译执行消息模板，确认未读筛选会移除已读行，但详情从全部消息按 ID 取得，仍可保留。已有生产回归检查选择与焦点。 | 正式实现继续保留详情，并补足行移除后的焦点回退。之前交互预览中出现的详情消失不当作现有产品缺陷。 |

## 范围与复杂度决定

采用前端功能范围重构。后端已经提供稳定记录 ID、完整详情字段、有界查询、来源附加与消息提交语义，这次默认复用 `read_logs`、`read_messages`、`mark_read`，不添加详情 RPC 或数据迁移。

- 涉及：两页控制器/模板/样式、console 的装配及外部入口、相关格式化、回归与性能测量调用方。
- 保持：Shell 导航与主窗口/工作窗口边界、服务器会话、设置/更新控制器、核心日志与消息存储、插件 RPC 和独立发行方式。
- 不在本次做：消息到业务任务路由、从 fields 猜服务器或可点击目标、Docker 容器日志页、终端输出、日志聚合平台、无限历史、全文索引、通用事件总线、新状态库、前端框架、可拖动分隔栏或独立日志窗口。
- 不新增生产依赖。日期用现有 date-fns，DOM 用现有 morphdom/updateDOM/DomRegion，图标和主题沿用公共实现。
- 不把两个页面抽成通用 MasterDetail 框架：日志有暂停/筛选/滚动窗口，消息有已读/去重/列表移除，生命周期不同。只共享已出现两处真实需求的来源显示、级别标签及短时间显示等小型纯函数。
- 不调整整个 SoDeck 外壳的导航宽度、顶栏、标签条或主题颜色。预览中的外壳只用于呈现；实际实现服从当前 Shell 几何与 DESIGN.md。
- 不默认改 `dom-update.ts`。优先正确划分区域与 key；只有页面测试证明公共实现存在缺陷，才单独说明最小公共修正及受影响插件回归。

后端查询扫描和通用 `changed()` 的成本列入测量，但不预先重写。若完成前端整改后，实际磁盘扫描仍导致不能及时显示，应先报告分段测量，再决定一个独立、可验证的查询优化；不能用浏览器 DOM 变快来宣称整个链路已解决，也不顺手引入索引或缓存架构。

## 精密工作台的产品行为

### 页面结构与视觉规则

日志为页头、紧凑筛选带、结果/更新状态、列表及右侧详情；消息为页头、全部/未读与批量已读、列表及右侧阅读区。两页有共同排版节奏，分别维护自己的状态。

| 部位 | 设计决定 |
| --- | --- |
| 字体 | 中文正文使用现有系统字体，正文 13px，元信息 12px，辅助标签最低 11px。时间、ID 和 JSON 使用等宽字与表格数字，不把整个页面都改成等宽。 |
| 页头和工具 | 页标题约 19px；搜索与筛选约 30–32px 高，主次动作分组。时间区间默认折叠为“时间范围”，有条件时显示已应用范围；清除筛选操作有稳定位置。 |
| 日志列 | 时间、级别、来源、正文摘要；时间保留日期辨识，不能让跨日记录只剩相同钟点。默认行高约 38px，正文单行省略，多行全文在详情。 |
| 消息行 | 类型图标＋文字语义、来源、人类可读时间、标题、最多一至两行摘要、未读标识及重复次数。未读与选中分别表达，级别不靠颜色单独区分。 |
| 详情 | 日志先正文，再接收时间/来源/插件/实例及可折叠 JSON；消息先类型、标题和全文，来源技术信息折叠。接收时间可查看毫秒精度；不得把接收时间描述成远端事件时间。 |
| 列宽 | 日志详情约 288–320px，消息列表约 280–320px；剩余空间给正文。按实际内容宽度降级，不照抄预览中较窄的外壳。 |
| 分隔和色彩 | 内容以中性面、细分隔、轻选中底组织；三主题使用现有角色。多巴胺保留暖底与壳导航个性，两页内部列表不逐行套粗黑框。 |

日志优先使用语义表格和正文列内的原生选择按钮，一行一个选择入口；完整字段不塞入隐藏的每行 DOM。消息用原生列表/按钮。两者均不引入自制 ARIA grid 和复杂方向键状态机；键盘能选择、进入详情、返回列表及复制，焦点可见。

容器内容宽度不足约 820px 时日志改为单栏列表/详情切换；消息约 720px 时同样切换。使用明确的“返回日志/返回消息”操作，避免把两块长内容机械堆叠成两层滚动。宽窗口保持行焦点，窄窗口选择后把焦点交给详情入口，返回时恢复原行或最近有效入口。最终阈值以真实 Shell、长中文、125%/150% 缩放验证后确定，不能在窄窗口隐藏全部入口。

### 日志：查询、暂停与阅读

1. 查询仍是“满足条件的最近最多 500 条”，按现有返回顺序展示，不把当前条数当历史总数，不暗示有未实现的分页。界面说明本地时间；跨日数据不使用“今天”作为整页固定标题。
2. 来源优先显示当前安装清单的名称；详情始终保留原 pluginId/instanceId 和 `source=core/plugin`。核心发出的插件故障显示“关联插件＋核心产生”，不能因为带 pluginId 就画成插件自行报告。
3. “核心”筛选仍匹配所有 source=core 的记录；某插件筛选同时包括核心关联该插件的记录和插件自行写入的记录。已卸载来源按原 ID 回退；筛选项来自当前清单、当前返回记录及已选值，不承诺枚举磁盘全部历史插件。
4. 正文搜索保留现有语义，不扩大为 JSON 搜索。输入防抖约 250ms，composition 期间不提交中间词；开始/结束沿用本地分钟输入到毫秒整分边界的现有转换，保留零时间戳。结束时间不偷偷扩成该分钟末尾。无效时间、早于可接收时间戳或开始晚于结束时就地提示，不提交无效查询。
5. 明确区分正在编辑的筛选与上一次成功结果对应的筛选。请求中或查询失败保留旧结果，并标注“正在查询/显示上次结果”；不能让旧列表看起来已满足新条件。
6. 暂停冻结已显示记录和详情，后台继续存储；同时让在途结果失效。暂停中修改或清除筛选只修改待应用条件，显示“筛选待应用，继续显示后更新”；复制仍复制冻结记录。继续显示时用最新条件重新查询。
7. 明确选择记录后，后续刷新不自动改选最新记录。详情按 ID 更新；记录因 500 条窗口滑动移出时，可保留唯一一条选中快照，并提示“已移出当前结果”。显式筛选变更成功应用新结果后清除旧选择；暂停或查询失败时仍保留原详情并说明它属于旧结果。新结果无选择时展示安静的详情提示，不把不匹配记录伪装为当前结果。
8. 首次进入没有阅读位置时显示最近记录区域；用户处于末尾时可以跟随更新。一旦主动向上阅读或选择文本，保留首个可见记录 ID＋偏移；给出“查看最新”入口。不能用旧 scrollTop 代表记录锚点，也不能把当前窗口的新增条数宣称为后台总积压。
9. 锚点被滚动窗口淘汰时定位到最近仍存在的记录，明确范围已变化；不承诺无限保留旧正文。普通列表不逐行播放动效，详情只在切换记录时局部揭示。
10. 保留“复制记录”为当前已成功显示记录的 JSONL，另在详情提供“复制本条”。点击时冻结复制内容，既不重新查询，也不根据正在编辑的筛选重新推导。复制正文与 fields 保持数据原值；失败在动作附近保留重试提示，不虚报成功。

fields 按实际 JSON 根类型显示，对象、数组、字符串、数字、布尔、空对象和无字段分别处理；不强制转成键值表或把不可恢复的缺失显示成完整字段。正文、标题、ID 和 JSON 经现有 escape 按纯文本渲染，不直接作为 HTML 或 Markdown 执行。

### 消息：选择、已读与去重

1. 全部/未读按钮显示各自计数，筛选只作用于列表；详情按独立的 selectedId 从已接收的完整消息集合取得。初次无选择时给阅读提示，不为填满详情区而自动标为已读。
2. 显式选择消息立即显示正文，再提交标为已读；保存成功后才更新有效已读状态和计数。失败保留正文、未读和可重试错误。批量已读保存中禁止重复提交；已读消息的普通选择不再次写磁盘。
3. 未读筛选下已读行移除，详情继续保留；焦点落到最近的未读行，无行时回到“未读/全部”切换入口。不得因详情保留而给空列表伪造一条未读记录。
4. 用户快速选择 A→B，A 的读写回执不得把详情改回 A、抢焦点或导航。连续写操作按控制器中的短队列收束，按 ID 去掉重复在途意图；不引入通用任务调度器。
5. 去重更新沿用核心 ID，并以接收时间/count/内容更新列表与详情。已选中的消息再次变成未读时保留“有更新”的未读事实，刷新不自动补发 mark_read；需要再次显式阅读或批量已读。
6. 保持现有后端执行语义：`mark_read(id)` 标记核心执行时的该 ID，`mark_read(null)` 标记执行时的全部消息。它们不是“仅标记用户此前看见的版本/集合”。去重与已读按核心存储提交顺序生效；本次不新增版本比较字段，不能承诺调用前后并发发布都保持未读。
7. 消息详情不长期缓存被存储淘汰的第二份消息仓库。已选择的 ID 被 1000 条限额淘汰时，显示“此消息已不在保存范围”，保留可用导航，随后选择新消息可恢复。
8. 顶栏/侧栏与托盘继续以核心事实为准。消息页计数来自本次完整消息读取，标为已读或 messages-changed 后唤醒宿主快照同步；不乐观扣减多个独立计数。不同读取间短暂不同步不当作同一时刻快照，失败保留最后有效计数并提示待同步。
9. 顶栏和托盘只打开消息页，不批量标为已读。toast 定位先按固定消息 ID 进入页面，再走相同阅读动作；旧异步操作不能在用户离开后重新打开消息页。过期 ID 给出明确提示，不猜最近一条。
10. “查看插件”只按真实 pluginId 定位已安装插件。插件已移除时保留历史身份并说明不可定位，不跳到空插件页、不安装插件、不复活会话。消息不解析标题/正文生成业务任务链接。

## 代码组织与所有权

建议采用以下最小功能拆分；命名可按仓库习惯微调，职责不可退回 console 的大分派中。

| 文件 | 整改后的职责 |
| --- | --- |

控制器各自暴露挂载/卸载、激活、更新显示上下文、失效/读取以及外部打开意图，使用少量明确方法。不要为统一方法名引入 Controller 基类、注册器或依赖注入容器。

### 状态分层

- 核心事实：日志/消息记录、安装清单、已读、count 和存储错误；通过现有 core 接口接收，不由模板反向改写。
- LogsPage：期望 filter、成功结果的 filter、最多 500 条 records、selectedId、最多一条移出窗口的 selectedSnapshot、paused、首次读取/读取错误、详情折叠与阅读锚点。
- MessagesPage：最多 1000 条 messages、unreadOnly、selectedId、读取/写入错误、待提交的已读意图、列表/详情阅读位置。详情尽量由 ID 投影，避免常驻另一份可变 Message。
- 运行期句柄：读取 inFlight/readAgain、意图代次、事件 AbortController、DOM region、定时器；不是可持久化设置。
- 普通页面切换保留上述页面状态；窗口关闭时释放，不为两页新增磁盘偏好或关闭草稿参与者。

## 请求、事件与 DOM 的整改方式

### 读取只有一个入口

每页只允许一个读请求在途。进入可见页、用户操作、事件与宿主 tick 都进入该页同一个读取方法：在途时只设置一次 readAgain，结束后最多补一次最新读取，持续事件不会堆积 Promise。

意图代次只在筛选变更、暂停、离开显示范围、销毁或使旧读不再有效的写操作时失效。普通数据事件只置 dirty，不能每条日志都递增代次，否则慢磁盘下所有请求都可能被新事件作废而永远不呈现结果。

- 只在 `shell.visibleConsolePage` 对应页面真正可见时读取；切回工作台、其他页或窗口后台时失效并停止页面读取，保留已显示数据。
- 复用宿主现有约 200ms 事件合并与每秒兜底 tick，不另起两组轮询定时器。parent refresh 只通知页面刷新/上下文变化，不再等待或直接操作两页正文。
- core-changed 仍驱动需要的应用快照；新增对现有 messages-changed 的定向分发，和 tick/通用事件在控制器内合并，防止订阅后反而多读。
- 日志防抖输入完成前不由后台 tick 抢先提交；暂停后旧读即使返回也不改 records。页面离开后回包不得渲染或覆盖下一次挂载状态。
- 消息已读写开始时使旧读结果失效；写入队列完成后重新读取。写回执只收束自己的 pending/error，不按过期结果恢复选择或覆盖整份 messages。
- 页面读取独立于应用/更新/网络计量组合快照的完成，不因某个无关读取挂起而不能打开日志或消息。插件清单作为可缺省的显示上下文，缺失时按原 ID 回退；不能把“尚未取得清单”误判为插件已卸载。
- 单次查询失败保留可用内容并显示就地重试，后台重复同一失败不制造 toast 风暴；首次读取失败与真正无记录分别呈现。
- snapshot 已报告的 storageErrors 以统一存储告警保持可见，不通过解析错误文案猜测错误归属；尤其不能把消息文件损坏后的空集合单独呈现为正常“暂无消息”。页面读取/写入错误与该告警分别维护，不相互清除。
- 本次不添加 IPC 取消协议；已经发出的阻塞查询可能继续完成，前端只拒绝过期回包，不能声称终止了后台扫描。

### 一个区域只有一个 DOM 所有者

1. console 切换页面时先卸载旧控制器，再装入新页面空容器并挂载；同页宿主刷新只交付上下文。父级不得继续把整页 HTML 交给 updateDOM 覆盖子树。
2. 各页独占自己的 toolbar/list/detail/status 区域，通过现有 DomRegion 处理按压期间的局部更新；不得复制第二套 DOM diff 或全局按压队列。
3. 日志行 key 为 log ID，消息行 key 为 message ID，详情 key 带类型和实体 ID。details 的保留以实体为范围：刷新同一条保留，换记录不能继承另一条的展开状态。
4. 不变区域不重建；只读快照更新不能清空焦点、正在输入的查询、composition、文本选区或滚动锚点。每次都重新拼接“同样的控件”仍须验证中间帧的连续性。
5. 跨页重挂载只保存必要值与锚点，不缓存整页 HTML 或维护离线 DOM 树；旧事件监听、region 和输入 timer 在卸载/销毁时释放。
6. 局部样式只作用于日志/消息根。清理旧 `.log-*`、`.message-*` 及确实仅本页使用的 `.segmented` 规则前查所有引用，保留 toast、通用 badge、其他页面 pair 等真正共享部分。

## 验收矩阵

| 场景 | 通过标准 |
| --- | --- |
| 首次进入/空/失败 | 首次读取有状态；空结果、未读为空、筛选无结果和读取失败区分；失败不擦掉有效内容，有明确重试。 |
| 多次读取回包颠倒 | 旧消息/旧筛选结果不能覆盖新结果；普通数据事件连续发生时，同条件的合法结果仍能呈现。 |
| 请求数量与隐藏 | 每页在途读最多一条，重复事件合并；工作台、其他页和后台不新增页面读请求，重新可见只恢复必要读取。 |
| 元数据与其他读取失败 | 挂住更新/网络计量读取时日志/消息仍可加载；清单尚未就绪时按 ID 回退而非判定卸载；存储损坏告警不被空结果隐藏。 |
| 暂停/清除/继续 | 暂停后迟到请求不改列表；改条件显示待应用；复制原冻结结果；恢复使用最新条件；跨页来回保持暂停状态。 |
| 中文搜索与时间 | IME 中间词不查询，焦点/选区不断开；零时间戳、本地时区、跨日、闰日与无效边界正确；结束分钟语义不变。 |
| 日志身份与窗口滑动 | 记录头部淘汰不借用别条 key；阅读锚点不跳；移出窗口的选中记录只保留一份快照且有说明；切筛选不混入旧详情。 |
| 读取与写入并发 | A→B 详情保持 B；mark_read 前发出的旧快照不能恢复未读旧状态；读失败/写失败各自提示；批量已读无重复提交。 |
| 未读行移除 | 行移除后详情保留，列表计数正确、焦点有落点；无剩余未读时可以返回全部。 |
| 去重与淘汰 | 同 ID 去重更新次数/内容且再次未读，不自动补读；超过 1000 条淘汰已选消息时不崩溃，不缓存无限历史。 |
| 来源与关联 | core＋pluginId、plugin 自报、纯核心、插件更名/移除分别准确；查看插件只命中真实 ID；不猜服务器或任务目标。 |
| 跨入口/多窗口 | 侧栏、顶栏、托盘、toast、插件详情、状态页进入同一控制器；用户离开后旧异步不重新导航；消息全局事实仍由核心同步。 |
| DOM 与资源 | 同实体刷新保留控件、展开/选区/焦点；切实体不串状态；连续挂载/卸载 20 次后监听、timer、在途尾回包不越界。 |
| 三主题与尺寸 | 320/640/1024/1440px 窗口及真实 Shell 下无控件横向溢出，长中文/ID/URL可读；125%/150%设备缩放与200%文本缩放分别记载。正文与次要文字对比度按实际背景检查。 |
| 键盘与设备 | 原生按钮可用键盘选择和返回，滚动区可达；实际鼠标文本选择/复制、CJK IME、触控板及读屏分别检查，不把合成输入记为真实设备通过。 |
| 有界渲染与性能 | 最多 500 条摘要＋一个日志详情、1000 条消息摘要；fields 只为选中项排版；不同 JSON 根类型及 HTML 字符按纯文本正确显示；30次短/长正文基准报告 P50/P95/最大值及节点数，真实磁盘/UI分段测量。无证据前不引入虚拟化库。 |
