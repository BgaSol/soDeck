# 两级 Tab 新建入口功能规划

2026-11-05 规划，2026-11-06 按用户确认实施并完成本机验证，见 [实施记录](implementation-tab-creation.md)。本方案替代此前“一级进入目录、二级按类型数量决定是否弹菜单”的提案；旧版默认组件持久化和拆分按钮未恢复。

## 1. 需求理解

一级 Tab 表示服务器工作区，`＋` 用来从已保存服务器中选择连接对象。二级 Tab 表示当前服务器主区域的组件页面，`＋` 用来立即新建一个默认组件页面。两个入口均放在所属标签条中。

本期默认主区域组件为官方终端。每次有效点击二级加号新建一个终端，不受当前正在看终端还是文件编辑器影响；“默认”不等于上一次打开的插件。本期不增加默认类型设置、记忆上次选择、拆分按钮或类型选择箭头。

## 2. 当前代码提供的基础

| 位置 | 现有行为 | 本次使用方式 |
| --- | --- | --- |
| `src/server-api.ts`、`src/server-views.ts` | 已有服务器目录、分组、名称/地址/账号/分组搜索和名称排序 | 选择浮层读取同一目录，沿用查找规则 |
| `src/connections.ts`、`connections/desktop.rs` | 已有 start/focus、指纹确认、补填凭据、连接状态通知 | 目录和浮层共用一个连接入口，保留现有认证流程 |
| `src/components.ts`、`component_ui/layout.rs` | 已有组件 open/select/locate；现有加号在只有一种创建类型时直接创建 | 加号明确打开产品默认组件，继续使用 open |
| `plugins/terminal/release.json` | 终端是中央页面，支持多个实例，新工作区推荐自动创建一个 | 保留初始终端；后续每次加号新建独立终端 |
| `src/ui.css`、`src/themes.css` | 已有公共图标按钮、菜单及主题描边规则 | 仅补布局，复用公共外观 |

现有新工作区归属在 `connections/admission.rs` 和 `workspaces.rs::adopt` 中固定为主窗口。要让独立窗口一级加号行为符合当前位置，需要将新工作区放入发起连接的窗口；这是一处明确的核心适配。重连和已打开工作区继续保留已有窗口归属。

## 3. 一级加号：服务器选择浮层

点击后在加号下方展开一个浮层，保留当前主区域内容。建议宽度 340～380px，列表最多占约半屏高度，更多条目在浮层内部滚动，尺寸随实际窗口收敛。

```text
[服务器管理] [生产环境 ×] [测试环境 ×] [＋]
                                         ┌──────────────────────────┐
                                         │ 搜索服务器               │
                                         │ 生产环境          已打开 │
                                         │ root@192.0.2.10 · 生产组  │
                                         │ 测试环境                 │
                                         │ ops@192.0.2.20 · 测试组   │
                                         └──────────────────────────┘
```

- 列表只展示已保存的 SSH 服务器；每行包含名称、`账号@地址:端口`、分组和当前连接状态。沿用目录的名称排序，搜索匹配名称、地址、账号和分组。
- 打开即聚焦搜索框；上下键选择、Enter 确认，Esc 或点击外部关闭。Esc 关闭后焦点回到加号，输入和菜单按键不传入背后的终端。浮层位置跟随触发点并限制在窗口内。
- 无资料显示“暂无服务器，请先在服务器管理中添加”；搜索无结果显示“没有匹配的服务器”；读取失败显示错误和重试。浮层只负责选择，不在这里嵌入资料编辑表单。
- 每次打开读取最新目录；打开期间目录或连接变化同步更新，保留搜索文字和仍有效的选中项。执行连接前再次校验选中的服务器及连接状态。

| 选择对象的状态 | 行为 |
| --- | --- |
| 尚未连接 | 关闭列表，调用现有连接流程；成功后在发起操作的窗口新增并选中一级 Tab |
| 已在当前窗口打开 | 关闭列表，选中已有 Tab |
| 已在其他窗口打开 | 关闭列表，定位并激活拥有该工作区的窗口 |
| 正在连接或等待认证 | 显示“正在连接/等待确认”，该行暂不可重复发起；继续由原发起窗口完成现有流程 |
| 已断线且工作区还在 | 使用现有重连流程，成功后定位原工作区；保留其窗口和页面 |

连接发起后应有持续可见的连接中反馈；认证仍由现有指纹/凭据弹窗处理。失败显示实际原因，用户可再次打开列表重试；取消或失败不留下空服务器 Tab。等待连接期间关闭发起窗口，沿用已有取消机制。

## 4. 二级加号：直接新建默认中央页面

```text
[终端 1 ×] [配置文件 ×] [终端 2 ×] [＋]       [全部页面]
```

- 本期默认目标使用稳定 ID `sodeck.terminal` / `terminal`，集中定义为产品默认入口；不按中文标题、插件枚举顺序或当前页推断。
- 点击后复用组件 open 动作，在当前服务器的二级 Tab 列表末尾追加一个终端并选中；就绪后将焦点交给新终端。每个终端使用插件已有的独立 PTY 生命周期。
- 已经存在终端时仍新建实例，不使用只定位旧页面的 locate。当前打开文件编辑器时也直接新建终端。
- 新工作区按既有推荐布局自动打开首个终端；只建立服务器连接不额外补建第二个。加号是之后主动追加页面的入口，不改变用户已有启动布局偏好。
- 同一次点击只提交一次创建请求；请求未完成时暂时禁用当前工作区的创建按钮，失败后恢复并显示原因。旧页面、输出和文件草稿保持。
- 默认终端未安装、未加载或已停止时显示不可用原因，仍允许一级选择服务器；提示从插件管理安装/启用，按现有生命周期重启后使用。连接断开时先通过现有底栏重连，再新建终端。
- “全部页面”入口只用于切换已打开页面。其他插件继续使用现有插件入口；本期不增加默认插件切换菜单，也不自动回退为其他插件。

## 5. 公共样式策略

采用 apple-design 的清晰层级、空间一致性和即时反馈。一级浮层锚定加号，二级点击直接产生页面变化；保持所属层级和结果一致。

- 两个加号使用现有 `sd-icon`，图标 16px、命中盒 28px；一级/二级条高继续为 44px/36px。加号排列在可见标签之后，标签溢出时加号保持可访问。
- 加号无常驻黑框，hover、按下、焦点、禁用复用公共规则。服务器浮层使用公共菜单表面与描边，业务 CSS 只管理宽高、排列和滚动。
- 浅色、深色沿用 1px 描边，多巴胺使用公共 2px 描边，且无投影。继续使用固定描边占位，切换主题不改变正文和终端尺寸。
- 打开反馈克制、即时；减少动态时取消位移和缩放。浮层不挤动 Tab 条、正文或侧栏。

## 6. 实施边界与验收

本期新增一个服务器选择浮层，将目录/选择器的连接动作复用为同一入口，调整二级加号的默认目标，并补齐新工作区的窗口归属。继续使用原目录和组件接口，不新增生产依赖、配置文件字段或插件协议；终端 PTY、认证和插件生命周期继续由原实现负责。

验收按两条用户流程组织：

1. 一级：空目录/搜索/无结果/读取失败、选择后认证成功或失败、同窗与跨窗复用、连接中防重复、断线重连、关闭窗口取消，以及键盘和焦点行为。
2. 二级：首次自动打开一个终端、每次加号恰好新增一个终端、文件页上点击也新建终端、不同服务器实例不串用、终端不可用与断线提示、失败可重试、旧内容和草稿保留。
3. 样式：浅色/深色/多巴胺、正常与窄窗口、长标题、多 Tab 溢出和常用显示缩放；结构线一致，浮层不越界，输入不穿透。

实施先完成以上功能及相关类型、格式、脚本、核心/界面回归和正式前端构建，提供真实界面检查。交互确认后再单独安排既有五目标原生打包、实际包和插件组合验收及发布。此前烟测重复回复、SSH 验收限时问题单独记录和处理，不扩大本功能范围。

本轮完成以上功能和相关本机检查，不修改版本、不创建标签或发行。五目标原生打包、实际安装包和独立插件组合验收留待后续发行任务。
