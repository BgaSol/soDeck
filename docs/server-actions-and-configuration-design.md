# 服务器快捷操作与统一配置窗口设计

日期：2026-10-21。状态：已实现，已完成界面回归、Windows 原生验收及本地安装包构建。

依据：用户最新要求“复制和编辑的弹窗放到一起，最后提供新建和编辑两个确认按钮即可”。遵循 [apple-design](C:/Users/bgaso/.codex/skills/apple-design/SKILL.md) 的直接操作、清楚命名、稳定布局、即时反馈和用户控制原则。

## 1. 用户意图与本次修订

用户希望先调整服务器配置，最后再决定保存结果：创建一台新服务器，或者更新正在查看的服务器。编辑与复制共用同一个窗口、同一份草稿；顶部不再设置“编辑/副本”模式，也不维护两份草稿。

核心流程：打开现有服务器 → 修改同一份表单 → 点击“新建服务器”或“保存修改”。“保存修改”是用户所说“编辑”的确认动作，文字直接表达实际结果。此版本取代此前的双模式、双草稿方案。

## 2. 列表快捷操作

保留已经提出的常驻图标顺序：连接/进入会话、新建会话｜编辑、复制配置｜端口转发｜删除配置。编辑和复制相邻，不收进下拉菜单。图标快捷入口指可点击按钮，本轮不新增键盘快捷键。

| 操作 | 图标 | 行为 |
| --- | --- | --- |
| 连接 / 进入会话 | Terminal | 沿用现有连接与会话选择规则 |
| 新建会话 | Plus | 新建独立会话，不复制配置 |
| 编辑 | Pencil | 打开统一配置窗口 |
| 复制配置 | Copy | 打开相同窗口，可聚焦并选中名称，方便改名 |
| 端口转发 | Network | 打开现有转发界面 |
| 删除配置 | Trash2 | 沿用现有删除确认、会话及跳板引用检查 |

两个配置入口的初始字段、保存按钮、按钮顺序和强调程度完全一致。复制入口不自动给表单名称加“副本”，避免用户随后点击“保存修改”误改原名称。点击入口本身不创建记录，不写剪贴板。

按钮具备可访问名称和悬停/聚焦提示。动作点击阻止冒泡，不误触发行选择、双击连接。列表窄时工具条换到下一行，所有动作继续可见；编辑与复制保持成组。详情页复用相同动作定义和启用规则。

## 3. 统一窗口与两个保存结果

窗口标题：**服务器配置**。标题下固定显示“当前配置：原名称 · 原地址”，不跟随正在修改的字段变化，始终能识别“保存修改”的对象。

表单保留现有名称、地址、端口、连接路径、用户名、认证方式、服务器间传输与标签等功能。只维护一份草稿、一份密码意图与一份未添加标签输入。

底部固定为：**取消｜新建服务器｜保存修改**。

| 按钮 | 保存对象 | 保存后结果 |
| --- | --- | --- |
| 新建服务器 | 生成新的服务器 ID | 使用当前整份草稿创建独立记录；原配置和原密码不变，选中新记录 |
| 保存修改 | 打开窗口时固定的原服务器 ID | 使用当前整份草稿更新该记录；不增加记录数量 |
| 取消 / 关闭 | 不提交 | 有实质修改时沿用一次放弃确认，否则直接关闭 |

“保存修改”作为主按钮，“新建服务器”作为次按钮。两入口不改变按钮位置或默认目标。底部说明：“新建保存为独立配置；保存修改会更新当前服务器。”

本窗口不再提供“保存并连接”第三种确认动作；保存后使用列表连接图标。删除入口保留在列表/详情，不放进统一窗口底部。全局“新增服务器”仍打开空白表单，仅提供“取消 / 新建服务器”，因为此时没有可更新的原记录。

成功关闭窗口并给出“服务器已新建”或“修改已保存”的准确反馈。失败保留整份草稿和当前输入，允许修正重试。已有会话不自动断开或重连，新连接使用保存后的配置。沿用现有筛选、选择和查看配置行为。

## 4. 名称、草稿与提交行为

两个入口都预填原名称。若名称仍与原名称一致，“新建服务器”使用现有唯一副本命名规则：“原名称 - 副本”“原名称 - 副本 2”等，遵循 120 字符限制。用户改名后按填写的名称创建，沿用现有名称校验。

名称下提前显示“新建名称：实际名称”，让用户提交前知道结果；“保存修改”始终使用输入框中的名称。更新对象只由固定 ID 决定，不能根据名称查找目标。提交时按最新列表复核名称；如果自动名称变化，更新预览并保留表单，请用户再次点击，不静默换名。

点击任一保存按钮都读取同一份当前草稿，包括待添加标签。提交函数显式接收 `intent: create | update`，同步锁定两个保存动作，避免交替连点导致重复或同时写入。执行按钮显示“新建中…”或“保存中…”。

普通输入框按 Enter 不隐式选择新建或更新；按钮按 Enter/Space 正常激活，输入法确认和标签 Enter 不触发保存。不增加全局快捷键。复制密码不使草稿变脏，放弃确认只针对实际配置变化。

## 5. 密码统一为保留、替换、清空

移除复制窗口专用的“复用来源已保存的登录密码”复选框。密码仍保持隐藏，空输入框不代表清空密码；清空必须通过明确的“清空已保存密码”动作，清空后提供“保留原密码”恢复入口。

| 当前密码意图 | 点击保存修改 | 点击新建服务器 |
| --- | --- | --- |
| 保留原密码 | 保留原记录已保存密码 | 从原服务器继承已保存密码 |
| 输入新密码 | 替换原记录密码 | 为新记录设置输入的密码 |
| 清空已保存密码 | 清除原记录密码 | 新记录不保存密码 |

没有已保存密码且没有新输入时，明确提示“未保存密码，连接时输入”。认证改为 Agent/私钥时按现有规则保存，新建不继承不适用的密码。

在密码标题旁直接提供 **复制已保存密码**，始终绑定打开窗口时的原服务器 ID。输入新密码或选择清空后，复制动作仍复制原记录当前保存的密码，旁边说明：“复制的是当前已保存密码，本次密码设置保存后生效。”这让“读取已有密码”和“决定保存密码”各自清楚。

- 有适用的已保存密码时允许重复复制；没有时显示状态，不提供无效动作。
- 复制不提交表单，不回显密码，不修改草稿。
- 复用现有 `copy_saved_server_password`，后端直接写入剪贴板并返回 `void`；继续使用敏感剪贴板标记，不新增前端明文读取接口或日志。
- 复制中只禁用复制按钮，允许继续编辑。成功就地提示，失败可重试；关闭、重开或认证上下文改变后忽略迟到反馈。
- “复制配置”是创建独立记录的入口；“复制已保存密码”是剪贴板动作，名称与位置保持清楚区分。

## 6. 现有约束与异常处理

### 保存目标相关的限制

共用表单后必须区分“字段是否合法”和“是否允许更新原记录”。必填项、端口、私钥、跳板选择等共有校验影响两个按钮。

原服务器处于待认证连接时，继续禁止更新原配置，但允许在现有规则允许的前提下使用其配置新建。若原记录被其他服务器作为跳板，改变其连接路径受到的限制应阻止“保存修改”，不应连带禁止合法新建。相关原因在按钮附近明确说明，提交时再次校验。不要仅因原记录限制而锁死整份表单。

跳板候选范围保持现有能力：排除当前原记录及已经使用跳板的服务器，不在本任务扩展级联跳板。删除继续使用既有检查。

### 服务器间传输地址

现有复制草稿修改连接地址会自动清空继承的真实地址。统一草稿后，建议取消按复制入口触发的隐式清空，改为在连接地址变化且真实地址仍为来源值时提示：“真实地址仍为来源地址，请确认。”

SSH 地址与真实地址可因 NAT 等原因不同，不强制一致。用户可主动编辑、清空，或使用现有“使用当前连接地址”。两个保存按钮都提交用户当前看到的字段，避免相同表单产生不同的隐藏字段变化。此项属于明确的行为调整，应单独回归验证。

### 来源失效

原记录被删除后，保留草稿并禁用“保存修改”。新建仍选择继承密码时明确报错，不能悄悄创建无密码记录；用户明确输入新密码或选择不保存密码后，可以沿用普通新建恢复路径。后端继续复核目标和来源存在性。

## 7. apple-design 的落实

1. 先操作内容，最后决定结果：一份表单，无顶部模式、无切换成本。
2. 按钮直接说明结果，主次清楚：更新主按钮、新建次按钮；位置不随入口变化。
3. 使用现有系统字体、语义颜色、圆角和线性图标，不添加装饰性玻璃层或多彩图标底座。
4. 按下立即反馈，异步开始即时显示状态，不添加人工等待；无需夸张弹跳或位移动画。
5. 鼠标目标至少约 36px，触控约 44px；保留清晰焦点、自然 Tab 顺序、对话框焦点约束及关闭后焦点恢复。
6. 列表按容器宽度换行，窄窗口底部可重新排布，保持两个保存动作可见，不退回菜单。
7. 检查深浅主题、forced-colors、减少动态效果、125%/150% 系统缩放。颜色不是唯一状态提示，正文与禁用原因保持可读。

以下阶段均已实现。列表与详情通过 `ServerActions.tsx` 共用动作定义；后端额外拒绝更新已删除的 ID，防止打开中的草稿重建已删除记录。

| 阶段 | 文件/组件 | 具体工作 |
| --- | --- | --- |
| A. 保存意图与纯逻辑 | `types.ts`、`serverConfiguration.ts` | 定义 create/update；提取新建名称预览、密码策略映射、按目标校验；替换复制入口专属的地址隐式清空逻辑 |
| B. 统一提交入口 | `App.tsx`、`ServerEditor.tsx` | 两入口使用相同原记录与草稿；固定原 ID；显式按 intent 路由更新或新建，不再依赖 duplicateSource 隐式决定保存对象 |
| C. 窗口与密码 | `ServerEditor.tsx`、`server-editor.css` | 删除模式/复用密码复选框、保存并连接和窗口内删除；双保存按钮、名称预览、三态密码、复制入口、失败与失效恢复 |
| D. 快捷动作 | `ServerHome.tsx`、`ServerDetails.tsx`、`server-home.css`；按需抽取 `ServerActions.tsx` | 六图标、编辑复制相邻、提示、焦点、阻止事件冒泡、按容器换行；两处共享状态规则 |
| E. 验证与交付 | `serverConfiguration.test.ts`、`connection-ui.spec.ts`、原生验收 | 覆盖提交目标、密码策略、保护规则、连点、错误保留；验证真实打包程序里的入口和密码复制 |

已有 `saveServer` 负责更新或普通新建；`duplicateServer` 负责从固定来源创建并按策略处理密码。前端以显式 intent 选择 API，不新增“读取明文密码”接口。无需数据库迁移或新依赖，后端已有权限和校验边界继续沿用。

实现采用局部修改，保留工作区中同期变更的 `App.tsx` 和连接测试。关闭窗口后焦点回到打开窗口的图标，键盘操作不改变所选服务器。

## 9. 验收标准

- 两个入口打开同一表单，初始值相同，顶部没有模式选择。
- 现有记录底部仅有取消、新建服务器、保存修改；空白新增没有无效更新按钮。
- 修改同一份草稿后，新建只增加新 ID，来源配置与密码不变；更新只修改原 ID，记录数不变。
- 原名称未改时展示唯一副本名预览；更新不意外增加“副本”后缀；重命名不改变更新目标。
- 两按钮都包含当前所有可见字段和待添加标签；连点和交替点击只提交一次。
- 输入 Enter、输入法确认、复制密码不触发保存。失败不丢内容，取消无写入，脏草稿只确认一次。
- 密码保留/替换/清空的两种提交结果符合映射表；空输入不清空，复制始终读取固定原记录已保存密码。
- 来源删除、待认证、跳板引用限制按提交目标生效，无静默丢密码或连接行为回归。
- 六项快捷动作常驻且不误连；鼠标、键盘、触控和窄布局可用。
- 最终在包含本次实现的安装包中验收，记录版本、构建来源及测试结果；计划示意通过不代表已打包上线。
