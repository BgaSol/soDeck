# 终端复制粘贴功能设计

日期：2026-10-20  
状态：已实施；具体实现与验证范围见 `docs/terminal-clipboard-verification.md`

## 1. 用户意图与设计目标

对“目前终端的复制粘贴功能不太行”的理解是：用户在服务器输出、本机应用与不同终端之间搬运文字时，希望像桌面软件一样顺手，同时保留终端必须具备的操作能力。用户不应该猜这次有没有复制成功、为什么粘贴没反应、快捷键被谁处理了。

核心场景：复制报错去搜索或询问 AI；复制路径、容器 ID、命令参数；从网页或编辑器粘贴命令和配置；在多个服务器或容器窗口之间复制内容；从历史记录复制旧输出。

推荐默认体验：Windows 使用有选区时 Ctrl+C 复制、无选区时 Ctrl+C 发送中断、Ctrl+V 粘贴；右键打开明确的操作菜单。保留传统终端快捷键与可选的鼠标高效模式。

本提案根据代码检查提出改进方向，尚未实际复现用户遇到的具体问题，不把所有体验问题归因于同一个已确认故障。

## 2. 当前实现与缺口

| 位置 | 代码中确认的现状 | 设计含义 |
| --- | --- | --- |
| `src/TerminalPane.tsx` | 使用 xterm；未见应用自定义复制粘贴快捷键、右键菜单或剪贴板服务；onData 直接调用 terminal_input | 基础操作依赖终端组件与 WebView 默认行为，缺少统一产品规则 |
| `src/TerminalWorkspace.tsx` | 工具栏提供历史、全局历史搜索、清理显示；历史覆盖实时层并传入 interactive=false | 可复用工具栏；必须明确只读状态与实时输入边界 |
| `src/TerminalHistoryView.tsx` | 记录范围复制先取文本，再调用 navigator.clipboard.writeText，并显示结果 | 已有范围复制应保留，与普通文本选区复制区分 |
| `src/TerminalReplayView.tsx` | disableStdin=true，没有输入处理器 | 回放可复制，但不得建立输入路径 |
| `src/systemSettingsApi.ts` | 当前设置接口主要处理开发者模式，有 revision 与变更事件 | 终端偏好需扩展持久化接口，不能只加本地开关 |
| `src-tauri/src/lib.rs` | terminal_input 核验窗口归属，限制单次数据不超过 1024×1024 字节，再交给输入队列 | 大段粘贴需提前校验；请求成功不等于远端程序已消费 |

实时层目前在 onData 中检查 session 和 transferring，没有显式检查 active / interactive。实施时应在用户输入入口补充状态校验；终端协议自动回复需单独区分，避免简单封锁所有 onData 而破坏后台程序的协议响应。

## 3. 操作规则

### 3.1 快捷键

快捷键仅作用于有焦点的终端。搜索框、设置输入框、粘贴预览编辑框保持普通文本编辑行为。

| 操作 | Windows 默认 | Linux 默认 | macOS 默认 |
| --- | --- | --- | --- |
| 复制选区 | Ctrl+C；也支持 Ctrl+Shift+C | Ctrl+Shift+C | Cmd+C |
| 粘贴文本 | Ctrl+V；也支持 Ctrl+Shift+V、Shift+Insert | Ctrl+Shift+V、Shift+Insert | Cmd+V |
| 向远端发送 Ctrl+C | 无选区时 Ctrl+C | Ctrl+C | Ctrl+C |
| 向远端发送 Ctrl+V | 菜单“发送按键 → Ctrl+V”，或关闭便捷快捷键 | Ctrl+V | Ctrl+V |
| 清除本地终端选区 | 有选区时 Esc，仅清除选区 | 同左 | 同左 |
| 全选终端缓冲区 | 右键菜单“全选缓冲区” | 同左 | 同左 |

补充规则：

- Windows 的“便捷快捷键”默认开启，关闭后 Ctrl+C / Ctrl+V 原样交给远端，复制粘贴使用 Ctrl+Shift+C / V。Linux 可主动开启同一模式。macOS 以 Cmd 系列操作本机剪贴板，不接管 Ctrl 系列。
- 有选区的 Ctrl+C 复制失败时只报错，不能继续发送中断；Ctrl+Shift+C / Cmd+C 没有选区时不发送任何远端输入。
- 复制后保留选区，避免视觉跳动。Windows 需要中断时可按 Esc 清除选区再按 Ctrl+C，或直接使用菜单“发送按键 → Ctrl+C”。重复 Ctrl+C 仍然复制，不能隐式变成中断。
- 不接管 Ctrl+A；它继续由远端程序处理。“全选缓冲区”只选当前 xterm 已加载的内容，不承诺选中全部持久化历史。
- 只处理一次 keydown；忽略组合输入阶段的快捷键与复制粘贴按键自动重复，不对 keyup 再次执行。
- 不根据是否显示全屏程序自动切换快捷键含义。使用 Vim 等程序且依赖原始 Ctrl+V 的用户可以关闭便捷快捷键。

### 3.2 鼠标与右键菜单

默认拖动选择，双击选择词元，三击选择行；复制使用终端选区文本，正确处理中文、宽字符与折行。右键打开菜单时保留既有选区，不自动改选右键下的单词。

菜单固定顺序：

1. 复制（没有选区时禁用）。
2. 粘贴（当前不能输入时禁用，并说明原因）。
3. 粘贴前预览…（即使单行也可主动预览）。
4. 全选缓冲区。
5. 发送按键 → Ctrl+C / Ctrl+V（仅实时、可输入状态）。
6. 复制粘贴设置…。

菜单右侧显示当前平台快捷键。支持键盘打开菜单、方向键移动、Enter 执行、Esc 关闭。弹出位置限制在窗口内；关闭后在目标仍有效时恢复焦点。

可选“选中即复制”：默认关闭。仅在用户完成非空选择后复制一次，不在拖动每一帧或程序性选区更新时写入剪贴板。失败保留选区并提供重试反馈。

可选“右键直接粘贴”：默认关闭。开启后，普通右键只执行粘贴，仍遵循同一预览规则；Shift+右键始终打开菜单。设置旁明确说明这一入口。

远端启用鼠标跟踪时，普通鼠标操作默认交给远端；本机选择使用平台对应的强制选择修饰键，应用菜单可通过键盘打开。Windows/Linux 使用 Shift+拖动，macOS 可配置 Option+拖动强制本机选择；Shift+右键保留为本机菜单入口。远端鼠标跟踪期间暂停“普通右键直接粘贴”。这些组合需要在打包后的各平台实际验收。

### 3.3 复制内容

- 默认只复制纯文本，不携带颜色转义、HTML、服务器标识或时间戳。
- 窗口宽度造成的软折行应还原为连续文本；真实换行保留。保持可见内容中的缩进与空白，不额外做 trim、去提示符或命令提取；底层选区对屏幕填充空白的处理以实际验证为准。
- 复制时立即取得文本快照；等待系统剪贴板写入期间，远端新输出不改变本次复制内容。
- 未选内容时不覆盖原剪贴板；系统写入失败也不能显示成功。
- 普通复制显示短暂的“已复制”状态，不弹窗、不把提示写进终端输出。选中即复制模式使用更轻的状态反馈。

### 3.4 粘贴内容

普通单行文本直接粘贴到远端当前输入位置，不主动补 Enter、不清空输入行。终端的输出选区不是远端编辑器选区，粘贴不能被描述为“替换选中文字”。

所有入口共用同一策略：快捷键、右键、工具栏，以及 WebView 原生 paste 事件。每次用户动作只产生一份输入。

建议首版规则如下，数值为产品初始值，应通过实际桌面体验校准：

| 内容 | 默认处理 |
| --- | --- |
| 空文本或仅有非文本格式 | 不发送，提示“剪贴板中没有可粘贴的文本” |
| 单行，含普通空格或 Tab，且不超过 16 KiB | 直接粘贴；空白本身是有效文本，不擅自丢弃 |
| 含任意 CR / LF，包括只有末尾一个换行 | 打开预览，说明换行可能被远端解释为提交 |
| 超过 16 KiB 的单行文本 | 打开预览，展示大小 |
| 含 ESC、NUL、除 Tab/CR/LF 外的 C0 控制字符或 DEL | 打开预览，显式显示字符与数量；处理前不允许发送 |
| 最终送入 terminal_input 的 UTF-8 数据超过 1 MiB | 阻止发送，提示使用文件上传或远程编辑器；不截断 |

预览是当前终端内的模态对话框，包含：

- 标题“粘贴到终端”，固定显示服务器名、账号、地址，容器会话附容器名；不以最新活动标签页替换目标。
- 等宽可编辑文本区、行数与字节数；可开启显示空白字符。较长内容使用有界渲染，但底层文本保持完整，不只发送可见部分。
- 末尾换行明确标记；只有一行命令加末尾换行时，突出提供“移除末尾换行”。修改前后可见，不自动悄悄删除。
- 普通多行文案：“内容包含换行，远端程序可能立即处理其中的命令。”不宣称一定不会执行。
- 若存在上述控制字符，提供“移除控制字符”操作；移除后允许粘贴。首版不提供绕过此项直接发送控制字符的入口，原始按键通过专门菜单发送。
- 操作按钮“取消”“粘贴”；初始焦点在预览文本区，Enter 在文本区正常换行，不能由触发粘贴的按键顺势确认。
- 编辑后重新计算规则与大小。取消只丢弃当前操作，不修改系统剪贴板。

保留正常缩进、Tab、换行与 Unicode 内容；仅对明确确认的编辑做转换。换行编码适配由终端粘贴 API 完成。

首版对所有含换行的文本提示，不依赖远端是否声明支持 bracketed paste 来跳过预览。bracketed paste 表示按远端模式包装粘贴数据，不能承诺任意程序都不会执行内容。

### 3.5 焦点、会话与异常

- 从工具栏或右键发起粘贴时，动作绑定触发时的终端实例、连接代次及窗口；校验通过后恢复终端焦点。
- 剪贴板读取或预览期间，若目标断开、重连、迁移、关闭、切换到历史、切换活动标签页或窗口失去激活，取消尚未发送的操作，提示“目标终端状态已改变，请重新粘贴”。不会转投新会话。
- 对话框内部焦点变化不算目标失效。取消或完成后仅在目标仍有效时恢复焦点，不抢占用户后来进入的其他窗口。
- 未连接时仍可复制保留的输出，粘贴禁用。连接中不排队等候发送；重连后不自动恢复旧粘贴。
- 同一终端的粘贴读取或预览期间不叠加另一份粘贴。每次明确完成后，下一次新的用户操作可以粘贴相同文本，不能靠内容去重吞掉合法操作。
- 读取失败显示“无法读取系统剪贴板，请重试”；写入失败显示“复制失败，请重试”。错误不回显剪贴板内容。
- terminal_input 返回仅表明本机输入请求被接收，不能显示“命令执行成功”。连接中途异常可能导致远端只收到部分内容，提示检查终端，不自动重发。

## 4. 界面安排与设置

在现有终端工具栏中增加“复制”“粘贴”图标按钮，带文字提示与平台快捷键。无选区时复制禁用；不可输入时粘贴禁用。窄窗口可收进“更多”，右键菜单和快捷键持续可用。

反馈复用工具栏状态区域：复制成功显示约 1.5 秒；错误提供可关闭提示与重试入口；正常单行粘贴以终端自身回显为主，不反复弹成功消息。屏幕阅读器可读取状态，提示不抢焦点。

“系统设置 → 终端 → 复制粘贴”首版只增加三个偏好：

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 便捷快捷键 | Windows 开，Linux 关；macOS 使用 Cmd | 有选区 Ctrl+C 复制、Ctrl+V 粘贴；关闭后保留原始 Ctrl 按键 |
| 选中即复制 | 关 | 完成鼠标选区后写入系统剪贴板 |
| 右键直接粘贴 | 关 | Shift+右键打开菜单；远端鼠标模式下普通右键交给远端 |

设置持久化到应用级配置，通过现有 revision / 变更事件思路同步所有窗口，不按服务器重复设置。正在进行的粘贴以发起时的设置快照完成，不能因设置刷新重复触发。

首版不加入剪贴板历史、命令收藏、自动执行、跨服务器批量粘贴或 AI 改写。多行预览保持统一默认，不增加一组难以理解的模式开关。

## 5. 不同视图的一致性

| 场景 | 复制 | 粘贴 |
| --- | --- | --- |
| 主窗口实时 SSH | 终端选区复制 | 当前可输入会话 |
| 独立 SSH / 容器窗口 | 同上 | 当前窗口所属会话 |
| 已断开但仍有画面的终端 | 可复制 | 禁用 |
| 历史阅读视图 | 有正文文本选区时优先复制该选区；无正文选区且有记录范围时复制所选记录 | 不向后台实时终端转发 |
| 历史搜索输入框 | 普通输入框规则 | 粘贴到搜索框 |
| 历史屏幕回放 | 可复制 xterm 选区，提供只读菜单 | 禁用，不建立输入通道 |

历史正文复制不附时间和来源；保留现有“复制记录”显式动作。虚拟列表跨未加载范围的复制继续走历史 API，不能依靠 DOM 拼接。回放的复制服务仅支持用户主动复制，不因重放终端输出自动访问系统剪贴板。

## 6. 实施结构

实现以当前 xterm 与 Tauri 架构为基础，无需更换终端组件。

- 增加统一的文本剪贴板服务。桌面端建议接入 Tauri clipboard-manager 的 readText / writeText，开发用浏览器模式通过 Clipboard API 适配。权限限定在需要的窗口：实时终端可读写，独立历史窗口仅写；不在打开菜单或后台轮询时提前读取剪贴板。
- 复制通过 xterm 的 getSelection；终端快捷键通过 attachCustomKeyEventHandler；粘贴最终通过 term.paste(text) 进入已有输入链路。不要使用 term.write 假装输入，也不要把未经包装的文本直接作为菜单粘贴发给 SSH。
- 在终端宿主统一捕获原生 paste 事件，明确阻止 xterm 再次处理已被接管的事件。键盘、菜单和原生事件的所有权必须唯一，以事件/操作标识协调，不用固定时间窗口粗略去重。
- 提取粘贴分析与目标校验逻辑，区分读取、预览、提交、完成、取消和失败。最终提交前再次校验目标和最终编码大小，并计算终端粘贴包装的开销。
- 首版沿用单次输入，不为超过上限的粘贴做分片。这样无需引入部分发送进度、恢复与撤销等更复杂的承诺。
- 用户输入权限检查必须覆盖 active、interactive、session、迁移状态与连接代次；继续保留 Rust 端窗口归属校验。
- 为后台终端自动协议回复保留独立处理；实现前确认当前 xterm 公开 API 的区分方式，必要时补充受控输入协调层，不能只给所有 onData 加一个统一可见性判断。
- 连接历史保存的是既有终端输出；此次剪贴板功能不新增剪贴板内容日志或持久化副本。远端可能回显粘贴内容，仍遵循现有终端输出记录规则，不承诺粘贴内容不会进入历史。

主要改动位置：`TerminalPane.tsx`、`TerminalWorkspace.tsx`、`TerminalHistoryView.tsx`、`TerminalReplayView.tsx`、系统设置前后端、Tauri 插件注册及 capabilities；新增公共剪贴板适配、交互协调与预览组件。

## 7. 交付顺序与验收

第一批交付组成完整可用版本：统一剪贴板服务、平台快捷键、右键菜单、工具栏入口、复制反馈、粘贴预览、大小限制和目标状态校验；覆盖主窗口、独立窗口、容器与历史只读场景。

第二批补充个人偏好：选中即复制、右键直接粘贴、跨窗口设置同步；便捷快捷键的关闭入口应随第一批提供，以免影响依赖原始 Ctrl+V 的用户。

验收以可观察行为为准：

| 验收场景 | 通过标准 |
| --- | --- |
| Windows 有选区 Ctrl+C | 系统剪贴板正确；远端收到 0 字节；失败也不发送 Ctrl+C |
| 无选区 Ctrl+C | 仅发送一次预期控制字符；远端实际行为由程序决定 |
| 每个粘贴入口 | 同样的文本、预览与错误规则；一次动作仅提交一次 |
| 复制中文、emoji、长路径、软折行、实际换行 | 内容不乱码，折行语义正确；无附加终端颜色编码 |
| 单行、仅末尾换行、多行脚本、Tab 与空白 | 普通单行直接输入；有换行进入预览；修改和取消结果符合展示 |
| ESC、NUL 等控制字符 | 可见且不会未经处理直接发送 |
| 16 KiB、1 MiB 附近与多字节中文 | 按 UTF-8 最终输入计算边界；无截断，无后端静默失败 |
| 读取等待、预览期间切换/重连/迁移/关闭 | 旧操作取消，新目标收到 0 字节 |
| 历史阅读与回放尝试粘贴 | 后台会话收到 0 字节；搜索框仍可正常粘贴 |
| 剪贴板被占用、无文本格式、权限失败 | 有可理解的反馈，不误报成功、不覆盖旧内容 |
| 开启/关闭 bracketed paste 的 shell 与 Vim/tmux | 包装正确，修饰键与远端鼠标操作符合规则，无重复输入 |
| IME、按键长按、菜单焦点、键盘导航 | 不吞组合输入，不重复粘贴；取消后焦点合理 |

自动化覆盖规则、事件重复与会话状态竞争；使用真实打包的桌面应用与系统剪贴板验证 Windows / macOS / Linux。模拟 navigator.clipboard 或 IPC 的网页测试不能替代原生验收。首版优先在当前 Windows 环境完成复现与实测，其余平台未验证前明确标记范围。
