# 工作区工具窗口优化方案

日期：2026-10-21。状态：用户已确认并授权实施，前端实现已完成。实际改动与验证范围见 [实施记录](./workspace-tool-windows-implementation.md)。

依据当前工作区代码、项目已有功能、仓库历史界面截图，以及用户提供的 IDEA 截图制定。截图用于理解布局与交互意图；实施授权来自用户在本次会话中的明确确认。

## 1. 意图与设计方向

将 SoDeck 工作区整理为“中央终端 + 左右工具栏 + 可收放工具窗口”：左边的文件夹图标控制远程文件面板；右边的 Docker、服务器状态、NetBird 图标分别控制对应面板。两侧入口始终可找到，面板按需展开，收起后把空间还给终端。

采用 IDEA 的工具窗口组织方式，结合 apple-design 的清晰层级、直接反馈、空间一致性和用户控制。保留 SoDeck 现有浅色、深色、系统主题、字体与图标体系。

本轮范围是 SSH 会话工作区，包括独立 SSH 窗口。服务器首页、文件编辑器、独立日志与监控窗口维持各自用途；文件传输、端口转发、终端历史等现有入口继续可达。

## 2. 当前界面与需要调整的地方

已核对 `WorkspaceLayout.tsx`、`workspaceSizing.ts`、`SessionWorkspace.tsx`、`ServicePanel.tsx`、主题样式与相关面板实现。

| 当前设计                                          | 调整方向                                                     |
| ------------------------------------------------- | ------------------------------------------------------------ |
| 宽度达到 1200px 时，文件、终端和服务三栏全部显示  | 文件与右侧工具窗口可独立收起；终端获得释放的空间             |
| 右栏顶部横排“监控 / Docker / NetBird”             | 入口移到最右侧纵向工具栏，右侧内容区一次展示一个工具         |
| 较窄窗口出现顶部工作区域切换条                    | 两侧工具栏承担统一入口，按可用空间选择停靠、浮层或内容区切换 |
| 文件及服务宽度可以拖动，已有键盘分隔条            | 保留调整能力，折叠后记住各自宽度                             |
| CPU、内存和网络摘要常驻终端底部                   | 保留轻量摘要，点击时打开右侧“服务器状态”的对应详情           |
| 会话移动快照已有目录、Docker、NetBird、尺寸与视图 | 扩展快照表达两侧开关，随标签切换和跨窗口移动保留             |

右侧“服务器状态”对应现有监控功能：CPU、内存、网络、磁盘与挂载。SSH 连接状态继续在会话标签和终端区域表达，避免把监控异常误认为连接中断。

## 3. 空间结构

以下为左右工具窗口均展开时的结构示意，宽度随窗口调整：

```text
┌───────────────────────────────────────────────────────────────────┐
│ 品牌 / 服务器入口 / 会话标签                      外观 / 设置 / 窗口 │
├────┬─────────────┬─────────────────────────────┬─────────────┬──────┤
│文件│ 远程文件  收起│ 终端身份与连接操作           │ Docker  收起│Docker│
│图标│ 路径 / 工具栏│                             │             │ 状态 │
│    │ 文件树      │           SSH 终端          │ 当前工具内容 │NetBird│
│    │             │                             │             │      │
│    │             │ 连接与资源摘要               │             │      │
├────┴─────────────┴─────────────────────────────┴─────────────┴──────┤
│ 工作区 / 文件任务与进度                                             │
└───────────────────────────────────────────────────────────────────┘
```

两侧工具栏位于标题栏下方、全局文件任务栏上方，贯穿工作区高度。中央终端始终是主要工作区域；工具窗口停靠在自己的图标栏内侧。取消右栏顶部重复的跨工具切换条，保留 Docker 与 NetBird 各自内部的业务导航。

## 4. 工具栏与面板行为

### 左侧：远程文件

- 一个文件夹图标，提示“远程文件”；点击展开文件面板，再次点击收起。
- 面板顶部显示“远程文件”和收起按钮，沿用路径定位、文件树、挂载信息、上传下载、新建和菜单操作。
- 收起只改变可见性，保留目录、展开节点、选中项和滚动位置，继续执行已有文件任务。
- 终端目录跟随可以更新状态，但不因为 `cd` 自动展开用户主动收起的面板。
- 用户明确执行“在文件中显示”时，展开文件窗口并定位目标；这是用户发起的导航行为。

### 右侧：Docker / 服务器状态 / NetBird

按用户描述，自上而下固定排列 Docker、服务器状态、NetBird。每项使用统一的单色线性图标，悬停或键盘聚焦显示完整名称，中文保持横向阅读。

| 用户动作                           | 结果                                 |
| ---------------------------------- | ------------------------------------ |
| 右侧全部收起时点击某项             | 展开右侧窗口，显示该工具             |
| 某工具已展开，再点其图标           | 收起右侧窗口                         |
| 某工具已展开，点击另一工具         | 在相同位置切换内容，保持宽度         |
| 点击面板标题中的收起按钮           | 收起面板，入口图标保留               |
| 点击终端底部 CPU / 内存 / 网络摘要 | 展开服务器状态并定位对应指标         |
| 切换会话或将会话移到另一窗口       | 恢复该会话的开关、工具选择及面板内容 |

右侧同时最多展开一个工具窗口，左侧文件可与它同时显示。工具不可用时仍保留入口，打开后显示明确原因与现有恢复入口，例如未安装 Docker、SSH 已断开或 NetBird 查询失败。

面板各自保存业务状态：Docker 搜索与选择、服务器状态的时间范围与指标详情、NetBird 筛选与所选节点。关闭面板不会关闭容器终端、日志窗口或中止已提交任务。

### 默认状态

建议新建会话首次打开文件面板，右侧工具窗口默认收起；监控摘要继续可见，便于先开始终端工作。进入已有会话恢复它自己的布局。

旧快照若只有 `pane` 等字段，应按旧窗口宽度与可恢复信息兼容还原；无法确定时使用上述新默认值。第一阶段只要求当前运行期间及会话跨窗口移动的状态保留，应用重启后恢复布局作为后续独立范围，避免把临时会话内容写入偏好存储。

## 5. Apple Design 的具体落点

### 视觉层级

- 工具栏建议宽约 44px，图标 18–20px，按钮命中区约 36–40px，所有数值作为 14px 基准下的初始值，使用 rem 支持字号缩放。
- 普通图标采用现有次级文字色；悬停显示轻背景；打开时使用柔和蓝色选中背景与清晰图标色。状态不只依赖颜色，配合背景形状、提示文字与辅助功能状态。
- 延续 `--canvas`、`--sidebar`、`--material`、`--selected` 等主题变量，深浅主题共用语义。
- 工具栏和标题区使用轻材质层次；文件、表单和终端内容保持稳定可读的背景。磨砂仅用于有内容穿过的浮动区域，避免多层透明叠加。
- 主要通过留白、对齐与背景层级区分区域；停靠窗口使用细分隔线，浮层才增加必要阴影。
- 面板标题约 14px、正文约 13px、辅助信息约 12px，沿用系统字体。数据采用等宽数字，频繁变化时减少视觉跳动。

### 反馈与动效

- 按下立即给视觉反馈，释放后执行开关；连续点击和反向操作始终有效。
- 文件窗口沿左侧进入和退出；服务窗口沿右侧进入和退出，起止方向一致。
- 需要位移动效时采用无明显回弹、可中断的弹簧，参考阻尼比 1.0、响应 0.3 秒；中断从当前屏幕位置继续。
- 避免逐帧改变终端容器宽度造成字符反复换行。首版优先一次提交最终停靠尺寸，再对面板内部做短淡入；可连续交互的侧向弹簧动效优先用于浮层。
- 拖动分隔条时内容跟随指针，保持 Pointer Capture，不添加追赶指针的延迟动画。终端尺寸调整合并到动画帧，并在拖动结束校准。
- 遵守减少动态效果、减少透明度和提高对比度：可改为直接切换或短淡入、实色背景与更清晰边界。

### 键盘与焦点

- 因为右侧允许全部收起，工具入口使用按钮开关语义，设置 `aria-expanded` 和 `aria-controls`；避免直接套用必须有活动页的普通标签页模型。
- 图标拥有完整可访问名称，提示与焦点轮廓支持鼠标和键盘。
- 隐藏面板移出 Tab 顺序并设为不可交互；仅对面板内部焦点被隐藏的情形恢复到触发按钮，不能每次收放都强行抢走终端焦点。
- 普通停靠面板支持 Tab 自由进出。Esc 优先关闭菜单和弹窗，再处理当前临时浮层；不能全局吞掉终端的 Esc。
- 第一阶段先确保按钮、Tab 和现有分隔条方向键完整可用。面板快捷键另行核对 Windows、macOS、终端及应用快捷键冲突后再确定，避免覆盖常用 Shell 按键。

## 6. 窗口变窄时的规则

布局以真实可用宽度计算，扣除左右工具栏和分隔条后，优先给终端保留约 560px 的舒适宽度。文件默认 280px，建议范围 240–520px；右侧默认 360px，建议范围 320–480px。字体放大后同步调整。

| 可用空间                     | 行为                                                                   |
| ---------------------------- | ---------------------------------------------------------------------- |
| 能同时容纳左右面板与舒适终端 | 左右可同时停靠；以默认尺寸估算约需 1320px 工作区宽度                   |
| 只能容纳一个面板与舒适终端   | 最近打开的一侧停靠，另一侧暂时收起；打开另一侧切换停靠对象             |
| 单个面板也会严重挤压终端     | 面板从对应侧覆盖展开，不显示模态遮罩，提供清晰关闭入口                 |
| 工作区极窄，例如低于约 760px | 一次显示终端或一个工具的完整内容，两侧入口保留；工具标题提供“返回终端” |

阈值需结合实际字号、内容最小宽度与原生窗口验证，不能继续只靠固定的三栏 / 两栏判断。窗口缩窄造成的临时隐藏与用户主动关闭分别记录；窗口重新变宽时恢复原本想要打开的面板，不覆盖用户记住的宽度。

浮层不是模态弹窗，不锁住整页焦点；进入更窄的内容切换模式时，隐藏的终端也不能继续接收键盘输入。真实业务确认弹窗仍按现有模态规则处理，优先于工具窗口。

## 7. 实施边界与批次

这次主要调整前端工作区外壳，复用现有文件、Docker、资源与 NetBird 业务组件，不以布局改造为由重写连接和任务系统。

| 批次                | 改动                                                   | 主要位置                                                                                           |
| ------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| A：工作区状态与外壳 | 两侧工具栏、展开开关、右侧工具选择、移除重复导航       | `WorkspaceLayout.tsx`、`ServicePanel.tsx`、`SessionWorkspace.tsx`、`workspaceSizing.ts`            |
| B：内容与导航衔接   | 面板标题与收起、监控指标跳转、文件定位、逐会话快照恢复 | `FilePanel.tsx`、`ResourcePanel.tsx`、`DockerPanel.tsx`、`netbird/NetBirdPanel.tsx` 及会话移动逻辑 |
| C：响应式与视觉     | 可用宽度预算、临时隐藏与恢复、主题、浮层与焦点         | `workspace-layout.css`、`resources.css`、`theme.css` 及布局逻辑                                    |
| D：交互验收         | 快速反向点击、终端尺寸、键盘、跨窗口移动与后台任务     | 现有 Vitest、Playwright 与桌面验证入口                                                             |

建议将“用户想打开哪些面板”与“当前宽度实际能显示哪些面板”分开建模。状态至少包含文件开关、右侧开关、最近选择的右侧工具、两侧偏好宽度；右侧工具选择复用现有 `resources.tab` 作为唯一来源，避免两个状态不同步。

隐藏时保留组件业务状态，同时使用可见性控制昂贵详情刷新。资源摘要仍需要共享监控数据；不能因为右侧收起就停掉整个 MonitorProvider。Docker 和 NetBird 的任务回执、结果核对及现有后台采集规则也必须继续运行。收起是展示操作，不能触发业务生命周期重建。

## 8. 完成标准

1. 文件夹图标可可靠开关文件窗口，右侧三个入口均可打开、切换和再次收起。
2. 两侧收起后终端占用释放空间；工具栏始终保留，窗口不出现空白占位列或横向溢出。
3. 反复收放不重连 SSH、不重建终端、不丢目录、搜索、选中项、滚动位置或正在编辑的业务草稿。
4. CPU 摘要与“在文件中显示”等现有导航可打开正确工具并定位目标。
5. 不同会话各自记忆布局，拖到独立窗口及移回时正确恢复；后台文件任务、Docker 操作和日志采集继续。
6. 以 1440、1280、1024、860、650px 及字号放大核对停靠、覆盖、内容切换、缩窄再放宽和用户主动关闭的区别。
7. 浅色、深色、高对比度、减少透明度与减少动态效果均可用；所有入口具备名称、焦点反馈和正确开关状态。
8. 桌面端核对终端输入焦点、Esc、连续切换、分隔条拖动与真实尺寸变化；浏览器测试不代替 Windows / macOS 的原生窗口验证。

以上保留获批方案的设计目标；已执行的验收与尚未验证的原生平台范围以实施记录为准。
