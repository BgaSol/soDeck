# 混合连接实施记录

2026-11-05，代码整改第 2 批，实现真实 SSH/SOCKS5 混合连接并交给既有工作台。本机开发验证时使用 0.4.0 版本号，随后以 [v0.5.0](releases/v0.5.0.md) 完成五目标原生打包并正式发行。本记录不代表终端、文件与统计设计全部完成。

## 已实现行为

- 从服务器详情建立连接，异步展示当前节点与 TCP、SSH 握手、认证、隧道或 SOCKS5 阶段。同一服务器档案复用正在进行的尝试；不同档案可并行。
- 核心从目录取得只在内部使用的资料快照，按 `route[]` 顺序追加最终目标。引用节点只贡献自身地址和认证，不展开自己的路径；不修改 `servers.json` 格式。
- 只有第一站使用本机 TCP/DNS。SSH `direct-tcpip` 和 SOCKS5 CONNECT 将后续域名原样交给上一站；支持无认证及用户名/密码 SOCKS5，不降级到其他认证方式。
- SSH 使用显式密码或私钥认证。私钥在核心读取，支持普通和加密的 OpenSSH Ed25519/RSA；缺少密码、私钥路径或加密口令时通过核心弹窗补填。补填仅供这次连接，记住凭据继续使用资料编辑表单，秘密不进入投影、事件或日志。
- 每个 SSH 节点在提交认证凭据前核验主机身份。首次指纹与密钥变化分别要求确认，变化展示旧/新 SHA-256 指纹。不导入或修改系统 known_hosts。
- `ssh-hosts.json` 按访问路径前缀、协议、端点及有关账号区分身份，前缀和配置身份摘要均不包含密码。名称、分组不影响身份；同一主机经过不同路径需要分别确认。并发确认相同密钥可复用，变化不能覆盖另一项更新。
- 每个非交互阶段限时 30 秒，等待用户回复的时间不计入。取消信号作用于第一条实际 socket，即使 SSH 握手内部已生成后台任务也会终止传输。已经读取/解密私钥的阻塞系统调用不会被强制杀线程，其迟到结果不能接纳为会话。
- 仅最终目标认证成功且尝试、资料身份、工作台仍有效时接纳连接；失败不创建工作台。资料身份在连接中改变会取消尝试；运行会话保留原连接身份。
- 主动断开或传输关闭后保留工作台；SSH 保活间隔 30 秒、最大未响应次数 3。手动重连成功才替换 connectionId 并递增 generation，视图同步绑定新 Context，旧 surface 作废。地址、账号、认证方式或路径改变时先确认按新资料重连。
- 工作台拖出/移回只移动展示归属，沿用同一 SSH 会话。关闭工作台、销毁窗口与应用退出会取消对应连接或尝试；重连期间关闭工作台也不能被迟到成功重新创建。
- 本地视图身份检查与远端在线检查分离；断线仍可处理适用的本地草稿操作。右上角状态显示已连接/正在连接数。

## 代码边界

`servers/connection_profile.rs` 生成无公开序列化/Debug 的内部快照；`connections` 持有有界尝试及实际会话。`route` 顺序建链，`ssh` 适配库与认证，`socks5` 实现字节通道上的协商，`io` 执行物理 socket 取消和计量，`host_keys` 持久化公开主机密钥，`admission` 短锁提交工作台，`desktop` 仅适配 Tauri 命令。

注册表锁不跨网络或用户等待。接纳遵循 servers → connections → workspaces → component_ui 的顺序；事件和插件回调在锁外执行。当前只存在核心归属的建链资源，所以取消作用域直接绑定 attempt/Context，没有提前建立空的通用资源框架。PTY/文件插件进入后再引入其真实 owner 和资源索引。

最多同时保留 32 个运行中的尝试/会话，最多保存 64 份最近结果；运行中的项目不被淘汰。问题绑定尝试 ID、问题 ID 和来源窗口，旧回复、重复回复及取消后的回复被拒绝。快速取消后重试的竞态已复现并修复：先更新工作台断线，再同时发布终态和完成标记。

桌面使用 `connection` 命令及类型化 `op`：snapshot/start/cancel/answer/disconnect/focus。插件尚不能通过 RPC 打开远程通道；初始化 capabilities 不提前声明会话、PTY、SFTP 能力。测试命令执行只有内部有界验证入口，不提供产品命令输入框。

## 计量口径

第一条 TCP socket 的成功读写使用原子整数计数；后续 SSH/SOCKS 封装不重复累加。数值为十进制 u64 字符串，包含 SSH/代理协议字节，排除 IP/TCP 头及重传；它表示应用在 socket 上读写的字节，不是抓包统计。失败尝试已经消耗的字节仍可查询。

本批只提供每次尝试/会话的累计量，尚未提供速率、跨重连运行累计、插件业务载荷及估算分摊。这些在 PTY/文件资源有真实 owner 后实现，不能把目前数值称作“某插件占用带宽”。

## 验证与剩余边界

隔离 Rust 测试覆盖混合链与远端 DNS、不展开引用路径、拒绝指纹前不提交认证、旧回复、错误密码、临时凭据、取消/修改资料回收 socket、原位重连、密钥变化、四种私钥组合、移窗及 socket 计量。另通过临时回环 OpenSSH 服务验证独立实现之间的认证与命令互操作。

`npm run ssh:test` 需要本机 OpenSSH 服务端与 ssh-keygen；脚本生成临时主机/用户密钥，用当前测试用户运行独立高端口服务，不修改系统 sshd 配置。普通 Rust 测试将此环境用例标记 ignored，独立入口实际执行；Windows x86_64 构建工作流声明安装 OpenSSH Server 系统能力，再执行源码和包内两层验证。`npm run ssh:test -- --packaged <已安装程序路径>` 还会验证实际包的 SSH、原生移窗、断开与重开退出。其他四个平台沿用五目标原生构建矩阵，但本次本机不能宣称它们已验证。

主机证书、SSH agent、读取系统 SSH config、交互式 MFA、自动重连、PTY、SFTP、正式终端/文件插件、数据通道和插件细分带宽尚未实现。独立 OpenSSH 验证目前为直连；混合链自动用例使用隔离 SSH/SOCKS 测试端。没有使用用户生产服务器或凭据。
