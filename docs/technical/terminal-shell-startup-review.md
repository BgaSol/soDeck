## 已证实的问题

隔离 Linux/OpenSSH、Bash 5.2.37 使用专门测试账号，比较 SSH shell 请求与内存环境集成后的 PTY exec。普通登录为 `profile:himBH → rc:himBH`；exec 为 `rc:hBc → profile:himBH → rc:himBH`。多出的是 sshd 通过账号 shell 执行 command 时的非交互 `.bashrc`。原方案 DR-07 关口失败，不能声称透明兼容。

原始证据：`.qa/t010/linux/shell-gate.json`；可复现入口 `tests/linux/t010/shell_gate.py`。只测试此启动差异，不代表全部 Shell 兼容测试已完成。

## 推荐补充设计：明确区分集成登录与兼容登录

- 新终端默认使用目录集成登录，完整保留 Bash 的 login shell；明确允许 exec 入口额外执行一次非交互 `.bashrc`。常规 `.bashrc` 在非交互时返回，需验证默认发行版配置；自定义启动副作用仍可能重复，不能保证透明。
- 终端设置提供“Shell 目录集成”开关，说明“用于目录自动跟随；SSH 执行入口可能额外读取非交互启动配置”。关闭后，新建/明确重连会话使用原 SSH shell 登录，目录显示不可用。开关作为明确用户偏好持久化，当前会话不热改。
- 若默认集成失败，只降级目录能力，不向现有终端追加命令；遇到回执不明不自动重放登录。其他旧方案中的无 dotfile 修改、无临时远端脚本、原生 login shell、会话/命名空间核对、无反向 cd 继续保持。
- 新增测试：默认开关、新建/重连生效、关闭开关后的标准 shell 请求、偏好重启保留、集成不热改当前会话；启动文件读取次数按已声明两种模式验证，不把副作用重复描述为已消除。补充确认后更新 F-TERM-003/DR-07 和实现方案。

另一选择是暂不采用集成登录，只完成已授权公共通信基础，目录自动跟随保留未完成；不能将基础设施交付等同联动功能交付。
