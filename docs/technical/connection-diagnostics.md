## 1. 本轮要修复的问题

用户希望连接失败时知道每一步是否成功、停在哪里，并合并链接对话中的弹窗、连续确认、表单与下拉问题。已读取当前代码及三张用户截图：

| 当前情况 | 本次处理 |
| --- | --- |
| `route_services::Attempt` 只保存 hop/stage/error；执行器 `progress` 在操作开始前调用 | 记录明确的开始、成功、等待、失败和取消结果，不能把“收到下一阶段通知”当作上一阶段成功。 |
| `route_snapshot` 只选择工作区最新 attempt，外壳又过滤与已保存修订不同的尝试 | 错误入口绑定实际 attempt；旧配置的失败仍可查看，多个终端和网络池不会互相覆盖。 |
| SOCKS `transfer` 将零字节 EOF 统一为“协商期间关闭连接” | 保留协议子阶段、读写方向、响应长度及已知错误码，显示哪一段、哪个回复没收到。 |
| 文件的命令错误和 worker message 同时渲染，截图红/黄两条同文错误 | 用同一诊断引用合并连接错误；独立的文件读取错误仍分别保留。 |
| 监控在连接已失败时仍只显示“等待已有连接” | 显示“目标连接未建立：第 N 站失败”，链接同一诊断，保持被动观察。 |
| `observability::route_stage` 将无 error 的阶段通知写为 succeeded | 修正事件语义：开始不等于成功，等待身份/凭据不记为连接失败；历史事件不倒改、不据其推断成功。 |

真实排查结果见 [T-027 结果](../tasks/T-027-results.md)。实际路径是本机 → SSH `192.168.1.104:22` → SOCKS5 `127.0.0.1:12021` → SSH `65.11.10.25:22`，没有 `.16`。原需求中的 `.16/.24` 仍是通用多跳验收例，不能冒充这次真实配置。

SoDeck 当前直接观测的是 `PROXY_DISCONNECTED / proxyNegotiate / stepIndex=1`。额外 SSH/curl 排查才确认 `.104` 的 12021 无监听；GOST 1080 要求认证且还依赖 12021，直接改成 1080 也未打通。本轮不自动改用户端口或远端服务，不把改善诊断描述为恢复了真实连接。

## 2. 用户看到什么

### 2.1 错误摘要与详情入口

连接失败后，发起操作的插件内保留一条稳定错误提示，例如：

> 第 2/3 站 SOCKS5 协商失败：192.168.1.104 上的 127.0.0.1:12021 在返回认证方式前关闭了通道。

提示提供“查看连接详情”；不自动弹模态窗口、不刷屏或自动消失。工作区底部状态也可打开详情。只有一条尝试时直接进入；多条时显示来源（终端名称/文件/监控/网络规则）、时间、状态，默认当前消费者，不能用全工作区最后一次错误覆盖所有视图。被动消费者显示“上次连接失败”及来源/时间；新尝试开始后转为连接中，不能一直挂着旧红条。

同一面板按 `(attemptId, round, phaseId, errorId)` 合并错误，不能仅按 message 去重。多个受影响面板可以各有简短入口，但引用同一记录；不同终端、网络连接池、不同业务错误不互相抹去。连接成功后错误退到历史，已打开的旧诊断保持原内容并提示有新的尝试。

### 2.2 详情结构示意

以下为文档示意，新增回复细节须由实施后的仪表记录支持，不声称旧包已经提供这些字段：

```text
连接详情                         65.11.10.25:22
终端 8 · 本次连接失败 · 时间 / 耗时
失败于第 2/3 站：SOCKS5 方法协商

✓ 1  SSH 192.168.1.104:22               由本机访问
     连接建立 / SSH 握手 / 身份核验 / 登录：已完成

× 2  SOCKS5 127.0.0.1:12021             由 192.168.1.104 访问
     ✓ SSH 转发通道已建立
     × SOCKS5 方法协商：读取方法选择回复时通道关闭
       预期 2 字节，本阶段收到 0 字节
     — 代理连接 65.11.10.25:22：未执行

— 3  SSH 65.11.10.25:22                 未执行

已知事实：尚未收到有效 SOCKS5 方法选择回复。
检查建议：检查 192.168.1.104 上的端口、代理进程及协议设置。
          127.0.0.1 指该服务器自身。

展开技术信息        复制诊断报告        编辑失败节点
```

已成功节点默认折叠，失败节点展开，后续节点显示“未执行”；不把全部节点染红。正在进行时显示阶段和已用时间，不编造进度百分比。阶段完成显示耗时；身份确认等待单列等待时间，耗时使用单调时钟，日历时间用于定位记录。

“SSH 转发通道已建立”仅证明通道打开操作成功；Windows OpenSSH 可能随后因后端连接失败关闭通道，因此不能写成“SOCKS 服务可用”。只有有效 SOCKS 回复才能证明协议阶段成功。

详情采用公共 DialogBody/DialogActions，基准宽 720px，窄窗不超可视区，正文独立滚动；短摘要、顺序节点、技术信息逐层展开。地址可换行，完整数据可复制，不靠横向滚动。首次打开定位失败项一次，刷新不抢滚动/焦点。使用 apple-design 的层次、空间对应和即时反馈，复用三主题状态色及文字/图标；减少动态即时切换、高对比实边，键盘可操作，读屏只播报状态变化。由宿主模态协调遮挡原生插件表面，不在 WebView 间叠透明浮层。

### 2.3 操作边界

- **查看/复制**均只读取记录，不触发新网络请求或远端命令。“复制诊断报告”生成易读文本：版本、时间、尝试来源、实际路线、每阶段结果、错误码、已知原因、建议和记录缺口。复制成功有反馈，失败保留内容可重试。
- 报告包含当前可见主机地址/端口，按钮附近明确这一点；省略账号、私钥路径、密码、口令、凭据 blob、信任上下文哈希、代理认证数据、终端输出和原始数据包。诊断 UI 也不展示秘密。复制只写本机剪贴板，不自动上传。
- **编辑失败节点**跳到现有连接首页定位该 SSH/代理档案；路径引用错误则定位目标路径。共享代理编辑仍展示已有依赖影响。节点已删除则提示不可编辑并提供目标路径入口；查看旧记录不从当前配置补写旧地址。
- **重试**保留在所属终端/文件/监控/网络插件现有操作中；公共详情不实现一个会重放业务的万能重试。编辑保存后提示回到原操作重试，新尝试用新配置并产生新记录。原 PTY 内容不自动重放，网络客户端数据不重发。
- 取消是“已取消”，待确认是“等待身份与登录确认”，不画成红色故障。手动关闭详情不取消连接；取消连接沿用原操作入口。缺失/过期记录明确显示“详细记录已过期”，仍保留已有安全摘要，不换成当前路线。

## 3. 核心状态和成功证据

### 3.1 一次连接的标识

保留核心生成的 `attemptId`（单次执行）和 generation，补齐 `bootId / workspaceGeneration / instanceId / operationId / purpose`。`purpose` 区分 session 与 network-data 等实际用途；由可信调用上下文产生来源。插件自己的业务 attemptId 命名为 `actionId` 或 `pluginAttemptId`，不能与核心 attemptId 混用。

每个 attempt 持有不可变 RoutePlan 引用、开始/结束时间、单调时钟耗时、状态、可选 connectionId/generation、前次引用及原因。凭据/身份确认后重新执行产生新 attempt，以 `continuationOf` 关联同一操作；用户重试/网络自动重连分别标记 `retryOf` 与触发原因。确认造成 routeRevision 更新是合法的新快照，旧 attempt 不改写。旧等待记录在继续时标记 superseded，页面显示“确认后继续至下一次尝试”，不能跨 attempt 拼接成一次全部成功。

操作在路径解析前先建立有界摘要；只有校验得到 RoutePlan 后才附不可变路线。路径缺失/非法或排队前取消时快照可为空，显示“连接准备未完成”和已知目标，节点列表不可用，不能从后来保存的路线补造历史步骤。整体状态为 running/waiting/succeeded/failed/canceled/superseded，复用是 succeeded 的独立执行方式。

同次执行内部 DNS 候选重试按 `round=1..8` 记录，沿用已有总 deadline 与重建前缀规则。新 round 从未执行状态开始；此前 round 的失败及耗时折叠保留。不能把第 1 轮前缀成功嫁接到第 2 轮失败，也不能把候选失败当作最终失败提前报警。

复用已有连接单列 `reused` 结果，带原 connectionId/generation/实际路线；不合成新的 DNS、握手、认证成功记录。有旧连接同时新建失败时，顶部分别写“已有连接仍可用 / 本次新建失败”。

### 3.2 阶段记录

内存中使用一套类型化 `AttemptRecord`，内含按 round 和执行顺序排列的 `PhaseRecord`；不另建独立跳板/代理错误表。字段为稳定 phaseId、scope（operation/node/edge）、stepId/index、from/toStepId、phase、status、开始/结束/耗时、白名单证据和可选结构化原因。

阶段状态为 `pending / running / waiting / succeeded / failed / canceled / notRun / notApplicable`。节点状态由自己的阶段归约，不用步骤下标猜测成功；连接等待挑战时未开始阶段保持 pending，失败/取消后才成为 notRun。无代理认证由协议方法结果证明 notApplicable，不能伪造一次认证成功。缓存的本地 DNS 列为“使用本次候选缓存”，远端解析仅说明由 SSH/SOCKS 端负责，不伪造远端 DNS 成功事件。

| 阶段 | 可以标为成功的边界 |
| --- | --- |
| 本机解析 / TCP 连接 | 本地解析返回有效候选 / connect 返回成功。解析失败仍定位本机→第一站。 |
| SSH 转发到下一站 | direct-tcpip 打开成功，仅标通道已建立；后续协议可独立失败。 |
| SSH 握手 | 协议握手完成且取得主机公钥；与身份信任分开。 |
| 身份核验 / 凭据选择 | 当前上下文指纹校验通过 / 凭据有效可用；待用户答复标 waiting。不能因同时取凭据失败而否认已完成的身份核验。 |
| SSH 登录 | userauth 返回成功且 authenticated() 为真；密码错只定位本站登录。 |
| SOCKS 方法选择 / 账号认证 | 完整读取并验证相应回复；方法不匹配、非法版本、提前 EOF 分开。 |
| SOCKS CONNECT 下一站 | 完整验证 CONNECT 回复且 REP=0；记录代理→下一站的边，不能误指来源 SSH。 |
| 资源接纳 / 交付 | 最终快照、取消、实例、资源预算检查通过且 lease 注册完成才标整个 attempt 成功。 |

入场排队、路径无效、预算/快照冲突、最终 lease 注册失败属于 operation 阶段，不硬塞到第 1 或最后 SSH 节点。`lib.rs` 当前先写 active 后做部分取消/租约检查，本次将成功记录移到实际交付之后；已完成网络阶段仍保留，显示“连接建立后，交付被取消/失败”。每条退出路径由 guard/finalizer 结束记录，防止长期停在 connecting。

连接建立后的断线另附 lifecycle 故障，不把最初建连成功改成失败。能定位载体边则注明该边；仅知道整体断线时显示“连接中断，具体断点未知”。PTY/SFTP/采集/业务目标失败由对应插件负责，连接详情仍显示当时的建连事实。

### 3.3 错误事实与建议

结构化原因建议包括 `code, category, phaseId, operation(read/write/connect), protocol, receivedBytes, expectedBytes, socksReply, osErrorCode, sshErrorCode` 及受控文案键；只按当前阶段适用字段生成。`receivedBytes` 是当前回复片段长度，不记录认证请求长度或字节，避免泄漏凭据长度。未知字段拒绝/丢弃，任意底层异常全文不直接写日志或渲染。

| 观测 | 展示 | 不得据此断言 |
| --- | --- | --- |
| SOCKS 方法选择读取 0 字节后 EOF | 方法选择尚未返回，通道关闭；建议检查该来源机器上的服务、端口、协议和转发 | “端口未监听”“目标密码错误” |
| 本机 socket 明确 ConnectionRefused | 对应来源→端点连接被拒绝，显示操作系统错误码 | 防火墙/进程哪个一定是根因 |
| SSH 通道返回 administratively prohibited | SSH 端拒绝转发，显示已知原因码 | 目标主机登录失败 |
| SOCKS REP 1～8 | 按协议分别显示一般失败/规则拒绝/网络不可达/主机不可达/拒绝/TTL/命令/地址类型；写明“代理返回” | 代理回复等同于已经独立检查目标机器 |
| 截短回复、非法版本/方法 | 明确子阶段和长度或受控协议字段 | 自动当作密码错并重复弹密码 |
| 超时、取消、等待确认 | 当前阶段 + 已用时/预算；取消与等待使用中性状态 | 未执行的所有节点都失败 |

建议由稳定原因码映射，为“检查建议”，与已知事实分区；无确定原因时说“原因未确定”。不自动扫描端口、执行远端命令、启动代理或修改路线。

## 4. 契约、存储和代码落点

### 4.1 公开接口与订阅

新增能力 `connections.diagnostics.v1`，提供下列只读接口；由 SDK 从单一 schema 生成类型/校验，不在插件中解析任意 error 字符串：

| 接口 | 输入与用途 |
| --- | --- |
| `connections.diagnostics.list` | workspaceId/generation、目标、可选 purpose/operation/source、cursor；有界列出摘要。被动消费者只选同目标、工作区、用途及相关操作。 |
| `connections.diagnostics.get` | bootId、attemptId、attemptGeneration；返回准确尝试摘要、快照引用、状态/失败/coverage 和记录 revision。 |
| `connections.diagnostics.phases` | 同一引用、revision、cursor；读取 round/节点/阶段页。cursor 绑定调用实例、过滤、attempt 和 revision；更新后重新读，不混页。 |
| `connections.diagnostics.v1` 状态订阅 | 复用 observeState 基础设施，只传摘要、attempt 引用和 revision；详情可见时才分页读取。读取/订阅不 acquire 连接。 |

所有连接入口错误的 `CoreError.details` 增加 `diagnosticRef`；挑战也关联该引用，但不暴露私有挑战信息。成功/复用通过公开查询按当前操作或 connectionId/generation 精确定位。宿主新增公开的“打开连接详情”工作台请求，接收引用，由当前发起视图所在窗口打开同一宿主组件；参数、工作区代次及失效视图按现有宿主边界验证。四插件不得导入外壳私有 React 组件，也不得各写一套协议诊断 UI。

采用 API/SDK 6.1.0 的增量能力。现有 `connections.route.v2` 的路径/运行资源形状不变；其中最后阶段摘要也从同一 AttemptRecord 投影，不另存一份。新诊断 UI 读取新能力，不靠旧摘要推断历史。不增加旧三模式适配；新插件声明所需能力/最低 SDK，缺能力明确拒绝加载，不静默隐藏详情。统一 SSH 确认入口和能力需求与整体方案 §3 一同发布。

状态消息保持现有 32 KiB 上限，摘要目标不超过 28 KiB；每页最多 64 项且编码后不超过 240 KiB。RPC 截断与缓存过期返回明确错误/coverage，不能返回一份看起来完整的假成功路径。高频 running 合并推送，失败/等待/取消/最终成功优先通知，状态丢通知后可重取。

### 4.2 数据库继续简单

**core.sqlite 保持 v7，不加诊断表，不迁移、不重建现有数据。** 配置还是原步骤表和凭据绑定；本轮 UI/诊断不会再要求用户重录服务器和代理。诊断属于运行状态：RoutePlan 用 Arc 共享，阶段只存结构化小记录，不复制整份配置和秘密。

在当前 App 内保留每工作区最近 10 条结束尝试、全局最多 512 条详细记录，结束记录最长 30 分钟，详细缓存总预算 16 MiB（含索引、摘要和引用账目；共享 RoutePlan 按已有快照预算计一次）。活动/待确认优先；达到预算先淘汰结束记录，再裁剪旧 round 的阶段细节并标 `coverage=partial`。最后错误/当前状态保留在活动操作的有界摘要中。诊断缓存绝不担任挑战有效性的唯一存储；淘汰记录不能使合法认证失效，也不能为保诊断阻止清理、建连或关闭。超大路径在现有路径预算内可运行，诊断预算耗尽只降级细节并显式提示。

本次内存详情不承诺重启后恢复；希望保留完整地址和阶段可复制报告。持久记录复用已存在的观测 events 表及其留存/容量/脱敏规则，不另建日志库、trace 表或无限文本日志。新增版本化 `connections.route.phase` 事件只存 attempt/round/step/phase、真实 outcome、耗时和白名单错误码，不持久保存地址、账号或自由错误全文。修正旧 `connections.route.stage` 的开始即 succeeded 写法，新产物只发新语义事件；旧历史保留且不反推成功。观测写入失败标健康/记录缺口，已有必要调用审计与 RESULT_UNKNOWN 策略不变，不为写诊断重跑业务。

2026-10-29 实施细化（原确认范围内，DIAG-04/05/09）：等待确认的记录也必须结束。操作取消、实例撤销或工作区代次失效后归为 canceled；超过挑战的五分钟有效期或网络回执过期归为 failed，并给出 HOST_CHALLENGE_EXPIRED。在现有维护循环和读取前检查，先复制待检查身份、释放诊断锁，再检查各所有者，回写时复核 revision，避免锁倒序和覆盖已继续的新状态。确认后删除挑战本身不能作为取消依据。补充取消/过期、工作区撤销、正常继续及旧记录淘汰测试；不改变认证有效性或数据库。

## 5. 四插件落实

| 插件 | 必须交付的结果 |

| 终端 | worker/session/snapshot 携带 diagnosticRef；terminal-view 错误摘要和详情入口定位此终端的尝试。认证继续只创建一个 PTY；重连保留屏幕但不重放输入。 |
| 文件 | state/命令结果/view 共用连接故障引用，消除同一原因红黄双条；连接失败与 SFTP 目录权限/容量/cwd 错误分开。被动观察跟随正确 session 用途，等待确认不报目录读取失败。 |
| 网络隧道 | Run 的 start/reconnect/网络池成员关联核心诊断，固定转发和内网代理均有详情入口；分别标到达 SSH 目标失败、监听失败、目标服务失败，保留既有有界自动重连，不新增重试策略。多成员展示成员/尝试，不借终端的成功覆盖 network-data 失败。 |
| 监控 | connection/controller/model/view 增加关联故障摘要；被动模式可解释最后失败，但不为了看详情拨号、弹认证或采样跳板。显式连接失败定位本次操作；旧样本仍按原连接代次隔离。 |

各插件清理自身重复提示；不同业务错误不得被连接去重吞掉。公共能力/组件更新必须进入四插件独立包，核对在途版本后递增。最终生成独立 Windows 开发目录包，用户原 r6 数据/运行目录保留；不包含 Git 提交、推送、安装器或发布。
