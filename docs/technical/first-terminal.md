## 1. 选定本批实现方向

以下作为同一批方案提出；用户确认后可据此实现和验证，不再先建立独立样例平台。这里的“建议采用”不表示已在 v2 实测通过。

| 层 | 本批建议 | 依据与验证要求 |
| --- | --- | --- |
| 桌面及核心 | Tauri 2 + Rust；Windows 平台窗口、托盘、秘密服务置于适配层 | 继承 v1 经验，使用普通原生多窗口；窗口移动不依赖 WebView reparent |
| 外壳及业务 UI | React 19、TypeScript、Vite；终端使用 xterm.js 6 的 fit/serialize | v1 已有输入与迁移基础；插件独立 bundle，不共享外壳 React 实例，不把终端源码编进核心 |
| 布局 | 从 v1 提取侧边工具区与窗口迁移思路，建立核心视图/双区域模型 | 暂不引入大型 IDE 布局库；不能复制 v1 的服务器/业务全局状态耦合 |
| 插件业务实例 | 每插件一个独立 QuickJS 子进程，首选 v1 已验证的 rquickjs 0.14.0 | 业务 bundle 随插件包，运行宿主随核心；App 退出回收子进程，不要求用户安装 Node |
| 插件视图 | Windows raw Wry/WebView2 子视图，来源绑定原生通道；每个可见逻辑视图独立表面 | 以 v1 现有原生适配为参考；真实终端补验焦点、IME、层叠、模态和崩溃/卡死恢复。隐藏表面仍受资源预算约束 |
| SSH | ssh2/libssh2 + 静态 OpenSSL，独立 I/O worker 驱动连接及通道 | Windows 实测 WinCNG 只满足 RSA PEM、不能满足本批 OpenSSH 私钥格式，因此改用同库 OpenSSL 后端并走内存认证；本后端不使用 v1 WinCNG 补丁。构建需要原生 Windows Perl，详情见[核心验证](../tasks/T-003-core-results.md) |
| 数据 | SQLite 存非秘密配置、布局、调用记录及插件设置；秘密使用 Windows 当前用户 DPAPI 加密文件 | 秘密经平台接口访问，普通库只存引用；DPAPI 密文位于独立数据目录，不提供 v1 导入或跨机迁移 |
| 包 | 版本化清单、UI/业务产物、文件清单哈希和 Ed25519 签名的 `.sodeck-plugin` | 私钥不入仓库；本地开发信任独立开发公钥，正式签名和在线渠道另做发布方案 |

v1 窗口迁移参考基线为 `436cad2` 的 `moves/transfer.rs`、`terminal.rs` 和 `useWorkspaceMoves.ts`，历史原生测试 11 项结果已核查，本轮未重跑。QuickJS/raw Wry 来自 v1 工作区实验，已有部分 Windows 记录；不把这些实验与已交付窗口能力混为一谈，也不把旧网络/插件权限限制移植到 v2。

移窗保持原 PTY，渲染面按快照重新挂载。流字节可直接从核心到当前插件表面，业务实例负责会话编排；所有通道固定真实来源、版本、实例及挂载代次。原生视图的位置、显隐和模态屏障由核心协调，不能覆盖核心错误/认证操作。业务实例或 UI 卡死时，核心资源和关闭入口必须可用。

如果容器不能满足输入、迁移或故障恢复要求，记录真实失败并调整实现；不能把终端塞回外壳、移窗即重连或删减测试来交付。方案内适配修复自主进行；若需改变上述运行/交互边界，先补充受影响方案。无需预先把所有候选都实现一次。

## 2. 工程和最小契约

按技术总览的单仓库边界建立 `apps/desktop`、核心/插件管理/宿主 crates、协议/SDK/UI 公共 packages 与 `plugins/terminal`。只建立实际用到的模块，不建 Docker/NetBird 空工程。使用 npm workspaces、Cargo workspace 和锁文件；具体 patch 版本在首次骨架落地时记录并锁定，不以 v1 的松散版本范围冒称 v2 已锁定。

SDK v1 的请求采用 `apiVersion/requestId/method/params/timeoutMs`，响应为相同 requestId 加 `result` 或结构化 `error`；error 包含稳定 code、脱敏 message、可选 operationId 与执行阶段。来源字段由宿主绑定；资源句柄包含本次 App/实例与资源代次校验。逻辑字段遵循 F-CORE-001，序列化类型以同一协议定义生成或校验两端。

插件清单必须含 pluginId、version、core/API 兼容范围、真实能力依赖、worker/UI 入口、视图声明和 dataSchemaVersion；校验默认位置属于支持位置。无权限声明。启动依次执行 prepare、本地迁移、activate/ready；stop 先停止接受新业务再释放普通资源。初始化阶段不打开远端会话。

本批实现 F-CORE-005 的接口，加能力查询、操作查询/取消、快照/事件/有界流、资源查询/停止、工作台打开/移动/关闭/布局、剪贴板与插件设置读写、调用记录查询。每个接口的请求、状态、错误和记录摘要在其协议定义前与所属规格对齐；不添加任意命令转发器。工作台 API 和主题协议保持独立版本。

移动操作使用 operationId、预期布局修订、viewId 与目标容器。prepare 时登记源绑定并冻结新输入；目标恢复完成后提交唯一新代次，响应丢失可查询结果。帧携带 streamId/generation/sequence，确认游标后续接；快照只传输展示状态，真实句柄从核心注册表重绑定。

## 3. 初始预算与故障策略

下表是本批验收基线，不是未来产品的最大规模承诺。需在测试前记录设备 CPU/内存、Windows/WebView2 及工具链版本；调整数值需先更新依据和测试目标。

| 项目 | 本批值与处理 |
| --- | --- |
| 同时运行 | 验证 2 个服务器工作区、共 4 个 PTY，最多 2 个独立窗口；达到暂定 8 个 PTY/8 个终端视图上限返回明确容量结果，不按插件身份分配不同权限 |
| 后台运行时 | 128 MiB JS 堆、1 MiB JS 栈、4 MiB 工作线程栈；连续 JS/job 执行 5 秒上限。等待异步 SSH 不占这段执行期限 |
| 请求与输出 | 控制帧最多 1 MiB；原始输出块最多 32 KiB，编码后仍受帧限额约束；每 PTY 待传输出最多 2 MiB，全局最多 16 MiB；达到上限停止上游读取并使用 SSH 窗口背压，取消/关闭独立调度 |
| 输入与滚屏 | 单次输入最多 64 KiB，大粘贴按序分块等待受理；每 PTY 待写最多 256 KiB，满时显式反馈，不静默丢输入；每终端最多 5000 行滚屏 |
| 建连与交互 | 网络连接 15 秒、协议握手/认证执行各 30 秒；用户认证交互单独最多等待 120 秒且可取消，不算网络无响应；首批不自动重连 |
| 迁移 | 快照最多 4 MiB，迁移 10 秒；超限或未提交超时回源。迁移输出使用有界流额度，不能丢字节后声称连续；正常负载必须无缺口 |
| 去重/订阅 | 每实例追踪请求 10 分钟且最多 10000 项，活跃项不被驱逐；满时拒绝新操作。完成项淘汰后不承诺重复安全，SDK 不自动重发输入。状态事件最多保留 1000 条，游标过期改取快照 |
| 退出 | 普通资源清理目标 5 秒，10 秒后由核心结束残留插件子进程并释放本机持有资源；未能确认的远端进程/操作明确记录，不能误写为已停止 |

负载验证：4 个 PTY 各产生 256 KiB/s 带序号数据，持续 60 秒；同时另一输入标记的往返 P95 ≤ 500 ms，核心状态查询/停止请求响应 P95 ≤ 500 ms（专用本机或同网段测试服务，记录网络 RTT）。将消费者暂停 10 秒后恢复，协议队列峰值不得超预算，无静默乱序或丢字节。进程内存同时采样，记录峰值及恢复；不能用队列计数冒称整个 WebView 内存已受同一限制。20 次创建/关闭循环后本机连接、PTY、订阅及业务子进程回到相应基线，泄漏视为失败。

## 4. 记录及存储失败

调用记录采用独立 SQLite 表/库、WAL 与同步提交：外部调用先提交开始记录，再执行；响应前写入执行结果或 operationId，异步终态另追加。实际持久化能力按 SQLite/操作系统保证说明，不承诺断电后任意硬件都无损。输入/输出只记长度、序号、标识和结果，不存正文。

记录保留最近 7 天或最多 256 MiB，先达到者触发清理最旧已完成记录；未完成项先保留并进行启动核对。总预算含 WAL，受控 checkpoint；若活跃记录或存储故障使容量无法维持则进入记录故障状态，不无限增长。分页最多 100 项，核心提供按来源/方法/服务器/结果筛选的最小查看入口及可见保留区间。

开始记录无法提交时不执行新的普通业务调用，向所有来源一致返回记录服务不可用。错误摘要进入最多 1024 条的内存故障队列，满后显示丢失计数；界面明确当前无法持久留痕，不声称每次调用已保存。已执行但结果写入失败时保留未决操作 ID 并报告结果待核对，不返回可诱使盲目重试的“未执行”。恢复后补写可确认事实。

停止资源、关闭窗口和退出必须仍能执行，不能被磁盘故障困住；这些清理调用尽力写入内存故障队列并显示持久化缺口。重启把未完成记录标为中断待核对，不自动补成功或重放。磁盘满、队列满及进程中断都要验证，这些是统一故障策略，不是插件权限控制。

## 5. 本批独立更新及测试

核心开发包附带一个独立构建并验证的终端包。核心的最小插件页显示运行版本、已准备版本、兼容/失败信息，提供“从本地包准备更新”，完成后显示“重启后生效”；本批不建立在线市场、自动下载或正式发布渠道。

本批以实际终端 `0.1.0 → 0.1.1` 验证。前一版提供可用 SSH 终端及字号增减，后一版增加“恢复默认字号”入口和插件业务处理，通过已有设置接口持久化结果；更新引入真实 UI/业务行为，不能只换版本字符串，也不能在核心内预埋两版终端代码。保留实际前一版本构建产物作为更新输入，不创建第二个测试插件。

包限制：压缩包 32 MiB、展开 128 MiB、文件数 2000；拒绝越界路径、符号链接及清单不匹配。本地开发包用专用开发签名密钥，公钥属于开发信任域，不能当正式发布凭据。格式、兼容、签名或空间失败都保留当前版本。

每个 pluginId/version 目录不可变；准备写暂存目录，验证后记录 pending，不改变本次 active。启动持有数据写锁，先写恢复日志，再对插件数据副本执行迁移和本地初始化；成功后提交包含版本和数据代次的单一激活记录。提交前失败恢复上次包和数据，提交后按日志完成同一代次；正常运行后不得以旧快照覆盖新数据。一个插件失败可禁用它进入核心恢复界面，不循环重启 App。更新重启会结束旧 PTY。

首批数据 schema 均为 1，设置兼容即可；用故障注入验证迁移失败和中断，不为了测试虚构用户数据功能。验收项 UP-AC-01：核心不变且运行固定版本；UP-AC-02：重启切换并可恢复；UP-AC-03：包及数据失败不损坏当前可用状态。

准备：Windows 原生 App、独立数据目录、两份实际终端版本和本地开发密钥；记录核心二进制与外壳资源哈希。变造包与迁移/初始化故障仅存在测试目录，生产包不保留故障开关。

| 用例 | 步骤 | 预期 |
| --- | --- | --- |
| UPD-01 | 单独构建两版终端，不重构建核心；在旧版真实会话运行时准备新版 | 核心哈希不变，旧会话/旧 UI/旧业务继续，pending 可见；UP-AC-01 |
| UPD-02 | 正常退出并重启，核查版本，连接真实 SSH并使用新增“恢复默认字号”，再次启动 | 仅新包 UI/业务生效，设置持久；原 PTY 已结束，不假称恢复；UP-AC-01、02 |
| UPD-03 | 提交错签名、改文件、越界/超量、不兼容包，并注入暂存空间不足 | 拒绝原因准确，active 和真实会话不变，无越界写入；UP-AC-03 |
| UPD-04 | 新版初始化失败、迁移副本失败；分别在恢复日志/数据副本/激活提交前后中断进程再启动 | 恢复到一致的包与数据代次，能使用旧版或核心恢复界面，不循环启动、不覆盖运行后数据；UP-AC-02、03 |
| UPD-05 | 临时移除终端包或令视图 schema 不兼容，再启动；恢复正确包后重试 | 核心服务器/资源/记录页仍可用，占位及恢复原因可见；不自动新建 SSH；UP-AC-02、03 |

清理：退出 App、确认旧新实例均结束，恢复包与数据副本，移除故障注入和本地测试私钥，保存脱敏哈希、版本与恢复结果。已执行及待验证子场景见[T-003 插件结果](../tasks/T-003-plugin-results.md)，不能将仅一个实际插件的更新解释为跨插件互不影响已验收。

## 6. 开发与测试入口

根命令已建立：`npm run desktop` 启动 Windows 开发 App；`npm run check` 执行类型/依赖边界检查；`npm run test:core` 测 Rust 工作区；`npm run test:contracts` 测协议；`npm run test:terminal:native` 验 SSH 协议/原生窗口；`npm run test:updates:native` 验真实终端更新；`npm run plugin:pack -- --plugin terminal` 独立打包。构建前置、Python 测试依赖、隔离目录及覆盖限制见[开发入口](../development-entry.md)。

身份 A/B、错误状态、存储及网络故障用测试宿主/提供者夹具构造，位于测试工程，不注册成产品插件。SSH、输入法、原生拖动、窗口生命周期及更新必须走实际边界；缺测试设备或服务时标记未运行，不能替换为 Mock 通过。
