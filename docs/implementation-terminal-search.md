# 终端历史搜索与常驻预览实施记录

2026-11-10。第一版源码已实现，正在准备核心 0.22.1 和终端 0.8.0 的独立发行。Windows x86_64 本机检查通过；本次五平台原生包验收仍待完成。行为与正式性能目标见[设计方案](plan-terminal-search.md)。本记录只描述本轮实际验证。

## 实现与核心边界

终端默认保留 100,000 行滚动历史，当前屏幕另计。浮动条支持普通子串、大小写、计数、循环前后定位、Unicode 和软换行；搜索高亮独立于正文选择。右侧 96 px 彩色预览常驻，窄窗口缩为 40 px，支持点击、拖动和键盘浏览。退出、断线页仍可搜索。

搜索不会发出 PTY 输入、读取远端 shell history、跨终端查询或保存关闭后的档案。具体操作维护在[使用说明](usage.md#终端历史搜索源码已实现尚未发布)。

| 位置 | 实际职责 |
| --- | --- |
| `plugins/terminal/ui-src/history.js` | 解析后抽取屏幕行、观察环形淘汰与结构变化；每片约 2 ms、每条消息最多约 48 KiB，一次只等待一个 Worker ACK，合并其后的脏区域 |
| `history-worker.js` | 子串扫描、软换行后缀、Unicode 位置映射、每行命中数量、256 行扫描状态检查点、64 行颜色块；约 4 ms 让出任务，过期 epoch/revision 不生效 |
| `search.js` / `minimap.js` | 浮动条、可见范围的有限分批高亮、计数与有效锚点、独立 UI 保存、预览绘制和手势；隐藏页面停止绘制 |
| `snapshot.js` / `view.js` | 固定版本冻结快照、回收行写时复制、分片序列化、16 KiB 上传、原子水位；快照不阻塞输出 ACK 链 |
| 核心 `streams.rs` / `streams/journal.rs` | 原始字节日志、不可变共享检查点、小 UI 元数据、恢复与额度；不解释搜索文字、颜色或查询结果 |
| 核心 `terminal.rs` | PTY 与真实 Surface 校验、生命周期、自然退出后保留输出至用户关闭 |

没有新增生产依赖。发行版本为核心 0.22.1 和终端 0.8.0。新终端初始化要求核心能力 `terminal.history.v1`；缺失时提示升级，API 主版本保持 1。协议维护在[插件 API](plugin-api.md#终端大历史恢复增量能力尚未发布)。

## 大历史恢复的实际约束

- 正常 ACK 只表示 xterm 已解析输出，释放实时队列不再等待全量显示快照。原始输出另写入每流 128 MiB 临时日志，文件按 1 MiB 分段。
- 已提交显示快照最多 128 MiB，保存为核心内存中的不可变共享字节。移窗读者只持有读取所需的引用，读完释放，不复制整个快照。
- 日志文件与所有在途/已提交快照分配共用 1 GiB 全局额度，旧快照和新上传同时计入。不是每个终端都能并行用满自己的上限。
- 快照正常约每 10 秒尝试一次，flush 等待必要快照和输入同步。快照固定其开始时的输出水位，后续输出继续运行；尺寸变化等到快照结束后合并。
- 日志只有在提交快照覆盖该字节、且没有旧读者需要它时才清理。上传中断不替换已提交版本，detach 释放在途上传。
- 写盘或额度失败以 recovery 帧通知活动页面；实时输出继续，慢读者依赖有界 ACK 背压。失败字节区间必须由新快照覆盖才能恢复。重新挂载遇到真实缺口会失败，不能重跑命令补历史。
- 关闭当前流清理其目录；启动只清理命名可识别、所属进程已退出的目录，保留运行中实例和其他目录。Unix 临时目录/文件为 0700/0600。

查询、有效的当前命中、阅读位置、底部跟随与正文选择独立保存为最多 8 KiB 的 UI 元数据，不推进检查点水位。同一行多处命中按文字偏移恢复；结构重建只有在实际文字仍匹配时保留锚点。

## 固定版本适配与修正

公开 xterm API 不能准确报告满滚动历史后的环形淘汰。行观察与冻结快照分别封装内部结构读取，资源构建强制检查 xterm **6.0.0**、SerializeAddon **0.14.0**。升级依赖前必须跑历史专项。

冻结缓冲复制活动屏幕和样式，历史行仅在环形回收前按需复制。正式 addon 在冻结门面上序列化，不修改真实终端或已加载的 addon。每段约 64 行并重叠一行，使用 ECH 清理重叠行，保持软换行标记。

补充样式/空单元格用例时发现：最后一片只覆盖部分屏幕会触发 addon 的无历史路径，省略尾部空行并偏移光标。末片改为包含整个屏幕和一行历史，再与完整官方序列化逐行对照。另修正恢复时空索引回包和随后尺寸/结构重建清掉当前命中的问题；对应回归覆盖同一行第 2/3 处恢复。

颜色摘要以 32 个水平格采样，同色区段压缩，保留 ANSI16/256、true color、反色、背景与加粗亮色。大量普通文字不需要每行永久保留一个 128 字节颜色数组。

### 阅读框透明修正

深色主题可稳定复现阅读框覆盖缩略内容：原样式引用不透明的 `accent-bg`，计算背景为 `rgb(53, 48, 71)`。改为完全透明的阅读框，使用主题滚动条细轮廓和左侧窄标记；悬停增强轮廓，拖动与键盘聚焦使用主题强调色。拖出轨道仍显示抓取状态，松手、取消或丢失捕获后清理；焦点轮廓内收，避免在历史底部被裁切。

本次 `npm run check`、106 项 `npm run scripts:test`、终端独立 UI 构建、实际 xterm 输入回归与搜索 UI 回归通过。新增回归先复现旧背景，再覆盖三主题透明性、悬停/拖动透明性、轨道外释放和内收焦点；三主题及窄窗口截图已核对，设计检测无发现。未执行五平台原生包验收或发布。

### 搜索条按钮对齐修正

旧输入框为 30 px 高，按钮为 28 px；按钮的 2 px 透明边框加 5 px 内边距只留下 14 px 内容空间，却放入 17 px 图标，造成图标偏移。统一为 32 px 高的输入框与方形按钮，按钮去掉内边距并居中承载 16 px 图标；箭头路径也在图标画布内居中。计数与控件共用中线，第二行说明使用明确行高和间距，输入边框跟随主题。240 px 窗口中输入单独占一行，按钮均匀排列。

本次 `npm run check`、106 项脚本回归、终端 UI 构建、真实 xterm 输入与搜索回归通过；新增回归先复现高度不一致，再检查三主题控件尺寸、图标中心、计数对齐、无匹配状态，以及 320/240 px 窗口的对齐和边界。截图已核对，未执行五平台原生包验收或发布。

## 本机性能证据

硬件：Intel Core Ultra 5 250K Plus，Windows x86_64；Node v24.22.0，Playwright Chromium 158.0.8127.18。报告保存在本机 `artifacts/terminal-history/`，均由测试脚本重生成。不同宿主、系统 WebView 与并行负载需重新测量。

`search.json`：10 万行、11,360,000 UTF-8 文本字节，按 120 列预算生成，100 个不同关键词；直接使用正式扫描器测完整计数，包含协作式让出任务，不含 UI 合并、终端网格或真实 Worker 传输。颜色摘要包含普通色和稀疏强调色。

| 查询类别 | 本次 P95 |
| --- | --- |
| 稀疏命中 | 134.1 ms |
| 无命中 | 116.7 ms |
| 密集重复子串 | 136.2 ms |
| 单字符 | 137.1 ms |

行补丁/颜色块初建约 36.2 ms。GC 后新增 JS 堆约 62.2 MB、外部 ArrayBuffer 约 0.2 MB，合计约 **59.5 MiB**。这是扫描器及文本/摘要样本的附加内存，不是整个终端、Worker 进程、核心或移窗峰值。

`ui-search.json`：102 列、100,031 个保留屏幕行，主要是短 heartbeat 行，100 个不同查询。输入事件到最终计数/有效当前序号，包括约 60 ms 合并与真实 Worker 消息：稀疏/无命中/常见片段/单字符 P95 分别约 **96.8 / 95.7 / 100.9 / 101.1 ms**。没有逐帧测量高亮完成、键盘输入响应或原生 WebView；短行结果不能代替更长文本负载。

`serialization.json`：120 列、100,024 保留行，中文/emoji/颜色/软换行约 7.94 MB 官方序列化内容。同步完整序列化约 328 ms；分片冻结快照约 549 ms，单次 iterator.next 等待最大约 17.2 ms，过程中另写入 159,200 行。恢复后的文字、颜色模式、宽度、样式、软换行、光标与官方完整序列化一致；小样本同时覆盖备用屏幕、终端模式与彩色空单元格。

上述数字支持第一版直接扫描的选择；没有启用 Bloom 过滤、通用倒排索引或额外搜索 addon。不是所有查询都能常数时间完成，也未据此宣布所有设计目标通过。

## 未完成验收与已知边界

五个正式系统架构组合的原生包、基本实际 PTY/显示、原生移窗、重开与退出已完成，来源与独立发行记录见[终端 CHANGELOG](../plugins/terminal/CHANGELOG.md)和[核心 0.22.1](releases/v0.22.1.md)。深度搜索与 Worker/CSP 的原生专项、系统 IME、字体/DPI 和多屏尚未执行；基本包验收不能替代这些专项。

240/1000 列、巨型逻辑行、逐字 true color、1/5 MiB/s 组合负载、四终端并行、主线程长任务、完整进程内存与移窗峰值，以及输入/导航/绘制延迟需要专项测量。当前没有提前返回部分计数、独立的附近优先命中或循环/淘汰提示；查询最多 1024 个 UTF-16 单元。超宽和并行终端可能消耗大量 xterm 网格与恢复资源。

xterm 的当前光标行在缩窄时可能保留或裁剪而不完整重排；搜索必须跟随实际仍显示的文字。重排后的原结果只有实际文字坐标仍有效才保留，否则从阅读位置重新定位。不能把源终端已裁剪的文字继续计为命中。

核心 0.22.1 和终端 0.8.0 已按[分发流程](distribution.md)独立发行；本轮检查、原始打包 run、正式 Release 与实际验证/跳过范围维护在上述发行记录中。
