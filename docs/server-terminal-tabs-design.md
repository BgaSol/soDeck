# 服务器标签与终端标签分层设计

状态：功能设计草案，2026-10-22。本文描述建议行为，尚未实施。

## 1. 需求理解

顶端标签代表服务器工作区，每台服务器只有一个；同一服务器打开多个终端时，在该工作区的终端区域新增二级标签。

例如，在“生产应用”上分别运行部署、日志查看和日常命令，应当看到一个“生产应用”顶端标签，以及其中三个独立终端。顶端标签数量由打开的服务器数量决定。

当前实现中，`WorkspaceTab` 同时承载服务器和单个会话，“新建连接到此服务器”会生成“生产应用 · 2”等顶端标签。`SessionWorkspace` 的文件、监控、Docker 和 NetBird 都依赖该终端的 `sessionId`。本次设计需要同时调整导航层级和工作区归属。

## 2. 信息结构与布局

```text
顶端：[服务器] [生产应用 ×] [测试环境 ×] [＋]

生产应用工作区
├─ 远程文件                  ← 服务器级，共享
├─ 终端区域
│  ├─ [终端 1 ×] [部署 ×] [日志 ×] [＋]
│  ├─ 当前终端工具：历史、复制、粘贴、清理显示、断开/重连
│  └─ 当前终端内容与连接状态
└─ 监控 / Docker / NetBird   ← 服务器级，共享
```

- 保留现有文件、中央终端、右侧服务面板和工具栏布局；二级标签只占中央终端区域的宽度。
- 顶端保留固定“服务器”首页入口。顶端“＋”进入服务器选择；终端区域“＋”为当前服务器新建终端，分别提示“打开服务器”和“新建终端”。
- 二级标签替代中央区域重复展示服务器名称的大标题位置，尽量控制在现有工具栏高度附近，避免连续堆叠多行导航。
- 服务器名称及登录地址放在顶端标签提示与连接详情中；当前终端的连接状态和断开/重连留在终端区域，端口转发入口归服务器级工具。
- 单个终端时也显示二级标签和“＋”，确保入口稳定。顶端不使用“服务器名 · 2”表达终端数量。
- 标签过多时，各层独立横向滚动并提供“全部服务器 / 全部终端”列表；激活项自动进入可见范围。关闭按钮不嵌套在切换按钮内。
- 窄窗口继续沿用现有侧栏收起规则，优先保留终端标签、添加按钮和当前状态；低频终端工具进入更多菜单。

## 3. 什么算同一台服务器

建议以已保存配置的 `server.id` 为唯一标识。相同地址但不同账号、跳板或独立配置，不自动合并；复制配置产生新的 ID，可以有自己的顶端标签。

建议唯一性覆盖当前应用实例的主窗口与独立窗口：一个 `server.id` 只有一个服务器工作区及一个所属窗口。服务器已经在独立窗口打开时，再次打开应激活那个窗口。该范围是本方案的推荐约定。

名称、标签等展示字段更新时同步更新顶端标签。连接参数更新不强制替换现有会话；之后新建或重连采用最新配置，现有终端仍能在连接详情中查看实际连接信息。

## 4. 打开与新建

| 用户操作 | 建议行为 |
| --- | --- |
| 首次打开服务器 | 创建唯一服务器工作区，并创建“终端 1”；沿用首页的连接进度与认证流程，成功后进入工作区 |
| 再次打开已有服务器 | 激活已有工作区，恢复上次选中的终端，不新增标签、不隐式重连 |
| 重复打开正在连接的服务器 | 显示同一连接进度，不创建第二个工作区或终端 |
| 点击终端区域“＋” | 在当前服务器下创建新终端并选中，使用独立 shell 和终端状态 |
| 从首页或顶端右键选择“新建终端” | 定位已有服务器工作区并新增二级终端；尚未打开时创建工作区和首个终端 |
| 切换服务器后再切回来 | 恢复该服务器最后激活的终端、终端滚动位置及共享面板状态 |
| 打开一个没有终端的服务器工作区 | 展示终端空态和“新建终端”；不自动补建已被用户关闭的终端 |

首页主按钮：未打开时为“连接”，已打开时为“进入工作区”，处于独立窗口时为“切换到窗口”。状态分别展示工作区是否打开和“终端 N 个 · 已连接 M 个”，不再用顶端标签数表示会话数。

新终端从账号默认登录目录启动；首期不自动执行 `cd`、复制命令或恢复上一终端进程。默认名称按该工作区的递增编号命名，如“终端 1、终端 2”，关闭不重排编号。支持双击或菜单重命名，例如“部署”“日志”；重命名只改变标签展示。

首次连接失败保留同一个工作区和失败终端，首页可继续显示错误并提供重试/进入工作区。重试复用原标签。取消认证结束对应连接尝试，保留可重试终端，不影响其他终端。晚到的连接成功或失败事件不抢走用户已经切换后的焦点。

## 5. 状态归属与切换规则

| 归属 | 保留的内容 |
| --- | --- |
| 每个服务器工作区 | 二级标签及顺序、最近激活终端、文件浏览位置与选择、服务面板状态、面板宽度、监控订阅 |
| 每个终端 | 独立连接与 shell、名称、工作目录、输出、滚动位置、输入状态、历史/实时视图、错误及重连状态 |

切换标签仅改变显示和输入焦点。后台终端继续接收输出、记录历史、维持会话；正在运行的命令继续执行。只有可见且激活的终端接收键盘输入，恢复显示时重新适配尺寸。隐藏页可减少绘制，但不能停止输出接收或丢失历史。

文件面板默认保持当前浏览位置，不随终端切换跳转；其“终端目录”标记与“定位到终端目录”操作使用当前激活终端。未获得当前终端目录时禁用定位，不能误用另一终端的目录。首期沿用显式定位，不增加自动跟随设置。

监控、Docker、NetBird 和文件访问使用服务器工作区拥有的服务连接上下文。它不依附于某个可关闭的终端，关闭“终端 1”或切到“终端 2”不会重建这些面板，也不会中断它们的操作。底层可复用连接资源，但各终端 shell 与状态仍独立。

顶端标签反映工作区汇总状态，终端标签反映单个终端状态：

- 终端状态包括连接中、等待验证、已连接、等待重连、已断开和连接失败；标签用状态标记，具体状态通过可访问名称、提示和当前工具栏说明。
- 工作区内存在需要处理的认证或失败时，顶端显示需要关注的提示及摘要，如“1 个终端连接失败”；不能把某个终端失败显示为整台服务器离线。
- 服务器工具连接可用但所有终端已关闭时，显示“工具已连接 · 无终端”。汇总提示区分工具连接和终端连接。
- 高频日志输出不持续闪烁顶端标签；后台失败或待认证才升级为服务器级提示。

## 6. 关闭、断开与重连

| 操作 | 影响范围及结果 |
| --- | --- |
| 终端内“断开” | 只断开当前终端，保留标签和已有输出，允许重连 |
| 终端内“重新连接” | 在原二级标签内建立新会话，保留标签名称；历史标明新会话边界，不声称恢复原进程 |
| 关闭二级终端标签 | 结束该终端并移除标签；其他终端和服务器工具继续运行 |
| 关闭最后一个终端 | 保留服务器顶端标签和共享面板，中央显示“尚无终端”和“新建终端” |
| 关闭顶端服务器标签 | 关闭该工作区及全部终端，释放工作区拥有的服务连接；不删除服务器配置或历史记录 |
| 顶端全部服务器均关闭 | 回到固定服务器首页 |

关闭活动终端后优先激活最近访问的剩余终端；没有访问记录时选择相邻终端。关闭后台终端不改变活动项。服务器层采用同样的选择规则。

关闭已断开的终端无需连接确认。关闭仍连接的终端显示“关闭‘部署’终端？SSH 会话将结束，终端内任务可能中断”，按钮为“取消 / 关闭终端”。不依赖不可靠的命令识别判断是否存在工作，也不承诺结束所有远端后台进程。

关闭服务器时合并为一次确认：“关闭‘生产应用’？将关闭 3 个终端，其中 2 个仍连接。”不逐个弹窗。确认前检查依赖工作区连接的操作；有这类操作时说明具体影响并提供“返回工作区”，首期阻止关闭直到其结束或用户在对应任务中明确取消。独立传输、端口转发、编辑器与日志窗口按各自所有权继续存在；如果资源实际仍由它们使用，必须延迟释放，不能因为顶端标签关闭而误中断。退出整个应用仍沿用应用退出流程。

首期保留终端级断开/重连，不额外增加含义模糊的“断开服务器”快捷按钮；关闭工作区统一走顶端关闭入口。

网络故障影响多个终端时，各终端保留输出并按既有策略重连；服务器层汇总提示，重连请求排队/退避，避免多个认证弹窗互相覆盖。认证提示明确标注服务器和终端，取消只作用于对应连接。恢复网络不自动重跑终端中的命令。

## 7. 菜单、键盘与独立窗口

- 顶端服务器菜单：新建终端、移到独立窗口 / 移回主窗口、向左 / 向右移动、关闭服务器工作区。
- 二级终端菜单：新建终端、重命名、断开 / 重连、向左 / 向右移动、关闭终端。历史、复制、粘贴和清屏继续使用现有终端工具。
- 两层分别支持拖动排序；终端只能在所属服务器内排序，不能拖到另一服务器改变归属。
- 独立窗口迁移以整个服务器工作区为单位，全部终端、活动项和共享面板一起移动；首期不提供单终端拆窗。
- 迁移期间冻结该工作区的新增、关闭和第二次迁移。完整接收成功后再移除原工作区；失败回滚，不丢失已有会话。认证未完成时沿用现有限制，完成或取消后才能迁移。
- 键盘聚焦某层标签栏后，方向键 / Home / End 只在该层切换，Delete 只关闭该层当前项并执行相同关闭规则。保留现有可访问标签与焦点恢复机制。
- 首期不新增可能被 shell、编辑器或现有剪贴板占用的全局组合键；终端输入区域中的键盘事件不误触顶端关闭。

## 8. 首期范围与实现约束

首期包括服务器唯一工作区、终端二级标签、新建/重命名/排序/切换/关闭、终端独立连接与历史、共享面板解耦、首页入口调整、异常状态汇总及整个工作区迁移。终端分屏、广播输入、单终端拆窗、跨重启恢复远端进程和自动恢复所有连接不纳入本期。

当前运行期间保留标签名称、顺序及状态；重启后沿用现有启动进入服务器首页的方式，不新增自动连接。终端历史继续使用已有持久化能力。

建议实现分为以下边界，后续代码设计再展开接口：

1. 服务器工作区管理：按 `server.id` 管理唯一工作区，统一处理普通打开、新建终端和跨窗口请求；并发重复请求也不能创建重复顶端标签。
2. 终端管理：每个终端有稳定 ID，独立保存连接、历史和控制器；原来按工作区区分终端事件的位置必须改为终端身份，避免输入、输出或认证串到其他终端。
3. 共享工具连接：从 `SessionWorkspace` 单一终端的 `sessionId` 中解耦文件和服务提供者；明确服务连接与独立任务的资源所有权，是本功能成立的必要条件。
4. 工作区迁移：快照从一个终端扩展为终端集合，服务上下文独立迁移；全局工作区登记保证跨窗口唯一性和完整回滚。
5. UI 组件：顶端 `WorkspaceTabs` 展示服务器；新增 `TerminalTabs`；现有 `TerminalWorkspace` 继续承担单终端实时/历史视图。

## 9. 验收场景

1. 对同一配置连续创建五个终端，顶端始终一个服务器标签，内部有五个独立终端；首次连接中重复打开也成立。
2. 打开 A、B 两个服务器，在各自内部新增终端，顶端始终只有 A、B 两个工作区。
3. A 的部署终端执行任务，切到日志终端、B 或服务器首页，再返回时任务持续、输出与滚动位置正确、输入焦点不串页。
4. 终端 A/B 位于不同目录，切换不改变文件浏览位置；显式定位只使用当前终端目录。工具面板不会被切换重置。
5. 关闭普通、首个、后台和最后一个终端，影响范围均正确；关闭最后一个后文件和服务仍可用。
6. 关闭服务器显示一次准确的汇总确认；取消保留全部内容；相关操作未结束时不意外中断。关闭其他服务器不受影响。
7. 单终端连接失败、取消认证或断开不影响其他终端。网络整体中断时认证有序、各终端可重试、不产生重复顶端标签。
8. 已在独立窗口打开的服务器再次被打开时激活原窗口；整体移动保留每个终端，迁移失败后原窗口继续可用。
9. 不同 `server.id` 即使名称/地址相同也保持独立；修改显示名称不会重复创建工作区，复制配置可独立打开。
10. 深浅主题、长名称、大量标签、最小窗口及 Windows 125%/150% 缩放下，两层标签含义明确、关闭目标明确、没有重叠；全局历史仍能区分各终端记录。
