# 文件管理：本地导入与双向传输

状态：功能梳理提案，2026-11-06。本文记录目标行为，不表示下列新增功能已经实现。

对应代码分层、API、实施批次及验证安排见 [文件管理编码方案](plan-file-management-coding.md)。

## 用户意图

让 SoDeck 的远程文件操作符合系统文件管理器的习惯：本地文件或文件夹可以从系统复制后在远程目录粘贴上传，也可以拖入远程目录；远程文件或文件夹通过“下载”选择本地保存位置。上传、下载按钮继续保留，不同入口使用同一套传输、冲突处理和任务反馈规则。

2026-11-06 范围收窄：用户明确去掉“远程复制后在系统粘贴”和“远程拖到系统目录”，两项不做实现，不作为本轮待办或验收缺口。双向传输仍指上传和下载；系统文件剪贴板及原生跨应用拖拽仅用于本地向远程导入。SoDeck 内同一服务器的复制、粘贴和移动不受这次删减影响。

以下多选、同名处理、传输队列、远程目录内管理和异常恢复是为完成这些流程补充的建议范围；跨服务器复制等扩展单独列在后文。

## 一、保留的四种传输入口

| 用户操作 | 目标行为 | 文件 / 文件夹 / 多选 |
| --- | --- | --- |
| 系统文件管理器中复制，在 SoDeck 远程目录粘贴 | 上传到确定的远程目录 | 全部支持，可混合选择 |
| 系统文件管理器拖入 SoDeck | 上传到落点对应的远程目录 | 全部支持，可混合选择 |
| 点击上传，或右键选择上传文件 / 上传文件夹 | 用系统选择器选源，上传到指定远程目录 | 全部支持；平台选择器可分文件、文件夹入口 |
| 右键下载，或点击下载 | 单文件选保存位置；文件夹或多选选本地目标目录 | 全部支持，直接保留目录结构 |

本地复制和拖入来源包括 Windows 资源管理器、macOS Finder、Linux 正式支持桌面环境的系统文件管理器。操作应同时适用于主窗口与移出的服务器窗口。

### 剪贴板规则

- 远程条目的“复制”用于 SoDeck 内同一服务器的复制粘贴，不向系统提供可下载的文件对象；“复制完整路径”提供可粘贴到文本框的路径，两者使用不同菜单项。
- 文件列表获得焦点时，Windows/Linux 使用 Ctrl+C/V，macOS 使用 Cmd+C/V；右键提供同等操作。路径输入框、重命名输入框和文本编辑器继续按文本处理快捷键。
- 本地粘贴上传读取系统中的本地文件列表或本地文件 URL。剪贴板中的普通文字、路径字符串、图片或网页内容不自动当作上传源。
- 文件复制记录固定原服务器、源条目及相应上下文。切换服务器、隐藏侧栏或移窗后仍指向原来源，粘贴时以当前明确的目录作为目标，不能把来源重新解释成当前服务器。
- 源会话失效、源文件被移除或变化时，说明实际原因并允许重新选择或重试，不把旧操作自动接到新会话。剪贴板被其他程序替换后，按新的系统内容处理。
- 远程复制到同一服务器的其他目录使用远程复制流程。远程取回本地使用“下载”，不通过系统粘贴触发；跨服务器目标按后续扩展处理，不误操作为同机复制。

### 拖拽规则

- 拖过目录时高亮该目录；悬停可展开目录，列表边缘可自动滚动。拖过空白处时清楚标出当前目标目录；普通文件行不作为目录落点。
- 拖动反馈显示本地拖入上传或同一服务器内复制、移动的意图和目标。无效落点、断线或不可用来源显示不可放置；离开或按 Escape 取消不产生任务。
- 本地拖入按复制上传处理，源文件保留。即使系统源条目来自剪切操作，也不能在复制后擅自删除源。
- 同一服务器内拖到其他目录默认移动，并通过该平台的复制修饰键切换为复制；按下和松开修饰键时更新反馈。
- 区分单击选择、框选或范围选择与拖动，达到拖动阈值才开始操作。拖动目录时拒绝自身和自己的子目录作为目标。

## 二、文件、文件夹与批量选择

- 支持单选、多选、范围选择、全选，键盘与右键操作作用于明确的选中集合。右键选中集合内条目保留集合，右键未选中条目改为选中该项。
- 全选范围必须可理解：当前已加载条目与未加载分页不能混淆，不能显示“全选目录”却只处理一页。
- 文件和文件夹可以混合上传、下载、复制、移动及删除；选择父目录又选择子项时去重，子项只处理一次。
- 文件夹递归保留顶层名称、相对路径、嵌套结构、空目录、隐藏文件、零字节文件和二进制内容。传输不受编辑器 1 MiB 或 UTF-8 限制。
- 以流式读写处理大文件，递归枚举按需推进，不把整个文件或整棵目录内容一次加载到内存。扫描未结束时显示“正在统计”，不显示虚假的完整总量。
- 中文、空格、emoji、长名称与深层路径按平台实际能力处理。Windows 保留名、非法字符、大小写冲突和名称规范化冲突必须显示，支持改名或跳过，不静默改名、丢文件或覆盖另一项。
- 符号链接明确显示。首轮递归传输默认不跟随链接，跳过并报告，避免循环和目录外内容被意外复制；不把链接悄悄变为普通文件。删除、重命名和移动链接时只操作链接本身。跨平台保留链接另行补充。
- 套接字、设备、FIFO 等特殊条目不按普通文件读取；跳过并说明原因，避免传输挂住。
- 保证文件字节一致；尽可能保留修改时间。跨平台权限、所有者及扩展属性不承诺完全一致，不能把未保留元数据报告为“完整克隆”。

## 三、目标、同名和数据完整性

- 所有入口遵守相同目标规则：选中目录则使用该目录，选中文件则使用其父目录；多选跨目录或没有明确目录时，展示并让用户确定目标，不能从路径框中的文件名猜测目录。拖拽使用明确的目录落点。
- 任务提交后固定源、目标与选中集合；随后切页、改变选中、拖动窗口不能改变正在运行的任务。
- 上传或下载文件夹默认在目标目录内保留该文件夹顶层名称；“仅传输目录内容”若提供，应作为明确的独立选项。
- 同名文件提供覆盖、跳过、保留两份和取消；同名目录可合并，内部同名文件继续使用文件冲突策略。支持对本次任务的同类冲突统一应用。
- 文件与目录同名时说明类型冲突，首轮提供改名、跳过或取消，不按普通覆盖递归删除目标。大小写或规范化碰撞按真实目标文件系统判断。
- 覆盖先写临时文件，完成并做必要校验后再提交。中断、取消、空间不足或写入失败不提前截断原文件；服务器不支持所需提交保证时，明确返回原因。
- 开始时检查源和目标，提交前再次检测可观察的变化。源在传输中变化、目标被其他程序修改或提交结果未知时，显示冲突或未知结果，不报告成功。
- 目录传输按文件提交，可能部分完成；失败或取消不回滚已经成功的条目，不把整个目录描述为原子操作。未完成条目可单独重试。
- 上传、下载的临时文件和失败残留有明确归属与清理策略，不留下无限增长的残留数据。

## 四、完成日常操作所需的远程管理

这是根据文件管理场景补充的建议范围，其中创建、重命名和删除也已在产品 MVP 目标中出现。

- 新建文件、新建文件夹、重命名、删除，操作成功后刷新受影响目录并尽可能保留选择与展开位置。
- 同一服务器内复制、粘贴、剪切、移动文件和目录。复制及移动目标有冲突时复用统一策略；剪切在粘贴成功后才清除标记。
- 同机移动优先使用服务器文件操作；需要复制后删除的情况，只有对应源条目完整复制并校验成功后才允许删除，部分失败不能删除未完成源。
- 同路径粘贴、重复提交、目录复制或移动到自身子目录需要可理解的处理；不能无限递归，也不能产生重复任务。
- 删除明确区分文件、目录和多选，确认包含递归删除的范围；没有远程回收站时明确告知是直接删除。
- 展示类型、大小、修改时间与可获得的权限信息，保留路径定位、刷新、排序和文本编辑。权限不足按服务器实际结果反馈，不增加插件授权流程。
- 重命名、移动、删除与已打开编辑器保持一致：没有草稿的页面更新位置或显示已删除；有未保存草稿时先处理冲突，不能丢草稿或保存到错误路径。

跨本地与远程的剪切并非用户已明确要求，首轮按复制传输处理；跨边界“传完自动删除源”的移动行为单独设计。

## 五、任务反馈和恢复

- 上传、下载、远程复制使用统一的任务展示，说明方向、服务器、源、目标、当前条目、字节进度、已完成项数、速度和可估计的剩余时间。
- 具备等待、统计、传输中、等待冲突处理、成功、部分失败、失败和已取消状态；区分请求取消与取消完成，提交结果不明时单独标记。
- 支持有界队列、取消单任务、取消整批、重试失败项；不因某一条失败丢掉整批结果，也不在重试时重复处理已经完成的条目。
- 批次结束展示成功、失败、跳过和取消数量，失败项可定位并查看原因；下载成功可打开本地所在目录。
- 传输中仍能浏览目录、切换服务器、隐藏侧栏和使用终端；移窗或重挂载不重复任务，回到面板可以查看进度。
- 关闭连接、结束工作区或退出应用时告知仍在运行的任务并处理取消或等待；取消关闭动作继续原任务。插件停止、崩溃或连接断开后释放相关资源并保留可理解的结果。
- 断线后不把旧任务静默绑定到新连接。重连后用户可重试失败项，首轮单个未完成文件从头传；暂停、断点续传与应用重启后的任务恢复不作为首轮保证。
- 高频进度留在任务界面，批次完成、失败或需要处理时使用重要消息；普通日志和用户通知仍分开，不对每个小文件都弹通知。

## 六、系统兼容与架构边界

完整目标覆盖 Windows x86_64 / ARM64、Linux x86_64 / ARM64、macOS ARM64。Linux 还需明确实际支持的桌面环境、文件管理器和 X11/Wayland 范围；架构编译通过不能替代桌面互通验证。

系统本地文件剪贴板读取与原生文件拖入由核心平台适配层提供统一接口；文件插件负责选择、目标目录、递归规则、冲突策略与文件任务界面。核心继续复用会话与通用文件读写、任务资源及清理能力，不把业务规则集中塞入核心。正文走流式能力，不把文件内容放进控制 RPC。

原生验证聚焦本地复制后粘贴上传、本地文件与文件夹拖入上传。下载继续使用系统保存或目录选择器；不为已去掉的两个方向引入远程文件对外取数、原生文件对象发布或拖出缓存机制。

本地粘贴或拖入存在平台限制时，列出具体平台、桌面环境及受限操作，并保留上传按钮作为可用入口；尚未通过的保留入口仍记录为未完成。新增 API 使用可发现能力和兼容策略，缺能力时明确提示升级。若确需新增生产依赖，再说明用途、维护情况与替代方案。本提案不引入插件权限声明或审批系统。

## 七、建议交付顺序

1. **先验证本地导入。** 在五目标的实际安装包中验证本地文件与文件夹的剪贴板读取和原生拖入，尽早确定 Linux 桌面兼容及目录来源识别的可行方案；此时能力可以是最小验证实现。
2. **完成双向传输基础。** 文件和文件夹、多选、系统选择器上传下载、流式任务、冲突、取消和失败重试形成完整可验收流程。
3. **接通本地粘贴和拖入。** 本地复制后远程粘贴、原生拖入复用上传流程，补齐主窗口、独立窗口、焦点与快捷键交互。
4. **补齐远程管理。** 新建、重命名、删除、同服务器复制与移动，以及这些操作与编辑器草稿的协调。

第 1 步的技术验证不能算正式功能完成，第 2 步完成也不能宣称已支持本地粘贴和拖入。每个实现改动仍应对应一个完整可验证的问题。

后续候选：暂停与断点续传、跨服务器复制、目录同步、压缩解压、权限及所有者修改、完整本地双栏浏览、递归搜索、跨平台链接保留、通过核心事件与终端目录联动。这些不自动加入首轮承诺。

## 八、验收场景

| 场景 | 通过标准 |
| --- | --- |
| 系统复制后上传 | 系统文件管理器多选文件和目录，SoDeck 粘贴到指定远程目录；结构、空目录和字节正确 |
| 本地原生拖入 | 本地文件和目录拖入 SoDeck 上传；目录落点、取消、主窗口及独立窗口符合约定 |
| 显式上传下载 | 文件、目录、混合批量经系统选择器完成；无需将目录手工打包 |
| 完整内容 | 覆盖二进制、大于 1 MiB 的文件、大文件、零字节、隐藏项、空目录、深层目录、中文和 emoji |
| 特殊条目及名称 | 链接不循环遍历；特殊文件不挂住；非法名、保留名、大小写和规范化冲突明确反馈，无静默丢失 |
| 同名处理 | 覆盖、跳过、保留两份、目录合并及文件/目录类型冲突均符合策略；批量策略仅作用于本任务 |
| 故障与取消 | 传输中断网、取消、空间不足、权限不足或文件变化时，原目标不被提前破坏，结果及残留清楚 |
| 部分失败及重试 | 已成功项保留，失败项单独重试；源不被错误删除，无重复任务 |
| 焦点和上下文 | 输入框正常复制文字；复制后切服务器仍保留原来源；任务启动后切页、移窗和重连不改变源目标 |
| 远程管理 | 创建、重命名、同机复制与移动、递归删除符合明确范围；已打开草稿不丢失，不能保存到错误位置 |
| 生命周期 | 侧栏隐藏、重挂载及移窗继续展示同一任务；关闭和退出正确处理在途任务与临时文件 |
| 既有能力回归 | 目录分页、键盘导航、主题、UTF-8/BOM/换行保留、保存冲突、草稿导出及单文件下载继续工作 |

正式交付分别在五个系统与架构组合使用独立发行的核心和文件插件包验证。本地文件复制后粘贴上传及原生拖入必须与系统文件管理器实际互操作；浏览器模拟事件、交叉编译或已有文本剪贴板测试不能替代这些验收。远程到本地按显式下载流程验收。
