# 服务器 Tab 与可拆合工作区

日期：2026-11-05。状态：方案已确认；v0.4.0 已实现工作区壳、原生移窗和拖动命中。SSH 与业务组件另行实施。

## 1. 对本次需求的理解

用户明确要求：一个 Tab 分配给一台已连接服务器；Tab 能拖出主窗口成为独立窗口，也能回到主窗口；Tab 内所有组件只处理所属服务器的业务；组件本次不实现；界面结构参考旧版。

因此，顶部 Tab 表示一份服务器工作区。服务器、连接、组件实例和工作区状态组成一个稳定上下文，移动窗口只改变其显示位置，不重新登录、不复制任务、不改变操作目标。

示例：生产 A 的工作区包含将来的文件面板、两个终端和网络面板。切到测试 B，A 的工作继续；将 A 拖到副屏，A 的全部面板与内部页一起过去；移回主窗口，仍是原来的 A 和原来的连接。

已经完成的 v0.3.0 服务器管理是档案目录，不等于已连接列表。本方案不假定当前产品已有 SSH，会话状态也不能由前端凭空创建。

## 2. 旧版取什么

只读参考旧仓库的 `apps/desktop/src/server-tabs.tsx`、`app.tsx`、`docs/core/server-tabs.md`、`docs/core/workbench-interaction.md`，以及本仓库 `docs/reference-v2/workbench-light.png`。旧文档包含多个阶段的覆盖条款；本方案以当前需求和本仓库约定为准，不迁入旧项目的状态机、生成契约、托盘或完整视图迁移机制。

保留这些界面关系：

```text
顶层：[服务器管理] [生产 A ×] [测试 B ×] [+]    状态 消息 设置  窗口按钮
      左工具栏 | 左面板 | 当前服务器的内部页签与主区域 | 右面板 | 右工具栏
底部：当前服务器账号与地址、连接状态
```

- 无独立标题栏。顶层 Tab 与窗口拖动区、右上角工具及窗口控制共用一行。
- 「服务器管理」是主窗口的固定核心页，继续承载现有服务器/代理 CRUD；它不是服务器工作区，不关联连接，也不参与拆窗。
- 服务器工作区内保留左右工具与可收起面板；中央是一组组件页签。本次只展示空槽位，不实现文件、终端、Docker 或 NetBird。
- 文件默认在左、网络能力入口默认在右，沿用旧版的空间关系。核心只管理位置与上下文，具体业务留给插件。
- 系统状态、消息和设置在右上角；插件管理仍在设置里，不挤进服务器工作区。
- 延用现有四种外观；多巴胺使用现有配色、深色轮廓与平面样式，不引入玻璃或装饰动画。

## 3. 建议的产品规则

下表中的“推荐”是本次推断，区别于用户已经明确提出的拆合与服务器归属。

| 场景 | 推荐行为 |
| --- | --- |
| 打开服务器 | 核心连接成功后建立并激活服务器 Tab；连接中/失败在原连接入口反馈，不伪装成已连接工作区 |
| 再次打开同一服务器档案 | 定位已存在的工作区及其窗口，不重复建立另一份；同服务器需要多个任务时放到内部组件页 |
| 相同地址的不同档案 | 按稳定 serverId 区分，可以各自打开，不根据 IP 合并 |
| 切换顶层 Tab | 只切换可见工作区，保留每台服务器自己的组件实例、内部页、侧栏状态与宽度 |
| 同窗拖动 | 调整服务器 Tab 顺序；固定服务器管理页不参与排序 |
| 拖出窗口 | 建立新的原生窗口并移动整份工作区；新窗口可容纳多个服务器 Tab，与主窗口共用布局 |
| 拖入另一窗口的顶层 Tab 条 | 按插入位置移动已有工作区，不创建副本，也不改变 connectionId |
| 菜单“移至新窗口 / 返回主窗口” | 与拖动执行同一条移动命令；作为键盘和不方便拖动时的入口 |
| 点 Tab 的 × | 关闭这份工作区并释放它自己的组件和连接引用，不删除服务器档案 |
| 关闭独立窗口 | 关闭该窗口中的工作区；存在未保存编辑/进行中任务时，先汇总组件的关闭检查。明确的“返回主窗口”按钮负责保留任务并合回 |
| 独立窗口移动走最后一个 Tab | 关闭空窗口，不执行工作区关闭或断连 |
| 主窗口移走最后一个服务器 Tab | 保留主窗口的服务器管理页 |
| 主窗口 × / 应用升级重启 | 沿用当前“退出应用”语义，统一检查所有窗口的未保存状态并清理资源，不新增托盘行为 |
| 退出再启动 | 先打开服务器管理；本轮不恢复运行连接、任务或一批独立窗口，也不自动连服务器 |

服务器断线后保留其原 Tab 和内容，显示真实的断线状态，后续提供原位重连。重连成功更新同一工作区的会话绑定与代次，不能悄悄创建新 Tab；旧请求不能继续写入新会话。关闭工作区释放的是本工作区持有的引用，底层共享跳板若仍有其他使用者继续保留。

修改服务器档案后，已打开工作区继续使用建立连接时的地址、认证和路径快照，下一次连接才采用新配置；重命名可同步显示。存在打开工作区时删除档案，应先提示关闭工作区，避免运行身份被悬空。

## 4. 服务器上下文如何保持正确

明确区分四个标识，避免把 Tab 数组下标或“当前活动服务器”当业务目标：

```ts
type Workspace = {
  id: string;                // 一次打开的服务器工作区
  serverId: string;          // 已保存服务器档案
  connectionId: string;      // 核心真实连接会话
  connectionGeneration: number; // 重连后递增，拒绝旧会话请求
  windowId: string;          // 当前承载窗口
  leftPanel: string | null;
  rightPanel: string | null;
  leftWidth: number;
  rightWidth: number;
  activeViewId: string | null;
  viewIds: string[];
};

type WorkspaceWindow = {
  id: string;
  role: "main" | "workspace";
  workspaceIds: string[];
  activePage: "servers" | { workspaceId: string } | null;
};

type ViewInstance = {
  id: string;
  workspaceId: string;
  pluginId: string;
  viewType: string;
};
```

- 核心内存是工作区归属、窗口顺序与会话关联的唯一事实来源。各窗口读取它自己的投影，通过命令修改；不各存一份互相同步的真相。
- 插件组件创建时得到固定的工作区上下文和会话引用。异步读取、回调、任务和事件一直携带这个上下文，不能在执行时查询某个全局 `activeServer`。
- 视图 ID 在移窗前后保持；切换到 B 时，A 的操作回包仍回到 A。核心做参数、会话代次和状态检查，不引入插件权限系统。
- connectionId 不等于唯一 TCP/SSH 对象，一个连接未来可以拥有通用会话能力及共享跳板引用。这个阶段只确定边界，不实现传输或连接池。
- 工作区和窗口运行状态不写进 `servers.json`。服务器目录仍只存用户资料，本轮不增加数据库或复杂布局持久化。

## 5. 移窗的最小可靠流程

先把移动命令做正确，再接拖拽手势；菜单和拖拽共用同一实现。

1. 核心核对 workspaceId 的当前窗口和移动状态；同一工作区的移动/关闭串行处理。
2. 若需新窗，先建立隐藏的目标窗口。目标读取该工作区信息并报告就绪；此时源工作区仍有效。
3. 交接时冻结这一工作区的新输入；将 windowId、两窗顺序和活动项一次提交到核心，再启用目标表面。始终只有一处有效业务输入表面。
4. 源窗口移除该 Tab，目标激活它；若源为已空的独立窗口，则回收空窗。
5. 目标未就绪、用户 Esc、窗口创建失败或等待超时，均保留原位置；不能先销毁源再尝试创建目标。

此时组件尚未实现，不搬真实终端 DOM、WebView 或文件编辑器。第一批真实插件接入时，业务会话/任务继续留在核心或插件进程，目标窗口重新挂载表现层并恢复需要的界面状态；不能承诺未来任意第三方组件无需配合就能完整迁移。届时只为第一个真实组件补最小的重挂载与关闭检查约定，不预建通用视图快照框架。

前端发起移动后立即显示预览和插入线。超过约 8px 才认定拖动，保持抓取偏移；Esc 随时取消。窗口空白拖动窗口，Tab 区域拖动工作区，两者命中不能重叠。移到内容区或系统按钮上不提交移动。焦点和活动页在成功后跟随工作区，减少动态时保留静态反馈。

跨原生窗口拖拽需要以操作系统屏幕坐标命中目标 Tab 条，处理不同显示器缩放；不能只用单个 WebView 的 HTML drag/drop。Windows/macOS/Linux 适配集中在核心窗口层。Linux Wayland 对全局坐标、程序定位和跨应用拖动有约束，需先做实际技术验证；原生拖拽/可用窗口几何是候选路径，菜单移动是必要的等价操作入口。仅菜单成功不算拖拽验收通过，限制必须如实记录。

## 6. 实施范围与顺序

本轮按已确认方案完成两部分代码，验收边界见末尾记录：

1. **工作区壳与菜单移窗**：顶部服务器 Tab、固定管理页、切换、关闭、左右空槽位、多原生窗口及移动/返回。通过测试构建注入示例会话验收，不在普通发行版伪造“已连接”；生产工作区只消费未来真实连接服务的结果。
2. **拖拽与原生验收**：同窗排序、拖出、跨窗放回、插入预览、取消及多显示器/DPI。继续使用第一步移动命令，不再建立第二套迁移逻辑。

SSH 建连是随后独立的一项工作：连接成功将会话交给工作区服务。文件、终端、Docker、NetBird 与单个内部组件的弹出、分屏、布局恢复不纳入本次。尚无真实连接时，发行界面保留服务器管理和明确空态，不展示模拟连接或假业务数据。

预计代码职责：`workspaces.rs` 管上下文/归属，`windows.rs` 管 Tauri 窗口与原生差异，`workspaces.ts` 管 Tab 和空槽位。`main.rs` 只组合命令与关闭入口；当前“任意窗口关闭都会退出应用”的处理需按窗口角色拆开。Tauri capability 中登记新窗口所需的同等桌面能力，不变成插件授权系统。不复制旧版巨型入口，不预先引入 Dock 框架或新生产依赖。

## 7. 可验收行为

- A/B 分别有不同占位页和侧栏状态，来回切换后各自保持，异步测试回包不串目标。
- 重复打开 A 只定位原工作区；A 被拆走后再次打开会聚焦所属独立窗口。
- 拖出/移回/跨窗排序后，workspaceId、connectionId、视图 ID 和测试任务身份不变；不创建新连接。
- 第一次目标准备失败、目标中途关闭、快速重复移动、移动时关闭、Esc 取消均不丢失或复制工作区。
- 子窗口全部回主窗后自动消失；主窗口仍保留管理入口；子窗口关闭不退出其他窗口，主窗口退出正确清理全部窗口。
- 所有被关闭组件先完成未保存检查；任何取消发生在释放资源之前。组件尚未实现时仅使用测试占位钩子。
- 断线不删除 Tab，旧会话回包被拒绝；编辑档案不改变正在使用的会话目标。
- 720×480、长名字、多 Tab、键盘、不同主题与减少动态可用；Tab 过多单行滚动，右上角及窗口按钮可达。
- 五个正式目标原生构建、打包并启动实际包；拖出和回窗另做各系统原生交互验证，浏览器原型不替代原生窗口/DPI 验收。

## 8. 原型边界

原型仅模拟服务器上下文、Tab 顺序、面板收起与窗口归属，显示的“已连接”均为示例。画面中的独立窗口也是同一原型画布内的示意窗口，不创建系统原生窗口，不访问服务器，也不证明真实组件可以无损迁移。

已用无头浏览器通过 11 组交互检查：双层导航、上下文与侧栏保留、菜单拆出、跨示意窗口拖回、同行排序、拖到示意桌面、Esc/无效落点取消、返回与关闭、右键固定目标、最后一个服务器关闭后的管理入口，以及 1040/720/360/320px 与减少动态。无页面脚本错误，无横向溢出；主窗口和拆出状态均已截图检查。只证明原型交互，不替代后续原生拖动、真实连接和实际安装包验收。以上为设计阶段的原型结果；产品实施见下面记录。

## 9. v0.4.0 产品实施与验证边界

- 核心内存唯一归属、同档案去重、固定 Context、断线保留与代次检查、布局保持及删除保护已落地；组件业务仍为空槽，不预造插件视图。
- 同窗排序、原生窗口移出/返回/合并使用同一 prepare/commit/cancel 路径。目标 frontend 读取投影并就绪后才交接，失败保留源；关闭与移动互斥。
- 主/子窗口关闭分开处理；全局升级、重启和退出通过主窗口检查目录草稿。关闭最后一个工作区后固定管理页保留，空子窗销毁异步完成。
- 指针超过 8px 开始拖动，抓取偏移保持；插入线、Esc、无效落点和等价菜单已实现。WebView pointer capture 保持到释放；原生命中使用每窗 inner_position、scale_factor 和顶部 Tab 区域，落窗位置使用物理坐标。
- `npm run ui:test` 包含真实 Rust 目录的 12 组测试和工作区的 9 组测试。后者验证 DOM、核心归属和手势；浏览器的桌面调用替身不等于原生拖拽验收。
- 实际包烟测通过原生 WebView 创建、目标就绪、A/B 合窗、返回、子窗关闭、空窗回收、Context/布局保持，并用实际窗口几何验证 Tab 条和无效区域命中；不操作系统指针。
- 五目标原生包结果记录在 v0.4.0 发布记录。跨原生窗口的实际指针手势、混合 DPI 显示器和 Wayland 限制仍需真实桌面人工验收；菜单与几何测试不冒充其结果。
